Lecture 6 · Part 1 of 14 · the opening two examples

The outcome is what happened, but the number is what you wanted to know

9 min foundation Two experiments the notes open with, and the one thing they have in common that the whole lecture is built on.

The one-minute version

  • Start where the last four lectures left you: a probability space (Ω, F, P), an experiment you can run, and a rule for pricing any event.
  • The notes then make a move that sounds trivial and is not. Having run the experiment, we are usually interested in some numerical property of the outcome rather than the outcome itself.
  • Toss a coin three times. The outcome is a string such as HHT. The number you want is the head count, and X(HHH) = 3 while X(HTH) = 2.
  • Roll two dice. The outcome is a pair such as (1, 6). The number you want is the total, and X((1,6)) = 7.
  • In both cases the map from outcome to number is many-to-one, and that is not a defect. Throwing information away on purpose is what makes the number useful.

1. Where this starts

Nothing new is assumed here. The notes open with a single line: consider a probability space, written (Ω, F, P), and recall what its three pieces are.

  • Ω, the sample space, is the set of every outcome the experiment can produce. Lecture 2, Part 2 built it.
  • F is the collection of events, the subsets of Ω we are entitled to ask about. Lecture 2, Part 4 built it.
  • P is the probability measure, the rule that assigns a number between 0 and 1 to each event in F. Lecture 2, Part 5 built it.

That triple is complete. It can answer any question of the form "how likely is this event". What it cannot do is answer a question about a quantity, because nothing in the triple is a quantity. An outcome in Ω is whatever the experiment produces, and that is very often not a number at all.

2. The first example: count the heads

The notes state it as follows. Toss a coin n times, where n is fixed in advance. Then the sample space is

Ω = { ω = (ω1, ω2, ..., ωn) : ωi ∈ {H, T} } ω is one outcome of the whole experiment, and it is an ordered list of n entries. ωi is what the i-th toss produced, and it is either H for heads or T for tails. The braces on the outside make Ω the set of every such list, and there are 2n of them because each of the n positions is filled independently in one of two ways.

Now define X to be the number of heads observed. That sentence is doing something specific: it is defining a rule that turns any one of those lists into a single integer. The notes give two instances of the rule, and both are worth reading slowly.

  1. The all-heads outcome. The list HHH has three entries and all three are H, so the number of heads is three. The notes write X(HHH) = 3. Read the notation aloud as "X evaluated at the outcome HHH is 3".
  2. A mixed outcome. The list HTH has H in the first and third positions and T in the second, so the number of heads is two. The notes write X(HTH) = 2.
  3. What the brackets mean. X(·) is ordinary function notation, the same notation you would use for f(x). What is unusual is only what goes inside: not a number, but an outcome of an experiment.

3. The second example: add the dice

The second example in the notes changes the experiment and keeps the move. Roll two dice, and record which face each one shows. The sample space is

Ω = { (i, j) : i, j ∈ [1, 6] } i is the face the first die shows and j is the face the second shows, and both are whole numbers from 1 to 6. The pair is written in order, so (1, 6) and (6, 1) are two different outcomes even though they contain the same two faces. There are 36 pairs in all, which Lecture 4, Part 9 counts with the basic counting rule.

Now define X to be the sum of the outcomes: given a pair, add the two faces. The notes give one instance, X((1,6)) = 7, and the double brackets are worth a sentence of their own. The inner pair of brackets belongs to the outcome (1, 6), which is a pair. The outer pair belongs to the function X. So the expression reads "X evaluated at the outcome (1, 6)".

4. What the two examples share

Strip the details away and the two examples are the same move made twice.

  1. There is a probability space already. Both examples begin by naming Ω. Nothing about the random variable is defined before the sample space is.
  2. There is a question about a quantity. "How many heads" and "what do they add to" are both questions about a number, and neither is a question about which outcome occurred.
  3. The quantity is a rule applied to the outcome. Given the outcome, the number follows with no further uncertainty. You do not have to run anything else to work out that HTH has two heads.
  4. The rule loses information. Both maps send several outcomes to the same number, and neither can be run backwards. That is what makes them useful: the number is comparable, addable and averageable in a way the outcome never was.

5. Check yourself

In the three-toss example, what kind of thing sits inside the brackets of X(HTH)?
X is a function whose input is a single outcome, so HTH is one of the eight members of the sample space and nothing else. A probability is what P takes as an output, not what X takes as an input, and no probability appears anywhere in the expression. An event is a set of outcomes, so it would be written with braces around it; HTH on its own is a single element, not a set of them. And a count of heads is what X gives back, so putting one inside the brackets confuses the output with the input.
Why can the map from outcome to number never be run backwards?
Three separate outcomes give a head count of two, so the value 2 cannot tell you which of them occurred, and that is the whole reason. Nothing in the definition of a probability space says anything about inverses; the obstruction here is arithmetic, not an axiom. Timing is not the issue either, since the rule is fully known before the experiment runs and could be tabulated in advance. And the difference in type is not the obstruction: the dice example maps pairs of numbers to a number and is just as impossible to reverse, for exactly the same reason.
The notes state the examples and stopThe source gives these two examples in five handwritten lines, with the three evaluations X(HHH) = 3, X(HTH) = 2 and X((1,6)) = 7 and no diagrams. The full list of eight coin outcomes, the whole dice grid, the tally of how many outcomes give each total, and the observation that the map is many-to-one are all this course's own expansion of what the notes assert. None of it goes beyond what the two definitions already fix, but none of it is on the page in the source either.
Your teacher. If you have written code, you already know this object well and under a different name. X is a pure function: same input, same output, every time, no state and no side effects. The experiment is what supplies the argument. That framing carries you a long way, and it makes the misnomer on the next page feel obvious rather than pedantic. A pure function is not random. What is random is which argument it gets called with. Once you see it, metrics everywhere are the same object: tokens per second, queue depth, time to first token are all pure functions of the serving system's state, and every one of them earns a distribution the moment the state starts moving.
