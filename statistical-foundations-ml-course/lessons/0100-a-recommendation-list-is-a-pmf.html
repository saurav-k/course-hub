Six measured numbers describe a click, and the distribution has no name

working 9 min The lecture's second worked example, delivered live: a recommendation list turned into a discrete random variable.

After this page

  • You can turn "where did the user click" into a random variable with a support of six values.
  • You can check whether a list of measured proportions is a legal PMF.
  • You can answer "which distribution is this" with "none, and it does not need to be one".

Before you start: The support and the PMF, for what a mass function is. Nothing else is needed.

The one-minute version

  • A system answers a query with five ranked items and a sixth "show more" link. The user clicks the first thing they like.
  • Define X = the position of the user's click. That one sentence turns a browsing session into a discrete random variable.
  • Its support is 1 to 6. Position 6 is not an item: it is the outcome "none of the five was any good".
  • The measured masses are 0.30, 0.25, 0.15, 0.10, 0.05, 0.15. They sum to 1, so this is a legal PMF and it is the whole model.
  • A student asked which family it belongs to. The answer is none, and a nameless distribution is still complete.

1. Turning a browsing session into a number

The setup is deliberately ordinary. You pose a query to a recommendation system, and it returns an ordered list: five items, ranked most relevant first, and below them a sixth row that is only a link reading "show more". The lecturer's own example was a YouTube search for Arsenal highlights.

The user's behaviour is a scan. They look at item one. If they like it, they click it and stop. If not, they look at item two, and so on down the list. If none of the five is any good, they press "show more" and ask for a fresh set.

That scan has exactly six possible endings, so it can be summarised by one number. The lecturer writes the definition on the board as X = position of user click, and from that moment the session is a discrete random variable.

2. Why the support runs to six

The list holds five items, so five is the tempting answer and it is wrong. The support of a random variable is the set of values it can actually take with positive probability, and "the user pressed show more" is a value the session can end on.

Leaving it out would not make the model simpler. It would make it illegal: the five item masses come to 0.85, and a mass function whose values sum to less than one is not a mass function. The sixth position is where the missing 0.15 lives.

pX(i) = P(X = i), for i in {1, 2, 3, 4, 5, 6} Read as: X is the position of the user's click, a whole number between 1 and 6. i is one particular position you are asking about. pX(i), the probability mass function of X, is the probability that the click lands exactly at position i. The braces list the support: the six values X can take. Hajek defines the pmf this way in section 2.1, and defines the support as the set of values whose mass is above zero.

3. The six numbers, and what they buy

A recommendation system at any scale has the data to measure these. The board's figures: 30% of users like the first link and click it, a quarter skip it and take the second, then 0.15, then 0.10, then 0.05 at position five, and 15% who like none of the five and ask for more.

These are teaching figures, not YouTube'sThe lecturer introduced the six numbers with the word "suppose": suppose YouTube did this experiment and they found, okay, 30% of the users actually like the first link. They are invented to make the arithmetic land, and nothing here is evidence about how any real recommendation system performs. What is real is the shape of the model, which is what the page is teaching.

4. The sum-to-one check, worked

The lecturer stops mid-example to run this check out loud, and it is worth copying the habit. A table of six numbers is only a PMF if two things hold: none of them is negative, and together they come to exactly one.

∑i=16 pX(i) = 1 Read as: the sigma sign means "add up". i runs over every value in the support, from 1 at the bottom to 6 at the top. pX(i) is the mass at position i. The whole line says that the six masses, added together, must come to exactly one. Hajek states this in section 2.1 as the defining property of a discrete-type random variable.
  1. Start at the top of the list. Position 1 contributes 0.30, so the running total is 0.30.
  2. Add position 2. 0.30 + 0.25 = 0.55.
  3. Add position 3. 0.55 + 0.15 = 0.70.
  4. Add position 4. 0.70 + 0.10 = 0.80.
  5. Add position 5. 0.80 + 0.05 = 0.85. The five items alone leave 0.15 unaccounted for.
  6. Add position 6. 0.85 + 0.15 = 1.00. Every number is at or above zero, so this is a valid PMF.

5. The family it belongs to, which is none

Near the end of the example a student asked the obvious question: is it a binomial, and if not, what is this called? The lecturer's answer was blunt. No, this distribution is not one of the families that we have discussed. This is just an arbitrary probability mass function. There is no name for it. It doesn't belong to some particular family.

That answer is worth more than it looks. Parts 1 to 3 of this lecture spent a poll inside the binomial, where every mass came from a formula with two parameters in it. It is easy to come away thinking a random variable must be one of the named shapes before you may reason about it.

The reframingA named family is a compression, not a licence. The binomial replaces a long table with two numbers, n and p, and that is worth having when a mechanism actually produces the table. Here no mechanism produces it: the numbers came out of a log. The table is already the shortest honest description, and everything Lecture 6 built on top of a PMF works on it unchanged.

Nothing on the next page needs a family either. The cumulative function is defined for any PMF, and the two product questions the lecturer asks are read straight off it.

Check yourself

Retrieval practice

Answer from memory before revealing.

The list shows five items. Why does X take six values rather than five?
Pressing "show more" ends the session just as a click does, so it is a sixth value of X, and it carries 0.15 of the mass. The first option invents a double count that never happens: the user clicks once and stops. The second is not a rule anywhere; a support has exactly the values the variable can take, no spares. The third misreads the picture, because row six is a link and not a sixth recommendation.
The six numbers are 0.30, 0.25, 0.15, 0.10, 0.05 and 0.15. Which family is this?
The lecturer answered this one live: it belongs to no family, and a table that sums to one is already a complete model. The binomial counts successes over a fixed number of independent trials with a shared p, and nothing here is counted that way. The geometric is tempting because the user does stop at the first hit, but a geometric's masses fall by a constant factor at every step and these rise again at position six. And rescaling cannot produce a uniform, because the six masses are not equal and rescaling a set of unequal numbers leaves them unequal.

Practice about 10 minutes, with paper

Practice 1working

A second product surface uses the same layout: four ranked items and a fifth "show more" row. The team measures the click positions over a month and reports four of the five masses.

pY(1) = 0.42, pY(2) = 0.21, pY(3) = 0.12, pY(4) = 0.07 Read as: Y is the position of the click on this second surface, a whole number from 1 to 5. pY(k) is the probability that the click lands at position k. Position 5 is the "show more" row, and its mass has not been reported.

Find the mass at position 5, and say whether this surface serves its users better or worse than the six-position list on this page.

Hint

You are not being asked to guess the missing number. There is only one value it can take, and the sum-to-one property is what pins it down. For the comparison, "better" has to be defined before it can be answered: pick the share of users who never reach the give-up row.

Show the worked solution
  1. Add the four reported masses. 0.42 + 0.21 = 0.63, then 0.63 + 0.12 = 0.75, then 0.75 + 0.07 = 0.82.
  2. Subtract from one. The five masses must sum to 1, so pY(5) = 1 - 0.82 = 0.18.
  3. Define "better" before comparing. Take the share of users who click a real item rather than the give-up row.
  4. Compute it for each surface. Here that is 1 - 0.18 = 0.82. On the page's six-position list it is 1 - 0.15 = 0.85.
  5. Read the comparison. 0.82 is below 0.85, so on this definition the four-item surface serves its users slightly worse, by 3 users in every 100.

Sanity check. The answer had to be between 0 and 1, and 0.18 is. It also had to be the largest single mass after position 1, which it is, and that matches the shape on this page, where the give-up row was also the second largest bar. A negative answer would have meant the four reported masses already summed past one, which is a measurement error rather than a distribution.

Carry this away

  • One sentence, "X is the position of the user's click", converts a browsing session into a discrete random variable with a support of six values.
  • The give-up row is an outcome, not an absence, and a support that omits it leaves 0.15 of the probability with nowhere to live.
  • A table of non-negative numbers that sums to exactly one is a legal PMF, and the sum test catches a forgotten outcome and a double-counted one at the same time.
  • A distribution with no name is not an incomplete distribution. A named family is a compression of a table, useful only when a mechanism produces the table.

Your teacher. If the support argument did not land, ask an agent to redo this page's model with the give-up row deleted, then work the sum-to-one check on the five remaining masses and say in one sentence what breaks. The answer is that 0.85 is not 1, and the interesting part is what that failure means: not "the arithmetic is wrong" but "there is an outcome this model cannot describe". That is the same failure mode as an enum in code with no default case, and it is worth feeling once rather than reading about.
