Glossary

111 terms One definition each. The night-before revision sheet: every term links to the chapter that develops it.

How to use this

  • Cover the definition column and recall it from the term. Retrieval beats re-reading.
  • Any term you cannot define in one sentence is a term you cannot defend at a whiteboard.
  • Definitions here are opinionated and single-meaning on purpose. The chapters carry the nuance.

Pillar 1 · LLM Basics

Developed in Chapter 1.

TermDefinition
TokenThe sub-word unit a model actually processes. Not a word, not a character, and the denominator of every cost and limit.
Context windowMaximum tokens the model can attend to in one request, covering instructions, history, evidence, and the answer. A budget, not a container.
Prompt designTreating the prompt as a versioned, tested, rollback-able interface rather than an editable string.
System promptThe highest-trust instructions in a request, carrying role and policy. Everything else in the window is untrusted input.
TemperatureRescales the token distribution before sampling. Low means low variance, which is not the same as deterministic.
Top-p samplingSample only from the smallest token set whose cumulative probability exceeds p. Also called nucleus sampling.
Structured outputsConstrained decoding that forces emitted tokens to conform to a JSON Schema. A guarantee, not a request.
JSON modeGuarantees syntactically valid JSON but not conformance to your schema. Parses is not conforms.
Function callingThe model emits a structured request to invoke a declared function. It returns intent; your code decides.
Tool callingThe loop where a tool result is executed by your runtime, appended to context, and generation continues.
AgentA model in a loop with tools choosing its own next step. Needs a step budget and a termination condition.
MemoryConversation state and long-term facts you store and retrieve. A database design, not a model feature.
GuardrailsIndependent checks around the model: input filtering, output validation, policy classification, refusal handling.
HallucinationFluent output unsupported by any source. Split into factuality failures and faithfulness failures.
Model latencyTwo numbers: time to first token, driven by prefill and queueing, and inter-token latency times output length.
Model routingSending each request to the cheapest model that can serve it, with escalation on low confidence.
Small versus large modelsA portfolio decision: small for the high-volume narrow path, large for the long tail, evaluation to set the boundary.
Fine-tuning versus promptingPrompting is per-request and instantly reversible. Fine-tuning moves behaviour into weights and buys a data pipeline.
Open-source versus closed modelsControl over hosting, residency, and cost curve, against best-in-class quality with zero infrastructure.

Pillar 2 · RAG and Retrieval

Developed in Chapter 2.

TermDefinition
EmbeddingA vector representation where semantic similarity becomes geometric proximity. Model-specific, so changing it means re-embedding everything.
Vector searchApproximate nearest-neighbour lookup over embeddings, trading recall against latency and memory.
Vector databaseAn index plus filtering, updates, persistence, replication, and multi-tenancy. The boring parts decide your design.
ChunkingSplitting documents into retrievable units. Structure-aware splitting beats fixed character counts.
Chunk overlapRepeating a tail of one chunk at the head of the next so boundary-spanning facts survive. Blunt and index-inflating.
Metadata filteringRestricting retrieval by tenant, source, date, or type. Ask whether it is applied before or after the search.
Hybrid searchRunning keyword and semantic retrieval together and fusing the ranked lists, because their failure modes are complementary.
Keyword searchLexical matching, typically BM25. Still the strongest option for exact identifiers, error codes, and rare terms.
Semantic searchDense retrieval matching meaning rather than surface form. Handles paraphrase, struggles with rare literals.
RerankingScoring query and document jointly over a short candidate list. Accurate, expensive, applied last.
Retrieval recallFraction of relevant documents that reached the candidate set. The ceiling on the entire system.
Retrieval precisionFraction of retrieved documents that are relevant. Low precision costs tokens and actively degrades answers.
Query rewritingExpanding, disambiguating, or decomposing the query before retrieval. Adds a model call to the critical path.
Document freshnessThe staleness policy of your index, including how deletions propagate and how fast.
Permission-aware retrievalAuthorisation applied inside the retrieval query, per request, against live permissions. Never a post-filter.
Citation groundingEach claim traceable to a retrieved span, emitted as part of structured output rather than reconstructed after.
Evidence selectionDeciding which retrieved candidates survive into the prompt: deduplicate, drop the tail, cap per source.
Context packingThe physical layout of the final prompt. Strongest evidence at the edges, because the middle is where accuracy drops.
Missing information detectionRecognising that retrieval returned nothing relevant and abstaining instead of guessing fluently.

Pillar 3 · AI System Architecture

Developed in Chapter 3.

TermDefinition
API gatewayAuth, validation, quota, and rate limiting at the edge. For AI, quota is denominated in tokens.
Request routingChoosing which pipeline serves a request, keeping expensive machinery off simple requests.
Model gatewayOne internal interface in front of every model, owning routing, failover, token accounting, and logging.
Prompt serviceVersioned prompt templates served centrally, so a prompt change ships and rolls back like code.
Inference serviceWhere generation runs, whether a vendor API or your own GPU serving stack.
Retrieval serviceSearch as its own service with its own scaling profile, cache, and quality metrics.
Ranking serviceReranking as a separate hop, so it can be degraded under load instead of failing the request.
Feature storeServes identical feature values to training and inference, preventing training-serving skew.
Offline pipelinesIngestion, chunking, embedding, index building, and evaluation runs. The half candidates forget to draw.
Online servingThe synchronous request path, bounded by an explicit latency budget.
Async processingLong work returns a job id and notifies on completion. Anything duration-scaling belongs here.
QueueingAbsorbing burst and prioritising expensive work. Always answer with max depth, timeout, and what the user sees.
Streaming responsesEmitting tokens as generated. Improves perceived latency; complicates retries and output guardrails.
Rate limitingLimits on tokens per minute as well as requests per minute, because request counts do not bound cost.
Fan-out and fan-inParallel branches merged into one answer. Multiplies cost and makes the slowest branch your latency.
Batch inferenceHigh-throughput offline processing where latency does not matter and the rate is lower.
Real-time inferenceThe interactive path, judged on time to first token.
Human-in-the-loopA first-class path with a queue, a reviewer interface, an SLA, and feedback flowing back into evaluation.
Fallback workflowThe ordered ladder used when the primary path fails, ending in an honest error rather than a fabrication.

Pillar 4 · Cost and Performance

Developed in Chapter 4.

TermDefinition
Token budgetingExplicit allocation of the context window across instructions, evidence, history, and answer reserve.
Prompt compressionSending less: summarised history, trimmed boilerplate, dropped low-scoring chunks.
Prompt cachingReusing the processed prefix across requests. Makes prompt layout an optimisation target.
Semantic cachingServing a stored answer when a new query is semantically close. Risks confidently wrong cache hits.
Response cachingExact-match caching on a normalised request. The cache key must include model, prompt version, and permissions.
Batch requestsGrouping independent work for a lower rate, trading latency for cost.
Model quantizationLower-precision weights for memory and throughput, with a task-dependent quality cliff you must measure.
DistillationTraining a small student on a large teacher's outputs to transfer narrow-task behaviour cheaply.
Latency budgetThe end-to-end target split across hops, allocated at the tail rather than the mean.
Cold startThe delay of loading model weights onto an accelerator, which makes scale-to-zero unattractive for interactive paths.
GPU utilizationBusy time, not useful work. Pair it with tokens per second per accelerator or it misleads.
ThroughputTokens produced per unit time, raised sharply by continuous batching and paged KV cache management.
Cost per queryInput tokens times input price plus output tokens times output price. The unit that makes architecture arguable.
Cost per userCost per query times usage. Watch the distribution, because heavy users dominate spend.
Model selectionChoosing the model per request against a measured quality bar, not per product by preference.
Inference scalingScaling on queue depth and token throughput, constrained by accelerator availability as much as by policy.
BackpressurePushing overload upstream with bounded queues and admission control instead of absorbing it invisibly.
Load sheddingDropping work by priority under overload. In AI systems you can shed quality before you shed requests.

Pillar 5 · Evaluation and Quality

Developed in Chapter 5.

TermDefinition
Offline evalsScoring a fixed dataset in continuous integration before release. The gate that makes changes shippable.
Online evalsMeasuring production traffic through implicit user signals and sampled automated scoring.
Golden datasetCurated inputs with known-good outputs, covering the common path, known failures, and past incidents.
Human reviewThe ground truth everything else calibrates against, with a written rubric and measured annotator agreement.
LLM-as-judgeA strong model scoring outputs against a rubric. Useful at scale, biased by position and verbosity, needs calibration.
A/B testingThe only reliable attribution of a production quality change to a system change.
Regression testingLocking fixed failures into the evaluation suite, since prompt and model changes regress untouched behaviour.
Answer relevanceWhether the response addresses the question asked. Weakness here usually means a query-understanding failure.
Factual accuracyWhether a claim is true of the world. Scale alone does not improve it and can worsen it.
FaithfulnessWhether every claim is supported by the retrieved context. The metric that catches the worst RAG failure.
GroundednessWhether each statement traces to a specific cited span a user could verify.
Toxicity checksIndependent classifier screening of inputs and outputs for abusive or harmful content.
Safety checksBroader policy conformance across regulated topics and brand constraints, reported alongside accuracy.
Drift detectionAlerting on movement in input distribution, retrieval scores, refusal rates, and output length over time.
Feedback loopsUser signals shaping evaluation shaping the system shaping user behaviour. Keep an untouched holdout.
Confidence scoringA calibrated ensemble of retrieval, grounding, and judge signals. Token probability alone is a poor proxy.
Escalation criteriaWritten, testable thresholds at which the system stops answering and hands off to a human.
Quality monitoringDashboards sliced by tenant, locale, and query type, because aggregates hide segment collapse.

Pillar 6 · Reliability and Security

Developed in Chapter 6.

TermDefinition
TimeoutsPer-hop limits derived from the latency budget. Bound output length or generation time stays unpredictable.
RetriesBackoff with jitter on transport failures. Expensive here, because a retry re-runs a costly generation.
Circuit breakerStop calling a degraded dependency and fail fast. Trip on latency as well as errors, since providers fail slowly.
FailoverSwitching region or provider. An untested failover model is not a failover model.
Model fallbacksThe ordered quality-for-availability ladder: primary, secondary, smaller, cached, search-only, honest error.
Graceful degradationServing something useful under stress by shedding quality before capacity.
Error budgetAn explicit allowance for unreliability. Refusals and abstentions are correct behaviour, not errors.
ObservabilityBeing able to reconstruct any past response: prompt version, model, retrieved documents, tools, tokens, cost.
TracingOne span tree per request across gateway, retrieval, rerank, model, and tools, using standard attribute names.
Prompt logsEssential for debugging and a privacy liability. Redact at capture, set retention, control access.
Token metricsTokens per request by tenant, feature, and model, plus cache hit rate. Cost, capacity, and abuse signal at once.
PII redactionMasking personal data before the model or the log. Before the model protects the vendor boundary but can cost quality.
Data privacyWhere data goes, who sees it, how long it is kept, whether it trains a model, and how deletion works.
Access controlAuthorisation over retrieval, tools, and actions. The system acts as the user, never as a privileged service.
Prompt injectionInstructions hidden in content the model reads. No complete fix, so bound the authority rather than the wording.
Jailbreak defenceLayered input and output classifiers. Refusal training is not a security boundary; attacks transfer across models.
Audit logsTamper-evident records of consequential events, distinct from prompt logs in purpose, retention, and access.
ComplianceSector rules plus AI-specific regulation, influencing logging, human oversight, and transparency requirements.
