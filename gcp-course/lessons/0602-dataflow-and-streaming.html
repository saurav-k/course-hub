One pipeline model covers a finished file and a stream that never ends

working 8 min Capabilities etl-service, stream-analytics and stream-ingest. Sourced from Dataflow and Managed Service for Apache Kafka.

The one-minute version

  • Dataflow runs Apache Beam pipelines as a managed serverless service, and the same programming model covers batch and stream.
  • Three properties make the unbounded case tractable: windowing, triggers, and exactly-once semantics.
  • Because of those, stream analytics has no separate product on this platform. Dataflow already is it.
  • Streaming Engine and flexible resource scheduling are the two execution options a Dataflow design chooses between.
  • Events reach a pipeline through Managed Service for Apache Kafka for Kafka-protocol workloads, with Pub/Sub as the platform's native alternative.

1. Bounded and unbounded, one model

2. What windowing is answering

Dataflow's third property is exactly-once semantics, which is what stops a retried element from being counted twice. Together the three are why the verified inventory records the stream-analytics row as delivered by Dataflow rather than missing: everything a dedicated streaming product would supply is already in the pipeline model.

3. Where the events come from

Managed Service for Apache Kafka exists for the ecosystem rather than for the semantics. Pub/Sub is the platform's native messaging service and module 12 covers it in its own right; naming it here matters only so that a Kafka choice is made because something needs the protocol.

The reframing The question "batch or streaming" is usually asked too early. On this platform it is a question about the source, not about the tool, the language or the team. Write the transforms once, decide whether the source has an end, and let windowing and triggers carry the difference.

Answer from memory before revealing.

Why does stream analytics have no product of its own on Google Cloud?
The row is delivered by Dataflow, whose windowing, triggers and exactly-once semantics are exactly what a streaming product would provide. The first names an ingest path rather than an analytics engine. The second asserts an absence that is false. The third gives the broker a role it does not have here.
What problem do windows solve that does not arise with a bounded source?
Without an end there is nothing to aggregate over, and a window supplies that set. The first names a real concern that applies to both. The second invents a schema difference. The fourth describes ordering, which is a different problem from having no boundary at all.
When does Managed Service for Apache Kafka earn its place over the native alternative?
The inventory records the service as being for Kafka-protocol workloads and ecosystem lift-in, so compatibility is the reason. The first names a Dataflow property that is unaffected by the choice. The third and fourth are downstream concerns that neither broker decides.

Practice about 15 minutes, with paper

Practice 1working

A team loads a daily file of transactions into BigQuery with a Beam pipeline. The business now wants the same aggregates within a minute of each transaction, and the payment gateway can publish events as they happen. The gateway's client library speaks the Kafka protocol and cannot be changed this year.

Say what changes in the pipeline and what does not, choose the ingest service with a reason, and name the two behaviours the team must now specify that the daily job never needed.

Hint

One part of this is almost free because of the programming model. Another part is not free at all, and it is the part the daily file answered implicitly by ending.

Show the worked solution
  1. Say what does not change. The transforms. Beam's model covers bounded and unbounded sources with the same pipeline, so the parsing, the joins and the aggregation logic carry over rather than being rewritten for a streaming tool.
  2. Say what does change. The source becomes unbounded, so the pipeline runs continuously instead of finishing, and Dataflow executes it as a streaming job with the execution options that suit that shape.
  3. Choose the ingest. The gateway cannot be changed and speaks the Kafka protocol, so Managed Service for Apache Kafka is the answer, and it is chosen for protocol compatibility rather than for any processing property. Pub/Sub would have been the native choice had the producer been free.
  4. Name the two new behaviours. A window, because an aggregate over an endless stream needs a defined set to be over, and a trigger, because something has to decide when the team stops waiting for late arrivals and emits the result. The daily file answered both implicitly - the window was the day and the trigger was the file ending.

Sanity check. Your answer should have kept the transforms and added exactly two specifications. If you found yourself choosing a new processing engine, re-read the first figure - the point of the unified model is that this migration does not need one.

Your teacher. If a streaming requirement is vague, ask an agent one question on your behalf: how late can an event arrive and still count. The answer is the trigger, it is a business decision rather than an engineering one, and a pipeline built without it will make the choice silently.
