Four shapes of message, told apart by who is on the other end

working 8 min Capabilities pub-sub, message-queue, event-bus, realtime-messaging and mqtt-broker. Sourced from Pub/Sub and Eventarc.

The one-minute version

  • Pub/Sub is the global publish-and-subscribe service: topics and subscriptions delivered by pull, push or straight into BigQuery, with ordering keys, exactly-once delivery, schemas and seek-based replay.
  • Cloud Tasks is the deferred-work primitive: queues with per-queue rate and dispatch control and retries. The inventory is candid that a Pub/Sub pull subscription is the closer classic queue.
  • Eventarc is the event bus: standardised CloudEvents from many sources to Cloud Run, functions, Workflows and GKE - including events derived from audit logs.
  • Pub/Sub has no browser transport. Fan-out to browsers and devices is done by database listeners, where clients subscribe to a path or a query rather than to a topic.
  • There is no first-party device broker. The retired IoT service is not replaced, and Google directs customers to partner platforms feeding Pub/Sub.

Two more properties shape designs. Ordering keys give per-key ordering rather than global ordering, so a design has to choose a key that means something. Schemas make the message contract explicit, which is the difference between a topic that can be evolved and one nobody dares change.

The reframing Ask what the receiver is and what it needs. Many services, replayable is Pub/Sub. One handler that must not be overwhelmed is Cloud Tasks. A runtime reacting to something the platform did is Eventarc, and audit logs are a source. A browser is a database listener, because there is no topic a browser can subscribe to here.

Answer from memory before revealing.

A browser must receive updates as they happen. What does this platform offer?
Pub/Sub has no browser transport, and the managed fan-out is through the database's own listeners. The first and second give a browser a transport neither product has. The fourth is the over-reading of a packaging difference - the capability is provided, by a different kind of product.
A downstream system can accept only a limited number of calls per second. Which service protects it?
Per-queue rate and dispatch control is the documented reason to reach for Cloud Tasks. The second gives ordering rather than a rate limit. The third invents throttling. The fourth changes the destination entirely.
What does the inventory record about a managed device broker on Google Cloud?
The retired service has no first-party successor, and the documented route is a partner platform feeding Pub/Sub. The first and third stretch two services beyond what the inventory records. The fourth invents the replacement.

Practice about 15 minutes, with paper

Practice 1working

A logistics platform needs four things. Every parcel scan must reach an analytics table and two services, and must be replayable if a consumer has a bug. Customer notifications go through an external provider that accepts a limited number of calls per second. A dashboard in the browser must show parcel movements live. And a compliance team wants an automation to run whenever somebody changes a firewall rule.

Choose a service for each, name the property that decides each choice, and say which one depends on something from module 10.

Hint

Four requirements, four products, one each. The last one is not a message your application sends.

Show the worked solution
  1. Parcel scans. Pub/Sub. One topic with three subscriptions - a BigQuery subscription for the table, needing no consumer, and one for each service. The deciding property is seek-based replay, which is what makes a consumer bug recoverable.
  2. Notifications through the rate-limited provider. Cloud Tasks. Per-queue rate and dispatch control is what protects a receiver that cannot be scaled, and retries per queue handle the failures a rate limit causes.
  3. The live browser dashboard. Database listeners on Realtime Database or Firestore. The deciding property is transport - Pub/Sub cannot reach a browser - and the subscription unit becomes a path or a query rather than a topic.
  4. The firewall-rule automation. Eventarc, triggered from the audit-log source, delivering a CloudEvent to Cloud Run, a function or Workflows.
  5. Name the module 10 dependency. The fourth. A firewall rule change is an Admin Activity audit entry, which is always on and free - so this one works out of the box. Had the requirement been about a data read instead, it would have needed Data Access logging enabled first, and would have silently done nothing until it was.

Sanity check. All four answers should be different products, and the browser one should not be Pub/Sub. If the fourth answer was a scheduled job that polls for changes, compare its latency and cost with a trigger that fires on the event itself.

Your teacher. When a design says "we will publish an event", ask an agent who the receivers are, whether any of them is a browser, and whether any of them can be overwhelmed. Those three answers select the product, and the answer people reach for by default is right about half the time.
