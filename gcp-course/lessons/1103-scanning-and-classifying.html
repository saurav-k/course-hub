Module 11 · Security services · Lesson 1103

Scanned before it ships, after it runs, and wherever the data sits

working 8 min Capabilities vulnerability-scanning, data-classification, ai-safety-guardrails and verified-permissions. Sourced from Artifact Analysis and Sensitive Data Protection.

The one-minute version

  • Artifact Analysis produces vulnerability metadata for containers and packages on push into Artifact Registry, and that severity can feed a Binary Authorization policy.
  • Web Security Scanner is the other half of the pair: it crawls the running application and finds what only a live site shows - cross-site scripting, mixed content, cleartext issues.
  • Sensitive Data Protection inspects, classifies and de-identifies personal data across Cloud Storage, BigQuery and streams, with discovery profiles that automate the cataloguing.
  • De-identification is a template rather than a deletion: tokenisation and masking transform values so a dataset stays usable while the original is not exposed.
  • Model Armor screens prompts and responses for model endpoints. The inventory records it as preview and says to verify the stage before teaching it as settled.

1. Two scanners, two moments

The push-time scan is the one with a lever attached: its severities can be consumed by Binary Authorization, which admits only images that satisfy a policy. Module 12 covers that gate, and this is the page where the evidence it acts on is produced.

2. Finding the data, and changing it

This is also where lesson 0604's policy tags meet their input: the catalogue can hold the classification and the warehouse can enforce column-level security from it, so classification and enforcement are two products doing two halves of one job.

3. The newest surface, and the row with no product

Model Armor is recorded in the verified inventory as preview, with an explicit instruction to confirm the stage before treating it as settled. Nothing here states it as generally available. Check the product documentation before a design depends on it.
The reframing Ask when the inspection happens and what exists at that moment. At push time an image exists and an application does not, so you can see dependencies and not behaviour. At run time the application exists, so you can see behaviour and not what is inside the layers. At rest the data exists, and it is the only moment at which you can find out what you are actually holding.

Check yourself

Retrieval practice

Answer from memory before revealing.

An image passes its push-time scan and the running application still has a cross-site scripting flaw. What explains it?
The two scanners see different things because they act at different moments, and behaviour is only visible once the application runs. The first invents a configuration gap. The second moves it to the wrong category. The fourth would be a real possibility and does not explain why a crawler is needed at all.
What does de-identification give a team that deleting the sensitive columns does not?
Tokenisation and masking transform values so analysis still works on the shape of the data. The first is an audit-log function. The third overstates what these templates promise. The fourth describes classification, which is a different verb on the same product.
An application needs to decide whether a given user may edit a given invoice. What does the inventory record?
Application-level authorisation has no managed product here, and the boundary is what IAM governs. The first stretches IAM to objects it does not know about. The second confuses classification with authorisation. The third names the directory the user came from, which authenticates rather than authorises.

Practice about 15 minutes, with paper

Practice 1working

A team ships containers to Cloud Run, holds customer records in BigQuery, and is adding a feature that sends customer text to a model endpoint. A review asks four things: that vulnerable images cannot reach production, that the live application is tested for common web flaws, that the analytics team works without seeing raw personal data, and that only a record's owner can edit it.

Assign a mechanism to each, name the one whose stage you would check before relying on it, and identify the requirement no Google Cloud product answers.

Hint

Four requirements, and one of them has no product on this platform at all. Another mentions a moment rather than a tool - which is what selects between the two scanners.

Show the worked solution
  1. Vulnerable images cannot reach production. Artifact Analysis produces the severities on push, and Binary Authorization from module 12 is the gate that refuses images failing the policy. The scan alone reports; the gate is what makes "cannot" true.
  2. Testing the live application. Web Security Scanner, crawling the running Cloud Run service. This finds what the image scan cannot see, because the flaw exists in how the assembled application behaves.
  3. Analytics without raw personal data. Sensitive Data Protection: discovery profiles to find where the data is, then a de-identification template applying tokenisation or masking so the analytics dataset is usable. Pair it with policy tags from lesson 0604 for column-level enforcement on the source.
  4. Screening the model feature. Model Armor screens prompts and responses, and it is the item whose stage to check - the inventory records it as preview, so a design should confirm before depending on it.
  5. Only the owner may edit a record. Nothing here answers this. There is no managed application authorisation service, because IAM governs Google Cloud resources rather than your application's own objects. This logic is yours to build and to test.

Sanity check. Four of the five items should map to a product and one should map to your own code. If the ownership rule was answered with IAM conditions, ask what resource the condition names - an invoice is not one IAM knows about.

Your teacher. For a scanning requirement, ask an agent at what moment the thing being looked for comes into existence. A dependency exists at build time, a behaviour at run time, and a record of what you hold only once the data is written - and that answer picks the product without a feature comparison.
