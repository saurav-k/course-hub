A gateway in front of a service, or a platform around an estate of APIs

working 7 min Capabilities api-gateway, api-management-enterprise and graphql-api. Sourced from API Gateway and Apigee.

The one-minute version

  • API Gateway is driven by an OpenAPI or gRPC configuration and fronts serverless backends. Quotas and token validation are built in, so a small API gets them without code.
  • Apigee is the full API lifecycle platform: policies, mediation, a developer portal, monetisation and analytics, with its own billing and environment-group model.
  • The line between them is not traffic volume. It is whether the APIs are a product with consumers to manage, or a service that needs a front door.
  • There is no managed GraphQL service. GraphQL is served from Cloud Run or App Engine, and can be fronted by Apigee.
  • Both sit in front of runtimes from module 03 and behind the edge from lesson 0705, so an API design has three layers to place rather than one.

The reframing Place an API in three layers rather than one. The edge from lesson 0705 terminates TLS and applies edge protection. The API layer here validates tokens, applies quotas and routes. The runtime from module 03 executes. Requirements arrive mixed together, and sorting them into those three layers is what stops a team building rate limiting three times.

Retrieval practice

Answer from memory before revealing.

A small API is sold to external developers who must self-register and be billed. Which product fits?
The requirement names onboarding and revenue, which is a programme rather than a front door, and size is not the discriminator. The second uses volume to decide, which this page argues against. The third rebuilds a portal by hand. The fourth places consumer management at a layer that knows nothing about consumers.
What does API Gateway give a serverless backend without any gateway code?
Validation and quotas arrive with the configuration, which is the practical value of the simpler product. The other three are all Apigee capabilities, which is what makes them useful distractors - each is real, on the other product.
What does the inventory record for a managed GraphQL service on Google Cloud?
There is no managed service, and the documented answers are an ordinary runtime with an optional management layer in front. The first invents schema support in the configuration. The third is the over-reading of an absence. The fourth gives Apigee a resolver role it does not have.

Practice about 12 minutes, with paper

Practice 1working

A company exposes two things. An internal ordering API is called by three of its own services and needs authentication and a per-caller rate limit. A public data API will be offered to partner developers under a contract, with usage reporting and a plan to charge for it later. A team also wants to publish a GraphQL endpoint over both.

Place each of the three, say which requirement decides the second one, and state what the GraphQL endpoint loses that a per-resource API would keep.

Hint

Two products, three things to place. The second requirement is decided by a word about consumers rather than a number about traffic. The third has no product at all.

Show the worked solution
  1. The internal ordering API. API Gateway. The requirements are authentication and a quota, both of which arrive with an OpenAPI or gRPC configuration, and the callers are three services rather than a community to manage.
  2. The public data API. Apigee. Partner developers under a contract need a portal to register through, analytics to report usage, and a monetisation path for the charging that is planned. That is a programme around the API rather than a front door in front of it.
  3. Say what decides it. The consumers. Not the traffic, which may well be lower than the internal API's - the deciding words are partner developers, contract and usage reporting.
  4. The GraphQL endpoint. No managed service exists, so it is an application on Cloud Run or App Engine, optionally fronted by Apigee for the management layer.
  5. State what it loses. Granularity. A quota or an analytics report on one GraphQL endpoint counts operations against that endpoint, and cannot distinguish a cheap query from one that resolved a hundred fields. A per-resource API gets those controls per resource for free.

Sanity check. Your two API products should be split by audience rather than by volume, and your last answer should name a loss rather than an impossibility. If the GraphQL endpoint was placed on API Gateway, ask what in the configuration would describe a schema.

Your teacher. When a team asks which API product to use, ask an agent to list the consumers and how each one gets its credentials today. A short list of internal services and a long list of external developers select different products, and the answer rarely mentions request rates at all.
