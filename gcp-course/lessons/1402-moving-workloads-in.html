A migration is rehearsed on a clone before anything is cut over

working 7 min Capability migration-service. Sourced from Migrate to Virtual Machines.

The one-minute version

  • Migrate to Virtual Machines moves machines into Compute Engine from AWS, Azure, vSphere and physical hardware, in waves rather than one at a time.
  • Its defining feature is the test clone: a copy is brought up and exercised while the source keeps running, so the cutover is rehearsed rather than attempted.
  • Migrate to Containers is the variant that lifts a machine's workload onto GKE instead of onto a virtual machine, which changes the destination runtime rather than the source.
  • Databases are deliberately out of scope. Database Migration Service from lesson 0504 covers those, and its ending - a promotion - is a different operation from a wave cutover.
  • So a real migration programme runs two services with two kinds of ending, and the sequencing between them is the plan.

The reframing A migration plan is three lists, not a tool choice. Which machines move together is the wave list. What was learned from each clone is the defect list, and it should be shrinking before anybody schedules a cutover. Which endings happen in which order is the sequencing list, and it is where the machine service and the database service meet.

Retrieval practice

Answer from memory before revealing.

What does a test clone let a team do that a cutover does not?
The source stays live, so the clone can be tested and discarded repeatedly before anything is committed. The second describes wave membership. The third invents a reverse path. The fourth crosses into the service that is deliberately separate.
Why does a migration programme usually involve two services?
Databases are out of scope for the machine service and covered by the database migration service, whose ending is a promotion. The first and second invent a division of labour. The fourth describes a variant of the same product rather than a second service.
What does Migrate to Containers change relative to the virtual machine path?
It changes where the workload lands and not where it comes from. The first reverses that. The third and fourth invent behaviours the inventory does not record for it.

Practice about 12 minutes, with paper

Practice 1working

A company is leaving a data centre. It has forty virtual machines on vSphere, of which six are application servers that talk to one PostgreSQL database, and two are a reporting pair that reads that database nightly. The programme has one weekend of agreed downtime.

Group the machines, place the database, sequence the two endings, and say what the team should have done every week before that weekend.

Hint

The grouping question is answered by what talks to what. The sequencing question is about two one-directional operations and what happens between them.

Show the worked solution
  1. Group the machines. The six application servers form a wave, because they share a database and each other's traffic and cannot be split across the move. The reporting pair can be a separate, later wave - it reads nightly, so it tolerates being behind the application for a period.
  2. Place the database. Not in either wave. Database Migration Service handles it, replicating continuously from the source while the source stays authoritative.
  3. Sequence the endings. Promote the database first, then cut over the application wave to point at it - or cut over and promote in one closely held window. Both operations are one-directional, and the question the plan must answer is what the application does in the gap between them, however short.
  4. Place the reporting pair. After both, since it reads the database and has no live traffic of its own to lose.
  5. Say what the weekly work was. Test clones. Bring up the application wave as a clone, run it against a copy of the database, find what breaks, fix it, and throw the clone away. Doing that every week means the weekend is an execution of a rehearsed procedure rather than the first time anyone has seen these six machines run here.

Sanity check. Your answer should have three groups - one wave, one database, one later wave - and the weekly work should have cost nothing but the clones, because the source was never touched. If the plan had the database inside a wave, note that the machine service does not migrate it.

Your teacher. Ask an agent how many times the target environment has been brought up and exercised before the cutover date. Zero is the answer that predicts a bad weekend, and the test clone is the feature that makes any other answer cheap.
