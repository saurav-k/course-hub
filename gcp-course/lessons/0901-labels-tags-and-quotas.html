Labels let you see it, tags let you police it, quotas decide when you run out

working 8 min Capabilities resource-tagging, resource-tags-governance and quota-management. Sourced from tags and labels and quotas.

The one-minute version

  • Labels are key and value metadata for cost breakdown, filtering and automation triggers. They describe a resource and enforce nothing.
  • Resource Manager tags are governance-grade values referenced by IAM Conditions and organisation policy rules. They are the only one of the two a rule can read.
  • Both are key and value pairs on the same resources, which is why the confusion is so reliable - and lesson 0102 named it as one of the platform's standing traps.
  • Quotas are per-project limits in two shapes: a rate quota bounds calls over time, and an allocation quota bounds how many of something may exist at once.
  • Increases are requested through the console or the command line, and the inventory records that some increases need billing history.

1. Two key-value systems that are not interchangeable

Both are documented on the same tags overview, which is itself part of why they are confused. The practical rule is one sentence: if a machine has to decide something from the value, it must be a tag; if a human or a report has to read it, a label is enough.

2. Two shapes of limit

Quotas are per project, which makes the project from lesson 0101 the unit of blast radius here too. Increases are requested through the console or the command line, and the inventory records that some of them need billing history - which is why a brand-new project is the worst place to discover a limit.

3. Where each system is decided

The reframing Three questions, asked once per estate rather than once per project. What will finance need to slice the bill by? Those are labels. What will a rule need to read? Those are tags. Which limits will this workload approach, and is it a flow or a count? That is the quota conversation, and it is the only one of the three that has a lead time attached to it.

Check yourself

Retrieval practice

Answer from memory before revealing.

An organisation policy must apply only to resources marked as production. What must the marking be?
Only tags are governance-grade and referenceable from policy rules and IAM Conditions. The second reverses the two. The third is the trap this page exists for. The fourth denies targeting that the platform provides.
A deployment fails because a limit on how many of a resource may exist has been reached. Which quota kind is it, and what fixes it?
An allocation quota bounds a level, so it stays reached until something is deleted or the limit is raised. The first two misidentify the kind. The third identifies it correctly and then applies the rate-quota remedy, which is why it is the strongest distractor.
Why is a brand-new project a poor place to discover a quota limit?
The inventory records that some increases need billing history, which a new project lacks by definition. The first and second misstate how quotas are scoped and initialised. The fourth invents a project state that does not exist.

Practice about 12 minutes, with paper

Practice 1working

A platform team is writing its metadata standard. Finance wants the bill split by business unit and by environment. Security wants a rule that forbids external addresses everywhere except a named set of internet-facing projects. The launch team is building a new project that will create several thousand instances in one region during a migration weekend.

Assign each requirement to labels, tags or quotas, say what goes wrong if the security requirement is met with the wrong system, and name the one item with a lead time.

Hint

Two requirements are metadata and one is a limit. The metadata pair splits on whether a machine has to decide something from the value.

Show the worked solution
  1. Finance. Labels, keyed by business unit and environment. The requirement is a breakdown of a report, so nothing has to be enforced from the values, and labels are what cost reporting slices on.
  2. Security. Resource Manager tags marking the internet-facing projects, referenced by the organisation policy rule that forbids external addresses. Enforcement is the requirement, so it must be a tag.
  3. Say what goes wrong with the wrong system. If the exception is expressed as a label, the policy rule has nothing to reference. The likely outcome is worse than a broken rule: the team applies the constraint without the exception and breaks the internet-facing projects, or applies it nowhere and enforces nothing.
  4. The launch. An allocation quota on instances in that region for that project. Several thousand at once is a level, not a flow.
  5. Name the lead time. The quota increase. Some increases need billing history and a new project has none, so this is the item to raise weeks before the migration weekend rather than on it.

Sanity check. Your two metadata answers should differ, and the deciding question should be whether a rule reads the value. If all three requirements were met with the same system, one of them is unenforceable and one of them will fail on the night.

Your teacher. Before a migration weekend, ask an agent for the allocation quotas on every resource kind the migration creates, in the exact project and region it will create them. A rate quota will slow the work down, and an allocation quota will stop it.
