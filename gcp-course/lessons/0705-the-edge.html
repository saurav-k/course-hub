The front door is the load balancer with things attached to it

working 9 min Capabilities l7-load-balancer, l4-load-balancer, global-front-door, cdn, ddos-protection, authoritative-dns, private-dns and dns-routing-policies. Sourced from load balancing, Cloud CDN and Cloud DNS.

The one-minute version

  • There is no separate front-door product. The capability is the global external Application Load Balancer on Premium-tier anycast, with Cloud CDN and Cloud Armor attached at the same edge.
  • The global balancer terminates TLS at the edge point of presence nearest the user, routes with URL maps, and can take serverless backends directly.
  • Layer four is a family, not a product: passthrough balancers preserve the source address and proxy balancers do not, which is a behavioural difference rather than a performance one.
  • There is no transparent appliance-insertion balancer. Appliances are inserted with an internal passthrough balancer as the next hop plus policy-based routes.
  • Cloud DNS serves public and private zones with a 100% availability SLA, and its routing policies - weighted, geolocation, geofenced and health-checked failover - are the traffic-steering layer above everything else on this page.

1. One request, and everything it passes on the way in

The verified inventory records the front-door row as delivered by this combination rather than by a product with that name: the global external Application Load Balancer plus Premium-tier anycast plus Cloud Armor plus Cloud CDN. Nothing is missing; there is simply no single SKU to buy.

2. The balancer family, and the row nothing fills

Where an appliance has to inspect traffic in the path, the pattern is an internal passthrough balancer named as the next hop with policy-based routes steering traffic to it. That is an assembly rather than a product, and knowing it is an assembly is what stops a team searching for a balancer type that does not exist.

The reframing Read the edge as one attachment point plus a steering layer. The balancer is the attachment point, and caching, edge protection and TLS termination are things that hang on it. DNS is above all of it and decides which attachment point a client reaches. A question of the form "which product does X at the edge" almost always resolves to "which thing is attached to the balancer".

Practice about 15 minutes, with paper

Practice 1working

A public site serves users on three continents. Most requests are for images and static pages, a small share are personalised, and a regulator requires that requests from one country are served only from that country. The security team wants abusive traffic dropped before it reaches any backend, and the fraud team wants the client address recorded in the application logs.

Assemble the edge, place each requirement at the point in the path where it is satisfied, and name the requirement that pulls against the rest of the design.

Hint

Work down the sequence diagram. Three requirements land cleanly at three different points, and the fourth conflicts with the very first choice.

Show the worked solution
  1. Choose the entry point. The global external Application Load Balancer on Premium-tier anycast. TLS terminates at the point of presence nearest each user, which is the property that serves three continents from one address.
  2. Place the caching. Cloud CDN attaches to that balancer, so images and static pages are answered at the edge. The personalised share is controlled by Cache-Control on the responses rather than by a setting on the cache, which is where this usually goes wrong.
  3. Place the residency requirement. Cloud DNS geofenced routing sends clients in that country to an address serving only from there. It is placed before the request exists, which is the only place a residency rule can be enforced by steering rather than by refusal.
  4. Place the abuse control. A Cloud Armor policy on the balancer, evaluated at the same edge, so abusive requests are dropped before any backend is reached. Standard always-on defence covers layers three and four beneath it.
  5. Name the conflict. The fraud team's requirement. The global balancer is a proxy, so the backend does not see the client address as the source, and recovering it means reading what the proxy forwards rather than reading the connection. A passthrough balancer would preserve it and would give up the edge entirely - the caching, the edge protection and the anycast entry all live on the proxy path.

Sanity check. Three requirements should have landed at three different points of the sequence diagram, and exactly one should have created a trade-off. If your answer switched to a passthrough balancer for the fraud team, count what the other three requirements lost.

Your teacher. When a cached page is stale or a private page is cached, ask an agent for the Cache-Control header the application sends before touching anything on the cache. The header is the control surface, and the cache is usually behaving exactly as instructed.
