The agent platform is real, and none of its names has settled

frontier 7 min Capability agent-platform. Sourced from the agent platform overview.

The one-minute version

  • The platform provides three surfaces: somewhere to build an agent, a runtime to run it in, and a search surface for it to ground on, with an enterprise-facing interface over them.
  • The verified inventory records it as preview, and describes it as a naming hotspot: the runtime, the search product and the platform itself all appear under more than one name in current material.
  • Underneath the branding, an agent on this platform is made of things earlier modules already taught: a model, a retrieval step, a runtime, and an identity.
  • That identity is a recorded absence. There is no distinct agent identity object - agents run as ordinary service accounts, so their lifecycle and their human sponsor are not modelled by the platform.
  • The safe way to design here is to pin the mechanism and not the name, and to keep the agent's permissions as small as any other principal's.

3. What an agent is made of

Module 08 recorded the absence that follows from this. There is no distinct agent identity object, so the platform does not model an agent's lifecycle or record which human sponsors it. That bookkeeping belongs to your own documentation, and it is worth starting it before the second agent exists rather than after the twentieth.

The reframing Design an agent as three decisions you already know how to make. Which model - a configuration value, from lesson 1300. What it retrieves and from where - lesson 1302, and the place quality actually comes from. What it may do - a service account with the smallest set of bindings that works, judged by the chain in lesson 0800. The platform's name is the fourth thing, and it is the one you should not build a dependency on.

Practice about 12 minutes, with paper

Practice 1frontier

A team wants an internal agent that answers staff questions from company documents and can also raise a ticket in an internal system. A draft design names the platform's product in three places, gives the agent the editor role on the project so it can raise tickets, and says nothing about who owns it.

Assess each of those three choices, replace the permission decision with a defensible one, and say what the team must record themselves because the platform will not.

Hint

One of the three choices is a documentation problem, one is a security problem, and one is the absence this page ends on.

Show the worked solution
  1. The product name in three places. A documentation problem with a real cost. This area is a naming hotspot and the pages have been retitled, so a design that names the product will read as wrong within a short time. Describe the mechanism - the runtime, the retrieval surface - and link the current page once.
  2. The editor role. A security problem, and a large one. The agent is an ordinary service account, so it is judged by the chain in lesson 0800, and a broad grant at project level is a union that nothing narrower subtracts. It also inherits every hazard of an agent acting on a prompt somebody supplied.
  3. Replace it. A dedicated service account for this agent, granted only the specific permission needed to create a ticket on the specific resource, with a condition if the ticketing system's resources support one. Read access to the document corpus, and nothing else. Then screen the prompts and responses with the guardrail product from module 11, whose stage is itself worth checking.
  4. Say what to record. Ownership. There is no distinct agent identity object, so nothing on the platform records that this agent exists, what it is for, or which human sponsors it. That register is the team's own, and it is what makes it possible to review or retire the agent later.

Sanity check. Your permission answer should name one action on one resource rather than a role, and your last answer should be a document rather than a product. If the design still names the platform product in prose, imagine reading it after the next rename.

Your teacher. Before an agent goes anywhere near production, ask an agent of your own to list the exact permissions its service account holds, and compare that list with the actions it actually needs to take. The gap is the blast radius of every prompt anyone will ever send it.
