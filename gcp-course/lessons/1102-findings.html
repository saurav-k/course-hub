Two kinds of finding, and only one of them is happening now

working 8 min Capabilities threat-detection, posture-management and security-investigation-graph. Sourced from Security Command Center threats and the posture service.

The one-minute version

  • Posture management assesses configuration continuously: misconfigurations, attack-path simulation, and a security health score. Its findings describe a state.
  • Event Threat Detection looks for anomalies in the logs the platform is already producing - crypto mining, data exfiltration, brute force. Its findings describe an event.
  • Because it reads logs, threat detection inherits every default from module 10. A stream that was never enabled produces no detections.
  • There is no separate security investigation graph product. The capability is delivered inside Security Command Center Enterprise, which folds in case management and attack-path analysis.
  • Two neighbours are worth naming: Cloud Armor Adaptive Protection covers volumetric attacks at the application layer, and the older Cloud IDS is retiring.

Two nearby facts are worth carrying so nothing is designed around them by mistake. Cloud IDS is retiring, so a new design should not start there; check its current status on the vendor documentation. And volumetric attacks at the application layer are covered by Cloud Armor Adaptive Protection rather than by threat detection, so the two products cover adjacent ground and neither substitutes for the other.
The reframing Read every finding by asking two questions in order. Is this a state or an event - which decides whether it goes to a backlog or to an on-call engineer. Then, for a state, does it sit on a path to something valuable - which decides where in the backlog it goes. Severity alone answers neither question, and it is the field most teams sort by.

Practice about 15 minutes, with paper

Practice 1working

A security team inherits a console with 1,800 open findings and a mandate to reduce risk this quarter. The findings are sorted by severity. The estate enabled no network streams and no Data Access logging. Nobody can say whether any of the open items represents something currently happening.

Split the queue, choose an ordering for the part that is a backlog, name what the team must enable before the other part is meaningful, and say what the count of 1,800 does not tell them.

Hint

The first move is the distinction this page opens with. The second is on the page too and is not severity. The third is a debt from module 10.

Show the worked solution
  1. Split the queue. Separate posture findings, which describe a state, from threat findings, which claim an event occurred. The first group is a backlog to schedule; the second is triage, and anything in it may be live.
  2. Order the backlog. By attack path rather than severity. Two medium findings that chain into a route to a production dataset outrank an isolated high one, and the simulation is what produces that ordering.
  3. Name what must be enabled. The telemetry. Event Threat Detection reads the logs that exist, so with no network streams and no Data Access logging the threat half of the console is close to blind. Enabling those streams - scoped, as lesson 1002 argued - is a prerequisite for the second queue to mean anything.
  4. Say what the count hides. Three things. How many of the 1,800 are events rather than states. How many sit on a path to anything valuable. And how many categories of finding are absent entirely because their input stream was never collected - which is the number nobody can see, and the reason a falling count is not by itself evidence of falling risk.

Sanity check. Your answer should have produced two queues with different handling, and the ordering of the backlog should not be severity. If the plan started by working down the list, note that the fastest way to reduce the count is to close the ones that lead nowhere.

Your teacher. Ask an agent to split an open findings list into state findings and event findings before anything else. The two halves want different people, different urgency and different tools, and one console showing them together is what hides that.
