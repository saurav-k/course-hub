Every network stream is off, and the flow log is an estimate

frontier 9 min Capabilities network-flow-log, firewall-rules-log, nat-logs, load-balancer-access-log, dns-query-log and service-specific-log. Sourced from VPC Flow Logs.

The one-minute version

  • All five network telemetry streams are off by default. Nothing about the network is being recorded until somebody enables it.
  • VPC Flow Logs are enabled at the organisation, VPC network, subnet, VLAN attachment or VPN tunnel scope. There is no per-machine scope.
  • Their byte and packet counts are interpolated estimates, not captures, aggregated over an interval that defaults to 5 seconds and can be set as high as 15 minutes.
  • There are two sampling layers. The first is dynamic and you cannot control it. The second defaults to keeping 50% when configured through the Compute Engine API and 100% through the Network Management API, which is the recommended path.
  • The other four are per-rule, per-gateway, per-backend-service and per-network toggles. DNS query logging does not record cached responses, so its counts undercount.

1. Five toggles, five different places

2. What a flow log actually is

Flow logs cover virtual machines and Cloud Run resources on direct network egress, and traffic through VLAN attachments and VPN tunnels. They land in Cloud Logging in the reporting network's project, which under Shared VPC is the host project rather than the team's. Generation charges are waived while the logs go to Logging, and the vended network-log storage rate applies.

No stream on this page captures packets. Flow logs never contain payload bytes, and packet-level capture is a separate feature - Packet Mirroring, which clones traffic to a collector and is not a log stream at all. Module 11 covers it. A requirement that says "capture the traffic" is not met by turning on flow logs, however complete they look in a console.

3. The other four, and the one that undercounts

Firewall rules logging is a per-rule flag and records the rule, the verdict and the connection tuple. Load balancer request logging is enabled per backend service with a configurable sample rate, and its records carry latency, cache status and the backend chosen. Cloud DNS query logging is set by a per-network server policy for private zones, with a separate toggle for public zones - and it carries a caveat worth holding: cached responses are not logged by default, so query counts systematically undercount.

4. What the services emit on their own

The research behind this course flags two rows of its own runtime-telemetry table as never verified: App Engine request-log behaviour, and the status of the legacy Cloud Storage usage and storage logs. Nothing about either is stated in this course. Treat them as leads to check against the vendor documentation rather than as established facts.
The reframing Two questions before any network investigation. Was the stream on - and for all five the honest default answer is no. What is the record actually made of - because a flow log is sampled twice and its counts are interpolated, so it answers "was there traffic between these two" well and "how many bytes exactly" not at all.

Check yourself

Retrieval practice

Answer from memory before revealing.

At what scopes can VPC Flow Logs be enabled?
Those five are the documented scopes and there is no per-machine one. The second is the assumption that makes a cost conversation go wrong. The third understates the range. The fourth confuses flow logs with firewall rules logging, which is a different stream on a different object.
A team compares two byte totals from flow logs and finds a discrepancy. What should they check first?
Byte and packet counts are interpolated rather than measured, and two sampling layers sit in front of them, so exact totals were never on offer. The first misdescribes what an interval does. The second invents double counting. The fourth names a real routing detail that does not change the totals.
Why do Cloud DNS query log counts systematically undercount?
A response served from cache does not produce a log entry by default. The first imports flow-log sampling into a stream that does not have it. The second is wrong - public zone logging has its own toggle. The third invents aggregation this stream does not do.

Practice about 15 minutes, with paper

Practice 1frontier

A security team is asked to answer three questions about last week. Did a machine in the payments subnet talk to an address outside the estate. What exactly was sent in that conversation. And was any connection to that machine refused by a firewall rule. The estate has never enabled any network stream.

Say for each question whether it can be answered, state what would have had to be enabled and at which scope, and identify the question that no log stream on this page would ever answer.

Hint

Two of the three are answerable in principle and not in fact, for the same reason. The third is not a logging question at all, and the warning on this page names what it is instead.

Show the worked solution
  1. Did it talk to an outside address. This is a flow-log question. It cannot be answered, because the stream was never enabled and there is no coarser background copy. Enabling it now records only the future.
  2. Name the scope. Flow logs on the subnet holding those machines, or on the VPC network, or at the organisation level - not on the machine, because no per-machine scope exists. And configured through the Network Management API, whose secondary sampling default keeps everything rather than half.
  3. Was a connection refused. This is firewall rules logging, a per-rule flag on the rules in question. Also not answerable for last week, and also enabled going forward only.
  4. What exactly was sent. This one is unanswerable in principle. Flow logs never contain payload bytes and no stream on this page captures packets. The capability exists as Packet Mirroring, which clones traffic to a collector and is not a log stream, and it would have had to be running at the time.
  5. State the lasting fix. The two enable-now decisions belong in the landing zone rather than in an incident, alongside the Data Access decision from the previous lesson - all three share the property that they only ever record the future.

Sanity check. All three answers about last week should be no, and exactly one of them should stay no even with unlimited budget and foresight about which stream to enable. If the payload question was answered with flow logs, re-read the warning - they carry no payload at any setting.

Your teacher. Ask an agent to list which of the five network streams are enabled today, and at which scope, across the whole estate. Most organisations cannot answer that from memory, and the answer is the ceiling on every network investigation they will ever run.
