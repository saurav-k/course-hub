Module 08 · Final delivery · Lesson 0810

A public repository is a promise that somebody else can reproduce your result

working 10 min Check names read from the OpenSSF Scorecard documentation at tag v5.5.0, and the model-card sections from Figure 1 of the paper that proposed them. · Scorecard checks

The one-minute version

  • A repository only you can start is a screenshot. Four artefacts carry the promise: the README, the environment, the licence and the system card.
  • A README that is all tutorial fails the reader who comes back. Four documentation modes exist and a first-run walkthrough is one of them.
  • “No licence” is a decision, and the decision is that nobody may use it. A repository with no licence file is not open in any sense that matters.
  • A system card is the honest version of a README's claims: what it is for, how it was evaluated, and where it fails. You did not train the model and you still owe one.
  • A stranger's tooling scores you whether you invited it or not. Twenty named checks, and four of them are things you can fix this afternoon.

1. A README that is all tutorial fails the second visit

Almost every first README is a walkthrough: clone this, set that, run this, see the output. It is the right thing to write first and it serves exactly one reader, once. The reader who comes back next month wants to know what a flag does, or why retrieval sits behind a tool call rather than in front of the model, and a walkthrough answers neither.

The Diátaxis framework, by Daniele Procida, is the sharpest available statement of why. It divides documentation into four modes - tutorials, how-to guides, reference and explanation - and it places them on two axes: whether the reader is acquiring a skill or applying one, and whether they need practical knowledge or theoretical knowledge. Those two axes make four quarters and the framework's claim is that there could not be three or five.

2. The environment: pinned, one command, no secret in the tree

Three properties, and each has a failure that is specific to this kind of project.

Pinned means a lockfile in the repository, not a range in a manifest. An AI project has a second thing to pin that an ordinary service does not: the model id. A repository that says it scored 0.68 on its golden set and does not name the model that scored it has recorded a number nobody can reproduce, including you next quarter.

One command means one, and the test of it is that the README contains a block a stranger can paste. If starting the system needs three terminals, write the script that needs one.

No secret in the tree is the property people believe they have. Check the history rather than the working copy: a key committed and then removed is still in the repository, and a public repository publishes every commit rather than the tip. An example file with the variable names and no values is what belongs in the tree.

3. The licence is a decision, and so is leaving it out

A repository with no licence file is not permissive by default. The default is the opposite: nobody may copy, modify or distribute it, so the reader you were trying to impress cannot legally run your example. The Scorecard tooling below has a check named exactly License, which looks for a published licence in the standard filenames, and it will report a zero.

There is a second decision underneath, and it is the one this course has been careful about all the way through: your corpus has a licence too, and it is not yours to relicense. A repository that ships a vector index built from documentation you do not own has redistributed that documentation in a form nobody can audit. Ship the loader and the corpus identity rather than the corpus, unless the corpus is something you may redistribute - which is the reason the fallback corpus this course offers is the hub's own content.

4. A system card, for a system you did not train

Mitchell et al. proposed model cards to make a trained model's intended use, evaluation and limitations legible, and Figure 1 of the paper lists nine sections: Model Details, Intended Use, Factors, Metrics, Evaluation Data, Training Data, Quantitative Analyses, Ethical Considerations, and Caveats and Recommendations.

You did not train anything, so four of the nine transfer almost unchanged and the rest need reading rather than copying. Intended Use is your charter from module 1. Metrics is the golden set and the score, with the k and the corpus version, which is the reporting rule this course has kept since lesson 0160. Evaluation Data is your thirty questions and where they came from - hand-written by you, or grown from real feedback in lesson 0430 - and that provenance is the difference between a set that can embarrass the system and one that cannot. Caveats and Recommendations is where the honest limits go: the question types you know it answers badly, and the corpus it has never seen.

Training Data is the interesting one, because the paper itself says it may not be possible to provide in practice. You have no training data and you do have a corpus, and naming the corpus, its version and its licence is the analogous fact. Call the file a system card rather than a model card. The distinction is honest and it is also a claim you can actually support.

5. The checks a stranger's tooling runs anyway

OpenSSF Scorecard reads a public repository and scores it against named checks with no cooperation from you. Read at tag v5.5.0, its documentation lists twenty: Binary-Artifacts, Branch-Protection, CI-Tests, CII-Best-Practices, Code-Review, Contributors, Dangerous-Workflow, Dependency-Update-Tool, Fuzzing, License, Maintained, Packaging, Pinned-Dependencies, SAST, SBOM, Security-Policy, Signed-Releases, Token-Permissions, Vulnerabilities and Webhooks.

Most of them are about a project with contributors and releases, which a capstone is not, and chasing the whole list is exactly the wrong use of an afternoon. Four are worth an afternoon: License, which is section 3 above; Maintained, which reads commit and issue activity and is honest about a repository you abandoned; Pinned-Dependencies, which asks whether a dependency is fixed to a hash rather than to a mutable version; and Token-Permissions, which asks whether your workflow tokens follow least privilege.

Two more deserve a mention because they are cheap and specific to a repository with a pipeline in it: Dangerous-Workflow looks for patterns like an untrusted checkout or a script injection in a GitHub Actions file, and a workflow that runs on a pull request from a fork and then executes its code is the shape it is looking for.

The Diátaxis framework is cited here by URL and nothing is quoted from it, because this hub requires a named licence before it reproduces somebody's words and the site's colophon names an author without naming a licence. The four modes and the two axes are facts about the framework rather than a reproduction of it. If you want its own wording, read it there.

Check yourself

Retrieval practice

Answer from memory before revealing.

Your repository is public and has no LICENSE file. What is the actual consequence?
Absent a licence, the default is that the copyright holder has granted nothing, so a reader who wants to run your example has no permission to. There is no permissive fallback. The Scorecard zero is a symptom rather than the consequence, and a platform's fork button is a feature of the platform rather than a grant of rights.
Which part of a model card transfers least directly to a system you assembled rather than trained?
You have no training data, and the paper itself notes this section may not be possible to provide in practice; the analogous fact is your corpus, its version and its licence. Metrics is the golden set and lands directly. Intended Use is the module 1 charter almost verbatim. Caveats is the section you are best placed to write, because you have read your own failures.

Practice about 45 minutes, plus a stranger

Practice 1working

Score the card above on your own default branch, fix the three lowest-scoring rows, then get a real measurement.

Find one person who has never seen it. Give them the URL and nothing else - no explanation, no help, no watching over their shoulder. Ask them to start a stopwatch at the clone and stop it at their first correct answer out of the system, and to write down every point at which they had to guess.

The list of guesses is the deliverable, not the time. Each guess is a sentence missing from one of the four quarters of section 1, and you now know which quarter.

Hint

Do not answer their questions while the stopwatch is running. A question you answer out loud is a question that stays missing from the README, and this is the only cheap chance you get to see it.

If you have nobody to ask, the next best thing is a fresh container with no cache and no credentials, and an agent given the URL and no other context. It will not be confused in the same places a person is, but it will find every missing command.

Show what a typical first run turns up
  1. The stopwatch stops at eighteen minutes, not eight. Nearly all of the overrun is one step: an environment variable named in no file, which they found by reading a traceback. That is a .env.example and one README line.
  2. Two guesses were about the corpus. They did not know what documents the system was supposed to answer about, so they could not tell a wrong answer from an out-of-scope one. That is the Intended Use section of the system card doing the work no README sentence was doing.
  3. One guess was a flag. They changed top-k because the answers looked thin, with no way to know that 10 was chosen by the sweep in module 2. That is the reference quarter, and one table fixes it permanently.
  4. The licence row scored zero and took four minutes to fix. It was the highest-weighted row on the card and the cheapest thing on the list, which is the usual shape of this exercise.

Sanity check. If your stranger finished with no guesses at all, they were not a stranger - they had context from you, from a conversation, or from having watched you build it. A genuinely cold reader on a first pass produces at least two or three, and a run that produces none has measured your explanation rather than your repository.

Your teacher. Ask your agent to read your repository and write the four sections of the system card that transfer, using only what is actually in the tree - then read what it wrote about your metric. If it could not state the k, the set size or the corpus version, that is not the agent guessing badly, it is your repository not recording them. Then ask it which of the four Diátaxis quarters each section of your README belongs in, and which quarter has nothing in it.
