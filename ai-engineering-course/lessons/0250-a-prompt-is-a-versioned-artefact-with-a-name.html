Module 02 · Retrieval quality and context engineering · Lesson 0250

Name the prompt, or the regression has no owner

working 8 min Grounded in the OpenTelemetry generative-AI span conventions, read at commit fee465db, where every document is marked Development. · GenAI spans

The one-minute version

  • The incident this prevents: the answers got worse, three people edited the prompt that week, and nobody can say which edit did it.
  • A prompt is an artefact with a name, a version, a template, its variables and the score it had to beat, stored beside the code.
  • The vocabulary already exists. The span conventions carry gen_ai.prompt.name and gen_ai.prompt.version, so a trace answers which prompt wrote this answer with no second system.
  • This is where the module 1 golden set stops being a report and becomes a gate: a new version ships only if it beats the current one.
  • It moves no retrieval number. What it buys is attribution, and the price of one gate run is small enough that there is no excuse to skip it.

1. The incident, stated plainly

Answers got worse. You have a golden-set score from a week ago and one from today and the second is lower. In between, the corpus was re-ingested once, a chunk size changed, and the prompt was edited three times by two people, all of it in commits that say "tweak prompt".

There is nothing to query. The trace records the model, the tokens and the latency, and the text of the system prompt is either absent or is a two-thousand-token blob with no identity, so you cannot group last week's requests by which prompt produced them. The only way forward is to re-run the eval on each candidate, and each of those runs costs money and an afternoon.

Everything in this lesson exists to make that a lookup instead.

2. What a prompt record holds

Move the prompt out of the code and into a record with an identity. Five fields cover it, and only the first two are non-negotiable.

A directory of files like that one, in the repository, under review, is enough for most systems and is what this course uses. A prompt registry earns its keep when non-engineers edit prompts, or when a change has to ship without a deploy. Neither is true of your capstone, and adding a service to hold five fields is a dependency you will regret before it helps.

3. The trace already has somewhere to put it

You do not have to invent an attribute. The OpenTelemetry generative-AI span conventions define gen_ai.prompt.name, which identifies the prompt template, and gen_ai.prompt.version, which is "The version of the prompt template used" and accepts semantic, date-based or platform-specific schemes. There is also gen_ai.prompt.variable for the values that were substituted in, which is opt-in because those values are frequently sensitive.

The same caution applies here as everywhere in this course: that convention is marked Status: Development, in a repository with no releases and no tags, so the attribute names may be renamed. What is stable is the shape - a request records which prompt, at which version, produced it - and a rename touches one file of constants rather than thirty pages of instrumentation.

With those two attributes present, the incident in section 1 becomes a query: group last week's spans by prompt version, join to the eval report, and read which version was live when the score fell. No archaeology and no re-runs.

4. The golden set becomes a gate

Module 1 built the golden set and used it to report a number. Here it starts refusing things. A prompt version is promoted only when it beats the current one on the same set, and a version that does not beat it goes back to draft rather than shipping with an argument attached.

The objection to a gate is always its cost, so price it. One gate run is the golden set once through the pipeline: thirty questions, each carrying its retrieved passages as input tokens and a few hundred output tokens.

5. What this changed

Nothing, on the golden set, and that is the row to write. Naming a prompt does not retrieve a better passage. Say so plainly in the capstone table, because a table where every change helped is a table nobody kept honestly, and this module needs at least one row that reads zero.

What changed is the cost of the next regression. Before this lesson, finding the cause of a drop meant re-running the eval once per candidate change. After it, the version is on every span and in every eval report, and the question is a group-by.

There is a second, immediate payoff. Every experiment in this module - the chunk sweep, the reordering, the reranker still to come - is now a comparison between two named configurations rather than between "before" and "after", so a result you get today is still readable in three months.

The concept-first version of the same discipline, framed as evaluation infrastructure rather than as a file format, is Shadow testing in Production Agent Engineering.

Check yourself

Retrieval practice

Answer from memory before revealing.

Your score fell last week. Which single recorded field turns the search into a query?
The prompt version lets you group last week's requests by which prompt produced them and line that up against the day the score moved, which is the whole point of recording it. Latency and top-k are configuration you would also want, but neither identifies an edit to the prompt text. The model id matters when the model changed and says nothing about three edits to one prompt in one week.
What does making the golden set a gate change about a prompt edit?
A gate has an exit that refuses, and refusing to promote a version that did not beat the incumbent is the whole of the change. Where the template is stored is a separate decision this page argues is usually a directory. The set does not grow at the gate; growing it is lesson 0430's job. Failed versions are kept precisely so the same idea is not re-proposed later with no record.

Practice about 40 minutes, with a terminal

Practice 1working

This increment is small in code and is what makes every later delta in the course readable.

Move the prompt into a record with a name, a version, the template and its declared variables, in a file under review. Render it from that record and delete the string literal from your code.

Emit the name and version on every inference span, using the convention's attribute names, and confirm you can filter your traces by version.

Write the gate: a script that runs the golden set against a candidate version, compares it with the current one, and exits non-zero when it does not beat it.

Then make a change that fails the gate on purpose - remove the citation instruction, for instance - and watch it be refused. A gate you have never seen refuse anything is a gate you have not tested.

Hint

Version by an integer you increment, not by a hash of the file. A hash changes when you fix a typo and gives you no way to say which of two versions is later.

Decide what "beats" means before you write the comparison, and write it into the record's own gate field. Otherwise you will decide it after seeing the number, which is not a gate.

Show what a good result looks like
  1. The golden-set score should not move. Rendering the same text from a file rather than from a literal changes nothing about the answer. If it did move, the template gained or lost whitespace, and that is worth knowing before you attribute anything else to it.
  2. Test the filter, not the emission. Anyone can add an attribute. The check is that you can select last week's requests by version in your trace backend, which is where the field earns its place.
  3. The deliberate failure is the acceptance test. Remove the citation instruction, run the gate, and expect faithfulness to fall and the script to exit non-zero. A gate that has only ever passed has never been shown to work.
  4. Write the zero-delta row. "prompt v4 named and versioned, recall@10 and faithfulness unchanged" belongs in the capstone table beside the changes that moved something. It is the row that proves the table is a record rather than an advertisement.

Sanity check. Your deliberately worse prompt should fail on faithfulness and leave recall@10 untouched, because retrieval never saw the prompt. If recall moved too, your evaluation is re-embedding or re-retrieving between runs, and the two halves of your harness are not independent - which would make every delta in this module suspect.

Your teacher. Ask your agent to write the gate script and then to try to get a deliberately worse prompt past it. What it reaches for when it cannot - loosening the threshold, changing the questions, comparing against an older baseline - is the list of ways a real gate gets quietly disabled by a team under deadline, and it is worth reading before you are that team.
