Three files decide whether anybody can reproduce your run

foundation 9 min Written against uv 0.12.x and the OpenTelemetry GenAI conventions read at commit fee465db, where every document is marked Development. · uv documentation

The one-minute version

  • A retrieval system fails statistically rather than loudly. A dependency that moved does not crash it; it moves the scores, and you find out three weeks later.
  • So the lockfile matters more here than in ordinary Python, and it pins the whole resolution rather than your direct dependencies.
  • The second file is the secret, and the rule is one line: an API key must never reach a trace, and lesson 0150 is about to start writing traces.
  • The third is the exporter, configured once, so instrumentation is a decorator later instead of a project.
  • The tooling landscape is four slots, not a product list. Fill each with one thing and write down why.

1. The lockfile, and why it matters more here

Every Python project wants a lockfile. This one needs it for a reason worth stating, because the reason changes what you do when it is missing.

In an ordinary service, an unpinned dependency that moves usually breaks loudly: an import fails, a signature changed, a test goes red. In a retrieval system, a tokenizer that changed its normalisation, a client library that changed a default, or a vector library that changed its distance metric does none of that. It changes the scores. Your tests still pass, your endpoint still answers, and the number you are about to spend eight modules moving has moved for a reason nobody recorded.

uv is the tool this course uses, at 0.12.x. Its own documentation describes it as a single tool replacing pip, pip-tools, pipx, poetry, pyenv, twine and virtualenv, and it produces a universal lockfile that resolves for every platform rather than for the one you happen to be on. That last property is the one that matters when a colleague on a different machine gets a different answer from the same corpus.

Astral publishes a speed claim for it, and it is worth reading as an example of the provenance rule this course applies to every number: 10 to 100 times faster than pip, measured by Astral, installing Trio's dependencies with a warm cache. That is the vendor's measurement under the vendor's condition. It is evidence that the effect is real. It is not a number you should expect on your own machine.

2. The key, and the one rule about it

Commit an .env.example carrying the names of every variable and no values. Never commit the .env. That much is ordinary practice and you already do it. The part specific to this course is the second half of the rule, and it arrives one lesson from now.

In lesson 0150 you start emitting spans, and a span is a structured record of a request that gets shipped somewhere else and kept. The OpenTelemetry GenAI conventions have an explicit opt-in tier for exactly this reason: attributes like gen_ai.input.messages, gen_ai.system_instructions and gen_ai.tool.definitions are marked Opt-In rather than Recommended, because they carry content and content carries whatever a user typed. Decide now, while there is nothing to leak, which of those you will ever turn on, and put the redaction in one place so the decision is enforceable rather than remembered.

3. The exporter, configured once

The third file is the smallest and it exists to stop instrumentation becoming a project later. One module that reads an endpoint from the environment, creates a tracer provider, and exposes a tracer. Ten lines. It does nothing visible today.

Writing it now rather than in lesson 0150 is deliberate. If the exporter arrives at the same time as the first span, the two get debugged together, and a missing trace is ambiguous between "my instrumentation is wrong" and "my collector is not running". Stand it up against a console exporter first, see a span printed to your terminal, and the ambiguity is gone before it costs anything.

4. The landscape is four slots

The tooling around this field is large and most of it is interchangeable, which makes a product list the wrong shape for learning it. Four slots is the right shape, because a slot has a question attached and a product does not.

The model client answers "who generates". This course is Claude first and Gemini second, and every sample is written so that changing provider is one edit rather than a rewrite. The store answers "what does the search run against", and this course uses one, so that the index parameters in lesson 0140 are concrete rather than generic. The orchestration slot answers "what holds the steps together", and until module 3 the honest answer is a function. Leaving it empty is a decision, not an omission. The observability slot answers "where does the record go", and it is the only one of the four the course fixes for you, because the whole point is that its vocabulary is not yours to invent.

The GenAI semantic conventions this course instruments against are marked Status: Development, in a repository that has published no release and no tag. Attribute names can be renamed. What is being committed to is the shape - one span per stage, the content-bearing attributes opt-in rather than default - and a rename costs one file of constants.

Check yourself

Retrieval practice

Answer from memory before revealing.

Why does an unpinned dependency hurt a retrieval system more than an ordinary web service?
A changed tokenizer or distance default shifts the numbers while every test still passes, so the failure is silent and statistical rather than loud. Resolution speed is a developer annoyance and not a correctness problem. Cross-platform installation is what a universal lockfile fixes, which is a benefit rather than the reason. Image size is real and unrelated to whether the answers changed.
The GenAI conventions mark message content and system instructions as Opt-In rather than Recommended. Why?
Content-bearing attributes ship user text to a system that keeps it, so the convention makes recording them a deliberate act. They are rarely empty; that is the problem. Length is a cost concern and not why the tier exists. The whole convention is at Development status, so instability is true of every attribute and cannot be what separates this tier from the others.

Practice about 30 minutes, with a terminal

Practice 1foundation

Stand up the project you will carry to the end of this course, and prove it reproduces.

Initialise it with uv, add the four slots' dependencies, and commit both pyproject.toml and uv.lock. Write the .env.example with names and no values, and confirm .env is ignored. Write the ten-line exporter module against a console exporter and emit one span from a script that does nothing else.

Then prove it. Clone your own repository into a fresh directory, install from the lockfile alone, and run the same script. If the span prints, you are done. If it does not, the difference between the two directories is the fourth file the diagram above says you forgot.

Hint

The clone step is the whole exercise and it is the step people skip because they are confident. Confidence is exactly what it tests: the environment variable you set in your shell three weeks ago is invisible to you and fatal to a colleague.

A console exporter needs no collector, no container and no account. Use it until lesson 0150 gives you a reason to want a real one.

Show what a reproducing setup looks like
  1. The lockfile is committed and the virtual environment is not. uv.lock holds the resolution, the .venv directory holds a machine-specific materialisation of it, and committing the second is how a repository becomes unusable on anybody else's operating system.
  2. Versions live in the lockfile and nowhere else. Pinning a version in pyproject.toml as well gives you two places to update and one of them will lag. Declare the constraint you actually have, which is usually none, and let the lock hold the resolution.
  3. The clone test fails for one of three reasons and each is worth meeting once. A variable set in your interactive shell and not in the example file. A file you created and never added. A tool installed globally on your machine and absent from the dependencies. All three are silent on your own machine by construction.
  4. One span, printed, is the whole acceptance criterion. It proves the tracer provider is constructed, the exporter is reachable and the module imports. Everything in lesson 0150 is attributes on a span that already flows.
  5. Write the four slots into the charter from lesson 0100, one line each, with the reason. In module 6 somebody will ask why this store and not another, and a sentence written today is worth more than a reconstruction later.

Sanity check. Delete your .env, run the script, and confirm it fails with a clear message naming the missing variable rather than with a stack trace from inside a client library. If the failure is a stack trace, your configuration is being read at the point of use rather than validated at startup, and lesson 0210 will make that a rule.

Your teacher. Ask your agent to diff the packages your lockfile resolved against the four you actually declared, and to name every transitive dependency that could plausibly change a retrieval score rather than crash. Then ask it which of those four slots you could remove today without changing what your system does, and defend the answer.
