Beyond the working demo

Your demo works, and you cannot prove it is any good.

This is the build track between the interview track and the harness track: what you do to turn one working LLM script into a system you can measure, improve, defend and operate. A retrieval pipeline with evaluation and observability wired in on day one, retrieval quality proved with numbers on your own thirty questions, agents with tools and memory graded on their trajectory, multi-agent orchestration over MCP and A2A priced before it is built, and a deployment with three probes, four caches and a threshold in CI. Fifty-three lessons across eight modules, 900 to 1,400 words each, built around one application you carry from the first page to the last.

Start with Your demo works and you cannot prove it, keep the Glossary open in a tab, and read AI System Design for Staff+ Interviews when your question turns from how to build one into how to defend one at a whiteboard.

01

Foundations

8 lessons

Foundation rung. A pipeline you can run, and then a number you can argue with. The observability and evaluation thread starts here at 0150 and every later module in the course re-runs the golden set built at 0160.

  • Lesson 0100The lifecycle is a loop with a measurement in it - An AI product has no training step, so what you version is the corpus, the prompt and the eval set.
  • Lesson 0110The environment is a lockfile, a key and a trace - A reproducible AI project is three files, and the tooling landscape only matters where it changes one of them.
  • Lesson 0120RAG is a search problem wearing a generation costume - Retrieval decides the answer and the prompt only decides the wording.
  • Lesson 0130An embedding is a lossy address, not a meaning - Similar addresses are a hypothesis about similar meaning, and the hypothesis is model-specific.
  • Lesson 0140A vector index trades recall for latency, and a filter breaks it - An approximate index is a deliberate loss of recall, and a WHERE clause spends the budget again without saying so.
  • Lesson 0150A RAG trace has a retrieval span, and that is where you look first - Instrument with names somebody else already agreed on, so why was this answer wrong is a query rather than an argument.
  • Lesson 0160Measure the retrieval before the model is involved - Retrieval is measurable with no generation at all, and that measurement tells you where to spend.
  • Lesson 0170A generation metric is a judge, and a judge needs its own eval - Reference-free scoring works, and the scorer is a model with named biases you evaluate too.
  • Lesson 0180Free position - Held for a lesson a module 1 writer discovers they need. Nothing may take it by accident.
02

Retrieval quality and context engineering

9 lessons

Working rung, and the module whose whole promise is a number that moved. No lesson here ships without stating what it changed on the reader's own golden set, and the module's capstone page must carry at least one row with a zero or a negative delta.

  • Lesson 0200Ingestion is a pipeline, and every chunk needs an identity - A chunk that cannot name its source, its offset and its checksum cannot be re-ingested or cited.
  • Lesson 0210A schema is a contract the model has to satisfy - One object in three forms: a Python class, a JSON Schema, and a wire payload you can validate at the boundary.
  • Lesson 0220Chunking is a boundary decision, and the boundary is where meaning is lost - Retrieval precision and generation sufficiency pull in opposite directions, and the sweep settles it.
  • Lesson 0230A chunk that cannot say where it came from cannot be found - Two repairs for the orphan chunk, with their bills: context written in, against embed then split.
  • Lesson 0240The window is an attention budget, not a container - More retrieved passages raise the chance the answer is present and lower the chance it is attended to.
  • Lesson 0250A prompt is a versioned artefact with a name - A prompt with no name and no version makes a regression unattributable, which is the Tuesday nobody enjoys.
  • Lesson 0260Two rankings beat one, and RRF is the cheapest way to add them - Reciprocal rank fusion needs no scores, no tuning and no training, and its k barely matters.
  • Lesson 0270A reranker is a second, more expensive opinion on twenty documents - A cross-encoder buys ranking quality with latency, linearly, and the funnel is where you choose how much.
  • Lesson 0280The document you retrieved is untrusted input - The retrieved passage is somebody else's text inside your prompt, and the model cannot see the seam.
  • Lesson 0290Free position - Held for a lesson a module 2 writer discovers they need.
03

Agents and agentic systems

8 lessons

Working rung. What an agent loop is, what bounds it, what a tool call actually carries, and how to grade a trajectory rather than an answer. No page in this module uses a coding-agent example.

  • Lesson 0300Five shapes, and the one that loops - Most systems people call agents are workflows with predefined code paths; only one shape hands the model the path.
  • Lesson 0310A loop you did not write is still a loop you must stop - A framework's agent loop has exactly one exit you control, and choosing it is a product decision.
  • Lesson 0320A tool call is the only verb an agent has - The model emits a name and a JSON object and executes nothing; everything happens in your code.
  • Lesson 0330A failed tool call is a result, not an exception - An error the model cannot see is an error the model cannot correct.
  • Lesson 0340Memory is four stores with four lifetimes - The context window is one of four, and the other three are the ones nobody in this hub has drawn.
  • Lesson 0350Give the agent a memory it maintains, and a path it cannot escape - A file-backed memory is a store you own, which makes path validation part of the design.
  • Lesson 0360Reflection works when the feedback comes from outside - Two peer-reviewed results disagree, and the difference between them is where the signal came from.
  • Lesson 0370Grade the path, not only the answer - A right answer reached by four redundant calls is a bill you will pay every day.
  • Lesson 0380Free position - Held for a lesson a module 3 writer discovers they need.
04

From basic to agentic RAG

6 lessons

Working rung, and the join. Module 2's pipeline and module 3's loop become one system: retrieval the model decides to call, a grader with a refusal path, a pause the reader can resume, and a feedback loop that grows the golden set.

  • Lesson 0400Retrieval becomes a tool the model decides to call - Always retrieve becomes retrieve if needed, and the tool description is what decides.
  • Lesson 0410A retrieval you do not trust is one you can correct - A lightweight grader between retrieval and generation buys a refusal path, which is a designed exit rather than a failure.
  • Lesson 0420A pause is a state you saved, not a thread you blocked - Human-in-the-loop is a checkpoint on disk, and the node restarts from its first line rather than resuming mid-function.
  • Lesson 0430A thumb down is a row in the golden set - A feedback record with no trace id is unusable, and the loop closes on the set module 1 built.
  • Lesson 0440Your RAG app is a host, and its best source is one you did not write - Mounting a server you do not run changes what reaches the window without changing top-k, and the annotation defaults are the trap.
  • Lesson 0450A deep research agent is a retrieval loop with a citation contract - The loop is cheap to describe and expensive to run, and the citation contract is what makes it checkable.
  • Lesson 0460Free position - Held for a lesson a module 4 writer discovers they need.
05

Multi-agent systems

6 lessons

Working rung, and the module a reader may correctly finish by deciding against. The arithmetic comes before the architecture: a recorded decision to refuse the second agent, with the numbers, is a complete capstone.

  • Lesson 0500The second agent is a cost before it is a capability - The token multiplier is measured and published, so the decision can be arithmetic rather than taste.
  • Lesson 0510Delegation is a tool call - A handoff is an ordinary tool call with a history filter on it, and the filter is the design.
  • Lesson 0520Planning is a ledger the orchestrator rewrites - An outer loop that rewrites a durable plan is what survives a stall; a plan held in the window does not.
  • Lesson 0530Shared state is what they actually disagree about - Three sharing mechanisms, and only one of them is still there after a restart.
  • Lesson 0540An agent that is not a tool - MCP goes down to tools and A2A goes across to peers, and the Agent Card is a list of promises.
  • Lesson 0550Read the trace before you touch a prompt - A multi-agent failure has a category, and the category names the design change.
  • Lesson 0560Reserved: in the field, the orchestrator-worker research system - Held, not written. The strongest available page here rests on an evaluation set that is not published, so it would have to be written as what the company says it measured. Module 7 uses the same post as one of two priced case studies instead.
  • Lesson 0570Free position - Held for a lesson a module 5 writer discovers they need.
06

Deployment, optimization and reliability

8 lessons

Working rung, and the heaviest module in the course. Six syllabus bullets that are each a separate mechanism with its own hands-on act: request shapes, health, latency, four caches, injection, the CI gate, and monitoring a system that fails without an error.

  • Lesson 0600Four shapes for a request that takes thirty seconds - Synchronous, streamed, queued with a handle, offline batch; picking the wrong one is what makes a demo unshippable.
  • Lesson 0610The provider is a dependency you do not own - A liveness probe that calls the model turns a provider outage into a restart storm you inflicted on yourself.
  • Lesson 0620Where the seconds go - Latency is time to first token plus tokens times inter-token latency, and only one of the three terms is yours.
  • Lesson 0630Four caches, and only two of them are yours - Caching names four mechanisms at four layers, and confusing them is why a team pays for a cache it is not using.
  • Lesson 0640Semantic caching, and the false hit you have to measure - A semantic cache answers a question nobody asked, at a rate you can measure and must measure.
  • Lesson 0650What a prompt injection is allowed to do - You cannot make a general-purpose agent injection-proof, so the design decision is what it may do after it reads untrusted text.
  • Lesson 0660CI when the unit test is a distribution - A prompt change is a code change with no compiler, so the gate is a threshold on a measured score.
  • Lesson 0670Monitoring a system whose failures are quiet - The signals worth alerting on are token counts, finish reasons and eval scores rather than 500s.
  • Lesson 0680Free position - Held for a lesson a module 6 writer discovers they need.

CAP

Capstone track

7 pages

One application, built as an increment per module and measured every time on the same golden set. Each page below is read at the foot of the module that supplies it, not after the course, and each card takes that position in this map once it is written. A capstone that correctly decides against a second agent, with the arithmetic recorded, is complete.

  • Capstone 1000 · Read after module 1The baseline you will argue with - The charter, the corpus, the golden set, the two numbers and the trace. The page that makes every later module falsifiable.
  • Capstone 1010 · Read after module 2The same thirty questions, six changes later - One row per change and the delta it produced. A row with a zero or a negative delta is required.
  • Capstone 1020 · Read after module 3The agent that knows when to stop - A turn ceiling, a token ceiling, retrieval bound as a tool, a file-backed memory with a traversal test, and an eval set with expected trajectories.
  • Capstone 1030 · Read after module 4The retriever other people can call - The refusal path, the resumable approval, the feedback endpoint, and a golden set bigger than the reader wrote by hand.
  • Capstone 1040 · Read after module 5The second agent you decided against - The measured single-agent cost, the projected multi-agent cost, and the go or no-go. Deciding against it correctly is a pass.
  • Capstone 1050 · Read after module 6Ship it - A deployed service with three probes, a written cost budget, one security pattern applied, and an evaluation threshold in CI.
  • Capstone 1060 · Read after module 8Deliver it - A public repository, three test tiers, the six-question design record, and a recorded five-minute walkthrough.
