The one-minute version

  • Kimi CLI is one asyncio Python process whose seams are three internal libraries: kosong for model calls, kaos for file and process operations, wire for UI events.
  • A turn runs up to 1000 model steps, and each step writes a checkpoint record to an append-only context file first.
  • Safety has no sandbox: the system prompt says so outright, and everything rests on an approval gate plus workspace-path checks.
  • The distinctive move: a tool called SendDMail lets the model itself rewind history to a chosen checkpoint and continue from there, erasing the failed branch.

Process architecture: three libraries inside one process

There is no daemon and no sidecar: one asyncio process hosts everything, and the Typer entrypoint only picks a UI mode - interactive TUI, non-interactive print, an Agent Client Protocol server over stdio, or a JSON event server, plus a FastAPI web app. All modes build the same stack through one constructor (app.py:122). The real module boundaries are the three libraries:

Kosong reduces a model call to two functions: merge one streamed completion into a message, and layer concurrent tool dispatch on top of it (kosong/__init__.py:104). Kaos abstracts every read, write, and exec behind path objects with pluggable backends - local disk, SSH over asyncssh, or an editor client speaking ACP - so no tool ever touches pathlib directly. Wire is the typed event queue between soul and interface, mirrored to a per-session log. Even subagents are just more KimiSoul instances in the same process, each with its own context file under the session directory.

The loop: a turn is many steps, each checkpointed

One user input is a turn; one model call inside it is a step. run() fires a UserPromptSubmit hook that can end the turn before the model ever sees the input, then enters the step loop (kimisoul.py:659). Each step appends to history, checks whether compaction is due, writes a checkpoint, and only then asks kosong for a completion (:937, :1036).

Stop conditions are plural by design: no tool calls ends the turn normally, a hard cap raises MaxStepsReached at 1000 steps per turn (config.py:78, kimisoul.py:1004), twelve consecutive identical tool calls force the turn to stop, and a Stop hook may trigger exactly one corrective extra turn. That ladder - cap, repetition breaker, hook - is the design-principles page's claim that stop conditions are policy made concrete (lesson 0010).

Context assembly: replay from an append-only file

The system prompt is a Jinja template rendered once per session and then frozen into the context file - work directory listing, detected OS and shell, skill catalog, and the project's AGENTS.md baked in as template arguments (agent.py:494). Memory-file support is deliberately narrow: AGENTS.md only, walked from project root to working directory, deeper files winning, with the concatenation capped at 32 KiB and the budget allocated leaf-first so the most specific file survives truncation (agent.py:87). There is no indexer and no embeddings anywhere - retrieval is Glob and Grep tools plus explore subagents.

Token accounting is hybrid: real usage numbers from the API are persisted into the file as _usage records, and messages that have not been through the API yet carry a character-based estimate until corrected (context.py:64). When tokens reach 85 percent of the model's window, or come within a 50k reserve of it, auto-compaction summarizes everything except the last two messages into a single user message prefixed "Previous context has been compacted" (compaction.py:75, :18). Two cache-aware details reward attention: every request carries prompt_cache_key=<session_id> (llm.py:362), and even the side-question feature declares the full tool list it will never execute, purely to keep hitting the same cache prefix (btw.py:1).

Trust posture: a gate, not a box

The system prompt tells the model the truth in one sentence: "The operating environment is not in a sandbox" (system.md:73). Enforcement lives entirely in an approval gate that every mutating tool must pass (approval.py:200), backed by workspace checks inside the file tools - a write outside the workspace needs absolute paths and takes a distinct approval action (write.py:142). MCP tool calls always go through the gate regardless of anything else.

Compare the postures from lesson 0050: Codex CLI sandboxes first and asks second; Claude Code interposes a classifier. Kimi CLI ships neither - rejection depends on a human being present, or on nothing at all under --yolo, which auto-approves globally. The escape hatch is also the failure mode.

The gate's answers are approve, reject with free-text feedback routed back to the model as the tool result, approve-for-session (persisted as an auto-approve set), yolo, and afk mode which implies yolo and auto-dismisses questions. Plan mode does not remove tools; instead each mutating tool checks plan state at call time and refuses, except writes to the designated plan file. Approvals are session-global - a subagent's request is projected onto the root conversation so the human answers once, in one place.

Model behavior: the K2-only wing of the adapter

Kosong speaks many providers - OpenAI-compatible, Anthropic, Google, Vertex - but the kimi provider gets code nobody else touches. Thinking rides a proprietary extra_body.thinking envelope rather than OpenAI's parameter, and reasoning round-trips through history as a non-standard reasoning_content field on assistant messages, including the subtlety that an empty-but-present reasoning string must survive the round-trip (kimi.py:214, :351). Tool names starting with $ are encoded as server-side builtin functions with no schema sent at all (:365).

The shims are equally specific. JSON schemas missing nested type fields are patched because the API rejects them; effectively-empty content next to a tool call is dropped entirely because the Kimi-for-Coding compatibility layer returns a 400 otherwise (kimi.py:342). And since 1.49.0, Kimi requests alone get an adaptive output budget recomputed every step - context size minus estimated input minus margin - which the changelog credits with fixing context-length overflow errors on long turns (llm.py:181). The guard is explicit: if the provider is not Kimi, none of these overrides apply (llm.py:164). This is lesson 0010's adapter principle with the favoritism left in, visible to the user as reliability gaps on every other family.

The distinctive mechanism: model-driven context time travel

Every harness in this course can compact history forward. This is the only one where the model itself can erase it. Because the loop checkpoints before every step, history is always a list of resumable points; the tool SendDMail takes a message and a checkpoint id and posts them to a store named DenwaRenji - "telephone range", Steins;Gate naming throughout (dmail/__init__.py:12, denwarenji.py:17). Once the current step settles, the soul fetches any pending mail and raises BackToTheFuture (kimisoul.py:1313); the loop catches it, physically rewrites the context file down to its prefix before the chosen checkpoint (context.py:135), and injects the mail as a user message wrapped in a system tag instructing the model never to mention it.

Two honest limits belong next to that claim. First, the machinery ships fully wired and tested, but both time-travel tools sit commented out of the default persona's tool list (agent.yaml:9) - today it is an opt-in capability for custom agents, not something a default user will meet. Second, only the conversation rewinds: the data model carries a TODO for restoring filesystem state too (denwarenji.py:7), so files edited along the abandoned branch stay edited. What survives is the judgment, not yet the undo.

What actually enforces the boundary when Kimi CLI considers editing a file outside its working directory?
The system prompt states plainly that there is no sandbox (system.md:73); enforcement is Approval.request plus workspace verification, with outside writes taking a distinct approval action (write.py:142). Seatbelt profiles are Codex CLI's posture and the scoring classifier is Claude Code's - different cast members, compared in lesson 0050 - and no namespace sandbox exists anywhere in this tree.
