Build the smallest harness that deserves the name, then meet who you reinvented

frontier 12 min Every component below exists in production form in a harness you can read - start from Pi's agent-loop.ts. · the loop, documented

The one-minute version

  • A harness is four decisions: a loop, one tool, one memory file, one permission gate. Everything else in today's products is elaboration on those.
  • You will write all four in about three hundred lines of TypeScript against one HTTP API - no framework, no SDK.
  • The closing sixteen-row matrix shows every subject of this course answering the same four questions differently, with evidence linked.
  • Your defaults land you closest to Pi; change exactly one default at a time and you reinvent Codex CLI, Claude Code, or Windsurf in turn.

The four components

Here is the whole thing. It speaks the Anthropic Messages dialect directly over fetch, runs one tool, reads one memory file, gates execution with three regexes, and stops when the model stops calling tools. Omitted on purpose: streaming, retries, output truncation edges, and any second tool - none of them change the architecture. This build exists to compare, and its readout is the sixteen-row matrix at the foot of the page; if you want the same loop built in order to read your own transcript afterwards, with four tools and no cast to diff against, that is Two hundred lines in AI Software Developer.

harness.ts · runnable TypeScript, Node 20+, standard library only
import { readFileSync, existsSync } from "node:fs";
import { execSync } from "node:child_process";
import { createInterface } from "node:readline/promises";

const MODEL = process.env.MODEL ?? "claude-sonnet-4-5";
const KEY   = process.env.ANTHROPIC_API_KEY ?? "";

const toolResult = (id: string, out: string) =>
  ({ type: "tool_result", tool_use_id: id, content: out });

const GATE = [                                    // component 4 - last match wins
  { pattern: /^(git status|ls\b|cat .+)/, action: "allow" },
  { pattern: /\b(rm|sudo|curl)\b/,        action: "deny"  },
];                                                // anything else asks

async function ask(cmd: string) {
  process.stdout.write(`run \`${cmd}\`? [y/N] `);
  return (await createInterface({ input: process.stdin }).question("")) === "y";
}

function loadMemory() {                           // component 3 - AGENTS.md walk
  let d = process.cwd(), memo = "";
  while (d !== "/" && !memo) {
    const p = `${d}/AGENTS.md`;
    if (existsSync(p)) memo = readFileSync(p, "utf8");
    d = d.slice(0, d.lastIndexOf("/")) || "/";
  }
  return memo;
}

async function main() {                           // component 1 - the loop
  const messages = [{ role: "user",
    content: `${loadMemory()}\n\nTask: ${process.argv[2]}` }];
  for (let step = 0; step < 20; step++) {         // component 1 - the leash
    const res = await fetch("https://api.anthropic.com/v1/messages", {
      method: "POST",
      headers: { "x-api-key": KEY, "content-type": "application/json",
                 "anthropic-version": "2023-06-01" },
      body: JSON.stringify({
        model: MODEL, max_tokens: 4096,
        system: `You are a coding agent. cwd: ${process.cwd()}`,
        tools: [{ name: "bash",                   // component 2 - one tool
          description: "Run a shell command in the project directory.",
          input_schema: { type: "object",
            properties: { command: { type: "string" } },
            required: ["command"] } }],
        messages }) });
    const reply: any = await res.json();
    messages.push({ role: "assistant", content: reply.content });
    const calls = reply.content.filter((b: any) => b.type === "tool_use");
    if (!calls.length) {                          // the stop condition
      console.log(reply.content.find((b: any) => b.type === "text")?.text);
      return;
    }
    const results = [];
    for (const c of calls) {
      const cmd: string = c.input.command;
      const hit = [...GATE].reverse().find(r => r.pattern.test(cmd));
      if (hit?.action === "deny")
        results.push(toolResult(c.id, "denied by policy"));
      else if (!hit && !(await ask(cmd)))
        results.push(toolResult(c.id, "the user declined"));
      else
        try {
          const out = execSync(cmd, { encoding: "utf8", timeout: 30000 });
          results.push(toolResult(c.id, out.slice(0, 2000)));
        } catch (e: any) { results.push(toolResult(c.id, String(e.stdout ?? e))); }
    }
    messages.push({ role: "user", content: results });
  }
}
main();

Find your own four answers in the grid and the design space organizes itself around you. Your harness is Pi plus a gate - Pi ships your loop, your memory walk, and your exact-replace tool, minus the regexes. Swap the ask state for an OS sandbox that enforces before prompting and you have rebuilt Codex CLI's posture. Replace the human answering ask with a classifier model consulting a security policy and you have Claude Code's auto mode. Move the edit off-model - send intent, generate the diff elsewhere - and you have Windsurf. None of those teams had information you lack; they priced the same trade-offs differently.

What this demonstrates

Three of the design principles lesson 0010 distills are visible in something this small. First, everything serves the loop: the gate, the memory walk, and the tool schema exist only because the iteration needs deciding, and the moment the reply carries no tool calls, all three go idle together. Second, defaults are the product: the twenty-step leash, the 2,000-character truncation, the y-default prompt - each silently defines what kind of agent this is, exactly as Goose's 1,000-turn ceiling and Pi's missing knob do at scale. Third, absence is architecture: this harness has no subagents, no MCP, no compaction, and works anyway, which is the honest measure of how much a harness must have - and why Pi's author shipped that emptiness on purpose.

Retrieval practice

Answer from memory before revealing.

Which single change converts your minimal harness into something shaped like Codex CLI?
Codex CLI's defining posture is enforce-then-ask: the sandbox fails closed, and approval amends persisted policy. The next-speaker check belongs to Gemini CLI, the patch tool alone changes the edit format but not the trust posture, and an unbounded ceiling is Pi's choice - none of those move the gate.
Your loop's stop condition fires. What did the model's reply look like?
The loop breaks exactly when the filtered list of tool_use blocks is empty - the model addressing you directly is the finish line. A denied call still produces a result that feeds another iteration, the ceiling aborts rather than completes the turn, and bare reasoning is just part of a reply that may still carry calls.

Practice about 45 minutes, with a terminal

Practice 1frontier

Add a second tool to the harness: edit_file, taking path, old, and new. It must refuse to touch a file whose content does not contain old exactly once, and on failure return the same style of hint Goose gives: the nearest matching region of the file so the model can retry with better anchors.

Find: proof the refusal path teaches rather than stalls - run the harness against a file, prompt a deliberate mismatched edit, and show the second attempt succeeding after your hint reached the model.

Hint

Count occurrences with split(old).length - 1; zero or many means refuse. For the hint, slide a window of old.split("\n").length lines over the file scoring rough similarity, and return the best-scoring region verbatim.

Show the worked solution
  1. Gate the happy path. Exactly one occurrence: splice in new, write the file, return a unified-diff rendering of the change so the transcript records what happened.
  2. Build the hint. On zero or multiple matches, score each window of the file against old by shared line count, and return the top region prefixed with "did you mean this anchor".
  3. Wire it as a tool result. Refusals and hints both travel as tool_result content, never as exceptions - the model must be able to read the failure.
  4. Prove the loop closes. A mismatched first attempt followed by a corrected second attempt in the same session is the deliverable: the error channel did the teaching.

Sanity check. If your second attempt needed you to re-explain the edit, the hint was decoration; the test is that the model self-corrects from your refusal text alone - the standard Aider, Gemini CLI, and opencode all meet in production form.
