Module 01 · Orientation · Lesson 00

Seven layers turn a raw model into the agent in your terminal

foundation 10 min Framed against the loop Anthropic documents for its own harness. · How Claude Code works

The one-minute version

  • You believe the harness is a thin wrapper around a model API. Every page of this course exists because that belief is wrong.
  • A harness does seven jobs: the loop, context assembly, the tool surface, the trust gate, the extension surface, the model adapter, and process identity.
  • Fifteen harnesses answer those jobs differently, and the differences are visible to you every day - in how edits fail, what gets asked, and why your agent forgets things.
  • This page builds the seven-layer map; the other twenty-seven pages hang their mechanisms on it.

1. What a harness is not

The thin-wrapper story goes like this: the model is smart, the harness is a chat box that forwards your messages and renders diffs, so capability differences between agents are really model differences. The story is even historically true - early harnesses were roughly that. It stopped being true the moment harnesses started making decisions the model cannot see them make.

Three decisions you can observe without reading any code: whether a shell command runs silently or stops to ask you; whether a failed file edit retries with a different strategy or gives up; and how much of your context window was spent before you typed anything. None of these is a model behavior. All three are decided by ordinary software around the model, and all three differ sharply between harnesses you have probably used.

2. The seven layers

Every harness in this course - from a twenty-year-old terminal habit wearing a new coat to platform agents that run while you sleep - answers the same seven questions. Learn the questions and unfamiliar code becomes navigable: you are always looking at one of seven layers.

The loop

The engine cycle: send the assembled context to the model, execute the tool calls in its reply, feed results back, repeat until the reply carries no tool calls. Everything else on this list serves the loop. Harnesses disagree about when it may stop - Gemini CLI adds a second model call asking who speaks next - and about whether a cap exists at all: Pi deliberately ships none.

Context assembly

Which bytes go into the window, in what order, and what happens when they stop fitting. Memory-file conventions are the visible tip: Claude Code reads CLAUDE.md, Codex CLI walks AGENTS.md upward from your directory under a 32 KiB budget, Goose reads exactly .goosehints and AGENTS.md. Compaction thresholds differ just as much: Goose summarizes proactively above 80 percent of the window; Cline waits until 90 percent.

The tool surface

The named actions the model may take - read, search, fetch, run - and, most consequentially, how an edit is expressed. Aider popularized search-and-replace blocks; Codex CLI speaks a patch grammar parsed against an embedded grammar file; Windsurf sends natural language plus a sketch and applies the diff off-model. What happens when the edit does not apply is where harnesses reveal their character, and it gets a whole page later.

The trust gate

Whatever stands between a tool call and its execution: human prompts, static allowlists, an OS-enforced sandbox, or something stranger. Codex CLI enforces first and asks second - the sandbox fails closed, then approval amends policy. Pi ships no gate at all and calls that architecture. Claude Code replaced human review with a second classifier model judging every action against a maintained security policy.

The extension surface

The sanctioned ways to grow the thing: MCP servers for external tools, skills for packaged procedures, subagents for isolated contexts, hooks for deterministic interception, modes and plugins beyond that. Eight harnesses in our cast converged on the same protocols here - which is itself evidence against the wrapper story, since wrappers would have nothing to converge on.

The model adapter

The dialect translator per provider, and the place per-family favoritism lives. opencode swaps its editor tools out entirely for OpenAI models that prefer patch dialects; Roo Code clamps Claude thinking budgets differently per family; Kimi CLI keeps proprietary reasoning fields for its own models only. When someone says "this agent works better with that model", the honest mechanism usually sits in this layer.

Process identity

How the harness exists on your machine: one binary or many processes, where sessions persist, how updates arrive, what the operating system sees. pi-launcher exists purely for this layer - two hundred lines of C whose entire job is giving an agent a stable cryptographic signature so other systems can recognize it.

Check yourself

Retrieval practice

Answer from memory before revealing.

Two harnesses on the same model class behave differently: one asks before running every shell command, the other runs everything inside a kernel-level sandbox without asking. Which layer differs?
Approval versus sandbox enforcement lives in the trust gate. The first option describes the models layer, which encodes wire dialects rather than policy. The second confuses context selection with enforcement. The fourth conflates packaging with policy.
A teammate claims their agent "got dumber" mid-session until it compacted. Which layer owns the mechanism they are describing?
Compaction - summarizing history to reclaim window space - is context assembly's job. The loop's stop condition is unrelated to quality drift. Extensions add capability rather than consuming history, and while big tool outputs do fill the window, deciding what to evict is still assembly's call.

Practice about 20 minutes, with a terminal

Practice 1foundation

Pick any coding harness installed on your machine - the one you drive daily is the best choice. Without reading documentation first, locate evidence of three of the seven layers: the loop's entry point, the tool surface's edit operation, and the trust gate's approval step. Open-source harnesses can be searched directly; closed ones can be probed behaviorally by watching what they ask, when, and what they write to disk while working.

Find: one artifact per layer - a function name, a config key, a prompt dialog, a directory - and write down which layer each proves.

Hint

Search the repository for the tool names the model is allowed to call - edit operations and lifecycle event names like PreToolUse are layer-three and layer-four fingerprints respectively. Session directories under a dotfolder are layer-seven evidence.

Show the worked solution
  1. Loop layer. In Gemini CLI the non-interactive path is a loop collecting tool-call events until none remain; in Claude Code the Agent SDK documents the identical cycle as turns ending when a reply carries no tool calls.
  2. Tool surface. Codex CLI's edit operation is a patch format with explicit begin and end markers; Cline's editor tool takes exact old and new strings and errors when the match is not unique.
  3. Trust gate. Claude Code surfaces permission prompts per tool call unless rules allow otherwise; Pi shows none at all, which is its documented default posture.

Sanity check. Three artifacts from three different layers means you found real boundaries; three artifacts from the same file usually mean you found the loop alone and labeled it thrice.

Your teacher. If the layers still blur together, ask for the contrast drill: for one layer at a time, have it name two harnesses that answer that layer differently and explain what the user sees because of it. If the sequence diagram felt abstract, ask it to re-walk the turn using the last real task you gave your own agent.
