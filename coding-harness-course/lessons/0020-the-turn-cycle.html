Module 02 · The Loop · Lesson 02

Every agent runs the same eight steps - the design lives at the exits

working 9 min The cycle traced in the source of ten open harnesses and the docs of five closed ones. · How the agent loop works

The one-minute version

  • One turn is eight steps: input, context assembly, model request, response parse, tool dispatch, result, next iteration, stop condition.
  • All sixteen subjects of this course run some shape of it - the cycle is boring on purpose, which is why you can learn it once and read any codebase.
  • The design lives at the edges: what may stop the loop ranges from a five-follow-up cap (Cursor) to nothing shipped at all (Pi).
  • Where mid-turn input lands differs just as much: Pi drains a steering queue before every model call; Windsurf makes your message wait for task end.

1. The cycle, end to end

Strip away the themes, the diff cards, and the permission dialogs, and every harness in this course runs the same cycle. A prompt arrives; the harness assembles the full context window around it; the model streams back text plus structured tool calls; the harness executes those calls and appends the results; and the whole thing repeats until a reply arrives with nothing left to execute.

Two details of this cycle are easy to misread from the outside. First, the model does not run anything: every tool_use block is a request, and the harness decides later - at the trust gate, lesson 0050's subject - whether it runs. Second, results travel back as ordinary conversation content, not as a special channel: a denied call produces a rejection as the tool result, so the model learns of your refusal through the same door as a successful command's output.

The ceilings deserve their own look, because they are the same loop wearing different amounts of leash. Windsurf stops after twenty calls and charges you a prompt credit to continue; Cursor auto-continues at most five times; Gemini CLI hard-stops at one hundred turns; Goose and Kimi CLI sit at a thousand; Pi ships no knob at all. These are code constants and documented defaults at the commits cited above, so you can check each one.

3. Where mid-turn input lands

You will type while the agent works. What happens to those keystrokes is a second axis of divergence, and it decides whether steering feels like a conversation or like queueing at a counter. Pi polls a steering queue before every model call - config.getSteeringMessages() at the top of each iteration - so your correction shapes the very next request. Codex drains pending input inside run_turn the same way. At the other end, Windsurf queues messages until the current task finishes, and Cursor splits the difference: queued messages wait for task end, but "send now" is delivered at the next tool-call boundary.

One cast member breaks the cycle's shape itself: GitHub Copilot Chat has no separate dispatch phase at all. Tool calls from round N execute inside the prompt renderer while round N+1's context is being assembled - the ChatToolCalls element runs the tools as it renders them into the message list. Parse, dispatch, and assembly collapse into one step, which is why its loop is a render loop that happens to call a model.

4. What this demonstrates

Two of lesson 0010's eleven design principles are visible here in their purest form. First, the stop condition is policy: the ceiling table is that principle made concrete - sixteen teams who agree on the cycle disagreeing entirely about the leash, visible to you every day as the difference between an agent that stops to breathe and one that burns your budget overnight. Second, everything serves the loop: the trust gate (lesson 0050), the context assembler, and the extension surface exist because the eight steps need deciding, and a harness that cannot state its stop condition cannot be trusted with a long task. When you reach the deep dives, watch each loop reappear - Pi's is the one shipped as a library, and it gets its own page there.

Check yourself

Retrieval practice

Answer from memory before revealing.

A reply arrives carrying three tool_use blocks and some prose. What does the loop do next?
Tool calls mean iterate: dispatch, append results, resend. Prose alongside calls is normal narration, not a stop signal - the stop is a reply with no calls. The gate evaluates calls at dispatch rather than ending the turn, and nothing about a turn resets the window.
Your agent is mid-task and you type a correction. Under which loop design does your text influence the very next model request?
Pi drains steering at the top of each iteration, so the next request carries your correction. Windsurf's and Cursor's queues hold until a boundary - exactly the opposite trade-off. Copilot's render-time execution is about where dispatch happens, not about when your input enters.

Practice about 15 minutes, with a terminal

Practice 1working

Clone one open harness from the table above - Pi is the smallest read. Find its loop function, then write down, without reading ahead in the file: what the stop condition checks, whether any maximum-iterations constant exists anywhere in the repository (grep for MAX_TURNS, maxSteps, max_iterations), and where user input typed mid-turn would enter.

Find: the function name, the stop expression, the presence or absence of a ceiling, and the steering entry point - four artifacts, each cited by file and line.

Hint

In Pi the whole answer is one file: packages/agent/src/agent-loop.ts. Search it for shouldStopAfterTurn, getFollowUpMessages, and getSteeringMessages.

Show the worked solution
  1. The loop. runAgentLoop in agent-loop.ts - an outer loop that polls follow-up messages, wrapped around an inner loop that runs while tool calls remain.
  2. The stop. No tool calls in the last assistant message, neither the steering nor the follow-up queue returns anything, and shouldStopAfterTurn did not fire - then agent_end emits.
  3. The ceiling. Grep finds no max-steps constant: Pi deliberately ships none, unlike Goose's DEFAULT_MAX_TURNS = 1000.
  4. The steering entry. await config.getSteeringMessages() at the top of the inner loop, injected as user messages before the model call.

Sanity check. Four artifacts from one small file means you found a real loop; if your four came from four different subsystems, you probably found the UI shell instead.

Your teacher. If the cycle still feels abstract, ask it to re-walk your last real task through the eight steps, naming what the context assembly step must have included. If the ceilings surprised you, ask why a team would ship 5 versus none, and steelman both.
