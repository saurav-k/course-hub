Something decided what is in your window before you typed

The one-minute version

  • Your conversation is a minority shareholder in the context window. A budget allocator inside the harness spends most of the space before you type a word.
  • The allocator has four jobs: pay the startup bill, load memory files under a precedence rule, choose retrieval style - a precomputed map or an agentic search loop - and run compaction when space runs out.
  • No two harnesses in our cast make the same choices. Compaction triggers alone spread from about 6 percent of the window to 95.
  • These choices are visible to you: what your agent seems to forget, when it slows down, and why one harness costs more per message than another.

The bill you never see

Before your first keystroke, the harness has already spent tokens. Claude Code documents its own startup stack: a system prompt near four thousand tokens, then auto-memory, environment info, deferred tool names, skill descriptions, and your global plus project CLAUDE.md. Summing the published estimates: 4,200 + 680 + 280 + 120 + 450 + 320 + 1,800 = 7,850 tokens committed before you speak (Claude Code docs, illustrative values). Pi ships deliberately opposite: a base prompt near one thousand tokens including tool definitions, because nothing may enter the window behind the user's back.

The rules layer: two loading strategies

Every harness reads instruction files, but they disagree on which files, in what order, and - the sharpest split - whether everything loads eagerly or waits until relevant. The eager camp concatenates: Codex walks every directory from root to your cwd gathering AGENTS.md files under one 32 KiB budget, re-reading them fresh each step (agents_md.rs); Pi concatenates ancestors too, with AGENTS.override.md beating AGENTS.md beating CLAUDE.md. The lazy camp attaches: Cursor's .mdc rules carry frontmatter deciding their fate - alwaysApply, globs attached when a matching file enters context, or description-only where the model decides (Cursor docs). Windsurf's rules use the same four-way switch (Windsurf docs).

Filling the rest: map versus search

After rules come the code files themselves, and here the cast splits by generation. Aider, the oldest member, computes a ranked outline of the whole repository and injects it into every prompt - no searching happens at runtime because there was no mechanism to search with. Every agentic member inverts this: the model gets search tools and pulls what it needs, paying latency and turns instead of upfront tokens. Gemini CLI hedges with a hybrid - deep GEMINI.md files are pulled in JIT-style when a tool touches their directory.

When it stops fitting: compaction

Long sessions overflow, and the trigger point is a pure design choice. Gemini CLI compresses at half its window, keeping the newest 30 percent (chatCompressionService.ts:38-47). Goose compacts at 80 percent into a structured summary (goose-context-management lib.rs); Copilot Chat starts background compaction at 80 percent and blocks the turn at 95 (agentIntent.ts:452-465); Kimi fires at 85 percent or a 50k reserve (config.py:88-95); Cline projects forward and triggers at 90 percent of input (compaction-shared.ts:13-18). Aider is the outlier: its history budget is one sixteenth of the window, clamped between 1,024 and 8,192 tokens (models.py:355-358) - it summarizes early because full file contents ride along in a separate chunk.

Side channels and the explicit ledger

Some context never appears on your screen. Codex renders unchanged inputs as empty diffs so an untouched AGENTS.md costs zero new tokens on the next request; Roo Code stamps an environment block - open tabs, git status, clock - onto every single turn; Goose writes the model a private note each turn with time, working directory, and remaining budget; Claude Code appends environment info invisibly after its system prompt. These channels exist because the model has no other way to know anything that happened outside its own replies.

Budgeting itself ranges from implicit to bookkept. opencode prunes old tool outputs once past a 20,000-token floor, protecting the most recent 40,000 (compaction.ts:28-33). Pi clamps every requested output cap against remaining space minus a safety margin. Aider is the most explicit ledger in the cast: repo map, history, reminder - each chunk gets a stated allocation, and the final reminder is appended only if the estimated total still fits the model's window (base_coder.py:1294-1329).

The reframing "Why did my agent forget that?" is rarely about the model. It is about which chunk the allocator evicted - and every harness evicts by its own rule.

Check yourself

Retrieval practice

Answer from memory before revealing.

Your teammate's agent ignores a coding convention - until anyone opens a file in one specific directory, after which it complies. Which loading strategy explains this?
Compliance appearing exactly when a directory's files are opened is the signature of glob-gated lazy attachment - Cursor and Windsurf both ship it. Truncation would be flaky everywhere, not fixed by opening one directory. Model-decision gating depends on the request wording, not on file access, and session memory has nothing to do with directories.
Aider summarizes chat history far earlier, relative to the window, than any agentic harness. What best explains the design?
The chat-files chunk carries whole fenced source files every turn, so history competes for the same window and loses. The weak model handles long inputs fine - the budget is a fraction of the main window regardless. Summaries are not length-capped by era, and git preserves code changes, not conversational decisions like naming or constraints.

Practice about 15 minutes, with paper

Practice 1working

Aider sizes three allocations straight from the model's window size. For a model with a 160,000-token window, compute each from the rules in models.py:355-358 and models.py:782-789:

Find: the repo-map allowance (one eighth of the window, clamped to 1,024 to 4,096), the history budget (one sixteenth, clamped to 1,024 to 8,192), and the history share of the window as a percentage.

Hint

Compute the raw fractions first - 160,000 ÷ 8 and 160,000 ÷ 16 - then apply each clamp separately. Neither result lands outside its bounds here.

Show the worked solution
  1. Repo-map raw fraction. 160,000 ÷ 8 = 20,000, which exceeds the 4,096 cap, so the allowance is 4,096 tokens.
  2. History raw fraction. 160,000 ÷ 16 = 10,000, which exceeds the 8,192 cap, so the budget is 8,192 tokens.
  3. History share. 8,192 ÷ 160,000 = 0.0512, so about 5.1 percent of the window.

Sanity check. Both caps bind above windows of 32,768 and 131,072 tokens respectively, so any modern large-window model lands at 4,096 and 8,192 - the clamps exist precisely so big windows cannot inflate these chunks.

Your teacher. Ask it to compare two harnesses you actually use: which memory files each reads, which compacts earlier, and which runs a static map versus live search. Then ask what you would see in each one's transcript when the window fills.
