Windsurf makes your actions between prompts a context channel the model reads continuously

The one-minute version

  • Most harnesses assemble context when you submit a task. Windsurf's Cascade also reads a compressed stream of your actions between tasks - which is why typing just "Continue" works.
  • That channel was expensive to feed, so the same company trained retrieval models that search in parallel, served them on the fastest inference hardware available, and measured their reward against context pollution.
  • The passive half of the same bet is Supercomplete: predict your next intent as a cursor-independent diff.
  • Closed source changes what this page can prove. Everything here comes from vendor documentation and engineering posts, and the honest gaps are marked, not smoothed.

Identity

The Windsurf Editor shipped generally available on November 13, 2024, built by Codeium (Exafunction), a company that had spent years selling code-context systems to enterprises before packaging its own editor (launch post). It is a fork of VS Code - your extensions and settings import directly - and it is closed: proprietary license, no public repository, no commit to pin. On July 14, 2025, Cognition, makers of the Devin agent, acquired the company; the announcement cites "hundreds of thousands of daily active users" and folds Windsurf's IP into Cognition's (Next Chapter). Documentation now lives at docs.devin.ai and the product ships as Devin Desktop, with the Windsurf brand retained; the changelog's current release at fetch time was v3.8.20 (changelog).

One structural fact colors every section below: there are now two local agents. Legacy Cascade, the subject of this page, remains fully supported - but new sessions default to the Devin Local agent, a newer harness shared with the Devin CLI (Devin Local docs). Where the two differ materially, this page says which one it is describing.

The loop

Cascade's turn follows the generic shape from lesson 00, with three harness-specific mechanisms bolted on: a hard tool-call ceiling per prompt, shell commands wrapped in veto-capable hooks, and a checkpoint written per user message so any step can be reverted (Cascade overview). A background planning agent runs alongside the model you picked, continuously refining a long-term plan - a Todo list - while the main model takes short-term actions against it.

The best public evidence for this shape is accidental: the post_cascade_response_with_transcript hook writes the whole conversation to a JSONL file at ~/.windsurf/transcripts/{trajectory_id}.jsonl, and the documentation shows the step types - user_input (carrying the rules that were applied), planner_response, and code_action with a path and new content (Hooks).

How an edit travels: officially documented as diff cards you approve per message, followed by an automatic lint-fix pass over generated code that is free of charge (Cascade overview) and a pre_write_code hook that can veto the write first. Contrast the two cast members that made the edit problem famous: Gemini CLI treats a failed match as its own bug and repairs it through a fallback cascade ending in a second model call (edit.ts), while Codex CLI never guesses - the model emits a patch document parsed by grammar (apply_patch_spec.rs). What Cascade does when an edit fails to apply is not publicly documented.

Context assembly

The window fills in a stable order, and the last slot before history is the one nobody else has.

The persistent layers around the prompt are file conventions you can read on disk. Rules live in .devin/rules/*.md (legacy .windsurf/rules/ still honored) with frontmatter choosing an activation mode: always_on rides in slot two every turn, model_decision contributes only its description until fetched, glob activates on matching files, manual waits for an @-mention - capped at 6,000 characters globally and 12,000 per workspace file (Memories & Rules). Root AGENTS.md is always-on; a subdirectory copy scopes itself to that directory automatically (AGENTS.md). Skills follow the cross-agent SKILL.md contract and practice progressive disclosure: only name and description ship until invoked (Skills). Memories are the odd layer out - auto-generated during conversation, stored locally under ~/.codeium/windsurf/memories/, retrieved on relevance, and explicitly unsupported by the newer Devin Local agent, which prefers you migrate them to skills (Devin Local docs).

Retrieval draws on an embeddings index of the workspace - snippets go to a remote embedding service, but nothing is stored server-side; enterprises can instead index remote repositories on isolated single-tenant servers, keeping only embeddings (Context Awareness, Remote Indexing). Ignore files bound what the index may see and what the agent may touch: anything in .gitignore is both unindexed and non-editable, extended by .codeiumignore/.devinignore patterns (Ignore docs).

Trust posture

Terminal commands sit behind four user-selectable auto-execution levels - Disabled, Allowlist Only, Auto (the model judges risk, premium models only), and Turbo (everything runs except the denylist) - with administrators able to cap the maximum level org-wide (Terminal docs). File edits are gated differently: they always render as approvable cards, and the veto points are the hooks. Twelve lifecycle events fire around the loop - pre_read_code, pre_write_code, pre_run_command, pre_mcp_tool_use, post_setup_worktree, and their siblings - and any pre-hook exiting 2 blocks the action and feeds its stderr back to the model (Hooks).

The contrast the trust module draws holds here: Codex CLI enforces first and asks second, failing closed inside a kernel sandbox (openai/codex); Claude Code interposes a second classifier model judging each action against a maintained policy (How Claude Code works). Cascade's native posture is ask-first with configurable escape hatches, and the successor agent hardens it into explicit Deny/Ask/Allow rules plus OS-level filesystem and network sandboxing (Devin Local docs).

Extension surface

MCP arrived early and deep: stdio, Streamable HTTP and SSE transports, OAuth per transport, a curated marketplace with one-click deeplinks (windsurf://windsurf-mcp-registry?serverName=...), and a hard budget of 100 tools across everything exposed to the model (MCP docs). Around it sit the file-convention extension families this course standardizes on - skills, rules, workflows-as-slash-commands with System-over-Workspace-over-Global precedence, and the twelve-event hooks schema - plus two shapes fewer harnesses offer. Arena mode runs the same prompt through several models in parallel, each in its own git worktree, and converges on the one you prefer; battle groups hide which models ran until after you choose (Arena docs). And the editor hosts foreign agents outright: anything speaking the Agent Client Protocol - Claude Code, Codex CLI, Gemini CLI - registers in ~/.windsurf/acp/registry.json and appears beside Cascade in the agent picker (ACP docs).

Model behavior

The model adapter fronts every major family - Claude, GPT, Gemini, Grok, DeepSeek and others - alongside an in-house SWE line, publishing per-model credit multipliers and cache prices in the user-facing table (Models docs). The default pick is Adaptive, a router that chooses the model per request and accounts for prompt-caching continuity when it routes (Adaptive docs). Free-tier users are pinned to SWE-1.6; the flagship SWE-1.7 ships Max and Medium reasoning variants, with a Lightning edition served on Cerebras hardware for latency.

The affinity story is concrete rather than folkloric: retrieval does not run on a rented frontier model at all. Cognition trained swe-grep and swe-grep-mini with reinforcement learning specifically to issue up to eight parallel tool calls per turn over at most four turns; serving mini on Cerebras reaches over 2,800 tokens per second (SWE-grep post).

The reward design encodes a philosophy worth stealing: scores weight precision over recall because context pollution hurts more than missing context - the main agent is usually a couple of searches away from anything left unfetched (SWE-grep post).

The distinctive mechanism

The launch post named the thesis AI Flow: copilots collaborate but stay shallow, agents act but lose the thread, and Windsurf wanted both - which requires the AI to hold "real time understanding of human actions," kept in sync with "checkpointing, information compression" so the stream stays affordable (launch post). That third channel is why the documentation's most characteristic user gesture is typing literally "Continue": the agent watched you work meanwhile (Cascade overview). The founding bet even predates the agent - the original Riptide was described as an LLM-based search tool ripping through millions of lines in seconds, claiming three times embedding accuracy - and the lineage runs forward through the M-Query embedding era to today's trained retrieval subagent.

The passive face of the same thesis is Supercomplete, which predicts "the next intent, not just the next text": diffs of insertions, deletions and edits surfaced wherever they belong, independent of your cursor, accepted with the same Tab. Its enabling machinery is the clearest engineering detail in the whole story - a purpose-built asynchronous algorithm compresses what the user is doing into a trajectory representation in ten milliseconds or less, because git status and friends are too slow and exclude non-git users; speculative decoding exploits the prior that most code stays unchanged; and the model was fine-tuned to emit diffs rather than parrot existing lines (Supercomplete post). Among the fifteen cast members, none else treats your between-prompt behavior as a maintained input channel with its own latency budget: Cursor trains on acceptance signals and Copilot renders tools inside its prompt tree, but neither keeps listening between prompts.

Evidence limit: this harness is closed source, so every claim above rests on vendor documentation and posts fetched on August 25, 2026, not on readable code. Two behaviors this page refuses to assert: what Cascade does internally when an edit fails to apply, and any per-model prompt-format differences - both unpublished. The leaked internal prompts circulating publicly were deliberately not used as evidence; their provenance fails this course's bar.

Practice about 15 minutes, with a terminal

Practice 1working

Windsurf leaves its state where you can read it. If Devin Desktop or Windsurf is installed on your machine, list ~/.codeium/windsurf/ and ~/.windsurf/transcripts/; if not, read the Hooks documentation and the on-disk layout FAQ instead.

Find: one artifact proving process identity (binaries), one proving persistent context (memories or global rules), and one proving the loop's storage format (a transcript JSONL) - then say which of the three would survive a crash mid-session and why.

Hint

The transcript directory is capped at 100 files pruned oldest-first, and memories are workspace-scoped - neither fact means "ephemeral."

Show the worked solution
  1. Identify the binaries. ~/.codeium/windsurf/bin/ holds the launcher CLIs - process identity, rewritten on update, not session state.
  2. Identify the memory. ~/.codeium/windsurf/memories/ stores auto-generated memories and global_rules.md - durable context that outlives any session.
  3. Identify the loop's trail. Transcript files named by trajectory id record each step as JSON - already-flushed entries survive a crash; the cap prunes old ones later.
  4. Decide. Memory and flushed transcript lines persist; only unflushed in-flight state is lost.

Sanity check. Three artifacts from three different layers means you found real boundaries; three files from one directory usually means you found the transcript store alone and labeled it thrice.

Your teacher. If the trajectory idea still feels abstract, ask it to compare what you would have to type in a plain chat agent versus Cascade after an hour of manual refactoring - then ask which parts of that typed context a ten-millisecond trajectory representation would have captured anyway.
