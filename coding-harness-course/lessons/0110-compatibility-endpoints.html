Module 05 · Models · Lesson 11

Your protocol became their API

working 11 min Framed against the vendors' own compatibility guides. · Z.ai guide · Kimi guide · OpenRouter cookbook

The one-minute version

  • The industry's portability dialect was OpenAI Chat Completions - until agentic coding needed thinking-block replay, which that shape cannot express natively.
  • Z.ai, Moonshot, and OpenRouter now implement the Anthropic Messages dialect so one demanding consumer runs unmodified: Claude Code.
  • Substitution works through environment slots: a base URL redirects the wire, four alias variables fill the harness's task tiers with foreign models.
  • An adapter translates shapes, not behavior - effort levels collapse, features vanish silently, and the quality ceiling stays with the family the loop was built against.

1. The inversion

Through the chatbot era, the lingua franca was obvious: every lab exposed an OpenAI-shaped /chat/completions skin because every tool spoke it. Agentic coding broke the equilibrium. A coding loop interleaves reasoning with tool calls across many turns, and Chat Completions has no native representation for reasoning riding between calls - so the industry standardized upward instead, toward the dialect that already carried thinking as content blocks. The evidence is legible in the neutral catalog: models.dev registers Moonshot's coding endpoint under the Anthropic adapter rather than an OpenAI-compatible one, with a maintainer note explaining the choice - the Messages surface "round-trips reasoning natively via thinking blocks."

Note who did not move: Anthropic itself publishes no OpenAI-compat skin for Claude, and xAI serves its coding model only in OpenAI shapes - the grok-build-0.1 page documents function calling and cached input pricing but no Messages path at all. Reaching Grok from a Claude-native harness means a translating gateway, not a URL swap.

2. The slots that make substitution possible

A compatibility endpoint is only half the trick; the other half is that the harness's model selection is a set of open slots. Claude Code resolves four task-tier aliases - and its documentation states plainly which variable pins each one. Point ANTHROPIC_BASE_URL elsewhere and fill the aliases with foreign IDs, and every tier lands on the substitute.

That is why the same six lines appear in Z.ai's guide writing into ~/.claude/settings.json, in Kimi's shell exports, and in OpenRouter's CI recipe - the slot system is the contract, and each vendor documents its own filling.

4. Where the ceiling stays

Substitution changes everything written on the wire and nothing about what the model was trained against. The gaps show up in three places.

Lossy knob mapping. Claude Code offers five effort levels; the models.dev entry for Z.ai records that GLM maps low, medium, and high all to high, and xhigh through ultracode to max. Two-thirds of the ladder collapses onto two rungs, silently. Kimi's subscription plan similarly serves fewer effective settings than the picker implies.

Features that quietly do not exist. Moonshot's own FAQ states WebFetch is unsupported on its endpoint - the tool fails regardless of configuration. Its kimi-k2.7-code rejects requests unless thinking is explicitly enabled, an error a generic adapter has no way to anticipate. And a community probe of the endpoint found temperature rescaled by a factor of 0.6 server-side, undocumented anywhere official.

The verification gap. Because the protocol is emulated, nothing errors when substitution is wrong. Moonshot devotes a section of its guide to the fact that Claude Code's /model menu shows none of this - it lists fixed aliases - and directs users to check /status for the base URL and model actually in effect. A harness whose model layer is fully configurable needs a status surface that tells the truth about what answered.

None of these endpoints ships a canonical protocol specification. Moonshot's own issue tracker carries an open request asking for one, noting that the request/response contract, supported headers, and feature matrix are unpublished. What you can rely on is the env-var contract and your own probing - treat everything else as implementation detail subject to change.

opencode closes the loop from the other direction: it treats model behavior as data entirely, compiling adapters, personas, effort menus, and even tool availability from a hosted catalog per provider. Where Claude Code substitutes models through slots left open in a native build, opencode makes every model a first-class compilation target - the same insight, generalized until there is no native family left to substitute away from.

Practice about 15 minutes, with a terminal

Practice 1working

You do not need a paid coding plan to see the slot system work: any OpenRouter account will do, since its Messages endpoint accepts the same environment variables. Read one vendor's setup guide end to end first - Z.ai's and Kimi's are linked from this page's header - and list every variable it sets before touching your own configuration.

Find: the complete slot table for your chosen endpoint - which variable covers which task tier, what value fills it, and which assumption patch (window, effort, auth form) the guide considers mandatory rather than optional.

Hint

Count the tiers: main conversation, background summarization, subagents, plus whatever the guide names beyond those. Kimi's configuration-reference table is the most explicit in the cast about what breaks silently when a slot is left empty.

Show the worked solution
  1. Wire and auth. Base URL to the compat path; bearer-style token in ANTHROPIC_AUTH_TOKEN, with OpenRouter additionally requiring ANTHROPIC_API_KEY blanked.
  2. Four alias slots plus one. Opus, Sonnet, Haiku, and Fable each pinned by name, plus CLAUDE_CODE_SUBAGENT_MODEL - Kimi's guide warns each unfilled tier fails its scenario silently.
  3. Assumption patches. Compaction window matched to the substituted model's real context, effort level set explicitly, timeout raised.

Sanity check. Six or more variables means you read the real contract; if you stopped at the base URL, reread the section on tiers failing silently - that silence is the trap this page exists to teach.

Your teacher. If the inversion still feels like trivia, ask it to explain who chose the portability layer and what would have had to happen for the answer to differ. If the ceiling section felt abstract, ask it to walk through which of the three gap types each vendor's guide documents in its own FAQ.
