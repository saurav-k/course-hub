Module 05 · Models · Lesson 10

Affinity is decided at the adapter, not in the benchmark

working 12 min Framed against the three wire dialects' own documentation. · Anthropic tools · OpenAI function calling · Gemini thought signatures

The one-minute version

  • "Works better with Claude" is not folklore - it is three encoding contracts where families genuinely disagree: tool-call shape, reasoning replay, and cache control.
  • The deepest fork is reasoning tokens: each family has different rules for what the model's thinking becomes on the wire and what the harness must do with it next turn.
  • Every harness keeps a translation shelf for these differences - Aider stores per-model edit formats in a config file, opencode swaps its editor tools out entirely for GPT models.
  • Vendors who own both sides stop translating and start training - which is why co-designed pairings keep a quality ceiling adapters cannot reach.

1. The same tool call, three ways

When your harness asks any model to edit a file, the request travels one of three wire dialects. The idea is identical - declare a function, receive a call, answer with a result - but every field name and container differs, and so does the strictness each dialect offers.

Two of these details are affinity-bearing rather than cosmetic. Anthropic documents that its API constructs a system prompt from your tool definitions before the model sees them, and OpenAI states functions are "injected into the system message in a syntax the model has been trained on" - so tool lists cost input tokens and sit inside the cached prefix on both. And forcing behaves differently under thinking modes: with manual extended thinking, tool_choice: any or tool is an error on Anthropic, while adaptive thinking allows forced calls. A harness that plans by forcing a tool call must know which regime the selected model is in.

2. Reasoning tokens are the real fork

The hardest adapter problem is not tools - it is what happens to the model's thinking between turns. Agentic coding interleaves reasoning with tool calls, so every multi-step task replays this decision over and over, and each family wrote different rules.

Gemini is the strictest: its thought signatures are encrypted reasoning state attached to content parts, and Google documents that Gemini 3 models return a 400 error when a required signature is missing from replayed history - even ordering matters, since interleaving a function response between two parallel calls is itself a 400. Gemini CLI lives inside these rules and shows the scar: geminiChat.ts defines SYNTHETIC_THOUGHT_SIGNATURE = 'skip_thought_signature_validator', injecting Google's own documented escape hatch when a call arrives unsigned, because the alternative is a failed turn. OpenAI took the opposite path - reasoning items are encrypted server-side and simply echoed back verbatim, which is why Codex CLI sends include: ["reasoning.encrypted_content"] and store: false to carry state client-side. Anthropic's thinking blocks are ordinary content blocks whose survival depends on generation: Opus 4.5 and Sonnet 4.6 onward preserve them across new user turns by default, while earlier models strip them - taking the cached prefix behind them along.

The open coding models inherit whichever host dialect they serve through, plus their own quirks: Moonshot's kimi-k2.7-code rejects any request where thinking is not explicitly enabled (invalid thinking: only type=enabled is allowed for this model), per Moonshot's own Claude Code guide. A generic adapter cannot know this; someone had to encode it.

3. Cache economics differ per family

Prompt caching is where affinity gets billed. All three labs discount reads of a cached prefix to about a tenth of fresh input, but they differ on who controls placement and what a write costs.

Placement control differs too. Anthropic creates prefixes in the fixed order tools, then system, then messages, allows up to four explicit cache_control breakpoints, and invalidates a level and everything after it when that level changes. OpenAI caches implicitly by default and only added explicit breakpoints with GPT-5.6. Both labs warn that changing reasoning effort changes model-side instructions and therefore breaks prefix reuse - so effort is part of the cache key whether you like it or not. This is why Goose places cache_control markers on its last two messages for Claude-shaped models while skipping the mechanism entirely on providers that cache automatically, and why Kimi CLI pins prompt_cache_key to the session ID.

Notice what this table does to the wrapper belief. If capability lived entirely in the model, the adapter would be a URL rewrite. Instead, Aider's maintainers learned that Gemini breaks unified-diff filename headers and gave it a fenced variant; opencode's learned that OpenAI models emit patch dialects more reliably than search-and-replace blocks and swapped the tools; Gemini CLI's rewrite tool descriptions per generation. Each entry is a recorded behavioral difference, paid for in maintenance.

5. Co-design beats adaptation

The translation shelf has a ceiling, and the vendors above it stopped translating. Cursor trains Composer on trajectories containing its real tool lists; Windsurf's swe-grep retrieval models are trained to issue parallel search calls its own harness schedules well; Anthropic and Claude Code gate features like auto mode on model recency and route classifier-flagged requests down per-version fallback chains. When one team owns the weights, the training loop, and the tool schemas, the model converges on the harness - a loop a third-party adapter cannot join by writing more translation code. That is the honest shape of affinity: the further a pairing sits from co-design, the more of it lives in tables like section 4's, and the more silently it degrades when you substitute the other half.

Practice about 20 minutes, with a terminal

Practice 1working

Find the translation shelf in a harness you have installed. If it is open source, search its repository for per-family branching - strings like claude, gpt-, gemini, or fields named after effort, thinking, or cache control. Closed-source harnesses expose the same seams behaviorally: switch the model with the picker, then watch what the permission prompts, output style, or error messages do.

Find: three per-family code paths or behaviors, and for each, name which of the three contracts from this page it serves - tool-call encoding, reasoning replay, or cache economics.

Hint

Adapter files cluster near the words provider, transform, or model. Aider's model-settings.yml is the largest single example in the cast if you want to see the whole shelf in one file.

Show the worked solution
  1. Tool-call encoding. opencode's registry swaps editor tools for gpt- models; Roo Code converts schemas to OpenAI strict form for some providers and leaves them alone for others.
  2. Reasoning replay. Copilot's Messages path round-trips signed thinking blocks; Kimi CLI guards its proprietary reasoning envelope behind a check for its own provider.
  3. Cache economics. Goose attaches cache_control markers only for Claude-shaped models; aider flags DeepSeek as caching by default and Claude via explicit headers.

Sanity check. Three findings mapping onto three different contracts means you found real affinity machinery; three findings all about prompts usually mean you found one family's system prompt and labeled it thrice.

Your teacher. If the three contracts blur together, ask it to trace one tool call from declaration to result in two dialects and name every field that changed spelling. If the reasoning section felt abstract, ask why swapping a model family mid-session can invalidate the prompt cache even when nothing else changed.
