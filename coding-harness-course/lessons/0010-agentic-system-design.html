Module 01 · Orientation · Lesson 01

Independent teams built one machine: the eleven principles behind every harness

foundation 11 min Distilled across sixteen first-hand studies - ten harnesses read at a pinned commit, five closed products covered from official documentation, plus one study of the model layer beneath them.

The one-minute version

  • Fifteen teams, zero coordination, and yet every coding harness converged on the same skeleton - because the constraints, not the fashion, chose it.
  • This page states eleven principles that follow from those constraints, and names the harness that demonstrates each one best.
  • The convergence is strongest where it is least visible: stop conditions, compaction thresholds, and edit-failure ladders differ everywhere in number but nowhere in kind.
  • Two teams refused parts of the consensus - and their refusals prove the rest of it is a decision, not an accident.

Why independent codebases converge

Aider is Python and predates the tool-call era. Codex CLI is Rust written by OpenAI. Goose is Rust written by Block, Kimi CLI is Python written by Moonshot, opencode is TypeScript, pi-launcher is 237 lines of C. None of these teams copied another's code, and several shipped before they could have. Yet all fifteen build a loop that stops when the model stops calling tools, assemble project memory from files on disk, express edits as matchable text rather than raw rewrites, and put something between a shell command and your filesystem. The explanation is boring and worth stating plainly: they all face the same physics - a stateless model, a finite window, a fallible decoder, and a user who will not approve forty times a day - so they all arrive at the same engineering answers. This page names those answers.

1. The stop condition is policy

Every harness iterates the same cycle: assemble, request, dispatch tool calls, append results. What differs is when it dares to stop. The universal floor is "no tool calls in the reply" - and everything above the floor is a product decision. Gemini CLI spends one extra structured model call asking whether the user or the agent should speak next (nextSpeakerChecker.ts). GitHub Copilot Chat caps an agentic session at a default 200 requests; Goose allows 1,000. Kimi CLI force-stops after twelve consecutive identical tool calls, and opencode converts the third repeat into a human permission prompt. Pi ships no cap at all and documents that as intentional.

2 and 3. Context is assembled, then governed

No harness lets the model remember anything. Project memory is read from disk by code, and every team drew the file boundaries differently. Codex CLI re-discovers instructions each step, walking directories upward and concatenating every AGENTS.md under a 32 KiB budget (its own doc spells out the walk). Claude Code tiers managed, user, ancestor, and project CLAUDE.md instead (memory docs). Windsurf caps global rules at 6,000 characters (Cascade docs); Goose reads exactly .goosehints plus AGENTS.md. Same layer, different answers - which is how you know it is a layer.

4. An edit is a protocol, and its failure path is the design

Models emit text; files need bytes. Between the two sits the most consequential translator in the stack, and every harness answers two questions: how is the change written, and what happens when it does not apply? Aider popularized search-and-replace blocks; Codex CLI parses a patch grammar against an embedded grammar file; Windsurf skips the question entirely by applying a sketch off-model. 5 and 6. Trust lives outside the model, and hooks enforce it

A model asked to be careful is a suggestion; a gate is a guarantee. Every harness places something between a tool call and execution, and the cast splits into exactly four postures. Codex CLI starts every command inside a kernel sandbox and treats approval as escalation. Claude Code and Cursor route uncertain calls to a second classifier model. Aider and Kimi CLI ask a human before every mutation. Pi installs no gate at all and writes down why. None of these postures trusts the model's judgment to be the enforcement mechanism - that is the principle.

Whichever posture a team picked, they all grew the same escape valve: lifecycle hooks, user code that runs at fixed points and can veto deterministically. Claude Code exposes around thirty events led by PreToolUse; Cursor lists about twenty including beforeShellExecution (hooks reference); Windsurf ships twelve whose exit code 2 blocks the action, deployable machine-wide (hooks docs); Google Antigravity carries five (hooks docs). Prompting the model to behave is persuasion; a hook is policy that survives a model upgrade.

7 and 8. Grow by protocol, absorb differences in the adapter

Extension is where convergence became standards. Eight harnesses in the cast speak MCP for external tools, and at least eight load skills as SKILL.md files per the Agent Skills convention - so many that compatibility directories appeared: Cursor, Kimi, Goose, opencode, Cline, and Windsurf all read .claude/skills/ even when Claude Code is not installed (Cursor's skill docs list its search path). Two refusals sharpen the point: Pi refuses MCP outright and Aider never grew a tool loop - proof that joining was a choice each team made, not gravity.

Protocols standardize the surface; the adapter layer absorbs what the surface cannot. Models disagree about reasoning fields, effort knobs, cache markers, and even which edit dialect they emit reliably, so every harness keeps a translation shelf. opencode goes furthest and compiles the entire adapter from a hosted catalog: persona prompt, sampling constants, effort menus, even which editor tool a model gets (transform.ts). Kimi CLI guards a proprietary reasoning round-trip behind its own provider check so other providers receive none of it (kimi.py). Underneath them all, the Anthropic Messages dialect displaced OpenAI's as the portability layer because agentic coding needs thinking blocks replayed verbatim - the catalog study records Kimi registering through an Anthropic adapter for exactly that reason (models.dev).

9. State is a designed artifact

A session that dies with the process is a demo. The cast stores sessions as designed artifacts, in three shapes: append-only logs (Claude Code writes JSONL transcripts per project; Kimi CLI appends typed lines to context.jsonl), databases (Goose re-reads the conversation from SQLite before every single reply), and shadow version control (Roo Code keeps a hidden git repository per task and rolls back with a hard reset - ShadowCheckpointService.ts). Kimi pushes furthest: its checkpoint-before-every-step discipline is what lets a model jump history back to any prior point mid-session. Rollback shape follows storage shape - git reset, SQL truncate, or file-prefix copy - and each harness inherited its rollback from its persistence choice.

10. Telemetry closes the loop

Fourteen of the sixteen subjects ship prompts; Cursor ships weights. Its Tab completion runs on hundreds of millions of accept-or-reject decisions a day, feeding online reinforcement learning whose reward is shaped around a 25 percent accept-probability threshold, with new checkpoints rolling out many times a day (Tab RL post). Its Composer model was trained with the harness's own tool lists re-inserted into failed training rollouts - the model literally studies this harness's tool surface (Composer post). Windsurf is the only other member pulling the same lever, RL-training retrieval models on search quality (swe-grep).

11. Absence is also architecture

Ten principles describe what harnesses build. The eleventh describes what they refuse, because a refusal is falsifiable in a way a feature list is not. Pi ships no permission system, no MCP client, and no built-in subagents, and its documentation argues the case: the trust boundary moves to project-level extension gating and to whoever holds the terminal (security note). Aider ships no tool loop at all - the formatted reply is the patch, retried at most three times - and its repo map does retrieval with tree-sitter and PageRank instead of embeddings (repo map docs). pi-launcher closes the spectrum: 237 lines of C whose entire feature is a stable cryptographic identity. When a tool omits a layer the others all carry, treat it as a thesis about that layer - then check whether the thesis costs its users something.

The reframing A harness is not a pile of features around a model. It is eleven defensible answers to eleven shared constraints - and you can now name each answer's owner.

Retrieval practice

Answer from memory before revealing.

A new agent stops its turn by spending one extra model call asking whether the user or the agent should speak next. Which principle does that implement?
That is Gemini CLI's next-speaker check: the reply carried no tool calls, so the default stop had fired, and the harness spent a call overriding it - pure stop-condition policy. The first option confuses assembly with termination, the third mislabels a plain second model call as dialect translation, and the fourth belongs to vendors training on usage, not to a turn ending.
Goose requires a byte-exact, single-occurrence match for its replace edit and otherwise returns an error with a did-you-mean region. Which principle covers the choice to ship no fuzzy fallback?
The miss path of the edit protocol is exactly the design surface here: Gemini heals it, Codex reports it richly, Goose refuses loudly. Option one is tempting because the refusal is deterministic, but hooks intercept before execution rather than shaping an operation's failure semantics. Option two overreaches - omitting a whole layer is absence-as-architecture, while tuning a ladder's length is a normal protocol choice. Option four describes bookkeeping, not edit semantics.

Practice about 20 minutes, with a terminal

Practice 1foundation

Take the harness you drive daily and assign it all eleven principles. For each, write one line: what it does, and which named member of the cast it most resembles. Three of the eleven can be checked without reading any code: the stop condition (watch when it halts), the compaction trigger (watch a long session get summarized), and the trust posture (watch what it asks before running).

Find: the three behavioral observations, plus your guessed owners for the remaining eight principles.

Hint

Force the observations: give it a long task in a big repository to provoke compaction, and a mildly dangerous command to see the trust posture fire. For the rest, look for its documentation pages on memory files, edits, hooks, MCP, and model settings - the section names of the docs usually mirror the principles.

Show the worked solution
  1. Stop condition. Halt timing right after the last tool result lands; compare against the four conditions in the sequence diagram - no-tool-calls, next-speaker override, repetition breaker, or cap.
  2. Compaction trigger. Watch for a summary notice during one very long session; if the docs quote a percentage, place the harness on the chart above and note how honest the docs are.
  3. Trust posture. Offer it one mutating command and record whether a sandbox notice, a classifier-style delay, an explicit prompt, or nothing at all precedes execution - then match it to one of the four postures.
  4. The remaining eight. Memory-file names give principle 2, edit-error messages give 4, hook-event lists give 6, config keywords like MCP or skills give 7, model-settings tables give 8, session files on disk give 9, vendor-owned models give 10, and documented omissions give 11.

Sanity check. Eleven lines means eleven distinct mechanisms named; if three of your lines cite the same docs page, you probably found one mechanism and labeled it thrice.

Your teacher. If the table blurred together, ask it to drill one principle at a time: name the principle, and have it produce the best demonstrator plus the second answer from memory. If the trust postures feel abstract, ask it to classify your own harness's last ten approvals into the four columns.
