Module 02 · The Loop · Lesson 04

An edit is a claim about a file - and the claim is often false

working 11 min Read across ten open-source editors at pinned commits, from Aider's SEARCH/REPLACE blocks to opencode's nine-stage matcher. · Gemini CLI edit.ts

The one-minute version

  • Every edit a model makes is a claim about file content - "this string is there" - and the claim goes stale the moment the file drifts.
  • Harnesses express the claim four ways: whole-file rewrite, search-and-replace block, patch dialect, or instruction plus sketch applied off-model.
  • When the claim fails, harnesses split into two schools: bounce an enriched error back to the model, or repair the attempt internally - up to and including a second cheap model call.
  • This is lesson 0000's tool surface layer under a microscope: same model, wildly different failure behavior.

1. Four ways to say "change this file"

The model never touches your disk. It emits a description of the change it wants, and the harness applies it. Everything about reliability follows from which of four descriptions the harness asks for.

RepresentationHow it worksNamed members
Whole-file rewriteModel returns the entire new file; harness writes it, creating parentsGemini CLI write_file; Claude Code Write; Roo Code write_to_file; Kimi CLI WriteFile (mode=overwrite|append)
Search-and-replace blockModel returns literal old/new strings; harness finds old and splicesGemini CLI replace; Claude Code Edit; Goose string_replace; Cline editor; Pi multi-block edits[]; Antigravity replace_file_content
Patch dialectModel returns a multi-hunk patch in a text grammar; harness parses against context anchorsCodex CLI apply_patch (*** Begin Patch); Copilot copilot_applyPatch; Aider udiff/patch formats; opencode gives it to gpt-* only
Instruction + sketch, off-modelModel sends intent plus changed lines only; a second component computes the real diffWindsurf edit_file with a {{ ... }}-elided sketch (closed source)

The choice is not aesthetic - it prices the transaction differently. Whole-file rewrites are unambiguous but pay the whole file in tokens every time, which is why Windsurf reserves write_to_file for new files and why Kimi's WriteFile diffs old against new purely to show you a reviewable change. Search-and-replace pays only the neighborhood, but borrows trouble: it assumes the model's memory of the file is byte-accurate. Patch dialects buy multi-hunk economy in one call and pay with grammar fragility - Codex carries permanent leniency that strips heredoc wrappers, because earlier models wrapped patches in <<'EOF' markers. And the sketch keeps generation cheap precisely by keeping the model blind to the final text.

Family affinity leaks into this table: opencode hands apply_patch to gpt-* models and takes their edit/write tools away, Cline enables apply_patch for any model id containing codex or gpt, and Gemini 3 makes the semantic instruction field mandatory on its replace tool. Same axis, per-family answers - the Models module picks this up again in lesson 0100.

2. When the string is not there

A search-and-replace fails whenever the model's old string disagrees with the file: stale read, reformatted code, wrong indentation, a smart quote. What happens next is the single most divergent behavior this course has measured, and it sorts into a ladder of escalating effort.

School one: bounce an enriched error. Claude Code documents the strictest contract - the file must have been Read earlier, the match must be exact and unique, and the error tells the model to read the file again before editing. Goose refuses fuzzy matching outright (no similarity library in its dependencies): zero matches earns a hand-rolled "Did you mean" region plus a numbered twenty-line preview, two or more matches earn the locations of the first two so the model adds context. Aider reflects the failure back as the next user message - every failed block, a nearest-snippet suggestion, and a note if the replacement text is somehow already present - and caps the reflection loop at three rounds. The cheapest member is Kimi CLI, whose _apply_edit is a plain str.replace(old, new, 1): a non-unique old silently rewrites the first occurrence, no guard, no error.

School two: degrade deterministically. Before admitting failure, these harnesses try progressively looser matchers. Codex CLI's seek_sequence runs four stages: exact, trailing-whitespace-trimmed, fully trimmed, then Unicode-normalized. Aider's replace_most_similar_chunk tries exact, then leading-whitespace-flexible, then expansion of ... elision blocks - and its genuinely fuzzy matcher is disabled, unreachable behind an early return. opencode runs nine stages, from line-trimming through block-anchor matching (first and last lines anchored, middle accepted at Levenshtein similarity ≥ 0.65) down to escape-normalization, crediting lineage to Cline's and gemini-cli's evaluators in its own source comments. Roo Code scans a ±40-line window outward with a similarity threshold, then strips line numbers a model hallucinated into the block. Pi re-matches after folding smart quotes, dashes, and Unicode normalization, preserving original bytes elsewhere.

School three: repair with a second model call. Two members spend inference on the problem. When all four of its deterministic stages fail, Gemini CLI's attemptSelfCorrection sends the semantic instruction, the failed old/new strings, the current file content refreshed from disk if it changed underneath, and the specific failure reason - and asks for a corrected pair, which re-enters the deterministic cascade from the top. The repair model may answer "no changes required," which the harness accepts as a legitimate outcome (EDIT_NO_CHANGE_LLM_JUDGEMENT) rather than an error. Copilot Chat independently grew the same organ twice: healCommit routes a failed copilot_applyPatch through a fast endpoint aliased to gpt-4o-mini with one retry, and its string-replace healing header credits Gemini CLI's edit corrector as the ancestor. Convergent evolution, documented in the source.

3. What each choice costs

DesignWinsLoses
Silent first-match (Kimi)Zero latency, zero tokens on recoveryCan rewrite the wrong occurrence and tell you nothing
Exact-only + rich error (Claude Code, Goose, Aider)Deterministic, auditable, never mis-appliesBurns a full agentic round-trip per failure
Graded fuzzy cascade (opencode, Codex, Roo, Pi)Absorbs formatting drift without a round-tripA loose match can apply somewhere unintended - opencode guards by rejecting matches that balloon past the requested size
Repair model call (Gemini CLI, Copilot)Recovers semantically, not just syntacticallyExtra inference cost and a nondeterministic fixer inside a deterministic pipeline
Off-model sketch (Windsurf)Tiny context cost; model never wrestles syntaxModel cannot see - or be blamed for - the final patch text
The reframing A failed edit is not an exception; it is a negotiation over how much the harness trusts the model's memory of the file. Every mechanism on this page - uniqueness guards, did-you-mean hints, similarity thresholds, repair calls - is a way of pricing that trust.
Three cast members cannot be graded on this ladder from public material: Cursor, Windsurf, and Antigravity document their edit representations but not their failure paths. Where this page says "not publicly documented," that is a finding, not an omission.

Retrieval practice

Answer from memory before revealing.

A patch fails to apply, and the harness quietly asks a second cheap model to repair the patch text before anything reaches your screen. Which harness does this?
healCommit is Copilot's patch healer - one retry through a fast endpoint aliased to gpt-4o-mini. Codex's four stages are deterministic string surgery, no model involved. Gemini CLI does make a repair call, but for its search-and-replace tool, not for patches. Goose enriches errors but never spends a model call.
Kimi CLI's replace tool receives an old string that appears three times in the file, with replace_all unset. What happens?
Its _apply_edit is str.replace with count 1, so the first occurrence is rewritten and no guard exists - the risky extreme of the design space. The first two options describe Goose and Cline, which do guard multiplicity. The third paraphrases Claude Code's documented advice to re-read, which Kimi does not give.

Practice about 25 minutes, with a terminal

Practice 1working

Open the matcher of any open-source harness in the table - the links in this page are real commits. Feed its edit path three deliberately broken inputs: one with wrong indentation, one with a smart quote swapped for a straight quote, and one where the target text genuinely is not in the file.

Find: for each input, which rung of that harness's ladder fires, what the model receives back, and whether a full agentic round-trip was spent.

Hint

In Gemini CLI, start at calculateReplacement in packages/core/src/tools/edit.ts and watch which strategy names appear in the telemetry events; in Aider, read replace_most_similar_chunk and look for the early return that disables fuzzy matching.

Show the worked solution
  1. Indentation drift. Exact match fails; the whitespace-insensitive stage recovers it. No round-trip spent - the model never learns there was a near-miss.
  2. Smart quote. Whitespace flexibility will not save it. In Codex the Unicode-normalization stage catches it; in Pi the NFKC fold does; in Goose it bounces with a did-you-mean preview and costs the model a turn.
  3. Genuinely absent text. Every deterministic rung fails. School one returns a structured error; school three spends one micro-inference before conceding.

Sanity check. Pure whitespace damage should never reach the final rung anywhere with a graded cascade - if it does, you broke the input in a second way too.

Your teacher. If the schools blur, ask it to sort all eight open-source members of the bar chart into the three schools and defend each placement from this page's sources. If the trade-off table felt abstract, ask which school your daily driver uses and what its last stuck edit cost you in turns.
