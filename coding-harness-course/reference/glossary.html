Glossary

12 terms Every term this course introduces, linked to the page that develops it. Print it and cover the right-hand column.

TermWhat it means here
Harness The program around a model that assembles context, dispatches tools, enforces trust, and persists state - the seven layers this course takes apart.
Agent loop (the loop layer) The turn cycle: send context to the model, execute the tool calls it returns, feed results back, repeat until it stops calling tools.
Context assembly (the context layer) What fills the window each turn and in what order: system prompt, memory files, tool schemas, history - assembled fresh by the harness, not chosen by the model.
Tool surface (the tool layer) The named actions a harness exposes - read, edit, search, run - and the edit format it uses when the model changes a file.
Permission gate (the trust layer) Whatever decides whether a tool call runs: human prompts, static rules, an OS sandbox, or - in Claude Code's case - a second classifier model.
Extension surface The sanctioned ways to change what the harness can do and do: MCP servers, skills, subagents, hooks, modes, plugins.
Model adapter (the models layer) The code that speaks one wire dialect per provider and absorbs per-family quirks - thinking blocks, caching breakpoints, patch dialects.
Process identity (the process layer) How the harness exists on your machine: one binary or many processes, how sessions persist on disk, how updates reach it.
Turn One round trip inside the loop: the model's response plus whatever tool calls it carried, executed before the next request.
tool_use block A structured part of the model's response naming one tool and its arguments; the loop's unit of work.
Thin-wrapper belief The cold spot this course erodes: that the harness is a chat box over an API and all capability lives in the model.
The cast of fifteen This course's fifteen harnesses - Aider through Windsurf, terminal agents to IDE forks to one signed launcher - each with a deep dive.
