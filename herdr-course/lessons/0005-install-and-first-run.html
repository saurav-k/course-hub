One command installs Herdr, one command runs it

foundation 7 min Every supported install path and your first five minutes - commands verified against the released binary and the install docs. · herdr.dev/docs/install

The one-minute version

  • Linux/macOS: a curl script puts herdr in ~/.local/bin. Windows: a PowerShell script with versioned folders.
  • Already use Homebrew, mise or Nix? Install through that instead - and update through it too.
  • Running herdr in any project folder starts or attaches to a background session.
  • The cost of picking the wrong updater: package-manager installs must not use herdr update.

1. Pick an install path

the two official one-liners · from herdr.dev/docs/install/ (opened this session)
# Linux and macOS
curl -fsSL https://herdr.dev/install.sh | sh

# Windows PowerShell
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"

What the scripts actually do matters for trust: the Unix script detects OS and CPU, downloads the release asset named for your platform from the same manifest the built-in updater uses (https://herdr.dev/latest.json), verifies its SHA-256, and moves it to ${HERDR_INSTALL_DIR:-~/.local/bin} (website/install.sh:5-110). The Windows installer keeps versioned copies under %USERPROFILE%\.herdr\packages\standalone\releases\ and flips a current junction, so an update never overwrites a running exe (website/install.ps1:683-692). Its Windows zip also carries an app-local ConPTY runtime - keep the folder together (install docs; pinned hashes in packaging/windows/conpty.json).

3. The first five minutes

Herdr is mouse-first: click panes and tabs to focus them, drag borders to resize, right-click for menus, drag-select text to copy (quick start, opened this session). The keyboard is optional and always starts with the prefix: press ctrl+b, release, then one action key - v split right, - split down, c new tab, q detach.

Updating a Homebrew, mise or Nix install with herdr update does not apply: Herdr detects package-manager-owned binaries and tells you to upgrade through that manager instead (src/update.rs:1877-1898). Only direct installs self-update.

Check yourself

Retrieval practice

Answer from memory before revealing.

You installed via Homebrew. A new version ships - what do you run?
Package-manager installs update through the manager - Herdr refuses self-update on brew-owned paths. Option one is for direct installs only; option three reloads settings, not versions; option four would double-install outside brew.
What does closing your terminal window do to running agents?
Closing the window detaches only the client; the server owns the processes. Pausing and restarting describe what a full server stop followed by restore does - and stopping is the explicit herdr server stop, not an accident of window management.

Practice about 10 minutes, at a real terminal

Practice 1foundation

Install Herdr by any path above, then in one project folder: start it, split right, run claude (or any shell command), detach, close the whole terminal app, reopen it, reattach, and finally stop the server.

Show for each step the command or keystroke you used, and what told you it worked.

Hint

Detach and stop are different keys entirely: ctrl+b q versus herdr server stop. The sidebar dot colour tells you the agent's state after detection.

Show the worked solution
  1. Install. curl -fsSL https://herdr.dev/install.sh | sh, then check herdr --version prints a number.
  2. Run. cd my-project && herdr; a workspace appears automatically when none exists.
  3. Split and run. ctrl+b then v; type claude; the sidebar marks it working.
  4. Detach. ctrl+b q; your shell prompt returns; the process list still shows the server.
  5. Close and return. Quit the terminal app entirely, open a fresh one, run herdr: same panes, same layout.
  6. Stop. herdr server stop; panes end with it - this is the step people forget exists.

Sanity check. After step 4 the agents were still running and after step 6 they were not - if both felt identical, redo step 4 watching the sidebar.
