Debug locally, then ship to the marketplace

working 10 min The local loop, the first errors you will hit, and the five steps that get a plugin listed. · marketplace docs

The one-minute version

  • Develop with link, not install - your working folder stays the live source.
  • Debug through two logs: per-command records, and herdr's own rotating log files.
  • Publishing is five steps and no review: repo, manifest, topic tag, push, wait.
  • The index rescans GitHub every 30 minutes; listing is automatic or nothing.

1. The local loop

herdr plugin link "$PWD" registers your working tree in place. Because the server re-reads manifests before every plugin call (refresh) and spawns scripts fresh each run, edit-and-rerun needs no reinstall at all. Two logs tell you what happened:

  • Per-command records: herdr plugin log list --plugin <id> shows status, exit code and capped output for recent runs.
  • Server logs: herdr.log, herdr-client.log and herdr-server.log under the session data directory; verbosity follows the HERDR_LOG env var, defaulting to info (logging).

2. A real plugin, dissected

github-link-preview from the community examples repo makes ctrl-clicked GitHub issue links open as a side pane instead of a browser tab. Three files:

herdr-plugin.toml · the link handler is the whole trick
id = "examples.github-link-preview"
name = "GitHub Link Preview"
version = "0.1.0"
min_herdr_version = "0.7.0"
description = "Open clicked GitHub issue and PR links in a Herdr side pane."
platforms = ["linux", "macos"]

[[actions]]
id = "open"
title = "Open GitHub link preview"
command = ["bash", "open.sh"]

[[panes]]
id = "preview"
title = "GitHub preview"
placement = "split"
command = ["bash", "preview.sh"]

[[link_handlers]]
id = "github-issue-or-pr"
title = "Preview GitHub issue or PR"
pattern = "^https://github\\.com/[^/]+/[^/]+/(issues|pull)/[0-9]+/?$"
action = "open"
open.sh · the handler action hands off to the pane
#!/usr/bin/env bash
set -euo pipefail

herdr_bin="${HERDR_BIN_PATH:-herdr}"
url="${HERDR_PLUGIN_CLICKED_URL:-}"

if [[ -z "$url" ]]; then
  echo "missing HERDR_PLUGIN_CLICKED_URL" >&2
  exit 0
fi

exec "$herdr_bin" plugin pane open \
  --plugin examples.github-link-preview \
  --entrypoint preview \
  --placement split \
  --direction right \
  --env "GITHUB_URL=$url" \
  --focus

The third file, preview.sh, parses the URL out of GITHUB_URL and runs gh issue view or gh pr view inside the pane. Note the soft-failure habit: a missing variable exits zero with a message on stderr rather than failing the log record.

3. Publish in five steps

  1. Make the repo installable. Public, not a fork or archived; valid manifest at the root or any subdirectory of the default branch (docs).
  2. Pass the metadata bar. Required fields must parse: id within 120 chars, description within 500, min_herdr_version strictly three-part semver (worker validator).
  3. Add the topic herdr-plugin. That is the entire submission.
  4. Wait one cycle. The worker rescans every 30 minutes; pushes trigger a rescan of your repo alone.
  5. Verify. Search herdr.dev/plugins, then dogfood herdr plugin install you/repo[/subdir].
Listings are not reviewed by anyone. Herdr shows users an install preview and requires confirmation, but the code itself arrives unvetted from its author's repository - keep your own manifest honest and your sources skimmable (trust guidance).

Retrieval practice

Answer from memory before revealing.

Mid-development you tweak a script. Fastest way to see the change?
Linked folders are re-read before every call, so the next invocation already uses your edits. Reinstalling is for refreshing managed github checkouts, the rescan only affects the marketplace index, and restarting discards your command log.
What actually gets a plugin listed on the marketplace?
Discovery is automatic: public repos tagged herdr-plugin whose default branch contains at least one parseable herdr-plugin.toml are indexed, unreviewed (docs). No submission channel exists - which is also why broken manifests silently drop out instead of being rejected.
