Everything you want to change lives in one TOML file

working 7 min The config file, the prefix key model, themes and notifications - with an example config that passes herdr config check. · herdr.dev/docs/configuration

The one-minute version

  • No config file is required; one appears at ~/.config/herdr/config.toml only if you write it.
  • The prefix key (ctrl+b) is Herdr's whole keyboard model: prefix, then one action letter.
  • Themes, sounds and notifications are short blocks in that same file.
  • Edits need herdr server reload-config to land in a running server - a restart is not needed for most UI settings.

1. The file

Herdr works with zero configuration. Print the full annotated default with herdr --default-config, save it to ~/.config/herdr/config.toml if you want a starting point, and validate any edit with herdr config check. Unknown keys warn instead of crashing, and an invalid value falls back to its safe default (src/config/io.rs:104-156; configuration docs, opened this session).

2. The prefix model

Programs inside panes already own most keystrokes - ctrl+c, history search, editor chords. Rather than fight them, Herdr reserves exactly one key. Press the prefix, release, press one more key: that second keypress goes to Herdr instead of the pane (keyboard docs, opened this session).

starter config · every line verified with herdr config check against 0.8.2 while writing this page
onboarding = false          # first-run setup already done

[keys]
prefix = "ctrl+b"           # try "ctrl+a" if tmux muscle memory points elsewhere
new_tab = "prefix+c"
split_vertical = "prefix+v"     # split right
split_horizontal = "prefix+minus" # split down
detach = "prefix+q"

[theme]
name = "tokyo-night"        # 18 built-ins incl. catppuccin dracula nord gruvbox

[ui.sound]
enabled = true              # embedded done/request sounds - no files needed

[ui.toast]
delivery = "herdr"          # off | herdr | terminal | system

Two binding rules bite people. First, "prefix+n" and "ctrl+alt+n" are different things: explicit prefix syntax versus a direct chord that fires without the prefix. A bare direct printable key like "n" intercepts typing and is almost always a mistake (docs/.../configuration.mdx:162). Second, one action can take several bindings as an array: focus_pane_left = ["prefix+h", "ctrl+alt+h"].

The silent failure: you bind a plain letter as a direct shortcut and can no longer type that letter anywhere in any pane. Nothing errors - the key just vanishes into Herdr. Use prefix+ syntax unless you truly mean a chord.

3. Sounds and notifications

Two sounds ship inside the binary: one for an agent finishing, one for an agent blocking on you, played via each platform's system audio tool (src/sound.rs:27-37). Notifications have four delivery routes configured under [ui.toast]: off, an in-app toast, the outer terminal's own notification (works over SSH), or the OS notification service (src/main.rs:401-408).

You edited config.toml and want the change live now. What do you run?
Reload applies most settings without touching panes. Option four validates the file but changes nothing; option two wipes your custom keybindings back to defaults; option one works but kills every pane process - far heavier than needed.
Why does Herdr use a prefix key instead of direct shortcuts everywhere?
One reserved key beats fighting every program in every pane for the rest of the keyboard. Direct chords do exist - the keyboard docs even recommend a ctrl+alt family - so option one overstates it; modifiers transmit fine, so option four is wrong; heritage is a side effect, not the reason.
