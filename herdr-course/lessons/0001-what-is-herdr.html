Herdr keeps your agents running when you close the laptop

foundation 5 min Orientation for the whole course · every claim here is unpacked by a later page. · herdr.dev/docs/concepts

The one-minute version

  • Coding agents run in terminal panes, and terminals die when you close them - so agents died with them.
  • Herdr is one binary that runs a background server owning those panes; your terminal is just a viewer that attaches to it.
  • Every pane's agent gets a live state - working, blocked, done, idle - shown in one sidebar.
  • It costs you a prefix key (ctrl+b) and a small config file if you want one at all.

1. Why this exists

A coding agent is a program running inside a terminal pane. Terminals are fragile: close the window, lose the network, shut the lid - and the pane and its agent are gone mid-task. tmux solved this for shells. Herdr solves it for agents, and adds what agents need that shells never did: knowing which one is waiting for you.

This matches how the docs define it: Herdr is a background session server plus one or more attached terminal clients, and detaching the client stops nothing (concepts; repo: docs/next/website/src/content/docs/concepts.mdx:65-77). The only way to really stop things is herdr server stop, which ends the panes too.

Closing the terminal window feels like quitting Herdr. It only detaches the viewer - the server and every agent run on. If you actually want everything stopped, say so: herdr server stop.

2. The part agents needed

Because Herdr owns the panes, it can watch them. Every recognized agent sits in one of five states - working, blocked, done, idle, unknown - rolled up into a sidebar across all projects (concepts.mdx:41-50). Retrieval practice

Answer from memory before revealing.

You close your laptop lid mid-task with agents running. What breaks?
Detach survives a lid close by design: the server owns the processes. Pausing describes suspend-and-resume of the agent itself; lost panes describe quitting the server - which only happens on purpose.
An agent shows as blocked in the sidebar. What does Herdr say that means?
Blocked is the needs-you state - the one the sidebar exists to surface. Finished-and-read is idle, unclassifiable is unknown, and a crash is not a detected state at all.
