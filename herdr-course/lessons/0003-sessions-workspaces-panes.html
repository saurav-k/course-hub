Module 02 · How it works · Lesson 03

Every room has a number that never repeats and a nameplate that can

working 7 min The object model you navigate daily: what contains what, identity versus labels, and how split layout really works. · herdr.dev/docs/concepts

The one-minute version

  • The chain is session → workspace → tab → pane; each level contains the next.
  • IDs like w1:t2:p3 are stable handles burned in when created - closed numbers are never reused.
  • Labels are nameplates: display-only, often duplicated, never used as identity.
  • Layout is not stored rectangles - it is a split tree, and geometry is recomputed from it every render.

1. What contains what

A session is a namespace: its own folder, its own sockets, its own session.json - the default session or any you create with herdr session attach work. Inside a session, workspaces are project containers, tabs are layouts inside a workspace, and panes are the real terminals. A workspace always has at least one tab; a tab always has at least one pane (src/workspace.rs:178-225, arch report section 3.1).

2. Room numbers versus nameplates

IDs are assigned once and never recycled: panes count up as w1:p1, w1:p2, and after you close w1:p2 the next pane becomes w1:p3 - the number stays burned (src/workspace.rs:1241-1244). Labels are the opposite: a workspace defaults to the git repo's directory name, a tab to its position number, a pane to your manual name or the detected agent's name. Two panes both running claude both read "claude" - only the room number tells them apart (src/workspace/git/discovery.rs:63-69, arch report section 3.2).

3. Layout is a tree, not a picture

Herdr does not store pixel rectangles. Each tab holds a split tree: every node is either a pane or a split with a direction and a ratio. Geometry is derived by walking the tree and cutting the area at each ratio - which is why resizing a border just edits one ratio, why layout survives any window size, and why the snapshot file can store the tree exactly and rebuild your arrangement on any screen (src/layout.rs:73-130, arch report section 3.3).

The trap worth paying for: renaming things feels like reorganizing, but labels are display-only. If a script drives Herdr by label, a rename breaks it silently - drive by ID (or a unique agent name) and renames never matter.
