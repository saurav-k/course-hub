The CDF and the u-machine: any distribution you can integrate, you can sample

13 min working Drag a probability, read off a value, watch an orbital ring appear at exactly that radius. Inverse transform sampling, with the gears exposed.

The one-minute version

  • The CDF F(x) = P(X ≤ x) climbs from 0 to 1 without ever descending - a completed accounting of probability by threshold.
  • If F can be inverted, then x = F-1(u) turns one uniform into a sample of X. No rejections, no waste.
  • For the Exponential(rate λ): F(x) = 1 - e-λx, and the machine outputs x = -ln(1-u)/λ.
  • This page comes BEFORE Box-Muller on purpose: here you build a transform from scratch; there you will meet a famous pre-computed one to stand beside it.
  • The same machinery, wearing business clothes, computes latency percentiles in serving dashboards.

1. The CDF: probability accounted by threshold

The PMF put probability mass on isolated points, which suits dice and dot-counts. Continuous variables need a ledger that works for intervals, and the one everyone uses is the cumulative distribution function:

F(x) = P(X ≤ x),   climbing from 0 up to 1, never descending Read as: F at x holds all the probability accumulated strictly left of x. Start from far left holding nothing; sweep right; every unit of probability you cross gets added; end holding everything.

Two properties follow immediately and both matter mechanically. F never decreases, because probability only accumulates. And F runs the full range 0 to 1, because sweeping far enough right collects everything. That full range is not decoration - it is precisely what lets a uniform play the role of "probability so far", which is the whole trick of this page.

2. Inverting the ledger

Suppose X's CDF is F and you hold one uniform u. Ask the ledger: at what threshold x does accumulated probability first reach u? That threshold is F-1(u), and the claim of inverse-transform sampling is that if you feed uniforms in and return thresholds out, the thresholds behave exactly like samples of X. High-u values get pushed far right; low-u values land near the origin - automatically matching whatever shape F encodes.

The exponential case, worked completely. The rate-λ exponential has F(x) = 1 - e-λx. Set F(x) equal to u and solve for x:

  1. Set the ledger equal to the draw. 1 - e-λx = u, so e-λx = 1 - u.
  2. Take logs. -λx = ln(1 - u).
  3. Isolate x. x = -ln(1 - u)/λ.

Three algebra lines, zero rejections, zero tuning. Sanity-check it at the edges: u near 0 gives ln(1) = 0, a tiny radius; u near 1 gives ln(tiny), a huge one. Now a concrete number you can check against the build: u = 0.700, λ = 8 gives x = -ln(0.300)/8 = 1.20397/8 ≈ 0.150. Set the u-slider below to exactly those values and the marked point should sit at 0.150 on the axis.

3. Run the machine by hand, then let it run

About that mean: E[X] = 1/λ, so tightening λ stretches the visible tail while printing a larger expected radius beside the slider. You can see why without integrating much - the survival function 1 - F(x) = e-λx means the population halves its presence with characteristic length 1/λ. Why the u-slider needs F invertible deserves naming too: if two different thresholds claimed the same accumulated probability, u would have to pick between them, and a slider cannot hesitate. Monotonicity is what makes the machine deterministic.

Enrichment - memorylessnessThe exponential has a famous property this course will not lean on: having already waited t units tells you nothing about how much longer the wait will be - the remaining time is again Exponential(λ). It is the only continuous distribution with that property, and it is why "waiting for a rare event" models default to it. File it; Week 3's muon counting will lend it real work.

Check yourself

With u = 0.700 and rate λ = 8, the u-machine returns x = -ln(1-u)/λ equal to about:
-ln(0.300) = 1.204, divided by 8 gives 0.150. Returning u unchanged forgets that the machine exists to move probability into shape; 5.600 looks like forgetting to divide by lambda after taking a natural log of something near 0.002 - a slip on the input side. And 1.139 is the sign slip: ln(0.300) is negative, so dropping the minus lands you at a nonsense positive-large value that no CDF threshold argument supports.
Why must F be invertible for the u-slider to work?
The machine is the mapping u to F-1(u); if two thresholds shared one accumulated probability, the input could not determine the output and the "machine" would stall making a choice it has no basis for. Widget colours are irrelevant, and a CDF's defining property is climbing 0-to-1, never going negative. If inversion were optional, rejection sampling would have no rival - but it does, because inversion is exactly what saves the exponential sampler its rejections.
Your teacher. Before touching anything, set λ = 4 in your head and predict the u-value whose threshold equals exactly 1/4 - that is, solve F(x) = u for the median. Then find it by dragging. The median of an Exponential is ln(2)/λ; percentages like u = 0.693 are quantiles wearing their working clothes, and dashboards use them daily.
