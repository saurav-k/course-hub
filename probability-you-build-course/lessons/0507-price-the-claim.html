Price the claim

12 min bootstrap intervals, aleatoric versus epistemic A benchmark number without an interval is a rumour. Resample your evaluation set and every headline number you have quoted this week grows a price tag - and the tag teaches you which uncertainties money can shrink.

The one-minute version

  • Any measured rate is an estimate from finite data. The bootstrap prices it: resample the rows with replacement, recompute, look at the spread.
  • This week's population, 2000 rows: accuracy 0.8255, 95% interval [0.813, 0.831]. A rival claiming 0.74 vs your 0.71 is not obviously wrong to disagree.
  • Aleatoric uncertainty is spread in the world itself (label noise); epistemic is your ignorance. They have different cures and confusing them wastes budgets.
  • An interval prices sampling noise of THIS evaluation set only. It says nothing about tomorrow's distribution, drift, or a gamed benchmark.

The resampling cousin of an old idea

Every number this week - accuracy, AUC, ECE, each gap - was computed once from one evaluation set. Had the world handed you a different 2000 rows, every value would move. How far? For simple means there is a formula, and the formal treatment lives in Math for ML's confidence intervals and cross-validation as an estimator; Statistical Foundations develops the CLT machinery in its A/B testing lesson. The bootstrap gets you the same kind of answer for ANY statistic - including ugly ones like ECE where no clean formula exists - by brute force:

repeat B times:
    draw n rows from your n rows, WITH replacement
    recompute the statistic on the resample
report the 2.5th and 97.5th percentiles of the B values

Two implementation details decide whether your intervals mean anything. Seed the resampler. Audits must be reproducible: this build uses a fixed seeded stream so two readers print identical intervals byte for byte. Never reseed inside the loop (every resample comes out identical and your interval collapses to zero width) and always sample with replacement (without it the interval is far too narrow). Both bugs produce plausible-looking numbers, which is what makes them dangerous; the sanity check is that interval width should shrink roughly like 1/sqrt(n).

Which kind of uncertainty are you holding?

The interval answers one question: how much would this statistic wobble if the world re-dealt the same-size evaluation set? That is sampling noise. Before recommending a remedy, classify what dominates your residual error instead:

aleatoric - spread in the WORLD itself.
    Two expert labellers disagree about the true label; the transaction
    was ambiguous when it happened. More model cannot fix it; better
    labels, more features, or a decision to abstain can.

epistemic - YOUR ignorance, given enough data or a better model.
    The model fails mostly on a slice it rarely saw; errors fall as you
    add rows from that slice. Gather data, grow capacity, refine features.

The test is counterfactual and cheap to state: if a hypothetically perfect model with these exact features would still err here, the residue is aleatoric; if more of the right data would shrink it, epistemic. The audit card asks you to classify the dominant residual and name the remedy, because the two failures are opposites - teams routinely spend months collecting training rows to cure what is label noise, or shrug at fixable ignorance as "inherent ambiguity". An interval cannot make this call for you; it prices the estimate, not the world.

What the interval does NOT cover

Say the full sentence in your audit: this is a percentile bootstrap interval over sampling variability of THIS evaluation set under THE SAME distribution that produced it. It does not cover distribution shift between evaluation and deployment; it does not cover label error inside the set (which biases every resample the same way); it does not cover adaptive overfitting if this benchmark was already used to make choices; and it does not license causal language about interventions. The strongest audits say what their numbers cannot show - that sentence is a rubric row, not a disclaimer.

Practice about 20 minutes, coding

Practice 7medium-code

Add a bootstrap engine to your own bench copy: resample the 2000 rows with replacement B = 1000 times using a seeded LCG, recompute accuracy each time, report the 2.5 and 97.5 percentiles. Run it and state the interval. Then deliberately commit both classic bugs - reseeding inside the loop, and sampling without replacement - and observe each bug's telltale signature.

Solution sketch

Typical output on the default population: [0.813, 0.831], a width of about +-0.009 around the point estimate - comfortably under the +-0.02 sanity bound at n = 2000, and shrinking like 1/sqrt(n) if you halve n and rerun.

Bug one, reseeding per resample: all 1000 resamples become the identical draw, the histogram collapses to a single spike, the "interval" has width zero - a beautifully confident nonsense. Bug two, sampling without replacement: every resample is just a permutation of the whole set, accuracy never moves, same zero-width collapse. Either way the failure mode is suspiciously tight output, which is exactly why the width-versus-1/sqrt(n) sanity line belongs next to the interval on any audit card.

For the formal estimator view - what the bootstrap approximates and when it misbehaves - see confidence intervals and hypothesis testing in Math for ML.
