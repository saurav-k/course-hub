Week 4 · Logistic regression · Lesson 03

The gradient, derived then coded

working 12 min Descent mechanics live in Math for ML 0102 · Piech, ch. Logistic Regression

The one-minute version

  • Training climbs the log-likelihood, and climbing needs the slope.
  • Five chain-rule steps collapse the derivative to (y − σ(z)) · xᵢₙ: error times input.
  • The same loop as Week 3 - batch ascent - now sums one such term per point.
  • Divide the sum by n. Raw-sum gradients scale with dataset size, so no learning rate fits two datasets.
  • Milestone one of the artifact ships below: the trainer, running on real generated data.

1. Five steps to the update rule

Take one point with label y and score z = θ·x, and write its slice of the log-likelihood:

ℓ(θ) = y log σ(z) + (1 − y) log(1 − σ(z)),    z = θ·x Read as: the log-probability the model gave this one true label - the inside of the sum from lesson 02. We want its slope in each θₙ direction (theta-sub-j).
  1. Differentiate the first term. Since dσ/dz = σ(1 − σ), d/dz [y log σ(z)] = y·σ(1−σ)/σ = y(1 − σ).
  2. Differentiate the second term. The same derivative fact gives d/dz [log(1 − σ(z))] = −σ, so the term contributes −(1 − y)σ.
  3. Add and cancel. y − yσ − σ + yσ = y − σ(z). The messy parts cancel exactly - that cancellation is why everyone trains with this loss.
  4. Chain rule down to the weight. z is linear in θₙ, so ∂z/∂θₙ = xₙ, and the slice’s slope is (y − σ(z)) · xₙ.
  5. Average over the data and step. θₙ ← θₙ + (η/n) Σi (yi − σ(zi)) · xij, where η is the learning rate and n the number of points.

Sanity check. When the model is right and confident (σ(z) near y), the error term vanishes and nothing moves; when it is wrong, the error is nearly ±1 and the input vector pushes hard. The rule spends effort exactly where the model is badly wrong.

One step by hand, to feel the machinery. Point x = (1, 2) - where the leading 1 feeds the bias - with y = 1, starting weights w = (0, 0), learning rate η = 0.5:

  1. Score it. z = 0·1 + 0·2 = 0, so σ(z) = 0.5.
  2. Error. y − σ(z) = 1 − 0.5 = 0.5.
  3. Per-weight gradient. 0.5·1 for the bias and 0.5·2 for the feature: g = (0.5, 1).
  4. Step. With one point, n = 1, so w₂ moves to 0 + 0.5·1 = 0.5, and the bias to 0.25.

Sanity check. Both updates are positive, and this point wants P(y=1) raised - the step moved every weight along the direction that raises it. Had the label been 0, both signs would flip.

2. Code it once, run it everywhere

The whole trainer is the five steps transcribed. This is the function inside this week’s harness, verbatim except for two norm checkpoints it records for lesson 04:

the fit loop · vanilla JavaScript, from assets/builds/lrharness.js
function fit(data, opt) {
  const lr = opt.lr ?? 0.05, steps = opt.steps ?? 4000, l2 = opt.l2 || 0;
  let w = [0, 0, 0];                      // [bias, weight for x1, weight for x2]
  for (let s = 0; s < steps; s++) {
    const g = [0, 0, 0];
    for (const p of data) {
      const z = w[0] + w[1]*p.x[0] + w[2]*p.x[1];
      const err = p.y - sig(z);           // (y - sigma(z)): the whole derivation
      g[0] += err;
      g[1] += err * p.x[0];
      g[2] += err * p.x[1];
    }
    for (let j = 0; j < 3; j++)
      w[j] += lr * g[j] / data.length - l2 * w[j];   // mean gradient, then optional L2 pull
  }
  return w;
}
Resist retuning per case. The prototype that became this week’s harness tried raw-sum gradients (no division by n): they change scale with dataset size, and one learning rate then fits some cases and oscillates on others - flaky fits that look like data problems. Every case in this suite runs eta 0.05, 4000 steps, mean gradient, so when a case misbehaves, the cause is the data. That is what makes the test suite worth trusting.

Check yourself

Retrieval practice

Answer from memory before revealing.

For one point with y = 1 and σ(z) = 0.2, what does the error term say, and which way does the update move?
The error is y − σ(z) = 0.8, positive whenever the model under-believes the truth, and the update adds error-times-input - so weights on features of this point grow. Overconfidence would give a negative error and the reverse step; both signs matter, but here the model said 0.2 for a positive point.
Why does the update divide the summed gradient by n, the number of points?
Raw sums scale linearly with dataset size: the same eta overshoots on big data and crawls on small data. The mean keeps step magnitude comparable - it says nothing about probabilities or sign, and MLE itself is perfectly happy as a sum.
