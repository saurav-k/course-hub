Week 4 · Logistic regression · Lesson 300

A test suite for a classifier

foundation 11 min Modelled on Stanford CS109’s logistic regression treatment · Piech, Probability for Computer Scientists, ch. Logistic Regression

The one-minute version

  • A trained classifier outputs probabilities - “0.87 positive” - and only becomes a bare label when someone applies a threshold.
  • The sigmoid function converts any linear score into a probability, and it equals 0.5 exactly when the score is zero.
  • This week’s artifact is not a model. It is an adversarial test suite: eight datasets with known properties, each asking you to predict what a hand-rolled logistic regression will do before you run it.
  • The harness grades you, not the model - the same habit as writing the assertion before running the test.

1. What a classifier actually outputs

A regressor predicts a number. A classifier looks similar and is not: given a feature vector x = (x₁, x₂), it predicts the probability that the label is 1, written p(y = 1 given x). The formal machinery behind “given x” is conditional probability, derived in Statistical Foundations, lesson on conditional probability; here we need only the shape of the output.

The shape matters because everything this week measures sits between 0 and 1. A model that says 0.9999 and a model that says 0.51 both count as “predicts positive” at the usual threshold, yet they are opposite claims about confidence. Accuracy throws that away; our test suite will not.

The reframing The model does not output classes. It outputs a probability, and a class is what you get after choosing where the 0.5 line falls. Every failure we will test - imbalance, noise, separation - is a failure of the probability, discovered by looking past the label.

2. The squash that makes scores into probabilities

The model scores a point linearly - weights times features plus a bias - and then squashes the score into (0, 1) with the logistic function, almost always called the sigmoid:

σ(z) = 1 / (1 + e−z),    z = θ₀ + θ₁x₁ + θ₂x₂ Read as: the raw score z (theta-nought is the bias, theta-one and theta-two weight the two features) passes through the sigmoid σ (sigma), which maps any real number into the open interval (0, 1). Large positive z gives a probability near 1; large negative z near 0; z = 0 gives exactly 0.5.

Three values are worth computing by hand once, because they anchor every later reading:

  1. Square the centre. σ(0) = 1/(1+e⁰) = 1/2 = 0.500.
  2. One positive push. σ(2) = 1/(1+e−2) = 1/(1+0.1353) = 0.881.
  3. One negative pull. σ(−3) = 1/(1+e³) = 1/(1+20.09) = 0.047.

Sanity check. The symmetry σ(−z) = 1 − σ(z) holds identically, so σ(3) must equal 1 − 0.047 = 0.953 - and it does. Scores push the probability away from 0.5 symmetrically in both directions.

3. The frame you will fill: eight cases, graded against you

The rest of the week builds one artifact in slices: a test suite for logistic regression. Each case is declared as data - a generator producing points with known properties, a written prediction, and a check over the measured record. When you press run, the harness fits the model on every case, measures what happened, and compares. The report table reads back: case, your claim, MATCHES or CONTRADICTED.

The frame below is that harness, wired and empty. Zero cases are registered so far; they arrive one or two at a time through lesson 0306, and the full eight-case suite assembles in lesson 0307:

The honour-system rule Write each prediction before pressing run, in plain English, from memory. Nothing stops you from running first and typing afterwards - except that the exercise then measures nothing. This is precisely the software habit of writing the assertion before running the test: the value comes from committing to a claim while it can still be wrong. The harness cannot enforce this. Only you can, which is why the rule is stated openly rather than hidden.

A case is three lines of data. This one, from later this week, is the whole pattern:

a case declaration · the exact shape every case in the week takes
{
  name: 'class imbalance 19:1',
  gen: 'imbalanced',                          // names a generator: labelled points, known properties
  predict: 'accuracy looks great (>90%) but the model misses most positives',
  check: (r) => r.acc > .9 && r.minorityRecall < .5   // graded against the measured record
}

The record r carries the observables the week teaches - accuracy, minority recall, minimum confidence, weight growth, coefficient correlation, seed spread - each introduced at the moment a case first needs it. In lesson 0307 you will add a ninth case of your own to this same list.

Retrieval practice

Answer from memory before revealing.

The sigmoid σ(z) equals exactly 0.5 when z equals...
σ(0) = 1/(1+e⁰) = 1/2, always: the pivot of the whole geometry. At z = 1 the probability is already 0.731, and at z = −1 it is 0.269 - neither is the halfway point. e−1 ≈ 0.368 is what the denominator’s second term equals at z = 0, not the score itself.
Why is the decision boundary of this model forced to be a straight line?
The boundary is where the score crosses zero; a linear score has straight level sets - no curvature involved. The sigmoid acts after the score, so its shape never redraws the border, and nothing about training or convention enters: it is algebra, not habit.
Your teacher. If the symmetry check failed, recompute σ(2) and σ(−2) by hand before moving on. Then ask: for the model to say “0.95 positive”, roughly what score did the point earn? Answering “about +3” from the curve, without arithmetic, is the fluency the next four lessons assume.
