Practice about 90 minutes, with paper and the browser console

Practice 1foundation

Compute the sigmoid at three scores, to three decimal places: σ(0), σ(2), σ(−3).

Hint

σ(z) = 1/(1 + e−z). Compute e−2 and e3 first; everything else is division.

Show the worked solution
  1. At zero. σ(0) = 1/(1 + e⁰) = 1/2 = 0.500.
  2. Positive score. e−2 = 0.1353, so σ(2) = 1/1.1353 = 0.881.
  3. Negative score. e3 = 20.09, so σ(−3) = 1/21.09 = 0.047.

Sanity check. The symmetry σ(−z) = 1 − σ(z) pairs these up: σ(3) should be 1 − 0.047 = 0.953. It is.

Practice 2foundation

A model has θ = (−1, 2, 1) - bias −1, weight 2 on x₁, weight 1 on x₂. Score the point x = (0.6, 0.5), give P(y = 1), and state the predicted label at threshold 0.5.

Hint

The score is z = θ₀ + θ₁x₁ + θ₂x₂. Only then does the sigmoid enter.

Show the worked solution
  1. Score it. z = −1 + 2(0.6) + 1(0.5) = −1 + 1.2 + 0.5 = 0.7.
  2. Squash it. P(y = 1) = σ(0.7) = 1/(1 + e−0.7) = 1/1.4937 = 0.668.
  3. Decide. 0.668 > 0.5, so predict 1.

Sanity check. A positive score must always give probability above half - if your p came out below 0.5 with z = 0.7, a sign slipped in the sigmoid.

Practice 3working

One gradient-ascent step by hand. One point, x = (1, 2) where the leading 1 feeds the bias, y = 1, starting weights w = (0, 0), learning rate η = 0.5, mean-gradient over this single point. What are the new weights?

Hint

Score first: with w = 0 the score is 0, so σ(z) = 0.5. The update is wₙ += η · (y − σ(z)) · xₙ.

Show the worked solution
  1. Score. z = 0·1 + 0·2 = 0, giving σ(0) = 0.5.
  2. Error. y − σ(z) = 1 − 0.5 = 0.5.
  3. Gradient per weight. Error times input: bias gets 0.5·1 = 0.5; feature gets 0.5·2 = 1.0.
  4. Step. With n = 1 the mean is the sum, so w₁ = 0 + 0.5·0.5 = 0.25 and w₂ = 0 + 0.5·1.0 = 0.5.

Sanity check. Both moves are positive, and this point wants P(y=1) raised from its current coin-flip value - the step must point that way.

Practice 4working

Show, filling every step, that the derivative of one point’s log-likelihood slice ℓ = y log σ(z) + (1 − y) log(1 − σ(z)) with respect to θₙ collapses to (y − σ(z)) · xₙ. Use dσ/dz = σ(1 − σ) and ∂z/∂θₙ = xₙ.

Hint

Differentiate each log separately. For the second one, remember the chain rule puts a −σ(1 − σ) inside from differentiating 1 − σ.

Show the worked solution
  1. First term. d/dz [y log σ(z)] = y · σ(1 − σ)/σ = y(1 − σ).
  2. Second term. d/dz [(1 − y) log(1 − σ)] = (1 − y) · (−σ(1 − σ))/(1 − σ) = −(1 − y)σ.
  3. Add. y − yσ − σ + yσ = y − σ. Both product terms cancel exactly.
  4. Chain rule to the parameter. ∂ℓ/∂θₙ = (∂ℓ/∂z)·(∂z/∂θₙ) = (y − σ(z)) · xₙ.
  5. Check against Practice 3. Plug y = 1, σ = 0.5, xₙ = 2 back into problem 3: (1 − 0.5) · 2 = 1.0 - the same gradient the hand-step produced.

Sanity check. The result is bounded: |y − σ| never exceeds 1, so no single point can dominate an update unless its features are enormous.

Practice 5working

A person currently has p = 0.8 of repaying a loan. A fitted model carries weight 0.7 on a feature that will increase by one unit, others unchanged. Give today’s odds and log-odds, then the new odds and new probability after the increase.

Hint

Odds = p/(1 − p). Adding 0.7 to a log-odds multiplies odds by e0.7. Convert back with p = odds/(1 + odds).

Show the worked solution
  1. Odds today. 0.8/0.2 = 4; log-odds = log 4 = 1.386.
  2. Add the coefficient. 1.386 + 0.7 = 2.086.
  3. New odds. e2.086 = 8.06, i.e. the odds multiplied by e0.7 ≈ 2.01.
  4. New probability. p = 8.06/(1 + 8.06) = 0.889.

Sanity check. The odds doubled but the probability moved only 0.089 - the compression lesson 307 taught. Any answer above 0.95 has quietly treated odds as probabilities.

Practice 6working

A dataset holds 190 negatives and 10 positives. First compute accuracy, recall on positives and recall on negatives for a model predicting negative for everyone. Then do the same for a model that catches 5 of the 10 positives while raising 5 false alarms among the negatives.

Hint

Recall on positives = TP/(TP + FN). Lay out the four counts - TP, FP, TN, FN - before computing anything.

Show the worked solution
  1. All-negative model. Accuracy = 190/200 = 95%; recall on positives = 0/10 = 0%; recall on negatives = 190/190 = 100%.
  2. Catching model’s counts. TP = 5, FN = 5, FP = 5, TN = 185.
  3. Catching model’s rates. Accuracy = (185 + 5)/200 = 95%; recall on positives = 5/10 = 50%; recall on negatives = 185/190 ≈ 97.4%.

Sanity check. Identical accuracies - 95% both times - with opposite usefulness. If your second model scored below the first, recheck the denominator: accuracy averages over points, and points are mostly negatives here.

Practice 7frontier

Separation blow-up, computed. Two points only: ((−1,), 0) and ((1,), 1), model score b + w·x with b fixed at 0. Write LL(w), evaluate it at w = 0, 2, 5, and conclude what happens as w grows without bound.

Hint

The negative point at −1 contributes log(1 − σ(−w)); use the symmetry 1 − σ(−w) = σ(w) to fold both terms together.

Show the worked solution
  1. Write the likelihood. LL(w) = log(1 − σ(−w)) + log σ(w) = log σ(w) + log σ(w) = 2 log σ(w).
  2. Evaluate at w = 0. σ(0) = 0.5, LL = 2 log 0.5 = −1.386.
  3. Evaluate at w = 2. σ(2) = 0.881, LL = 2 log 0.881 = −0.254.
  4. Evaluate at w = 5. σ(5) = 0.9933, LL = 2 log 0.9933 = −0.0134.
  5. Conclude. LL climbs toward 0 as w → ∞ but equals 0 nowhere: the supremum is approached, never attained. No finite maximiser exists.

Sanity check. Every value stays negative - a log-likelihood of probabilities can be nothing else - and rises monotonically, matching lesson 301’s chart of this exact curve.

Practice 8frontier

Code - add a case to the suite. In any Week 4 page carrying the full harness, declare:

your case · drop into window.MY_CASES on lesson 307
{
  name: 'wide noise',
  seed: 48,
  gen: (g) => [...g.blob(-1, -1, 50, 0, 3), ...g.blob(1, 1, 50, 1, 3)],
  predict: '...',
  check: (r) => r.acc > .6 && r.acc < .85
}

Write the prediction yourself before running. Run, record the verdict, and explain it in one sentence referencing minConf. Then push the clouds’ spread from 3 up toward 5 and predict what happens to accuracy before you re-run.

Hint

Spread-3 clouds centred at ±1 overlap heavily: most boundary-region points are genuinely ambiguous, and ambiguous data caps confidence.

Show the worked solution
  1. Canonical run. On seed 48 the fit lands at acc ≈ 0.72 with minConf ≈ 0.11 - comfortably inside the asserted band, verdict MATCHES.
  2. The explanation. Wide overlap means even well-placed boundaries cannot separate confidently: minConf stays far below 0.9 because contradictory neighbours force hedged probabilities.
  3. The dial. Raising spread toward 5 drags accuracy toward the 0.60 floor of the check - the generator, not the trainer, decides the outcome.

Sanity check. If your run gave accuracy near 0.95, the spread argument did not take effect - most likely the sd argument went to the wrong blob parameter position.

The design problem open-ended, about a working day - this is the week’s capstone piece

Designfrontier

The metric that lies. Your team’s fraud classifier reports 98% accuracy; fraud prevalence is 1.5%. Choose two additional observables the Week 4 suite should track for a case shaped like this system, define their check predicates with explicit thresholds, predict their values from the prevalence arithmetic alone, and state what observed result would falsify your claim that the model is fine (or isn’t). Ship it as a case declaration in the lesson 307 block, prediction written first.

Rubric - what a strong submission contains
  1. Names the right instruments. Recall (or precision) on fraud explicitly, or minority-recall in the suite’s vocabulary - essential. Accuracy appears only as the villain of the piece.
  2. Predicates carry numbers. Checks like r.minorityRecall < 0.5 or precision > 0.3, not prose gestures - strong.
  3. Predictions survive prevalence arithmetic. At 1.5% prevalence the all-negative baseline sits at 98.5% accuracy; predictions consistent with that world (e.g. minority recall near 0, precision low because false alarms swamp true positives) - strong.
  4. A falsifier and an asymmetry sentence. What observation would prove the model not fine - and one sentence on why a missed fraud costs more than a false alarm, or honestly why not, for this product - exceptional.

Sanity check. If your two observables would both look healthy on the all-negative predictor, they measure nothing this problem is asking about.
