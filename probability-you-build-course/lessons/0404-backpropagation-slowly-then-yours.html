Backpropagation, slowly, then yours

14 min you code the backward pass The chain rule walked backwards through the layers, reusing work as it goes - first on a two-weight net you can check by hand, then in the page, where you replace the supplied trainer with your own and let the finite-difference checker prove it.

The one-minute version

  • Backpropagation answers one question: how much does the loss blame each of the 88 weights? It answers all 88 at once by walking the chain rule from output to input and reusing every intermediate result.
  • The alternative - nudge each weight, measure the loss twice - is correct but costs 176 forward passes per gradient estimate. Backprop costs one backward sweep.
  • Your job today: in your own copy of this page's build file, wipe out the marked body of trainEpochMine and type the backward pass yourself, guided line by line below.
  • The checker button perturbs five random weights and compares numerical against analytical gradients, printing max relative error. Below 1e-6 means your maths is right; the symptom table maps wrong values to their causes.
  • The new gradient-flow bars show mean |delta| per layer during training - vanishing gradients become visible instead of vocabulary.

1. Blame, allocated by the chain rule

Gradient descent needs ∂L/∂w for every weight w: if I nudge this weight up a hair, does the loss fall, and how fast? For the final neuron the answer is immediate, because you already know the composite derivative from week 4:

∂L/∂z(out) = p̂ - y Cross-entropy chained through a sigmoid collapses to this famously clean form: the error is just "probability said minus truth observed". Every blame signal in the network starts from this number.

Every earlier weight is blamed through later ones, so the chain rule walks backwards. Do it once, slowly, on the smallest network that has a hidden layer: one input x = 1, one hidden neuron h = tanh(w1x), one output p̂ = sigmoid(w2h), label y = 1, weights w1 = w2 = 1.

  1. Forward pass. h = tanh(1) = 0.76159. Then u = w2h = 0.76159, and p̂ = sigmoid(u) = 0.68170.
  2. Output delta. The blame at the output pre-activation: p̂ - y = 0.68170 - 1 = -0.31830. Negative means "raise u to lower the loss".
  3. Blame w₂ directly. Raising w₂ raises u one-for-one per unit of h, so ∂L/∂w₂ = (p̂-y)·h = -0.31830 × 0.76159 = -0.2424.
  4. Pass the blame back. Raising w₁ changes h by tanh′(z) = 1 - h² = 1 - 0.57902 = 0.41997 per unit, and that change reaches u scaled by w₂. So ∂L/∂w₁ = (p̂-y)·w₂·(1-h²) = -0.31830 × 1 × 0.41997 = -0.1337.

(Every one of those numbers reproduces to the digit shown - they were recomputed mechanically while writing this page.) Both gradients are negative: raising either weight pushes p̂ toward 1, which is toward y. Notice what step 4 reused: steps 2 and 3's work, not a fresh sweep of the network. That reuse is the whole invention.

2. Why not just nudge each weight and measure?

You could estimate any weight's gradient without calculus: add a tiny epsilon to wj, run the whole dataset through, note the loss; subtract epsilon, do it again; divide the difference by 2ε. This finite difference is correct - for small enough epsilon it converges on the true derivative. What it is not is cheap. Each trial costs a full forward pass over every row, and you need two per weight: 88 weights × 2 passes = 176 sweeps to price one epoch's gradient, where backprop pays one backward sweep for all of them. Backpropagation is not an approximation of the finite-difference answer; both converge to the same numbers, which is precisely what makes the checker in section 4 meaningful.

The same arithmetic, run per-row and summed over the training set, gives the full-batch gradient this week's trainer descends along. (One pass over all rows before each step is batch gradient descent; the stochastic and mini-batch variants trade sweep size for noise, treated in stochastic gradient descent, and the optimisers that adapt the learning rate for you live in adaptive learning rates. Our lr field stays honest and manual.)

3. Now yours: replace the trainer

The build below carries two trainers. Supplied is the instructor implementation, used by lessons 1-4. Mine is yours: in the copy of assets/builds/glassnet.js you keep locally, find the function trainEpochMine, delete everything between the STUDENT CODE marks, and type the backward pass yourself from the listing below - reading, not pasting. Then reload, select mine, train, and confirm the boundary behaves exactly as the supplied trainer's did.

function computeGrads(net, data) {
  /* zero accumulators gW[l], gb[l]; loop rows: */
  const cache = {};                 // 1. cache the forward pass
  const p = forward(net, row.x, cache);
  let delta = [p - row.y];          // 2. output delta: probability minus truth
  for (let l = lastLayer; l >= 0; l--) {
    // 3. price this layer: gb[l][j] += delta[j];
    //    gW[l][i*nout+j] += delta[j] * activationsOf(l)[i]
    // 4. pass blame down (if l > 0):
    //    nd[i] = sum_j W[l][i*nout+j] * delta[j], times (1 - a[i]*a[i]) for tanh
    delta = nd;
  }
  /* divide every accumulator by data.length */
}

The two lines learners get wrong most often are both visible there. The blame passed to layer l must be multiplied by the activation derivative evaluated at layer l's activations - for tanh that is 1 - a², applied to the array you cached, not recomputed from z. And the accumulators must be fresh zeros each epoch: writing into a copy of the weight array instead of the gradient array produces gradients of exactly zero, which trains nothing and looks like a stuck loss curve.

4. Prove it with the checker

Pressing check gradients runs both estimators on five random weights: your analytical gradient from computeGrads, and the numerical central difference (L(w+ε) - L(w-ε)) / 2ε with ε = 10⁻⁵. It prints the worst relative error, |ga - gn| / max(1, |ga|+|gn|), across the five. On a freshly initialised net the shipped maths prints around 10⁻¹⁰; anything under 10⁻⁵ is a pass. Your typed version should match within rounding of that. When it does not, the value itself diagnoses the bug:

Why the bars shrink leftwardsEach backward hop multiplies the signal by that layer's tanh′ factors, each strictly less than 1 away from the knee, so four hidden layers stack four attenuations between the loss and the earliest weights. The fix families - ReLU-style slopes of exactly 1 on the active branch, normalisation, residual adds that give the signal a skip path - each attack one term of that product; they belong to the deep-learning course, not this one. What you own from today is the diagnostic reflex: early-layer bars near zero mean late layers are hogging the learning.

5. Check yourself

Why does backpropagation beat "nudge each weight and measure the loss change", given both give the same gradients eventually?
Both estimators converge to the true derivative - the checker depends on that agreement - so accuracy is not the differentiator; cost is. Pricing 88 weights numerically costs 176 full forward passes; backprop caches one forward sweep and walks backwards once. Option four conflates the cost of estimating a gradient with the speed of descending on it; the estimator choice does not change how many epochs descent needs.
During training the last layer's mean absolute delta reads large while layer 1's sits near 0.001. What is this pattern, and what follows?
The backward signal attenuates with every hop through tanh-prime factors below one, so deep stacks starve their earliest layers - the bar chart above shows exactly this ordering live. Exploding is the opposite sign of trouble; overfitting is diagnosed from a test split, not from delta sizes; and dead neurons are a per-unit phenomenon, invisible in a per-layer average like this one.

Where this came from

Backpropagation's founding paper is Rumelhart, Hinton and Williams, Learning representations by back-propagating errors, Nature 323:533-536 (1986). The slow-derivation style of section 1, and the reuse argument of section 2, follow Nielsen, Neural Networks and Deep Learning, ch. 2. The stability-minded reader should also know Karpathy's micrograd, a tiny autograd engine built from scratch under the same zero-dependency discipline this course keeps. The checker formula follows the relative-error convention used in the CS231n notes.
