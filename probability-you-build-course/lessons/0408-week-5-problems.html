Week 5 problems: the network, worked by hand where it can be

45-60 min graded easy to hard Eight problems from one-neuron arithmetic to a recorded vanishing-gradient experiment, every step shown, every solution hidden until you ask. Close with the design problem: choose the machine you will defend.

How to work this set

  • Pencil first: P1–P4 need nothing but the chain rule and honesty. P6 needs a calculator that handles e⁻¹.
  • Code second: P5 and P8 extend your local copy of this week's build (assets/builds/glassnet.js). The checker is your grader.
  • Solutions stay collapsed until you open them. Reading a solution before attempting the problem costs you the problem.
  • The design problem at the end is the week's capstone artefact: half a page of defended choice with your own screenshots as evidence.

P1 (easy). A neuron by hand

A single neuron has weights w1 = 2, w2 = −1, bias b = 0. Input x = (1, 3). Compute z, then a = sigmoid(z), rounded to three decimals, then say what the neuron believes in words.

Show solution
  1. Weighted vote. z = w₁x₁ + w₂x₂ + b = 2(1) + (−1)(3) + 0 = −1.
  2. Squash. a = sigmoid(−1) = 1 / (1 + e¹) = 1 / (1 + 2.71828) = 1 / 3.71828 = 0.26894... → 0.269. (Recomputed mechanically when this page was written.)
  3. Read it as probability. This neuron believes class 1 with probability about 27% for this input - below even coin-flip confidence, because the negative weight on the large feature dragged the vote down.
Notice the shape of the whole exercise: one multiply-add and one squash. Lesson 0400's boundary was exactly this computation run over every point of the plane.

P2 (easy). Why one line cannot do it

Four points on the unit square: A(0,0) label 1, B(1,0) label 0, C(0,1) label 0, D(1,1) label 1 - the XOR corners. Prove that no single straight line separates the label-1 points from the label-0 points.

Show solution

Suppose some line does the job: its inside-positive form is ax + by + c > 0 for label 1. Write what each point demands:

  1. A(0,0): c > 0.
  2. B(1,0): a + c < 0.
  3. C(0,1): b + c < 0.
  4. D(1,1): a + b + c > 0.
  5. Add inequalities 2 and 3: a + b + 2c < 0, so a + b + c < −c.
  6. But inequality 1 says c > 0, hence −c < 0, giving a + b + c < 0 - contradicting inequality 4's strict positive requirement.
No coefficients (a, b, c) survive all four demands, so no such line exists. One neuron draws precisely such a line (z = ax + by + c), which is lesson 0401's plateau in algebra: the model class simply does not contain a correct answer.

P3 (medium). Composition beats one line

Using P2's four points, build a two-layer fix from threshold units H(t) = 1 if t > 0, else 0. Two units in the hidden layer, one summation output. Verify all four points.

Show solution

The two label-1 corners are A (where x + y is small) and D (where it is large); the label-0 pair sits between. So fire one voter for "x + y very small" and another for "x + y very large":

  1. Voter 1: g₁ = H(0.5 − x − y) - fires when x + y < 0.5, the corner near A.
  2. Voter 2: g₂ = H(x + y − 1.5) - fires when x + y > 1.5, the corner near D.
  3. Output: o = g₁ + g₂. Check A(0,0): x+y = 0, g₁ = 1, g₂ = 0, o = 1. Correct.
  4. B(1,0): x+y = 1, both voters silent, o = 0. Correct. C(0,1): same by symmetry, o = 0. Correct.
  5. D(1,1): x+y = 2, g₁ = 0, g₂ = 1, o = 1. Correct.
Two threshold voters plus one sum cover a region no single voter can draw - two half-plane strips glued by addition. This is the pencil sketch of what lesson 0402's network learned to do smoothly: the bent tanh boundary is the differentiable limit of exactly this trick.

P4 (medium). Chain rule down two layers, by hand

Tiny net: h = tanh(w1x), output p̂ = sigmoid(w2h), loss L = −(y log p̂ + (1−y) log(1−p̂)), with x = 1, w1 = 1, w2 = 1, y = 1. Compute ∂L/∂w₂ and ∂L/∂w₁ to four decimals, showing every intermediate.

Show solution
  1. Forward. h = tanh(1) = 0.76159. u = w₂h = 0.76159. p̂ = sigmoid(u) = 1/(1 + e−0.76159) = 1/(1 + 0.46694) = 0.68170.
  2. Loss gradient at p̂. With y = 1, L reduces to −log p̂, so ∂L/∂p̂ = −1/p̂ = −1.46692.
  3. Through the sigmoid. dp̂/du = p̂(1−p̂) = 0.68170 × 0.31830 = 0.21699. Chain them: ∂L/∂du = −1.46692 × 0.21699 = −0.31830 (which is exactly p̂ − y - the shortcut from lesson 0404).
  4. To w₂. du/dw₂ = h = 0.76159, so ∂L/∂w₂ = −0.31830 × 0.76159 = −0.2424.
  5. To w₁. du/dh = w₂ = 1, dh/dw₁ = 1 − h² = 1 − 0.58003 = 0.41997, so ∂L/∂w₁ = −0.31830 × 1 × 0.41997 = −0.1337.
Both gradients are negative: raising either weight lowers the loss by pushing p̂ toward 1. Every number here reproduces mechanically; if your walk disagrees past rounding, suspect step 3 - the sigmoid-plus-cross-entropy collapse to p̂ − y is where sign errors like to hide.

P5 (medium-code). Gradient check in your page

Add to your local copy of the build a routine that picks five random weight indices j, takes ganalytic[j] from your backward pass, computes gnumeric[j] = (L(w + εej) − L(w − εej)) / (2ε) with ε = 10−5, and prints maxj |ga − gn| / max(1, |ga| + |gn|).

Show solution

This problem is milestone M3's acceptance gate, and the shipped checker button implements it - read its source in glassnet.js, function checkGradients: fresh full-batch analytical gradients, five indices drawn from a seeded stream (so everyone checks the same weights), central differences, worst relative error printed. Expected outcomes, each mapped to its cause:

  • 2.9 × 10−11 on a fresh 2–8–8–1 net, 4.6 × 10−13 after 500 epochs: what the shipped maths prints. Treat anything below 10−6 as a pass.
  • 2 × 10−2 to 1 × 10−1: the wrong derivative entirely - a sigmoid′ = a(1−a) left where tanh′ = 1−a² belongs.
  • 2 × 10−2 to 2 × 10−1: the analytic gradient is identically zero, because you accumulated into a copy of the array. Note the overlap with the row above - a loud number tells you the gradient is wrong but not which mistake it is. Print one analytic gradient and look at whether it is zero.
  • 10−6 to 10−4: the right derivative on the wrong argument - 1 − z² on the cached pre-activations instead of 1 − a² on the activations. This is the dangerous one: quiet enough to pass for rounding if you were expecting a catastrophe, loud enough that training limps. It is the reason the pass bar is a number rather than a feeling.

Two traps in how you test. First, checking on blobs proves nothing about a hidden-layer bug: that network has no hidden layer, so all three mistakes above print a clean 1.8 × 10−11. Check on moons. Second, do not "improve" the check by shrinking ε. The error is a U in ε, and 10−5 is its floor: the same fresh net prints 2.6 × 10−7 at ε = 10−2 where truncation dominates, 2.9 × 10−11 at 10−5, and climbs back to 3.9 × 10−4 at 10−12, where subtracting two nearly equal losses has thrown away the precision you needed.

The habit this installs outlives the week: any hand-coded gradient gets finite-differenced before it gets trusted.

P6 (medium-hard). Softmax arithmetic and the max trick

Scores s = (1000, 1001, 999). Compute softmax naively in double precision and explain the result. Then compute softmax(s − 1001) by hand and show the two agree mathematically.

Show solution
  1. Naive. IEEE double precision overflows near e^709.8 (the largest finite double is about 1.8 × 10308). e¹⁰⁰⁰ and e¹⁰⁰¹ evaluate to Infinity; e⁹⁹⁹ is finite but vanishes in the total Infinity/Infinity. Naive softmax prints NaN, NaN, NaN - not an approximation, an absence of opinion. (Demonstrated live in lesson 0405's bench via the 1000 button.)
  2. Shifted. s − 1001 = (−1, 0, −2). e⁻¹ = 0.36788, e&sup0; = 1, e⁻² = 0.13534. Sum = 1.50322.
  3. Distribution. 0.36788/1.50322 = 0.24473; 1/1.50322 = 0.66524; 0.13534/1.50322 = 0.09003. Check: 0.24473 + 0.66524 + 0.09003 = 1.00000.
  4. Equality argument. For any constant c, softmax(s − c)i = e(si − c) / Σj e(sj − c): every term in numerator and denominator carries the same factor e−c, which cancels in the ratio. The shifted computation is the true answer; the naive one computed nothing.
Subtracting the max is therefore not a hack but a free choice among infinitely many equivalent formulations, picked because it keeps every exponent at or below e&sup0;.

P7 (hard). Temperature limits

Show: (a) as T → 0+, softmax(s/T) concentrates all mass on argmax(s); (b) as T → ∞ it approaches uniform; (c) dividing logits by T relates multiplicatively to rescaling scores, and why fitted temperature scaling (week 6) still counts as reshaping rather than retraining.

Show solution
  1. (a) Let smax = max s. Divide every exponentiated term by e^(smax/T): terms become e^((sᵢ − smax)/T) with the maximiser contributing e&sup0; = 1. For any i with sᵢ < smax, the exponent (sᵢ − smax)/T is strictly negative and divided by T → 0+, so it tends to −∞, killing the term. Total mass survives only on the argmax: probability 1 there, 0 elsewhere - greedy decoding.
  2. (b) As T → ∞, sᵢ/T → 0 for every i, so every exponential tends to e&sup0; = 1 and the distribution tends to 1/k for each of k candidates - exact uniformity, the dashed line the bench never lets you cross toward zero information.
  3. (c) Dividing logits by T multiplies them by 1/T, and softmax responds only to score differences scaled linearly - so temperature is a pure reshaping of a fixed opinion. Week 6's fitted variant (Guo et al., arXiv:1706.04599) chooses T once on held-out data to improve calibration; no parameter of the underlying model moves during or after the fit, which is exactly why accuracy can provably stay untouched while probabilities become trustworthy.

P8 (hard-code). Watch a gradient vanish

Set lesson 0404's build to two spirals and hidden layers 4, 4, 4, 4 - a 2–4–4–4–4–1 tanh stack - at learning rate 2, and read the five gradient bars at epoch 100 and again at epoch 2000. Write the ten numbers down before reading the solution, then answer the question they raise: the shrinking is not there at epoch 100 and is enormous at epoch 2000, so where did it come from? Explain using tanh′ = 1 − tanh², and say what the loss readout is doing while this happens.

Show solution

These are the bars this build draws, with the mean value of tanh′ across each hidden layer's units measured alongside them, so you can watch the cause and the effect together. Layer 5 is the output neuron.

  1. The answer to the question. At epoch 100 there is essentially no vanishing - the front bar is the second largest of the four hidden ones. The starvation is trained into the network, not present at initialisation, and the third column says why: at epoch 1 the mean tanh′ per layer sits at 0.91 to 0.99, so four hops cost a factor of about 0.9⁴ ≈ 0.66, which is nothing. By epoch 2000 the same means are about 0.15, 0.02, 0.03 and 0.25, whose product is roughly 2 × 10−5. That is the vanishing, and it arrived because the units saturated.
  2. Why saturation does it. tanh′ = 1 − a² is 1 at the knee and falls toward 0 as |a| approaches 1. A backward hop multiplies the signal by the layer's weights and by these factors, so a layer whose units have been driven to their flats passes almost nothing through. Layer 2's mean of about 0.02 at epoch 2000 puts its units at |a| ≈ 0.99 on average: fully committed, and therefore deaf.
  3. Read the loss column, because it is the point. This network does not merely learn slowly. It starts at 0.6912, dips to 0.61 around epoch 500, and is back above 0.70 by epoch 2000 - and ln 2 ≈ 0.693 is what an uninformed coin flip scores. Four narrow tanh layers on spirals do not learn the problem at all, while the two-hidden-layer network of lesson 0402 handles the same data. Depth bought a failure.
  4. An honest caveat about the last two rows. Rows 1 and 100 reproduce to every digit shown, in any browser and in Node. Rows 500 and 2000 do not, and the reason is worth knowing. The seeded data and the initial weights are identical everywhere, because integer arithmetic and IEEE addition and multiplication are exactly specified. Math.tanh, Math.exp and Math.log are not: the standard permits an implementation-dependent approximation, so two engines can differ in the last bit. On a run that is descending steadily, that difference stays in the last bit. On this run it does not, because a network stuck near a plateau amplifies any perturbation - which is why the same experiment in Node prints 0.6952 and bars of 0.0000 0.0000 0.0003 0.0071 0.5000 at epoch 2000 instead. Every conclusion above survives that: the front bars are three to four orders of magnitude below the output bar in both, the mean tanh′ has collapsed in both, and the loss is at or above ln 2 in both. Quote orders of magnitude from a chaotic run, never four decimals - and notice that the difference between "reproducible" and "chaotic" is a property of the run, not of the seed.
  5. One honest caveat about the bars. The chart plots mean |delta| per layer, and a layer's mean is taken over its own width, so a wide layer and a narrow one are not directly comparable. That is why the shallow 2–8–8–1 run shows no clean ordering at all: with only two hops there is nothing to attenuate, and the widths differ. Compare bars within one architecture over time, which is what the table above does.
  6. The fix families, named and filed. ReLU-type activations keep the slope at exactly 1 on the active branch; normalisation keeps pre-activations near the knee where the slope is high; residual adds give the signal a skip path around each hop. Each attacks one term of that product. Depth of treatment belongs to a deep-learning course - what you own is the diagnostic pair: front bars near zero together with a loss stuck at ln 2 means the architecture is starving its own input layer, and no learning rate fixes that.

Design problem: choose the machine you will defend

The briefA hospital triage desk wants a small, auditable model reading two numbers - age band coded 0–4, and a lab score normalised to [0, 1] - and outputting p(complication within 30 days). They ask you to recommend either (a) logistic regression or (b) a two-hidden-layer MLP. Decide, train both in this week's page (the blobs dataset stands in for the lab-score geometry; noisy moons stands in for messier reality), and write half a page covering: what each model can represent on this input space; evidence from your own runs; the calibration behaviour you would expect before any week-6 tooling exists; and - stated explicitly - what observation in a future evaluation would falsify your choice.
Show rubric (self-assess before you submit anywhere)
LevelEvidence shown
FailChoice asserted from fashion ("MLP is modern"); no run evidence; no falsifier.
PassCorrect representational claim (linear boundary vs bent boundary); one screenshot per model on comparable data; names at least one falsifying observation - for example "if a well-tuned linear model's residuals show systematic curvature by lab score, I was wrong".
StrongAdds the deployment argument: with two inputs and audit requirements, the interpretable model wins unless measured accuracy gain exceeds a stated margin; quantifies the gap from their own runs; notes the larger model's overfitting risk via the test-split curve from lesson 0407.
ExcellentAlso states the probabilistic commitment being made - both models output P(y = 1), so downstream thresholds are decisions, week-6 territory - and pre-registers which metric will arbitrate, before seeing week 6's machinery.
There is no single right answer; there is a defensible one and an undefended one. The falsifier clause is what separates them.
