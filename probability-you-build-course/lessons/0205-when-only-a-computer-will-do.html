When only a computer will do, write the ten lines yourself

14 min build inside Two parameters ended the algebra's luck: the phone tracker's peak has no formula, so you will derive its slope, code the climb, and break it with a bad step size on purpose.

The one-minute version

  • The grid search is honest but blind: it only knows settings it thought to visit. A smooth surface invites something better - evaluate the slope, step uphill, repeat.
  • You will derive the tracker's slope by the chain rule, all five factors of which mean something physical, then write the ten-line ascent that uses it.
  • The step size eta decides everything: this page's own dataset climbs home in sixty steps at eta near 40, crawls at 0.5, and diverges off the map near 1,800.
  • Dividing the gradient by the number of towers keeps one eta working everywhere - the same fix week 4's trainer will need.

1. Why the pyramid's trick does not carry this far

Build 1 fell to a double loop because two parameters on a coarse mesh is 833 evaluations and a browser shrugs. The habit scales badly: ten parameters at even three points each is 59,049 fits per refresh. Worse, a grid answers nothing between its mesh points - the true argmax of build 1 was lucky to sit on your multiples of five. What you want is local information used globally: at this spot, which way is uphill, and how steeply? That object is the gradient, and for the tracker it can be derived by hand.

2. The tracker's slope, derived once

Each tower reports a signal strength in dBm. Under the standard log-distance model the predicted strength falls logarithmically with true distance, and the shadowing noise is Gaussian in dB, so the log-likelihood of a candidate position q collapses to a sum of squared residuals - weighted least squares, a standard result in the localization literature:

LL(q) = -∑i ( ri - predi(q) )² / (2σ²) ri is tower i's reading; predi(q) = Pref - 10γ·log10(di) is what the model predicts if the phone sits at q, with di the straight-line distance from tower i to q and σ the shadowing spread in dB. A position explaining all towers well leaves every residual small.
  1. Differentiate one term. By the chain rule, ∂LL/∂q = Σi (ri - predi)/σ² · (∂predi/∂d) · (∂d/∂q).
  2. Name the middle factor. Differentiating the path-loss law: ∂pred/∂d = -10γ/(ln 10 · d). Predicted strength falls slowly when the phone is far away, steeply up close.
  3. Name the last factor. Distance changes fastest along the line to the tower: ∂d/∂q = (q - ti)/di, a unit vector pointing from tower to guess.
  4. Assemble. dLL/dq = Σi -(ri - predi) · 10γ /(σ² ln 10 · di²) · (q - ti). Read physically: if a reading comes in stronger than predicted, walk toward that tower; weight the pull by closeness, because nearby towers discriminate sharply.

General treatments of these mechanics live in partial derivatives and what the gradient points; the derivation above stays two-dimensional on purpose. One more engineering decision before coding: divide the summed gradient by the number of active towers. Without that, doubling the measurements doubles every step and your tuned eta stops being tuned - the raw-sum version oscillated visibly during this course's prototyping, and week 4 will meet the identical issue training on bigger datasets.

3. The learner's optimiser

ascent, hand-coded · evaluate slope, step uphill, repeat
function gradStep(meas, q, eta) {
  const g = gradLL(meas, q);     // your derived slope, one vector
  return { x: q.x + eta * g.x,
           y: q.y + eta * g.y }; // the entire update rule
}

function ascend(meas, q0, eta, steps) {
  const path = [q0];
  let q = q0;
  for (let s = 0; s < steps; s++) {
    q = gradStep(meas, q, eta);
    path.push(q);
  }
  return path;
}

Check yourself

Your gradient ascent overshoots the peak and oscillates forever. Which knob do you turn first?
Oscillation means each step carries you across the summit and up the far side: the direction was fine, the magnitude was greedy. More iterations repeat the leap, and a better start changes nothing about step greediness. Eta is the knob whose whole job is step magnitude.
In this model the noise sigma lives in dB. Why does a constant dB error imply a constant ratio distance error?
The path-loss law predicts dB as -10 gamma log10(d), so adding a constant in dB space multiplies d by 10^(constant/10 gamma) regardless of d. Equal relative scatter at any range is why the likelihood contours flare outward at distance, and why close-in towers dominate the fit.
Your teacher. Deliberately break the climb twice: once with eta tiny, once enormous, predicting aloud what the readout will say before pressing run. Then halve a good eta and count how much longer convergence takes - the rough doubling is the signature of linear convergence and the reason eta tuning feels so touchy.

Where this came from

Sensor model: the log-distance path loss model, canonical textbook treatment in Rappaport, Wireless Communications: Principles and Practice. Gaussian-noise positioning reducing to least squares is standard in the localization literature (survey record). Gradient vocabulary: partial derivatives, the gradient points uphill, and for deeper mechanics gradient descent as a first-order model. Newton-style methods exist and matter; this course names them here and moves on.
