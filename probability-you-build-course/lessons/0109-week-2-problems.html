Week 2 problems: the garden, on paper

about 2 hours working Ten problems graded easy to hard, two of them code. Attempt on paper first; every solution stays hidden until you ask.

How this sheet works

  • Each problem is self-contained and names the build page it grows from.
  • Attempt before revealing: the disclosure exists so that your attempt meets the worked solution, not so the solution can replace it.
  • Every solution ends in a sanity check - one sentence telling you roughly what the answer should be, so you can catch your own arithmetic without us.
  • Problems 1-8 are pencil-and-paper; problems 9-10 are JavaScript you can run in any browser console.

Practice problems 1 to 10, easiest first

Practice 1foundation

200 dots land uniformly on a plate cut into 40 equal cells. Take one cell: the count in it is Binomial(n = 200, p = 1/40). Compute P(X = 7) exactly using the multiplicative form of C(n,k), then compare against a Poisson approximation with rate np = 5.

Show the worked solution
  1. Name the parameters. n = 200, p = 0.025, so the question is C(200, 7)(0.025)7(0.975)193.
  2. Compute the coefficient multiplicatively. Multiply seven rising factors while dividing by 1 through 7: after each step the running value reads 194; 18,915; 1,235,780; 60,862,165; 2,410,141,734; 79,936,367,511; and finally C(200,7) ≈ 2.284 × 1012. No factorial anywhere near its overflow.
  3. Multiply the three pieces. (2.284 × 1012) × (0.025)7 × (0.975)193 ≈ 0.1052.
  4. Poisson ballpark. With rate np = 5: e-5·57/7! ≈ 0.1044.

Sanity check. The two answers agree within one percent, which is what large-n tiny-p promises; if your binomial value landed far from the Poisson one, suspect the coefficient, not the concept.

Practice 2foundation

A rejection sampler's counter reads 4,000 accepted out of 47,000 proposals. Estimate the Bernoulli success probability p, give the variance of the accepted count over 47,000 attempts, and judge how stable the estimate is.

Show the worked solution
  1. Estimate p. p-hat = 4000/47000 ≈ 0.0851. This estimates the mean of f over the proposal region, per page 0103.
  2. Variance of the count. For Binomial(47000, 0.0851): Var = m·p(1-p) = 47000 × 0.0851 × 0.9149 ≈ 3,660.
  3. Standard deviation. sqrt(3660) ≈ 60.5 accepted counts, one sigma of wobble either side of 4,000.

Sanity check. The sd of about 60 is under two percent of the count itself, so the 8.5% acceptance figure is stable - exactly why the build's simulated-versus-analytic pair sit close together.

Practice 3working

X is uniform on [0, 1] and Y = X². Derive the CDF and PDF of Y, and state which part of [0, 1] Y prefers.

Hint

Start from the definition: F_Y(y) = P(Y ≤ y). Substitute what Y is, then solve for X.

Show the worked solution
  1. Write the event in terms of X. P(X² ≤ y) = P(X ≤ sqrt(y)) for y in [0, 1], because X is never negative.
  2. Use X's own CDF. X uniform gives P(X ≤ sqrt(y)) = sqrt(y), so F_Y(y) = sqrt(y).
  3. Differentiate. f_Y(y) = 1/(2 sqrt(y)) on (0, 1].
  4. Read off the preference. The density blows up gently near 0: squares of uniforms pile toward zero.

Sanity check. Integrate the density: an antiderivative is sqrt(y), which runs 0 to 1 across [0,1] - total area 1, as a PDF requires.

Practice 4working

Pareto circles, after Piech's algorithmic art example: radii have F(x) = 1 - x-a for x ≥ 1. Derive the inverse-transform sampler, then compute the median radius when a = 2.

Show the worked solution
  1. Set the ledger equal to u. 1 - x-a = u, so x-a = 1 - u.
  2. Invert both sides. xa = 1/(1-u), giving x = (1-u)-1/a - the sampler, one power away from the exponential machine of page 0104.
  3. Median at a = 2. Set u = 0.5: x = (0.5)-1/2 = sqrt(2) ≈ 1.414.

Sanity check. The median sits above the support floor of 1, as it must, and small a pushes it further out - heavy tails are the point of Pareto rings in artwork.

Practice 5working

Radii in the ring layer are Exponential with rate λ = 8. What fraction of rings has radius below 1/λ? Below 2/λ?

Show the worked solution
  1. Evaluate the CDF at 1/λ. F(1/8) = 1 - e-1 ≈ 0.632.
  2. Evaluate at 2/λ. F(2/8) = 1 - e-2 ≈ 0.865.
  3. Interpret. Nearly two-thirds of all rings crowd inside the mean radius 1/λ, and barely 13% live between one and two means out.

Sanity check. These are the exponential's famous landmarks, 63% and 86%, independent of λ - if your numbers depend on the rate, the exponent went wrong.

Practice 6working

Splat x-offsets are N(0, σ²). The slider moves σ from 40 to 80. State the new expectation and variance, and the fraction of offsets within one sigma of the mean.

Show the worked solution
  1. Expectation. E stays 0: sigma moves spread, never centre.
  2. Variance. σ² goes from 40² = 1600 to 80² = 6400 - fourfold, because variance squares the deviation.
  3. Within-one-sigma share. For any normal, about 68% lies within one standard deviation of the mean - quoted as the normal's property, and visible as the dashed span on page 0105's plate.

Sanity check. Doubling sigma doubles the cloud's width but multiplies its area-density peak down by half - width up, height down, total area pinned at 1.

Practice 7frontier

A fair walk takes N = 200 independent +/-1 steps. Estimate P(|endpoint| > 20) using the normal approximation, and say what the cone picture suggests the answer should feel like.

Show the worked solution
  1. Standardise. sd = sqrt(200) ≈ 14.14, so the threshold is z = 20/14.14 ≈ 1.414 sigmas.
  2. Two-tail normal tail. P(|Z| > 1.414) ≈ 2 × (1 - 0.9213) ≈ 0.157.
  3. Read it against the cone. About one walk in six escapes the ±20 line - rare enough to notice, common enough to see happen among sixty walkers.

Sanity check. Roughly the 16% that a 1.4-sigma two-sided tail should give; if you got 4%, you took a one-sided tail or halved twice.

Practice 8frontier

Splats are bivariate normal with sigma-x = 60, sigma-y = 20, independent coordinates. Describe the cloud, write both marginal densities, then state precisely what visibly changes when rho rises to 0.8.

Show the worked solution
  1. The cloud. An ellipse elongated along x: three times wider than tall, upright while rho = 0.
  2. The marginals. f_X is the normal centred 0 with sd 60; f_Y the normal centred 0 with sd 20. Independence makes the joint their product, but only the marginals are asked for.
  3. Raising rho. The ellipse tips diagonally upward; both marginal densities stay exactly as written above, and both edge histograms hold still.

Sanity check. This is page 0106's punchline with numbers attached: dependence changed, every marginal did not - shadows cannot see tilt.

Practice 9working · code

Generalise the u-machine: implement inverse-transform sampling for a tabulated CDF - a sorted grid of (x, F(x)) pairs with no closed form. Validate it against the closed-form exponential by comparing the sample mean of 100,000 draws against 1/λ within 3%.

Hint

You need, for a given u, the first grid index where F crosses u. Binary search does that in log(steps) comparisons.

Show the worked solution
tabulated-inverse-sample.js · runnable in any browser console
function makeTabulatedSampler(xs, cdfs) {
  // xs ascending, cdfs ascending from ~0 to ~1
  return function (u) {
    var lo = 0, hi = cdfs.length - 1;
    while (lo < hi) {
      var mid = (lo + hi) >> 1;
      if (cdfs[mid] < u) lo = mid + 1; else hi = mid;
    }
    return xs[lo]; // first threshold whose CDF reaches u
  };
}

// validation against the exponential, lambda = 8
var lam = 8, N = 100000, sum = 0;
var grid = [], M = 1000;
for (var i = 0; i <= M; i++) {
  var x = (i / M) * (6 / lam);
  grid.push([x, 1 - Math.exp(-lam * x)]);
}
var draw = makeTabulatedSampler(
  grid.map(function (p) { return p[0]; }),
  grid.map(function (p) { return p[1]; })
);
for (var k = 0; k < N; k++) {
  sum += draw(Math.random());
}
console.log(sum / N, 'vs', 1 / lam); // e.g. 0.1254 vs 0.125

Sanity check. At 100k draws the standard error of the mean is roughly 0.00044 for this distribution, so landing within 3% of 0.125 is nearly guaranteed; a systematic miss means the grid clipped the tail - widen xmax.

Practice 10working · code

Return to the PMF build (page 0102). Add a second stick layer computing the Poisson approximation P(X=k) = e-mmk/k! with m = n·p_cell, drawn in a different colour behind the bars, and report the total variation distance between the observed cell-count histogram and the Poisson law at n = 5000. Expect it below about 0.05.

Show the worked solution
poisson-sticks.js · the overlay and the distance, drop-in for the pmf build
function poissonStickHeights(n, pCell, kMax) {
  var lam = n * pCell, out = [];
  var pk = Math.exp(-lam);            // P(0)
  for (var k = 0; k <= kMax; k++) {
    out.push(pk);
    pk *= lam / (k + 1);              // the stable ratio step
  }
  return out;
}

function tvDistance(counts, pmf, cells) {
  var tv = 0;
  for (var k = 0; k < pmf.length; k++) {
    tv += Math.abs((counts[k] || 0) / cells - pmf[k]);
  }
  return tv / 2;
}
// draw each height as a thin stick behind the existing bars,
// then log tvDistance(...) at n = 5000, 64 cells: typically ~0.02-0.04

Sanity check. Sticks and bars should interleave rather than sit apart - the Poisson is a good approximation here because n is large and p_cell small. A TV distance stuck near 0.1 signals the ratio step accumulating error: compute P(0) directly and rebuild multiplicatively, never with factorials.
