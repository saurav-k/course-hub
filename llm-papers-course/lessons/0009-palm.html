PaLM: Scaling Language Modeling with Pathways

2022 Chowdhery, Narang, Devlin, Bosma, Mishra, and 62 others (Google). · arXiv:2204.02311

The one-minute version

  • PaLM is a 540-billion-parameter dense decoder-only Transformer - every parameter is used for every token, no mixture-of-experts.
  • It was trained with Google's Pathways system across two TPU v4 pods (6144 chips), one of the largest single models trained at the time.
  • It bundles a set of now-standard architecture upgrades: SwiGLU activations, parallel attention and feed-forward layers, multi-query attention, RoPE positions, no bias terms, and shared input-output embeddings.
  • Its headline result was reasoning: with chain-of-thought prompting, PaLM broke through on multi-step arithmetic and commonsense tasks and beat the fine-tuned state of the art on several BIG-bench problems.

1. Why this paper exists

By 2022 the field had a recipe: make the model bigger, feed it more text, and capabilities keep climbing. GPT-3 (Lesson 06) proved few-shot learning at 175B parameters. But two questions were still open. Could you push an order of magnitude further in training scale without the whole run collapsing? And would raw scale unlock genuinely new abilities, especially reasoning, rather than just sharper autocomplete?

PaLM answers both. The engineering answer is Pathways, a system that lets one model span two entire TPU pods efficiently. The science answer is that at 540B, with the right prompting, PaLM crosses thresholds on tasks that smaller models simply fail - some skills appear discontinuously with scale.

2. Dense, not sparse: what 540B means here

PaLM is densely activated. That word matters. In a mixture-of-experts model (Module 09) only a slice of the parameters fire for any given token, so a "540B" MoE might touch far fewer parameters per step. PaLM touches all 540 billion for every token. That makes it a clean scaling experiment - and an expensive one.

3. The Pathways training system

Training a 540B dense model needs thousands of accelerators working as one. A single TPU v4 pod has 3072 chips; PaLM used two pods, 6144 chips. The trick is combining two kinds of parallelism. Model parallelism splits one copy of the giant model across many chips (no single chip could hold it). Data parallelism runs many copies over different batches of data and averages the gradients. Pathways coordinates both across pods with high efficiency.

4. The architecture upgrades, one by one

PaLM keeps the decoder-only Transformer from GPT but swaps in six refinements. Each is small; together they improve quality and training stability. You will meet most of them again in LLaMA (Lesson 12) and later.

  • SwiGLU activation in the feed-forward network - a gated activation that outperforms plain ReLU at the same compute.
  • Parallel layers - attention and the feed-forward network read the same normalised input and run side by side, instead of one after the other. This speeds up large-scale training with roughly neutral quality.
  • Multi-query attention (MQA) - all heads share one Key and one Value projection (many queries, one key/value). This shrinks the memory read during generation and speeds up inference. Full lesson: 0015.
  • RoPE embeddings - rotary position encoding instead of learned or sinusoidal absolute positions. Better extrapolation to longer sequences. Full lesson: 0013.
  • No biases - bias terms are dropped from all dense layers and layer norms, which improved training stability at scale.
  • Shared input-output embeddings - the token embedding matrix and the final output projection are the same weights, saving parameters.

5. SwiGLU, exactly

A standard Transformer feed-forward network is Linear -> ReLU -> Linear. SwiGLU replaces the middle with a gate: it computes two linear projections, passes one through a smooth Swish activation, and multiplies them elementwise. One branch decides "how much", the other decides "of what".

FFNSwiGLU(x) = ( Swish(x W1) ⊙ (x W3) ) W2 x W1 and x W3: two separate linear projections of the same input. Swish(z) = z · sigmoid(z): a smooth activation that, unlike ReLU, never fully zeroes small negatives. ⊙: elementwise multiply - the Swish branch gates the other branch. W2: projects the gated result back to the model width. Because there are now three matrices instead of two, PaLM shrinks the hidden width so total compute stays comparable.
Why gating helps A plain ReLU makes a hard yes/no decision per unit. A gate makes a soft, input-dependent decision: the network can pass a feature at 30% strength. That extra expressiveness, for the same parameter budget, is why SwiGLU became the default feed-forward network in PaLM, LLaMA, Mistral, and most models since.

6. Parallel layers: the block rewired

In the original Transformer (Lesson 01) a block is serial: normalise, attend, add back, normalise again, feed-forward, add back. Attention must finish before the feed-forward network starts. PaLM makes them parallel: one normalisation feeds both attention and the feed-forward network at once, and their outputs are summed with the residual together.

7. Implement it: SwiGLU and the parallel block

Here is the difference in code. First the serial block you already know from Lesson 01, then PaLM's parallel version with a SwiGLU feed-forward network. Read them side by side - the only structural change is that attention and the feed-forward network share one norm and are added together.

palm_block.py · runnable with torch
import torch, torch.nn as nn, torch.nn.functional as F

class SwiGLU(nn.Module):
    """PaLM/LLaMA feed-forward network: gated Swish."""
    def __init__(self, d_model, hidden):
        super().__init__()
        self.w1 = nn.Linear(d_model, hidden, bias=False)  # gate branch
        self.w3 = nn.Linear(d_model, hidden, bias=False)  # value branch
        self.w2 = nn.Linear(hidden, d_model, bias=False)  # project back
    def forward(self, x):
        # Swish(x) = x * sigmoid(x); F.silu is exactly that
        return self.w2(F.silu(self.w1(x)) * self.w3(x))

class SerialBlock(nn.Module):
    """The Lesson 01 shape: attention THEN feed-forward, each own norm."""
    def __init__(self, attn, d_model, hidden):
        super().__init__()
        self.n1, self.n2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.attn, self.ffn = attn, SwiGLU(d_model, hidden)
    def forward(self, x):
        x = x + self.attn(self.n1(x))     # attend, add residual
        x = x + self.ffn(self.n2(x))      # THEN feed-forward, add residual
        return x

class ParallelBlock(nn.Module):
    """The PaLM shape: ONE norm feeds both branches, summed together."""
    def __init__(self, attn, d_model, hidden):
        super().__init__()
        self.norm = nn.LayerNorm(d_model, bias=False)   # note: no bias
        self.attn, self.ffn = attn, SwiGLU(d_model, hidden)
    def forward(self, x):
        h = self.norm(x)                  # shared, computed once
        return x + self.attn(h) + self.ffn(h)   # both read h, summed with residual

# smoke test with a stand-in attention module
attn = lambda h: h                       # identity placeholder for shape check
blk  = ParallelBlock(attn, d_model=128, hidden=256)
out  = blk(torch.randn(2, 6, 128))
print(out.shape)                          # torch.Size([2, 6, 128])

Two things to notice. The SwiGLU uses bias=False everywhere, matching PaLM's no-bias choice. And in ParallelBlock.forward, self.norm(x) is computed once and reused by both branches - that shared h is the whole idea. On real hardware the attention and feed-forward matrix multiplies can then be batched into fewer, larger operations.

8. What scale unlocked: reasoning

PaLM's most cited result is not a benchmark number but a behaviour. On multi-step problems - grade-school math, logical puzzles - large models fail if you ask for the answer directly. But if you prompt them to show their work first (chain-of-thought, Lesson 30), PaLM 540B jumps sharply and, on several tasks, beats systems that were fine-tuned specifically for them.

What does it mean that PaLM is a "dense" 540B model?
Dense means no expert routing: all 540B parameters fire for every token, unlike a mixture-of-experts model.
In PaLM's parallel block, what is shared between the two branches?
One LayerNorm is computed once; both attention and the SwiGLU feed-forward read that same normalised input, and the outputs are summed.
What does the SwiGLU feed-forward network add over a plain ReLU one?
SwiGLU multiplies a Swish-activated gate against a value branch, giving a soft, input-dependent gate instead of ReLU's hard cutoff.
What was PaLM's headline capability finding?
At 540B, chain-of-thought prompting let PaLM solve multi-step reasoning tasks, sometimes beating fine-tuned systems.
