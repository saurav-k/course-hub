Module 01 · The Transformer Core · Lesson 01

Attention Is All You Need

2017 Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin (Google Brain / Google Research). · arXiv:1706.03762

The one-minute version

  • Before this paper, sequence models (RNNs, LSTMs) read text one step at a time, which is slow and forgets long-range context.
  • The Transformer throws out recurrence entirely and uses self-attention: every token looks at every other token in one parallel operation.
  • The key trick is scaled dot-product attention over learned Query, Key, Value vectors, run in several parallel heads.
  • Because attention is order-blind, positional encodings add word-order information. Result: faster training, better translation, and the architecture behind every modern LLM.

1. Why this paper exists

In 2017 the best translation systems were recurrent: an RNN or LSTM would read a sentence word by word, carrying a hidden "memory" vector forward. Two problems dogged them. First, they are sequential - you cannot compute step 10 until step 9 is done, so training cannot use the full parallelism of modern GPUs. Second, long-range dependencies fade - information from the start of a long sentence gets diluted by the time you reach the end.

The paper's radical claim was in the title: you do not need recurrence or convolution at all. Attention is all you need.

2. The one idea: attention as soft lookup

Think of attention as a soft dictionary lookup. Every token produces three vectors by multiplying its embedding by three learned matrices:

  • Query (Q) - "what am I looking for?"
  • Key (K) - "what do I contain / advertise?"
  • Value (V) - "what do I actually pass on if selected?"

To update a token, you compare its query against every token's key. High match means high relevance. Those match scores become weights, and the token's new representation is a weighted blend of everyone's values. A token literally gathers information from the tokens it finds relevant.

3. Scaled dot-product attention, exactly

Stack all tokens' queries into a matrix Q, all keys into K, all values into V. The entire attention layer is one compact formula:

Attention(Q, K, V) = softmax( Q Kᵀ / √dk ) V Q Kᵀ: every query dotted with every key → an N×N grid of raw relevance scores. ÷ √dk: divide by the square root of the key dimension to stop the scores getting huge (which would make softmax razor-sharp and kill gradients). softmax: turn each row into weights that sum to 1. × V: use those weights to average the value vectors.
Why divide by √dk If keys and queries have dimension dk, their dot products grow roughly like √dk. Left unchecked, large scores push softmax into near one-hot spikes where gradients vanish. Dividing by √dk keeps the scores in a sane range. Small detail, big stability.

4. Multi-head attention: many views at once

One attention operation can only learn one kind of relationship. Real language has many at once: subject-verb agreement, pronoun references, adjacent-word phrasing. So the Transformer runs attention several times in parallel with different learned Q/K/V projections. Each is a head. Their outputs are concatenated and mixed by one more matrix.

5. The full Transformer block

Attention is the star, but a working block wraps it with three supporting pieces you met in the primer: a per-token feed-forward network, residual connections (add the input back), and layer normalisation (keep activations stable). Stack this block N times and you have an encoder or a decoder.

The original paper is an encoder-decoder for translation: the encoder reads the source sentence with full (bidirectional) attention; the decoder generates the translation with causal attention (each output token may only see earlier ones) plus cross-attention into the encoder. Later, LLMs kept only the decoder half - but the block above is the shared building material.

6. Positional encoding: putting order back

Here is a subtlety. Attention treats its input as a set, not a sequence - shuffle the tokens and the math is identical. But "dog bites man" and "man bites dog" are not the same sentence. So the Transformer adds a positional encoding to each embedding: a vector that depends only on the position, built from sines and cosines of different frequencies. The model can read these patterns to recover order and even relative distance.

PE(pos, 2i) = sin( pos / 100002i/d )   PE(pos, 2i+1) = cos( pos / 100002i/d ) Each dimension i is a sine or cosine wave of a different wavelength. Low dimensions wiggle fast (encode fine position), high dimensions wiggle slowly (encode coarse position). Together they give every position a unique fingerprint, and the fixed geometry lets the model reason about relative distance. Lessons 13-14 (RoPE, ALiBi) improve on exactly this.

7. Implement it: self-attention from scratch

Everything above fits in a small, runnable PyTorch module. This is causal multi-head self-attention - the exact core inside GPT. Read it against the diagrams: you will find Q/K/V projection, scaled scores, the causal mask, softmax, the value blend, and the output projection.

self_attention.py · runnable with torch
import torch, torch.nn as nn, torch.nn.functional as F

class MultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model=128, n_heads=4, causal=True):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.dk = n_heads, d_model // n_heads
        self.qkv  = nn.Linear(d_model, 3 * d_model)   # make Q, K, V in one shot
        self.proj = nn.Linear(d_model, d_model)       # W_O: mix the heads
        self.causal = causal

    def forward(self, x):                             # x: (B, N, d_model)
        B, N, d = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)        # each (B, N, d)
        # split into heads -> (B, h, N, dk)
        q = q.view(B, N, self.h, self.dk).transpose(1, 2)
        k = k.view(B, N, self.h, self.dk).transpose(1, 2)
        v = v.view(B, N, self.h, self.dk).transpose(1, 2)

        # scaled dot-product scores: (B, h, N, N)
        att = (q @ k.transpose(-2, -1)) / self.dk ** 0.5
        if self.causal:                               # forbid looking at the future
            mask = torch.triu(torch.ones(N, N, device=x.device), diagonal=1).bool()
            att = att.masked_fill(mask, float('-inf'))
        att = att.softmax(dim=-1)                      # weights sum to 1 per row

        out = att @ v                                  # blend values: (B, h, N, dk)
        out = out.transpose(1, 2).reshape(B, N, d)     # re-merge heads
        return self.proj(out)

# smoke test
x = torch.randn(2, 6, 128)          # batch 2, sequence length 6, d_model 128
y = MultiHeadSelfAttention()(x)
print(y.shape)                       # torch.Size([2, 6, 128])

Notice the causal mask: we set the future positions to -inf before softmax, so their weight becomes exactly zero. That one line is what makes a Transformer generate left to right, and it is why the same architecture can be trained on every position of a sequence at once (each position only ever sees its past). That parallel training over all positions is the efficiency the RNN could never match.

In production You would rarely write the raw softmax(QKᵀ)V today. Modern code calls F.scaled_dot_product_attention(q, k, v, is_causal=True), which dispatches to FlashAttention (Lesson 17) - same math, far less memory and time. But the module above is that math, unrolled, so you can see it.

8. Why it mattered

PropertyRNN / LSTMTransformer
Training parallelismSequential (slow)Fully parallel over positions
Path length between two tokensUp to N steps1 step (direct attention)
Long-range dependenciesFade with distanceAny distance, equal access
Cost per layerO(N · d²)O(N² · d)

The one price is that N² attention grid: cost grows with the square of sequence length. That single trade-off launched an entire research industry - FlashAttention, MQA/GQA, PagedAttention, KV-cache compression - all of which you will meet in Modules 04 and 05.

Check yourself

Retrieval practice

Answer from memory before revealing.

In attention, what do the Query and Key vectors produce together?
Query dot Key gives the raw relevance score; softmax turns scores into weights that blend the Values.
Why divide the attention scores by the square root of d_k?
Dot products grow with dimension; scaling by √d_k stops softmax from becoming a gradient-killing spike.
Why does the Transformer need positional encodings at all?
Shuffle the tokens and self-attention gives the same result; positional encodings inject the order.
What is the main computational cost of self-attention?
Every token attends to every token, so you build an N×N grid: O(N²) cost. Later papers attack exactly this.

How this connects

  • Next up, BERT keeps only the encoder and trains it bidirectionally for understanding.
  • GPT keeps only the decoder (causal attention) and trains it to generate - the shape of every LLM since.
  • The O(N²) cost flagged above is the target of FlashAttention, MQA, and PagedAttention.
  • The positional encoding here is replaced by RoPE and ALiBi in Module 04.
