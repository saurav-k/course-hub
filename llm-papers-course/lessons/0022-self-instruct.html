Self-Instruct

2022 Wang, Kordi, Mishra, Liu, Smith, Khashabi, Hajishirzi (University of Washington, Allen Institute for AI, and collaborators). · arXiv:2212.10560

The one-minute version

  • Instruction tuning needs thousands of "instruction, answer" pairs, and writing them by hand is slow and expensive.
  • Self-Instruct bootstraps that data from the model itself: start with a tiny seed set of human tasks, then ask the model to invent more.
  • The loop is generate new instructions, generate instances (inputs and outputs), filter for quality and diversity, add the survivors back to the pool, and repeat.
  • The diversity filter uses ROUGE-L overlap: a new instruction is kept only if it is less than 0.7 similar to everything already in the pool.
  • Applied to vanilla GPT-3, it gave a 33% absolute jump on Super-NaturalInstructions, landing within a few points of the human-supervised InstructGPT-001.

1. Why this paper exists

A base language model predicts the next token. It is not, by default, helpful: ask it to "summarise this email" and it might continue the email instead of summarising it. Instruction tuning fixes this by fine-tuning on many examples of the form "here is an instruction, here is the correct response." The catch is where those examples come from. The strong instruction-tuned models of 2022 relied on large hand-written datasets: humans writing prompts and humans writing gold answers. That is costly, slow, and skewed toward whatever tasks the annotators happened to think of.

Self-Instruct asks a cheeky question: the model already knows a lot about language and tasks - can it write most of its own training data? The answer is largely yes.

2. The bootstrap loop, diagram first

The whole method is one loop that grows a task pool. It begins with 175 human-written seed tasks (25 classification tasks and 150 non-classification tasks). Each round, the model proposes new instructions, writes example instances for them, throws away the bad and the duplicated, and folds the good ones back into the pool - which makes the next round richer.

3. Step by step, in plain English

Step 1 - generate instructions. Sample a handful of instructions already in the pool (the paper uses 8, mixing 6 human seeds with 2 model-generated ones) and drop them into a prompt that asks for a new, different instruction. Because the examples are diverse, the model tends to riff into new territory rather than copy.

Step 2 - classify the task. The model is asked whether the new instruction is a classification task (a fixed set of labels) or not. This matters because the next step generates instances differently for the two.

Step 3 - generate instances. Now turn an instruction into concrete "input, output" pairs.

  • Input-first (for most tasks): ask the model to produce an input, then the correct output for it.
  • Output-first (for classification): ask for the label first, then an input that fits it. This stops the model from lazily generating only one class (for example, always "positive" in sentiment).

Step 4 - filter. Keep only tasks that add something. A new instruction is added to the pool only if its ROUGE-L overlap with every existing instruction is below 0.7. Instances are also filtered: drop ones that are identical, that have the same input but different outputs, that are too long or too short, or that contain tell-tale junk (for example, "image" or "graph" for a text-only model).

What is ROUGE-L ROUGE-L measures overlap between two texts by the length of their longest common subsequence - roughly, how many words appear in the same order in both. A score near 1 means "almost the same sentence." Self-Instruct rejects a new instruction when its ROUGE-L against any pool member is 0.7 or higher, so the pool keeps spreading out instead of clustering.

4. The math you actually need: the diversity gate

There is no exotic loss here - the training objective is ordinary instruction fine-tuning (next-token cross-entropy on the response). The one formula worth pinning down is the acceptance rule for a new instruction.

accept(tnew) = 1  if  maxt ∈ pool ROUGE‑L(tnew, t) < 0.7  else  0 tnew: the candidate instruction just generated. pool: every instruction already accepted. ROUGE-L(a, b): similarity of two instructions by longest common subsequence, from 0 (nothing shared) to 1 (identical). max over the pool: find the single most similar existing instruction. < 0.7: keep the candidate only if even its closest match is fairly different. This one rule is what prevents the self-generated pool from collapsing into a thousand rewordings of the same few tasks.

And the fine-tuning objective, for completeness, is the same maximum-likelihood loss you have seen throughout the course, applied to the generated pairs:

L(θ) = − ∑(x, y) ∑t log Pθ( yt | x, y<t ) (x, y): a generated instruction-plus-input x and its target response y. yt: the t-th token of the response. y<t: the tokens before it. Pθ: the model. We simply maximise the probability the model assigns to the correct response tokens - standard supervised fine-tuning, just on data the model authored.

5. Implement it: the generate - filter - add loop

Below is the core Self-Instruct loop in Python. The calls to a real model are stubbed by llm() so the control flow is crystal clear: sample seed examples, ask for a new instruction, gate it by ROUGE-L, generate an instance, then grow the pool. Swap llm() for an actual API call and this is the real algorithm.

self_instruct.py · the bootstrap loop with ROUGE-L dedup
import random
from difflib import SequenceMatcher

def rouge_l(a: str, b: str) -> float:
    """Cheap ROUGE-L stand-in: longest-common-subsequence ratio over words.
    Real Self-Instruct uses the rouge library; this keeps the demo dependency-free."""
    aw, bw = a.lower().split(), b.lower().split()
    lcs = SequenceMatcher(None, aw, bw).find_longest_match(0, len(aw), 0, len(bw)).size
    if not aw or not bw:
        return 0.0
    prec, rec = lcs / len(aw), lcs / len(bw)          # precision & recall of the LCS
    return 0.0 if prec + rec == 0 else 2 * prec * rec / (prec + rec)   # F-measure

def is_novel(candidate: str, pool: list[str], thresh: float = 0.7) -> bool:
    """Diversity gate: keep only if the closest existing task is < 0.7 similar."""
    return max((rouge_l(candidate, t) for t in pool), default=0.0) < thresh

def is_valid(instr: str) -> bool:
    """Quality gate: drop empty, too-long, or clearly non-text tasks."""
    if not (3 <= len(instr.split()) <= 150):
        return False
    banned = ("image", "picture", "graph", "file", "plot")
    return not any(w in instr.lower() for w in banned)

# --- the bootstrap loop ---------------------------------------------------
seed_tasks = [
    "Give three tips for staying healthy.",
    "Sort these numbers in ascending order.",
    "Translate the sentence into French.",
    # ... 175 of these in the real paper (25 classification, 150 not) ...
]
pool = list(seed_tasks)                 # the growing task pool
generated = []                          # accepted (instruction, input, output) triples

for step in range(2000):                # each step tries to add one new task
    # 1. GENERATE: prompt the model with 8 in-context examples, ask for a new instruction
    examples = random.sample(pool, k=min(8, len(pool)))
    new_instr = llm(build_instruction_prompt(examples))       # model invents a task

    # 2. FILTER (diversity + validity) before anything expensive happens
    if not (is_valid(new_instr) and is_novel(new_instr, pool)):
        continue                        # too similar or malformed -> skip

    # 3. INSTANCE: classification uses output-first, everything else input-first
    if llm(is_classification_prompt(new_instr)).strip().lower().startswith("yes"):
        inp, out = llm(output_first_prompt(new_instr))        # label first, then input
    else:
        inp, out = llm(input_first_prompt(new_instr))         # input first, then answer

    if not instance_is_clean(new_instr, inp, out):            # drop dup / bad instances
        continue

    # 4. ADD: fold the survivor back into the pool so it can seed future prompts
    pool.append(new_instr)
    generated.append((new_instr, inp, out))

print(f"grew pool to {len(pool)} tasks, {len(generated)} training triples")
# finally: finetune the SAME base model on `generated` with next-token cross-entropy

Read the loop against the diagram in section 2. The two continue statements are the two filter gates; the pool.append line is the self-feeding step that makes each round richer than the last. Notice that the diversity check runs before instance generation, so you never waste model calls on a task you are going to throw away.

Design detail Output-first generation for classification tasks is not a footnote - it is what stops label collapse. If you always generate the input first and then ask for a label, the model quietly prefers easy, majority-class inputs. Fixing the label first and then writing an input forces balanced coverage of every class.

Applied to the vanilla GPT-3 base model, Self-Instruct produced about 52,000 instructions and 82,000 instances, and the fine-tuned result improved by roughly 33 absolute points on Super-NaturalInstructions - close to InstructGPT-001, which used private human data. The lesson landed hard: a large fraction of instruction-tuning quality can come from the model bootstrapping itself. This idea seeded a wave of synthetic-data work (Alpaca, and many after it).
