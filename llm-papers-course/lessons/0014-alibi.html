ALiBi: Attention with Linear Biases

2021 Ofir Press, Noah A. Smith, Mike Lewis (University of Washington / Allen Institute for AI / Meta AI). · arXiv:2108.12409 · "Train Short, Test Long"

The one-minute version

  • ALiBi uses no position embeddings at all - no vectors added to the input, no rotations on Q and K.
  • Instead it adds a fixed, non-learned penalty to each attention score that grows with how far apart two tokens are: the further back a token is, the more its score is docked.
  • The penalty is −m · (i − j), a straight line in distance, where each head gets its own slope m from a geometric sequence (1/2, 1/4, 1/8, ...).
  • Because the rule is just "distant tokens are penalized" and never memorises specific positions, a model trained on length 1024 extrapolates cleanly to 2048 and beyond - the paper's headline result, with 11% less time and memory than sinusoidal.

1. Why this paper exists

Every position method so far has a hidden weakness: they all learn or bake in something tied to specific positions. Sinusoidal encoding has a fixed wave shape; learned embeddings have a row per slot; even RoPE was tuned to a training length. So when you feed a model a sequence longer than anything it saw in training, the position signal wanders off the map and quality collapses. The authors asked a blunt question: can we train cheaply on short sequences and still run correctly on long ones?

2. The one idea: bias the scores by distance

Recall the attention score for query i against key j is a dot product qi · kj. ALiBi leaves that untouched and simply adds a bias before the softmax. The bias is negative and proportional to the distance between the two tokens.

scoreij = qi · kj + m · ( −(i − j) ) qi · kj: the ordinary content-based attention score. (i − j): how many tokens back the key is from the query (0 for itself, 1 for the previous token, and so on). −(i − j): turn that distance into a penalty - further back means a bigger negative number. m: a fixed positive slope for this head that sets how harshly distance is punished. No learning, no embeddings: the bias is computed from indices alone.

The nearest token gets a bias of 0 (no penalty). The token one step back gets −m. Ten steps back gets −10m. After softmax, that steadily growing penalty makes attention fade smoothly with distance - a built-in preference for recent context, which the paper calls an inductive bias toward recency.

3. The bias matrix and the causal mask

Stacked over all query-key pairs, the bias is a fixed matrix that is added onto the whole score grid. In a causal (left-to-right) model each query only sees the past, so we combine the linear bias with the usual upper-triangular mask that hides the future.

4. Per-head slopes: a geometric ladder

A single slope would make every head decay at the same rate. Instead each head gets a different slope so the model can look at several distance scales at once: sharp-decay heads focus tightly on the last few tokens, gentle-decay heads still reach far back. The slopes form a geometric sequence. For a model with n heads (a power of two), the slopes start at 2−8/n and multiply by that same ratio.

slopes = ( 2−8/n )1, ( 2−8/n )2, ..., ( 2−8/n )n n: the number of attention heads. 2−8/n: the first slope and also the common ratio of the sequence. For n = 8 this gives 2−1, 2−2, ..., 2−8 = 1/2, 1/4, 1/8, down to 1/256. Big slopes (steep penalty) make short-range heads; tiny slopes (mild penalty) make long-range heads. The geometric spacing spreads heads evenly across scales.

5. Implement it: the bias matrix and slopes

ALiBi is remarkably little code. Here we compute the per-head slopes, build the distance-penalty matrix, add it to raw scores, and mask the future.

alibi.py · runnable with torch
import torch, math

def alibi_slopes(n_heads):
    # geometric sequence starting at 2^(-8/n) with that same ratio
    start = 2 ** (-8.0 / n_heads)
    return torch.tensor([start ** (h + 1) for h in range(n_heads)])

def alibi_bias(n_heads, seq_len):
    # distance matrix: entry (i, j) = -(i - j) for j <= i, else masked later
    idx = torch.arange(seq_len)
    dist = idx[None, :] - idx[:, None]          # (i, j) -> j - i  = -(i - j)
    dist = dist.clamp(max=0).float()            # keys ahead handled by mask
    slopes = alibi_slopes(n_heads)              # (n_heads,)
    return slopes[:, None, None] * dist         # (n_heads, seq, seq)

def attention_with_alibi(q, k, v, n_heads):
    # q, k, v: (n_heads, seq, d_head)
    seq, d = q.shape[1], q.shape[2]
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(d)   # raw QK^T
    scores = scores + alibi_bias(n_heads, seq)          # add linear bias
    future = torch.triu(torch.ones(seq, seq), diagonal=1).bool()
    scores = scores.masked_fill(future, float('-inf'))  # causal mask
    return scores.softmax(dim=-1) @ v

print(alibi_slopes(8))                          # 1/2, 1/4, ... 1/256
h, s, d = 8, 6, 16
out = attention_with_alibi(torch.randn(h,s,d), torch.randn(h,s,d),
                           torch.randn(h,s,d), h)
print(out.shape)                                # torch.Size([8, 6, 16])

Notice what is not here: no embedding table, no sinusoids, no rotation. The only position input is the integer distance i − j. That is exactly why extrapolation works - to run on a longer sequence you just build a bigger distance matrix; the slopes and the rule never change.

Why it extrapolates A learned or sinusoidal encoding must represent position 4000 with something it may never have seen at training length 1024. ALiBi represents position only through relative distance fed into a fixed linear penalty. Distance 3000 is handled by the same slope as distance 30, just a bigger number, so nothing is out of distribution. Train short, test long.

Retrieval practice

Answer from memory before revealing.

What does ALiBi add to the model to encode position?
ALiBi adds a non-learned bias, minus m times the distance, directly to the QK score before softmax. No embeddings.
Why can an ALiBi model test on far longer sequences than it trained on?
ALiBi only ever uses relative distance in a fixed penalty, so distance 3000 is just a bigger input to the same rule.
Why does each attention head get a different slope m?
Steep slopes make short-range heads, shallow slopes make long-range heads; the geometric ladder spreads them out.
What bias does the query receive for the key right next to itself?
Bias is minus m times distance; distance 0 gives bias 0, so the nearest token keeps its raw score.

How this connects

  • Contrast with the previous lesson, RoPE: RoPE keeps a position encoding but makes it relative by rotation, while ALiBi throws position embeddings out entirely and biases the scores.
  • Replaces the sinusoidal positional encoding from the original Transformer - same goal, a much simpler and more extrapolation-friendly mechanism.
  • Shares infrastructure with Multi-Query Attention and Grouped-Query Attention: all three are surgical edits to the attention block rather than the rest of the network.
  • Feeds into long-context work; both ALiBi and RoPE-with-scaling are how models reach the huge context windows you use today.
Your teacher. The intuition to lock in is "penalize distance with a straight line, and never learn anything position-specific". Ask the agent to print the full ALiBi bias matrix for a length-6 sequence and one head, then show how extending it to length 12 changes nothing except adding more rows and columns of the same rule. That is extrapolation made visible.
