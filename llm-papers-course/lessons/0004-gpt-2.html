GPT-2: Scaling + Zero-Shot

2019 Radford, Wu, Child, Luan, Amodei, Sutskever (OpenAI). · "Language Models are Unsupervised Multitask Learners"

The one-minute version

  • GPT-2 is GPT-1's recipe made much bigger: same decoder-only design, scaled to 1.5B parameters (with 124M, 355M, and 774M siblings) and trained on far more, cleaner web text.
  • Its headline claim: a big enough language model can do tasks zero-shot - no task-specific fine-tuning, no labeled examples, no new head. You just describe the task in the prompt.
  • The data is WebText, ~40GB scraped from outbound Reddit links with at least 3 karma, a cheap quality filter. Tokens use byte-level BPE (~50,257 vocab) so nothing is ever out-of-vocabulary.
  • Two architecture tweaks matter: pre-norm (LayerNorm moved to the input of each sub-block) plus an extra final LayerNorm, which stabilises very deep training.
  • It set state of the art on 7 of 8 language-modeling datasets zero-shot and reframed NLP: stop building task models, start prompting one general model. The road to GPT-3 and ChatGPT starts here.

1. Why this paper exists

GPT-1 still had a supervised second stage: pretrain, then fine-tune on labeled data per task. BERT did too. GPT-2 asks a sharper question: if we make the generator big enough and feed it enough varied text, does the fine-tuning stage become unnecessary? The intuition is that natural text already contains countless tasks in disguise. Somewhere on the web, a translation sits next to its source; a question sits next to its answer; an article sits next to its summary. A model that predicts the next token well enough must implicitly learn all of these.

If that is true, then a single model can be a multitask learner without ever being told what the tasks are - hence the paper's title, "Unsupervised Multitask Learners." You elicit a task not with a new output head but with words: a prompt that frames what you want.

2. What "zero-shot" actually means

Zero-shot means the model sees zero labeled examples of the task and gets no gradient updates for it. You simply arrange the input so that the natural continuation is the answer. The classic trick for summarization is to append TL;DR: after an article - a pattern the model has seen thousands of times on the web, always followed by a summary - and then let it generate.

This works only if the model is large and well-trained enough. A key finding of the paper: zero-shot performance rises smoothly as the model gets bigger. The smallest model does the tasks poorly; the 1.5B model does them well. Scale is not a detail here - it is the mechanism.

Why you will also see 117M, 345M, 762M, 1542M The paper itself printed those four numbers, and they are still quoted widely. They are wrong. OpenAI corrected them in the release repository README, which says plainly: "our original parameter counts were wrong due to an error (in our previous blog posts and paper). Thus you may have seen small referred to as 117M and medium referred to as 345M." The released checkpoints are named for the corrected counts, and counting the weights of the published architecture yourself confirms them: with a 50,257-token vocabulary, a 1024-token context, a four-times-wide feed-forward block, two LayerNorms per block and biases included, the smallest model comes to 124,439,808 parameters and the next one to 354,823,168. This lesson uses the corrected figures throughout. It is a useful habit to take with you: a paper is a primary source, not an infallible one, and the arithmetic is yours to check.

3. The data: WebText and byte-level BPE

Raw web crawls are full of garbage. GPT-2's authors wanted scale and quality, so they built WebText: they scraped all outbound links from Reddit that had received at least 3 karma, treating that human upvote as a cheap signal that a page is worth reading. After de-duplication and cleaning, that is about 8 million documents, ~40GB of text. Wikipedia was deliberately removed to avoid overlap with common evaluation sets.

For tokenization, GPT-2 uses byte-level Byte-Pair Encoding. Because it operates on raw bytes, any string can be encoded - emoji, code, foreign scripts - so there is never a truly unknown token. The vocabulary is 50,257 tokens.

4. Architecture tweaks: pre-norm and a final LayerNorm

GPT-2 is architecturally GPT-1, with a few changes that make very deep stacks train stably. The big one is moving to pre-normalization. In the original Transformer, LayerNorm sat after each sub-block (post-norm). GPT-2 moves LayerNorm to the input of each sub-block, and adds one extra LayerNorm after the final block. It also scales the residual-path weights at initialization by 1/√N (with N the number of layers) to keep signal magnitudes controlled.

5. The math: still just next-token prediction

Despite all the framing about multitask learning, the training objective has not changed at all from GPT-1. It is next-token prediction. The trick is to notice that conditioning on a task description turns one objective into many.

P( output | input, task ) = ∏i P( si | s1, ..., si−1 ) s1 ... sN: the tokens of one long sequence that already contains the task framing, the input, and the answer, all concatenated. P( si | ... ): the model's probability for each next token given the tokens before it. ∏: multiply those per-token probabilities to score the whole continuation. The point: because the prompt already encodes the task, ordinary next-token modeling is "do the task." No new loss is needed.
The whole trick GPT-2 does not add a "task" input to the math. The task is smuggled in as text inside the sequence. That is why the same frozen next-token model can summarise, answer questions, and translate - the different behaviours are all just different continuations of different prompts.

6. Implement it: generation and a zero-shot frame

The GPT-2 architecture is the causal decoder from Lesson 03. What is new is how you use it: an autoregressive generation loop, and framing a task purely as a prompt. Below is a self-contained sampling loop (greedy and temperature/top-k sampling) plus a zero-shot summarization frame using the TL;DR: trick.

gpt2_generate.py · runnable with torch (model = any causal LM from Lesson 03)
import torch, torch.nn.functional as F

@torch.no_grad()
def generate(model, ids, max_new=40, temperature=1.0, top_k=None, greedy=False):
    """Autoregressive generation: feed tokens back in, one at a time."""
    for _ in range(max_new):
        logits = model(ids)[:, -1, :]                  # logits for the next token only
        if greedy:
            nxt = logits.argmax(dim=-1, keepdim=True)  # pick the single likeliest token
        else:
            logits = logits / temperature              # <1 sharper, >1 more random
            if top_k is not None:                      # keep only the k best options
                v, _ = torch.topk(logits, top_k)
                logits[logits < v[:, [-1]]] = float('-inf')
            probs = F.softmax(logits, dim=-1)
            nxt = torch.multinomial(probs, num_samples=1)   # sample from the distribution
        ids = torch.cat([ids, nxt], dim=1)             # append and continue
        # (in practice: stop on an end-of-text token)
    return ids

# ---- zero-shot summarization: the task lives entirely in the prompt --------
def zero_shot_summarize(model, tokenizer, article):
    prompt = article + "\nTL;DR:"                       # the web pattern that cues a summary
    ids = tokenizer.encode(prompt, return_tensors="pt")
    out = generate(model, ids, max_new=50, top_k=40, temperature=0.7)
    return tokenizer.decode(out[0])                     # model's continuation = the summary

# ---- zero-shot QA: same model, different frame, no training ----------------
def zero_shot_qa(model, tokenizer, question):
    prompt = f"Q: {question}\nA:"
    ids = tokenizer.encode(prompt, return_tensors="pt")
    return tokenizer.decode(generate(model, ids, max_new=20, greedy=True)[0])

# Note: with the real weights, load via Hugging Face:
#   from transformers import GPT2LMHeadModel, GPT2Tokenizer
#   model = GPT2LMHeadModel.from_pretrained("gpt2")          # 124M, the smallest size
#   tok   = GPT2Tokenizer.from_pretrained("gpt2")

Two ideas are doing all the work. First, generation is a loop: predict one token, append it, feed the longer sequence back in. Second, the prompt is the task specification: switching from TL;DR: to Q: ... A: changes the behaviour without touching a single weight. That is zero-shot prompting in nine lines.

7. GPT-1 to GPT-2: what changed

PropertyGPT-1 (2018)GPT-2 (2019)
Largest size~117M parameters1.5B parameters
Training dataBooksCorpus (~7k books)WebText (~40GB, 8M docs)
TokenizerBPE, ~40k mergesByte-level BPE, 50,257
Context length512 tokens1024 tokens
NormalizationPost-normPre-norm plus final LN
Task adaptationSupervised fine-tuningZero-shot prompting

The architecture barely moved. What moved was scale and ambition: more data, more parameters, a cleaner tokenizer, and the confidence to drop fine-tuning entirely. GPT-2's smooth size-versus-skill curves are the empirical hook that the next module's Scaling Laws paper turns into precise predictions, and that GPT-3 then pushes to 175B parameters and few-shot prompting.

Retrieval practice

Answer from memory before revealing.

What does "zero-shot" mean in the GPT-2 paper?
Zero-shot means the task is specified only through the prompt; the frozen model gets no examples and no gradient steps.
How was the WebText training corpus filtered for quality?
A karma threshold of 3 uses human upvotes as a cheap quality signal. Wikipedia was actually removed to avoid evaluation overlap.
Why did GPT-2 move LayerNorm to the input of each sub-block?
Pre-norm leaves the residual path clean and keeps signal magnitudes controlled, which stabilises deep training. It is now standard.
What actually changed most between GPT-1 and GPT-2?
The architecture is nearly identical; GPT-2 scales parameters and data, cleans the tokenizer, and drops fine-tuning.

How this connects

  • Built on GPT-1 - same decoder-only recipe, scaled up and stripped of the fine-tuning stage.
  • Contrast with BERT, whose bidirectional encoder is built for understanding, not the open-ended generation GPT-2 relies on.
  • Next up, Scaling Laws turns GPT-2's "bigger is smoothly better" curves into precise, predictive relationships.
  • Zero-shot prompting here becomes few-shot in-context learning in GPT-3.
  • The 1024-token context and its O(N²) cost are what FlashAttention and KV-cache optimization later attack.
Your teacher. The mind-bending claim here is that "predict the next token" and "do the task" become the same thing once the prompt carries the task.
