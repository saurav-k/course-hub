BLIP-2 and LLaVA

working 2023 15 min Li, Li, Savarese, Hoi (Salesforce Research) and Liu, Li, Wu, Lee (Wisconsin-Madison, Microsoft Research, Columbia) · arXiv:2301.12597

The one-minute version

  • BLIP's durable idea is about data, not architecture: web captions are noisy, so generate better captions and filter the bad ones before training. Recaptioning is now standard practice.
  • BLIP-2's idea is about cost: freeze the image encoder and freeze the language model, and train only a small bridge between them. That put multimodal work on one node instead of in a datacentre.
  • Its bridge, the Q-Former, then lost to a two-layer projection. LLaVA-1.5 reports the plain connector as "surprisingly powerful and data-efficient", trained "in ~1 day on a single 8-A100 node".
  • The reason is the lesson: a Q-Former compresses the image into a fixed set of query tokens, a projection keeps every patch token and lets attention choose. Compress at the bridge, or spend the tokens - and that trade is live again at high resolution.

1. BLIP: do not train on the captions the web gave you

BLIP attacked two problems. The first was that models of the day were good at understanding or at generation, and it trained one model that "transfers flexibly to both vision-language understanding and generation tasks". The second problem is the durable one: image-text pairs scraped from the web are noisy. The alt text under a photograph is often a filename, a slogan, or a description of something else on the page.

Its answer is CapFilt. In the paper's own words, "a captioner generates synthetic captions and a filter removes the noisy ones". Train a captioner and a filter on clean data, run them over the web corpus, and retrain on the cleaned and augmented set.

2. BLIP-2: freeze the expensive parts

A year later the question was cost. Training a vision-language model end to end means paying for a full image encoder and a full language model at once, and few teams can. BLIP-2's answer is to freeze both and train only what sits between them: the Q-Former, described in the paper as "a lightweight Querying Transformer".

The Q-Former holds a set of learned query vectors. Those queries cross-attend to the frozen image features and emit a fixed number of output tokens that the language model reads as if they were words. The result the paper reports is the one that made the recipe famous: it "outperforms Flamingo80B by 8.7% on zero-shot VQAv2 with 54x fewer trainable parameters".

The recipe that stuck Freeze the expensive parts, train the bridge. That sentence, not the Q-Former, is what every open vision-language model still does. It is the same instinct as LoRA in Module 07: leave the general capability alone and buy the connection cheaply.

3. Then the bridge got simpler

Three months after BLIP-2, LLaVA connected a CLIP image encoder to a language model with a plain projection and trained it on instruction data. LLaVA-1.5 then stated the result directly: "the fully-connected vision-language cross-modal connector in LLaVA is surprisingly powerful and data-efficient", using "CLIP-ViT-L-336px with an MLP projection", reaching the state of the art across 11 benchmarks on "merely 1.2M publicly available data" and finishing "full training in ~1 day on a single 8-A100 node".

That is the reason worth carrying, and it generalises past this pair. Compression at the bridge is a bottleneck the model has to learn to use well. Keeping every patch token spends context but asks the attention mechanism - which is designed for exactly this - to work out what matters for the current question. When you can afford the tokens, do not compress.

4. But you cannot always afford the tokens

Recall the arithmetic from Lesson 38. At 336 pixels with 16-pixel patches an image is 576 tokens. A tiled document page is several thousand. A video is that, times every sampled frame.

bridges.py · runnable with torch
import torch
import torch.nn as nn

PATCHES, VIS_DIM, LM_DIM = 576, 1024, 4096      # 336px at 16px patches

class MLPBridge(nn.Module):
    """LLaVA-1.5 style: one token per patch, nothing thrown away."""
    def __init__(self):
        super().__init__()
        self.proj = nn.Sequential(nn.Linear(VIS_DIM, LM_DIM), nn.GELU(),
                                  nn.Linear(LM_DIM, LM_DIM))
    def forward(self, patches):                  # (B, 576, VIS_DIM)
        return self.proj(patches)                # (B, 576, LM_DIM)

class QueryBridge(nn.Module):
    """BLIP-2 style: a fixed set of learned queries cross-attends to the
    patches, so the output length is chosen by you, not by the image."""
    def __init__(self, n_queries=32):
        super().__init__()
        self.queries = nn.Parameter(torch.randn(1, n_queries, VIS_DIM))
        self.attn = nn.MultiheadAttention(VIS_DIM, 8, batch_first=True)
        self.proj = nn.Linear(VIS_DIM, LM_DIM)
    def forward(self, patches):
        q = self.queries.expand(len(patches), -1, -1)
        out, _ = self.attn(q, patches, patches)  # queries read the image
        return self.proj(out)                    # (B, n_queries, LM_DIM)

patches = torch.randn(2, PATCHES, VIS_DIM)
print("mlp bridge  ", MLPBridge()(patches).shape)      # 576 image tokens
print("query bridge", QueryBridge()(patches).shape)    # 32 image tokens

# the trade, stated as a number: what each choice costs in context
for n in (576, 64, 32):
    print(f"{n:4d} image tokens -> {n * 8:5d} tokens for an 8-frame clip")

The query count in that code is a knob, not a result: the number of learned queries is yours to choose, and choosing it is exactly the design decision this lesson is about. Run the last loop and the video case explains itself.

5. What neither of them solved

Neither paper solved hallucination, and neither solved reading fine text in an image reliably. Both remain live problems in 2026.

The third unsolved problem is measurement, and it is the one most likely to mislead you. A benchmark question about an image can often be answered correctly without looking at the image, from the question's wording and world knowledge alone. A score that rises may be measuring the language model rather than the vision path. The hub's multimodality lesson raises the same warning from the chronology side. Before trusting any multimodal benchmark, check what a text-only model scores on it.

6. Does this still matter in 2026?

BLIP as a model: historical. You would not deploy it. Its captioning checkpoint is occasionally still used as a cheap automatic captioner, and a small vision-language model does that job better now.

The Q-Former as an architecture: superseded. Say that plainly. MLP projectors won for ordinary images, and for high resolution the field moved to tiling and resampler-style approaches rather than back to a purpose-built querying transformer.

BLIP's ideas: alive and load-bearing. Synthetic recaptioning with filtering is standard data practice across both vision-language training and image generation. Freezing expensive components and training a small bridge is still the default training recipe.

And the trade itself never closed. High-resolution documents and video make the token count hurt again, which puts compression back on the table for exactly the reason it was abandoned - not because the Q-Former was a bad idea, but because at 576 tokens per image nobody needed it.

Check yourself

Retrieval practice

Answer from memory before revealing.

What is CapFilt?
CapFilt is a data pipeline: generate synthetic captions, then filter both those and the originals. It is not a safety filter, a cache, or a cropping heuristic.
What does BLIP-2 actually train?
Both large components are frozen and only the Q-Former trains, which is where the 54x fewer trainable parameters comes from. Joint training is exactly the cost the paper avoids.
Why did a two-layer projection beat the Q-Former?
Compressing to a fixed set of queries is a bottleneck the bridge must learn to pack. The projection forwards everything and lets the language model's attention choose per question. It has fewer parameters, not more.
When does compressing at the bridge become attractive again?
The projection is affordable at 576 tokens per image and painful at several thousand per page or per clip. That is why the trade reopened rather than being settled.

How this connects

  • The frozen image encoder is CLIP, and its patch count comes from ViT.
  • Freezing the expensive part and training a small addition is the argument of LoRA and QLoRA, applied across modalities instead of within one.
  • Training on model-written data is the same move as Self-Instruct, one modality over.
  • Image tokens are ordinary context, so KV cache economics and PagedAttention apply to them unchanged.
Your teacher. Ask the agent to count the total context used by an eight-frame clip under both bridges, then to work out at what query count the Q-Former stops being worth its extra complexity for a single photograph. Then ask it to find a multimodal benchmark and check what a text-only model scores on it - that number is the evaluation trap made concrete.
