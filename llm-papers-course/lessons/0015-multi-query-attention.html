Multi-Query Attention

2019 Noam Shazeer (Google). · arXiv:1911.02150 · "Fast Transformer Decoding: One Write-Head is All You Need"

The one-minute version

  • When a model generates text, it caches the keys and values of past tokens (the KV cache) so it does not recompute them each step.
  • That cache is huge and reading it from memory is the real bottleneck of generation, not the math.
  • Multi-Query Attention (MQA) keeps many query heads but shares a single key head and single value head across all of them.
  • The KV cache shrinks by the number of heads (e.g. 32× smaller), decoding speeds up a lot, and quality drops only slightly.

1. Why this paper exists

Recall from Lesson 01 that each token has a Query, Key, and Value, and multi-head attention runs several of these in parallel. During generation the model produces one token at a time and must attend to all previous tokens. To avoid recomputing every past token's K and V at every step, they are stored in the KV cache. The problem: this cache is enormous, and modern GPUs finish the arithmetic long before they finish fetching the cache from memory. Generation is memory-bandwidth bound.

2. The size of the problem

The KV cache stores, for every layer, every head, and every past token, both a key vector and a value vector. Multiply it out and it is easy to reach many gigabytes.

cache_bytes = 2 · L · H · dhead · S · B · bytes 2: keys and values. L: number of layers. H: number of heads. dhead: size of each head. S: sequence length so far. B: batch size. bytes: 2 for fp16. The term that MQA attacks is H - the number of heads.

3. The MQA idea: one key, one value, many queries

Standard multi-head attention gives each head its own Q, K, and V projection. MQA keeps a separate Query for each head - queries are what make heads look at different things - but collapses all the Key projections into one and all the Value projections into one. Every query head now attends using the same shared K and V.

Why it barely hurts quality Most of a head's specialisation comes from its query - what it looks for. The keys and values are more like a shared library that all heads read from. Sharing that library costs a little expressiveness but saves an enormous amount of memory traffic.

4. See the savings in code

This module implements both, switching between them with one flag, and a calculator for the cache size. Note how MQA projects K and V to a single head width (d_head) rather than the full H · d_head.

mqa.py · runnable with torch
import torch, torch.nn as nn, torch.nn.functional as F

class Attention(nn.Module):
    def __init__(self, d_model=512, n_heads=8, multi_query=False):
        super().__init__()
        self.h, self.dk, self.mq = n_heads, d_model // n_heads, multi_query
        self.wq = nn.Linear(d_model, d_model, bias=False)          # H query heads
        kv_out = self.dk if multi_query else d_model               # 1 head vs H heads
        self.wk = nn.Linear(d_model, kv_out, bias=False)
        self.wv = nn.Linear(d_model, kv_out, bias=False)
        self.wo = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x):
        B, N, _ = x.shape
        q = self.wq(x).view(B, N, self.h, self.dk).transpose(1, 2)   # (B,H,N,dk)
        if self.mq:
            k = self.wk(x).view(B, N, 1, self.dk).transpose(1, 2)     # (B,1,N,dk)
            v = self.wv(x).view(B, N, 1, self.dk).transpose(1, 2)
            k, v = k.expand(-1, self.h, -1, -1), v.expand(-1, self.h, -1, -1)
        else:
            k = self.wk(x).view(B, N, self.h, self.dk).transpose(1, 2)
            v = self.wv(x).view(B, N, self.h, self.dk).transpose(1, 2)
        o = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.wo(o.transpose(1, 2).reshape(B, N, -1))

def kv_cache_mb(layers, heads, d_head, seq, batch=1, fp=2):
    return 2 * layers * heads * d_head * seq * batch * fp / 1e6

# 32-layer, 32-head model, 4096 tokens
mha = kv_cache_mb(32, 32, 128, 4096)
mqa = kv_cache_mb(32,  1, 128, 4096)     # heads collapses to 1
print(f"MHA cache: {mha:8.0f} MB")
print(f"MQA cache: {mqa:8.0f} MB   ({mha/mqa:.0f}x smaller)")

The calculator shows the whole point: collapsing 32 KV heads to 1 makes the cache 32× smaller, which directly translates into longer contexts, bigger batches, and faster tokens per second.

5. The trade-off

SchemeKV headsCache sizeQuality
Multi-Head (MHA)H (all)LargestBest
Multi-Query (MQA)1SmallestSlightly lower

MQA sits at one extreme: maximum memory savings, small quality cost. The next lesson, Grouped-Query Attention, finds the sweet spot between these two rows.

Answer from memory before revealing.

What exactly does Multi-Query Attention share across heads?
MQA keeps per-head queries but collapses keys and values into one shared head.
Why is autoregressive decoding memory-bandwidth bound?
The arithmetic finishes fast; fetching the large KV cache from memory is the real limit.
In the cache-size formula, which factor does MQA cut?
MQA drives the head count H to 1 for the K/V storage, shrinking the cache by roughly H.
Why does sharing K and V cost little quality?
Queries define what each head looks for; K/V act as a shared library, so sharing them is cheap.
