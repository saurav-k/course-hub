Tree of Thoughts

2023 Yao, Yu, Zhao, Shafran, Griffiths, Cao, Narasimhan (Princeton University / Google DeepMind). · arXiv:2305.10601

The one-minute version

  • Chain-of-Thought commits to a single line of reasoning left to right. If an early step is a dead end, there is no way back.
  • Tree of Thoughts (ToT) generalizes CoT into a search: at each step generate several candidate thoughts, forming a branching tree of partial solutions.
  • The model self-evaluates each candidate (rating it or voting among siblings), and a search algorithm (BFS or DFS) explores promising branches and backtracks out of bad ones.
  • On the Game of 24 puzzle, ToT solved 74% of instances versus just 4% for GPT-4 with Chain-of-Thought - a huge jump on tasks that need planning and search.

1. Why this paper exists

Chain-of-Thought writes one reasoning path, token after token, with no going back. That is fine when the first idea happens to be right. But many problems need exploration: you try an approach, hit a wall, and must abandon it for another. A single chain has no branch to abandon and no way to compare alternatives. It is like solving a maze by committing to the first turn at every junction and never retracing.

ToT reframes reasoning as a classic search problem. Every partial solution is a node; extending it is expanding the node; evaluating it is scoring the node. Once reasoning is a tree, decades of search algorithms - breadth-first, depth-first, with backtracking - become available.

2. The four ingredients

ToT is defined by four design choices you plug in per problem.

  • Thought decomposition - what counts as one "thought" (one step)? For Game of 24 it is one arithmetic combination of two numbers.
  • Thought generator - given a state, propose several next thoughts (by sampling or by prompting for k distinct options).
  • State evaluator - rate how promising each state is, using the model itself to value a state or to vote among states.
  • Search algorithm - how to walk the tree: BFS (keep the best b states per level) or DFS (go deep, backtrack on failure).

3. Self-evaluation: the model as its own critic

The engine of ToT is that the same model that generates thoughts can also judge them. Two evaluation styles are used. In value mode, you ask the model to rate a single state - for example, "given the numbers left, is 24 still reachable: sure / maybe / impossible?". In vote mode, you show the model several sibling states and ask it to pick the most promising. Either way, the model's judgment prunes the tree so search does not explode.

4. Searching the tree with backtracking

With a generator and an evaluator, a search algorithm ties it together. BFS expands level by level, keeping only the best b states at each depth (a beam). DFS dives down one promising branch until it either solves the problem or the evaluator declares the state hopeless, then backtracks to the last junction and tries the next option. Backtracking is the ability CoT never had.

The headline result: on the Game of 24 (use four numbers and +, -, *, / to make 24), GPT-4 with standard Chain-of-Thought solved only 4% of puzzles, because one wrong first operation dooms the chain. ToT with BFS solved 74%, because it could try several first operations, evaluate which keep 24 reachable, and back out of the ones that do not.

5. The math, read in plain English

ToT does a value-guided search over states. At each state it generates candidate children, scores them, and keeps the best set to expand next.

Sgen = { s + g : g ~ G(s), sampled k times },    V(s') = evaluator(s'),    Snext = top-b by V(s') s: the current state (a partial solution). G(s): the thought generator - sample k candidate next thoughts g and attach each to s to form a child state s'. V(s'): the evaluator's score for a child, from the model valuing or voting. top-b: keep the best b children (the beam width) to expand at the next level. Bigger k explores more per node; bigger b keeps more paths alive.
answer = first s reaching the goal along argmax-value path;   else backtrack to last open node Search returns the first state that satisfies the goal test, found by preferring high-value children. If a branch dead-ends (every child scores hopeless), the search backtracks to the most recent node with unexplored children and continues - the recovery move a single chain cannot make.

6. Implement it: BFS Tree-of-Thoughts on a toy problem

The code runs a real ToT breadth-first search on Game of 24 with a stubbed model. The generator proposes ways to combine two numbers; the evaluator rules out states from which 24 is unreachable; BFS keeps a beam of the best states per level. Swap the two stubs for LLM prompts and it becomes the paper's method.

tree_of_thoughts.py · runnable with Python
from itertools import combinations

# --- thought generator: propose next states by combining two numbers ---
def generate(nums):
    """Each 'thought' combines two numbers with one operation."""
    states = []
    for a, b in combinations(nums, 2):
        rest = list(nums); rest.remove(a); rest.remove(b)
        cands = {a + b, a * b, abs(a - b)}
        if b != 0: cands.add(a / b)
        if a != 0: cands.add(b / a)
        for c in cands:
            states.append(tuple(sorted(rest + [c])))   # new state
    return set(states)

# --- state evaluator: is 24 still reachable from these numbers? ---
def reachable(nums, target=24):
    if len(nums) == 1:
        return abs(nums[0] - target) < 1e-6
    return any(reachable(list(s), target) for s in generate(nums))

def evaluate(state):
    # 'value' score: sure (reachable) vs impossible (prune)
    return 1.0 if reachable(list(state)) else 0.0

# --- BFS Tree-of-Thoughts search with a beam ---
def tot_bfs(start, beam=5, target=24):
    frontier = [tuple(sorted(start))]           # level 0
    while frontier:
        # goal test: a single number equal to the target
        for s in frontier:
            if len(s) == 1 and abs(s[0] - target) < 1e-6:
                return True
        # expand every state, score children, keep the best 'beam'
        children = set()
        for s in frontier:
            if len(s) > 1:
                children |= generate(s)
        scored = [(evaluate(c), c) for c in children]
        scored = [(v, c) for v, c in scored if v > 0]   # prune impossible
        scored.sort(reverse=True)
        frontier = [c for _, c in scored[:beam]]        # beam of promising states
    return False

print("4 9 10 13 ->", tot_bfs([4, 9, 10, 13]))   # True: (13-9)*(10-4)=24
print("1 1 1 1  ->", tot_bfs([1, 1, 1, 1]))      # False: cannot reach 24

Trace it against the diagrams. generate is the thought generator (branching). evaluate is the state evaluator that prunes hopeless states (here using exact reachability; the paper uses the LLM's own judgment). And tot_bfs keeps a beam of the best states per level - breadth-first search with pruning. The dead-end pruning plus level-by-level beam is what gives ToT its recovery ability.

Generate, evaluate, search Every ToT variant is these three knobs: how many thoughts to generate per node, how to score them, and which search walks the tree. Chain-of-Thought is the degenerate case - generate one thought, never evaluate, never branch. ToT simply turns those knobs up.

7. Cost and when to use it

PropertyChain-of-ThoughtTree of Thoughts
Paths exploredOneMany (a tree)
Recover from a dead endNoYes - backtracking
Self-evaluationNoneValue or vote per state
Compute per problemLowHigh - many model calls
Game of 24 (GPT-4)4% solved74% solved

The cost is real: ToT makes many model calls per problem - to generate candidates and to evaluate them - so it is far more expensive than a single chain. It pays off precisely on problems that need search: planning, puzzles, tasks where the first idea is often wrong. On easy one-shot questions it is overkill. ToT is the moment the field started treating inference-time compute as a dial you can turn up for harder problems - the theme the next lesson makes explicit.

How does Tree of Thoughts generalize Chain-of-Thought?
ToT turns the single left-to-right chain into a branching tree of candidate thoughts, then searches it with evaluation and backtracking.
What role does self-evaluation play in Tree of Thoughts?
The model rates each state (value) or picks among siblings (vote); those scores let the search keep promising branches and prune dead ones.
Which ability does backtracking give ToT that a single chain lacks?
Backtracking lets ToT return to the last open junction after a dead end and try another option - the recovery move a linear chain cannot make.
Why is Tree of Thoughts more expensive than Chain-of-Thought?
ToT calls the model repeatedly to propose candidate thoughts and to score them, so it spends far more inference compute per problem than one chain.

How this connects

  • ToT directly extends Chain-of-Thought: a chain is a tree of width one with no evaluation.
  • It shares the search-and-evaluate spirit of ReAct, but searches over reasoning states rather than world actions.
  • Trading many model calls for higher accuracy is precisely the subject of Test-Time Scaling.
  • The self-evaluation step foreshadows the verifiers used in reasoning-model training like GRPO.
