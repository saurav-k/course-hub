GPT-1: Generative Pre-Training

2018 Radford, Narasimhan, Salimans, Sutskever (OpenAI). · "Improving Language Understanding by Generative Pre-Training"

The one-minute version

  • GPT-1 keeps the decoder half of the Transformer and trains it with one simple goal: predict the next token, over and over, on plain unlabeled text.
  • That is generative pre-training. It needs no labels, so it can drink from a huge corpus (BooksCorpus, ~7,000 books) and learn grammar, facts, and reasoning as a side effect.
  • Then comes a second, supervised fine-tuning stage on each specific task, using input transformations (delimiter tokens) so one architecture handles classification, entailment, similarity, and multiple choice.
  • A small auxiliary language-modeling loss during fine-tuning keeps the pretrained skills sharp and speeds convergence.
  • The 12-layer, ~117M-parameter model beat task-specific systems on 9 of 12 benchmarks - proof that one pretrained generator transfers everywhere. It is the direct ancestor of every GPT since.

1. Why this paper exists

Labeled data is scarce and expensive; raw text is nearly infinite and free. In 2018 most NLP models were still trained from scratch, per task, on small labeled datasets, each with a hand-crafted architecture. Progress was slow because every new task started from zero. The question GPT-1 answers is: can one model learn general language ability from unlabeled text, then transfer that ability to any task with only light tuning?

Its sibling paper, BERT (Lesson 02), answered a related question with a bidirectional encoder. GPT took the other road: a left-to-right generator. The bet was that if a model gets genuinely good at predicting the next word, it must along the way learn syntax, world facts, and even some reasoning - because all of those help you guess what comes next.

2. Decoder-only: what GPT keeps

GPT-1 is the decoder stack from Lesson 01, with the encoder and the cross-attention removed. What remains is a tower of blocks doing masked (causal) self-attention: each token may attend only to itself and the tokens before it, never the future. That causal mask is the whole reason the model can generate - it predicts token N+1 using only tokens 1..N, exactly the setting it will face at generation time.

The concrete recipe: 12 layers, hidden size 768, 12 attention heads, a feed-forward inner size of 3072, and a context window of 512 tokens - roughly 117M parameters. Tokenization is byte-pair encoding (BPE) with 40,000 merges.

3. Stage one: unsupervised generative pretraining

The pretraining objective could not be simpler. Slide over the corpus and, at every position, ask the model to predict the next token given a window of previous ones. Maximise the probability it assigns to the token that actually came next. No labels, no task - just the text predicting itself.

GPT-1 pretrained on BooksCorpus: over 7,000 unique, unpublished books. Long books matter here - contiguous passages let the model learn genuinely long-range structure, not just neighbouring words.

4. Stage two: supervised fine-tuning with input transformations

After pretraining, you have a strong generator but no task-specific behaviour. Stage two fixes that. Take a labeled dataset, feed each example through the same model, and read out the final token's vector into a small linear task head. The clever part is how GPT-1 makes every task look like one long sequence, so the architecture never changes: it uses input transformations with special delimiter tokens.

5. The auxiliary language-modeling loss

During fine-tuning, GPT-1 does not just optimise the task label. It also keeps predicting the next token on the fine-tuning text, as a secondary objective, weighted by a small factor. This "auxiliary LM loss" acts like a memory aid: it stops the model from forgetting its general language skills while it specialises, and the paper reports it improves generalisation and speeds up convergence.

6. The math: both objectives

Pretraining maximises the log-probability of each token given the previous k tokens. Equivalently, we minimise the negative of that sum.

L1(U) = ∑i log P( ui | ui−k, ..., ui−1 ) U: the stream of tokens u1, u2, ... in the corpus. ui: the token at position i, the one we are trying to predict. ui−k ... ui−1: the previous k tokens, the context window the model may look at. P( ui | ... ): the probability the model gives the correct next token. Sum the logs over all positions and push it up - that is "get good at predicting the next word."

Fine-tuning combines the supervised task objective with the auxiliary language-modeling objective from above.

L3(C) = L2(C) + λ · L1(C) C: the labeled fine-tuning dataset. L2: the supervised loss - predict the right label from the final token's vector. L1: the same next-token language-modeling loss as pretraining, now applied to the task text. λ: a small weight (the paper uses 0.5) that says how much to care about staying fluent while specialising. Adding them means "learn the task, but do not forget how to model language."
One idea, two uses Notice that L1 is the same next-token loss in both stages. In pretraining it is the whole game; in fine-tuning it is a gentle regulariser. GPT's entire philosophy is that this one objective, at scale, is enough - a theme that only gets louder in GPT-2 and GPT-3.

7. Implement it: a causal LM training loop

Here is stage one in runnable PyTorch. It reuses the causal self-attention you built in Lesson 01, stacks it into a tiny GPT, and trains the next-token objective. Watch how the labels are just the inputs shifted by one - that shift is "predict the next token."

gpt1_pretrain.py · runnable with torch
import torch, torch.nn as nn, torch.nn.functional as F

class CausalBlock(nn.Module):
    """Decoder block: causal self-attention (see Lesson 01) + feed-forward."""
    def __init__(self, d_model=256, n_heads=4):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
        self.ln1  = nn.LayerNorm(d_model)
        self.mlp  = nn.Sequential(nn.Linear(d_model, 4 * d_model),
                                  nn.GELU(),
                                  nn.Linear(4 * d_model, d_model))
        self.ln2  = nn.LayerNorm(d_model)

    def forward(self, x):
        N = x.size(1)
        # causal mask: position i may not attend to any j > i (the future)
        mask = torch.triu(torch.ones(N, N, device=x.device), diagonal=1).bool()
        a, _ = self.attn(x, x, x, attn_mask=mask, need_weights=False)
        x = self.ln1(x + a)
        x = self.ln2(x + self.mlp(x))
        return x

class TinyGPT(nn.Module):
    def __init__(self, vocab=5000, d_model=256, n_layers=4, max_len=128):
        super().__init__()
        self.tok = nn.Embedding(vocab, d_model)
        self.pos = nn.Embedding(max_len, d_model)
        self.blocks = nn.ModuleList(CausalBlock(d_model) for _ in range(n_layers))
        self.ln_f = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab)          # project to next-token logits

    def forward(self, ids):
        N = ids.size(1)
        pos = torch.arange(N, device=ids.device).unsqueeze(0)
        x = self.tok(ids) + self.pos(pos)
        for blk in self.blocks:
            x = blk(x)
        return self.head(self.ln_f(x))                 # (B, N, vocab)

# ---- the next-token training step ------------------------------------------
model = TinyGPT()
opt   = torch.optim.AdamW(model.parameters(), lr=3e-4)

batch = torch.randint(0, 5000, (4, 65))                # 4 sequences of length 65
inputs, labels = batch[:, :-1], batch[:, 1:]           # labels = inputs shifted by 1

logits = model(inputs)                                 # (4, 64, vocab)
loss = F.cross_entropy(logits.reshape(-1, 5000), labels.reshape(-1))
loss.backward(); opt.step(); opt.zero_grad()
print(round(loss.item(), 3))                           # ~log(vocab) at init

The single most important line is inputs, labels = batch[:, :-1], batch[:, 1:]. Predicting a sequence shifted one step to the left is next-token prediction, and the causal mask guarantees no position ever cheats by seeing its own answer. This exact loop, scaled up, is how every GPT model is pretrained.

8. GPT-1 versus BERT: two answers to one question

PropertyGPT-1 (this paper)BERT (Lesson 02)
Transformer half keptDecoderEncoder
Attention directionLeft-to-right (causal)Bidirectional
Pretraining objectiveNext-token predictionMasked LM plus NSP
Adapting to a taskInput reshape plus headAdd a small task head
Natural strengthGenerating text fluentlyUnderstanding and tagging
Layers / parameters12 layers / ~117M12 or 24 / 110M-340M

The two papers landed months apart and framed the field's central fork. BERT's bidirectional understanding won the classification leaderboards of the era. GPT's causal generation looked less flashy at first, but it is the branch that scales into GPT-2, GPT-3, and the chat assistants you use today - because prediction-as-pretraining and generation-as-interface turned out to be extraordinarily general.

Answer from memory before revealing.

What single objective does GPT-1 use for its pretraining stage?
Stage one is plain next-token prediction on unlabeled text - no labels, no masking, just modeling what comes next.
How does one GPT-1 architecture handle so many different tasks?
Input transformations turn structured inputs into flat token sequences; only a thin linear head changes per task.
What is the auxiliary language-modeling loss used for during fine-tuning?
The down-weighted next-token loss on task text acts as a regulariser, preserving fluency and improving transfer.
Why can GPT-1 generate text left to right at inference time?
Causal attention means each position was always trained to predict the next token from its past, exactly the generation setting.

How this connects

  • Built on Attention Is All You Need - GPT-1 is that paper's decoder stack, causal mask and all.
  • Contrast with BERT, the encoder sibling that learns bidirectionally for understanding rather than generation.
  • Next up, GPT-2 drops task-specific fine-tuning entirely and does tasks zero-shot, just by scaling this same recipe.
  • The "one objective at scale" bet here is quantified by the Scaling Laws paper in Module 02.
