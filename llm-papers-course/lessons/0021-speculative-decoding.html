Speculative Decoding

2022 Leviathan, Kalman, Matias (Google Research). · arXiv:2211.17192 · "Fast Inference from Transformers via Speculative Decoding" (companion: Chen et al., DeepMind, 2302.01318)

The one-minute version

  • Generation is slow because it is sequential: the big model runs one full forward pass per token, and each pass waits on the last.
  • Speculative decoding uses a small, fast draft model to guess the next K tokens autoregressively, then has the big target model check all K in a single parallel forward pass.
  • A modified rejection sampling rule accepts the guesses that agree and resamples the first one that does not. It is proved that the accepted output has exactly the target model's distribution.
  • When the small model guesses well, several tokens come out per big-model pass, giving a 2-3× speedup with identical quality. No retraining, no approximation.

1. Why this paper exists

A transformer can score a whole sequence in parallel during training, but generation is stubbornly serial. To produce token 100 you need token 99, which needs 98, and so on. Each step is one full pass through a giant model, and the GPU spends most of that pass waiting on memory rather than doing math. So the machine is underused: it could evaluate many tokens at once, but autoregression only asks it for one.

2. The idea: draft, then verify in parallel

Split the work. A small model (the draft, distribution q) is cheap, so let it generate a guess of the next K tokens one by one. Then feed those K guesses to the big model (the target, distribution p) all at once. Because the target can score many positions in parallel, checking K guesses costs about the same as generating one token normally. The trick is turning "the target scored these guesses" into "the target actually produced these tokens", with no change to what the target would have said on its own.

3. The accept/reject rule that keeps quality exact

This is the clever heart of the paper. For each drafted token x, compare how likely the target thought it was, p(x), to how likely the draft thought it was, q(x). Accept x with probability min(1, p(x)/q(x)). If the target likes the token at least as much as the draft did, accept outright. If the target likes it less, accept it only proportionally, and on rejection resample from a corrected leftover distribution.

accept x with prob = min(1, p(x) / q(x)) p(x): the target (big) model's probability of the drafted token. q(x): the draft (small) model's probability of the same token. If p ≥ q the ratio is ≥ 1 so we always accept. If p < q we accept with probability p/q, correcting for the draft over-proposing that token.

When a token is rejected, you do not just retry - that would bias the result. You sample the replacement from the residual distribution: the target's probabilities minus the draft's, clipped at zero and renormalised. This exactly fills the gap the acceptance step left behind.

on reject, sample from p′(x) = norm( max(0, p(x) − q(x)) ) max(0, p − q): keep only the probability mass the target wanted but the draft under-supplied (negative parts clipped to zero). norm(...): divide by the total so it sums to 1. Sampling from this residual, combined with the acceptance rule above, provably reproduces the target distribution p exactly.
Why this is not an approximation It would be easy to build something "close enough" to the target and call it fast. Speculative decoding refuses that trade. The acceptance probability and the residual resample are constructed so that the math cancels: the probability of emitting any token equals p(x) exactly, whatever the draft model is. A bad draft only makes it slower (more rejections), never wrong.

4. Where the speedup comes from

Every accepted draft token is a token the big model produced without its own sequential pass. If the draft agrees with the target most of the time, a single verification pass yields several tokens. The expected number of tokens per pass depends on the acceptance rate, which depends on how well the small model imitates the big one. Because the target verification is parallel, its cost is roughly one normal step, so the whole scheme turns "K sequential big passes" into "one big pass plus K cheap draft passes".

5. Implement it: speculative sampling that preserves the distribution

This toy runs the full accept/reject loop over small hand-made draft and target distributions, then checks empirically that the emitted tokens match the target distribution - the paper's central guarantee, verified by counting.

speculative.py · runnable, numpy only
import numpy as np
rng = np.random.default_rng(0)

# toy vocabulary of 5 tokens. p = target (truth), q = draft (approximation)
p = np.array([0.05, 0.35, 0.30, 0.20, 0.10])   # big model distribution
q = np.array([0.10, 0.20, 0.40, 0.20, 0.10])   # small model distribution

def residual(p, q):
    r = np.clip(p - q, 0, None)                 # keep mass target wanted, draft missed
    return r / r.sum()

def speculative_step(p, q):
    x = rng.choice(len(q), p=q)                 # draft proposes a token from q
    if rng.random() < min(1.0, p[x] / q[x]):    # accept with prob min(1, p/q)
        return x                                # accepted draft token
    return rng.choice(len(p), p=residual(p, q)) # rejected -> corrected resample

# emit many tokens and compare their distribution to the target p
N = 200_000
counts = np.zeros(len(p))
for _ in range(N):
    counts[speculative_step(p, q)] += 1
emp = counts / N

print("token :  target p  |  speculative empirical")
for i in range(len(p)):
    print(f"  {i}   :   {p[i]:.3f}   |   {emp[i]:.3f}")
print(f"max abs error vs target: {np.abs(emp - p).max():.4f}")   # ~0.00x, matches p

Run it and the empirical column tracks the target p to within sampling noise, even though every proposal came from the different distribution q. That is the proof made concrete: the draft only changes speed, never the distribution you sample from. Swap in any q you like and the emitted tokens still follow p.

6. The trade-off table

PropertyStandard decodingSpeculative decoding
Big-model passes per tokenExactly oneAbout one over n accepted
Output distributionTarget model pTarget model p (identical)
Extra model neededNoneA small draft model
Failure mode of bad draftNot applicableSlower only, never wrong

The whole appeal is in the second row: the answer is bit-for-bit the distribution the big model would have produced, just reached with fewer sequential big-model steps. A companion DeepMind paper published the same idea independently, and speculative decoding is now standard in production inference stacks.

What is the division of labour in speculative decoding?
The draft model proposes K tokens autoregressively; the target model checks all K in one parallel pass.
How is a single drafted token accepted?
Acceptance probability is min(1, p(x)/q(x)) - always if the target likes it at least as much as the draft.
On rejection, where does the replacement token come from?
You resample from norm(max(0, p - q)); with the accept rule this reproduces the target distribution exactly.
What does a poorly matched draft model cost you?
A bad draft is rejected more often, so it is slower, but the output distribution is still exactly the target's.
