GRPO

2024 Shao, Wang, Zhu, Xu, Song, Bi, Zhang, Zhang, Li, Wu, Guo (DeepSeek-AI). "DeepSeekMath" - introduces Group Relative Policy Optimization. · arXiv:2402.03300

The one-minute version

  • DPO and ORPO removed reinforcement learning entirely. But for reasoning tasks - maths, code - you often want real RL against a checkable reward (was the final answer correct?).
  • Classic PPO (Lesson 23) needs a value network - a second model the size of the policy - to estimate a baseline for each token. That doubles memory and is hard to train.
  • GRPO drops the value network. For each prompt it samples a group of answers, scores them all, and uses the group's own average as the baseline.
  • The advantage of an answer is (its reward − group mean) / group std - literally how far above or below its peers it scored, standardised.
  • Then a normal clipped PPO update plus a KL term. Cheaper than PPO, and it is the RL engine behind DeepSeek's maths and reasoning models.

1. Why this paper exists

The last two lessons made alignment cheap by deleting reinforcement learning. But some goals resist the preference-pair format. For a maths problem there is a correct answer: you can run the model's solution and check it. That gives a clean, automatic reward, and to fully exploit it you want to explore - generate solutions, see which get the reward, and reinforce those. That is reinforcement learning, and it is how reasoning models are trained.

The trouble is PPO's cost. PPO estimates, for every token, how much better the outcome was than expected - the advantage - and to get the "expected" part it trains a value network (a critic) that is typically as large as the policy itself. That is a second full model to hold in memory and train, and value networks are notoriously finicky. GRPO removes it with a simple idea: if you sample several answers to the same prompt, the group average reward is already a fine baseline. No critic needed.

2. The group idea

Here is the whole trick in a sentence: to know whether an answer is good, compare it to other answers to the same prompt. For each question, sample a group of G outputs from the current policy. Score each one with the reward (for maths, 1 if the final answer is correct, 0 otherwise, plus format checks). An answer that beats the group average gets a positive advantage; one below average gets a negative advantage. The group is its own yardstick.

3. The group-relative advantage, exactly

For outcome-supervised training, the advantage assigned to every token of answer i is the standardised reward - subtract the group mean, divide by the group standard deviation.

Âi,t = r̃i = ( ri − mean( { r1, ..., rG } ) ) / std( { r1, ..., rG } ) ri: the reward for answer i in the group (for maths, correctness of the final answer). mean({r1..rG}): the average reward across the group of G sampled answers - the baseline. std({r1..rG}): the spread of rewards, used to standardise. Âi,t: the advantage, the same value given to every token t of answer i. Positive means this answer beat its peers; negative means it lagged. No value network appears - the baseline is purely the group statistics.
Why standardise Subtracting the mean centres the signal so only relative quality matters - if every answer in a group scores 1, none is reinforced over the others. Dividing by the std keeps the update size stable whether a group is tightly clustered or spread out. It is the same z-score you would compute in statistics, applied per group.

4. The GRPO objective, exactly

With advantages in hand, the update is standard clipped PPO, averaged over the group and over tokens, minus a KL term to a reference model. The clip keeps each step small so training stays stable.

JGRPO(θ) = E [ (1/G) ∑i=1G (1/|oi|) ∑t=1|oi| { min( ri,t Âi,t, clip(ri,t, 1−ε, 1+ε) Âi,t ) − β DKL[πθ ‖ πref] } ] ri,t = πθ(oi,t|...) / πθold(oi,t|...): the probability ratio - how much more likely the updated policy makes this token than the policy that generated it. Âi,t: the group-relative advantage from above. min(·, clip(·)): PPO's clipped surrogate - allow the ratio to help only within [1−ε, 1+ε], so no single step lurches too far. (1/G) ∑i: average over the group of answers. (1/|oi|) ∑t: average over the tokens of each answer. β DKL[πθ ‖ πref]: a KL leash to the reference model, added directly to the loss (not folded into the reward as PPO does).

One more detail worth its own note: GRPO estimates that KL with an unbiased, always-positive estimator, added straight to the loss.

DKL[πθ ‖ πref] = ( πref(oi,t|...) / πθ(oi,t|...) ) − log( πref(oi,t|...) / πθ(oi,t|...) ) − 1 πref / πθ: the ratio of the reference model's probability to the trained policy's for this token. ratio − log(ratio) − 1: a standard estimator of KL divergence that is always ≥ 0 and unbiased, so it never accidentally rewards drift. Keeping this term in the loss (rather than in the reward) keeps the advantage calculation clean.

5. Implement it: group advantages plus the clipped update

The two pieces - group-relative advantage and the clipped objective - are short in PyTorch. This is a teaching sketch; a full trainer adds generation, tokenisation, and the KL term, but the core signals are exactly these.

grpo_core.py · group advantage + clipped PPO-style objective
import torch
import torch.nn.functional as F

def group_advantages(rewards):
    """
    rewards: (G,) reward for each of the G sampled answers to ONE prompt.
    Returns (G,) standardized advantage: (r - mean) / std.  No value network.
    """
    mean = rewards.mean()
    std  = rewards.std() + 1e-8          # guard against a zero-variance group
    return (rewards - mean) / std        # z-score within the group

def grpo_objective(logp_new, logp_old, advantages, eps=0.2):
    """
    logp_new  : (G, T) log-prob of each token under the CURRENT policy
    logp_old  : (G, T) log-prob of the SAME tokens under the sampling policy
    advantages: (G,)   one advantage per answer, broadcast to its tokens
    eps       : PPO clip range (illustrative; the paper leaves eps symbolic)
    Returns a scalar to MAXIMIZE (KL term omitted for clarity).
    """
    A = advantages.unsqueeze(1)          # (G, 1) -> broadcasts over tokens
    ratio = torch.exp(logp_new - logp_old)   # pi_new / pi_old, per token

    unclipped = ratio * A
    clipped   = torch.clamp(ratio, 1 - eps, 1 + eps) * A
    surrogate = torch.min(unclipped, clipped)    # PPO's pessimistic bound

    # average over tokens within each answer, then over the group
    per_answer = surrogate.mean(dim=1)   # (G,)
    return per_answer.mean()             # scalar

# --- smoke test: 4 answers to one maths prompt, rewards are correctness ---
rewards = torch.tensor([1.0, 0.0, 1.0, 0.0])   # 2 right, 2 wrong
adv = group_advantages(rewards)
print(adv)            # correct answers get +, wrong answers get - (mean 0)

G, T = 4, 6
logp_old = torch.log(torch.rand(G, T))
logp_new = logp_old + 0.05 * torch.randn(G, T)   # slightly updated policy
print(float(grpo_objective(logp_new, logp_old, adv)))

Look at the smoke test. Two answers were correct and two were wrong, so the group mean is 0.5; after standardising, the correct answers get a positive advantage and the wrong ones negative - all without ever training a critic. The clipped objective then nudges the policy to make the good answers more likely, in small, safe steps. That is GRPO.

GRPO made RL fine-tuning cheap enough to scale on reasoning. DeepSeekMath used it (with a group size of 64 and a KL coefficient of 0.04) to push open-model maths performance sharply upward, and the same algorithm later powered DeepSeek's reasoning models trained largely by RL against checkable rewards. It closes this module by showing the other way to cut RLHF's cost: not by removing RL, as DPO and ORPO did, but by removing the most expensive piece inside it.

Check yourself

Retrieval practice

Answer from memory before revealing.

What does GRPO remove compared with standard PPO?
GRPO drops the critic. It samples a group and uses the group's mean reward as the baseline, so no separate value network is trained.
How is an answer's advantage computed in GRPO?
Advantage = (r_i - mean) / std over the group. It is a z-score: how far above or below its peers the answer scored, standardised.
Why sample a whole group of answers per prompt?
The group's mean reward is the baseline. Comparing each answer to its peers is what lets GRPO skip the critic entirely.
On what kind of task does GRPO's checkable reward shine?
Reasoning tasks give an automatic, verifiable reward (is the answer correct?), which is ideal for RL and powers DeepSeek's maths and reasoning models.

How this connects

  • Previously, ORPO cut RLHF's cost by removing reinforcement learning; GRPO takes the opposite route, keeping RL but removing its value network.
  • GRPO is a variant of PPO from InstructGPT (RLHF) - same clipped objective and KL leash, minus the critic.
  • The checkable rewards it thrives on connect to Chain-of-Thought and Test-Time Scaling in Module 08, where models reason step by step.
  • Next, LoRA opens Module 07 on parameter-efficient fine-tuning - a different lever for making all this training cheaper.
Your teacher. The insight to internalise is that a baseline just needs to answer "better than what?" PPO answers with a learned value; GRPO answers with the group average. Ask the agent to run group_advantages on a group where all rewards are equal and explain why every advantage is zero, or to show how the clip prevents a single lucky answer from dominating. Do not move on until "the group is its own baseline" feels obvious.
