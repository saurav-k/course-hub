Module 07 · Parameter-Efficient Fine-Tuning · Lesson 29

QLoRA: Efficient Finetuning of Quantized LLMs

2023 Dettmers, Pagnoni, Holtzman, Zettlemoyer (University of Washington). · arXiv:2305.14314

The one-minute version

  • LoRA made the trainable part of fine-tuning tiny. QLoRA attacks the part LoRA left alone: the frozen base model, which still had to sit in memory in 16-bit.
  • QLoRA stores the frozen base weights in a new 4-bit format called NormalFloat (NF4), shaped for the bell-curve spread of neural-net weights, then trains 16-bit LoRA adapters on top.
  • Double quantization compresses the little scaling constants that quantization itself creates, and paged optimizers use unified CPU-GPU memory to survive sudden memory spikes.
  • Result: finetune a 65B model on one 48GB GPU in 24 hours, with no quality loss versus 16-bit finetuning. The Guanaco models it produced reached 99.3% of ChatGPT on one benchmark.

1. Why this paper exists

LoRA solved the gradient side of fine-tuning. You freeze the giant base model and train two skinny adapter matrices, so you update maybe 0.1% of the parameters. That slashes the optimizer state and the gradients. But there is a stubborn cost LoRA does not touch: the frozen base weights themselves. A 65-billion-parameter model in 16-bit is about 130 GB just to hold still in memory. No single consumer or workstation GPU has that. The adapters are cheap; the tenant they live with is not.

QLoRA's insight is that the base model is frozen - it is never updated, only read during the forward pass. Anything you never train, you can afford to store in a lossy, compressed form, as long as you decompress it accurately enough to compute a good forward pass. That is exactly what quantization does.

2. Quantization in one picture

Quantization means mapping a wide range of real numbers onto a small set of buckets, then storing only the bucket index. A 16-bit weight uses 16 bits per number; a 4-bit weight uses 4. That is a 4x saving, but only if the 16 available buckets are placed where the weights actually are. Placing buckets badly wastes precision on values that never occur.

3. Part one: 4-bit NormalFloat (NF4)

Here is the observation NF4 is built on. Trained neural-net weights are not spread evenly; they cluster in a bell curve (a zero-centered normal distribution). Most weights are small, near zero; extreme values are rare. So a good 4-bit format should place many buckets near zero, where the weights are dense, and few buckets out in the tails, where weights are scarce.

NF4 is an information-theoretically optimal data type for normally distributed data: its 16 levels are the quantiles of a standard normal, so each bucket is expected to hold the same number of weights. Weights are first normalized into the range the buckets cover (by dividing each block of 64 weights by that block's largest absolute value, called the quantization constant), then snapped to the nearest NF4 level. Because the format is matched to the shape of the data, a 4-bit NF4 weight loses far less information than a 4-bit integer would.

Block-wise, not model-wide Quantization is done per block of 64 weights, each with its own scaling constant. One outlier weight would otherwise stretch the scale for the whole tensor and crush precision everywhere. Blocking contains the damage: a single big value only affects its own block of 64.

4. Part two: double quantization

Blocking creates a new, smaller cost. Every block of 64 weights needs its own scaling constant, and those constants are stored in 32-bit floats. Across a 65B model that is a lot of little numbers - about 0.5 bits of overhead per weight, which partly undoes the saving. QLoRA's fix is delightfully recursive: quantize the quantization constants too.

5. Part three: paged optimizers

The third piece is not about steady-state memory but about spikes. During training, a long sequence or a big mini-batch can momentarily balloon memory for a single step - long enough to trigger an out-of-memory crash even when the average usage is fine. QLoRA uses NVIDIA unified memory to give the optimizer state paging, just like an operating system pages RAM to disk.

6. Putting it together: frozen 4-bit base, 16-bit adapters

Now the full picture. The base model is stored once in 4-bit NF4 and never changes. On top of the layers you want to adapt, you attach LoRA adapters, which stay in 16-bit because they are the only thing being trained. In the forward pass, each 4-bit weight block is dequantized back to 16-bit on the fly, used in the matrix multiply, and thrown away. Gradients flow only into the tiny adapters.

7. The math, read in plain English

Dequantizing an NF4 weight is just an index-and-scale lookup. For a single weight stored as NF4 code c in a block with scaling constant s:

Ŵ = s · NF4_level[c] c: the 4-bit code (0 to 15) actually stored for this weight. NF4_level[c]: look that code up in the fixed 16-entry table of normal-distribution quantiles, a value in roughly [-1, 1]. s: the block's scaling constant, which rescales the [-1, 1] level back to the weight's true magnitude. Ŵ: the reconstructed 16-bit weight used in the forward pass. Under double quantization, s is itself reconstructed from an 8-bit code times a super-block constant.

And the layer output is the LoRA equation from Lesson 28, with the frozen term now coming from a quantized weight:

h = Ŵ x + (α / r) · B A x Ŵ x: the frozen base path, using the dequantized 4-bit weights. B A x: the low-rank adapter path, where A is r×d and B is d×r, so only r (say 8 or 64) new dimensions are learned. α / r: a fixed scaling that keeps the adapter's contribution stable as you change the rank r. Only A and B receive gradients; Ŵ is read-only.

8. Implement it: NF4 quantize / dequantize, then a QLoRA layer

The snippet below builds a small NF4-style codebook from normal quantiles, shows the store-and-restore round trip block by block, and wires a frozen 4-bit base to a trainable 16-bit LoRA adapter. It is a teaching illustration of the mechanism, not the optimized CUDA kernel from the bitsandbytes library, but the arithmetic is the same.

qlora_illustration.py · runnable with torch
import torch, torch.nn as nn

# --- build a 16-level NF4-style codebook from the normal distribution ---
# 16 quantile points of a standard normal, normalized into [-1, 1].
def make_nf4_levels():
    from statistics import NormalDist
    nd = NormalDist()
    # 16 evenly spaced quantiles, avoiding the infinite tails at 0 and 1
    qs = [(i + 0.5) / 16 for i in range(16)]
    levels = torch.tensor([nd.inv_cdf(q) for q in qs])
    return levels / levels.abs().max()            # scale into [-1, 1]

NF4 = make_nf4_levels()                            # the fixed lookup table

def quantize_nf4(w, block=64):
    """Store weights as 4-bit codes + one scale per block."""
    w = w.reshape(-1, block)
    scale = w.abs().amax(dim=1, keepdim=True)      # per-block quantization constant
    normed = w / scale                             # bring block into [-1, 1]
    # snap each value to the nearest NF4 level -> a code in 0..15
    codes = (normed.unsqueeze(-1) - NF4).abs().argmin(dim=-1)
    return codes.to(torch.uint8), scale            # codes are the 4-bit payload

def dequantize_nf4(codes, scale, block=64):
    """Restore approximate 16-bit weights: level lookup times scale."""
    vals = NF4[codes.long()]                        # index the codebook
    return (vals * scale).reshape(-1)               # undo the per-block scaling

# round-trip check: quantize then dequantize a random weight matrix
w = torch.randn(256, 256)
codes, scale = quantize_nf4(w.flatten())
w_hat = dequantize_nf4(codes, scale).reshape(256, 256)
err = (w - w_hat).abs().mean().item()
print(f"mean abs error after 4-bit round trip: {err:.4f}")   # small

# --- a QLoRA linear layer: frozen NF4 base + trainable 16-bit LoRA ---
class QLoRALinear(nn.Module):
    def __init__(self, d_in, d_out, r=8, alpha=16):
        super().__init__()
        base = torch.randn(d_out, d_in) * 0.02
        codes, scale = quantize_nf4(base.flatten())
        # store ONLY the 4-bit codes + scales; the frozen base is never trained
        self.register_buffer("codes", codes)
        self.register_buffer("scale", scale)
        self.shape = (d_out, d_in)
        # LoRA adapters stay in 16-bit float and ARE trained
        self.A = nn.Parameter(torch.randn(r, d_in) * 0.01)
        self.B = nn.Parameter(torch.zeros(d_out, r))   # start as no-op
        self.s = alpha / r

    def forward(self, x):
        # dequantize the frozen base on the fly, use it, then let it go
        W = dequantize_nf4(self.codes, self.scale).reshape(self.shape)
        base_out = x @ W.t()                           # frozen path (no grad)
        lora_out = (x @ self.A.t()) @ self.B.t() * self.s   # trained path
        return base_out + lora_out

layer = QLoRALinear(256, 256)
# only A and B carry gradients; the base buffers do not
trainable = sum(p.numel() for p in layer.parameters() if p.requires_grad)
print(f"trainable params: {trainable}  (base weights are frozen 4-bit)")
print(layer(torch.randn(4, 256)).shape)              # torch.Size([4, 256])

Read it against the diagrams. quantize_nf4 is the store step: normalize each block, snap to the codebook, keep 4-bit codes plus a scale. dequantize_nf4 is the restore step used inside the forward pass. And QLoRALinear holds the base as read-only buffers while only A and B are nn.Parameters that receive gradients. That is QLoRA in miniature.

In production You would not hand-roll this. You load a model with bitsandbytes in 4-bit (load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True) and attach adapters with the peft library. The paper's real contribution is the NF4 kernel, double quantization, and paged optimizers baked into those libraries.

9. What it bought

The headline claim, verified in the paper: QLoRA matches full 16-bit finetuning quality while dropping the memory enough to train a 65B model on a single 48GB GPU in 24 hours. Using it, the authors finetuned the Guanaco family on a curated dataset; the best Guanaco reached 99.3% of ChatGPT's score on the Vicuna benchmark. Quantize the frozen weight, keep the trained weight sharp - that is the whole trick, and it democratized finetuning of large models overnight.

Retrieval practice

Answer from memory before revealing.

Why is the NF4 data type a good fit for storing neural-net weights?
Trained weights are normally distributed, so NF4 places its 16 levels on normal quantiles - most buckets near zero, where the weights actually are.
What exactly does double quantization compress a second time?
Each block of 64 weights needs a scale; those scales are a big pile of numbers, so a second pass quantizes them from 32-bit to 8-bit.
What problem do paged optimizers specifically solve?
Paged optimizers use unified CPU-GPU memory to evict optimizer state during a spike and page it back, turning fatal OOM crashes into brief slowdowns.
In QLoRA, which parameters actually receive gradient updates?
The 4-bit base is read-only and only dequantized for the forward pass; gradients flow solely into the 16-bit LoRA adapters.

How this connects

  • Builds directly on LoRA: QLoRA keeps LoRA's low-rank adapters and adds 4-bit storage of the frozen base underneath them.
  • The quantization mindset here echoes the efficiency work in Module 05, like KV cache compression - trade a little precision for a lot of memory.
  • QLoRA made instruction-tuning of big models cheap, which powers the alignment recipes in Module 06 such as DPO and InstructGPT.
