Muon Optimizer

2024 Keller Jordan, with Yuchen Jin, Vlado Boza, Jiacheng You, Franz Cesista, Laker Newhouse, Jeremy Bernstein. · kellerjordan.github.io/posts/muon

The one-minute version

  • Every optimiser you have met (SGD, Adam, AdamW) treats each weight as an independent number. But a hidden layer's weights are a matrix, and that shape carries information the per-number view throws away.
  • Muon (MomentUm Orthogonalized by Newton-Schulz) takes the ordinary SGD-with-momentum update for a weight matrix and orthogonalises it before applying: it replaces the matrix's singular values with 1s.
  • The orthogonalisation is done cheaply with a few Newton-Schulz iterations, a short polynomial recipe that runs in low precision and adds under 1% compute.
  • Why it helps: a raw momentum update tends to collapse into a few dominant directions. Flattening the singular values spreads the update evenly, so rare but useful directions get updated too. Use Muon for 2D hidden matrices and plain Adam for 1D things (embeddings, norms, biases). It has set training speed records and trains LLMs faster than AdamW.

1. Why this optimiser exists

Training a neural network means repeatedly nudging its weights downhill on the loss. The optimiser decides how to turn a gradient into that nudge. AdamW, the workhorse behind almost every LLM, does this element by element: it keeps a running average of each weight's gradient and each weight's squared gradient, then scales every weight's step on its own. It never looks at how the weights sit together.

But a hidden layer is a weight matrix that maps one vector space to another. Its gradient is also a matrix, and matrices have structure that individual numbers do not: directions, and how much the update stretches along each. When you look at a real momentum update as a matrix, it is nearly low-rank. A handful of directions dominate, and everything else is tiny. Element-wise optimisers cannot see this, so they keep pouring the step into the same few directions the network already favours.

2. The one idea: orthogonalise the momentum update

Muon is short. Start with the familiar SGD-with-momentum update for a weight matrix: a running average of the gradients. Then, instead of subtracting that update directly, first orthogonalise it, and subtract the orthogonalised version. That is the whole optimiser.

What does "orthogonalise a matrix" mean here? Any matrix B can be written (by the singular value decomposition) as B = U S Vᵀ, where U and V hold orthogonal directions and S is a diagonal of non-negative singular values that say how strongly B stretches each direction. Orthogonalising means throwing away S and using U Vᵀ: the same directions, but every one scaled equally to 1. It is the closest semi-orthogonal matrix to B, and also the matrix sign of the update.

Why flatten the singular values A big singular value means the update strongly favours one direction; a tiny one means another direction barely moves. Left alone, training keeps reinforcing the dominant directions and starves the rest. Setting every singular value to 1 gives each direction an equal say, so the small-but-important directions finally get their share of the update.

3. Newton-Schulz: orthogonalising without an SVD

Computing a real SVD every step for every matrix would be far too slow and does not run well on GPUs in low precision. Muon avoids it with a Newton-Schulz iteration: a short fixed recipe that, applied a few times to a normalised matrix, drives all its singular values toward 1 without ever computing U, S, or V explicitly. It is a matrix polynomial, so it is just a few matrix multiplies.

Each iteration applies the same quintic (degree-5) polynomial. Because it only touches singular values, you can reason about one number s at a time: the iteration maps s → a·s + b·s³ + c·s⁵, and the tuned coefficients make any s in a sensible range march toward 1. Five iterations are enough in practice, and it stays stable in bfloat16.

X ← a X + b (X Xᵀ) X + c (X Xᵀ)² X,   (a, b, c) = (3.4445, -4.7750, 2.0315) X: the momentum update, first divided by its norm so its singular values start below 1. X Xᵀ: a symmetric matrix whose action on singular directions is s², so one line of matrix multiplies applies the polynomial to every singular value at once. a, b, c: coefficients tuned (by Bernstein and Newhouse) so the map s → a s + b s³ + c s⁵ converges quickly to 1. Repeat about 5 times and every singular value is close to 1, i.e. X is now orthogonal.

4. When to use Muon, and when not to

Muon's whole premise is that the parameter is a matrix with meaningful row and column directions. That is true for the 2D weight matrices in hidden layers (and flattened convolution filters). It is not true for 1D parameters: bias vectors, LayerNorm gains, and embedding tables, where the notion of orthogonalising has no useful meaning. Those keep using a standard optimiser, normally Adam.

So a real training run is a hybrid. Muon steps the 2D hidden weight matrices; Adam steps the embeddings, the norms, the biases, and typically the final output head. This split is not a compromise, it is empirically better than forcing Muon everywhere.

5. A full Muon step, in order

Trace one update for a single 2D weight matrix. It is plain momentum until the very end, where the orthogonalisation slots in.

Bt = μ Bt-1 + Gt,   Ot = NewtonSchulz(Bt) ≈ U Vᵀ,   Wt = Wt-1 - η · Ot Bt: the momentum buffer, a running average of gradients with decay μ (about 0.95). Gt: this step's gradient. NewtonSchulz(Bt): the five-iteration recipe that returns the orthogonalised update, approximately U Vᵀ from the SVD Bt = U S Vᵀ. η: the learning rate. A small scale factor depending on the matrix shape is also applied so the step size is consistent across layers.

6. Implement it: Newton-Schulz and a Muon step

Here is the core, close to the reference implementation. The first function is the orthogonaliser; the second is the optimiser that wraps momentum around it. Read them against the diagrams: normalise, iterate the quintic, subtract the result.

muon.py · runnable with torch
import torch

def zeropower_via_newtonschulz5(G, steps=5, eps=1e-7):
    """Orthogonalise G: drive its singular values toward 1 (approx U V^T).
    A quintic Newton-Schulz iteration - stable even in bfloat16.
    Coefficients tuned by Bernstein and Newhouse."""
    assert G.ndim == 2
    a, b, c = 3.4445, -4.7750, 2.0315
    X = G.bfloat16()
    X = X / (X.norm() + eps)              # normalise so singular values start <= 1
    transpose = G.size(0) > G.size(1)     # iterate on the smaller dimension
    if transpose:
        X = X.T
    for _ in range(steps):
        A = X @ X.T                        # acts as s -> s^2 on singular values
        B = b * A + c * (A @ A)            # build the quintic from A and A^2
        X = a * X + B @ X                  # apply s -> a*s + b*s^3 + c*s^5
    if transpose:
        X = X.T
    return X

class Muon(torch.optim.Optimizer):
    """Muon: MomentUm Orthogonalised by Newton-Schulz. For 2D weight matrices."""
    def __init__(self, params, lr=0.02, momentum=0.95, nesterov=True, ns_steps=5):
        super().__init__(params, dict(lr=lr, momentum=momentum,
                                      nesterov=nesterov, ns_steps=ns_steps))

    @torch.no_grad()
    def step(self):
        for group in self.param_groups:
            mu = group["momentum"]
            for p in group["params"]:
                if p.grad is None:
                    continue
                g = p.grad
                state = self.state[p]
                if "buf" not in state:
                    state["buf"] = torch.zeros_like(g)
                buf = state["buf"]
                buf.mul_(mu).add_(g)                       # momentum accumulate
                upd = g.add(buf, alpha=mu) if group["nesterov"] else buf
                O = zeropower_via_newtonschulz5(upd, group["ns_steps"])
                # shape-dependent scale keeps step size consistent across layers
                scale = max(1.0, p.size(0) / p.size(1)) ** 0.5
                p.add_(O.to(p.dtype), alpha=-group["lr"] * scale)

# demo: watch Newton-Schulz flatten the singular values toward 1
G = torch.randn(256, 128)
O = zeropower_via_newtonschulz5(G, steps=5).float()
print(torch.linalg.svdvals(G)[:4])    # spread out: big and small values
print(torch.linalg.svdvals(O)[:4])    # all near 1.0 -> orthogonalised

The demo is the point. Feed in a random matrix whose singular values are all over the place, and after five Newton-Schulz steps they are all close to 1. That is the orthogonalisation, done with nothing but matrix multiplies. In the optimiser, that orthogonalised update replaces the raw momentum before it is subtracted from the weights.

The cost is tiny Five iterations is a handful of matrix multiplies per weight matrix, and it runs in bfloat16. For real LLM training the overhead is well under 1% of total FLOPs. You pay almost nothing and get a better-shaped update.

7. Does it actually help?

Muon came out of the world of training speed records, where the whole game is reaching a target loss in as little compute as possible. The reported gains are consistent rather than marginal. On the widely used NanoGPT speedrun it cut time-to-target by roughly a third versus a strong AdamW baseline. Scaled up, a 1.5B-parameter model reached GPT-2 XL quality in about 10 H100-hours where AdamW needed around 13. It also set image-classification speed records on CIFAR-10.

Two honest caveats. Muon is new (late 2024) and still being studied, so treat exact speedups as setup-dependent rather than universal laws. And it is not a drop-in for every parameter: the hybrid with Adam for 1D tensors is part of why it works. What is solid is the core idea - using the matrix structure of the update, not just its per-element magnitude.

What is the one new thing Muon does over momentum SGD?
Muon keeps ordinary momentum, then orthogonalises that update (via Newton-Schulz) before subtracting it from the weights.
Which parameters should use Muon, and which should use Adam?
Orthogonalising needs a matrix, so Muon takes the 2D hidden weights; 1D tensors (embeddings, norms, biases) stay on Adam.
What do the Newton-Schulz iterations do to the update matrix?
The quintic iteration drives every singular value toward 1, approximating U V^T from the SVD without computing a real SVD.
Why does orthogonalising the update help training?
Raw updates are nearly low-rank; flattening singular values gives every direction equal weight, so rare useful directions get updated too.

How this connects

  • The weight matrices Muon updates are the ones inside every Transformer block: the attention projections and the feed-forward layers.
  • Muon is about training efficiency, the same goal as the systems work in FlashAttention and Chinchilla, but it acts on the optimiser rather than the kernels or the data budget.
  • It composes with sparse architectures like DeepSeekMoE: the expert weight matrices are exactly the 2D tensors Muon is built for.
  • It leaves the alignment and fine-tuning stages (Modules 06 and 07) untouched; it changes how the base weights are learned, not what they are aligned to.
