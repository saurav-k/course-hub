GPT-3: Few-Shot Learning

2020 Brown, Mann, Ryder, Subbiah, Kaplan, Dhariwal, Neelakantan, and 24 co-authors (OpenAI). · arXiv:2005.14165

The one-minute version

  • GPT-3 is a decoder-only Transformer with 175 billion parameters - 96 layers, hidden size 12288, 96 heads, 2048-token context - trained on roughly 300 billion tokens. It is the scaling-laws advice (Lesson 05) taken to an extreme.
  • The headline is not the size. It is in-context learning: you describe a task and show a few worked examples in the prompt, and the model does the task - with no gradient updates and no fine-tuning.
  • Three settings: zero-shot (instruction only), one-shot (one example), few-shot (a handful of examples). More examples in the prompt usually means better accuracy.
  • The weights never change at inference. The model "learns" the task purely by reading the context during a single forward pass, then predicting the next token.
  • This reframed how we use language models: from "fine-tune a new model per task" to "write a good prompt for one general model".

1. Why this paper exists

Through 2018-2019 the dominant recipe was pre-train then fine-tune: take a general model like BERT or GPT-1, then update its weights on a labelled dataset for each new task. It worked, but it needed thousands of labelled examples per task and produced a separate specialised model each time. Humans do not work that way. Tell a person "translate these, here are two examples" and they just do it, no retraining required.

GPT-3 asks: if we scale a plain language model far enough, does that human-like flexibility simply emerge? The answer is largely yes. A big enough next-token predictor can pick up a task from a description and a few examples placed directly in its input, with no weight updates at all.

2. What "in-context learning" actually means

Take the word apart. In-context: the demonstrations live inside the model's input window, the context. Learning: from those demonstrations the model infers the task and applies it to a new query. Crucially, no backpropagation happens - "learning" here is inference-time pattern completion, not training.

3. A concrete prompt

Nothing here is exotic - a prompt is just text. Suppose the task is translating English words to French. The few-shot prompt is literally:

sea otter => loutre de mer
cheese => fromage
plush giraffe => girafe en peluche
otter => ______ The first three lines are demonstrations - input/output pairs in a fixed english => french format. The last line is the query with the answer left blank. The model has seen the pattern three times, so it completes the fourth line in the same shape. No labels, no fine-tuning: the format itself is the "training signal", consumed during one forward pass.

4. How a forward pass "learns" without updating weights

This is the part worth slowing down on. Normal learning nudges the weights by gradient descent. In-context learning does not touch the weights at all. So what changes? The activations - the internal state the model builds up as it reads the prompt.

As GPT-3 processes the demonstrations, attention (Lesson 01) lets later tokens look back at the example pairs. By the time the model reaches the query, its internal representation already encodes "the task is english to french, in this exact format". The next-token prediction is then conditioned on that inferred task. The weights are a fixed program; the prompt is the input that program runs on.

5. Build the prompt: few-shot construction in code

The mechanism on the input side is just string assembly. Here is a tiny, faithful few-shot prompt builder plus a mock of how the model consumes it. The real GPT-3 replaces mock_lm with the 175B network, but the prompt construction is exactly this.

few_shot.py · runnable Python (no GPU needed for the builder)
from typing import Callable

def build_prompt(task_desc, examples, query, sep=" => ", eol="\n"):
    """Assemble a zero/one/few-shot prompt exactly as GPT-3 expects.
    examples: list of (input, output) demonstration pairs.
    Pass examples=[] for zero-shot, one pair for one-shot, many for few-shot.
    """
    parts = []
    if task_desc:                                   # optional natural-language instruction
        parts.append(task_desc + eol)
    for x, y in examples:                            # the k demonstrations
        parts.append(f"{x}{sep}{y}{eol}")
    parts.append(f"{query}{sep}")                    # query, answer left blank
    return "".join(parts)

def n_shot_generate(lm: Callable[[str], str], task_desc, examples, query):
    """lm is the frozen model: text in, continuation out. NO training here."""
    prompt = build_prompt(task_desc, examples, query)
    completion = lm(prompt)                          # single forward pass
    return completion.split("\n")[0].strip()         # first line = the answer

# --- demonstrations for English -> French ---
shots = [("sea otter", "loutre de mer"),
         ("cheese", "fromage"),
         ("plush giraffe", "girafe en peluche")]

# a stand-in "model": in reality this is GPT-3's 175B forward pass
lookup = {"otter": "loutre", "bread": "pain"}
def mock_lm(prompt: str) -> str:
    query = prompt.rsplit(" => ", 1)[0].split("\n")[-1]
    return lookup.get(query, "???")

print("zero-shot:", n_shot_generate(mock_lm, "Translate English to French.", [], "otter"))
print("few-shot :", n_shot_generate(mock_lm, "Translate English to French.", shots, "otter"))
# The ONLY difference between the two calls is how many (input, output)
# pairs sit in the prompt. The weights are identical and frozen.

Stare at the last comment. Zero-shot and few-shot are the same model and the same code path. The only difference is how many demonstration pairs you concatenated into the string. That is the entire trick: adaptation happens in the prompt, not in the parameters.

In production today Every time you paste a couple of examples into a chat model and it copies the format, you are using in-context learning - the capability this paper named and measured. Modern "prompt engineering" is the applied craft of arranging demonstrations that GPT-3 first showed to work.

6. The architecture, by the numbers

GPT-3 is not architecturally novel - it is GPT-2's decoder-only design scaled up, with one tweak: attention layers alternate between dense and locally-banded sparse patterns (borrowed from the Sparse Transformer) to keep the long context affordable.

A Chinchilla-shaped footnote Trained on ~300B tokens, GPT-3 has only about 1.7 tokens per parameter. Lesson 08 (Chinchilla) argues that is badly under-trained - the compute-optimal ratio is closer to 20 tokens per parameter. GPT-3 followed Lesson 05's "make it huge" advice, and later work showed a smaller, better-fed model can beat it.

In few-shot in-context learning, what changes when the model adapts to a task?
The weights stay frozen. Attention reads the demonstrations and conditions the prediction, so only the internal activations differ.
What distinguishes zero-shot, one-shot, and few-shot prompting?
Zero, one, or several demonstration pairs in the prompt. Same frozen model; only the count of in-context examples differs.
Roughly what scale defines the largest GPT-3 model?
GPT-3's flagship is 175B params, 96 layers, hidden size 12288, 96 heads, and a 2048-token context.
Architecturally, how does GPT-3 relate to GPT-2?
GPT-3 is GPT-2's decoder-only design scaled up, with attention alternating between dense and locally-banded sparse patterns.

How this connects

  • Previously, Scaling Laws predicted that a much bigger model keeps improving. GPT-3 is that prediction cashed out at 175B parameters.
  • The attention you met in Lesson 01 is the exact mechanism that reads demonstrations from the context and makes in-context learning possible.
  • Next, The Pile pushes on GPT-3's data: better-curated, more diverse text as an alternative to raw Common Crawl.
  • Chinchilla shows GPT-3 was under-trained for its size - a smaller model on more tokens beats it at equal compute.
  • InstructGPT later fine-tunes a GPT-3-style model with human feedback so it follows instructions rather than just completing text.
