CLIP

working 2021 15 min Radford, Kim, Hallacy, Ramesh, Goh, Agarwal, Sastry, Askell, Mishkin, Clark, Krueger, Sutskever · OpenAI · arXiv:2103.00020

The one-minute version

  • Two encoders, one for images and one for text, trained on 400 million image-text pairs with a single task: given a batch of images and a batch of captions, say which caption belongs to which image.
  • What falls out is one vector space for pictures and words. Classification becomes a lookup against sentences you invent at inference time, which is what "zero-shot" means here.
  • It matches "the accuracy of the original ResNet-50 on ImageNet zero-shot without needing to use any of the 1.28 million training examples it was trained on".
  • The technique matters absolutely in 2026; the 2021 checkpoint is superseded by SigLIP and SigLIP 2. And CLIP embeddings behave like a bag of words, which breaks any product that needs "cat on mat" to differ from "mat on cat".

1. Why this paper exists

The bottleneck was labels. In the paper's framing, standard vision systems "are trained to predict a fixed set of predetermined object categories", and "additional labeled data is needed to specify any other visual concept". Every new concept costs an annotation campaign, and the model can only ever answer questions whose vocabulary was fixed before training.

Meanwhile the internet is full of images with captions attached. They are noisy, informal and unlabelled in any structured sense, but there are hundreds of millions of them and they are free. The question this paper answers is what you can learn from that data with no annotation at all.

2. The mechanism: agree on a batch

Take a batch of N images with their N real captions. Encode all the images and all the captions, and compute every image-caption similarity: an N by N grid. The N pairs that genuinely belong together sit on the diagonal, and every other cell is a wrong pairing that happens to be in the same batch. Train so the diagonal wins.

Note what that buys. Nothing in the loss names a category. The supervision is entirely "these two go together and those two do not", so the model is pushed to encode whatever distinguishes one caption from another, which is roughly everything a person would bother writing down.

3. Zero-shot classification is a lookup

Once images and sentences live in one space, classifying an image does not need a classifier. Write one sentence per class, embed them, embed the image, and take the nearest. Because the classes are sentences and not indices, you can invent them after training.

4. The maths, read aloud

The loss is ordinary cross-entropy applied twice to the same grid: once treating each row as a question over captions, once treating each column as a question over images.

L = ½ · CE(rows of S, diag) + ½ · CE(columns of S, diag),   Sij = (îi · t̂j) / τ îi: the image vector for row i, normalised to unit length. t̂j: the caption vector for column j, also unit length, so their dot product is a cosine similarity between -1 and 1. τ: the temperature, a learned number that divides every similarity and so decides how sharply the model must separate the right pair from the near misses. S: the N by N grid of scaled similarities. CE(rows, diag): read each row as a multiple-choice question whose correct answer is the cell on the diagonal, and take the usual cross-entropy. The two halves: one asks each image to find its caption, the other asks each caption to find its image, and the loss is their average.
clip_loss.py · runnable with torch
import torch
import torch.nn.functional as F

def clip_loss(img_vecs, txt_vecs, logit_scale):
    """Symmetric contrastive loss over one batch.
    img_vecs, txt_vecs: (N, D) outputs of the two encoders.
    logit_scale: exp of a learned parameter, i.e. 1 / temperature."""
    img = F.normalize(img_vecs, dim=-1)          # unit length, so dot = cosine
    txt = F.normalize(txt_vecs, dim=-1)
    logits = logit_scale * img @ txt.T           # (N, N) similarity grid
    target = torch.arange(len(img), device=img.device)   # the diagonal is correct
    loss_i = F.cross_entropy(logits, target)     # each image picks its caption
    loss_t = F.cross_entropy(logits.T, target)   # each caption picks its image
    return (loss_i + loss_t) / 2

def zero_shot(img_vec, class_vecs, class_names):
    """Classification with no classifier: nearest class sentence wins."""
    sims = F.normalize(img_vec, dim=-1) @ F.normalize(class_vecs, dim=-1).T
    return class_names[int(sims.argmax())]

torch.manual_seed(0)
N, D = 8, 512
img_vecs, txt_vecs = torch.randn(N, D), torch.randn(N, D)
scale = torch.tensor(100.0)                      # a trained model learns this
print(float(clip_loss(img_vecs, txt_vecs, scale)))   # high: random vectors do not agree

# now make one pair agree and watch that row's similarity dominate
txt_vecs[3] = img_vecs[3]
grid = F.normalize(img_vecs, dim=-1) @ F.normalize(txt_vecs, dim=-1).T
print(grid[3].argmax().item())                   # 3: the matched pair is now nearest

Two details in that code carry the whole idea. Normalising both sides makes the dot product a cosine, so only direction matters and not vector length. And the target is arange(N), which is another way of saying the correct answer is always the diagonal.

5. What it did not solve

The paper's own limitations section is unusually honest and worth quoting rather than paraphrasing.

  • Fine-grained recognition. "performance of CLIP is poor on several types of fine-grained classification such as differentiating models of cars, species of flowers, and variants of aircraft".
  • Counting and systematic tasks. It struggles with "abstract and systematic tasks such as counting the number of objects in an image".
  • Genuinely unfamiliar data. "zero-shot CLIP still generalizes poorly to data that is truly out-of-distribution". The paper's own example is MNIST, where logistic regression on raw pixels beats it.
  • Scale. "we estimate around a 1000x increase in compute is required for zero-shot CLIP to reach overall state-of-the-art performance. This is infeasible to train with current hardware."

And one failure the paper did not identify, found later and load-bearing for anyone building retrieval. Yuksekgonul and colleagues showed that vision-language models of this kind have "poor relational understanding", "blunder when linking objects to their attributes", and show "a severe lack of order sensitivity". Their diagnosis points at the training task rather than the architecture: "it is possible to perform well on retrieval over existing datasets without using the composition and order information", so contrastive pretraining was never forced to learn it.

A retrieval system built on CLIP-style embeddings cannot reliably tell "the cat on the mat" from "the mat on the cat". The embedding is closer to a bag of the concepts present than to a description of how they relate. If your product turns on that distinction, embeddings alone will not carry it, and no amount of index tuning changes the finding.

6. Does this still matter in 2026?

The technique, yes. The checkpoint, no. The successor is SigLIP, which changes exactly one thing: it replaces the softmax contrastive loss with a pairwise sigmoid loss that "operates solely on image-text pairs and does not require a global view of the pairwise similarities for normalization".

That is a cluster-engineering win before it is a quality win. CLIP's softmax normalises across the whole batch, so computing the loss needs every other example's similarity, which on many devices means an all-gather. Batch size is therefore tangled up with the loss and with your hardware. A sigmoid loss scores each pair on its own, which "allows further scaling up the batch size, while also performing better at smaller batch sizes". The same work reports a useful negative result too: pushing batch size towards a million gives diminishing returns, with "a more reasonable batch size of 32k being sufficient".

SigLIP 2 added caption-based pretraining, self-distillation, masked prediction and multilingual data, and ships at four sizes: 86M, 303M, 400M and 1B parameters. It is the default vision tower in current open vision-language models.

What to actually pick Start at SigLIP 2 rather than original CLIP. Reach for the 2021 CLIP checkpoint only when something downstream already expects it, which in practice mostly means older image-generation checkpoints whose text conditioning was trained against it. The concept - a shared image-text space learned contrastively from web pairs - is unchanged, and that is what this lesson teaches.

Check yourself

Retrieval practice

Answer from memory before revealing.

What is CLIP's training task?
The task is matching within a batch, so every other caption is a negative. Masked captioning and pixel prediction are different objectives, and a fixed taxonomy is exactly what CLIP avoids.
Why can CLIP classify categories it never trained on?
Classification is a nearest-neighbour lookup against embedded class sentences, so the label set is a list of strings. The other three all describe some form of retraining, which is what zero-shot avoids.
Which weakness did later work identify rather than the paper itself?
The first three are named in CLIP's own limitations section. The order and relation failure came from the later ARO work, which traced it to the training task rather than the architecture.
What does SigLIP's sigmoid loss actually buy you?
Softmax normalises over the batch and so needs a global view; a sigmoid scores each pair alone, which decouples batch size from the loss. It does not shrink encoders and it does not fix the bag-of-words finding.

How this connects

  • The image encoder is the Vision Transformer of the previous lesson, and the text encoder is the model from Attention Is All You Need.
  • The text conditioning inside Latent Diffusion is a CLIP text encoder, so this lesson is a prerequisite for that one.
  • BLIP-2 and LLaVA reuse the contrastive objective and then bolt the frozen image encoder onto a language model.
  • The bag-of-words finding is a retrieval-quality result, so read it beside Retrieval-Augmented Generation when you design an embedding index.
Your teacher. Ask the agent to build the N by N similarity grid for a small batch and print it, then to swap two captions and watch the diagonal stop winning. Then ask it to write two prompts that differ only in word order and compare their text embeddings - that is the bag-of-words result reproduced on your own machine.
