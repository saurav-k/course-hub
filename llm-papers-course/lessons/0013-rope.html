RoPE: Rotary Position Embeddings

2021 Su, Lu, Pan, Murtadha, Wen, Liu (Zhuiyi Technology). · arXiv:2104.09864 · "RoFormer: Enhanced Transformer with Rotary Position Embedding"

The one-minute version

  • The original Transformer adds a position vector onto each token embedding. RoPE instead rotates the query and key vectors by an angle proportional to their position.
  • Rotations compose: rotate by m, then compare with something rotated by n, and the dot product only depends on the difference m − n. So absolute rotations produce relative position awareness for free.
  • Each 2D sub-pair of the head dimension gets its own rotation speed, with frequencies θi = 10000−2i/d - fast wheels for fine position, slow wheels for coarse position.
  • It needs no extra parameters, plugs straight into attention, gives some length extrapolation, and is now the default in LLaMA, PaLM, GPT-NeoX and most modern LLMs.

1. Why this paper exists

Lesson 01 gave every token a position vector built from sines and cosines, then added it onto the token embedding before attention. That works, but it is a little clumsy. The position signal is bolted onto the content, so the model has to disentangle "what this token means" from "where this token sits". And what attention actually cares about is usually relative distance: is the verb three words after its subject? Absolute added encodings only hint at relative distance indirectly.

RoPE's promise: encode absolute position by rotation, but arrange the geometry so that when a query at position m meets a key at position n, the score they produce depends only on m − n. Absolute in, relative out.

2. The one idea: position is a rotation

Take the simplest case: a 2-dimensional vector. To "encode position m" into it, spin it counter-clockwise by an angle mθ. That is a standard rotation matrix.

Rm = [ cos mθ   −sin mθ ;   sin mθ   cos mθ ] Rm: a 2×2 rotation matrix. m: the token's position (0, 1, 2, ...). θ: a fixed frequency for this 2D pair. Multiplying a vector by Rm turns it by angle mθ without changing its length. Position 0 turns nothing; position 5 turns five times as far.

3. Why absolute rotation gives relative scores

Attention scores a query against a key with a dot product. Rotate the query by its position m and the key by its position n, then dot them:

(Rm q) · (Rn k) = qT RmT Rn k = qT Rn−m k Rm q: query rotated by its position m. Rn k: key rotated by its position n. RmT: transpose of a rotation is the reverse rotation, R−m. R−m Rn = Rn−m: rotations compose by adding angles, so the two absolute positions collapse into a single relative rotation by n−m. The score depends only on the query, the key, and their distance - never on where they sit absolutely.
The magic line A rotation's transpose is its inverse: RmT = R−m. And rotations add: R−mRn = Rn−m. Put those together and the two absolute positions m and n cancel into one relative term n−m. That is why rotating by absolute position yields a purely relative score.

4. Many wheels: frequencies across the head dimension

A head vector is not 2D, it is d-dimensional (say 64 or 128). RoPE slices it into d/2 pairs and gives each pair its own rotation speed. Pair 0 spins fast, the last pair spins glacially slow. The speeds follow a geometric ladder, exactly like the sinusoidal wavelengths in Lesson 01:

θi = 10000−2i/d,   i = 0, 1, ..., d/2 − 1 θi: the rotation frequency for the i-th 2D pair. i = 0 gives θ = 1 (fast wheel, turns a lot per token). i near d/2 gives a tiny θ close to 10000−1 (slow wheel, barely turns). 10000: the base wavelength constant, inherited from the original Transformer. Fast wheels resolve nearby positions crisply; slow wheels stay coherent across very long distances.

5. Where RoPE sits in the attention block

Crucially, RoPE is applied to Q and K only, after their linear projection and right before the score. Values are left untouched, and there is no added position embedding at the input. Every layer re-rotates, so position information is refreshed all the way up the stack.

6. Implement it and prove the relative property

Here is apply_rotary_emb in PyTorch, then a numerical check of the paper's central claim: shift a query and key by the same amount and the score does not move; it only tracks the gap between them.

rope.py · runnable with torch
import torch

def rope_angles(seq_len, d, base=10000.0):
    # one frequency per 2D pair:  theta_i = base^(-2i/d)
    i = torch.arange(0, d, 2).float()          # 0,2,4,... -> d/2 values
    freqs = base ** (-i / d)                    # (d/2,)  fast -> slow
    pos = torch.arange(seq_len).float()         # positions 0..seq-1
    angles = torch.outer(pos, freqs)            # (seq, d/2)  pos * theta
    return angles.cos(), angles.sin()           # each (seq, d/2)

def apply_rotary_emb(x, cos, sin):
    # x: (seq, d).  Rotate each adjacent 2D pair (x_even, x_odd) by its angle.
    x1, x2 = x[..., 0::2], x[..., 1::2]         # even and odd lanes
    xr1 = x1 * cos - x2 * sin                    # standard 2D rotation
    xr2 = x1 * sin + x2 * cos
    out = torch.empty_like(x)
    out[..., 0::2], out[..., 1::2] = xr1, xr2    # re-interleave
    return out

# ---- verify: score depends only on (m - n), not absolute position ----
torch.manual_seed(0)
d, seq = 8, 64
cos, sin = rope_angles(seq, d)
q = torch.randn(d); k = torch.randn(d)          # one query, one key

def score(m, n):                                # rotate q by m, k by n, dot
    qm = apply_rotary_emb(q.unsqueeze(0), cos[m:m+1], sin[m:m+1])
    kn = apply_rotary_emb(k.unsqueeze(0), cos[n:n+1], sin[n:n+1])
    return (qm * kn).sum().item()

print(score(5, 3))    # gap = 2
print(score(9, 7))    # gap = 2, shifted by +4  ->  same score
print(score(20, 18))  # gap = 2, shifted again  ->  same score
print(score(5, 4))    # gap = 1  ->  different score

Run it and the first three numbers match to floating-point precision while the fourth differs. The score is a function of the distance m − n alone. That is the paper's theorem, reproduced in ten lines. No lookup table of relative-position biases, no learned parameters - just rotation geometry.

In production Real code precomputes cos and sin once per sequence length and caches them, and fuses the rotation into the attention kernel. LLaMA, Mistral, Qwen and most 2023+ models ship RoPE by default. Long-context tricks like position interpolation and NTK / YaRN scaling just stretch or reshape these same θ frequencies to reach context lengths far beyond training.

Retrieval practice

Answer from memory before revealing.

How does RoPE inject position into a token representation?
RoPE turns Q and K by an angle proportional to position; length is unchanged, and position rides in the angle.
Why does rotating by absolute position give a relative score?
R_m^T R_n equals R_(n minus m): the absolute positions cancel and only the distance survives in the dot product.
What do the frequencies theta_i control across the head dimension?
Each pair spins at its own theta_i = 10000^(-2i/d): fast wheels resolve nearby positions, slow wheels span long range.
Which vectors does RoPE actually rotate inside attention?
RoPE rotates Q and K only, every layer; values carry content to blend, so they are left untouched.

How this connects

  • Builds directly on the sinusoidal positional encoding from the original Transformer - same 10000 frequency ladder, but rotating instead of adding.
  • Powers LLaMA and PaLM; if you studied those, RoPE is the position mechanism they quietly rely on.
  • Contrast with the next lesson, ALiBi, which drops position embeddings entirely and biases the attention scores by distance instead.
  • Interacts with KV-cache methods like Multi-Query Attention: RoPE is applied to K before it is cached, so the cache stores already-rotated keys.
Your teacher. The one thing to nail is the cancellation RmTRn = Rn−m. Ask the agent to draw two 2D arrows on a clock face, rotate them by m and n, and show that the angle between them only depends on n−m. Then run the code above and watch the three equal-gap scores line up. Once that clicks, RoPE is obvious.
