ReAct: Synergizing Reasoning and Acting

2022 Yao, Zhao, Yu, Du, Shafran, Narasimhan, Cao (Princeton University / Google Research). · arXiv:2210.03629

The one-minute version

  • Pure Chain-of-Thought reasons in a closed room: it cannot check a fact, so a wrong intermediate step snowballs into a confident wrong answer.
  • ReAct interleaves two things the model already can do: Thought (reasoning in words) and Action (calling a tool like a search API), then feeds the tool's Observation back in.
  • The loop is Thought → Action → Observation → Thought → ..., repeating until the model emits a Finish action with the answer.
  • Grounding each reasoning step in real observations reduces hallucination and produces interpretable trajectories. This simple loop is the blueprint for essentially every LLM agent built since.

1. Why this paper exists

Chain-of-Thought gave models a way to reason across steps, but the reasoning is entirely internal. If step two asserts a false fact, there is no mechanism to catch it - the model has no way to look anything up. Meanwhile a separate line of work had models take actions in environments (click, search, move) but without explicit reasoning, so they flailed on tasks that needed planning. Each half was missing the other.

ReAct's contribution is not a new architecture or new training. It is a prompting format that lets one model do both, taking turns: think about what to do, do it, observe the result, think again.

2. The mechanism: a Thought-Action-Observation loop

ReAct structures the model's output into labelled lines. A Thought line is free-form reasoning. An Action line is a structured call the runtime can execute, like Search[Eiffel Tower height]. The runtime runs it and appends an Observation line with the result. That observation goes back into the prompt, and the model produces its next Thought. The cycle repeats until the model outputs Finish[answer].

Crucially, everything the model emits and everything the tools return lives in the same growing transcript, which is re-fed to the model each turn. The model's "memory" of the task is just this text. That is why the pattern is so general: any tool that takes a string and returns a string can be an action.

3. Why interleaving beats either half alone

The synergy runs both directions. Reasoning guides acting: a Thought decides which search to run, or notices the last result was useless and plans a different query. Acting grounds reasoning: an Observation injects a real fact that the model could not have reliably recalled, so the next Thought is built on evidence rather than a guess.

The paper shows this concretely. On HotpotQA (multi-hop question answering) and FEVER (fact verification), ReAct with a Wikipedia search tool hallucinates less than CoT because it checks claims against retrieved text. On interactive benchmarks it is dramatic: +34% absolute success on ALFWorld (text-based household tasks) and +10% on WebShop (online shopping), versus imitation or reinforcement-learning baselines, because reasoning lets the agent plan through long action sequences.

4. The math, read in plain English

ReAct widens the model's action space. A plain policy maps context to an action in the environment. ReAct adds "thinking" as a special action that changes only the internal context, not the world.

at  ~  π( · ÷ ct ),    ct+1 = ct + (at, ot),    at ∈ { thoughts } ∪ { tool actions } ct: the context at step t - the whole transcript of prior thoughts, actions, and observations. π: the model, acting as a policy that samples the next line. at: that next line, which may be a thought (updates the context only) or a tool action (also produces an observation from the world). ot: the observation the runtime returns for a tool action (empty for a pure thought). ct+1: the new context, grown by appending what just happened. The loop runs until the action is Finish.

The key line is the union: the action set includes both language "thoughts" and real "actions." A thought is a free action that reorganizes the model's own context; a tool action reaches out and pulls a fact back in. Alternating them is the whole method.

5. Implement it: a ReAct agent loop with a mock tool

The code below is a complete, runnable ReAct loop. It maintains a transcript, calls a (stubbed) model to get the next Thought and Action, parses the Action line, executes a mock search tool, appends the Observation, and repeats until Finish. Swap the stub for a real model and the mock tool for a real API and you have a working agent.

react_agent.py · runnable (model call stubbed)
import re

# --- a mock search tool: string in, string out ---
KB = {
    "eiffel tower height": "The Eiffel Tower is about 330 metres tall.",
    "eiffel tower city":   "The Eiffel Tower is located in Paris, France.",
}
def search(query):
    q = query.lower().strip()
    for key, val in KB.items():
        if key in q or q in key:
            return val
    return "No results found."

TOOLS = {"Search": search}   # register available actions by name

# --- parse an 'Action: Name[argument]' line out of model output ---
ACTION_RE = re.compile(r"Action:\s*(\w+)\[(.*?)\]")
def parse_action(text):
    m = ACTION_RE.search(text)
    return (m.group(1), m.group(2)) if m else (None, None)

# --- the ReAct control loop ---
def react(question, call_model, max_steps=5):
    transcript = f"Question: {question}\n"
    for step in range(max_steps):
        out = call_model(transcript)      # model writes a Thought + Action
        transcript += out + "\n"
        name, arg = parse_action(out)
        if name == "Finish":
            return arg, transcript        # agent decided it is done
        if name in TOOLS:
            obs = TOOLS[name](arg)        # execute the tool
        else:
            obs = "Invalid action."
        transcript += f"Observation: {obs}\n"   # feed the result back in
    return None, transcript               # ran out of steps

# --- stub model: returns scripted Thought/Action lines per turn ---
_script = [
    "Thought: I need the tower's height.\nAction: Search[eiffel tower height]",
    "Thought: I have the height now.\nAction: Finish[about 330 metres]",
]
def call_model(transcript):
    # a real model would read the transcript; the stub just steps a script
    return _script[call_model.i] if call_model.i < len(_script) else \
           "Action: Finish[unknown]"
call_model.i = -1
def stepped(transcript):
    call_model.i += 1
    return call_model(transcript)

answer, log = react("How tall is the Eiffel Tower?", stepped)
print(log)
print("FINAL ANSWER:", answer)      # about 330 metres

Read it against the state machine. The transcript is the context ct. parse_action turns the model's Action: line into a real call. The tool's return becomes the Observation: line appended to the transcript. And Finish is the exit edge. That is the entire agent - a text loop with a parser and a tool table.

This is what an "agent" is Strip away the branding and a modern tool-using agent is exactly this loop: reason, pick a tool, run it, read the result, repeat. Function-calling APIs, ReAct-style frameworks, and browser agents all descend from these two pages. Understanding this loop is understanding agents.

6. Strengths and honest limits

PropertyChain-of-ThoughtActing onlyReAct

HallucinationHighMediumLower - grounded
Planning long tasksLimitedPoorStrong
InterpretabilityChain visibleActions onlyThoughts + actions

ReAct is not magic. If the search tool returns junk, a bad Observation can still mislead the model, and a loop can get stuck repeating a useless query - which is why real systems add step limits, retries, and reflection. But the core lesson stands: let the model think and act in turns, and ground its thoughts in what its actions return. That single idea is the foundation of the agent era.

Check yourself

Retrieval practice

Answer from memory before revealing.

What are the three repeating elements of the ReAct loop?
ReAct alternates a Thought (reasoning), an Action (tool call), and an Observation (the tool's returned result), repeating until Finish.
How does acting reduce hallucination compared to plain reasoning?
A tool observation is real data from the world, so the model's next thought is anchored to fact rather than to fuzzy memory.
In the ReAct formulation, what makes a Thought special as an action?
A thought is a free action that reorganizes the model's own context; only tool actions reach out and return an observation from the environment.
What signals that a ReAct agent should stop looping?
The loop exits when a Thought concludes there is enough evidence and the model emits Finish[answer]; runtimes also add a step cap as a backstop.

How this connects

  • ReAct fuses Chain-of-Thought reasoning with tool use, curing CoT's inability to check itself.
  • Its search action is often retrieval, but ReAct makes retrieval a choice the model plans, not a fixed first step.
  • Tree of Thoughts adds search and backtracking over reasoning states, complementing ReAct's search over the world.
  • Running many reasoning-action rollouts at inference is exactly the compute trade of Test-Time Scaling.
Your teacher. Ask the agent to run the loop with a broken tool that returns "No results found," and watch how the transcript evolves - does it retry, or loop uselessly? Then ask it to add a second tool (say a calculator) to the TOOLS table and a task that needs both. Building the two-tool version yourself is the moment agents stop feeling mysterious.
