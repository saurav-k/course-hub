Module 08 · Reasoning, Retrieval & Agents · Lesson 34

Test-Time Scaling

2024 Snell, Lee, Xu, Kumar (UC Berkeley / Google DeepMind). · arXiv:2408.03314

The one-minute version

  • For years, the way to get a smarter model was to make it bigger - more parameters, more training compute. That is expensive and paid once, at training time.
  • This paper studies the other dial: spend more compute at inference. Let the model think longer, sample many answers, search, and revise before committing.
  • Two main levers: searching against a verifier (generate many candidates, pick the one a scorer trusts) and revising the model's own answer step by step.
  • Allocating that compute optimally per question beats a naive best-of-N by over 4x, and a small model given extra test-time compute can outperform a model 14x larger on matched FLOPs. This is the idea behind long-CoT models like OpenAI o1 and DeepSeek-R1.

1. Why this paper exists

The scaling laws of Module 02 pointed one way: bigger models, trained on more data, are more capable. But that capability is frozen into the weights at training time, and training a giant model is enormously expensive. Meanwhile Chain-of-Thought and Tree of Thoughts had shown that the same model gets much better if you let it think longer at inference. That raises a sharp question: for a fixed compute budget, is it better spent on training a bigger model, or on running a smaller model harder?

The answer reframes how we think about intelligence in models: capability is not only a property of the weights, it is also a property of how much you let the model compute at answer time. Inference compute becomes a resource you can trade for accuracy.

2. Lever one: search against a verifier

The simplest way to spend more inference compute is best-of-N: sample N candidate answers, then use a verifier - a model trained to score correctness - to pick the best one. Generating is cheap and parallel; the verifier turns quantity into quality. A stronger version uses a process reward model that scores each step of a reasoning chain, so search can be guided step by step rather than only judging the final answer.

3. Lever two: revise your own answer

The second lever changes the model's output distribution adaptively: instead of many independent shots, the model produces an answer, then refines it, sequentially, each revision conditioned on the last. This is a chain of self-corrections rather than a spray of parallel guesses. Sequential revision helps most on problems where the model is close and just needs to fix mistakes; parallel search helps most where it needs to find a fundamentally different approach.

4. The key idea: compute-optimal allocation

The paper's central result is that how you spend inference compute should depend on the difficulty of the question. Easy questions are solved on the first try, so extra samples are wasted; hard questions need deep search or many revisions. A fixed strategy (always best-of-N, always revise) is inefficient. A compute-optimal strategy predicts the difficulty and routes the budget accordingly - more parallel search here, more sequential revision there.

With this allocation, the authors show a striking trade: in FLOPs-matched comparisons, a smaller model given extra test-time compute can outperform a model 14 times larger that just answers once. Spending compute at inference is sometimes a better deal than spending it at training - as long as the base model is capable enough to benefit and the verifier is good enough to steer.

5. The math, read in plain English

Best-of-N picks the candidate the verifier likes most. Compute-optimal scaling chooses the whole strategy to maximize accuracy for a given budget.

ŷ = argmaxi ∈ 1..N   R( y(i) ÷ x ),    y(i) ~ π( · ÷ x ) x: the question. y(i): the i-th sampled candidate answer from the model π. R(y ÷ x): the verifier's score for how likely answer y is correct. argmaxi: return the single candidate the verifier scores highest. As N grows you get more shots on goal, but the payoff is capped by how well R can tell right from wrong.
strategy* (x, C) = argmaxstrategy   E[ correct ÷ x, strategy ]   s.t.   compute(strategy) ≤ C C: the inference compute budget for this question. strategy: a choice of how to spend it - how many parallel samples, how many sequential revisions, how deep to search. E[correct | x, strategy]: expected accuracy under that strategy. argmax s.t. compute ≤ C: pick the strategy that maximizes accuracy without exceeding the budget. Because the best strategy depends on x's difficulty, the allocation is adaptive, not fixed.

6. Implement it: best-of-N with a verifier, plus a budget sweep

The code samples N candidate answers, scores them with a verifier, and returns the best - then sweeps the budget N to show accuracy climbing with compute, and flattening once the verifier can no longer tell candidates apart. Model and verifier are stubbed so it runs offline.

test_time_scaling.py · runnable with Python
import random

# --- a toy task: guess a hidden target; model is noisy, verifier is decent ---
TARGET = 42

def model_sample(x):
    # the base model: right sometimes, noisy otherwise (like a real sampler)
    if random.random() < 0.25:
        return TARGET                       # a correct attempt
    return random.randint(30, 55)           # a plausible wrong attempt

def verifier(candidate, x):
    # an imperfect scorer: higher when candidate is near the target.
    # a real verifier is a trained reward model over reasoning traces.
    noise = random.uniform(-3, 3)
    return -abs(candidate - TARGET) + noise

# --- best-of-N: sample N, keep the verifier's favourite ---
def best_of_n(x, n):
    cands = [model_sample(x) for _ in range(n)]      # parallel attempts
    return max(cands, key=lambda c: verifier(c, x))  # verifier picks one

# --- sweep the compute budget N and measure accuracy ---
def sweep(trials=2000):
    print(f"{'N (budget)':>10} | {'accuracy':>8}")
    for n in [1, 2, 4, 8, 16, 32, 64]:
        hits = sum(best_of_n(None, n) == TARGET for _ in range(trials))
        acc = hits / trials
        bar = "#" * int(acc * 40)
        print(f"{n:>10} | {acc:>7.2%}  {bar}")

random.seed(0)
sweep()
# accuracy rises steeply with N, then flattens: more compute helps,
# but the verifier's ceiling caps how much best-of-N can buy.

Two lessons fall out of the sweep. First, more inference compute buys accuracy - doubling N reliably lifts the score early on. Second, the curve flattens: once the verifier can no longer distinguish a right answer from a near-miss, extra samples stop helping. That plateau is exactly why the paper cares about a better verifier and smarter allocation, not just brute-force N.

The verifier is the bottleneck Best-of-N can only be as good as the scorer that picks the winner. A perfect verifier turns N samples into near-perfect accuracy; a weak one wastes them. This is why so much reasoning-model work is really reward-model and verifier work - the generator has plenty of good answers in its N tries; the hard part is recognizing them.

This paper is the analysis behind a wave of reasoning models. OpenAI o1 (2024) is trained to produce very long internal chains of thought before answering - test-time compute turned into a first-class trained behavior. DeepSeek-R1 showed the same long-CoT reasoning could be elicited largely through reinforcement learning with verifiable rewards. The common thread is this lesson's claim: for hard problems, letting a model think longer at inference is a real, sometimes better, alternative to making it bigger.

How this connects

  • Thinking longer began with Chain-of-Thought; this paper measures how much accuracy that extra thinking is worth.
  • Tree of Thoughts is one search strategy for spending test-time compute; here it becomes one option among several to allocate.
  • The verifiers and reward models are close cousins of the reward signal in GRPO and reasoning-model training.
  • It reframes the training-side scaling laws and Chinchilla compute-optimality with a new axis: inference.
Your teacher. Run the sweep, then make the verifier perfect (drop the noise) and re-run: accuracy should shoot toward 100% as N grows. Now make it near-random and watch the curve go flat. That single experiment teaches the paper's deepest point - test-time compute is only as valuable as the verifier steering it. Ask the agent why o1 and R1 therefore invest so heavily in reward signals.
