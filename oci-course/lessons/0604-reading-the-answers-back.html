Module 06 · Analytics · Lesson 0604

Three different products answer to the word dashboard, and picking by name picks wrong

working 10 min Capability area analytics, matrix rows managed-search and bi-dashboards.

The one-minute version

  • Search with OpenSearch is the managed cluster for full-text search and log analytics, with OpenSearch Dashboards on top.
  • It also serves vector search and searchable snapshots, and its alerting plugins deliver through the Notifications service.
  • Oracle Analytics Cloud is the enterprise business intelligence layer: semantic models, dashboards, self-service visualisation and natural-language questions.
  • It is a separate purchase from the platform's own observability dashboards, and it connects natively to the Autonomous Lakehouse from lesson 0600.
  • The word dashboard therefore names three unrelated things here, and the console-native Dashboards service is a fourth kind of surface again.

The mental model: two query shapes, two products

Search with OpenSearch gives managed OpenSearch clusters with the OpenSearch Dashboards interface, supporting full-text search, log analytics, vector search and searchable snapshots. Its alerting plugins are wired into Notifications, and cluster sizing is what drives its cost.

Oracle Analytics Cloud is the enterprise business intelligence platform: semantic models, dashboards, self-service visualisation and natural-language questions, connecting natively to the Autonomous Lakehouse. When it faces the internet it is normally published behind a load balancer and the web application firewall, which module 07 and module 11 cover.

The mechanism: what the word dashboard is doing here

The reframing A name collision inside one platform is worse than a name collision between platforms, because both parties assume they are talking about the same tenancy and the same console. Resolve it the same way as the two Kafka products: ask which documentation page they had open.

The trade-off: a sized cluster on one side, a separate purchase on the other

OpenSearch here is a cluster you size, which is the same fork the module has met twice already. There is no serverless variant of it on this platform, so the idle state is part of the deal and capacity planning is part of the job.

Oracle Analytics Cloud is bought separately from the platform's own observability surfaces, which is not a technical limitation but is a real procurement one. A team that wants one dashboard covering both its business metrics and its infrastructure metrics is asking two products to become one, and on this platform they do not.

Vector search is worth noticing where it appears rather than where it is advertised. It is available in Search with OpenSearch, and lesson 0502 recorded it in OCI Cache as well. Module 13 returns to vector storage properly. The point here is that the capability is spread across services you already run rather than concentrated in one, so a design should look for it before adding a new component to get it.

Check yourself

Retrieval practice

Answer from memory before revealing.

Which product answers "summarise last quarter by region and product line"?
Aggregation by business dimension is the business intelligence shape, and Oracle Analytics Cloud is the product for it. The first and fourth are the search engine and its interface, aimed at retrieval. The third reads platform metrics, not business rows, which is the collision this page is about.
Where do the alerting plugins of the search service deliver their alerts?
The plugins are wired into Notifications. The first and second name real observability services that are not what the documentation describes here. The third confuses an alert with a report and crosses into a different product entirely.
A colleague says "put it on the dashboard". What is the useful next question?
Several unrelated surfaces answer to the word, so the first thing to resolve is which one. The first and second are real questions that only make sense after the product is known. The fourth is a good question about the data and does not disambiguate the surface at all.

Practice about 15 minutes, with paper

Practice 1working

Four requests arrive in the same week. (a) Support wants to type a customer's name and see every ticket mentioning it. (b) Finance wants revenue by region with a filter for the last four quarters. (c) The platform team wants processor use and error rates for a compartment on one screen. (d) A product team wants "find me tickets that mean the same thing as this one" rather than exact word matching.

Name the surface for each, and identify which two of the four would be served by the same product.

Hint

Sort the four by question shape first: retrieval against aggregation against platform telemetry. Then notice that one of the retrieval requests is asking for a different matching method rather than a different product.

Show the worked solution
  1. Request (a). Retrieval by text across documents, so Search with OpenSearch, read through OpenSearch Dashboards.
  2. Request (b). Aggregation by business dimension over warehouse rows, so Oracle Analytics Cloud, connected to the Autonomous Lakehouse.
  3. Request (c). Platform metrics and logs for a compartment, so the console-native Dashboards service. This is the one that belongs to module 10 rather than to this module.
  4. Request (d). Matching by meaning rather than by word is vector search, which the same OpenSearch service supports. No new product is needed.
  5. The pair. Requests (a) and (d) are both Search with OpenSearch, which is the answer the wording of (d) is designed to hide.

Sanity check. Three distinct products for four requests, with the search service appearing twice. If request (d) added a fourth product, ask which service already in the design supports vector search.

Your teacher. Ask an agent to list every surface in a tenancy that somebody calls a dashboard, and who reads each one. Duplicated panels across two of these products are common, and they usually disagree, because they were built from different sources by people who each thought there was only one dashboard.
