Module 08 · Identity and access · Lesson 0801

A policy is one sentence, its verbs are a ladder, and enabling deny is permanent

frontier 12 min Capability area identity-workforce, matrix row iam-policy-language.

The one-minute version

  • A statement reads allow, group, verb, resource family, location, and optionally conditions. That is the whole grammar.
  • The four verbs are a ladder: inspect, read, use, manage, each containing the one below it.
  • Statements inherit downward. One attached at the tenancy applies to every compartment beneath it, and there is no resource-level policy layer to narrow it.
  • Explicit deny is opt-in for the whole tenancy and enabling it is permanent. Once on, the documentation states it cannot be turned off.
  • Deny is subtractive from the bottom of the ladder: denying manage leaves inspect, read and use intact, so you deny the lowest verb you want gone.

The mental model: five slots in one sentence

policy statements · the shape every grant on this platform takes
Allow group NetworkAdmins to manage virtual-network-family in compartment Prod

Allow group Auditors to read all-resources in tenancy
  where request.region = 'IAD'

Allow dynamic-group BuildRunners to use object-family in compartment Artifacts
  where target.bucket.name = 'releases'

The mechanism: the ladder, and which way deny walks it

The mechanism: the door that only opens

The enablement flow offers to create a root-level statement that reserves deny authoring to the enabler and to the default administrators, which is worth accepting. Deny evaluates before allow, comes in three forms so that it also reaches the cross-boundary grants of lesson 0803, and exempts only the default administrator group in the default domain. It does not override identity-domain administration roles at all.

Three documented known issues shape how this feature is rolled out. Tag-based denies can take up to a day to become fully effective after the feature is first enabled. Denies conditioned on a target tag do not prevent console-initiated deletion of users, groups and dynamic groups. And conditions naming a dynamic group by identifier or name are not enforced across the console, the software development kit and the API. Read the known issues page before relying on any of the three.

The mechanism: which limit actually binds

The reframing Because statements inherit downward and there is no resource-attached policy, the compartment tree is the permission model. Where a resource sits decides which statements reach it, and the hard statement limit means the tree cannot be flattened into one compartment full of exceptions.

The trade-off: deny buys subtraction and hands out a weapon

Without the feature, the only way to withhold access is to not grant it, and in a large estate that becomes an argument about which of a hundred statements is the one granting too much. Deny lets you subtract directly, which is genuinely easier to reason about.

The cost is symmetric. Oracle's own warning is that administrators in child compartments can use deny statements to block parent access, so once the feature is on, a compartment administrator can fence out the tenancy administrator over their own subtree. That is a property of the feature rather than a defect, and it is the reason the enablement offers to reserve deny authoring in the first place.

Check yourself

Retrieval practice

Answer from memory before revealing.

A principal should keep listing but lose everything else. Which verb do you deny?
Deny is subtractive from the verb named upward, so denying read removes read, use and manage while inspect survives. The first leaves read and use intact. The second removes listing as well, which the question wanted kept. The third is more work and also removes listing.
What is irreversible about deny policies on this platform?
The tenancy-wide feature switch is the permanent part; statements stay ordinary editable objects. The first inverts it exactly and is the fear that stops teams writing useful denies. The third and fourth describe fixed properties that were never adjustable, so calling them irreversible says nothing.
Which limit constrains a large estate's policy design first?
The per-hierarchy figure is an order of magnitude below what the object limits multiply to, and Oracle states it cannot be raised. The second and third are the factors of the larger number. The fourth is a real limit on a different object entirely.

Practice about 20 minutes, with paper

Practice 1frontier

A tenancy administrator wants a contractor group to be able to list and read everything in a production compartment, to work with objects in one bucket there, and never to be able to create or delete anything anywhere in the tenancy. The deny feature is currently off.

Write the statements, decide whether the deny feature needs enabling at all, and state what changes about the tenancy if it is enabled.

Hint

Work out first whether the requirement can be met by writing no grant rather than by writing a subtraction. Then check the verb ladder: one verb covers "work with" without covering "create and delete".

Show the worked solution
  1. Grant the reading. Allow the contractor group to read all-resources in the production compartment. Read carries inspect with it, so listing is covered by the same statement.
  2. Grant the bucket work. Allow the group to use object-family in that compartment, narrowed with a condition naming the one bucket. Use sits below manage, so it does not confer creation or deletion.
  3. Judge the prohibition. Nothing grants manage anywhere, and access is denied by default in the absence of an allow. The requirement is already met without any deny statement.
  4. Decide about the feature. Leave it off. A one-way tenancy-wide switch should be taken for a requirement that cannot be met by withholding a grant, and this one can.
  5. State what enabling would change. Deny would evaluate before allow across the whole tenancy, only the default domain's default administrator group would be exempt, and administrators of child compartments would gain the ability to fence out the parent. None of that is needed here.

Sanity check. Two statements, no denies, and the feature still off. If your answer enabled a permanent tenancy-wide feature to express a permission that was never granted, that is the trap the question was built around.

Your teacher. Ask an agent to count the policy statements attached at or above each compartment in a tenancy, and compare each total against the five hundred figure. The hierarchy that is closest to it is the one whose next reorganisation will be blocked, and nobody discovers it until the day they try.
