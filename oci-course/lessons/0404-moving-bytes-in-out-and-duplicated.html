Module 04 · Storage · Lesson 0404

Every storage service brings its own copy mechanism, and the platform brings none

working 10 min Capability areas storage and resilience-migration, matrix rows bulk-transfer-appliance, cross-region-replication and backup-service.

The one-minute version

  • There is no one replication service. Each storage service carries its own: a bucket replication policy, a block volume replica, a file system replication, a NoSQL global table.
  • Backups follow the same shape. Backup policies schedule block and boot volume backups, and a volume group is what makes a multi-volume capture consistent.
  • Restoring creates a new volume or instance rather than overwriting the old one, so a restore is a fork rather than a rewind.
  • The first copy of a very large dataset arrives offline: a 150 TB Data Transfer Appliance, shipped free, mounted over NFS, sealed and returned - and export works the same way.
  • Four rows in this area are genuine absences with documented reasons, and each has a substitute worth naming.

The mental model: one column per service

Oracle documents the object half on its replication page: a policy on the source bucket mirrors into a destination bucket. Block volumes take replicas into another availability domain or another region. File systems replicate across regions. Module 14 is where these are combined into an orchestrated recovery plan, and this page is the inventory that plan is built from.

The mechanism: backups, and the group that makes them true

The reframing A backup of four volumes taken one at a time is four snapshots of four different moments. A volume group captures the set at one instant, which is what makes it a backup of a database rather than a collection of backups of disks.

The first copy: when the network is the wrong path

The four rows OCI genuinely leaves empty

Each of these is recorded as a real absence in the verified inventory, with a reason and a substitute. Naming the substitute is what keeps them findings rather than complaints.

  • No managed online bulk transfer service. The Data Transfer service is the offline path only. Online copies are made with the command line interface or a third-party sync tool.
  • No first-party storage gateway. The on-premises appliance that fronted Object Storage is retired, and Oracle's page for it now says only that the service is no longer available. On-premises access is left to the command line, S3-compatible clients, or a partner appliance.
  • No single-zone high-performance object tier. Object Storage is regional and replicated across availability or fault domains by default, so the trade that tier represents elsewhere is not offered here.
  • No table-aware object storage type. Table formats sit in the bucket as ordinary objects and are maintained by the query engine reading them rather than by the storage service.
The third and fourth of those are absences of a trade, not of a capability, and they are easy to report wrongly. OCI has no cheaper single-zone object tier because its object storage is replicated by default - which is a stronger position rather than a weaker one - and it stores table-format data perfectly well, just without the storage service knowing that is what the objects are.

Check yourself

Retrieval practice

Answer from memory before revealing.

A workload uses a bucket, three block volumes and a file system. How many replication decisions does a second-region copy need?
Replication is a per-service feature, so the bucket, the volumes and the file system each need their own decision - three services, whatever the resource count. The second and third invent a platform-level switch that does not exist, and the fourth counts resources where the mechanisms are per service.
A runbook says "restore the volume and carry on". What is missing?
A restore creates a new volume rather than rewriting the old one, so the runbook has to say what attaches it and what happens to the original. The other three are all worth recording somewhere and none of them is the step that leaves the workload still pointing at the old disk.
Which statement about Object Storage tiers on OCI is accurate?
Object Storage is regional and replicated across availability or fault domains by default, so the cheaper single-zone trade is simply not on offer. The first and fourth invent the tier, and the third gets the conclusion right for exactly the wrong reason - the service is regional, not zonal.

Practice about 20 minutes, with paper

Practice 1working

A research group is moving onto OCI. They hold 90 TB of historical results that must land in a bucket, a 6 TB working set on block volumes that will be replicated to a second region, and a shared 2 TB scratch area on a file system. Their site has a 2 Gbps internet link that is already 60 per cent busy during working hours.

Plan the move: work out the transfer time for the historical data over their link, decide the path for it, and list every replication decision the finished estate needs.

Hint

Compute the usable rate before the transfer time, and remember the link is shared. Then count replication mechanisms by service rather than by resource.

Show the worked solution
  1. Find the usable rate. A 2 Gbps link at 60 per cent busy leaves about 0.8 Gbps for the transfer during working hours. Even assuming the full 2 Gbps overnight, a realistic sustained average is well under 2.
  2. Compute the time. 90 TB is 90,000 GB, which is 720,000 gigabits. At 0.8 Gbps that is 900,000 seconds, or about 10.4 days of continuous transfer. At a generous full 2 Gbps it is still about 4.2 days with the link doing nothing else.
  3. Decide the path. Ten days of saturated link, or four days with the site's network unusable, is the curve the appliance exists for. 90 TB fits comfortably inside one 150 TB appliance, which is shipped at no charge and mounted over NFS, so the copy is an ordinary file copy.
  4. List the replication decisions. Three, one per service. A bucket replication policy for the historical results if a second copy is wanted. Block volume replicas into the second region for the working set - and those volumes should sit in a volume group if they are ever captured together. File Storage replication for the scratch area, or a deliberate decision that scratch is not replicated, which is a decision rather than an omission only if it is written down.

Sanity check. The transfer estimate should come out in days rather than hours, and the replication count should be three rather than one or ten. If the transfer looked feasible over the link, the 60 per cent existing load was probably not subtracted.

Your teacher. Ask an agent to list every bucket, volume and file system in a compartment together with whether each one has replication configured. The rows with nothing in that column are the ones a recovery plan will discover at the worst possible moment.
