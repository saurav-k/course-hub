Module 12 · Delivery and integration · Lesson 1203

The gateway meters requests per subscriber, and it stops forwarding a body past a fixed size

working 10 min Capability area integration-messaging, matrix rows api-gateway and managed-integration.

The one-minute version

  • API Gateway is regional, and it requires regional subnets, which is the subnet decision from lesson 0700 arriving with consequences.
  • It fronts functions, ordinary web backends and private endpoints, and adds authentication, rate limiting and client library generation.
  • Usage plans are per subscriber: a request rate per second plus quotas over longer periods, so different callers get different allowances.
  • A request body forwarded to a function backend is capped at six megabytes, which is a design constraint on any upload path.
  • Oracle Integration is a separate product for connecting enterprise systems: adapters, recipes and, in its larger edition, process automation.

The mental model: what a gateway adds to a backend

The mechanism: metering is per subscriber, not per route

Two limits are worth carrying into any design. A request body forwarded to a function backend is capped at six megabytes, so an upload path that exceeds it must write to Object Storage directly rather than passing through the function. And the gateway consumes certificate authority bundles with a small default limit per gateway, from lesson 0804, which constrains how many internal authorities one gateway can be made to trust.

The mechanism: a different kind of integration

The reframing A gateway publishes one interface and governs who may call it. An integration platform connects several systems that each believe they are the centre of the world. Reaching for the second when you wanted the first buys an enterprise product for a routing problem, and reaching for the first when you wanted the second leaves the data mapping to be written by hand.
Three genuine absences sit around this area and each is easy to assume the other way. There is no managed service for a query-language interface of the kind that resolves a client-specified shape. There is no managed service for pushing updates to many connected browser clients. And there is no managed broker for the lightweight publish and subscribe protocol used by devices. All three would be built on the compute and messaging services this course has already covered.

The trade-off: a gateway is a single point of policy and of failure

Putting authentication, metering and logging in one place means they are configured once, reviewed once and consistent across every backend behind it. That consistency is the reason the pattern exists, and it is difficult to achieve any other way once there are several backends.

It also means every caller depends on one regional component, and a change to it affects every route at once. The mitigation is ordinary: deploy gateways per environment, test route changes as deliberately as code changes, and remember that the execution logs are off until enabled, so the evidence about a failed change exists only if somebody turned it on first.

Check yourself

Retrieval practice

Answer from memory before revealing.

A gateway will not deploy into an existing subnet. What is the likely reason?
Regional subnets are a documented requirement, and the older shape is the trap from lesson 0700. The first describes a private gateway, which is supported. The second invents an exclusivity rule. The third would produce a traffic problem rather than a deployment refusal.
What does a usage plan attach to?
Plans are per subscriber, which is what lets one route serve callers on different terms. The other three each name a real object in the model and attach the plan to the wrong one, which is precisely the mistake that produces a gateway nobody can price.
An upload of twenty megabytes must reach a function. What does the design need?
The function-backend body limit is six megabytes, so a large upload goes to storage directly and the function is told about it. The first invents a shape that changes a documented limit. The second confuses a rate quota with a size limit. The fourth chains two functions and still has to get the bytes through the first.

Practice about 15 minutes, with paper

Practice 1working

A team publishes an interface used by three groups: their own internal services, a paying partner, and trial users. Two routes are small requests to a function, and one route accepts document uploads of up to fifty megabytes. They also need to synchronise customer records with a packaged finance system that has its own data model.

Design the front door, state what happens to the upload route, and say which requirement does not belong at the gateway at all.

Hint

Three groups with different terms is a metering question. The upload size should be checked against the documented limit before anything else. The last requirement mentions another system's data model, which is a different category of problem.

Show the worked solution
  1. One gateway, three plans. Deploy into regional subnets, and attach a usage plan per subscriber group: a generous one internally, a contracted rate for the partner, a small one for trials. One backend deployment serves all three.
  2. The two small routes. Function backends behind the gateway, with authentication and execution logging enabled so that a failure has evidence.
  3. The upload route. Fifty megabytes exceeds the six-megabyte function-backend limit, so the payload cannot pass through the function. The client writes to Object Storage directly and the function is triggered by the object event of lesson 1202, or is called with a reference rather than with the bytes.
  4. The finance system. This is not a gateway requirement. Mapping between two systems' data models is what the integration platform's adapters and recipes exist for, and its process automation is where any approval step would live.
  5. What the design avoids. No second deployment per customer group, and no attempt to raise a documented limit that cannot be raised.

Sanity check. One gateway, three plans, an upload path that never carries the bytes through a function, and one requirement handed to a different product entirely. If the upload still passes through the gateway to a function, check the limit again.

Your teacher. Ask an agent which gateway deployments have execution logging enabled. It is off by default, and a gateway without it is a component that shapes every request and can tell you nothing about any of them.
