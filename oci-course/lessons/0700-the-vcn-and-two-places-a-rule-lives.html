Module 07 · Networking and delivery · Lesson 0700

A packet is judged by rules written in two places, and the subnet choice is made once

working 11 min Capability area networking-core, matrix rows virtual-network, subnet and stateful-packet-filter.

The one-minute version

  • A Virtual Cloud Network is regional, carries configurable address ranges and supports IPv6. Overlapping ranges between peered networks are forbidden, which makes address planning a design step rather than a formality.
  • A subnet is regional or tied to one availability domain, and regional is the recommended shape. Regional subnets are required for API Gateway and for load balancer high availability.
  • Rules live in two places: security lists on the subnet and network security groups on the individual network card.
  • A rule is stateful or stateless per rule, and a stateless rule needs a matching rule in the other direction or the reply never returns.
  • A network security group can name another group as its source or destination, so a tiered design never hard-codes an address.

The mental model: three nested things, two rule sets

The VCN documentation carries the regional scope, the address ranges and the subnet shapes. The security rules page carries both rule sets, and the network security group is the one worth learning properly because it is the one that can name another group.

The mechanism: the subnet shape is chosen at creation

The reframing Read a network security group as a label rather than a place. Membership of a group is what a rule refers to, so "the web tier may reach the database tier" is written once and stays true as instances come and go. A security list is genuinely about a place, and the two are worth keeping in separate jobs for exactly that reason.

The mechanism: stateless rules come in pairs

Stateful and stateless is chosen per rule rather than per rule set, so one subnet can hold both kinds. A network card can also have its source and destination address check disabled, which is what turns an ordinary instance into a firewall or routing appliance, a pattern module 11 returns to.

Because both rule sets apply to the same network card at once, confirm on the vendor page above how the two combine before relying on one of them to constrain the other. The safe design habit is to give each set one job - the security list for the subnet-wide baseline, groups for the relationships between tiers - so that no packet's fate depends on remembering which set wins.

The trade-off: address planning is permanent in a way rules are not

Rules can be rewritten in seconds. An address range cannot, because peering two networks requires that their ranges do not overlap, and by the time a merger or an acquisition puts two networks in the same room the ranges were chosen years earlier by people who were not thinking about each other.

The counterweight is that the recommendation is cheap to follow at the start: pick regional subnets, leave room in the address plan, and keep tier relationships in groups rather than in address ranges. None of the three costs anything on day one, and all three are expensive to retrofit.

Check yourself

Retrieval practice

Answer from memory before revealing.

Where can a rule that affects one instance's traffic be written?
Both rule sets apply to the same card, which is why a search for a missing rule has two places to look. The first and second each name one of the two and deny the other. The fourth confuses routing with filtering, and a route table attaches to a subnet rather than to an instance.
A stateless ingress rule allows a request. What else does the reply need?
Stateless means each direction is decided separately, so the reply needs its own egress rule. The second doubles up on the direction that already works. The third describes stateful behaviour. The fourth is a routing answer to a filtering question.
Why does a design prefer regional subnets over the availability-domain shape?
The regional shape is the recommendation and it is what the regional endpoints require. The first invents an addressing benefit. The third contradicts the rule that peered ranges may not overlap. The fourth describes network security groups, which are a separate mechanism entirely.

Practice about 15 minutes, with paper

Practice 1working

A three-tier application has web instances, application instances and a database. The web tier must accept traffic from a load balancer, the application tier only from the web tier, and the database only from the application tier. Instances are replaced regularly by an instance pool, so their addresses change. A network engineer proposes writing all of it as subnet security lists using address ranges.

Redesign it using the mechanism this page describes, say what each rule set is doing in your version, and name what breaks in the original proposal when the pool replaces an instance.

Hint

Ask what each rule is really about. Two of the three relationships are about which tier the sender belongs to, not about where it happens to be. Then remember what a network security group is allowed to name as its source.

Show the worked solution
  1. Make a group per tier. Three network security groups, one for web, one for application, one for database, and each instance's card joins the group for its tier.
  2. Write the relationships between groups. The application group allows ingress from the web group, and the database group allows ingress from the application group. Neither rule mentions an address.
  3. Leave the subnet baseline in the security list. Anything true of every card in the subnet regardless of tier stays there, which keeps the two rule sets doing different jobs.
  4. Say what broke in the original. Address ranges are a statement about place, and the pool replaces instances with new addresses. Every replacement either widens the range until it means nothing or breaks a rule nobody edited.

Sanity check. Your rules should contain zero instance addresses and exactly two tier-to-tier statements. If a rule still names an address range for the application tier, ask what happens to it the next time the pool scales.

Your teacher. Ask an agent which subnets in a tenancy are tied to one availability domain rather than regional. Every one of them is a future argument about load balancer resilience, and the list is usually shorter and older than anyone expects.
