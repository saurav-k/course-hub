Module 11 · Security services · Lesson 1103

There is no client VPN here, so a session is brokered rather than a network joined

working 10 min Capability area security-services, matrix rows bastion and packet-mirroring.

The one-minute version

  • OCI has no native remote-access VPN. Oracle's own tutorial says so, and names the alternatives.
  • Bastion is the documented answer: managed, time-boxed sessions into a private subnet, either a shell session or a forwarded port, without giving the target a public address.
  • Each bastion sets a maximum session lifetime and an allowlist of client addresses, and the service itself carries no charge.
  • A brokered session is not a joined network. It reaches one target through one session, which is a narrower and more auditable thing than a tunnel into the subnet.
  • Traffic mirroring copies packets from a card, a subnet or a balancer to an out-of-band collector, which sits behind a load balancer so the collector fleet scales like any backend.

The mental model: a session, not a tunnel

Where a network-level tunnel is genuinely required, Oracle documents appliances from the marketplace running on your own instances as the path. That is a composition rather than a service, and naming it that way is the honest description.

The mechanism: what bounds a session

Two related absences complete the picture and both were touched earlier. There is no identity-controlled authorisation for host sign-in, so who may log into a guest is decided by keys supplied at launch and managed inside it, as lesson 0802 described. And there is no identity-aware application proxy: reaching an application, as opposed to a host, is fronted by the load balancer and the request firewall of the previous pages. Bastion brokers host sessions and nothing more.

The mechanism: copying traffic to somewhere else

The reframing Both mechanisms on this page exist because the obvious thing is deliberately unavailable. There is no tunnel into a private subnet and no packet content in a log. What replaces each is narrower, more explicit and more auditable, and reading the substitution as a limitation misses that the narrowing is the security property.

The trade-off: brokered access is bounded and inconvenient

A session that expires by itself, reaches one target and comes from an allowed address is genuinely safer than a tunnel, and it is more work every single time. An engineer investigating an incident across six machines creates six sessions, and a long investigation runs into the lifetime.

The lifetime is therefore a real design decision rather than a default to accept: too short and it interrupts legitimate work at the worst moment, too long and the property that makes the mechanism safe is weakened. Set it against how long your longest legitimate task actually takes, and let people create a new session rather than raising it for everyone.

Retrieval practice

Answer from memory before revealing.

An engineer needs shell access to an instance with no public address. What is documented?
Bastion brokers a bounded session, and Oracle documents it as the answer where a client VPN would be expected. The first names a service the vendor's own tutorial says is not offered. The third and fourth both give the target public exposure, which is what the mechanism exists to avoid.
What bounds a brokered session besides the target it reaches?
The bastion sets a maximum session lifetime and an address allowlist. The first invents command-level control the service does not offer. The second invents a per-person quota. The third describes something that would be useful and is not what bounds the session.
Where do mirrored packets go?
The target sits behind a network load balancer with an encapsulation listener. The second contradicts the fact that flow logs never carry payloads. The third and fourth name destinations the mirroring session does not write to.

Practice about 15 minutes, with paper

Practice 1working

A team is moving from another platform where engineers connected to a client VPN each morning and then reached anything in the network for the rest of the day. They also had an intrusion detection appliance that received a copy of all traffic. They ask how to reproduce both arrangements here, and want to know what changes for their engineers day to day.

Describe the replacement for each, and state clearly what changes for a person and what changes for the intrusion detection system.

Hint

Neither arrangement transfers as it stands. For the first, the unit of access changes from a network to a target. For the second, the mechanism exists but the destination has a shape the old appliance may not have expected.

Show the worked solution
  1. The morning VPN. Replaced by Bastion sessions. There is no native client VPN here, so access is per target rather than per network, and each session is bounded by the bastion's maximum lifetime.
  2. What changes for a person. They create a session for the machine they need instead of connecting once and roaming. Long tasks may outlive a session and need a new one, and their client address has to be on the allowlist.
  3. If a network-level tunnel is truly required. Oracle documents marketplace appliances running on your own instances. That is a composition you operate, and it should be chosen deliberately rather than as a way to avoid changing habits.
  4. The intrusion detection copy. Traffic mirroring, with capture filters selecting the traffic of interest by protocol, source and destination.
  5. What changes for the detection system. The collector sits behind a network load balancer with an encapsulation listener, so it becomes a scalable, health-checked backend set rather than one appliance receiving a span port. The appliance has to accept the encapsulated form, and the fleet can now grow.

Sanity check. Your answer should change the unit of human access from a network to a target, and should turn one appliance into a load-balanced fleet. If either replacement looked identical to what they had, re-read what the platform actually offers.

Your teacher. Ask an agent for the maximum session lifetime configured on each bastion in a tenancy, and compare it against how long your longest legitimate maintenance task takes. A mismatch in either direction shows up as either interrupted work or a control nobody is really relying on.
