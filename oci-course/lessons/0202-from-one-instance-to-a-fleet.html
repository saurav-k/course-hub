A fleet is a chain of three objects, and the middle one decides what it may contain

working 10 min Capability areas compute-iaas and compute-scaling, matrix rows vm-images, instance-template and autoscaling-group.

The one-minute version

  • Scaling on OCI is a chain: an image, an instance configuration that saves a whole launch, and an instance pool that keeps a count of instances built from it.
  • Autoscaling attaches to the pool and fires on one of two triggers: a metric threshold or a schedule. There is no predictive scaling.
  • An instance pool can attach a load balancer, so new members join the backend set without a separate step.
  • The chain is what makes the exclusions bite. Preemptible instances cannot go into an instance configuration, so a preemptible instance pool does not exist.
  • An image is either one Oracle publishes or one you build, and a custom image is stored and billed like the object it is.

The mental model: the chain

An image is the first link. Oracle publishes platform images - Oracle Linux, Ubuntu, Windows - and you can capture a custom image from a running instance or import one from Object Storage in the usual disk formats. A custom image is stored per gigabyte-month as object data, and a Windows image brings its own licence cost, so the image line of a bill grows with the number of golden images kept rather than with the fleet size.

The instance configuration is the second link and the important one. It saves an entire launch: the shape, the image, the metadata, the networking. A pool is then simply a count applied to that saved launch.

The reframing The instance configuration is not a convenience. It is the gate: what may enter a fleet on OCI is exactly what an instance configuration can express, and the platform's exclusions are written at that boundary rather than at the pool.

The mechanism: two triggers, and only two

The trade-off: what the chain refuses

Preemptible instances cannot be used in instance configurations. Because an instance pool is built from a configuration, that single exclusion removes the entire pattern of a discounted, automatically replaced fleet. A design carried in from a cloud where reclaimable capacity sits inside a launch template and a scaling group has no direct translation here, and the honest options are to drop the discount, to drive the reclaimable instances from your own launcher without the pool, or to move the workload onto Kubernetes, whose node pools do support preemptible capacity.

The second refusal came from the previous page: a dedicated virtual machine host supports neither pools nor autoscaling. Between the two exclusions, the shape of an OCI fleet is decided by what the instance configuration will accept, and it is worth checking that before the design is drawn rather than after.

Check yourself

Retrieval practice

Answer from memory before revealing.

Why can a fleet of preemptible instances not be built with an instance pool?
The exclusion is written at the instance configuration, and a pool can only be built from a configuration - so the refusal happens one object earlier than most people look. The first option puts the rule on the wrong object, and the third and fourth invent requirements a pool does not have.
A workload has a sharp, well known daily peak at a fixed time. Which autoscaling trigger fits, and why?
OCI offers a metric trigger and a schedule trigger and nothing that anticipates, so a known peak is served by growing the pool before it arrives. The second option names a trigger that does not exist here. The first arrives late by definition, and the fourth adds a false limitation - a schedule shrinks a pool as readily as it grows one.
What does an instance configuration actually store?
It is a saved launch, which is why it is the object the exclusions attach to. The second describes the pool, the third describes a custom image, and the fourth describes an autoscaling policy - three other real objects in the same chain, each of which people name when they mean this one.

Practice about 15 minutes, with paper

Practice 1working

A media transcoder is being moved onto OCI. Today it runs sixty reclaimable workers that a scaling group replaces automatically, behind a load balancer, growing on queue depth and shrinking overnight. Cost is the reason the workers are reclaimable.

Rebuild it on OCI in three ways, and say what each one gives up: one that keeps the pool, one that keeps the discount, and one that keeps both.

Hint

Start from the object that refuses, not from the requirement. Then ask, for each of the three answers, which link in the chain has been replaced by something else.

Show the worked solution
  1. Name the refusal. Preemptible instances cannot enter an instance configuration, and a pool is built from a configuration. So no single object gives a discounted, self-replacing pool.
  2. Keep the pool. Build the instance configuration with ordinary on-demand instances, put them in a pool, attach the load balancer, and drive the count from a metric on queue depth. Everything works and the discount is gone - this is the version that costs money.
  3. Keep the discount. Launch preemptible instances directly from your own controller, react to the two-minute preemption event yourself, and register instances with the load balancer as they come up. The discount survives and the platform's replacement behaviour does not - this is the version that costs engineering.
  4. Keep both. Move the workers onto a Kubernetes node pool, which does support preemptible capacity, and let the cluster handle replacement and draining. Both requirements survive and the cost is a new runtime to operate - which is the subject of the next module.

Sanity check. Each of the three answers should give up exactly one thing, and the third should be the only one that changes the runtime rather than the fleet. If any answer kept the discount inside an instance pool, the refusal in step one was not applied.

Your teacher. Ask an agent to write the instance configuration for a fleet you actually run, then to try to make it preemptible. Reading the refusal at the object where it happens is worth more than reading it here, because that is where you will meet it again.
