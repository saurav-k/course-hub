The migration path forks on one question: may the source stop

working 10 min Capability area databases, matrix rows db-migration-service, change-data-capture and database-fleet-management.

The one-minute version

  • The Database Migration service assesses a source, guides the schema conversion and runs the move, for Oracle and non-Oracle sources alike.
  • It offers two paths. The offline one uses Data Pump and the online one uses GoldenGate underneath, and the choice between them is whether the source may stop accepting writes.
  • GoldenGate is also a service in its own right: managed real-time change data capture across heterogeneous databases and into big-data targets.
  • The name is a trap. The older Classic GoldenGate Cloud Service has reached end of life and the OCI-native GoldenGate is the current one, so older tutorials configure a product that is gone.
  • Database Management is the fleet view: one console covering Autonomous, Base Database, Exadata and external on-premises databases through an agent.

The mental model: one question splits the two paths

The Database Migration service covers assessment, schema conversion guidance and the move itself, for Oracle and non-Oracle sources, whether those sit on premises or in another cloud. Its offline path is the Data Pump one; the online path runs GoldenGate underneath, and there is also a Zero-Downtime Migration route.

The mechanism: what the online path is actually doing

OCI GoldenGate is also worth knowing outside a migration. It is a managed real-time change data capture platform across heterogeneous databases, and it streams into big-data targets, which makes it the bridge between this module and the analytics pipelines of module 06.

The name collides with a retired product. Older material describes the Classic GoldenGate Cloud Service, which has reached end of life and is listed on Oracle's Service Change Announcements page. The OCI-native GoldenGate above is the current service. This is lesson 0103's retired-service trap in its most confusing form, because both products carry the same name and only one of them has a live documentation set.

The mechanism: one view across an estate that is not all in the cloud

The reframing A migration is two projects wearing one name. Moving the bytes is the part the service automates. Moving every application, job and dashboard that holds a connection string is the part it does not, and that second project is what decides whether an online path was worth its extra setup.

The trade-off: the online path buys uptime with complexity

The offline path is one export and one import. It has few moving parts, it either worked or it did not, and its cost is an outage that lasts as long as the copy. For a database that is idle overnight, that is the right answer and the online path is over-engineering.

The online path keeps the source serving throughout and shrinks the outage to the cutover moment. What it adds is a running replication pipeline to configure, monitor and eventually shut down, plus a period during which two databases both believe they are current. That period is where migrations go wrong, and it is the reason the cutover is planned rather than improvised.

Check yourself

Retrieval practice

Answer from memory before revealing.

Which tool sits underneath the online path of the Database Migration service?
GoldenGate is the documented engine of the online path. The second names the offline path, which is the same service taking the other fork. The third and fourth are storage mechanisms from module 04 and neither understands a transaction.
A source database can pause writes for a whole weekend. Which path fits?
The fork is whether the source may stop, and this one may, so the simpler offline path is the right answer. The first picks capability over fit. The second invents a constraint. The fourth misreads a planned write pause as an outage of the whole system.
Which databases does Database Management cover in one fleet view?
Its coverage spans the Oracle Database services plus external databases reached through a management agent. The first invents a boundary. The second understates it. The third overstates it: MySQL HeatWave and PostgreSQL have their own narrower views instead.

Practice about 15 minutes, with paper

Practice 1working

An estate holds three Oracle Databases on premises. The first is a nightly batch warehouse that nobody touches between midnight and six. The second is a payments ledger that must accept writes at every hour of every day. The third is a retired application's database that is read once a quarter by an auditor. The team wants all three on OCI and wants one place to watch them from during the move.

Choose a path for each database, say what the outage looks like in each case, and name what watches all three while some are still on premises.

Hint

Ask the fork question of each database separately: for how long may this one stop accepting writes. Then remember that the fleet view has a path to databases that have not moved yet.

Show the worked solution
  1. The batch warehouse. It has a six-hour window in which nobody writes, so the offline Data Pump path fits and the outage is invisible because it lands inside a window that was already quiet.
  2. The payments ledger. It may never stop, so the online path with GoldenGate underneath, and the outage shrinks to the cutover moment rather than the length of the copy.
  3. The auditor's database. It is read once a quarter, so the offline path again, and the outage is whatever the copy takes, scheduled between two audits.
  4. Watching all three during the move. Database Management, with the management agent reaching the two that are still on premises, so the fleet view is complete before the migration finishes rather than after.

Sanity check. Only one of the three databases should have earned the online path. If two or three did, check whether you asked the fork question of each database or answered it once for the estate.

Your teacher. Ask an agent to list, for a database you are about to move, every distinct client that has opened a connection to it recently. That list is the real migration plan, and it is almost always longer than the one the project has written down.
