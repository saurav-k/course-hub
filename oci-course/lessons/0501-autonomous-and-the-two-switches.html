One service, four workload types, and two autoscale switches that ship opposite

working 11 min Capability area databases, matrix rows relational-serverless and data-warehouse.

The one-minute version

  • Autonomous Database is one service selected by workload type: Transaction Processing, Lakehouse, JSON and APEX. The type shapes the defaults, not the product you buy.
  • Billing is in ECPUs, and Oracle recommends the ECPU model over the older processor model.
  • Compute autoscaling is on by default and lets the database bill up to three times its provisioned ECPU count.
  • Storage autoscaling is off by default. The two switches ship in opposite positions, which is the single most surprising thing on this page.
  • Database clients can authenticate with IAM tokens instead of passwords, and APEX is built into the service.

The mental model: the workload type is a preset, not a product

The billing summary is the page that names those four types and states the ECPU model. The Lakehouse type is the one formerly known as Autonomous Data Warehouse, and its defining trick is the external table: a table whose rows live as files in Object Storage and are queried in place, which is the lakehouse pattern module 06 returns to.

The mechanism: the two switches, and which way each one points

The auto scaling documentation carries both defaults, and they point opposite ways: compute autoscaling on, storage autoscaling off.

The reframing A self-driving database still has a steering wheel, and these two switches are it. The service name promises that you will not have to tune an index. It does not promise that a default chosen for someone else's workload is right for yours.

The trade-off: what you gain by leaving both defaults alone

Leaving compute autoscaling on buys headroom for a spike with no operator in the loop, and that is genuinely what most transactional workloads want. Turning it off caps the bill and hands the spike back to the application as slow queries. Neither is wrong; the mistake is only ever discovering which one you chose from an invoice.

Leaving storage autoscaling off caps the storage bill in exactly the same way, and its cost is the one an on-call engineer meets at three in the morning. Turning it on trades that outage for a bill nobody approved. Say which of the two you prefer before the database exists.

Authentication is the other setting worth deciding early. Autonomous Database can accept IAM database tokens so that a client authenticates with its OCI identity rather than a database password. Retrofitting that onto an application that has been shipping a password in a connection string for a year is a far larger change than enabling it at creation, because every client, job and dashboard has to move at once.

Check yourself

Retrieval practice

Answer from memory before revealing.

Which pair of defaults does an Autonomous Database start with?
Compute is on and storage is off, which is the asymmetry the page is built around. The first and fourth both assume the two switches agree with each other. The third has them exactly the wrong way round, which is the answer a reader gives who remembers there is an asymmetry but not its direction.
A database is provisioned at eight ECPUs with the defaults untouched. What is the compute ceiling?
The documented multiplier is three, so eight provisioned allows twenty-four. The first is the answer if you believe autoscaling is off. The second and third are plausible multipliers that the documentation does not state, and picking one of them is guessing at a number rather than reading it.
What actually happens when a database with the default settings fills its storage?
Storage autoscaling is off, so nothing happens automatically and a human has to act. The first describes the compute switch applied to the wrong resource. The second invents a one-shot behaviour. The fourth is the most tempting: the switch that is on has nothing to do with disk space.

Practice about 15 minutes, with paper

Practice 1working

A reporting database is provisioned at twelve ECPUs with both autoscale switches left at their defaults. It is idle for twenty-two hours a day and runs a heavy batch for two hours each night, during which it would happily use every ECPU it can reach. Its data grows steadily and will pass the reserved storage in a few months.

Work out the highest ECPU count the database can be billed for during the batch, then say which of the two switches this workload should have moved and why the other one should be left alone.

Hint

Apply the documented multiplier to the provisioned count first. Then ask, for each switch separately, whether its default behaviour matches what this particular workload wants to happen.

Show the worked solution
  1. Take the provisioned count. Twelve ECPUs is what was asked for, and that is the floor.
  2. Apply the documented multiplier. Compute autoscaling allows up to three times the provisioned count, so 12 × 3 = 36 ECPUs during the batch.
  3. Judge the compute switch. A batch that wants every ECPU it can get is precisely the case the default was designed for, and the two-hour window bounds the exposure. Leave it on.
  4. Judge the storage switch. Data that grows steadily past the reserved storage will stop the database on a night nobody is watching. This is the switch to move, and moving it converts a future outage into a gradual bill.

Sanity check. The ceiling must be exactly three times the provisioned figure, so 36 and not 24 or 48. And the switch you moved should be the one whose default failure mode is an outage rather than a cost, because this workload has already told you it is willing to pay for the batch.

Your teacher. Ask an agent for the provisioned ECPU count and the autoscaling settings of every Autonomous Database in a tenancy, then multiply each provisioned count by three. That column is the tenancy's real compute exposure, and it is usually the first time anyone has seen it written down.
