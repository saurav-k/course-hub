Module 09 · Governance, tenancy and cost · Lesson 0902

A tag is not a label here, it is the reporting dimension and sometimes the permission

working 10 min Capability area org-tenancy, matrix row resource-tagging.

The one-minute version

  • Two kinds exist. A free-form tag is a loose key and value. A defined tag lives in a namespace, can restrict its values to a list, and can be given a default.
  • The budget per resource is 10 free-form and 64 defined tags, within a total size of five kilobytes.
  • Tags on a compartment inherit to the resources inside it for cost reporting, unless a resource overrides them.
  • A tag variable such as the calling principal's name resolves at creation, so ownership can be recorded without anyone typing it.
  • A policy condition can read a tag, so a tag is sometimes an access control input as well as a reporting dimension.

The mental model: two kinds, one of them governed

The mechanism: the per-resource budget

The mechanism: a resource that tags itself

The reframing Design tags as the columns of a report you will have to produce, then work backwards to who supplies each one. A column that a human must fill in gets a default or a variable; a column with a fixed set of legal answers gets a value list; a column nothing will ever query does not need to exist.
Inheritance is narrower than it sounds and the distinction matters. Compartment tags flow down to the resources inside for cost reporting purposes. Access control does not inherit in the same way: a policy condition reading a tag is evaluated against the request and its target, so a tag used for attribution and a tag used for authorisation should be thought about separately even when they carry the same name.

The trade-off: governed tags cost coordination

A defined tag needs a namespace, and a namespace is a shared object that somebody owns. Value lists have to be maintained as the organisation changes. That is real overhead, and it is the reason teams reach for free-form tags, which need no agreement at all.

The overhead buys the only thing that makes tag-based reporting work: consistency. Two teams writing the same concept as different free-form values produce two columns in the bill, and nothing detects it. A value list makes that mistake impossible at the moment it would have been made.

Retrieval practice

Answer from memory before revealing.

Which tag kind can restrict its values and be applied automatically?
Namespaces, value lists, defaults and variables belong to defined tags. The second and third extend those features to the loose kind, which has none of them. The fourth denies the default mechanism outright.
What do compartment tags do for the resources created inside that compartment?
Compartment tags inherit downward for cost reporting unless overridden. The first denies inheritance. The second confuses attribution with authorisation, which the page separates deliberately. The fourth describes a guardrail from lesson 0900.
How many defined tags may one resource carry?
The documented allowance is sixty-four defined tags within five kilobytes. The first uses the free-form figure. The second invents a relationship between the count and the size. The third drops the count limit and keeps only the size one.

Practice about 15 minutes, with paper

Practice 1working

Finance wants the monthly bill broken down by business unit, by environment, and by the person who created each resource. Business units are a fixed list of six. Environments are production, staging and development. Creators are whoever happened to run the command. Today the tenancy has some resources tagged with a free-form key spelled three different ways, and many with nothing at all.

Design the tag scheme, say for each of the three dimensions how a value gets there, and name what you would do about the resources that already exist.

Hint

Take the three dimensions in turn and ask who knows the answer at the moment a resource is created. One is known by the compartment, one is a fixed list, and one is known by the platform itself.

Show the worked solution
  1. One namespace. Create a defined tag namespace to hold all three keys, so the scheme is a single governed object rather than three conventions.
  2. Business unit. A defined tag with a value list of the six units, and a tag default on each business unit's compartment so resources arrive carrying the right one. Nobody types it and no seventh value can be invented.
  3. Environment. A defined tag with a value list of the three environments, again defaulted per compartment where the compartment layout follows environments. Where it does not, the value list at least keeps the spelling consistent.
  4. Creator. A defined tag whose default uses a tag variable resolving to the calling principal's name. This is the dimension a human would always forget and the only one the platform can supply on its own.
  5. The existing resources. Search for resources missing the namespace, tag them in bulk, and stop writing the three spellings by removing the free-form key from templates. Nothing enforces a free-form value, so the fix is to stop producing new ones as well as to correct the old ones.

Sanity check. All three dimensions should end up as defined tags in one namespace, and only one of them should rely on a human at any point. If the creator dimension involved a person typing their own name, look again at the variable mechanism.

Your teacher. Ask an agent for the distinct values of each free-form tag key in a tenancy. The list of near-duplicates is the cost of not having used a value list, and it is the shortest possible argument for a defined tag namespace.
