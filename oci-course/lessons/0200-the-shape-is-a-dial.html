One dial sets the processors, the memory, the bandwidth and the network cards

working 11 min Capability area compute-iaas, matrix row vm-instances.

The one-minute version

  • OCI sizes a machine with a flexible shape: you set the processor count and the memory yourself instead of picking a named size from a catalogue.
  • The unit is the OCPU, a physical core with multithreading, which is about two x86 virtual processors. Every size carried in from elsewhere has to be halved.
  • The dial is coupled. Network bandwidth and the number of virtual network cards scale with the OCPU count rather than being chosen beside it.
  • Bandwidth climbs at about one gigabit per second per OCPU and then stops at a ceiling the shape family fixes, not the workload.
  • So on OCI you cannot buy a small machine with a big pipe. A network-bound workload is sized by its bandwidth and becomes a fleet.

The mental model: one input, four outputs

The unit is the load-bearing detail. Oracle's own documentation states that an OCPU is a physical core with simultaneous multithreading, equivalent to about two x86 virtual processors, on its supported shapes reference. So a machine described elsewhere as sixteen processors is an eight-OCPU machine here, and a price compared without that conversion is wrong by roughly a factor of two in whichever direction is least convenient.

Memory is the second dial and it moves within a published ratio. The Compute Shapes reference records 64 GB of memory per OCPU for the flexible families, which is the number that decides whether a memory-heavy workload has to buy processors it will not use.

The reframing A flexible shape is not "a catalogue with more entries". It is a coupling: the processor number you type is also the bandwidth number and the network-card number. Sizing on OCI means asking which of the four outputs is actually binding, and typing the OCPU count that satisfies that one.

The mechanism: what the coupling actually looks like

The families, and what each one is for

FamilyWhat it isReach for it when
E4, E5, E6 flexibleAMD flexible shapes, the general workhorseNothing else applies. E6 is the family with the higher bandwidth ceiling
Standard flexibleIntel flexible shapesThe workload is licensed or tuned for Intel
Ampere A-seriesArm flexible shapesThe stack builds for Arm and you want the price per core
DenseIOShapes carrying local NVMeThe workload wants attached fast disk more than durability
BurstableBilled against a baseline fraction of the OCPUThe average load is low and the peaks are short
GPUVirtual machines with GPUs, and bare metal superclustersThe work is model training or model serving

GPU capacity is two products under one word, and the last row hides the difference. Virtual machine GPU shapes cap at four GPUs per machine, which suits serving and small training runs. Large-scale training is served instead by superclusters: bare metal servers on a non-blocking remote-direct-memory-access fabric, carrying NVIDIA and AMD accelerator parts. Choosing between them is choosing between a machine and a cluster, and the shape name is the only place that distinction appears.

Burstable instances are the one row that changes how the bill is computed rather than what the machine is: you pay for a baseline share of each OCPU and the instance may rise above it. They also carry their own exclusion list, and that list is where they meet the next lesson but one.

The bandwidth ceiling is the trap that survives review, because nothing about it is visible in a sizing spreadsheet. A workload moved from a cloud where the network is chosen separately arrives with a four-OCPU shape and a forty-gigabit expectation, deploys successfully, and is slow. The instance is correct, the pipe is about four gigabits, and no error is raised anywhere.

Check yourself

Retrieval practice

Answer from memory before revealing.

A design document specifies 16 processors per worker. What is the equivalent OCI request?
An OCPU is a physical core with multithreading, so it is worth roughly two x86 virtual processors and sixteen of those is about eight OCPUs. The first option inverts the conversion and buys twice the machine. The third skips it entirely, which is the most common version of this error, and the fourth invents a unit OCI does not use.
A workload needs 40 Gbps of network throughput on one machine and very little processing. What does the OCI shape model force?
Bandwidth rises at roughly one gigabit per second per OCPU, so forty gigabits means buying about forty OCPUs whether or not they are used. The first option describes a purchase that does not exist here. The second changes who shares the host, not the pipe. The third names a real shape family but not the reason - the coupling is what decides this.
How many virtual network cards does a one-OCPU flexible shape have available?
The flexible shapes start at two cards for the first OCPU and then add one per OCPU, capped at twenty-four. The second option would leave a small instance with no room for a second interface at all, which is the case the rule exists to cover. The third and fourth would reach the cap far sooner than the documented tables do.

Practice about 15 minutes, with paper

Practice 1working

A packet-inspection appliance is being moved onto OCI. It needs four network interfaces, 24 processors as measured on an x86 hypervisor, 128 GB of memory, and 20 Gbps of aggregate throughput.

Work out the OCPU count each requirement implies on its own, say which one binds, and state what the other three then get for free.

Hint

Convert the processor requirement first, then turn each of the other three requirements into an OCPU number using the published rule for that output. The binding requirement is simply the largest of the four.

Show the worked solution
  1. Convert the processors. 24 x86 virtual processors divided by about 2 gives 12 OCPUs.
  2. Turn the interfaces into OCPUs. Two cards come with the first OCPU and one per OCPU after that, so four cards need 3 OCPUs: one gives two cards, the second gives three, the third gives four.
  3. Turn the memory into OCPUs. At 64 GB per OCPU, 128 GB needs at least 2 OCPUs. Memory is nowhere near binding here.
  4. Turn the throughput into OCPUs. At about 1 Gbps per OCPU, 20 Gbps needs about 20 OCPUs.
  5. Pick the binding one and read off the rest. The largest is throughput at 20 OCPUs. Ordering 20 OCPUs then yields 20 network cards against the four needed, 20 processor-equivalents beyond the twelve needed, and memory capacity far beyond 128 GB - so only the memory figure still has to be typed in, because it is the one output that is not implied.

Sanity check. The binding number should be the throughput one, and it should be larger than the processor number. If the processor requirement came out largest, the conversion was applied in the wrong direction and the machine is twice the size it needs to be.

Your teacher. Take one instance you actually run and ask an agent for its OCPU count, then for the bandwidth and network-card count that follow from it. If any of the three surprises you, the coupling on this page is doing work in your estate that nobody wrote down.

Primary source to go deeper

Read Compute Shapes and stay in the per-shape tables rather than the prose. Those tables are where the bandwidth ceilings, the network-card rules and the family memory ratios are actually stated, and they are the page an OCI capacity argument is settled from.
