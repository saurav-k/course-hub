Module 01 · The lay of the land · Lesson 0103

OCI answers "does it have that" three different ways, and only one of them is no

foundation 10 min The whole capability taxonomy in outline, and the reading habit the rest of this course depends on.

The one-minute version

  • OCI's map has the same layers as any cloud. What differs is where a capability is packaged, and that is what a service list will not tell you.
  • Three answers, not two. A capability is a product, or it is delivered inside another product, or it is genuinely absent - and confusing the middle answer for the last is the most expensive mistake a reader can make here.
  • Five OCI words mean something else on other clouds. The two that cost money are OCPU, which is about two x86 virtual processors, and availability domain, which is not always present in threes.
  • There is no role object. Permissions attach to groups through policy statements, so a role-shaped design has to be re-modelled rather than translated.
  • Retired OCI services still rank well in search results. The service change announcements page is the authority on what is current, and checking it is a habit rather than an occasional task.

The mental model: the map has the ordinary layers

The mechanism: three answers, and how to tell which one you have

The right-hand branch is real and this course does not soften it. There is no native remote-access client VPN, and Oracle's own guidance points at the Bastion service for brokered administrative sessions or at marketplace appliances for network-level access. There is no bucket website endpoint, and the documented pattern is Object Storage behind API Gateway. There is no generally available first-party workflow orchestrator with product documentation, and the current answers are Oracle Integration process automation or chains built from Functions and the Events service.

The reframing "No product" and "no capability" are different findings and they lead to different designs. The first tells you to look one service further out. The second tells you to build, buy or move. Reading the first as the second is the single most common serious error in cross-cloud writing about OCI, and it is the error this course is built to avoid.

The five words that mean something else here

The wordWhat a reader assumesWhat OCI means
OCPUA virtual processorA physical core with multithreading, so about two x86 virtual processors
Availability domainOne of three zones, alwaysA data-centre boundary that many regions have only one of
CompartmentA separate account or projectA global folder inside one tenancy, sharing its bill and identity store
RoleA grantable permission bundleNothing. Permissions attach to groups by policy statement
StreamingThe one messaging serviceOne of several, beside Queue, Notifications, Events and Connector Hub

The first row is the one that changes a number. Because one OCPU is roughly two x86 virtual processors, a size or a price carried across from another cloud without converting is out by a factor of two, in whichever direction hurts more at the time. Module 02 opens on exactly this.

The last row is the one that changes a design. Five services on OCI all move messages, and the differences between a queue, a stream, a notification topic, an event rule and a telemetry connector are real rather than cosmetic. Module 12 is where this course separates them properly.

The trap: a retired service outlives its documentation

The list of names currently in the outer states is longer than most readers expect, and it includes OCI Service Mesh, whose documentation now names open-source Istio on Kubernetes as the replacement. Rather than carry a list that ages, this course points at the authority: Oracle's Service Change Announcements page is where deprecations and end-of-life notices are published, and reading it is the habit that keeps a design current.

The same trap has a quieter form. A capability can be present but packaged with a surprising default: Autonomous AI Database ships with compute auto scaling on and storage auto scaling off, so an untouched database can bill above its provisioned size while refusing to grow its storage. Defaults are part of the map, and this course names them where the verified sources do.

Check yourself

Retrieval practice

Answer from memory before revealing.

A search for an OCI certificate authority product returns nothing. What is the correct conclusion?
The capability is delivered inside the Certificates service, which runs a managed internal authority beside imported third-party certificates - the middle branch of the three answers. The first is the false absence this page exists to prevent, the second invents a retirement, and the third pushes a first-party capability out to a partner.
A design document copied from another cloud sizes each worker at 8 processors. What must be checked before it is priced on OCI?
One OCPU is a physical core with multithreading, about two x86 virtual processors, so eight of one is not eight of the other and the price differs by roughly a factor of two. The other three name real OCI facts that are true regardless of the answer: fault domains always come in threes, compartments are always global, and confidential shapes are a separate concern.
A tutorial from a well-known site configures a current-sounding OCI service, but no page under the vendor documentation describes it. What does that pattern usually mean?
A missing documentation page is the signature of both outer states: announced but never documented, or documented once and now a retirement notice. The first two options describe plausible-sounding situations that do not remove a service from the public documentation, and the fourth would still leave a docs page under the current name.

Practice about 15 minutes, with paper

Practice 1foundation

A reviewer sends back four one-line claims about OCI written by someone porting a design from another cloud:

(a) "OCI cannot host a static website." (b) "OCI has no way to give a pod its own identity." (c) "OCI has no managed Prometheus." (d) "OCI has no way to stop a team from using a region."

Classify each as a product, delivered elsewhere, or a genuine absence, and rewrite the two that are wrong.

Hint

For each claim, ask what the person actually needs rather than what they asked for. Two of these are asking for a specific package and one is asking for an outcome that OCI reaches from a different direction entirely.

Show the worked solution
  1. Classify (a). Wrong as written. There is no bucket website endpoint, so the specific package is absent, but the outcome is documented: serve the site from Object Storage behind API Gateway. Rewrite as "OCI has no bucket website endpoint, so a static site is fronted by API Gateway for a custom domain and TLS."
  2. Classify (b). Wrong. Pod-level identity exists as OKE workload identity, where a Kubernetes service account is matched by policy. Rewrite as "OCI gives a pod its own identity through OKE workload identity, on enhanced clusters." This is the product branch, not an absence at all.
  3. Classify (c). Correct as a statement about packaging, and worth keeping. There is no managed Prometheus store; Prometheus endpoints are scraped into the Monitoring service by the management agent. Keep it, and add the substitute so it does not read as a dead end.
  4. Classify (d). Correct only if the team owns the tenancy. Inside one tenancy a compartment quota or a policy condition on region can constrain use, and above the tenancy a parent's governance rule can lock the allowed region list. The honest version names which of those applies.

Sanity check. Two of the four should have survived with an added substitute, and two should have been rewritten. If all four came out as absences, the classification collapsed the middle branch into the right-hand one, which is the failure mode this page is about.

Your teacher. Next time an agent tells you a cloud lacks something, ask it for the vendor page that says so. An absence that can only be evidenced by the lack of a search result is not yet a finding, and asking for the page is the fastest way to separate the three answers on this page.

Primary source to go deeper

Keep the Service Change Announcements page bookmarked and read it before trusting any tutorial. It is the one Oracle page that tells you which names are current, and almost every confident wrong claim about OCI would have been caught by opening it.
