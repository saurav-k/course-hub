Module 13 · AI and ML · Lesson 1302

An agent is a service like any other, so it authenticates as a resource rather than as itself

working 10 min Capability area ai-ml, matrix row agent-platform.

The one-minute version

  • Generative AI Agents is the managed platform for retrieval, query and tool-calling agents, built around knowledge bases.
  • Those knowledge bases index content held in object storage and in a search cluster, which is where the retrieval capability of the previous lesson is delivered.
  • Answers come back with citations, so a reader can see which indexed content an answer rests on.
  • Digital Assistant is the conversation layer: a chatbot builder with channels and integrations that can call agent endpoints. It is the interface, not the reasoning.
  • There is no agent identity object. An agent authenticates with a resource principal like any other service, so lesson 0802 governs what it may reach.

The mental model: three layers, and what each owns

The mechanism: a question, answered with citations

The reframing Think of a knowledge base as an index over content you already govern. The permissions on the bucket and the cluster from earlier modules still decide what may be indexed, and the agent reaches that content as a workload principal. Nothing here introduces a new access model, which is why the identity page from module 08 is the one to reread.
There is no distinct agent identity object on this platform. An agent authenticates with a resource principal, exactly like the functions of lesson 0303 and the services of lesson 0802, so what it may read is decided by a dynamic group rule and a policy statement. That is worth stating plainly because a design that expects a per-agent identity with its own permission boundary will not find one, and the caveats about principals in lesson 0802 apply here unchanged.

The mechanism: what the older product still does

The conversation layer predates the agent platform and does a different job: it holds the channels, the skills and the prebuilt integrations that put a conversation in front of a person, and it can embed in low-code applications. Positioning it as the interface rather than as the reasoning core is what keeps a design from duplicating one of them inside the other.

The trade-off: a managed agent is fast to build and opaque to tune

Creating an agent over a knowledge base is a small number of steps, and the citations make the result reviewable immediately. For a team whose alternative is building retrieval, prompting and tool-calling themselves, that is a large saving.

What a managed platform gives up is the ability to change the parts of the pipeline it owns. Where retrieval behaviour has to be tuned in ways the platform does not expose, the alternative is the components of the previous two lessons assembled directly: a vector column, a query and a model call, with the pipeline as ordinary code you can change.

How does an agent authenticate when it reaches other services?
Agents use resource principals, so lesson 0802 governs them. The first invents an identity object the inventory records as absent. The second describes delegation the platform does not perform. The third reintroduces the stored secret that principals exist to remove.
What does a knowledge base index?
Knowledge bases index object storage and search cluster content. The second invents a compartment-wide scope. The third confuses the interface layer's history with the source material. The fourth invents automatic database indexing.
What is the relationship between the two products on this page?
One is the conversation surface and the other is the reasoning and retrieval layer behind it. The first and fourth collapse two real products into one. The second gives the agent platform a channel layer it does not provide.

Practice about 15 minutes, with paper

Practice 1working

A company wants an internal assistant that answers questions from a policy library held in a bucket, and that can also look up an employee's own leave balance from a database. It must be reachable from an internal chat tool. A security reviewer asks what the assistant can read, and whether one employee can see another's balance.

Design the layers, and answer both of the reviewer's questions using the identity model this platform actually has.

Hint

Three layers, one per component in the mental model figure. Then answer the identity questions from lesson 0802 rather than from anything on this page, and be careful with the second one.

Show the worked solution
  1. The knowledge base. Index the policy library from its bucket. Answers come back with citations, so an employee can see which policy an answer rests on.
  2. The leave lookup. A tool the agent can call, reaching the database. This is a function-shaped step rather than retrieval.
  3. The chat tool. The conversation layer, using its channel integration, calling the agent endpoint behind it.
  4. What the assistant can read. Whatever a policy statement grants its resource principal. There is no agent identity object, so the answer is a dynamic group rule and the statements naming it, exactly as for any workload.
  5. Whether one employee sees another's balance. Not automatically prevented. The agent reaches the database as itself, not as the asking employee, so the design must pass the employee's identity through to the tool and have the tool filter on it. Without that step the agent holds one set of permissions for everyone.

Sanity check. The second answer should be a warning rather than a reassurance. If you concluded that per-employee filtering happens by itself, re-read which principal the agent uses when it calls the database.

Your teacher. Ask an agent which dynamic group and which policy statements govern an assistant you are about to build. That pair is the complete answer to what it can read, and writing it down before the first knowledge base is created is far easier than reconstructing it afterwards.
