Module 07 · Networking and delivery · Lesson 0702

One gateway attaches everything that is not in this network, and the rest is route distribution

working 11 min Capability area networking-core and hybrid-connectivity, matrix rows transit-hub, network-peering, site-to-site-vpn and dedicated-interconnect.

The one-minute version

  • The Dynamic Routing Gateway is a regional router that attaches networks, private circuits, virtual private network connections and cross-region peerings, each with its own route table.
  • Its route distributions and import rules are what make hub-and-spoke transit work, including steering spoke-to-spoke traffic through a firewall.
  • Local peering is the direct alternative for two networks in one region, needing one gateway per peer and non-overlapping address ranges.
  • Site-to-Site VPN terminates on the routing gateway, gives two tunnels per connection, and carries no hourly or per-byte fee.
  • FastConnect is the private circuit: cross-connect ports of 1, 10, 100 or 400 gigabits per second, billed by port hour with no data transfer charge.

The mental model: one hub, four kinds of attachment

Transit routing is the pattern built on those distributions, optionally sending traffic through a firewall appliance on the way. The alternative for two networks in one region is local peering, which needs one gateway per peer and non-overlapping address ranges, and which does not scale to many networks for exactly that reason.

The mechanism: the private circuit comes in four port sizes

The mechanism: the doors, placed against each other

The reframing Every one of these paths terminates on the same routing gateway. That means the choice of path is a procurement and bandwidth decision, not an architecture decision: the routing, the rules and the spokes are identical whichever door the traffic came through, so a design can start on a virtual private network and move to a circuit without being redrawn.

The trade-off: the hub concentrates control and concentrates risk

Route distributions on the hub are a single place to express which network may reach which, which is the whole reason enterprise designs converge on this shape. The same property means a mistake in a distribution is a mistake for every spoke at once, and that the hub is on the path for traffic that has nothing to do with it.

Two absences are worth stating precisely rather than loosely. There is no separate routing-protocol resource to configure: the inventory records the border gateway protocol speaker as embedded in the routing gateway itself, so it is configured as part of an attachment rather than as an object of its own. And there is no dedicated attachment type for a software-defined wide-area network; third-party appliances connect over an encrypted tunnel to the routing gateway, or run as instances in the hub network. Both capabilities exist, and neither has a product page of its own.

Latency figures deserve the same care. Oracle publishes no commitment for latency over any of these paths, so this course teaches the ordering rather than numbers: a dedicated circuit is materially better than a tunnel across the public internet, and how much better depends on the physical route.

Retrieval practice

Answer from memory before revealing.

What decides which routes a spoke network learns from the hub?
Each attachment carries its own route table, which is what makes per-spoke reachability expressible in one place. The first confuses filtering with routing. The second matters for overlap but does not decide learning. The fourth invents an ordering rule.
How many tunnels does one Site-to-Site VPN connection give you?
A connection provides two tunnels. The second describes a design people build on other platforms and pay for twice here. The third invents a relationship with fault domains. The fourth confuses tunnels with attachments.
Which statement about the paths from on premises is accurate?
They converge on one object, which is what lets a design change path without being redrawn. The first is the assumption that makes people build separate designs per path. The third and fourth each keep one path and exclude the other, and both are refuted by the same documentation page.

Practice about 15 minutes, with paper

Practice 1working

An organisation has three application networks in one region and a data centre that must reach all three. Two of the three application networks must never reach each other, but all three must reach a shared services network. The data centre connection starts as an encrypted tunnel and is expected to become a private circuit within the year.

Draw the design in terms of attachments and route tables, and say what changes when the tunnel is replaced by a circuit.

Hint

Count the networks that need to reach something outside themselves, and give each one an attachment. Then write down, per attachment, the list of destinations it should learn. The last question is about which of those lists mentions the door rather than the destination.

Show the worked solution
  1. One hub. A single routing gateway in the region, with four network attachments: the three application networks and the shared services network.
  2. The data centre attachment. A Site-to-Site VPN connection terminating on the same gateway, giving two tunnels for redundancy at no hourly or per-byte fee.
  3. Write the per-attachment tables. Each application attachment learns the shared services network and the on-premises ranges, and does not learn the other application networks. Shared services and the data centre learn all three.
  4. Notice what did the isolating. The two application networks are kept apart by what their attachments learn, not by any rule inside them. Nothing in their subnets had to change.
  5. The upgrade. A FastConnect circuit becomes a fifth attachment on the same gateway. The route distributions are the same statements about the same destinations, so nothing about the three application networks is touched.

Sanity check. Your design should have exactly one hub and no local peering gateways at all. If you reached for peering between the applications and shared services, count how many gateways that needs as the network count grows.

Your teacher. Ask an agent to print, for each attachment on a routing gateway, the routes that attachment currently learns. A spoke that learns another spoke's range and should not is invisible in every subnet's own configuration, and this table is the only place it shows.
