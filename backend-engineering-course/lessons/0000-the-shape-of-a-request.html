Module 01 · The shape of a request · Lesson 0000

A request is turned into a response by layers, and every framework is a skin over the same layers

foundation 10 min The whole course's map drawn once. · RFC 9110 - HTTP Semantics

The one-minute version

  • Whatever the framework, a backend is one request in, one response out, and the work between is done by a fixed set of layers.
  • The layers, in order: transport, HTTP shape, routing, your code, then back up as the response.
  • The framework is a skin that decides how many of those layers you write by hand and how many it hands you - but it never removes a layer, it only hides one.
  • Naming the layers now means every later page in this course is just one layer taken apart to see its mechanism.
  • What it costs: this page teaches no code and buys a map, and the framework-specific flags stay out until the module that owns them.

1. One request, one response

Start with the smallest true statement about any backend: a client sends a request, and the server returns a response. Everything a framework does sits between those two moments. Even at a billion requests an hour, the unit of work is still one request, and every piece of the system exists to move that one unit from client to answer and back.

That framing matters because it gives you the right instinct about size. A backend is not "a bunch of endpoints". It is a machine for turning requests into responses, and every mechanism in this course - routing, caching, a queue, a database - sits somewhere on that one path. When you can point at which layer a mechanism lives on, you can also say which layer a bug belongs to.

2. The layers are the same under every framework

Here is the fact that makes this course teachable. Python's FastAPI, Go's net/http, Node's Express, and a raw socket server do not differ by which layers exist - they differ by how many layers are hidden. Something must receive bytes, must understand them as a request, must decide which of your functions runs, and must hand you a place to read input and write output. Every framework does all four.

A framework's real contribution is deciding which of those you write. A raw socket writes all four by hand. A microframework hides transport and most of routing. A batteries-included framework hides all four and adds the ones around them (sessions, validation, background jobs). None of that removes a layer; it moves the layer from code you write to code someone else wrote. The mechanism underneath is unchanged, which is why learning it once, on the bare wires, survives any framework switch you make later.

3. What owning a layer means

Owning a layer means you can say, without reading the framework, what responsibility it carries and where its failure mode is. The transport layer is where a dropped connection lives. The HTTP shape layer is where an unparsable request or a wrong status is judged. The routing layer is where a URL maps to the wrong handler. Your code layer is where the business decision is made. When a production incident happens, the first question is always which layer the symptom lives on - and the answer is rarely "the framework is arbitrary magic", because each layer has a definable contract about what it produces and what it needs.

That is the whole reason this course starts with a map instead of a framework. Every later module names a layer before it names a tool, so the reader can place a mechanism in a running system even before the later modules exist. The rest of Module 01 exists only to make the map stick.

The failure this framing can cause: mistaking "the framework does this for me" for "this layer does not exist". When the framework's caching silently serves stale data, the layer is still there - the mechanism was hidden, and a hidden default is how a subtle bug ships. Owning the layer means you know what the default is.

Which statement is true of every backend, framework included?
Going down, each layer produces what the next consumes; going back up, the response re-crosses the same layers in reverse. The options that say a layer disappears are the strong distractors: a framework hides a layer, never removes it.
A cached response goes stale. Which layer owns the symptom?
Staleness is an invalidation failure on the cache layer; the other options name layers that exist, but each answers a different question: delivery, mapping and authorship rather than lifetime.
