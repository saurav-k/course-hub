The framework is a skin

The framework is a skin; the layers underneath are the same in every backend.

The connected route from one request to a horizontally scaled fleet, taught as a design you can reason about. Thirteen modules, one idea per page, each mechanism owned rather than waved at. Prose and diagrams are re-authored from first principles, following the arc of the open Backend from First Principles field manual.

Start with the shape of a request, keep the Glossary open in a tab, and read Inside AWS when a mechanism's deployment is the point.

HTTP is the language

6 lessons
Lesson 0200
A request is a method, a target and headers
The frame every framework fills in rather than replaces: three parts that are always present, a body that is optional, and a target that names a resource rather than a file.
foundation8 min
Lesson 0201
Methods are verbs with guarantees
Safe, idempotent and cacheable are promises the whole network reads without asking you, and they are what makes a retry free or dangerous.
foundation7 min
Lesson 0202
Status codes are three families with one job each
The first digit is the contract: 1xx to 3xx say where the request stands, 4xx blames the request, 5xx blames the server, and every client must understand the class.
foundation7 min
Lesson 0203
Headers carry what the body cannot
Four families of field settle everything a body cannot say about itself: what it is, which version you wanted, whether your copy is current, and who is asking.
working7 min
Lesson 0204
Caching is a contract between two clocks
A hit is one comparison: the lifetime the origin published against the age the cache counted. Validators are what make the re-check cost headers instead of a body.
working7 min
Lesson 0205
CORS is the browser enforcing the server's own policy
The server states a policy and enforces nothing. The preflight asks permission before the real request, and a CORS error is a reading refused rather than a request blocked.
working7 min
03

Routing

6 lessons
Lesson 0300
A route is a pattern and a method
The pair a router registers: one method token and one path pattern. Either half on its own answers a different question, and a router holding only the path can never tell a missing resource from a wrong verb.
foundation8 min
Lesson 0301
Path parameters and query strings say different things
RFC 3986 separates the two by hierarchy alone, and both identify the resource. Which half a value goes in decides whether the router, a cache and your authorisation rules can see it at all.
foundation8 min
Lesson 0302
Matching is a tree, not a list of ifs
Patterns are compiled once into a tree keyed on host, then method, then path segments, so a match costs one lookup per segment however many routes are registered. Precedence, conflicts and backtracking all fall out of it.
working9 min
Lesson 0303
Middleware is a chain, and order is the design
A middleware wraps the handler rather than queueing in front of it, so one registration order gives two orders: first in, last out. A link that never calls the next one has ended the request there.
working8 min
Lesson 0304
404 and 405 are routing verdicts
No handler ran, so no handler can answer. Only the route table knows whether a target has no resource at all or a real one that refuses this verb, and RFC 9110 makes the Allow field a MUST on the second.
working8 min
Lesson 0305
Mounting composes routers
A router is itself a handler, so one can hold another under a prefix. The prefix is stripped before the inner router matches, and kept aside so the inner router still knows where it lives.
working8 min
04

Serialization and contracts

6 lessons
Lesson 0400
A wire format is a contract you can break silently
Two independently deployed programs agree here, and the format checks only its own grammar - so the break arrives as a wrong value rather than as a compiler error.
foundation8 min
Lesson 0401
JSON is text and text has no types
Six kinds of value, and not one of them is a date, a decimal or a 64-bit integer. Every domain type you send is a convention you have to state and keep.
foundation9 min
Lesson 0402
Schema-first makes the contract the source
A .proto file compiles into code both ends import, so the contract becomes a build artefact - and the field number, never the name, is what travels.
working8 min
Lesson 0403
Validation belongs at the boundary, once
Parse untrusted input into a trusted type at the edge. A re-check deeper in the service is a symptom: it says the value arrived carrying no guarantee.
working8 min
Lesson 0404
Content negotiation picks the representation
One resource, many renderings. Accept is a wish about the response and Content-Type is a fact about this body, and the two refusals are 406 and 415.
working8 min
Lesson 0405
Compatibility is a rule, not a hope
Adding a field is safe and reusing a number is corruption, and renaming is free on the binary wire and breaking in JSON, because the encodings key on different things.
working9 min
05

The layered service

6 lessons
Lesson 0500
A layer is a boundary you can test across
A directory named services is a claim about intent. A layer is a contract you can substitute across, and the substitution is the only property that cannot degrade quietly.
working9 min
Lesson 0501
The controller translates transport into intent
Two translations and no third thing: a request becomes a call with no HTTP in it, and a named outcome becomes a status the client already knows how to read.
working8 min
Lesson 0502
The service layer owns the decision
A rule that neither the transport above nor the store below can reach is a rule you can move to a second transport and reach from a test that needs neither.
working8 min
Lesson 0503
The repository hides the store behind a contract
The methods follow the loads and saves the domain needs, never the tables. The query language, the driver errors and the schema all stop at the contract's edge.
working8 min
Lesson 0504
Request context carries what every layer needs
A deadline, a cancellation signal, an identity and a trace id belong to one request. Threading them explicitly beats a global whose lifetime is the whole process.
working9 min
Lesson 0505
Dependency direction is the design
The architecture is the import graph. An inner layer never names an outer one, and one file at the edge decides which concrete things are really there.
working8 min
06

API design

6 lessons
Lesson 0600
An API is a promise with a cost of breaking
You cannot recall a published shape, because the callers are not enumerable and do not deploy when you do. Design is choosing what to promise, and saying what you did not.
foundation8 min
Lesson 0601
Resources are nouns and the method is the verb
HTTP already separates identity from intent, and every cache and proxy reads the method without asking. A verb in the path hands all of that back for nothing.
foundation8 min
Lesson 0602
Collections need pagination, not a limit
Offset counts rows and a cursor anchors on values, so one concurrent write repeats or skips items under the first and neither under the second.
working9 min
Lesson 0603
An error body is part of the contract
The status code says which family the failure is in, which is all an intermediary needs. A problem document says which failure it is, which is what the caller branches on.
working8 min
Lesson 0604
Versioning is choosing who pays to change
A break costs somebody a piece of work, and a scheme only decides whose calendar it lands in. Pick the bill you can still afford in three years.
working9 min
Lesson 0605
Idempotency keys make retries safe
A client cannot tell a lost request from a lost response. Recognition of the repeat is a stored key claimed before the work, not a hope that the first attempt missed.
working9 min
07

Auth and security

7 lessons
Lesson 0700
Authentication answers who, authorization answers what
Identity is established once, at a price you make deliberately high. Permission is decided again on every request, because the login said nothing about this resource.
foundation8 min
Lesson 0701
A session is server state behind an opaque id
The cookie carries a name and nothing else, so logout is a real deletion - and the store every instance must reach is the first genuine dent in statelessness.
foundation8 min
Lesson 0702
A token moves the state to the client
A signed token removes the lookup and removes revocation with it. Verification is an ordered checklist, and token lifetime is how long a withdrawn permission keeps working.
working9 min
Lesson 0703
OAuth delegates access without sharing the password
A password has no scope, no expiry and no identity of its own. Four roles, an authorization code bound by PKCE, and an access token that is not proof of who anybody is.
working9 min
Lesson 0704
Injection is data arriving where code is expected
Concatenation destroys the boundary before the parser runs. Binding restores it by sending the statement and the value on separate channels, and identifiers need an allow-list.
working8 min
Lesson 0705
XSS is code injected into someone else's browser
Injected script has your origin, so the same-origin policy protects the attacker. Encoding is chosen by context, and a strict CSP is the layer for the site you missed.
working9 min
Lesson 0706
CSRF is the server trusting the browser
The cookie is attached whoever wrote the request, so presence proves nothing about intent. A synchroniser token is a secret the other site cannot read - SameSite is not one.
working8 min

Async work and search

7 lessons
Lesson 1000
Async work is work that outlives the response
A response promises a result, and some work finishes long after the caller has gone. HTTP has a word for the smaller promise, and it obliges you to build a second resource.
foundation10 min
Lesson 1001
A queue delivers at least once
The broker hands out a lease and takes it back when nothing acknowledges. Where the acknowledgement sits is the entire delivery guarantee, and exactly-once is not on offer.
working10 min
Lesson 1002
A failed job is a policy you wrote in advance
Which errors, how far apart, how many, and where the job goes when they run out. Backoff sets the ceiling on the wait and only jitter relieves the contention.
working10 min
Lesson 1003
A consumer must be idempotent
The lease and the retry policy manufacture duplicates on purpose, so the consumer absorbs them: rewrite the effect, or claim a key in the same transaction as the work.
working10 min
Lesson 1004
Enqueue and commit are two writes
No transaction spans a database and a broker, so a crash in the gap loses one of them silently. The outbox makes it one write and gives the second system its own reader.
working10 min
Lesson 1005
Search is an inverted index, not a scan
A pattern match asks every document the same question. An index has answered the opposite one already, which is why the lookup does not grow with the corpus.
working10 min
Lesson 1006
Relevance is a ranking function
Matching is exact and ranking is a judgement. BM25 is legible: rarer helps, more helps with diminishing returns, and longer hurts by exactly as much as you allow.
working12 min
