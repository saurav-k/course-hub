Glossary

206 terms Every term this course introduces, linked to the page that develops it. Print it and cover the right-hand column.

TermWhat it means here
Accepted, 202 The status code for a request taken but not completed. Intentionally noncommittal, and it owes the caller a status monitor because HTTP cannot re-send a status code from an asynchronous operation.
Access token A string representing an authorization issued to a client, scoped and expiring. It is addressed to the resource server, so holding one is not evidence about who the end user is.
Additive-only evolution Promising that the published surface only ever grows, so no caller ever migrates. A real versioning scheme with a real price, paid at design time: every field you regret stays.
Age The time since a response was generated by, or last validated with, the origin server. Not the time since this cache stored it, which is why a response can arrive already stale.
Algorithm confusion Letting a token's own alg header choose the verification primitive. Setting it to none removes the check, and switching RS256 to HS256 turns the published public key into the shared secret.
Allow field The response field listing the methods a target resource currently supports. RFC 9110 makes it a MUST on a 405, permits it anywhere else, allows an empty value, and forbids a proxy from modifying it.
Ambiguous failure A timeout that a client cannot resolve: the request may never have arrived, or the response may have been lost. The two histories need opposite actions and produce identical evidence.
At-least-once delivery The guarantee a broker gives when it requeues anything it was not told was finished: nothing is lost and a message may arrive twice. It is not a setting to turn off - it is what an acknowledgement boundary implies, so the handler has to survive a repeat.
At-most-once delivery The opposite bargain: messages may be lost but are never redelivered. In a log you choose it by committing the offset before doing the work, so a crash steps over the record instead of repeating it.
Atomicity The promise that from the point of view of other transactions a group of writes either happens completely or not at all. A claim about what can be observed, not about how many instructions the engine used.
Authentication Establishing who is calling. Deliberately expensive, so it is done once and exchanged for a cheap credential the caller re-presents.
Authorization Deciding whether this caller may do this thing to this resource. Cheap and re-decided on every request, because the login said nothing about the resource now in front of you.
Authorization code grant The OAuth flow where the user authenticates at the authorization server and the client receives a short-lived code it redeems for a token, so the client never sees a password and the token never crosses the redirect.
B-tree The default index structure: a balanced tree with a large branching factor, holding indexed values in sorted order beside a pointer to each row. Serves equality, ranges, sorted retrieval and a pattern anchored at the start.
Backtracking The walk undoing a step when the literal branch it took first turns out to be a dead end. The cost of trying the more specific pattern first, and bounded by the depth of the path.
Backward compatibility New code making sense of data written by the version already deployed, including everything already sitting in a queue, a log or a table. One of the two directions a rolling deploy exercises at once.
Bearer credential A credential where possession is the whole of the proof, with nothing tying it to the party it was issued to. Every log line and error report that captures one is holding a working credential.
BM25 The ranking function Lucene and Elasticsearch use by default. A term contributes more when it is rare, more when it repeats but with a ceiling, and less when the document is long.
Boundary parsing A check at the edge that returns a value of a different type rather than a boolean, so the knowledge it earned travels with the value and cannot be lost by the next function.
Breaking change A change that makes a call correct yesterday fail today. Removing or renaming is the obvious form - narrowing what an existing field accepts is the form that looks like a bug fix.
Cache key The name an entry answers to, and a claim that everything under that name changes at the same moment. RFC 9111 builds the protocol's own from the method and target URI, with Vary adding a secondary key.
Cache stampede Every reader of a hot entry missing at once when it expires, and each one querying the store for the same answer. Also called a thundering herd. The recomputation window admits the herd and the herd lengthens the window.
Cache-aside The read pattern in which the application, not the cache, goes to the store on a miss and writes the answer back. Also called lazy loading, or a look-aside cache. It is what keeps the cache an optional dependency.
Cacheable method A method whose responses may be stored and reused for a later request. RFC 9110 defines caching semantics for GET, HEAD and POST, and notes that most implementations support only the first two.
Capped exponential backoff Each attempt waiting twice as long as the last, up to a maximum. It spreads attempts out in time and leaves every client synchronised, which is why it needs jitter to be useful.
Cgroup The kernel feature that puts processes into hierarchical groups whose resource usage is limited and accounted. A container's CPU and memory limits are a cgroup, and a descendant can never exceed its ancestor's.
Client error (4xx) The status class saying the client seems to have erred. Repeating the request unchanged gets the same answer, so a 4xx is not a retry signal and not an availability signal.
Cold start (cache) An empty cache after a restart, a scale-out or a failover, during which the store receives the full read rate it was not provisioned for. A scheduled, normal state, and the one the service least survives.
Composite index An index over several columns, sorted by the first, then the second within equal firsts. Equality on the leading columns plus one inequality on the first column without an equality is what limits the scan.
Composition root The one file at the outermost edge that names every concrete implementation and hands it to whatever needs it. Everything imports it and it imports everything, so the answer to what this service actually runs against is one file long.
Concurrency A structure that lets several requests be in progress at once by overlapping the time each spends waiting. Distinct from parallelism, which is a count of cores actually executing.
Conditional request A request carrying a precondition on a validator, so the server acts only if the representation still matches. If-None-Match gives a cheap re-check; If-Match gives optimistic concurrency control.
Constraint A rule declared in the schema and checked by the engine on every write. Unlike a rule in service code it binds writers who never ran your code, which is what makes it an invariant rather than a convention.
Consumer acknowledgement The signal that ends the broker's ownership of a message. Sent manually after the work, it makes a crash harmless; sent automatically on delivery, it makes a crash a silent loss.
Consumer group A set of processes that share a topic's partitions, each partition read by exactly one of them at a time. It is what preserves per-partition order under parallelism, and why the partition count caps the number of useful consumers.
Consumer-driven contract test A test written by the caller stating what it relies on, published so the provider runs it on every build. The only layer that can see a break which lives between two services rather than inside one.
Content negotiation The client stating preferences in the Accept family and the server choosing. Advisory in one direction and authoritative in the other, with Vary naming the request fields the choice depended on.
Content Security Policy A response header restricting what the code in a page may do, most usefully by admitting only scripts carrying a fresh per-response nonce. A second layer against XSS, never a replacement for encoding.
Continuous delivery The discipline of building software so it can be released at any time. Continuous deployment is the stricter thing, where every change actually goes, and it requires this one first.
Control loop A non-terminating loop that compares desired state against current state and acts on the difference. It is the whole of the orchestration model, applied recursively rather than once.
Controller The layer that performs two translations and no third thing: a request into an intent with no transport type in it, and a named outcome back into a status and a body.
Covering index An index built to hold every column a query references, so the answer can come from the index alone. Payload columns are added with INCLUDE and are stored rather than ordered.
Credentialed request A cross-origin request carrying cookies or an authorization field. The page opts in, the server must allow credentials explicitly, and a wildcard origin is refused rather than expanded.
Cross-site request forgery Another site causing a reader's browser to send an authenticated request to yours. The credential is attached automatically, so the request is indistinguishable from one the user intended.
Cross-site scripting A value rendered into a page becoming markup the browser executes. The script has your origin, so the same-origin policy protects the attacker rather than the reader.
Cursor pagination Continuing a collection from the sort key of the last row delivered, so the position is a value rather than a count. Concurrent writes elsewhere in the collection move nothing it depends on.
Custom method An action no standard method expresses, written after a colon on the resource name, as in orders/42:cancel. POST when it has side effects, and used only where a standard method will not do.
Data race A write to a memory location concurrent with any other access to it, unless every access is atomic. The result is undefined rather than merely wrong, and a multiword read may return a value nobody wrote.
Dead letter exchange Where a broker republishes a message that was rejected without requeue, expired, overflowed a queue limit, or exceeded a delivery limit. The escape hatch that stops one unprocessable message occupying a worker forever.
Dead-letter queue Where a message goes once its receive count passes the limit. A diagnostic surface rather than a bin, and one with no alarm on it is a silent failure with extra storage.
Deadline An absolute point in time past which the caller stops waiting. Distinct from a timeout, which is a duration; gRPC sets neither by default, so an unbounded client waits effectively forever. Across services it travels as the time remaining rather than as an instant, so clock skew between two hosts cannot corrupt the budget.
Deadline propagation Carrying a request's deadline as an instant rather than a duration, so a call three layers down inherits what remains. A duration restarts at every hop, which silently multiplies the budget by the number of hops.
Deadlock A cycle in which each transaction waits for a row another holds, which no further waiting resolves. Detected automatically and broken by aborting one of them, after a deliberately lazy timeout.
Deduplication interval The window in which a broker suppresses a repeated send. On SQS FIFO it is five minutes and it covers the send action only, so it never removes a consumer's duplicate delivery.
Delete-on-write Removing the cached entry after the store is updated, leaving the next reader to refill it. Preferred over replacement because deletes are idempotent, so a retried, delayed or reordered one is still harmless.
Dependency inversion Declaring what a component needs and having it supplied, rather than the component going to find it. The call still runs downward; what moves is ownership of the contract, from the implementation to the caller.
Derived key A key built from a question rather than from an identity - a list page, a search result, a rendered fragment. The writer cannot enumerate the derived names its change made wrong, which is where invalidation becomes a design.
Desired state The state you wrote down, as opposed to the state that exists. Applying a manifest changes only this, and every visible effect afterwards is some loop noticing the two differ.
Dirty read Reading data written by a concurrent transaction that has not committed. Forbidden at every isolation level PostgreSQL actually implements.
Domain error A named outcome in the service's own vocabulary rather than a boolean, a status code or a message string. It is what lets a controller, a queue consumer and a test each interpret the same result in their own terms.
Double-submit cookie Sending the same anti-forgery value in a cookie and in the request, and comparing them. The naive form is bypassable by anyone who can write a cookie on the domain, which a sibling subdomain can.
Dual write Committing to a database and publishing to a broker as two separate acts with no transaction between them. A crash in the gap leaves a state change with no event, or an event describing a change that never happened.
Eventually consistent read A read that may not reflect a write which already returned success, because it was served by a replica that has not caught up. The default read model in DynamoDB, and half the price of the strong one.
Eviction An entry removed because the cache ran out of memory rather than because its lifetime elapsed. Governed by a policy: a volatile- policy considers only keys carrying an expiration and evicts nothing when none do.
Exchange The thing a producer actually publishes to. Bindings then route the message to zero or more queues, and the exchange type is the routing algorithm - fanout copying to every bound queue, direct matching a routing key exactly.
Field number The integer that identifies a field in the protobuf wire format. It is what a reader matches on, so it can never change once a message type is in use and must never be reused.
Foreign key A constraint saying the values in a column must match values appearing in some row of another table. What maintains referential integrity, and what gives the child table a say in what the parent may do.
Forward compatibility Old code making sense of data written by a newer version. Unavoidable during a rolling deploy, because instances of both builds are producing and consuming at the same time.
Freshness lifetime How long the origin believes a representation will not change in a way that matters. Set by s-maxage, then max-age, then Expires minus Date, and guessed heuristically when none is present.
GIN index PostgreSQL's preferred full-text index: an entry per lexeme with a compressed list of matching locations. It stores no weight labels, so a weighted query rechecks the table row.
Goroutine A function running concurrently in the same address space, costing little more than a small stack and multiplexed onto OS threads, so a blocked one does not hold a thread.
gRPC A schema-first call framework rather than a message format: a stub generated from a service block, and a mapping that makes one RPC one HTTP/2 stream with the outcome in trailers.
Head-of-line blocking The cost of a single position per partition: a record that always fails cannot be skipped without committing past it, so everything behind it in that partition waits. The reason a log needs an errors topic where a queue has a dead letter exchange.
Header field A name and value pair carrying what the method and target cannot say. A flat, extensible namespace of independent statements, readable by an intermediary that never parses the body.
Header versioning Carrying the version out of band, usually date-named and defaulted or pinned per account. The caller pays nothing until they opt in, and the provider keeps every old behaviour alive.
Hit rate The share of reads the cache answered by itself. Its complement is the quantity that sizes the store, which is why two hit rates that sound alike can differ by an order of magnitude in database load.
Hold time How long one request occupies a worker, computing or not. With arrival rate it fixes how many requests are in flight, which is the number a pool size has to cover.
HTTP method The token saying what action is asked of the target. A request for a defined semantic rather than a hint, which is why moving the verb into the path loses every guarantee it carried.
HttpOnly A cookie attribute forbidding script from reading the value. It closes the read and not the use: the cookie is still attached to requests the page itself makes.
Idempotency fingerprint A digest of the request payload stored beside an idempotency key, compared on every arrival. It is what separates a genuine retry from the same key sent with a different body.
Idempotency key A client-generated value that lets a server recognise a retry of a non-idempotent request. The server stores the first result beside it and replays that result rather than repeating the work.
Idempotent consumer A handler that can be given the same message twice and produce one effect. Either the write is naturally repeatable, or a key is claimed in the same transaction as the work.
Idempotent method A method whose intended effect from several identical requests equals the effect of one. PUT, DELETE and the safe methods. It compares server state, not the responses returned.
Image digest The content hash that names an image and each of its layers. It is what turns "the same version" from a claim about process into something a node can verify after pulling.
Immutable key A name that carries the content or a version, so a change produces a new name rather than a wrong entry. Invalidation becomes a rename: nothing is found, nothing is deleted, and the old entries expire unread.
Index-only scan Answering a query from index entries with no read of the table. Needs every referenced column in the index and a visibility map bit saying the heap page is all-visible, so it is a bet on the table being quiet.
Injection A value reaching an interpreter as part of the command text, so it is parsed as grammar rather than held as data. A property of every interpreter, not of SQL.
Interim response (1xx) A response reporting connection status or progress before the final one. It carries no content, and a request may have several of them followed by exactly one final response.
Interpreter lock CPython's guarantee that one thread executes bytecode at a time. It protects the object model, not your invariants, and it is always released during I/O.
Inverse document frequency The factor in a ranking function that weights a term by how rare it is across the corpus. A word appearing in nearly every document says almost nothing about which one to read.
Inverted index A map from each normalised word to the documents that contain it. It answers the search question in advance, so the lookup costs the length of one list rather than the corpus.
Isolation level A named subset of the four concurrency phenomena a transaction agrees to tolerate. Not a measure of care taken: the default permits three of the four.
Jitter Randomness added to a retry delay so that clients which failed together do not wake together. Full jitter draws uniformly from zero up to the backoff value, and is one line of code.
JSON number A decimal literal with no declared precision. RFC 8259 names the interoperable integer range as -(253)+1 to 253-1; beyond it a binary64 parser rounds, with no error raised.
JSON value types The six kinds RFC 8259 allows: object, array, number, string, boolean and null. There is no seventh and no extension point, so every domain type is carried by one of them under a convention.
JSON Web Token Three base64url parts - header, claims, signature. The first two are encoded rather than encrypted, so anyone holding the token can read every claim in it.
Layer A named unit of responsibility on the request→response spine. Transport, HTTP shape, routing, and your code; a framework hides a layer, never removes it.
Lease (cache) A token the cache issues on a miss and verifies on the matching set, refusing the store if a delete invalidated it meanwhile. It closes the stale-set race by making a fill conditional on nothing having happened to the key.
Length normalisation Judging a term's frequency against the document's length relative to the corpus average. BM25's b decides how much it matters, and at average length every setting agrees.
Length-prefixed framing One flag byte and four big-endian length bytes in front of every gRPC message. Protobuf is not self-delimiting, so this is what lets one stream carry a sequence rather than a single blob - which is what makes streaming a call shape.
Lexeme A token normalised for indexing - case folded, suffixes stripped - so that different forms of one word become the same entry. It is what is stored and looked up, never the original word.
Liveness probe A check that decides when to restart a container, for a process that runs but cannot progress. Pointing one at a shared dependency turns that dependency's outage into a fleet-wide restart.
Media type The type and subtype token naming both a data format and how a recipient should process it. Carried as a fact in Content-Type and as a preference in Accept.
Message body The optional fourth part of a request. Its presence is a property of the method and the framing, so a request with no body is complete rather than truncated.
Message relay The process that publishes committed outbox rows to a broker, by polling the table or by tailing the transaction log. It can crash after publishing, so it is at-least-once by construction.
Method dispatch Selecting a handler by the request method as well as the path. An exact token comparison, placed in front of the path walk because it discards most of the route table for the price of one equality.
Method Not Allowed (405) The status saying the method is known to the origin server but not supported by this target resource. It asserts the resource exists, which is the fact a 404 withholds.
Middleware A component that wraps the thing after it, acting as an application to the server above and as a server to the application below. Wrapping is what gives it a pass on the way in and a pass on the way out.
Middleware chain Middleware composed by nesting rather than queueing. Registered first means outermost, so the registration order is the request order and the exact reverse of the response order.
Miss penalty The extra cost a read pays when the cache has nothing: the ask, the query and the write-back, three trips where no cache would have cost one. It is why a cache makes most reads faster and the rest slower.
Mount path The prefix an inner router was reached through, kept aside rather than discarded so the inner router can build correct URLs. WSGI's SCRIPT_NAME and Express's req.baseUrl.
Mounting Registering one router inside another under a path prefix. Possible with no new machinery, because a router is itself a handler and nothing above it can tell the difference.
Multi-stage build A Dockerfile where each FROM starts a new stage and only the last becomes the image, so the compiler and package manager build the artefact and are then left behind.
MVCC Multiversion concurrency control: each statement reads a snapshot of the data as it was at some moment, so reading never blocks writing and writing never blocks reading. The question is never whether you get an answer, only which version it came from.
Namespace A kernel abstraction that makes a global resource appear to be a process's own: its own process table, its own network stack, its own mounts. Eight kinds exist and none of them is a machine.
Nonrepeatable read Re-reading a row already read and finding it changed by a transaction that has since committed. Permitted under Read Committed because each statement takes a fresh snapshot.
Not Found (404) The status saying the origin server found no current representation for the target, or is not willing to disclose that one exists. It says nothing about whether the absence is permanent.
Offset A consumer group's position in a partition. Because the position belongs to the reader rather than to the broker, several groups read the same events independently and any group can move backwards and replay.
Offset pagination Continuing a collection by a count of rows to skip. One insert or delete before the reader's position shifts everything after it, so the next page repeats or skips items.
Output encoding Transforming a value so the browser reads it as text in the exact place it is written. The transformation differs by context, and using the wrong one is itself a defect.
Page token The encoded cursor a caller sends back to continue a collection. Published guidance requires it to be opaque and unparseable, and requires the other request parameters to match the call that issued it.
Parameterised query A statement parsed and planned before its values arrive, which then land in slots that can hold data only. The security comes from the ordering, not from inspecting the value.
Partition One of the buckets a topic is spread over. Order is guaranteed inside a partition and nowhere else, and the event key is what decides which partition a record lands in.
Path parameter A named hole in a path pattern standing for one whole path segment. It ends at the next literal slash, so a value containing a slash needs a multi-segment hole or an explicit converter.
Path pattern The shape a route matches paths against: a sequence of segments, some literal and some named holes. A hole must be a full segment, so a hole glued inside a literal segment is not a pattern.
Path versioning Putting the version in the URI, so it is part of the resource identity, visible in every log and cached separately. The caller pays by rewriting URLs and the provider by running both surfaces.
Persistence model The shape the store keeps data in, which is allowed to differ from the domain model and usually does. Mapping between the two is the repository implementation's work, and doing it there is the point rather than an inconvenience.
Phantom read Re-running a query and finding the set of rows matching the condition has changed. Permitted by the standard at Repeatable Read, and not permitted by PostgreSQL's implementation of it.
PKCE Proof Key for Code Exchange. The client keeps a random verifier and sends only its hash, so an intercepted authorization code cannot be redeemed by whoever caught it.
Prefix stripping Removing the mount prefix from the path before the inner router matches, so its patterns are written without it. Go's StripPrefix copies the request and answers 404 when the prefix is absent.
Prefix tree The structure a router compiles its patterns into: host, then method, then consecutive path segments, one level each. Shared prefixes are shared nodes, so a match costs one lookup per segment.
Preflight request An OPTIONS request the browser sends unasked, naming the method and fields the real request will use, so permission is obtained before a request with effects is sent.
Proactive negotiation The client sending preferences in the Accept family and an algorithm on the server choosing from the representations it has. Advisory: a user agent cannot rely on a preference being honoured.
Problem details document An application/problem+json body carrying type, status, title, detail and instance, plus any members the problem type defines. The machine-readable half of a failure the status code can only classify.
Problem type The URI identifying a kind of failure, and the member a client branches on. An identifier rather than a location, and absent it defaults to about:blank, meaning the status code is the whole story.
Property graph A store whose units are nodes carrying labels and directed relationships between them, both able to hold properties. Reached for when the answer is a path whose length you cannot write out in advance.
Protection space An origin plus a realm, and the domain over which a user agent may re-apply credentials without being asked again. Automatic re-presentation is specified behaviour, and it is what CSRF exploits.
Published surface Everything a caller can observe and rely on, whether or not you meant to offer it: field names, status codes, error wording, identifier shapes. A promise nobody wrote down is still a promise.
Quality value The q parameter on a media range, expressing relative preference. Where several ranges match one type the most specific wins, so a full type beats type/* and type/* beats */*.
Query string The non-hierarchical component of a URI, after the question mark. Part of the identifier and part of the cache key, and reachable by the handler but never by the router.
Read-through The read pattern in which the loader is registered with the cache, so every read goes through it and the application never learns whether it hit. A better abstraction and a worse dependency than cache-aside.
Readiness probe A check that decides when a container may take traffic. Failing it removes the pod from every matching Service and restarts nothing, which is what makes it the safe place to check a dependency.
Release A build combined with one environment's configuration, carrying a unique identifier. Releases are an append-only ledger and none may be mutated, which is what makes a rollback a selection.
Repository A contract for the loads and saves the domain needs, written in the domain's vocabulary. The method list follows the operations, never the tables, and the query language stops at its edge.
Representation One concrete rendering of a resource, in a particular media type, language and encoding. A single URI can have several, and the response has to say which one it sent.
Representation metadata The fields describing the representation carried in this message rather than the resource behind it: Content-Type, Content-Length, Content-Encoding, Content-Language.
Request context An immutable value carrying the facts that belong to one request - deadline, cancellation signal, identity, trace id - derived rather than mutated, and passed explicitly to each function that needs it.
Request target The components of the parsed target URI, sent so a recipient can identify the resource the client meant. The fragment is excluded, so a server never sees it.
Reserved field number A protobuf field number promised never to be used again, declared so the compiler refuses a reuse. The only part of the compatibility rule set a build can enforce.
Resource Whatever you are willing to give a stable name and a representation. Not a table and not a class: HTTP separates identifying a resource from the semantics of the request, which live in the method.
Retriable error A failure about the world rather than about the job, so the same job has a real chance later. A terminal error retried thirty times reaches the same failure and costs thirty worker slots.
Retry amplification What happens when every hop retries independently: attempts multiply along the chain, so three attempts at three hops delivers twenty-seven calls into the service that was already struggling.
Revocation window The time a withdrawn permission keeps working. Zero when the server looks the credential up, and equal to the token lifetime when it does not.
Rolling update Scaling a new ReplicaSet up while the old one scales down, inside an envelope set by two defaults of 25%: surge above the desired count, and unavailable below it.
Route A registered pair of a method token and a path pattern, with the function to call. Compiled once at registration, so a malformed pattern fails at startup rather than on an unlucky request.
Route precedence The rule deciding between two patterns that both match. The more specific one wins, meaning the one matching a strict subset of the other's requests; when neither does, the two conflict.
Row lock The exclusive hold a write takes on a row, released at transaction end rather than at the end of the statement. Which is why hold time is transaction time and a transaction's length is its blast radius.
Safe method A method whose semantics are essentially read-only: the client neither requests nor expects a state change. GET, HEAD, OPTIONS and TRACE. Every safe method is also idempotent.
Same-origin policy The browser rule that script on one origin may not read a response from another unless that origin permits it. Enforced in the browser, so a non-browser client is unaffected.
SameSite A cookie attribute deciding whether the browser attaches it to requests another site started. Defence in depth rather than a defence: it is scoped to the registrable domain, and Lax still allows a safe method.
Schema-first Writing the message definition before the handler and generating both ends from it, so the shape, names and types are checked by a build rather than remembered by a reviewer.
Seam A place where behaviour can be changed without editing the code whose behaviour changes. An interface the consumer declares in a typed language, and a constructor argument in an untyped one.
Selectivity The fraction of a table a condition is estimated to match, computed by the planner from sampled statistics. A wrong estimate produces a plan that is the correct decision for a table you do not have.
Serialization The mapping between your program types and a format's small type system, in both directions. It is generated from a declaration on each side, and neither side can check the other.
Serialization anomaly A set of committed transactions leaving a state inconsistent with every possible order of running them one at a time. The general case the other three phenomena are special cases of.
Server error (5xx) The status class saying the server erred or could not perform the method. The request may be valid, so a retry with backoff is meaningful, and this is the class an availability alert fires on.
Server-sent events A one-way stream from server to browser with reconnection and a resume point built in. The right answer whenever the client never needs to send anything on the channel, which is most live features.
Service layer The layer that owns the decision, defined by what it cannot reach: no transport type passed in from above and no storage type passed up from below. That placement is what makes a rule portable and testable.
Session fixation An attacker supplying the session id rather than stealing it, then waiting for the victim to log in. Closed by issuing a new id at every privilege change.
Session identifier A random key into a table the server owns, carrying no meaning of its own. At least 64 bits of entropy, because being unguessable is its only job.
Short circuit A middleware answering the request itself instead of calling the next link, so nothing nested inside it runs. The mechanism behind every authentication gate and rate limiter.
Simple request A cross-origin request the browser sends without a preflight and judges afterwards: GET, HEAD or POST, only CORS-safelisted fields, and one of three permitted content types.
Snapshot The version of the data a read sees. Taken per statement under Read Committed and once per transaction under Repeatable Read, and that one word is the whole difference between the two levels.
Socket affinity The fact that an open connection is a file descriptor in one process and cannot be addressed from outside it. Delivering to one reader therefore means broadcasting to every process and letting the owner act.
Stale set A reader storing a value it fetched before a write replaced it, so the entry is wrong after the write already removed it. Caused by the read path rather than the write path, so no ordering of the writer's steps prevents it.
Staleness window How long a reader may see a value that is out of date. Every caching design has one whether or not it states it, and a lifetime is what bounds it when the invalidation message is lost.
Stated non-promise Writing down what a caller may not rely on, so an accidental promise becomes a documented reservation. The cheapest design act available and the one most often skipped.
Stateless constraint The requirement that each request carry everything needed to understand it, so the server keeps nothing between them. It buys visibility, reliability and scalability, and costs repetition on the wire.
Status class The first digit of a status code, which every client must understand. An unrecognised code is treated as the x00 of its class, which is what keeps the status space extensible.
Status mapping The controller's table from named outcomes to status codes, decided once. 400 for malformed, 422 for parsed but unprocessable, 409 for a conflict with current state, and 500 only for what was genuinely unexpected.
Sticky session Routing a client to the same instance every time, usually by hashing its address. The guarantee carries its own exception, that it holds until the instance is unavailable, which is when it was needed.
Stop word A word common enough to be useless for searching, dropped during analysis. One reason the index is a lossy derivation and the original text cannot be recovered from it.
Sunset The response header naming the date a resource is expected to stop responding. It travels with Deprecation, which names the date deprecation takes effect, and it may never be the earlier of the two.
Surrogate key A tag attached to an entry when it is stored, so the cache can maintain a reverse index and one purge can remove every entry carrying it. The only mechanism that solves the derived-key problem outright.
Synchroniser token An unpredictable per-session value required back on every state-changing request, and never delivered in a cookie. The attacking site can cause a request but cannot read one, so it cannot learn the value.
Temporal coupling Whether two parties have to be running at the same instant for work to happen. A synchronous call requires it and multiplies unavailability along a chain; a broker removes it and turns an outage into a backlog.
Term frequency saturation The rule that repeating a word helps and then stops helping. BM25's k1 sets how fast, and the contribution can never pass k1 plus one however often the word appears.
Test double Whatever is put on the far side of a seam while a test runs. Its job is not to be realistic but to make the behaviour under test the only thing that can vary, and it is trustworthy only as far as it has been checked against the real thing.
Test pyramid Two claims and no more: write tests at several granularities, and have fewer the higher you go. The reason is cost and flakiness, not virtue, and the inverted shape has its own name.
Trace context The standardised per-request identity that survives a hop into a service you did not write. W3C Trace Context defines a traceparent field carrying a version, a 32-character trace id, a 16-character parent span id and a flags byte.
Trailer An HTTP field sent after the body. gRPC puts its outcome there as grpc-status, which is why the HTTP status of a failed gRPC call is 200 and why a hop that drops trailers breaks the call invisibly.
Transaction A boundary drawn around several writes so that others see all of them or none. The unit of correctness in a store, and its edges are a design decision nobody else can make for you.
Transactional outbox Writing the message into a table in the same local transaction as the business data, and letting a separate relay publish it. It buys atomicity, not exactly-once: the relay can still publish twice.
Trusted type A type that cannot be constructed in an invalid state, produced by the boundary and accepted by everything downstream. A function taking one states its precondition in its signature.
ts_rank PostgreSQL's ranking function, scoring on the frequency of matching lexemes in the vector it is given. It takes no corpus-wide statistic, and offers per-field weights instead.
Uniform interface REST's central distinguishing feature: identity, methods and their guarantees agreed once for the whole web, so caches, proxies and clients act correctly without reading your documentation.
Unknown field A field a parser meets and its schema does not define. Proto3 keeps it and writes it out again, which is what lets a middle hop lag the schema without losing data.
Upgrade handshake The ordinary HTTP request that becomes a WebSocket - Upgrade: websocket with a nonce, answered by 101 Switching Protocols and a value derived from that nonce. After the 101 nothing on the connection is a request or a response.
URI template A syntax describing a URI space with expressions expanded from variables. RFC 6570 gives the path and the query different operators, so the split between them is encoded in the grammar.
Validator A compact token for the state of a representation: an ETag the server alone interprets, or a Last-Modified date. Sent back in a precondition, it turns a refetch into a 304.
Visibility timeout The lease on a received message: 30 seconds by default on SQS, 12 hours at most, measured from first receipt. When it expires with no acknowledgement, the message is delivered again.
Wire format The grammar two programs both parse, and the only layer of a serialized message with a specification behind it. It decides valid or not, and never what the bytes mean.
Write-ahead log The sequential record flushed to disk before the changed data pages are written, which is what makes a commit durable. Recovery replays it forward over whatever the files hold.
Write-around Updating the store and leaving the cached entry untouched, so the caller waits for the store alone and the entry stays wrong until its lifetime runs out. What a service has when nobody changed the write path.
Write-back Acknowledging a write once the cache holds it and flushing to the store later, so between the two the authoritative copy lives in the cache. Also called write-behind. An eviction is enough to destroy an acknowledged write.
Write-through Updating the store and the cached entry in the same request, so the entry is never stale. It costs two trips on every write and fills memory with answers nobody reads.
