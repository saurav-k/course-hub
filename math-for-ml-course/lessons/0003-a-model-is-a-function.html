A model is a function, and depth is composition

foundation 10 min The word "deep" in deep learning is a statement about function composition and nothing else.

The one-minute version

  • f : A → B is a contract about shapes, declared before any formula and checkable before any code runs.
  • The codomain is what a function declares it returns; the image is what it actually reaches. A sigmoid declares all of the reals and reaches only the open interval between 0 and 1.
  • The semicolon in f(x; θ) separates what you feed the model from what you train.
  • A network is a composition, and the length of the chain is what the word depth means.
  • An inverse exists only for a one-to-one function, which is why a network cannot simply be run backwards.

1. A function is a declaration before it is a formula

Most people meet a function as a rule for computing something. The more useful reading, and the one every paper assumes, is that a function first declares what it accepts and what it returns.

f : ℝ45 → ℝ3 Read as: f takes a list of 45 real numbers and returns a list of 3. The set on the left is the domain, the set on the right is the codomain, and the arrow is the whole of the claim. Nothing here says how the numbers are computed.

That single line already tells you the ticket classifier takes 45 features and scores 3 classes, before you have read a line of its code. It is the same information a type signature carries, written in the older notation.

2. Codomain against image, and why the difference bites

The codomain is what the function promises. The image is what it actually produces. They are usually different, and one case matters more than all the others.

A note on the word, because you will meet both. Some texts, the Deep Learning notation table among them, write "the function f with domain A and range B" and mean the codomain by "range". Others use "range" for the image. This course says image when it means what is actually reached, and flags the ambiguity here rather than letting you meet it cold in a paper.

Now the part that costs an afternoon. Mathematically a sigmoid never returns exactly 1. In float64 it returns exactly 1.0 for every input above about 36.74, and in float32 above about 16.64 - both measured by this lesson's program, not quoted. The moment it does, log(1 − ŷ) is -inf and your loss is nan. The mathematics and the arithmetic disagree here, and knowing which of the two you are looking at is the entire skill.

3. The semicolon does real work

f(x; θ) Read as: a function of x, parametrised by θ. x is what you feed it at prediction time and changes with every example; θ is what training chose and is the same for every example. The semicolon is what separates the two roles.

Almost nobody explains that punctuation, and it is the difference between an input and a weight. When a paper writes f(x) and drops the θ, it is not saying the parameters vanished; it is saying they are being held fixed and are not the subject of the sentence.

4. Depth is the length of the chain

Composition means feeding one function's output into the next. It has one hard rule: the codomain of the first must be the domain of the second. That rule is the whole of shape checking.

The Deep Learning textbook puts it directly: a network is f(x) = f(3)(f(2)(f(1)(x))), and "the overall length of the chain gives the depth of the model. The name deep learning arose from this terminology." That is the whole etymology.

One property of composition is worth stating because people assume the opposite: it does not commute. f2 ∘ f1 and f1 ∘ f2 are different functions, and in the chain above the second one is not even defined.

5. Inverses, and why a network is not one

A function has an inverse only if it is one-to-one: distinct inputs must give distinct outputs. If two inputs collide there is no way back, because the return trip would not know which one to pick.

The pair you will meet constantly is worth writing out, since one of them turns a score into something that looks like a probability and the other undoes it.

σ(x) = 1 / (1 + e−x)     logit(p) = ln(p / (1 − p)) Read as: sigma squashes any real number x into the open interval between 0 and 1; the logit takes a number p strictly inside that interval and returns the real number that sigma would have squashed into it. Each undoes the other.

6. The contract, checked at run time

The program for this lesson builds the 45-32-16-3 chain over the real ticket data and prints the shape after each layer, so the signature is not a claim on a page but something you watch happen.

for n, (weight, bias) in enumerate(layers, start=1):
    before = activation.shape[1]
    assert before == weight.shape[0], (
        f"layer f{n} declares domain R^{weight.shape[0]} and was handed R^{before}"
    )
    activation = activation @ weight + bias
    if n < len(layers):

Check yourself

Retrieval practice

Answer from memory before revealing.

A sigmoid is declared σ : ℝ → ℝ. Can it return exactly 1.0?
Mathematically the image is the open interval, so the answer is no. The second option confuses what the function declares with what it reaches, which is the distinction this page exists for. The third is true of the arithmetic and false of the mathematics: float64 does return 1.0 above about 36.74, and telling those two facts apart is the point. The fourth is simply false about the real numbers.
Given f1 : ℝ45 → ℝ32 and f2 : ℝ32 → ℝ16, which composition is defined?
Only one order lines up: f1 leaves a 32-vector and f2 wants a 32-vector. The first option is the misconception, and composition never commutes in general. The second has f1 being handed a 16-vector when it declared it takes 45. The fourth is the panic answer, and the widths do match in one direction.

Practice about 12 minutes, with paper

Practice 1foundation

An autoencoder on the ticket features. The encoder is 45 → 32 → 8 and the decoder is 8 → 32 → 45.

(a) Write the signature of each of the four layers, and of the two halves.
(b) Count the parameters, counting one bias per output unit.
(c) The composition decoder ∘ encoder has domain ℝ45 and codomain ℝ45. Why is it not the identity function?

Hint

For (c), count how many numbers go in and how many survive the middle, then ask what section 5 says has to be true before an inverse can exist.

Show the worked solution
  1. Write the four signatures. ℝ45 → ℝ32, ℝ32 → ℝ8, ℝ8 → ℝ32, ℝ32 → ℝ45. Each one's target is the next one's source, so the chain is legal.
  2. Compose the halves. Encoder ℝ45 → ℝ8, decoder ℝ8 → ℝ45. The middle number is the only thing the outside world does not see.
  3. Count each layer. 45×32 + 32 = 1,472; 32×8 + 8 = 264; 8×32 + 32 = 288; 32×45 + 45 = 1,485.
  4. Add. 3,509 parameters in total, and every one of those numbers came from the shapes alone, before any training.
  5. Count what goes through the middle. 45 numbers go in and 8 come out of the encoder. There are far more possible 45-vectors than 8-vectors, so different tickets must arrive at the same code.
  6. Apply the rule. A function that maps two different inputs to the same output is not one-to-one, so it has no inverse. A composition ending where it started is not the identity unless nothing was lost, and here something was lost by construction.
  7. Name why that is the point. The bottleneck is deliberate. An autoencoder that could be inverted exactly would have learned nothing worth having.

Sanity check. The two halves are near mirror images, so their parameter counts should be close but not equal - the biases follow the output width, and 45 is not 8. If your two halves came out identical, you counted biases on the input side.

Your teacher. This page names no theorem. A function, a domain and a composition are definitions, and there is nothing here to prove - saying so is more honest than dressing a definition up as a result. What is worth practising instead is reading signatures: point an agent at any model file you have and ask it to "write the signature of every layer as f from R^a to R^b and tell me where the composition would break if I changed one width".
