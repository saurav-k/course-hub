Module 06 · Optimization · Lesson 100

Learning is an optimization problem

working 10 min The first page of the module that explains what fit() is doing.

The one-minute version

  • A trained model is one chosen point in a space of possible parameter values.
  • Choosing it means naming three things: what varies, what is scored, and what is forbidden.
  • The thing you minimise is almost never the thing you are paid for. Accuracy has no usable gradient, so you minimise a stand-in.
  • The objective is an average over the rows you happen to have, and that is a different quantity from the one you care about.

1. A trained model is a chosen point

Before anything is trained, a model is a family. A linear model with twelve features is not one function, it is every function you can write by picking thirteen numbers. Training picks the numbers.

So the useful mental picture is not a machine that learns. It is a space, with one point for every possible model, and a landscape of scores laid over it. Training is a walk to a low point.

2. The three parts

Every training run in this course, and every one you will start at work, is these three things and a solver.

minimise J(θ)   over   θ   subject to   constraints θ: the parameters, the thing that varies. For a linear model on twelve features it is a vector of thirteen numbers, twelve weights and an intercept. J: the objective, a single number scoring how bad a given θ is on the data you have. Lower is better. constraints: anything θ is forbidden to do. Often there are none written down, and Lesson 110 shows that a penalty is a constraint in disguise.

Naming them is not bookkeeping. It tells you which lever you are pulling. Changing the model class changes what θ ranges over. Changing the loss changes J. Adding weight decay adds a constraint. Three different interventions, three different places, and they are routinely confused with one another.

3. What you minimise is not what you want

You are usually paid for accuracy, or for revenue, or for a fraud caught. None of those can be minimised directly, and the reason is worth seeing rather than being told.

Accuracy counts how many predictions land on the right side of a threshold. Nudge a weight by a millionth and no prediction crosses the threshold, so accuracy does not move at all. Nudge it enough and one flips, and accuracy jumps. It is a staircase: flat almost everywhere, with a cliff at every step. A flat surface gives no direction to walk in, and a cliff gives no usable one either.

Name the substitution out loud, every time. Choosing a differentiable stand-in is what makes the problem solvable, and it is also what makes it a different problem. When your loss falls and your metric does not, this is usually where to look first, and it is not a bug in the optimizer.

4. The objective is an average over the rows you have

The second substitution is quieter. J is built by scoring each row of your data and averaging, so it measures performance on the sample in front of you rather than on the world the sample came from. Every optimizer in this module minimises the first and is judged on the second.

That gap is what Module 09 is about, and it is why Lesson 110 and Lesson 111 exist at all. Here it is enough to know the gap has a name and is not the optimizer's fault.

5. Reading a real objective

Here is the objective that scikit-learn's LogisticRegression minimises. It runs through this whole module: Lesson 101 asks whether it is convex, Lesson 102 walks down it, and Lesson 110 takes its second term apart.

J(θ) = −(1/n) ∑i [ yi log pi + (1 − yi) log(1 − pi) ]  +  (1 / 2C) ∑j≠0 θj2 n: how many rows of data there are. i: the index over rows, running 1 to n. yi: the true label for row i, either 0 or 1. pi: the probability the model gives row i of being a 1, always strictly between 0 and 1. log: the natural logarithm, so log of a probability is always negative and the minus sign in front makes the whole first term positive. θj: the j-th parameter. j ≠ 0: the sum skips the intercept, which is conventionally left unpenalised. C: the inverse regularization strength, so a smaller C penalises harder.

The first term says "fit the data". The second says "and do not use large weights to do it". They disagree, and C is the exchange rate between them.

6. Worked: which model does the objective prefer?

Two candidate parameter vectors on the credit dataset. B is fitted, forty plain gradient steps, so it fits better and its weights are larger. A is B shrunk to a quarter, so it fits worse and costs almost no penalty. Neither is the optimum; the question is only which one J prefers.

  1. Score the fit of each. On all 20,000 rows the mean logistic loss is 0.5453 for A and 0.3783 for B. B fits better, as it was built to.
  2. Score the size of each. The squared norm of the penalised weights is 0.0163 for A and 0.2609 for B. B is larger, as it was built to be.
  3. Take C = 100, a very weak penalty. The penalty terms are 0.0163 ÷ 200 = 0.00008 and 0.2609 ÷ 200 = 0.0013. Totals: A = 0.5455, B = 0.3809. B wins.
  4. Take C = 1, the library default. Now the penalties are 0.0082 and 0.1305. Totals: A = 0.5616, B = 0.6392. A wins.
  5. Take C = 0.01. Penalties of 0.8155 and 13.05. Totals: A = 2.176, B = 26.47. A wins by a distance.
  6. Read the reversal. Somewhere between C = 100 and C = 1 the objective changed its mind about which model is better, without a single number in the data changing.

Sanity check. The likelihood term alone must always prefer B, because B was produced by minimising it. So any preference for A has to come from the penalty, and it does.

What changes if the weights are rescaled? Double every weight in both candidates and the penalty term quadruples while the fit term changes shape entirely. This is why features are standardised before regularization: the penalty compares weights that have to be on comparable scales, and Lesson 103 measures what happens when they are not.

What it means. The default C=1.0 is not "no regularization". It is a specific rate of exchange between fitting and simplicity, chosen for you, and it is strong enough to reverse which of two models your objective prefers.

code/0100-learning-is-an-optimization-problem.py · NumPy and Pandas only · download
def objective_by_loop(design, target, theta, inverse_strength):
    """Mean logistic loss plus the L2 penalty, one row at a time."""
    total = 0.0
    for row, label in zip(design, target):
        logit = float(np.dot(theta, row))
        probability = float(sigmoid(np.array([logit]))[0])
        total += -(label * np.log(probability)
                   + (1.0 - label) * np.log(1.0 - probability))
    mean_loss = total / len(target)
    # The intercept is conventionally left unpenalised, so theta[0] is skipped.
    penalty = float(np.dot(theta[1:], theta[1:])) / (2.0 * inverse_strength)
    return mean_loss + penalty

The full program computes the same number a second way, as one vectorised expression over the whole matrix, and prints the difference. It comes out at about 3 × 10-15, which is machine precision. The loop is what this page teaches and the vector form is what a codebase runs, and knowing they are the same arithmetic is what lets you trust the fast one.

Check yourself

Retrieval practice

Answer from memory before revealing.

In LogisticRegression(C=1.0), what does C control?
C is the inverse penalty strength, so a smaller C regularises harder and the default of 1.0 is emphatically not "no regularization". The first option is max_iter and the fourth is tol, both real parameters answering different questions. The second describes something that does not exist here: the default lbfgs solver has no learning rate for you to set.
Why is classification accuracy not used as a training objective?
Accuracy is a staircase in the parameters: flat between decision flips, so it carries no descent direction anywhere. The second is false and backwards, since accuracy is cheaper to compute than the loss. The third confuses "undefined" with "misleading", which under imbalance it certainly is. The fourth is false for a running estimate, and would not make it unusable anyway.

Practice about 15 minutes, with paper

Practice 1working

A two-feature logistic model has parameters θ = (θ0, θ1, θ2), an intercept and two weights. Two candidates:

θA = ( 0.0, 1.0, −1.0 )     θB = ( 0.0, 3.0, −3.0 ) Read as: two candidate parameter vectors for the same model. Both have a zero intercept. B is exactly three times A in its two weights, so it makes the same predictions in the same direction, only more confidently.

On a row with features x = (1, 1) and label y = 1, find which candidate the objective prefers at C = 1, and then at C = 0.05.

Hint

Compute the fit term and the penalty term separately and only add them at the very end. The penalty does not look at the data at all, so you can write both penalties down before you touch the row.

Hint for the second half

Nothing about the data changes between the two parts. Only the exchange rate changes, so only one of the two terms in your total moves.

Show the worked solution
  1. Compute the logit for each. For A: 0 + 1(1) + (−1)(1) = 0. For B: 0 + 3(1) + (−3)(1) = 0. They are the same.
  2. Turn each into a probability. The logistic function at 0 is 0.5, for both.
  3. Score the fit. With y = 1 the loss is −log(0.5) = 0.6931, for both. The fit term cannot separate them.
  4. Compute the penalties. A: (12 + 12) = 2. B: (32 + 32) = 18. Nine times larger, because the penalty is quadratic and B is three times A.
  5. At C = 1. Penalties are 2 ÷ 2 = 1.0 and 18 ÷ 2 = 9.0. Totals: A = 1.693, B = 9.693. A wins.
  6. At C = 0.05. Penalties are 2 ÷ 0.1 = 20 and 18 ÷ 0.1 = 180. Totals: A = 20.69, B = 180.69. A wins again, by more.
  7. Name what happened. On this row the two models are indistinguishable, so the objective decides entirely on size, and it never prefers B at any C. Weakening the penalty narrows A's margin but cannot reverse it, because B has nothing to offer in the term that would have to do the reversing.

Sanity check. Both probabilities must lie strictly between 0 and 1, and both came out at exactly 0.5, which is what a zero logit must give. The penalty at C = 0.05 must be exactly twenty times the penalty at C = 1, because C appears only as a divisor and 1 ÷ 0.05 = 20: check 1.0 → 20 and 9.0 → 180. If either ratio is not 20, the arithmetic is wrong before the comparison starts.
