Backpropagation is the chain rule run right to left on a computation graph

working 14 min The algorithm every model in this hub is trained by, worked by hand on every number.

The one-minute version

  • Backpropagation is not the learning algorithm and it is not specific to neural networks. It computes a gradient, and something else learns with it.
  • Draw the computation as a graph and the gradient is one sweep backwards, multiplying local derivatives and accumulating.
  • It is provably correct, by induction on a topological order, and provably costs the same order as the forward pass.
  • A hidden unit that is off receives nothing, and you can see that in the worked numbers rather than being told it.

1. Two things it is not, before anything it is

Both misconceptions are in the same paragraph of Deep Learning, because both are that common.

The reframingBackpropagation computes the gradient. That is all it does. Stochastic gradient descent, or Adam, or anything else in Module 06, is what does the learning with that gradient. And it is not a neural-network technique: it differentiates any function you can express as a graph of differentiable operations.

2. The computation graph

Nodes are variables. Edges are operations. Every model, every loss, every regulariser you have met is one of these, whether or not anyone drew it.

Here is the graph of a two-input, two-hidden-unit, one-output network, with real numbers on every node. Inputs x = (1, 2), weights W1 = [[0.5, −0.5], [1.0, 0.5]], a ReLU, output weights w2 = (1.0, −2.0), bias 0.5, target 1.

3. The backward sweep

Start at the end with dL/dL = 1 and walk backwards. At each node, multiply what arrived by the local derivative of the edge you are crossing, and add it to what is already there.

4. Why it is correct

Proposition. Order the graph's nodes u1 to uN so every edge runs from a lower index to a higher one, with uN the scalar output. Define adjoints by setting the last to 1 and, for each earlier node, summing over its children the child's adjoint times the local partial. Then each adjoint equals dL/dui.

What is assumed: the graph is finite and acyclic, and every local partial exists. The shape of the argument: induction running backwards along the topological order. The step that does the real work is the decomposition over children, because that is the multivariate chain rule and everything else is bookkeeping.

  1. Base case. For the last node, dL/duN = dL/dL = 1, which is what the definition sets.
  2. Inductive hypothesis. Assume the claim holds for every index above i.
  3. Decompose. Every path from ui to the output leaves through exactly one child, so by the multivariate chain rule of Lesson 85, dL/dui is the sum over children of (dL/duj)(duj/dui).
  4. Apply the hypothesis. Every child has index above i, by the topological order, so each dL/duj may be replaced by its adjoint.
  5. Recognise the result. The right-hand side is now exactly the defining sum for the adjoint at i. QED
What the proof makes visibleThe induction runs on the topological order, which is why the graph must be acyclic: a cycle has no such order and the argument has nothing to stand on. And each local partial is used exactly once in the whole sweep, which is the next proposition.

5. Why it is affordable

Proposition. With a single scalar output and constant-time local partials, the backward pass costs O(number of edges), the same order as the forward pass.

  1. Count the work per node. At node i the recursion does one multiplication and one addition for each outgoing edge.
  2. Sum over nodes. That counts every edge exactly once, so the total is O(edges) multiplications and additions.
  3. Compare with the forward pass. It also touches each edge once. QED

This is the most consequential fact in the module. It is why a gradient over a hundred billion parameters costs about what evaluating the loss costs, and why the alternative does not scale.

6. Worked: every number in the backward pass

L = ½( y-hat − y )² ,   y-hat = w₂ · h + b₂ ,   h = ReLU(W₁x + b₁) x: the two inputs. W₁: the first layer's weight matrix, two by two. b₁: its bias, both zero here. h: the hidden activations after the ReLU. w₂: the output weights. b₂: the output bias. y-hat: the prediction. y: the target. L: the loss, one number.
  1. Forward. z₁ = (−0.5, 2.0), so h = (0, 2) after the ReLU, y-hat = 1(0) − 2(2) + 0.5 = −3.5, and L = ½(−4.5)² = 10.125.
  2. Start the sweep. dL/dy-hat = y-hat − y = −3.5 − 1 = −4.5.
  3. Through the output layer. dL/dw2 = (dL/dy-hat) h = −4.5 × (0, 2) = (0, −9), and dL/db2 = −4.5.
  4. Back into the hidden layer. dL/dh = (dL/dy-hat) w2 = −4.5 × (1, −2) = (−4.5, 9).
  5. Through the ReLU. Its local derivative is 1 where the pre-activation was positive and 0 where it was not. z₁ = (−0.5, 2.0), so the gate is (0, 1) and dL/dz1 = (0, 9).
  6. Into the first layer's weights. The outer product with the input: dL/dW₁ = (0, 9) ⊗ (1, 2) = [[0, 0], [9, 18]], and dL/db1 = (0, 9).

Sanity check. The prediction is −3.5 against a target of 1, so the model is badly wrong and dL/dy-hat must be large and negative. It is. Every number here is a small whole number, so the whole pass can be redone on paper, which is the point of choosing these weights.

The teaching moment is the zeros. The first row of dL/dW₁ is (0, 0). Not rounding, not a bug. The first hidden pre-activation was −0.5, so ReLU output zero, so its local derivative is zero, so that zero blocks the gradient to both weights feeding that unit. This is the dead-ReLU phenomenon, and you are looking at it rather than reading about it.

What changes if W₁[0][0] is raised from 0.5 to 1.0? Then z₁[0] = 0 exactly, the unit sits on the kink from Lesson 82, and the framework returns one of the one-sided derivatives. Raise it further and the whole first row becomes non-zero and the unit starts learning again.

In words. The gradient flows only along paths the forward pass actually used. Backpropagation does not need a special case for a switched-off unit, because the arithmetic already handles it.

7. Checking the whole thing against the definition

The proposition in section 4 is a proof, and a proof does not catch an implementation error. Gradient checking does: perturb one parameter, take a central difference, compare.

code/0086-backpropagation.py · NumPy and Pandas only · download
def backward(p, cache):
    """Reverse accumulation. Start at dL/dL = 1 and walk the graph backwards,
    multiplying each node's local derivative and accumulating."""
    n = len(cache["residual"])
    d_z2 = 2.0 * cache["residual"] / n           # dL/dz2
    d_w2 = cache["h"].T @ d_z2                   # through h . w2
    d_b2 = np.array([d_z2.sum()])
    d_h  = np.outer(d_z2, p["w2"])               # gradient flowing into h
    d_z1 = d_h * (1.0 - cache["h"] ** 2)         # through tanh, reusing h
    d_W1 = cache["x"].T @ d_z1                   # through x . W1
    d_b1 = d_z1.sum(axis=0)
    return {"W1": d_W1, "b1": d_b1, "w2": d_w2, "b2": d_b2}

Scaled up to a 6-32-1 network on the sensor data, the program checks all 257 parameters, not one. The worst relative error is 1.088 × 10−5 and the best 7.232 × 10−9. It also measures the cost: the backward pass takes 3.23 times the forward pass, while a full finite-difference gradient would need 514 forward passes and measured 2.27 seconds against 0.019.

A defect worth learning fromThe line marked "reusing h" was not there at first. An earlier version recomputed tanh in the backward pass instead of reusing the activation the forward pass had already stored, and it measured 12.21 times the forward pass, which flatly contradicts the O(edges) proposition above. The cache is not an optimisation bolted on afterwards. It is the reason the cost claim is true, and getting it wrong moves the number by a factor of four.

Check yourself

Retrieval practice

Answer from memory before revealing.

Backpropagation computes what, exactly?
It computes the gradient and stops there; stochastic gradient descent or Adam does the learning. The first is the optimiser's job and is the misconception this page opens with. The third is the forward pass, which backpropagation depends on but is not. The fourth is Lesson 89's subject and nothing to do with this algorithm.
In the worked network dL/dW1 has a first row of zeros. Why?
z1 = -0.5 for that unit, so ReLU output zero and its local derivative is zero, which blocks the gradient to every weight feeding it. The first is false: those weights are 0.5 and -0.5. The second is false: the inputs are 1 and 2 and the finite-difference check returns exactly zero, not a cancellation. The third is the trap, and it is wrong in a way that matters, because treating a structural zero as noise is how a dead unit goes unnoticed.

Practice about 15 minutes, with paper

Practice 1working

Run the whole pass by hand on this network.

x = (1, 2), W₁ = [[0.5, −0.5], [1.0, 0.5]], b₁ = (0, 0), ReLU, w₂ = (1.0, −2.0), b₂ = 0.5, y = 1 Read as: two inputs, a two-by-two first layer with no bias, a rectified linear activation, a two-into-one output layer with bias 0.5, and a target of 1. The loss is half the squared error.

Compute the forward pass, then the backward pass, then check dL/dW₁[0][0] against a central difference.

Hint

Do the backward pass strictly in reverse order and write the adjoint at every node before moving on. If you jump ahead you will need a derivative you have not computed yet.

Hint for the check

To check one weight numerically, change only that weight, recompute the loss twice, and divide by twice the step. Everything else in the network stays exactly where it is.

Show the worked solution
  1. Forward. z₁ = (0.5(1) − 0.5(2), 1.0(1) + 0.5(2)) = (−0.5, 2.0). h = (0, 2). y-hat = 0 − 4 + 0.5 = −3.5. L = ½(−4.5)² = 10.125.
  2. Backward, step 1. dL/dy-hat = −4.5.
  3. Steps 2 and 3. dL/dw2 = (0, −9), dL/db2 = −4.5.
  4. Step 4. dL/dh = (−4.5, 9).
  5. Step 5. The ReLU gate is (0, 1), so dL/dz1 = (0, 9).
  6. Step 6. dL/dW₁ = [[0, 0], [9, 18]], dL/db1 = (0, 9).
  7. The check. Nudging W₁[0][0] by 1e-5 either way leaves the loss unchanged to machine precision, so the central difference returns exactly 0, matching the analytic 0. The unit is off and moving that weight a little does not switch it back on.

Sanity check. L must be ½(−3.5 − 1)² = ½(20.25) = 10.125. If the forward loss is anything else, stop before differentiating: every backward number is built on it.

Your teacher. If the sweep still feels mechanical rather than understood, ask an agent to redo it with the ReLU replaced by the identity, so no gate shuts, and compare which numbers change. If the outer product in step 6 is the sticking point, ask it to write out dL/dW1[i][j] as a single expression in dL/dz1[i] and x[j] and confirm it matches.
