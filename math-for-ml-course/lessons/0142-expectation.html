The one identity that never asks whether your variables are independent

working 12 min Expectations of sums always add. Expectations of products almost never multiply.

The one-minute version

  • Expectation is a weighted average of the possible values, weighted by how likely each is, and it is the balance point of the distribution.
  • Linearity says E[aX + bY] = aE[X] + bE[Y], and it holds for any X and Y with finite means. Dependence is never a condition.
  • E[XY] = E[X]E[Y] needs independence, and that asymmetry between sums and products is the thing to carry away.
  • Linearity is what lets you answer questions about dependent things without ever writing down their joint distribution.

1. The mental model: a balance point, not a typical value

The expectation of a random variable is where the distribution balances if you cut it out of card and rested it on a knife edge. That picture is worth more than the formula, because it explains the thing beginners find strange: the balance point does not have to be anywhere near where the mass is.

2. The mechanism, in both cases

For a discrete variable, take each value, multiply by how likely it is, and add up.

E[X] = ∑x x · p(x) Read as: the expectation of X is the sum, over every value x that X can take, of that value multiplied by its probability. The capital sigma is the instruction to add over all of them. Nothing here is an approximation.

For a continuous variable the sum becomes an integral and the mass becomes a density, but the instruction is unchanged.

E[X] = ∫ x · f(x) dx Read as: sweep across every value x the variable can take, weight it by the height of the density f there, and accumulate. The dx is the width of the slice you are weighting, which is what makes the total a balance rather than a pile.

For a function of a variable you do not need that function's distribution first. Weight the transformed values by the original probabilities.

E[g(X)] = ∑x g(x) · p(x) Read as: to average g of X, apply g to each value and weight by the probability that X took that value. g is any function you like: squaring it, taking a log, or clipping it at a threshold.

3. Linearity, and the proof that shows why dependence is irrelevant

Linearity is worth seeing proved once, because the proof is where you watch independence fail to appear.

Theorem For any two random variables X and Y with finite means, and any constants a and b, E[aX + bY] = aE[X] + bE[Y].

Proof. Work with the joint distribution p(x, y), because the sum aX + bY is a function of both variables at once. By the rule for the expectation of a function, average that combination over the joint.

E[aX + bY] = ∑x ∑y (ax + by) · p(x, y) Read as: run over every pair of values the two variables could take together, form the combination ax + by for that pair, weight it by the joint probability of the pair, and add.

Split the bracket in two, and pull each constant out.

= a ∑x ∑y x · p(x, y)  +  b ∑x ∑y y · p(x, y) Read as: the two halves of the bracket are added separately, which is allowed because addition inside a sum can always be separated. The constants a and b do not depend on x or y, so they come outside.

Now the step that does the real work. In the left term, x does not depend on y, so the inner sum over y touches only p(x, y). Summing the joint over y is exactly marginalising, and it gives pX(x). The same happens on the right with the roles swapped.

= a ∑x x · pX(x)  +  b ∑y y · pY(y)  =  aE[X] + bE[Y] Read as: each double sum has collapsed to a single sum against a marginal, and each of those is the definition of an expectation. That completes the proof.

Read back over those four lines and look for the place independence was used. There is no such place. The only fact the proof needed about p(x, y) is that summing it over one variable gives the marginal of the other, and that is true of every joint there is.

Borrowing the condition from the product identity onto the sum identity is the most common error in this territory. Sums always add. Products multiply only under independence.

4. Worked example: what fraction of your training set does a bootstrap miss?

A random forest builds each tree on a bootstrap resample: draw n rows with replacement from n rows. The rows left out are the out-of-bag sample, and they are what oob_score_ scores. What fraction is left out?

The indicators of "row j was missed" are dependent, because a resample that over-picks one row must under-pick others. Writing their joint is unpleasant, and linearity means you never have to.

  1. Define one indicator. Let Ij be 1 if row j never gets drawn, and 0 otherwise.
  2. One draw misses row j. There are n rows and the draw takes one, so the chance it is not row j is (n - 1) ÷ n, which is 1 - 1/n.
  3. All n draws miss it. The draws are independent of each other, so multiply: P(Ij = 1) = (1 - 1/n)n.
  4. That is also its expectation. An indicator's expectation is the probability it is 1, so E[Ij] = (1 - 1/n)n.
  5. Sum by linearity. The expected count left out is E[∑ Ij] = ∑ E[Ij] = n(1 - 1/n)n, and the dependence between the Ij never entered.
  6. Turn it into a fraction. Divide by n: the expected fraction left out is (1 - 1/n)n.
  7. Put numbers in. At n = 100 that is 0.366032, at n = 1,000 it is 0.367695, and at n = 10,000 it is 0.367861.
  8. Take the limit. It converges to 1/e = 0.367879. About 36.8 percent of every training set is out of bag, and that is where the free validation estimate comes from.
code/0142-expectation.py · NumPy and Pandas only · download
import numpy as np

rng = np.random.default_rng(20260824)

for n in (10, 100, 1_000, 10_000):
    derived = (1.0 - 1.0 / n) ** n
    measured = np.mean([len(np.unique(rng.integers(0, n, n))) / n
                        for _ in range(2_000)])
    print(f"n={n:>6}  derived {derived:.6f}  measured left out {1 - measured:.6f}")

print("limit 1/e =", 1 / np.e)

5. Check yourself

Retrieval practice

Answer from memory before revealing.

When may you write E[X + Y] = E[X] + E[Y]?
Linearity needs nothing beyond finite means, and the proof above never touches the joint except to marginalise it. The first two options are the condition for E[XY] = E[X]E[Y] and for variances adding, borrowed onto the wrong identity, which is the most common error here. The third is not a condition for anything on this page.
A session shows 5 items, each clicked with probability 0.2, but clicks are positively correlated. Expected clicks?
Five indicators each with expectation 0.2 sum to 1.0 by linearity, and the correlation never enters. The first two options both assume dependence moves the mean; it moves the variance instead, and the click count will be more spread out while averaging the same. The fourth is the honest-sounding trap: the joint is exactly what linearity spares you from needing.

Practice about 15 minutes, with paper

Practice 1working

You shuffle a deck of 52 cards and deal them one at a time. A card is a "hit" if it lands in the position matching its own rank order, that is, the first card dealt is the first card of the sorted deck, or the second is the second, and so on. How many hits do you expect? Then say what makes this problem hard without linearity.

Hint

Define an indicator per position and find the probability that one particular position is a hit. Do not attempt to count arrangements or to work out how many hits are possible at once. The indicators are strongly dependent, and that is the point.

Show the worked solution
  1. One indicator per position. Let Ij be 1 if position j holds its own card.
  2. The probability for one position. By symmetry, any of the 52 cards is equally likely to land in position j, so P(Ij = 1) = 1 ÷ 52.
  3. That is its expectation. E[Ij] = 1/52.
  4. Sum by linearity. E[hits] = ∑j=152 (1/52) = 52 × (1/52) = 1.
  5. Note the answer does not depend on 52. The same argument on a deck of n cards gives exactly 1, for every n.
  6. Why it is hard otherwise. The indicators are heavily dependent: if the first 51 positions are all hits, the 52nd is forced to be one too, so you can never have exactly 51 hits.
  7. What the joint would cost. Getting this by counting means the derangement numbers and an inclusion-exclusion argument over 52 terms.
  8. What linearity cost. Four lines, and it never asked how the indicators relate to each other.

Sanity check. the answer must be a number between 0 and 52, and it must not change if you re-label the cards, since nothing in the setup distinguishes them. An answer that grows with deck size means you multiplied where you should have summed, and an answer near 0 means you computed the probability of getting at least one hit, which is a different question with the answer 1 - 1/e.

Your teacher. Next time you need an expected count of something in a system you own, resist the urge to model the whole thing. Write one indicator, find its probability, and multiply by how many there are. If that feels like cheating, re-read the proof above and find the line where dependence would have mattered.
