Three questions decide every counting problem

foundation 12 min Does order matter, is repetition allowed, and how many are you choosing. That is the whole decision.

The one-minute version

  • The multiplication rule is the only primitive: independent choices multiply.
  • C(n,k) is the ordered count divided by k!, because you counted every subset once per ordering. This page derives it rather than asserting it.
  • Pascal's rule and Σk C(n,k) = 2n both fall out of counting one collection two ways.
  • 2n is the number that makes things impossible, and it is the same number behind dropout's thinned networks, SHAP's coalitions and exhaustive feature selection.

1. One primitive, and a grid you have already run

Everything here is built from one rule: if a first choice has a options and a second has b options, independently, the pair has a × b. That is all.

You have already used it. A hyperparameter grid of 4 learning rates, 3 depths and 2 optimisers has 4 × 3 × 2 = 24 configurations, and with 5-fold cross-validation that is 120 model fits. The grid is a Cartesian product from lesson 02, and its size is the product of the sizes.

3. The binomial coefficient, derived

The middle-right leaf is the one worth deriving, because the derivation is the idea and it is the thing people forget.

  1. Count ordered selections first. Pick the first item: n ways. The second: n − 1, since one is gone. Down to the k-th: n − k + 1.
  2. Multiply. By the multiplication rule that is n(n−1)…(n−k+1), which is written n! / (n−k)!.
  3. Notice the overcount. The subset {a, b, c} was produced six times, once for each ordering of its own three members. In general each subset appears k! times.
  4. Divide it out. Every subset was counted the same number of times, so dividing the total by that number gives the number of subsets: C(n,k) = n! / (k!(n−k)!).
The step that does the work Step 3, and specifically the word every. The overcount has to be the same for every subset, or there would be no single number to divide by. That is exactly what fails when repetition is allowed - the selection {a, a, b} has fewer distinct orderings than {a, b, c} - which is why the fourth leaf of the tree needs a different formula rather than a tweak to this one.

4. Two more results from counting one thing twice

Pascal's rule: C(n,k) = C(n−1, k−1) + C(n−1, k).

Proof. Fix one particular element, call it x. Every k-subset either contains x or does not, never both, so those two cases split the whole collection with no overlap. The ones containing x are settled by choosing the other k − 1 members from the remaining n − 1, giving C(n−1, k−1). The ones without it choose all k from the remaining n − 1. Two disjoint counts add. The work is done by choosing an element to condition on, which turns one hard count into two easy ones.

The subset sum: Σk=0n C(n,k) = 2n.

Proof. Count the subsets of an n-element set twice. Once by grouping them by size, which gives the left-hand sum. Once by walking the n elements and making an independent in-or-out choice at each, which by the multiplication rule gives 2 × 2 × … × 2. Two correct counts of one collection must agree. The work is done by both sides counting the same thing, and that technique - double counting - is worth a name because you will meet it again.

5. Where the counting stops being possible

The number that ends things in practice is 2n, and it is the same number in three unrelated-looking places.

The dropout paper states it exactly: "A neural net with n units, can be seen as a collection of 2n possible thinned neural networks. These networks all share weights so that the total number of parameters is still O(n2), or less." That one sentence carries a counting claim and an asymptotic claim, and the second is lesson 09's subject.

SHAP is the same count with a cost attached: an exact Shapley value sums over every subset of the other features, so a model with M features needs 2M evaluations. And exhaustive feature selection over d candidates is the power set of lesson 02, which is the same number a third time.

6. Where the factorials go when you are not counting

SHAP's attribution weight is made of nothing but factorials, and working it once shows what they are doing.

φi = ΣS [ |S|! (|F| − |S| − 1)! / |F|! ] × [ f(S ∪ {i}) − f(S) ] Read as: feature i's attribution is a weighted average, over every subset S of the other features, of how much adding i to S changes the prediction. F is the set of all features, |S| is how many are in S, and the bracketed fraction is the weight.
  1. Fix a size and count the subsets. With |F| = 15, the subsets of the other 14 that have exactly 7 members number C(14,7) = 3,432.
  2. Compute one weight. 7! × 7! / 15! = 1.9425e-5.
  3. Multiply for the layer's share. 3,432 × 1.9425e-5 = 0.06667.
  4. Recognise the number. That is 1/15, exactly. And it is 1/15 for every size from 0 to 14, because C(14,s) × s!(14−s)!/15! collapses to 14!/15! whatever s is.
  5. Add them up. Fifteen sizes, each contributing 1/15, totalling exactly 1 - which is what a weighted average has to do.
Sanity check. The weights sum to 1. If yours do not, either the subset count or the factorial is wrong, and this is the cheapest possible test of both. What changes if the model gains a feature: the coalitions double to 216 and each layer's share becomes 1/16.

The cost is the same count from the outside. At 1 ms per model evaluation, 15 features is 32,768 coalitions and about 33 seconds for a single explanation; 20 features is 1,048,576 and about 17.5 minutes. That is why approximate Shapley methods exist at all.

That is the theorem tested rather than believed. It then verifies Pascal's rule across thirteen rows, checks the SHAP weights sum to 1, and prints how long enumeration would take at one nanosecond per subset: 230 is about a second, 260 is about 36.5 years.

Check yourself

Retrieval practice

Answer from memory before revealing.

The dropout paper says a net with n units is a collection of how many thinned networks?
Dropout keeps or drops each unit independently, which is a subset, so the count is 2 to the n. The second option is the paper's parameter count, O(n squared), stated in the very same sentence, which is what makes it the strongest distractor here. The third counts orderings and the fourth counts pairs, and neither is what "which units survived" describes.
How many ways can you choose 3 validation folds from 10 when order does not matter?
Order does not matter and repetition is not allowed, which is the middle-right leaf of the tree. The first option is the ordered count and is exactly 3! = 6 times too big, which is the overcount section 3 divides out. The second allows both order and repetition. The third has n and k swapped, which is worth checking whenever an answer looks surprisingly large.

Practice about 15 minutes, with paper

Practice 1foundation

You are budgeting a search before you launch it.

(a) A grid of 4 learning rates, 3 depths and 2 optimisers, evaluated with 5-fold cross-validation. How many model fits?
(b) Instead you decide to try every subset of 12 candidate features. How many fits, and at 2 seconds each, how long?
(c) How many of those subsets use exactly 5 features?
(d) Check that the counts by size add up to your answer to (b).

Hint

(a) is the multiplication rule and (b) is the power set. For (c), walk the decision tree in section 2 before reaching for a formula: does the order of the five features matter?

Show the worked solution
  1. Multiply the grid. 4 × 3 × 2 = 24 configurations, each fitted 5 times, so 24 × 5 = 120 fits.
  2. Recognise (b) as a power set. Each of the 12 features is in or out, independently, which is 12 independent two-way choices: 212 = 4,096 subsets.
  3. Convert to time. 4,096 × 2 s = 8,192 seconds, which is about 2.3 hours - for a search over twelve features.
  4. Walk the tree for (c). A feature set is unordered, and a feature cannot appear twice, so it is the C(n,k) leaf.
  5. Evaluate. C(12,5) = 12! / (5! × 7!) = 792.
  6. Check (d). The counts by size are 1, 12, 66, 220, 495, 792, 924, 792, 495, 220, 66, 12, 1, and they total 4,096, matching (b) exactly. That is the subset sum from section 4.

Sanity check. The answer to (c) must be much smaller than (b): one size cannot outnumber all thirteen sizes together. And the size counts must be symmetric, because choosing which 5 features to keep is the same act as choosing which 7 to drop - if your list is lopsided, recheck it.

Your teacher. The derivation in section 3 matters more than the formula, because the formula is on every reference card and the reason for the k! is not. If you want to test whether it landed, ask an agent to "count the ways to pick 3 letters from A B C D allowing repetition, list them all, and show why dividing the ordered count by 3! gives the wrong answer here" - seeing the division fail is what fixes when it works.
