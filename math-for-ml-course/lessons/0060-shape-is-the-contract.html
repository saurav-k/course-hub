Everything is a rectangular array, and its shape is the first thing to read

foundation 8 min The container the whole of machine learning is built out of, and the one rule that quietly changes what your arithmetic means.

The one-minute version

  • A scalar, a vector, a matrix and a tensor are one container seen at four sizes. The only thing that changes is how many axes it has.
  • An axis is a question, not an index. Reading a shape means saying what each axis counts.
  • Broadcasting is a rule with a definition, not a convenience. Two axes are compatible when they are equal or one of them is 1.
  • The dangerous failure here is silent: a wrong shape usually produces a wrong-shaped answer rather than an error.

One container, four names

There is a temptation to learn four separate objects here, each with its own notation and its own rules. That is not what is going on. There is one object, an array of numbers laid out on a regular grid, and the four names record only how many axes that grid has.

A scalar is a single number and has no axes at all. A vector has one axis, so one index reaches an entry. A matrix has two, so it takes two indices. A tensor, in the sense every machine-learning library uses the word, is the general case: Goodfellow, Bengio and Courville define it as "an array of numbers arranged on a regular grid with a variable number of axes". Variable is the operative word. Zero axes is a legal number of axes, so a scalar is a tensor too, and a library will tell you so.

Physics uses the word tensor for something stricter, an object defined by how it transforms under a change of coordinates. The two meanings share an ancestor and are not the same. In this course, and in every library you will use, a tensor is an n-dimensional array.

An axis is a question

The shape of an array is the tuple of its axis lengths, and it is the first thing to look at, before any value. The reason is that an axis length is an answer to a question, and if you cannot say what the question was, you cannot say what the arithmetic will mean.

Take the activations flowing through one layer of a language model. Their shape is written (batch, seq, d_model), and the three numbers answer three different questions: how many sequences are being processed at once, how many tokens are in each, and how many numbers describe each token. At the sizes GPT-3 uses, a context window of 2,048 tokens and a model width of 12,288, a single sequence's activations for one layer are 25,165,824 numbers, which is 50.3 MB in half precision. Nothing about that is visible in the values. It is all in the shape.

The same reading applies to a data table, and it is the convention this module ends on. A row is one sample and a column is one feature, so X[0, :] is one house and X[:, 0] is one measurement taken across every house.

Broadcasting is a rule, and it fails quietly

Arrays of different shapes can often be combined, and the rule that decides how is called broadcasting. It is worth learning as mathematics rather than as a library habit, because it is where the expensive mistakes live.

NumPy states the rule as a comparison that runs from the trailing axis leftwards. Two axes are compatible when they are equal, or when one of them is 1. An axis of size 1 is stretched to match the other. A missing axis is treated as size one, so an array with fewer axes is lined up from the right.

(4, 1) against (4,)  →  (4, 1) against (1, 4)  →  (4, 4) Read as: the shorter shape gains a leading axis of size 1, then each axis of size 1 is stretched to match the other operand. The first shape's second axis stretches from 1 to 4, and the second shape's new first axis stretches from 1 to 4, so the result has four rows and four columns.

That single line is the most common silent bug in this territory. A column of four numbers minus a row of four numbers is not four numbers. It is a four by four table of every difference, and nothing raises an error. The arithmetic ran, the answer has a shape, and the shape is not the one you wanted.

The error message you get is a gift. Centring a data matrix with X - X.mean(axis=1) raises ValueError, which is helpful. Writing X - X.mean(axis=1, keepdims=True) runs perfectly and centres every sample instead of every feature, which is silent and wrong. Print the shape.

A worked example, in eight steps

The dataset is housing.csv, generated for this course: 20,000 houses and five measurements each.

  1. Name the objects. X is the data matrix. n is the number of samples and d the number of features, so X has shape (n, d).
  2. Read the shape. X.shape is (20000, 5). The first axis counts houses, the second counts measurements.
  3. Take one of each. X[0, :] is five numbers describing one house. X[:, 0] is 20,000 numbers describing one measurement.
  4. Ask for the feature means. X.mean(axis=0) collapses the sample axis, so five numbers survive, one per feature. Its shape is (5,).
  5. Centre correctly. X - X.mean(axis=0) lines (5,) up against the trailing axis of (20000, 5). They match, so the means are subtracted column by column. The largest surviving column mean is 1.16e-13, which is zero to floating point.
  6. Centre incorrectly. X.mean(axis=1, keepdims=True) has shape (20000, 1). Subtracting it also works, because 1 stretches to 5, and it removes each house's own average of five unrelated quantities. The largest column mean afterwards is 5,272.5, so nothing was centred.
  7. Check the rule itself. Expanding both operands by hand with np.repeat and subtracting gives exactly the array broadcasting produced, entry for entry.
  8. Say what would change. If the table were stored transposed, as features by samples, every axis in the steps above flips. Nothing else about the mathematics changes, which is why the convention has to be stated and then held.
code/0060-shape-is-the-contract.py · NumPy and Pandas only · download
import numpy as np
import pandas as pd

frame = pd.read_csv("../datasets/housing.csv")
X = frame[["area_k_sqft", "bedrooms", "bathrooms", "age_years", "lot_sqft"]].to_numpy(float)

print(X.shape)                      # (20000, 5)
print(X.mean(axis=0).shape)         # (5,)   one mean per feature
print(X.mean(axis=1).shape)         # (20000,) one mean per house

areas = X[:8, 0]                    # shape (8,)
column = areas.reshape(8, 1)        # shape (8, 1)
print((areas - areas).shape)        # (8,)   what you meant
print((column - areas).shape)       # (8, 8) what you get, silently

The full program prints the shapes above, then checks NumPy's broadcast against an expansion written out with np.repeat, and confirms the two agree entry for entry.

Retrieval practice

Answer from memory before revealing.

An array c has shape (4, 1) and an array r has shape (4,). What is the shape of c - r?
Shapes are compared from the trailing axis leftwards and an axis of size 1 is stretched, so (4, 1) against (4,) becomes (4, 4). The first option is what you almost certainly meant and is not what you get. The second is a shape this rule never produces here. The fourth is the outcome you would want, and the reason this is dangerous is precisely that it does not happen.
In a machine-learning library, what is a scalar?
A tensor is an array on a grid with any number of axes, and zero is a legal number, so a scalar is the zero-axis case. The second describes a length-one vector, which has a different shape and a different index. The third has two axes and a library will not treat it as a scalar. The fourth is the physics reading of the word, which is a different concept that happens to share the name.
Practice

A model has d_model = 4096 and processes a batch of 16 sequences of 1,024 tokens each.

  1. Give the shape of one layer's activation tensor, and say what each axis counts.
  2. How many numbers is that?
  3. How much memory does it take in half precision, in megabytes?
  4. The code then runs activations - activations.mean(axis=1). What does that subtract, and is it what someone centring the features wanted?
Hint

Read each axis as a question before multiplying anything. For part 4, work out the shape of the mean first, then line it up against the trailing axis of the original.

Solution
  1. (16, 1024, 4096): sequences in the batch, tokens in each sequence, numbers describing each token.
  2. 16 × 1024 × 4096 = 67,108,864 numbers.
  3. Half precision is two bytes each, so 134,217,728 bytes, about 134.2 MB for one tensor in one layer.
  4. axis=1 is the token axis, so it subtracts each sequence's average over its own positions. The mean has shape (16, 4096), which cannot line up against (16, 1024, 4096) from the right, so this particular line raises an error. Adding keepdims=True makes it run and centre the wrong axis. Centring features means collapsing the axis that counts samples, and here that is a reshape away.

Sanity check: your answer to part 3 should be exactly twice part 2 in bytes, and a tensor that big is why activation memory, not weights, is often what runs a training job out of memory.

Your teacher. If step 6 of the worked example did not land, ask an agent to print X.mean(axis=0).shape and X.mean(axis=1, keepdims=True).shape side by side and then to show which axis each one collapsed. Seeing the two shapes next to each other is usually the whole explanation.
