A kernel is a dot product in a space you never build

frontier 13 min Cortes and Vapnik, Support-Vector Networks (Machine Learning 20, 1995), section 4.

The one-minute version

  • A kernel is an inner product in some feature space: k(x, z) = phi(x) . phi(z). No approximation is involved.
  • If an algorithm touches its inputs only through dot products, you may substitute any kernel and it becomes non-linear.
  • You never compute phi. For 256 inputs at degree 4 that space has 186 million coordinates and the kernel costs 259 multiplications.
  • The legality condition is that the Gram matrix is positive semi-definite, which is Module 04's eigenvalue test.
  • The bill arrives elsewhere: the Gram matrix is n by n, so you have traded a dimension problem for a sample-size one.

1. Data no line can separate

Two concentric rings of points in the plane, one class on each ring. No straight line separates them, and no amount of fitting will change that: a linear model in two dimensions has three parameters and this problem needs a circle.

Add a coordinate. Send each point (x1, x2) to the third value x12 + x22, its squared distance from the origin. The inner ring now sits low and the outer ring sits high, and a horizontal plane separates them cleanly. Project the plane back down and its shadow in the original picture is a circle.

So far this is just feature engineering, and it has an obvious cost: you had to invent the feature, and you had to compute and store it for every point. For a degree-two map on 256 inputs that means thirty-three thousand numbers per row. The kernel trick removes both costs at once.

2. Two routes to one number

Take the feature map that squares everything, in two dimensions, together with its cross term and its linear part.

φ(x) = ( 1, √2 x1, √2 x2, x12, √2 x1x2, x22 ) Read as: the feature map sends a two-dimensional point to a six-dimensional one made of the constant 1, the two original coordinates each multiplied by the square root of two, the two squares, and the cross term also multiplied by the square root of two. Those square roots look arbitrary and are not: they are exactly what makes the next line come out clean.

Now compute φ(x) · φ(z) for x = (2, 1) and z = (1, 3), and compute (x · z + 1)2 as well.

k(x, z) = φ(x)Tφ(z) Read as: a kernel function k of two inputs is defined to be the ordinary dot product of their images under some feature map φ. The map may go anywhere, including into an infinite-dimensional space; all that is required is that the dot product on the right exists.

Now the substitution. Bishop states it as plainly as it can be stated: if an algorithm is written so that the input enters only in the form of scalar products, you can replace that scalar product with any kernel. Nothing else in the algorithm changes. Support vector machines, ridge regression, principal component analysis and nearest-neighbour classification all qualify; anything that inspects individual coordinates does not.

3. Which functions are legal

You cannot invent any symmetric similarity you like and call it a kernel. If no feature space exists, the substitution is not licensed, and the failure is not cosmetic: the optimisation problem stops being convex and a solver can return something meaningless without complaining.

The theorem. If k(x, z) = φ(x) · φ(z) for some map φ, then for any finite set of points the Gram matrix K with entries Kij = k(xi, xj) is symmetric and positive semi-definite.

  1. Symmetry is immediate. The dot product does not care about order, so Kij = Kji.
  2. Take any real vector c and write out the quadratic form: cTKc = ∑i∑j cicj φ(xi) · φ(xj).
  3. Move the sums inside. The dot product is bilinear, so this equals ( ∑i ciφ(xi) ) · ( ∑j cjφ(xj) ). This is the step that does the real work, and after it there is nothing left to do.
  4. Recognise it. That is a vector dotted with itself, which is a squared length, which cannot be negative.

The whole proof is four lines and it has an operational payoff: "is my similarity function legal" becomes "compute the eigenvalues of the Gram matrix and look for a negative one", which is Module 04's test applied to a matrix of similarities. The program does exactly that on four hundred real rows.

The converse is a harder theorem and this course states it rather than proving it. Mercer's theorem says a continuous symmetric function satisfying an integral positivity condition is a dot product in some feature space. That direction needs the spectral theory of integral operators, which is beyond this course. The direction proved above is the one an engineer uses, because it is the one that turns a question into an eigenvalue check.

4. Three kernels worth knowing

Linear. k(x, x′) = x · x′. The feature map is the identity. Useful as the base case and as a sanity check.

Polynomial. k(x, x′) = (x · x′ + 1)d, which is Cortes and Vapnik's equation 37. Its feature space is every monomial of degree at most d, and the count of those is what section 5 measures.

Radial basis. k(x, x′) = exp(−γ|x − x′|2). Its feature space is infinite-dimensional. Its ancestor is the potential function exp(−|u − v|) of Aizerman, Braverman and Rozonoer in 1964, which Cortes and Vapnik cite as equation 36.

The reframing The RBF kernel is a function of |x − x′|, which is lesson 185's Euclidean distance wearing a different hat. So every warning on that page applies to it: it is dominated by whichever column has the largest scale, and standardising before using it is not optional. Everything lesson 188 is about to say about high dimensions applies to it too.

5. Worked: the identity, then the economics

  1. Take two points. x = (2, 1) and z = (1, 3).
  2. The kernel route. x · z = 2 + 3 = 5, so k = (5 + 1)2 = 36. Two multiplications, one add, one square.
  3. The explicit route, first vector. φ(x) = (1, 2.8284, 1.4142, 4, 2.8284, 1).
  4. Second vector. φ(z) = (1, 1.4142, 4.2426, 1, 4.2426, 9).
  5. Dot them. 1 + 4 + 6 + 4 + 12 + 9 = 36. The same integer, six multiplications in a bigger space.
  6. Sanity check. The kernel is a square, so it cannot be negative. If the explicit route ever disagrees with the kernel route, the usual cause is writing x1x2 where the map needs √2 x1x2, which puts the cross term out by a factor of two.
  7. What changes if the inputs are 256-dimensional? The number of monomials of degree at most d in n variables is C(n + d, d). At d = 2 that is C(258, 2) = 33,153. At d = 4 it is 186,043,585. The kernel route costs 256 multiplications plus a handful, at every degree.
  8. Read it back. At degree 4 the ratio is about 718,000 to one, and it keeps growing while the kernel column does not move at all. That is the trick, quantified.

And on a real problem, from Cortes and Vapnik's own table 2: US Postal Service digits, 16 by 16 pixels, 7,300 training and 2,000 test patterns, input dimension 256.

A discrepancy worth owning. The paper's "about 33,000" for degree 2 matches C(258, 2) = 33,153 exactly. Its 109 for degree 4 and 1016 for degree 7 do not match C(260, 4) = 186,043,585 and C(263, 7) = 1.59 × 1013. The figures in the chart are theirs, marked as quoted; the exact monomial counts are this page's own arithmetic and are marked as derived. They are order-of-magnitude claims and the conclusion is unaffected, but a course that quietly reconciles two sources teaches you not to check.

6. What the trick costs

Nothing is free. The kernel route replaces every dot product with a kernel evaluation, and a method written in dual form needs all of them: the Gram matrix has one entry per pair of training points.

At six hundred training points, which is the ring problem the program solves, that is 360,000 entries and a system you solve in milliseconds. At a million training points it is 1012 entries, which is eight terabytes at double precision before you try to invert anything.

So kernel methods trade a dimension problem for a sample-size problem. That trade was excellent in 1995, when datasets had thousands of rows and features were hand-designed, and it is the honest reason deep networks displaced them: a network's cost grows with its parameters, not with the square of the dataset. Random-feature methods exist to approximate a kernel in linear time and are the standard answer when you want the trick at scale.

code/0187-kernels.py · NumPy and Pandas only · download
K = rbf_kernel(train, train, gamma)                  # 600 by 600
alpha = np.linalg.solve(K + lam * np.eye(split), y_train)
kernel_pred = np.sign(rbf_kernel(test, train, gamma) @ alpha)
# linear ridge in the input space : accuracy 0.6650
# kernel ridge with an RBF kernel : accuracy 1.0000

Six lines, no feature vector ever formed, and the ring problem goes from 66.5 per cent to 100 per cent. The same six lines at a million rows do not run at all.

Check yourself

Retrieval practice

Answer from memory before revealing.

What does the kernel trick let you avoid doing?
The feature vector is never built, never stored and never multiplied. The first option inverts the situation: the kernel is a dot product, in a different space. The second is the opposite of true, and it is the trade-off in section 6: a dual method keeps the training points and needs them at prediction time. The third confuses the kernel substitution with the choice of solver, which is untouched by it.
Which condition must a proposed similarity function satisfy to be a valid kernel?
Positive semi-definiteness is the condition, and it is checkable by taking eigenvalues. The third option is the trap: symmetry is necessary and not sufficient, and the tanh function in section 3 is symmetric with an eigenvalue of minus 42.66. The first describes the RBF kernel and is not required of kernels in general, since the polynomial kernel grows with the dot product. The fourth is false of both the polynomial and the linear kernel.

Practice about 12 minutes, with paper

Practice 1frontier

Inputs are two-dimensional. x = (3, 1) and z = (2, 2).

Find k = (x · z + 1)2 directly, then write out φ(x) and φ(z) and verify the same number. Finally, someone proposes s(x, z) = 1 / (1 + |x − z|) as a similarity: say what you would run to decide whether it is a valid kernel, and what result would rule it out.

Hint

The six coordinates of the map are the constant, the two linear terms each scaled by the square root of two, the two squares, and the cross term also scaled by the square root of two.

Show the worked solution
  1. The dot product. x · z = 6 + 2 = 8.
  2. The kernel. (8 + 1)2 = 81.
  3. First feature vector. φ(3, 1) = (1, 4.2426, 1.4142, 9, 4.2426, 1).
  4. Second feature vector. φ(2, 2) = (1, 2.8284, 2.8284, 4, 5.6569, 4).
  5. Dot them, term by term. 1 + 12 + 4 + 36 + 24 + 4 = 81.
  6. What to run on the proposal. Take a few hundred of your own rows, build the matrix Sij = s(xi, xj), and compute its eigenvalues with numpy.linalg.eigvalsh.
  7. What rules it out. Any eigenvalue meaningfully below zero. There is then no feature space, so the substitution is not licensed and any convexity guarantee your solver relied on is gone.
  8. What does not rule it out. A single eigenvalue of order −10−13, which is rounding, exactly as in the chart in section 3 where two genuine kernels show small negative values.

Sanity check. Steps 2 and 5 must give the same integer, not two numbers that are close. If they differ, compare your cross term against 24: writing x1x2 instead of √2 x1x2 in both vectors halves that term and leaves you at 69.

Your teacher. If section 3 did not land, ask an agent to build the Gram matrix of the cosine similarity on a few hundred of your own vectors and take its eigenvalues, then do the same for one minus the cosine. The first is a valid kernel and the second is not, and seeing where the negative eigenvalue appears is more convincing than the proof.
