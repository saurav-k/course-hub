A random variable is neither random nor a variable

foundation 9 min It is a function from outcomes to numbers, and the name is the only hard part. · Hajek, ECE 313, sections 2.1 and 3.1

The one-minute version

  • A random variable is a function from the sample space to the real numbers. It is fixed and deterministic.
  • The randomness lives entirely in which outcome gets drawn, never in the function.
  • Writing it as a function is what earns you probabilities: {X ≤ c} is a subset of Ω, so it is an event.
  • One sample space carries many different random variables, because it carries many different questions.
  • "Gradient noise" means the gradient is a function of which minibatch you drew. That is all it means.

1. The name is wrong, so deal with it first

X : Ω → ℝ Read as: X is a function whose input is an outcome from the sample space Ω and whose output is a real number. ℝ is the set of real numbers. That is the entire definition, and there is nothing probabilistic in it.

X is not random. Hand it the same outcome twice and it returns the same number twice. X is not a variable either, in the sense you know from programming: it does not hold a value and it is not reassigned. It is a rule.

The randomness is upstream. Something draws an outcome from Ω, and that draw is the only random thing in the picture. X then does what functions do.

2. Why writing it as a function buys anything

Here is the payoff, and it is the reason the definition is worth the awkward name.

When you write P{X ≤ 7}, that is shorthand. Written out, it means P({ω : X(ω) ≤ 7}), which is the probability of the set of outcomes whose value is at most 7. That set is a subset of Ω. A subset of Ω is an event. Events have probabilities, by Lesson 121.

The reframing Every probability statement about a number is secretly a statement about a set of outcomes. The function is what carries you back and forth, and that trip is called taking the preimage.

3. One world, many questions

A sample space does not come with a random variable attached. You choose one, and the choice is the question you are asking.

Notice that Y is a function of X, not of the rows directly. Functions of random variables are random variables too, which is the move Lesson 133 makes when it standardises a normal.

4. Worked: counting flags in a minibatch

Split the 25,000-row log into consecutive batches of 256, dropping the last 168 rows so every batch is the same size. That gives 97 batches, and no flagged request falls in the dropped tail, so all 99 are accounted for.

Let X be the number of flagged requests in a batch. So Ω is the set of 97 batches, and X maps each one to a whole number.

  1. Apply the function to every outcome. Counting flags in each batch gives 37 batches with 0, 34 with 1, 16 with 2, 7 with 3 and 3 with 4.
  2. Check nothing was lost. 37 + 34 + 16 + 7 + 3 = 97 batches, and 0×37 + 1×34 + 2×16 + 3×7 + 4×3 = 99 flags. Both totals close.
  3. Turn counts into proportions. 37 ÷ 97 = 0.3814, then 0.3505, 0.1649, 0.0722 and 0.0309.
  4. Take the average value. 99 ÷ 97 = 1.0206 flagged requests per batch.
  5. Take a preimage. {X = 3} is the set of batches numbered 27, 29, 50, 53, 59, 77 and 86. Seven outcomes out of 97, so P(X = 3) = 0.0722. The probability came from counting outcomes, exactly as Lesson 122 said it would.

Sanity check. The proportions must sum to 1 and the total flags recovered from the distribution must be the 99 you started with. Both hold, so no request was double counted or lost.

What changes if you use batches of 1,024. The same 99 flags now land in 24 batches, so P(X = 0) collapses from 0.3814 to 0.0417 and the mean rises from 1.0206 to 4.1250. The world did not change. The function did. A distribution is always a distribution of some particular function, and changing the batch size changes the question you asked.

5. Where this bites: gradient noise is a function of the draw

Three quantities you already work with are random variables, and naming them as such makes their behaviour ordinary rather than mysterious.

  • The minibatch gradient. Ω is the set of possible minibatches; the function maps a batch to the gradient it produces. Different draw, different gradient. That is what "gradient noise" is, and it is why the loss curve moves when the seed does.
  • Validation accuracy under a seed. Ω is the set of seeds, and the function is the entire training run followed by evaluation. Deterministic given the seed, and a random variable across seeds.
  • The loss on one example. Ω is the data distribution and the function is the loss. Training minimises its average, which is Module 08's subject.
Naming these as functions on a sample space is what makes questions about them well posed. "Is this model better?" is not answerable until you say which sample space you are averaging over: across seeds, across test sets, or across both. Reporting one number from one seed is reporting one value of a random variable, which is the same mistake as reading a rate off ten rows in Lesson 120.

6. The function, applied two ways

code/0127-random-variables.py · NumPy and Pandas only · download
def apply_the_function_one_batch_at_a_time(flags, batch):
    """X(omega) for each batch omega, counted row by row."""
    values = np.empty(len(flags) // batch, dtype=int)
    for index in range(len(values)):
        total = 0
        for row in flags[index * batch:(index + 1) * batch]:
            total += int(row)
        values[index] = total
    return values


def apply_the_function_vectorised(flags, batch):
    """The same function, computed for every outcome at once."""
    n = len(flags) // batch
    return flags[: n * batch].reshape(n, batch).sum(axis=1)


assert np.array_equal(by_loop, vectorised)

The assertion is element-for-element, not just equal in distribution. The vectorised form is the same function on the same outcomes, and the loop is there so you can see it being applied.

Check yourself

Retrieval practice

Answer from memory before revealing.

In a random variable, which part is actually random?
The function is fixed and deterministic, and so is its output once you know the outcome. Only the draw of the outcome is random. The first option is the natural misreading, and it is worth being precise about: the output varies across outcomes, which is not the same as being random given one. The second and third invent randomness in the rule, which would make the whole framework unusable.
Why does the expression P{X ≤ 7} have a probability at all?
Probabilities are assigned to events, and events are subsets of the sample space, so the expression works because the preimage is such a subset. The second option is true and does not answer the question: mapping into the reals is what makes the inequality writeable, not what makes it probable. The fourth reverses the order - the distribution is derived from the function and the underlying probabilities, not assumed before them.

Practice about 10 minutes, with paper

Practice 1foundation

Using the same 97 batches, define Y to be 1 when a batch contains at least one flagged request and 0 otherwise.

Write down what Y is as a function, give its distribution, and say what Y throws away that X kept.

Hint

Y is a function of X rather than of the rows. Work out which values of X map to 1, and the rest is one subtraction.

Show the worked solution
  1. Write the rule. Y = 1 exactly when X is at least 1, and Y = 0 exactly when X = 0. So Y is the composition of X with the rule "is this positive".
  2. Count the zeros. X = 0 on 37 batches, so Y = 0 on 37 batches.
  3. Count the ones. The remaining 97 − 37 = 60 batches, so Y = 1 on 60.
  4. Give the distribution. P(Y = 0) = 37 ÷ 97 = 0.3814 and P(Y = 1) = 60 ÷ 97 = 0.6186.
  5. Say what was lost. Y throws away how many. A batch with four flagged requests and a batch with one are indistinguishable to Y, and both map to 1.

Sanity check. P(Y = 0) must equal P(X = 0) exactly, because those describe the same 37 batches by two different routes. If they differ, the mapping was applied wrongly. Notice also that the two probabilities sum to 1, as they must for a function with only two possible values - which is the Bernoulli distribution of Lesson 129, arriving early.

Your teacher. When a random variable confuses you, write down Ω first, in words, out loud: "the set of possible minibatches", "the set of seeds". Nine times in ten the confusion was that two people had different sample spaces in mind and neither said so. Ask an agent for three different random variables defined on the outcome of rolling two dice, and check that all three really are functions on the same 36 outcomes.
