One line of a paper needs every module in this course

foundation 12 min The line is from Vaswani et al. (2017), section 3.2.1. · arXiv:1706.03762

The one-minute version

  • A single line of the Transformer paper contains five different subjects at once, and this course is those five subjects.
  • You are not missing intelligence. You are missing the meaning of about forty symbols, and symbols are learnable in a way that talent is not.
  • Every page here gives you a picture before the formula, a number worked by hand, and a problem you solve yourself.
  • Every result also ships as a program you can point at real data, because a result you cannot compute is a result you do not own.

The line

Here is the whole of attention, the mechanism underneath every large language model in this hub. It is one line.

Attention(Q, K, V) = softmax( Q Kᵀ / √dk ) V Q, K, V: three matrices, called queries, keys and values. Each row is one token's vector. Kᵀ: K transposed, so its rows become columns. Q Kᵀ: every query vector dotted with every key vector, giving a grid of relevance scores. dk: the width of a key vector, a plain whole number. √dk: its square root, used to shrink the scores. softmax: a function that turns a row of scores into positive weights that add up to 1. V: multiplying by it uses those weights to average the value vectors.

Read the gloss rather than the line. That is the point of this page: nothing in that formula is difficult, and all of it is unfamiliar. Now watch where each piece comes from.

What softmax actually does

Take the one piece that is a genuine function and do it by hand. Four scores go in, four weights come out.

  1. Raise e to each score. e2 = 7.3891, e1 = 2.7183, e0 = 1.0000, e-1 = 0.3679. Every one is positive, which is the whole trick: the exponential cannot return a negative number.
  2. Add them. 7.3891 + 2.7183 + 1.0000 + 0.3679 = 11.4752.
  3. Divide each by that total. 7.3891 ÷ 11.4752 = 0.6439, then 0.2369, then 0.0871, and finally 0.0321.
  4. Check the total. 0.6439 + 0.2369 + 0.0871 + 0.0321 = 1.0000, because every part was divided by the sum of all the parts.
What changes if the scores move together. Add 5 to all four scores and the weights do not move at all. Every exponential is multiplied by e5, top and bottom, and it cancels. Only the gaps between scores matter, never their level, and two scores one apart always end up in the ratio e = 2.7183. Here 0.6439 ÷ 0.2369 = 2.7180, and the 3 in the last place is lost to the rounding in the four weights above, not to the mathematics: carried at full precision the ratio is e to every digit.

Why the same line has a program

Four numbers fit on a page. Real ones do not, and a result you have only ever seen at the size of four numbers is a result you cannot use. So every named result in this course also arrives as a program you can point at a real table.

That cancellation above is not a curiosity. It is the one thing standing between the formula and an arithmetic failure, because e800 is larger than a 64-bit float can hold. Subtracting the biggest score from all of them first changes no answer and removes the overflow.

code/0000-one-line-of-a-paper.py · NumPy and Pandas only · download
def softmax_from_the_definition(scores):
    weights = np.exp(scores)                     # exactly what the formula says
    return weights / weights.sum(axis=1, keepdims=True)

def softmax_the_way_libraries_do_it(scores):
    shifted = scores - scores.max(axis=1, keepdims=True)   # same answer on paper
    weights = np.exp(shifted)
    return weights / weights.sum(axis=1, keepdims=True)

Run against the 12,000 by 8 table in datasets/sensors.csv, the two agree to 2.220e-16. That is machine epsilon, the gap between 1.0 and the next number a 64-bit float can represent, so the two methods are as close as this arithmetic can tell. Multiply the scores by 300 and they stop agreeing.

This is also why the line divides by √dk. Large dot products are exactly what produce large scores, and large scores are what break the exponential. The square root in the original formula is doing the same defensive job as the shift in the code, one step earlier.

Check yourself

Retrieval practice

Answer from memory before revealing.

Why does softmax raise e to each score before dividing?
Dividing by a sum only gives a valid set of weights if nothing is negative, and the exponential is what guarantees that. The first is wrong because softmax is deliberately soft, and every score keeps a share. The second is false, and it would not be a mathematical reason anyway. The fourth confuses the constraint: the outputs sum to exactly 1, not to less than 1.
Adding 5 to all four scores changes the softmax weights how?
Every exponential is multiplied by e to the fifth, in the numerator and in the denominator, so it cancels exactly. The second forgets that the weights must still total 1, so they cannot all rise. The third and fourth both assume the level of the scores matters, but adding a constant changes no gap, and only gaps move a softmax.

Practice about 10 minutes, with paper

Practice 1foundation

A model scores three candidate next tokens:

s = ( 3, 1, 1 ) Read as: three raw scores, one per candidate token. They are ordinary real numbers and nothing yet requires them to be positive or to add to anything in particular.

Find the three softmax weights, and then say what happens to them if every score is doubled rather than shifted.

Hint

Two of the scores are equal, so two of the weights must be equal too. That is one answer you can write down before doing any arithmetic, and it is a check on the other two.

Hint for the second half

Doubling is not the same move as adding a constant. Adding shifts every score by the same amount; doubling changes the gaps between them. Only one of those cancels.

Show the worked solution
  1. Exponentiate each score. e3 = 20.0855, e1 = 2.7183, e1 = 2.7183.
  2. Add them. 20.0855 + 2.7183 + 2.7183 = 25.5221.
  3. Divide each by the total. 20.0855 ÷ 25.5221 = 0.7870, and 2.7183 ÷ 25.5221 = 0.1065 twice over.
  4. Check the total. 0.7870 + 0.1065 + 0.1065 = 1.0000.
  5. Now double the scores to (6, 2, 2). e6 = 403.4288, e2 = 7.3891 twice, totalling 418.2070. The weights become 0.9647, 0.0177 and 0.0177.
  6. Name what happened. Doubling widened every gap, so the distribution got sharper and moved towards putting everything on the winner. Shifting would have changed nothing.

Sanity check. Two equal scores must give two equal weights, and they do. The largest weight has to sit between one third, which is what three equal scores would give, and 1, which is what an infinitely large gap would give. 0.7870 sits between them, and after doubling 0.9647 sits closer to 1, which is the direction a wider gap must push it.

Your teacher. If the exponential step is the part that did not land, ask an agent: "show me e to the x for x from -2 to 2 as a table, and tell me why it is never negative". If it was the transpose, ask it to write out a 2 by 3 matrix and its transpose side by side with the indices labelled. Both are built properly in Modules 01 and 03.
