Glossary

The canonical vocabulary for the inference course. Every lesson uses these terms as defined here.

Phases and latency

Prefill - the phase that processes the whole input prompt in one parallel pass and builds the KV cache. Compute-bound.

Decode - the phase that generates output tokens one at a time, each re-reading weights and the KV cache. Memory-bandwidth-bound.

TTFT - Time To First Token. The initial wait a user feels; dominated by prefill and queueing.

TPOT / ITL - Time Per Output Token (a.k.a. inter-token latency). The steady gap between streamed tokens during decode.

Throughput - total tokens per second served across all concurrent requests.

Goodput - requests per second that actually met their latency target (SLO). The number that matters for a product.

SLO / SLA - the latency/availability target you promise (e.g. p95 TTFT < 500 ms).

Roofline - a model of whether a kernel is limited by compute (FLOPs) or memory bandwidth (bytes moved).

Memory and cache

KV cache - stored keys and values of past tokens, reused during decode to avoid recomputation. Grows with context length and batch size.

PagedAttention - vLLM's KV cache manager that stores the cache in fixed-size non-contiguous blocks (pages), eliminating fragmentation and enabling sharing.

Prefix caching - reusing the KV cache of a shared prompt prefix across requests (system prompts, few-shot examples).

RadixAttention - SGLang's automatic prefix reuse via a radix tree over cached KV.

Eviction - dropping some cached tokens when the KV cache will not fit (sliding window, attention sinks, H2O).

Attention sink - keeping the first few tokens' KV permanently (StreamingLLM), which stabilises long-context decode.

Batching and scheduling

Static batching - group requests, run them together to completion. Simple, but the batch waits for the slowest member.

Continuous (in-flight) batching - add and remove requests at every decode step, so finished sequences free their slot immediately. The biggest throughput lever.

Admission control - deciding whether to accept a new request now or queue/reject it to protect latency.

Chunked prefill - splitting a long prompt's prefill into chunks interleaved with decode, so prefill does not stall streaming.

Throughput tricks

Speculative decoding - a small draft model proposes several tokens, the target model verifies them in one pass; same output distribution, fewer target steps.

Draft model - the small, fast model used to propose tokens in speculative decoding.

Self-speculation / Medusa / EAGLE - speculative methods that draft from the target model itself (extra heads or a light draft head) instead of a separate model.

Acceptance rate - the fraction of drafted tokens the target accepts; higher means bigger speedup.

Quantization

Quantization - storing weights/activations/KV in fewer bits to save memory and bandwidth.

INT4 / INT8 - 4-bit / 8-bit integer formats. FP8 - 8-bit float (E4M3/E5M2), well supported on H100.

GPTQ - post-training weight quantization using second-order (Hessian) information, layer by layer.

AWQ - Activation-aware Weight Quantization; protects the most salient weight channels based on activation scale.

Weight-only vs KV vs activation quant - which tensors you shrink; each has different quality/speed effects.

Serving stack and ops

vLLM - high-throughput serving engine built around PagedAttention and continuous batching.

SGLang - serving engine with RadixAttention and a structured-generation front end.

TensorRT-LLM - NVIDIA's compiled, highly optimised inference library for their GPUs.

ONNX Runtime - cross-platform runtime for models exported to the ONNX format.

WebLLM - running quantized models in the browser via WebGPU.

LiteLLM - a proxy/SDK giving one OpenAI-compatible interface over many providers and local servers.

Ollama / LM Studio - tools for running models locally with minimal setup.

HPA - Kubernetes Horizontal Pod Autoscaler; scales replicas on metrics (CPU, GPU, custom queue depth).

Prometheus / Grafana - metrics database and dashboarding used to monitor the golden signals.

Golden signals - latency, traffic, errors, saturation; the core things to alert on.

Economics

Cost per token / per request - GPU-hour cost divided by tokens or requests served; the unit that decides margins.

Utilization - fraction of paid GPU time doing useful work. Low utilization is where money leaks.
