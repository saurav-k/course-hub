Module 03 · Agent skills and the CLI · Lesson 0300

A skill is knowledge that costs nothing until the task needs it

working 11 min Written against the Agent Skills specification and Claude Code's own skills documentation. · The specification

The one-minute version

  • You have pasted the same procedure into a chat box four times. The fix is not a better paste, it is a file.
  • An Agent Skill is a directory holding a SKILL.md: some YAML frontmatter, then the instructions. Two fields are required and the rest is Markdown.
  • Progressive disclosure is the whole trick. Only name and description are resident at startup; the body arrives on the turn that needs it, and bundled files only when read.
  • The cost lands on the description, which is the one part you always pay for and the only part the model sees before deciding. A vague description is a skill nobody opens.

1. The fourth paste is the signal

There is a moment every daily driver of an agent recognises. You have a twelve-line procedure for cutting a release, or for writing a migration the way this team writes migrations, and you paste it into the chat box again. It works, again. And you will paste it again next week.

The obvious fix is to put those twelve lines in the repository instruction file, so they are always there. That works and it is expensive: the instruction file is prepended to every request, so a procedure you need on one turn a fortnight is now riding along on every turn forever. Anthropic's own guidance draws the line in exactly that place: create a skill "when a section of CLAUDE.md has grown into a procedure rather than a fact".

A skill is the artefact for that case. It is a directory with a SKILL.md in it, and the agent reads the body only on a turn where your request matches what the description says the skill is for.

Where a mechanism belongs to a neighbour, this course links rather than re-derives. Customization primitives in Coding Harness Engineering compares skills, subagents, hooks and modes across fifteen harnesses. This page is one reader writing one file.

2. Three stages, and only the first is always paid for

That is why the amount of material you can bundle into a skill is, as Anthropic's engineering write-up puts it, "effectively unbounded". An agent with a filesystem does not need the whole skill in its window to use it; it needs to know the skill exists, and then it can go and read.

The smallest legal skill is four lines. The specification's own minimal example:

SKILL.md · agentskills.io specification · site text, licence unstated · quoted, four lines
---
name: skill-name
description: A description of what this skill does and when to use it.
---

The directory it lives in must carry the same name as the name field, and that is the entire required contract.

4. The arithmetic, on real skills

Anthropic publishes nineteen skills in its open skills repository. Reading all nineteen at the commit current in this session, their SKILL.md files total 268,179 bytes; their nineteen descriptions total 9,384 characters. At the crude four-characters-per-token estimate that is roughly 67,000 tokens against roughly 2,300, and the second number is the one you pay for having them installed.

5. Four artefacts, four different moments

Skills are one of four things you can install, and the useful way to tell them apart is when each one is loaded and who decides.

ArtefactWhen it loadsWho invokes itCan it refuse?
Instruction file (CLAUDE.md, AGENTS.md)Every session, every turnNobody: it is always thereNo
SkillOn a description match, or when you type /nameThe model, or youNo
HookAt a named point in the loopThe harness, unconditionallyYes
SubagentWhen the main agent delegatesThe model, or youNo

Only one row of that table can stop anything, and it is not the one this module is about. A skill is context, and context asks. That limit returns in module 4, where hooks are the enforcement layer.

The listing your skills sit in is not unbounded. Claude Code caps each entry's combined description and when_to_use text at 1,536 characters, and the whole listing at a budget that scales at 1% of the model's context window; when it overflows, descriptions are dropped starting with the skills you invoke least. A skill whose description was truncated is still installed and no longer findable, and nothing in the transcript says so.

Check yourself

Retrieval practice

Answer from memory before revealing.

You install twelve skills and use none of them in a session. What did they cost that session?
The frontmatter of every installed skill is read at startup and the listing goes into every request, so twelve descriptions are the standing cost. The first option confuses the body's cost with the metadata's. The third describes the design progressive disclosure exists to avoid. The fourth invents a preloading step that no documented client performs.
A twelve-line procedure is needed on roughly one turn a fortnight. Where does it belong?
A procedure needed rarely is exactly the case the skill format exists for: pay a hundred tokens always and the body only on the turn that needs it. The first option pays for twelve lines on every request forever. The second is enforcement, not knowledge, and a hook cannot supply a procedure. The third is the habit this page is replacing, and it fails the moment somebody else has to run the procedure.

Practice about 15 minutes, with a terminal

Practice 1working

Open the last two weeks of your own agent transcripts, or your shell history, and find one procedure you have supplied more than once. Not a fact about the codebase, a procedure: a numbered sequence with a beginning and an end.

Estimate two numbers for it. First, what it would cost as a section of your instruction file, in characters, multiplied by the number of turns you take in a typical week. Second, what it would cost as a skill: its description on every turn plus its body once.

Decide which of the two is smaller, and say what would have to be true about the procedure for the answer to flip.

Hint

Four characters to a token is close enough for this. The instruction-file cost is a rectangle: characters times turns. The skill cost is a thin rectangle plus one square.

Show the worked reasoning
  1. Price the instruction file. A 900-character procedure is about 225 tokens. Across 200 turns in a week that is 45,000 tokens, every week, whether or not the procedure came up.
  2. Price the skill. A 300-character description is about 75 tokens. Across the same 200 turns that is 15,000 tokens, plus the 225-token body on the one turn it fires: about 15,225.
  3. Find the flip. The skill wins whenever the description is shorter than the procedure, which it always is, and loses only when the body is needed on nearly every turn. At that point the material is a fact about the repository rather than a procedure, and the instruction file is the right home for it.

Sanity check. Your two numbers should differ by roughly the ratio of procedure length to description length, not by orders of magnitude. If the skill came out more expensive, the thing you picked is probably a fact rather than a procedure, and moving it would be the wrong call.

Your teacher. If the three stages still feel abstract, ask your agent to list the skills it currently has available and then to tell you, for one of them, which of its files it has actually read this session. The answer is almost always "none of them, only the description", and that is the mechanism in one sentence.
