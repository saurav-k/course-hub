Module 01 · The internals of coding agents · Lesson 0170

The gap is context, permission and recovery

foundation 10 min The permission modes below are the ones Claude Code documents. · Configure permissions

The one-minute version

  • Your 231 lines have the architecture and none of the operations. The gap has seven names, and every one of them is a later page in this course or a page in a sibling.
  • Permission is the gap with a public taxonomy: six documented modes, and the rule that matters is that they are enforced by the harness rather than by the model.
  • Context is the gap with the sharpest number: a shipped harness pays a tenth for its fixed part, because it caches it and yours does not.
  • Recovery is the gap you already met. A tool result is the model's only feedback channel, so a check nobody runs costs a whole turn to discover.

1. Seven gaps, each with an owner

Here is what the 231 lines do not have. Nothing on this list is architectural: each one is a layer that sits on the loop you wrote, and each one has a page that owns it.

2. Permission, the gap with a published taxonomy

Your agent asks nobody anything. A shipped one has a documented answer to "may this run", and Claude Code publishes six modes. Read them as six default answers to one question rather than as six features.

ModeWhat it does with a tool call
defaultPrompts for permission on first use of each tool. Labelled Manual in the interfaces, with manual accepted as an alias.
acceptEditsAutomatically accepts file edits and common filesystem commands such as mkdir, touch, mv and cp, for paths in the working directory or an additional directory.
planReads files and runs read-only shell commands to explore, and does not edit your source files.
autoAuto-approves tool calls with background safety checks that verify actions align with your request.
dontAskAuto-denies tools unless pre-approved through a permission rule. It never prompts.
bypassPermissionsSkips permission prompts, except for the actions no mode auto-approves. Documented as for isolated environments only.

Under the modes sit three rule types - allow, ask and deny - and one ordering that decides every conflict: "Rules are evaluated in order: deny, then ask, then allow", with the first match winning and specificity changing nothing. A broad deny cannot carry an allowlist exception.

The sentence to carry out of this page is the one that separates modules 4 and 7 from everything you have read so far.

The reframing "Permission rules are enforced by Claude Code, not by the model. Instructions in your prompt or CLAUDE.md shape what Claude tries to do, but they don't change what Claude Code allows." That is the difference between an instruction and a gate, stated by the vendor about its own product, and it is why the rest of this course keeps moving decisions out of prose and into files.

3. Context, the gap with the sharpest number

Your agent re-sends its fixed part at full price on every turn. A shipped harness marks that part as cacheable, and the published multipliers make the difference stark: a cache read is 0.1x the base input price, a five-minute cache write is 1.25x, and a one-hour write is 2x. The documentation states the break-even directly: caching pays off after one read at the five-minute duration and after two at the one-hour one.

Caching is the cheap half of the context gap. The expensive half is that a long session eventually fills the window, and the documented reason to care is not the limit itself: "As token count grows, accuracy and recall degrade, a phenomenon known as context rot. This makes curating what's in context just as important as how much space is available." Compaction is the server-side answer, and module 2 is the whole argument.

4. Recovery, and the honest limits

Your agent already recovers from a tool that throws, which is most of the way there. What it does not do is notice. Nothing in the 231 lines runs a check the model did not ask for, so a change that breaks the build is discovered only if the model chooses to run the build, and a truncated read is discovered only if the model reads the truncation notice you wrote.

That is the sentence module 5 is built on: a tool result is the model's only feedback channel, so a check nobody runs is a check that does not exist.

Three of the seven layers cannot be judged from the outside, and this course will not pretend otherwise. Claude Code's own system prompt is not published, so every claim this course makes about it comes from documented behaviour - the permission table, the settings reference - and never from the prompt itself. Where a vendor states a number with no published method, this course labels it MARKETING and says what would have to be published for it to be evidence. Nothing on this page is in that category; the permission modes, the multipliers and the context-rot statement are all documented.

5. Score the one you built

Check yourself

Retrieval practice

Answer from memory before revealing.

A deny rule and a narrower allow rule both match one command. Which wins?
Rules are evaluated deny, then ask, then allow, and the first match ends it, so a broad deny cannot carry an exception. The first is the intuition from firewall and IAM specificity rules and is exactly backwards here. The second describes an ask rule, which is a third rule type rather than a conflict resolution. The third would make ordering matter, and it does not.
Why does prompt caching not remove the reason to prune a conversation?
Caching changes what those tokens cost, not whether they are in the request, so accuracy and recall degrade exactly as before. The first is true of the short duration and is a reason to cache differently rather than to prune. The third is false: tool definitions are cacheable. The fourth contradicts the published 0.1x multiplier.

6. The module assignment

This is where module 1 lands, and it is the first thing the capstone asks you for. The capstone page that follows this module has you pick a repository and record a baseline; this assignment is what you bring to it.

Practice about 45 minutes, with the agent you built

Module 1 assignmentfoundation

Goal. Build the loop, then read its own trace, and answer three questions from the log rather than from memory.

Do this. Add one line to the agent from lesson 0160 that appends every request body to requests.jsonl before it is sent. Give the agent one real task in a scratch copy of a repository you know - something you would otherwise have done yourself in half an hour.

Then answer, from the log alone: how many tokens did the tool schemas cost, how many turns did the task take, and which turn was wasted?

Hand in the program, the request log for that task, and a short note answering the three questions.

Hint

One line does it: await fs.appendFile("requests.jsonl", JSON.stringify({ system: SYSTEM_PROMPT, tools: TOOLS.map((t) => t.schema), messages }) + "\n") immediately before messages.create. Every line of the file is one pass through the inner loop, which makes the second question a wc -l.

Show the worked answers, and what each one is for
  1. The schema cost. Serialise the tools array once and divide the character count by four. For the four tools in lesson 0160 that is 2,146 characters, so about 537 tokens - identical on every line of the log, which is the point. Add the published 286-token preamble on Claude Opus 5 and the fixed part is over 800 before your system prompt.
  2. The turn count. wc -l requests.jsonl. Four to eight for a small task is ordinary. Above about fifteen, look for a tool result the model could not use: a truncated read, an error with no next move, or a listing of a directory it did not want.
  3. The wasted turn. Find the first result carrying is_error, then compare the request before it with the request after. A turn is wasted when the recovery re-fetched something already in the array rather than doing something new. Price it: one wasted turn re-sends the whole conversation, so on a 20,000-token context that is $0.10 at $5 per million.
  4. Why the log and not the terminal. The terminal shows what your console.log chose to print. The log is what the model was actually handed, and the two differ in exactly the places that matter - which is the habit lesson 0130 asked you to build and this assignment makes you use.
  5. Keep the directory. This is the capstone's home. Module 2 mounts an MCP server on this agent, module 4 gives it a memory file and a hook, module 7 attacks it, and module 8 runs it unattended against a repository that is not yours.

Sanity check. The schema figure must be identical on every line of the log - if it moves, you are logging after a mutation and the number is not the fixed part. The turn count must be at least two, because the loop always pays one final call to learn that it is finished. And there should be at least one is_error turn the model recovered from: if there is none, the task was too easy to teach you anything about recovery.

Your teacher. Ask your usual agent which of the seven rows in the scorecard it satisfies, and to point at the documentation for each answer rather than asserting it. Where it cannot point at anything, you have found something that is not public, which is a useful thing to know before you depend on it.
