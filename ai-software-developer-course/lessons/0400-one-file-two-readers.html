Module 04 · Customizing your agent · Lesson 0400

Write one instruction file, then make the reader that ignores it read it anyway

working 8 min Built from the AGENTS.md format's own site and Anthropic's memory documentation. · How Claude remembers your project

The one-minute version

  • AGENTS.md is an open instruction file at a repository root, described by its own site as a README for agents and stewarded by the Agentic AI Foundation under the Linux Foundation.
  • Claude Code's documentation states flatly that it reads CLAUDE.md, not AGENTS.md. Writing one file and assuming every agent opens it is the mistake this page exists to stop.
  • Two documented bridges, both one line: an @AGENTS.md import inside CLAUDE.md, or a symlink. The import wins, and Windows is why.
  • This repository ships the import. Its CLAUDE.md is 90 bytes, of which 11 reach the model.

1. Everybody agreed on the file, and one reader does not open it

The convergence is real. AGENTS.md asks you to put agent-facing context in one predictable place at the repository root, in ordinary Markdown with no frontmatter, and its own site lists Codex, Cursor, Gemini CLI, Jules, Amp, Factory, Zed, Warp, opencode, Devin, Windsurf and a dozen more as reading it.

Then there is the sentence that costs people an afternoon. Anthropic's memory documentation says it without hedging: "Claude Code reads CLAUDE.md, not AGENTS.md." Your file is committed, it is well written, the team reviewed it, and the agent half of them are running never loaded it. Nothing fails. The agent simply behaves as though the file is not there, because for that reader it is not.

The reframing An instruction file only exists for a reader that opens it. "Committed at the root" is not a delivery mechanism, it is a hope. The load path is the thing to verify, and this course verifies it on every page that adds a file.

2. Two bridges, both one line, and one of them is better

The documentation gives both, in the same section, and they are not equivalent.

The first is an import. A CLAUDE.md whose first line is @AGENTS.md expands that file into context at session start, and you may write Claude-specific instructions underneath it that the other agents never see.

CLAUDE.md · code.claude.com/docs/en/memory · Anthropic documentation · reproduced verbatim
@AGENTS.md

## Claude Code

Use plan mode for changes under `src/billing/`.

The second is a symlink, which the documentation offers for the case where you need no Claude-specific content at all.

shell · code.claude.com/docs/en/memory · Anthropic documentation · reproduced verbatim
ln -s AGENTS.md CLAUDE.md

Prefer the import, for a reason the same page states: "On Windows, creating a symlink requires Administrator privileges or Developer Mode, so use the @AGENTS.md import instead." A symlink also has no room for the Claude-only paragraph you will eventually want, and converting it later is a commit that looks like a rename and reads like nothing.

3. What this repository ships, in full

The course-hub repository this page lives in is a working example, and its content is CC BY 4.0 and its code MIT, so it can be quoted whole rather than excerpted. Its CLAUDE.md is two lines.

CLAUDE.md · this repository, at the repository root · CC BY 4.0 · reproduced verbatim, complete
<!-- Points Claude at AGENTS.md via import; edit AGENTS.md, not this file. -->
@AGENTS.md

The first line is a design decision worth stealing. Block-level HTML comments in a CLAUDE.md are stripped before the content is injected, so a note addressed to a human maintainer costs nothing at all in the context window. That leaves a file of 90 bytes on disk of which 11 reach the model, and those eleven pull in the whole 62,412-byte contract behind them.

4. Nesting, and the one thing that outranks every file

A monorepo does not need one enormous root file. The AGENTS.md format's own rule is that "the closest AGENTS.md to the edited file wins", so a subproject carries its own and it is the one that applies while the agent is working there. cloudflare/agents uses exactly this shape and publishes a table of which nested file governs which directory.

The same rule ends with the sentence that keeps all of this in proportion: "explicit user chat prompts override everything." Every file in this module is a default, and you are always able to say otherwise in the turn. That is a feature until you need a rule that holds when you are not watching, which is where lesson 0430 picks the argument up.

The agents.md site states that the format is "used by over 60k open-source projects" and lists more than twenty compatible tools. Both figures are self-reported by the format's own site with no method, no query and no sample published, so this page treats them as a vendor claim rather than a measurement. Nothing in this lesson depends on either number: whether the count is six thousand or six hundred thousand, the load path in your own repository is still something you check rather than assume.

5. Verify it rather than assuming it

The check takes one command and it is the habit this whole module rests on. Start a session and run /context: the documentation's instruction is to "confirm CLAUDE.md appears under Memory files". If it is not in that list, the agent cannot see it, and no amount of rewriting the file will change that.

For how the same primitive is spelled across other harnesses, Coding Harness Engineering, lesson 0080 compares instruction files, skills, subagents and hooks across the whole cast. This course goes the other way from here: what to put in the file, and what it costs you per turn.

Check yourself

Retrieval practice

Answer from memory before revealing.

Your repository has a good AGENTS.md and no CLAUDE.md. What does Claude Code load from it?
The documentation states that Claude Code reads CLAUDE.md and not AGENTS.md, so with no CLAUDE.md present nothing from your contract enters the session. The first option is the assumption this page exists to break. The third confuses the 200-line guidance for CLAUDE.md, which is a size target rather than a truncation. The fourth describes /init, which can read an existing AGENTS.md and write a CLAUDE.md for you, but it is a command you run, not something that happens on load.
Why does the documentation prefer the import over the symlink for cross-platform teams?
The stated reason is that creating a symlink on Windows requires Administrator privileges or Developer Mode. The first option is invented: both mechanisms deliver the same text at session start. The second is wrong in the other direction, since the two put identical content in the window and the import adds only its own line. The fourth is simply false, and this repository commits twenty-one of them for its course folders.

Practice about 15 minutes, with a terminal

Practice 1working

Take the capstone repository you picked in lesson 0000 and answer one question with evidence rather than belief: does the agent you actually use load your instruction file?

If the repository has no instruction file yet, write a four-line AGENTS.md naming the install command, the test command, and one convention an agent could not guess. Then wire whichever bridge your platform calls for, start a session, and prove the file arrived.

Hint

You are looking for a list, not a feeling. The session-level command that prints what was loaded is /context, and the section it prints under is Memory files. If your agent is not Claude Code, find its equivalent before you write anything.

Show what a good answer looks like
  1. Write the contract once. AGENTS.md at the root, in ordinary Markdown, with the setup and test commands and one non-obvious rule. Four lines is a fine first version.
  2. Add the bridge, not a copy. A CLAUDE.md whose only content line is @AGENTS.md. If you catch yourself pasting the contract into a second file, stop: two copies drift within a fortnight and neither is authoritative.
  3. Prove the load. Start a session, run /context, and read the Memory files list. Your CLAUDE.md should be named there.
  4. Prove the expansion. Ask the agent, in that same session, to quote the test command from your contract back to you. If it can, the import resolved. If it names the file but not the command, the import did not.

Sanity check. Two files, one of them two lines long, and the contract itself appearing nowhere twice. If your CLAUDE.md is longer than three lines at the end of this exercise, you have written a second contract rather than a bridge, and lesson 0420 explains what that costs.

Your teacher. If the load path still feels like magic, ask your agent to print the exact list of instruction files it loaded this session, in order, and then to say for each one which directory it came from. If the nesting rule did not land, ask it to describe what would change if you added a second instruction file inside one subdirectory of your repository.
