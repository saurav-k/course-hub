Module 03 · Agent skills and the CLI · Lesson 0330

Two of the four agents resolve the same name clash in opposite directions

working 7 min Every path and every precedence rule read from that tool's own documentation in this session. · Claude Code · Cursor

The one-minute version

  • Four agents read the same file from a folder each. The format travels; the folder name and the precedence do not.
  • Claude Code resolves a clash enterprise over personal over project. Gemini CLI resolves the same clash workspace over user. Those are opposite directions.
  • Codex does not resolve it at all: on a name clash both skills stay available and appear in the selector together.
  • .agents/skills/ is the shared path that three of the four read. Claude Code reads none of them, so the portable answer is that folder plus a symlink.

2. The table you will come back to

AgentProject pathsUser pathsName clash resolves to
Claude Code .claude/skills/, and every parent up to the repository root ~/.claude/skills/ The personal one. Enterprise beats personal, personal beats project. Plugin skills are namespaced plugin:name and cannot clash.
Cursor .agents/skills/, .cursor/skills/, and .claude/skills/ and .codex/skills/ for compatibility The same four under ~ The nearest folder. A skill in a nested project directory is scoped automatically to files under that directory.
Gemini CLI .gemini/skills/ or .agents/skills/ ~/.gemini/skills/ or ~/.agents/skills/ The workspace one. Built-in, then extension, then user, then workspace. Inside a tier, .agents/ beats the tool's own folder.
Codex .agents/skills in the working directory, its parent, and the repository root $HOME/.agents/skills, then /etc/codex/skills, then bundled Neither. Codex does not merge two skills of the same name; both can appear in the selector.

One more Claude Code behaviour is worth holding because it is the one that surprises people in a monorepo: a skill in a nested .claude/skills/ below your working directory is not loaded at startup. It loads the first time Claude reads or edits a file in that subtree, and if it clashes with a root skill both stay available, the nested one under a directory-qualified name such as /apps/web:deploy.

4. The portable answer, and why it needs a symlink

The obvious conclusion from that chart is to put every skill in .agents/skills/. Three of the four agents read it, and Codex reads nothing else. But Claude Code's documented locations do not include it, so a skill filed there is invisible to the tool a great many readers of this course are running.

The fix is one line, and Claude Code documents it: a skill entry in a skills folder may be a symlink to a directory elsewhere on disk, which it follows, and if the same target is reachable from more than one location the skill is loaded once rather than twice.

repository tree and one command · this repository's own convention · MIT · complete
your-repo/
├── .agents/
│   └── skills/
│       └── release-notes/
│           ├── SKILL.md
│           ├── references/
│           │   └── house-format.md
│           └── scripts/
│               └── since_tag.sh
└── .claude/
    └── skills/
        └── release-notes -> ../../.agents/skills/release-notes

# create that symlink once, and commit it
mkdir -p .claude/skills
ln -s ../../.agents/skills/release-notes .claude/skills/release-notes
git add .agents/skills/release-notes .claude/skills/release-notes

Cursor finds it twice, once through .agents/skills/ and once through its compatibility read of .claude/skills/, and its identity comes from the folder holding SKILL.md either way. Gemini and Codex find the real folder. Claude Code follows the link.

5. When the wrong one runs

Nothing in any of these four tools reports a skill that lost a clash. The winner runs, the loser is not mentioned, and the transcript looks exactly the same either way. If a skill you know exists does not behave as its file says, list what the agent can actually see before you edit anything: Claude Code answers "what skills are available", Gemini CLI has /skills list, and Cursor lists them under Customize.

Check yourself

Retrieval practice

Answer from memory before revealing.

A deploy skill sits in both ~/.claude/skills/ and the project's .claude/skills/. Which runs?
Claude Code documents the order as enterprise over personal over project, so the copy in your home directory wins. The first option is the intuition most people carry from configuration files and it is wrong here. The second describes no tool in this lesson. The third is Codex's behaviour, not Claude Code's, and it is the strongest distractor because it is true somewhere.
You file a skill in .agents/skills/ only. Which of the four will not find it?
Claude Code's documented locations are enterprise, ~/.claude/skills/, .claude/skills/ and plugins, and a symlink is the documented way to reach anything else. Codex reads only .agents/skills, so it is the one that certainly finds it. Cursor reads that folder natively and four more for compatibility. Gemini CLI accepts it as an alias and gives it precedence over its own folder.

Practice about 15 minutes, with a terminal

Practice 1working

Take the skill you have been building since lesson 0310 and move it into the repository under .agents/skills/, add the .claude/skills/ symlink, and commit both.

Then prove the discovery rather than assuming it. Ask each agent you have installed to list the skills it can see, from a clean session started at the repository root. Note for each one whether your skill appears and under what name.

Then break it deliberately. Put a second skill with the same name in your home directory, restart, and record which one runs. That is the experiment that makes the precedence table stick.

Hint

Start a session in a scratch directory outside the repository as well. A skill that appears there and not in the repository is being found through your home directory, which tells you the commit did nothing.

Show what each result means
  1. It appears in the repository and not outside it. The project copy is being found. This is the state you want.
  2. It appears in both. There is a copy in your home directory. On Claude Code that copy is also the one running inside the repository, which is the silent failure this lesson exists for.
  3. It appears under a qualified name such as apps/web:deploy. The folder is nested below your working directory, and it only became visible after the agent touched a file in that subtree.
  4. It does not appear at all. Check the folder name against the name field, then check that the opening --- is the first line of the file. Those two account for most of it.

Sanity check. After the deliberate break, exactly one of your two skills should run and nothing should warn you. If you got a warning, you found a behaviour none of these four documents, and it is worth writing down.

Your teacher. Ask your agent to print the absolute path of the SKILL.md it just used. Not which skill, the path. If it cannot say, ask it to run ls -l on both candidate folders and reason from what comes back, which is the same thing you would do.
