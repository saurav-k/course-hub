Module 05 · Agent-ready codebases · Lesson 0560

The gaps are boring, repeatable, and each one has a named artefact that closes it

working 8 min Sized against a published instruction-file context budget and against three real instruction files, this repository's own included. · Factory: AGENTS.md, and its context budget

The one-minute version

  • Eight gaps account for most of what stops an agent, and every one of them has a named artefact that closes it.
  • Split them by how they fail. A loud gap costs minutes. A silent gap produces a confident wrong change that survives into review.
  • An instruction file is charged against context on every turn, so it has a budget: one published harness caps the initial load at 80,000 characters.
  • Triage by hours to close, not by severity, and start with the silent ones because they are the expensive ones.

1. The eight, and what each costs

None of these is exotic and none of them is about the model. They recur across languages, sizes and teams, which is the useful part: a list this stable is a list you can work through.

2. Loud gaps are cheap, silent gaps are not

Sort the same eight by how the failure reaches you and the triage order falls out on its own. A loud gap stops the agent in the first two minutes and costs you a message. A silent gap lets the run complete, produce a diff, and announce success, and you find out at review time or later.

3. The instruction file has a budget, and it is smaller than you think

The fourth gap deserves its own treatment because it is the one people create while fixing the others. Every rule you add to the instruction file is loaded into the session and charged against context, on every turn, whether or not the task needs it. Factory publishes the cap it applies: 80,000 characters for the initial guideline load and 40,000 for guidelines discovered while reading files. Anthropic's guidance makes the same point behaviourally rather than numerically: "Bloated CLAUDE.md files cause Claude to ignore your actual instructions", and its advice for each line is to ask whether removing it would cause a mistake.

The test for a line Before a line goes into an instruction file, ask whether removing it would cause a mistake. If the agent already gets it right without the line, the line is costing context on every turn and buying nothing. If it is only needed sometimes, it belongs in a skill or a nested file, which load when the task matches instead of always.

4. One run, hitting them in order

Read the gaps as a sequence rather than as a list, because that is how they arrive: each one is a place where a run either stops or, worse, does not.

5. What to do first, if you have one afternoon

Triage by hours, then by silence. Name the selectable test command first: it is one paragraph and it closes the most expensive silent gap on the list. Mark the generated files second, one line each, because that gap destroys correct work rather than merely wasting time. Write down the setup command third, and run it from a clean checkout before you write it down. Everything else, including ownership and the environment, is a second afternoon, and none of it is worth doing before those three.

Check yourself

Retrieval practice

Answer from memory before revealing.

Why is a missing test command more expensive than a missing install command?
The install gap halts the run and diagnoses itself in two minutes; the test gap lets a plausible diff reach a human wearing a false claim. The first is a cost comparison that is often true and is not the reason. The third is also true, and it makes the install gap cheaper still rather than making it worse. The fourth argues the wrong way, since CI catching something is what makes a gap loud.
Your instruction file has grown to 30,000 characters. What is the specific harm?
Dilution is the documented failure, and it is behavioural rather than a hard limit. The second is false at that size: 30,000 is well inside both published caps, which is what makes this the difficult case. The third invents a rule no harness has. The fourth describes a loading failure that does not happen and would at least be loud if it did.

Practice about 25 minutes, with a terminal

Practice 1working

Find your repository's silent gaps by looking for the one thing they have in common: a command whose failure is indistinguishable from its success.

For each of the three commands an agent would run in your repository - install, the test you would tell it to use, and whatever you call "done" - answer two questions. Does it exit non-zero when it should? And does it say which file was wrong?

Then count your generated files, and how many of them carry a line saying so.

Hint

A shell pipeline is the usual culprit for the first question. Without set -o pipefail, the exit code of a | tee log is tee's, so a failing check inside a wrapper script reports success and nothing warns you.

Show the three findings and their fixes
  1. A command that exits zero on failure. Usually a pipeline or a script missing set -euo pipefail. One line, and it converts a silent gap into a loud one, which is the whole move this lesson is about.
  2. A command that fails without naming a file. Most tools have a formatter flag that adds the path and line. Turning it on is free and it is what lesson 0540 makes CI do as well.
  3. Generated files with no marker. Count them, then add one line each. A repository with lockfiles, an API client and a schema dump typically has three to six, and every one is a place a correct agent change silently disappears.

Sanity check. If all three commands already exit correctly and name their files, your gaps are in navigation and ownership rather than in signalling. That is a better position to be in, and it is the one where a nested instruction file buys the most.

Your teacher. Ask your agent to list every file in your repository it believes is generated, and how it can tell. Then ask what it would do if it needed to change one. The answers where it says it would edit the file directly are your missing markers, in priority order.
