Module 03 · Agent skills and the CLI · Lesson 0320

Move everything the agent does not need every time out of SKILL.md

working 12 min Measured against the nineteen published skills and against this repository's own. · Equipping agents with Agent Skills

The one-minute version

  • Keep SKILL.md under 500 lines. It is the file that loads whole, so every line in it is paid for on every activation.
  • references/ holds material the body points at. The agent reads one file, not all of them, and the branch that is not taken costs nothing.
  • scripts/ holds code. A script is better than an instruction for the same job because it is deterministic and its output is small.
  • The strongest instruction in a real skill is "run it with --help first and do not read the source". Reading a script is a context decision disguised as diligence.

1. Three folders, one rule each

The specification names three conventional directories beside SKILL.md, and the useful way to hold them is by what makes each one cheap.

FolderWhat goes in itWhy it is cheap
references/Documentation the body points at by nameThe agent reads the one file the branch needs; the others never enter the window
scripts/Executable code the body tells the agent to runIt is executed rather than read, so its cost is its output, not its length
assets/Templates, schemas, images, lookup tablesIt is copied or filled in rather than reasoned about

The specification adds one constraint that is easy to break by accident: keep file references one level deep from SKILL.md, and avoid a reference that points at a file that points at another file. A chain costs a read per link and the agent has to decide at every one of them.

2. The reference pattern, in one real skill

The internal-comms skill quoted in the previous lesson is the whole pattern in thirty-two lines. Its body carries a numbered instruction to load exactly one of four files from examples/, chosen by what the request asked for, and then to follow that file.

3. The same shape, twenty-five times bigger

This repository ships a skill of its own, and it is the pattern under load. Its SKILL.md is 81 lines. The reference it points at for widget markup is 2,021 lines, which is twenty-five times the entry file and is read only when somebody is actually drawing a figure.

.claude/skills/course-authoring/SKILL.md · this repository · MIT for code, CC BY 4.0 for content · reproduced verbatim, frontmatter only
---
name: course-authoring
description: The course-hub house standard for teaching pages, and the procedure that produces one. Use when creating a course, writing or rewriting a lesson or chapter, or checking a page against the standard before a pull request. Also use when installed in any other project to author self-contained local HTML learning pages, study notes or an explainer pack, with no hub clone and nothing published.
---

Two sentences of when against one of what, and the second sentence exists because the skill has a second mode. That is the ratio the previous lesson asked for, written by somebody who had to live with the consequence.

4. Where real skills sit against the ceiling

5. Why a script beats an instruction

Some of what a skill does is not reasoning. Anthropic's engineering write-up puts the case plainly: "sorting a list via token generation is far more expensive than simply running a sorting algorithm", and beyond cost, many jobs need a determinism only code has.

The webapp-testing skill states the consequence as an instruction to the agent, and it is the single most transferable sentence in the whole published set:

The reframing "Always run scripts with --help first to see usage. DO NOT read the source until you try running the script first and find that a customized solution is absolutely necessary. These scripts can be very large and thus pollute your context window. They exist to be called directly as black-box scripts rather than ingested into your context window." Quoted from webapp-testing/SKILL.md, Apache-2.0. The original spells one word abslutely; it is corrected here and the file is reproduced verbatim, slip included, in lesson 0340.

The size difference is measurable rather than rhetorical. Running that skill's own script with --help in this session produced 474 bytes. The source of the same script is 3,693 bytes. Reading it costs about eight times what calling it does, to learn a usage line the script prints for free.

A script is deterministic; a skill telling the agent to run it is not. Nothing in the format stops a model reading the source anyway, and the instruction above is a request rather than a rule. If a script must never be read, or must always be run, that is a hook, and hooks are module 4. This is the honest limit of every skill in this module: a skill is context, and context asks.

Check yourself

Retrieval practice

Answer from memory before revealing.

Your skill has four mutually exclusive procedures. Where should the three unused ones live?
Four named files with the body choosing one is the reference pattern, and the three not chosen cost nothing. The first pays for all four on every activation, which is the thing disclosure exists to avoid. The second overruns a 1,024-character field and confuses routing with content. The fourth is not wrong so much as pointless: a script that only prints text is a file read with extra steps and less searchability.
Why does a skill tell the agent to run a script rather than read it?
The measured ratio on the one real example here is about eight to one, and that is the whole argument: the output is the answer and the source is a much longer route to it. The second is false and patronising. The third has it backwards: the script is deterministic whether or not anybody reads it. The fourth invents a prohibition the specification does not contain, and the instruction in a real skill is phrased as a request precisely because nothing enforces it.

Practice about 20 minutes, with a terminal

Practice 1working

Take the skill you wrote in the previous lesson and split it. Find the part of the body that is only needed on some activations, move it into references/, and replace it in the body with one line naming the file and saying when to read it.

Then find the part that is not reasoning at all - a lookup, a sort, a diff, a count - and move it into scripts/ with a --help that prints its usage. Add the instruction to call it and not read it.

Measure the body before and after in bytes, and the script's --help output in bytes.

Hint

The part to move out is usually the part you wrote as a list of cases. If the body says "if X do this, if Y do that" for more than two cases, each case is a reference file and the body keeps the table.

Show the shape a split should produce
  1. Body before. One file carrying every case, say 6,000 bytes, all of it loaded whenever the skill fires.
  2. Body after. The same file at about 1,500 bytes: the frontmatter, the decision table naming four files, and the script instruction.
  3. Cost per activation. 1,500 plus whichever one reference file the turn selected, say 1,600, so about 3,100 against 6,000. Roughly half, and the saving grows with every case you add.
  4. The script. A --help under 600 bytes against a source over 3,000 is the ratio to aim for. If the help is longer than the source, the script is too small to be a script.

Sanity check. Your new body should be shorter than the longest file you moved out of it. If it is not, you moved prose rather than branches, and the reference files will all be read anyway.

Your teacher. Ask your agent to activate your split skill on a task that needs only one branch, then ask it which files it read. If it read more than one reference file, your decision table is ambiguous: the fix is in the table's wording, not in the files.
