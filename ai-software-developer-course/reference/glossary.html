Glossary

112 terms Every term this course introduces, linked to the page that develops it. Definitions here are deliberately narrower than the field's: they say what the word means in this course. Print it and cover the right-hand column.

This sheet grows with the course. Every module adds its own terms here, alphabetically, in the same pull request that adds its lessons, so a term is never introduced on a page without a definition to come back to.
TermWhat it means here
[NEEDS CLARIFICATION] A marker a generated spec puts where it would otherwise have invented an answer. Its value is that it is findable, so the open questions can be collected and asked rather than shipped.
acceptance rate The share of a reviewer's comments the author actually acted on. Blunter than precision, because a correct comment nobody had time for counts as a miss, and the only one of the three metrics you can compute on your own repository from the first week.
activation The moment an agent decides a skill's description matches the task and reads its body. Before activation a skill costs its description; after it, the whole body.
agent loop The cycle your own program drives: send a request, receive a request to call a tool, run it, append the result, send again, until the model stops asking.
agent perception gap Anything a human can see that an agent cannot: a running devserver's terminal, a rendered page, a screenshot. It is closed by giving the thing an address, usually a file the agent can grep.
agent skill A directory holding at minimum a SKILL.md: YAML frontmatter followed by Markdown instructions, which an agent loads on demand rather than on every turn.
agent-ready The property of a repository that lets an agent set up, change and prove a change by running commands the repository names, with no human in the loop. Not the same as tidy.
agentic review A reviewer that runs tools during the review - grep, read, git, the test suite - so its context is what it chose to fetch rather than what it was handed.
annotation A line a CI step prints in the form ::error file=,line=,title=::message, which becomes a finding attached to a place in a file rather than a paragraph in a log.
application scope Evaluating a criterion once per independently deployable application inside a repository, so the answer is three of four rather than pass. Repository scope is the other one, evaluated once for the whole repository.
approval mode Gemini CLI's name for the session-wide approval baseline, taking default, auto_edit, yolo or plan. The same idea Claude Code calls a permission mode and Codex splits across sandbox and approval flags.
autofix A model-generated diff attached to a scanner finding. The call is not repeatable: the same alert and the same code may produce a different suggestion, or none.
autotriage A model call that reads a finding, the surrounding code and the team's past decisions, and proposes that the finding be acted on or ignored. It closes nothing on its own.
bare mode A -p run started with --bare, which skips discovery of hooks, skills, commands, subagents, plugins, MCP servers, auto memory and CLAUDE.md. What makes a scripted run identical on every machine.
bundled resource A file under scripts/, references/ or assets/ inside a skill. It enters the context window only when the body sends the agent to read it, and a script ideally never does.
CODEOWNERS The file that routes a change to the humans who own the paths it touches. The last matching pattern wins, an approval from any one owner is enough, and a pattern with no owner after it deliberately removes ownership.
compaction Server-side summarising of the earlier part of a conversation so it can continue past the context-window limit. It is the platform's eviction policy, not yours, and every harness has one of its own on top.
context rot The documented decline in accuracy and recall as the token count in a request grows. It is why curating context matters as much as having room left.
context window Every token a model can reference in one request, its own output included. The system prompt, the tool definitions and every message all count toward it.
devcontainer A declarative development environment defined by a devcontainer.json. It is reproducible only when its image tag names a build rather than latest.
diff-aware scanning Scanning only what a change touched rather than the whole tree, so a gate can be turned on without a backlog making it unreadable.
diff-only review A reviewer that sees the patch and nothing else. Cheapest and fastest, and structurally blind to any defect whose site is outside the changed files.
elicitation The one feature an MCP client offers a server: a way for the server to ask the user for extra information part-way through a call.
evidence rule The rule that makes a readiness score reproducible: every point is a file path or a command you ran, never an impression. A dimension whose evidence you cannot name scores zero.
exact-string edit The dominant edit primitive: quote the text to remove, give the text to put there, and refuse when the quote matches zero times or more than once.
fan-out Running many one-shot agents, one per unit of work, usually as a loop over claude -p with the tool list scoped. The cost is linear in the units, so three of them price the whole job.
few-shot prompting Steering the shape of an output by showing three to five relevant, diverse examples in <example> tags, rather than describing the shape in words. Also called multishot.
fixed part The system prompt plus the tool schemas: the portion of a request that is roughly the same size on turn one and turn forty, and is re-sent on both.
flaky check A check that fails for reasons unrelated to the change. Worse for an agent than no check, because you remember the flake across runs and the agent reads it as information and edits correct code.
frontmatter The YAML block between --- markers at the top of a SKILL.md. Read only when the opening marker is the file's first line; otherwise the whole file, markers included, is treated as skill content.
golden set A hand-validated list of the defects actually present in a set of pull requests. It is what recall is divided by, it is expensive to build, and it is why almost nobody publishes a recall figure.
harness The ordinary program that drives the loop: it assembles the request, dispatches the tool calls, applies your rules, and shows you the result. It is what you are typing into, and it is not the model.
host, client, server MCP's three roles. The host is the application you are typing into, a client is one connector inside it, and a server is a separate program providing context and capabilities.
incremental review Reviewing only what changed since the reviewer's last pass, rather than the whole diff again on every push. One of the four volume controls every product ships under a different name.
indirect prompt injection Injection that arrives through content the model reads - a file, a fetched page, a tool result, a tool description - rather than through what a user typed.
input_schema The JSON Schema on a tool definition saying what arguments the model may send. It constrains what an argument may be; only the description says what it should be.
instruction file The repository's standing brief for agents, usually AGENTS.md. It is loaded into every session and charged against context on every turn, so it has a budget: one published harness caps the initial load at 80,000 characters.
is_error The optional flag on a tool result telling the model the call failed. It is a field on a message rather than a stop reason, so the loop carries on unchanged.
isError The MCP field marking a tool execution error, which is a normal result the model is meant to read and recover from. Distinct from a JSON-RPC protocol error, which the model usually cannot fix.
job summary Markdown a step appends to the file named by $GITHUB_STEP_SUMMARY, capped at 1 MiB per step with at most 20 shown per job. The right home for a table of verdicts and the command that fixes each.
lazy LGTM Approving a change without reading it, because the cost of reading has passed what the risk feels like it is worth. The human failure mode automated review is aimed at, and one an automated first pass moves rather than removes.
lethal trifecta Access to private data, exposure to untrusted content, and the ability to communicate externally, all in one agent. Cutting any one leg ends the exfiltration path.
line jumping Tool poisoning that lands when the client lists tools, before any tool has been invoked, so no approval gate has had anything to approve.
LLM-as-judge Using a model to decide whether a reviewer's comment matches a known defect, because exact matching cannot. It makes every acceptance and recall figure an estimate produced by the same class of system being measured.
lockfile The generated file that turns "it installed" into "it installed the same thing CI installed". It only makes that second claim when the install command carries the frozen or deployment flag.
MCP endpoint The single HTTP path a Streamable HTTP server exposes. Under revision 2026-07-28 it accepts POST only: the GET stream was removed.
metavariable A $NAME placeholder in a pattern that matches an unknown value, and matches the same thing everywhere it appears within one logical AND.
namespacing Prefixing a tool name with the service it belongs to, so a library of mounted servers stays unambiguous. Tool-name uniqueness in MCP is scoped to one server, so collisions across servers are yours to prevent.
non-interactive mode One turn with no terminal interface, started with -p or --print. It reads standard input, writes standard output, and exits zero on success and non-zero on failure. Also called print mode.
oracle Whatever the agent can run that returns a pass or a fail: a suite, a build exit code, a linter, a fixture diff, a screenshot comparison. Without one, "looks done" is the only signal it has.
output format How a non-interactive run writes its answer: text, json (one object carrying the result, a session id and a cost estimate), or stream-json (one JSON event per line).
ownership coverage The share of paths a CODEOWNERS file actually matches. Tracked as a committed list of uncovered paths, it becomes a number that can only go down.
parallel tool use Several tool calls in one assistant turn, answered by several results in one user message and matched by tool_use_id. It costs one round trip rather than several.
permission mode The session-wide baseline for which actions run without anybody being asked, and who reviews the rest: you, a classifier, or nobody.
permission rule A tool name, optionally narrowed by a specifier, in an allow, ask or deny list. Deny is read first, then ask, then allow, and the first match decides.
pillar One of the nine dimensions of the published Agent Readiness Model. Pillars say along what; levels say how far. Six of the nine are movable by one engineer in an afternoon.
plan mode A permission mode in which the agent reads files and runs read-only commands but may not edit source. It is the harness enforcing the first moves of a research-then-propose loop rather than your discipline holding them.
precision (in review) The share of a reviewer's comments that are real defects. A setting rather than a limit: a reviewer reaches high precision by saying less, so a precision headline reports what a vendor chose.
prefill Supplying a partial trailing assistant turn for the model to continue from. Unsupported on Claude 4.6 and later, where such a request returns a 400.
PreToolUse hook A program that receives a proposed tool call as JSON and returns a decision. Deterministic where a classifier is probabilistic, and blind to anything not in the call.
progressive disclosure Loading a skill in three stages: metadata always, the body on activation, bundled files only when read. It is what makes the material a skill can carry effectively unbounded.
project rule Cursor's always-or-conditionally-loaded context file, an .mdc under .cursor/rules. Three frontmatter fields - alwaysApply, globs, description - combine into four different loading behaviours.
prompt (MCP) A template a person invokes, not something the model calls on its own. Getting this wrong makes a workflow fire when the model feels like it.
prompt caching Marking part of a request as reusable so a later request pays a fraction for it. It changes what those tokens cost, never whether they occupy the window.
prompt chaining Splitting a task across sequential API calls so intermediate output can be logged, evaluated or branched on. The common shape is draft, then review, then refine.
prompt injection Input that alters the model's behaviour or output in unintended ways. In a coding agent the direct form matters least, because the typist already has your reach.
push protection Blocking a push that contains a detected secret, so the credential never reaches the remote at all. The only control in this module that prevents rather than reports.
ratchet baseline A committed list of known failures, so a new defect fails the build and existing debt does not. It only shrinks if a recorded failure that stops happening also fails.
reachability Whether the vulnerable code inside a flagged dependency is actually called from yours. A three-way verdict - reachable, unreachable, or no analysis - rather than a yes or no.
readiness level One of five bands - Functional, Documented, Standardized, Optimized, Autonomous. A repository unlocks the next by passing 80% of the criteria at the one below, and work above a locked gate scores nothing.
recall (in review) The share of the real defects present that a reviewer mentioned at all. The number a vendor is least likely to publish, and the one that decides whether a green review may be treated as a gate.
repo-aware review A reviewer given an index of the whole repository to retrieve from. It may return the call site the patch breaks, and it may return two chunks from a deleted branch, because retrieval is a ranking rather than an answer.
RePPIT Research, Propose, Plan, Implement, Test: a five-move loop that puts the human decision between two written options rather than in front of a finished diff. A named framework with one public write-up and a single author.
request One HTTP body carrying a system prompt, a set of tool definitions, the whole conversation so far, and the model and length settings. One turn is one request.
required status check A check a branch ruleset will not merge without. It publishes a claim to every later reader, which is why what is required must be deterministic and an AI review must not be.
resource (MCP) Read-only data addressed by a URI. It is controlled by the application rather than by the model, which is why a document exposed as a tool behaves differently from the same document exposed as a resource.
review depth A configured trade of cost and latency against recall, shipped as deep and shallow, as four effort levels, or as named tiers. One dial, several vocabularies.
review rule A checked-in standard in three parts: a condition, a scope, and a required action including the finding's title and whether it blocks. Miss any one part and the reviewer improvises.
rug pull A server changing a tool's description or behaviour after the user approved it, so the artefact now running is not the artefact that was approved.
sandbox Filesystem and network isolation applied by the operating system to a command and every process it starts, which is the set a rule on a command string cannot see into.
sandbox mode Codex's -s/--sandbox flag, taking read-only, workspace-write or danger-full-access. It bounds what a command can reach rather than whether the agent asks first.
SARIF The interchange format that puts a scanner finding on a specific line in a code-hosting interface. Uploading it needs a write scope the rest of the workflow does not.
SAST Static application security testing: reading first-party source, without running it, to find code shaped dangerously.
SCA Software composition analysis: matching the packages a manifest declares against a vulnerability database. It reads lockfiles and never your logic.
secret scanning Reading text, including git history, for things shaped like credentials. A key deleted from the working tree is still in the history a scanner reads.
selectable test A documented way to run one file or one test rather than the whole suite. It is what puts the check inside the loop: iterations per hour is sixty divided by the suite's minutes.
self-consistency Sampling several reasoning paths and taking the most common answer. The most expensive technique in the module, because you pay for every path and keep one.
session id The identifier in a JSON response that --resume takes. Capturing it is what makes a second invocation a second turn rather than a second conversation.
severity taxonomy A fixed set of finding levels used for triage rather than for accuracy. The right number of bands is the number your team will actually sort into, and each band is also a switch deciding what gets posted.
silent gap A gap that lets the run finish and report success anyway, such as a timed-out suite or an unmarked generated file. The opposite is a loud gap, which stops the agent and has already diagnosed itself.
skill listing The names and descriptions of every installed skill, assembled before your first word and carried in every request. It has a budget, and a description dropped to fit it is a skill that can no longer be matched.
source, sink, sanitizer Where untrusted data enters, where it must never arrive, and what clears the marker on the way. The three arms of a taint rule.
spec-driven development Making a written, committed specification the unit of work, so the agent builds from it and the reviewer checks against it instead of against a conversation they were not in.
stdio transport MCP over a subprocess's standard input and output, one newline-delimited JSON-RPC message per line. Nothing that is not a valid message may go to standard output, which is why logging goes to standard error.
stop_reason The response field the loop is keyed on. tool_use means run the tools and send again; any other value means stop.
Streamable HTTP MCP's remote transport: one POST per message to a single endpoint, answered with JSON or an SSE stream scoped to that request.
structured outputs Constraining a response to a JSON Schema through output_config. The constraint is enforced rather than requested, which is what removes the rare malformed response instead of making it rarer.
system prompt The instructions sent above the conversation. In a harness it is a template filled in at run time from the machine, the session and your repository.
taint A marker attached to a value because it came from an untrusted source, carried along the dataflow until something clears it.
task runner One documented entry point per intent - bin/setup, bin/test, bin/verify - so the agent never reconstructs a command line. The verify entry is the definition of done.
token The unit a model reads, writes and is billed in - documented as roughly four characters or 0.75 words of English.
tool annotation Untrusted metadata hinting at a tool's behaviour, such as readOnlyHint. A server declares its own, so it is documentation for a human reviewer and never a permission decision.
tool call A structured request from the model naming a tool and its arguments. It is a request rather than an action: nothing has happened until your program acts on it.
tool definition A name, a plaintext description and an input_schema. The description is the part the model plans against, which makes it behaviour rather than documentation.
tool poisoning Hiding instructions inside a tool's description, which the model reads in full and the user usually sees only in summary.
tool result What your program sends back after running a tool. A refusal is a tool result too, and it travels through the same channel as a success.
tool search Loading tool definitions on demand instead of up front, by marking them defer_loading. It changes what enters the context window, not what you send: every definition still travels with every request.
tool-use system prompt The extra instructions the API prepends whenever a request carries tools. You never write it, you cannot set it, and it is charged on every turn.
trace The messages array over time. It is not a log of your agent, it is the agent's entire memory, and it answers “why did it do that”.
validator Code that calls the issuing service to decide whether a detected credential is live, replacing a guess about a string with a fact about an account.
web skill A skill whose instructions reach outside the working tree: a fetch, a browser, a cloud command-line tool, a documentation lookup. Nothing about the format changes; the blast radius does.
XML tagging Wrapping each kind of content in its own named tag so a prompt mixing instructions, context and input parses unambiguously. The cheapest high-value technique in the module.
