Glossary

61 terms Every term this course introduces, linked to the page that develops it. Definitions here are deliberately narrower than the field's: they say what the word means in this course. Print it and cover the right-hand column.

This sheet grows with the course. Every module adds its own terms here, alphabetically, in the same pull request that adds its lessons, so a term is never introduced on a page without a definition to come back to.
TermWhat it means here
actor gating The two checks an unattended run applies before it starts: the triggering user has write access, and the actor is not a bot unless it was listed deliberately.
agent identity A single-purpose credential belonging to one agent, carrying the minimum permissions for that agent's job and nothing more.
agent loop The cycle your own program drives: send a request, receive a request to call a tool, run it, append the result, send again, until the model stops asking.
agent perception gap Anything a human can see that an agent cannot: a running devserver's terminal, a rendered page, a screenshot. It is closed by giving the thing an address, usually a file the agent can grep.
agent-ready The property of a repository that lets an agent set up, change and prove a change by running commands the repository names, with no human in the loop. Not the same as tidy.
annotation A line a CI step prints in the form ::error file=,line=,title=::message, which becomes a finding attached to a place in a file rather than a paragraph in a log.
application scope Evaluating a criterion once per independently deployable application inside a repository, so the answer is three of four rather than pass. Repository scope is the other one, evaluated once for the whole repository.
autofix A model-generated diff attached to a scanner finding. The call is not repeatable: the same alert and the same code may produce a different suggestion, or none.
automatic memory Notes the agent writes for itself, kept per repository. It records preferences, corrections, project context and pointers, and skips anything derivable from the codebase or already said in an instruction file.
automation mode A run started from a stored prompt rather than from a mention. Supplying that one input is what selects it.
autotriage A model call that reads a finding, the surrounding code and the team's past decisions, and proposes that the finding be acted on or ignored. It closes nothing on its own.
benchmark saturation The point at which a benchmark stops separating two models, because the leaders resolve nearly all of it. The scores keep rising and stop meaning anything.
credential masking Showing a sandboxed command a placeholder in place of a secret, and letting the proxy substitute the real value only on requests to named hosts. Distinct from denying it, which protects the secret and breaks the tool.
devcontainer A declarative development environment defined by a devcontainer.json. It is reproducible only when its image tag names a build rather than latest.
diff-aware scanning Scanning only what a change touched rather than the whole tree, so a gate can be turned on without a backlog making it unreadable.
egress allowlist The set of hosts an agent's machine may reach. It admits a host rather than a purpose, which is why a second, provenance-checking proxy sits behind it.
evidence rule The rule that makes a readiness score reproducible: every point is a file path or a command you ran, never an impression. A dimension whose evidence you cannot name scores zero.
factory loop The ordinary delivery cycle - issue, branch, pull request, review, merge, deploy, monitor - with an agent walking some of its arcs and a person on exactly one.
fire payload Text supplied when an unattended run is triggered. It arrives wrapped and labelled untrusted, and stays inert unless the stored prompt explicitly names the block.
flaky check A check that fails for reasons unrelated to the change. Worse for an agent than no check, because you remember the flake across runs and the agent reads it as information and edits correct code.
gate The one arc of the factory loop a person must walk. For nearly every team it is merge, because everything before it is a proposal and everything after it is production.
harness The ordinary program that drives the loop: it assembles the request, dispatches the tool calls, applies your rules, and shows you the result. It is what you are typing into, and it is not the model.
indirect prompt injection Injection that arrives through content the model reads - a file, a fetched page, a tool result, a tool description - rather than through what a user typed.
instruction file The repository's standing brief for agents, usually AGENTS.md. It is loaded into every session and charged against context on every turn, so it has a budget: one published harness caps the initial load at 80,000 characters.
job summary Markdown a step appends to the file named by $GITHUB_STEP_SUMMARY, capped at 1 MiB per step with at most 20 shown per job. The right home for a table of verdicts and the command that fixes each.
kill switch A control that stops a class of agents at once. Five exist, they act at different scopes, and each leaves something else still running.
lethal trifecta Access to private data, exposure to untrusted content, and the ability to communicate externally, all in one agent. Cutting any one leg ends the exfiltration path.
line jumping Tool poisoning that lands when the client lists tools, before any tool has been invoked, so no approval gate has had anything to approve.
lockfile The generated file that turns "it installed" into "it installed the same thing CI installed". It only makes that second claim when the install command carries the frozen or deployment flag.
metavariable A $NAME placeholder in a pattern that matches an unknown value, and matches the same thing everywhere it appears within one logical AND.
oracle Whatever the agent can run that returns a pass or a fail: a suite, a build exit code, a linter, a fixture diff, a screenshot comparison. Without one, "looks done" is the only signal it has.
ownership coverage The share of paths a CODEOWNERS file actually matches. Tracked as a committed list of uncovered paths, it becomes a number that can only go down.
path-scoped rule An instruction file carrying a paths field, so it enters the context window only when the agent reads a matching file and costs nothing on every other turn.
permission mode The session-wide baseline for which actions run without anybody being asked, and who reviews the rest: you, a classifier, or nobody.
permission rule A tool name, optionally narrowed by a specifier, in an allow, ask or deny list. Deny is read first, then ask, then allow, and the first match decides.
pillar One of the nine dimensions of the published Agent Readiness Model. Pillars say along what; levels say how far. Six of the nine are movable by one engineer in an afternoon.
PreToolUse hook A program that receives a proposed tool call as JSON and returns a decision. Deterministic where a classifier is probabilistic, and blind to anything not in the call.
prompt injection Input that alters the model's behaviour or output in unintended ways. In a coding agent the direct form matters least, because the typist already has your reach.
push protection Blocking a push that contains a detected secret, so the credential never reaches the remote at all. The only control in this module that prevents rather than reports.
ratchet baseline A committed list of known failures, so a new defect fails the build and existing debt does not. It only shrinks if a recorded failure that stops happening also fails.
reachability Whether the vulnerable code inside a flagged dependency is actually called from yours. A three-way verdict - reachable, unreachable, or no analysis - rather than a yes or no.
readiness level One of five bands - Functional, Documented, Standardized, Optimized, Autonomous. A repository unlocks the next by passing 80% of the criteria at the one below, and work above a locked gate scores nothing.
rug pull A server changing a tool's description or behaviour after the user approved it, so the artefact now running is not the artefact that was approved.
sandbox Filesystem and network isolation applied by the operating system to a command and every process it starts, which is the set a rule on a command string cannot see into.
SARIF The interchange format that puts a scanner finding on a specific line in a code-hosting interface. Uploading it needs a write scope the rest of the workflow does not.
SAST Static application security testing: reading first-party source, without running it, to find code shaped dangerously.
SCA Software composition analysis: matching the packages a manifest declares against a vulnerability database. It reads lockfiles and never your logic.
secret scanning Reading text, including git history, for things shaped like credentials. A key deleted from the working tree is still in the history a scanner reads.
selectable test A documented way to run one file or one test rather than the whole suite. It is what puts the check inside the loop: iterations per hour is sixty divided by the suite's minutes.
shadow mode A newly added agent that only proposes - comments, drafts, suggestions - until its record justifies widening what it may do.
silent gap A gap that lets the run finish and report success anyway, such as a timed-out suite or an unmarked generated file. The opposite is a loud gap, which stops the agent and has already diagnosed itself.
source, sink, sanitizer Where untrusted data enters, where it must never arrive, and what clears the marker on the way. The three arms of a taint rule.
taint A marker attached to a value because it came from an untrusted source, carried along the dataflow until something clears it.
task runner One documented entry point per intent - bin/setup, bin/test, bin/verify - so the agent never reconstructs a command line. The verify entry is the definition of done.
time horizon, 50% The length of task, in human minutes, that a model completes half the time. It keeps discriminating between models after a pass rate has saturated.
tool call A structured request from the model naming a tool and its arguments. It is a request rather than an action: nothing has happened until your program acts on it.
tool poisoning Hiding instructions inside a tool's description, which the model reads in full and the user usually sees only in summary.
tool result What your program sends back after running a tool. A refusal is a tool result too, and it travels through the same channel as a success.
validator Code that calls the issuing service to decide whether a detected credential is live, replacing a guess about a string with a fact about an account.
weak-link production The reading under which a pipeline's gains are capped by its least-improved stage. It is the authors' own explanation for commits rising 180 percent while releases rose 30.
workload identity federation Exchanging a workflow's own short-lived OpenID Connect token for provider access through a named service account, so no long-lived key is stored anywhere.
