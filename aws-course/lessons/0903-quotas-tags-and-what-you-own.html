What you have and what you may have are both things you instrument

working 7 min Capability keys quota-management, resource-tagging, config-drift-assessment, resource-graph-query and compliance-pack. · Service Quotas

The one-minute version

  • Quotas are per service, per account, per Region. An increase granted in one Region does nothing in the next, and quotas for global services are requested in us-east-1.
  • New accounts start with small vCPU-based EC2 quotas - often zero for accelerated families - so capacity has to be requested before it can be designed around.
  • Tags are the only attribute that crosses every service, which is why tag policies exist to enforce key and value standards organisation-wide.
  • Cost allocation tags need explicit activation and take about a day to appear, so a tag applied today does not explain yesterday's bill.
  • What it costs: there is no unified graph query language. Inventory is assembled from a configuration recorder, a keyword index and your own tags, and each of the three is partial.

1. The mechanism: where a quota lives

2. Tags, the only attribute every service shares

Tags are how an estate is sliced by anything the platform does not model - team, environment, cost centre, data classification. Tag policies apply at organisation level and enforce which keys and which values are acceptable, so the slicing works because the tags are consistent rather than because everyone remembered (Tag Editor).

Two tag behaviours surprise people. Cost allocation tags must be activated explicitly before they appear in cost reporting, and activation takes about a day - so tagging an estate today and opening a cost report tomorrow shows untagged history, not a broken tag. And on EC2, tags are exposed through instance metadata, so a workload can read its own tags without an API call.

3. Assembling an inventory from three partial views

For an auditor's evidence there are two different products. AWS Artifact self-serves AWS's own attestations - the audits of the platform itself. The service that automated evidence collection about your estate is entering maintenance, and AWS points that work at Config conformance packs and partner tools instead (availability change).
The reframing Treat inventory as a pipeline rather than a query. Turn the recorder on before you need the history, index every Region before you need to search, and enforce the tag standard before the resources exist - because every one of these three views only knows about what it was watching at the time.

Check yourself

Retrieval practice

Answer from memory before revealing.

A quota increase was granted last month. A launch in a second Region now fails on the same quota. Why?
Quotas are per service, per account and per Region, so an increase in one Region says nothing about another. Increases do not lapse with low use, they are granted per account rather than organisation-wide, and no support plan change is implied by a second Region.
Tags were applied estate-wide yesterday and today's cost report still shows them as untagged. What is happening?
A cost allocation tag has to be activated explicitly and takes about a day to appear, so the report is simply behind. Tag policies would have prevented the tags being written rather than hiding them afterwards, cost reporting does not depend on the configuration recorder, and the delay is roughly a day rather than a billing period.
Why can no single query list every resource with a given relationship across the estate?
No unified graph query language exists, so relationships must be assembled across partial views, and Config advanced queries accept a SELECT subset with no joins. Configuration items do record relationships, tag visibility is not the constraint, and the index is eventually consistent rather than refreshed daily.

Practice about 15 minutes, with paper

Practice 1working

A company is opening a second Region for a workload that runs 400 vCPUs of general-purpose instances and 32 GPU vCPUs, behind a load balancer, with data in S3. Finance separately wants every resource attributed to one of nine cost centres. The security team asks for an inventory of every internet-facing resource in both Regions.

List the preparation each of the three demands needs, and name the one item with a lead time you cannot compress.

Hint

Take the three demands separately and ask what has to be true before each one can be satisfied. Two of the three can be arranged in an afternoon; one depends on somebody else saying yes.

Show the worked solution
  1. Capacity in the second Region. Quotas are per Region, so both the general-purpose vCPU quota and the accelerated-family quota must be requested there specifically. The accelerated one is the risk: new accounts commonly start at zero for those families, so 32 GPU vCPUs is a request rather than a formality.
  2. Check the rest of the stack too. Load balancers, buckets and everything else carry their own quotas in the new Region. Use the utilisation view against the existing Region as the checklist rather than guessing which limits matter.
  3. Cost attribution. Define the tag key in an organisation tag policy so the nine values are the only acceptable ones, apply the tags in bulk, then activate the key as a cost allocation tag and expect about a day before it appears in cost reporting. Reporting on months already closed will not be retagged.
  4. The internet-facing inventory. Turn on the configuration recorder for the relevant resource types in both Regions, create a Resource Explorer index in each Region, and accept that the answer is assembled from both plus your tags. Remember that Config advanced queries have no joins, so a relationship question becomes several queries and some code.
  5. Name the incompressible lead time. The accelerated-instance quota increase. Everything else is configuration you control; that one is a request to AWS and it decides when the second Region can actually run the workload.

Sanity check. Your answer should contain two quota requests rather than one, and your incompressible item should be the one that leaves your organisation. If you assumed the existing Region's quotas carried over, that is the failure this problem exists to produce.
