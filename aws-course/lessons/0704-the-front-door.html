A request crosses a ladder of front doors, one rung per question

working 8 min Capability keys l7-load-balancer, l4-load-balancer, gateway-load-balancer, global-front-door, cdn, authoritative-dns, private-dns, dns-routing-policies and domain-registrar. · Amazon CloudFront

The one-minute version

  • Three balancers, chosen by layer: ALB routes on host, path, header and query at layer 7; NLB works at layer 4 with static addresses per zone; GWLB is a transparent layer-3 entry point that puts third-party appliances inline.
  • Two global front doors that complement rather than replace each other: CloudFront caches and terminates at the edge, and Global Accelerator gives two static anycast addresses that ride the AWS backbone to healthy Regions.
  • Route 53 is the authoritative DNS, with eight routing policies that decide which answer a caller gets, and private hosted zones that give a different answer inside a VPC.
  • The Route 53 100 percent monthly uptime SLA covers DNS queries per hosted zone. Domain registration carries no SLA, which is a different product on the same console page.
  • What it costs: each rung has its own failure mode and its own cache, so a change at the DNS rung is not a change any caller sees until their resolver agrees.

1. The mental model: the ladder

2. The mechanism: which balancer, and why

Two details decide real designs. An ALB bills hourly plus capacity units and defaults to 100 rules per listener, an adjustable quota that a large host-based routing scheme reaches sooner than expected (Application Load Balancer). An NLB uses zonal isolation: an unhealthy zone is removed from DNS rather than being balanced into (Network Load Balancer).

3. Two global front doors that are not rivals

CloudFront is a content delivery network: hundreds of points of presence, origin access control for signed S3 origins, and two ways to run code at the edge - CloudFront Functions for sub-millisecond JavaScript and Lambda@Edge for richer Node.js or Python logic. Global Accelerator is two static anycast addresses that carry any protocol over the AWS backbone to healthy regional endpoints, with sub-minute failover and traffic dials (Global Accelerator). Reach for the accelerator when the traffic is not HTTP - gaming over UDP, IoT, voice - or when HTTP needs fixed addresses. They are complementary, not alternatives.

4. The rung above everything: DNS

A private hosted zone gives a different answer inside an associated VPC, which is what split-view DNS means here. It requires the VPC's DNS hostnames and DNS support attributes to be enabled, and a cross-account association has to be authorised from the other side first (private hosted zones). A name that resolves for you and not for a colleague in another account is almost always this.

Registration is a separate product from resolution. The Route 53 registrar is ICANN-accredited, includes hosted DNS and WHOIS privacy with a registration, and inherits ICANN's sixty-day transfer lock after a registration or transfer - a constraint that has delayed more than one migration (Route 53 registrar).

The reframing These are not competing products to choose between. They are rungs, and a real system uses several at once: a DNS policy chooses a Region, an edge or an accelerator carries the traffic there, a balancer chooses a target group, and a health check at each rung removes what is broken. Ask which rung a requirement belongs to before asking which service satisfies it.

Check yourself

Retrieval practice

Answer from memory before revealing.

A regulator requires two fixed IP addresses to allow-list for a non-HTTP protocol. Which service fits?
Global Accelerator provides exactly two static anycast addresses and carries any protocol. CloudFront is an HTTP delivery network without a fixed pair of addresses to hand out, IP-based routing steers on the caller's address rather than publishing yours, and an ALB does not offer per-zone static addresses - that is the NLB.
A name resolves correctly from one account and not from another. What is the most likely cause?
A private hosted zone answers only inside VPCs associated with it, and cross-account association needs authorisation from the other side. A weighted record with a zero share would fail everywhere, a cache miss resolves itself within the record's lifetime, and a transfer lock affects moving a domain rather than resolving it.
Which requirement rules out an Application Load Balancer?
Client IP preservation is a Network Load Balancer property. Path and header routing is exactly what layer-7 balancing is for, authentication actions at the listener are an ALB feature, and a web application firewall attaches to an ALB listener.

Practice about 15 minutes, with paper

Practice 1working

A company runs one web application in two Regions and a real-time voice service in three. The web application must serve static assets fast worldwide, route /api to one target group and everything else to another, and fail over between Regions within a minute. The voice service runs over UDP, must be allow-listed by two enterprise customers, and must never send a caller to an unhealthy Region.

Design the inbound path for each, naming the rung each requirement lands on, and identify the one requirement that DNS alone cannot meet.

Hint

Take the requirements one at a time and label each with a rung - name, edge, balancer, target - before naming a service. The requirement DNS cannot meet is the one with a deadline measured in seconds.

Show the worked solution
  1. Web, edge rung. CloudFront in front of both Regions. Static assets are served from the point of presence, and origin fetches from AWS origins carry no transfer charge, so the edge pays for part of itself.
  2. Web, balancer rung. An Application Load Balancer per Region. Routing /api to one target group and the rest to another is path-based layer-7 routing, which is the one thing only the ALB can do. Keep an eye on the hundred-rules-per-listener default if the path list grows.
  3. Web, failover rung. A Route 53 failover policy with health checks removes an unhealthy Region from the answer. Note the honest limit: DNS failover is bounded by record lifetime and by whatever resolvers actually do, so "within a minute" is a hope rather than a guarantee at this rung.
  4. Voice, everything at once. Global Accelerator. UDP rules out CloudFront, the two enterprise allow-lists are exactly the two static anycast addresses, and the accelerator's own health checking gives sub-minute failover away from an unhealthy Region without waiting for anyone's resolver cache.
  5. Name the requirement DNS cannot meet. Failing over inside a minute. It is the same requirement in both systems, and only the voice design actually satisfies it - which is the argument for putting an accelerator in front of the web application too if the one-minute figure is a real commitment rather than an aspiration.

Sanity check. Every requirement should be labelled with a rung, and your two designs should share no services except Route 53. If you put the voice service behind CloudFront, check the protocol: a content delivery network is an HTTP product.
