The packet filters never look inside the packet

working 7 min Capability keys cloud-firewall, gateway-load-balancer and packet-mirroring. · AWS Network Firewall

The one-minute version

  • Security groups and network ACLs decide whether a packet may pass. Nothing about them examines its contents.
  • Network Firewall is the managed inspection layer: stateless rules plus a Suricata-compatible stateful engine, with TLS inspection, deployed centrally in an inspection network.
  • Where the appliance is somebody else's, the Gateway Load Balancer puts it transparently in the path and scales it, reached across networks through its own endpoints.
  • Traffic mirroring copies traffic from an interface to an out-of-band appliance: a session binds a source interface, a filter and a target, and filters plus truncation keep the volume sane.
  • What it costs: mirroring is limited by instance type, so a design that assumes every instance can be mirrored has to be checked against the supported list first.

1. The mental model: three ways to see inside

2. The mechanism: one place to inspect everything

The stateful engine being Suricata-compatible matters commercially as well as technically: rule sets written for that engine are portable, so an organisation with existing intrusion-detection rules is not starting from an empty policy. TLS inspection is available where the content of encrypted sessions has to be examined, which is a decision with privacy and key-handling consequences well beyond networking.

3. The copy that cannot block

Instance-type support for mirroring is limited. A monitoring design that assumes every instance in the estate can be mirrored will meet that list at the worst moment, so check it while choosing instance types rather than while building the detection.
The reframing Sort these three by what happens when the inspection layer fails. In-path inspection failing takes the traffic with it; an out-of-band copy failing costs you visibility and nothing else. That single question decides which of the three a given requirement should use, long before anyone compares rule languages.

Check yourself

Retrieval practice

Answer from memory before revealing.

Traffic between two workload networks is not being inspected despite a firewall being deployed. What is missing?
In-path inspection only sees what routing sends to it, so the route tables are the first thing to check. A missing rule would let traffic through after inspection rather than skipping it, and mirroring is an out-of-band mechanism that is not how a firewall receives traffic in the path.
Which mechanism cannot drop a malicious packet?
A mirror is a copy and the original is unaffected, so mirroring gives visibility and never enforcement. The stateful engine and an in-path appliance both sit in the traffic path, and a network ACL denies at the subnet edge.
What does a mirror session bind together?
A session is exactly those three: where the copy comes from, what is kept, and where it goes. The other three answers describe routing, filtering and load balancing constructs that belong to other parts of the platform.

Practice about 15 minutes, with paper

Practice 1working

A bank must satisfy three requirements. Outbound traffic from every workload network must be inspected and blocked when it matches known-bad indicators. A security team wants to run their existing intrusion-detection rules, written for Suricata, without rewriting them. A forensics team wants full packet capture from four specific application servers, without any risk of affecting production traffic.

Choose a mechanism for each, say where the routing has to change, and name the one preparation step that has to happen before the forensics requirement can be promised.

Hint

Ask of each requirement whether it must block or only observe. Two of the three must block, and one must be certain not to.

Show the worked solution
  1. Outbound inspection with blocking - Network Firewall in an inspection network. It must be in the path to block, so a dedicated inspection network attached to the transit hub is the shape, with the firewall's endpoints inside it.
  2. Say where routing changes. Each workload network's route to the internet, and the hub's route tables, must send traffic through the inspection network rather than directly to egress. Without that change the firewall exists and inspects nothing, which is the most common failure of this pattern.
  3. Existing Suricata rules - the same service. The stateful engine is Suricata-compatible, so the team's rules are portable rather than rewritten. This is a reason to prefer the managed firewall over a third-party appliance here, since no appliance licence is needed to get the rule language they already use.
  4. Forensic packet capture - traffic mirroring. The requirement explicitly forbids any risk to production traffic, and a mirror is an out-of-band copy that cannot drop the original. Bind a session per source interface, filter to the traffic of interest, and send the copies to the forensic appliances behind a balancer with a UDP listener if one appliance cannot keep up.
  5. Name the preparation step. Check the instance types of the four application servers against the mirroring support list. Mirroring is limited by instance type, so the promise cannot be made until that is confirmed, and if a server is unsupported the answer is a different instance type rather than a different filter.

Sanity check. Two requirements should share one service, and the third should be the only one described as out of band. If your forensic answer put an appliance in the path, re-read the requirement - it rules that out explicitly.
