A function is a container with three properties taken away and one given back

working 6 min Capability key functions-faas. · AWS Lambda

The one-minute version

  • A Lambda function is invoked by an event, billed per request and per gigabyte-second, and has no long-running process for you to hold state in.
  • The ceiling that decides most designs is duration: fifteen minutes is the maximum a single invocation may run.
  • It assumes its execution role automatically at invoke time, so a function is the cleanest identity story in this module - there is no credential anywhere in the package.
  • A function can be packaged as a container image of up to ten gigabytes pulled from ECR, so the container and function worlds share a build.
  • What it costs: releasing safely happens through an alias rather than through the function, and a workload that does not fit inside fifteen minutes has to be split rather than tuned.

1. The mental model: an event, a handler, and nothing between invocations

Function logs go to CloudWatch Logs by default, which is unusual on a platform where most services log only once you ask (Lambda and CloudWatch Logs). It is convenient and it is a cost line, and Module 10 returns to what that costs at volume.

2. The mechanism: releasing through an alias

The reframing Every layer of this module has the same release shape and a different price for it. A fleet rolls a launch-template version and rebuilds machines. A service rolls a task set and drains connections. A function repoints a name. The mechanism you get is decided by the layer you chose, so "how do we roll back?" is really a question you answered earlier.

3. The wall at fifteen minutes

A single invocation may run for at most fifteen minutes. That is not a default to raise; it is the shape of the product, and it is the boundary that sends a workload back up the ladder.

What the work looks likeWhere it belongs
Short, event-shaped, independentA function
Long but divisible into short stepsSeveral functions with a workflow between them - Module 12
Long and genuinely one processA container task or a batch job - lessons 0300 and 0204
Needs a GPU, a host port or a block volumeNode-backed container capacity, per lesson 0301
Splitting a long job into steps looks free and is not. The state that lived in one process now has to be written down and passed between invocations, retries stop being local, and partial failure becomes a case you must design rather than one the runtime handles. Workflow orchestration is Module 12's subject, and the express execution mode there carries a five-minute ceiling of its own, so the split has to be genuine rather than nominal.

4. One build for two worlds

A function does not have to be a zip archive. It can be a container image of up to ten gigabytes pulled from ECR, which lets a team keep one build pipeline, one scanning path and one registry for both its containers and its functions. Lesson 0302's exception applies here and nowhere else: that image must be pushed rather than reached through a pull-through cache rule.

Check yourself

Retrieval practice

Answer from memory before revealing.

A nightly job takes about fifty minutes as a single process and cannot be divided. Where does it belong?
Fifteen minutes is the ceiling rather than a default, so no timeout setting reaches fifty. Re-invoking a function repeatedly only works if the work is divisible, and the requirement says it is not. A workflow of short steps has the same problem. Indivisible long work belongs on container or batch capacity.
Where does a Lambda function get its AWS credentials from?
Lambda assumes the execution role automatically at invoke time and hands the code temporary credentials, so nothing is stored in the package or in configuration. A key file or an environment variable would be the credential this design exists to remove, and the instance metadata service belongs to EC2 rather than to functions.
A new function version misbehaves under a canary shift. What is the rollback?
Versions are immutable and the alias is the moving pointer, so rollback is one alias update and the previous version is untouched and still there. Redeploying over a version is not possible, deleting the new version is destructive and unnecessary, and draining environments is not a concept a caller sees.

Practice about 15 minutes, with paper

Practice 1working

A media pipeline has four stages: accept an upload and record it, transcode a file that takes between two and forty minutes depending on size, generate three thumbnails, and notify a downstream system. The team wants everything on functions "because it is serverless".

Place each stage, name the property that decided it, and say what new failure case the team inherits from the one stage that has to be split or moved.

Hint

Only one of the four stages has an unbounded duration, and it is the only one worth arguing about. Ask what the runtime handled for you that you now have to handle yourself.

Show the worked solution
  1. Accept and record: a function. It is short, event-shaped and independent, which is exactly the fit. The execution role is assumed at invoke, so it writes its record with no stored credential.
  2. Thumbnails: a function, or three. Also short and independent, and the three can be separate invocations that fail independently rather than one that fails as a unit.
  3. Notify: a function. Shortest of all, and event-shaped by definition.
  4. Transcode: not a function. Up to forty minutes exceeds the fifteen-minute ceiling, and no setting raises it. If the transcode can be split by segment, it becomes several short invocations behind a workflow. If it cannot, it belongs on a container task or a batch job.
  5. Name the inherited failure case. Whichever way the transcode is moved, partial failure becomes yours. A single long process either finished or did not; a segmented job can leave some segments done and some not, so the pipeline now needs a record of which segments completed, a retry that does not redo finished work, and a decision about what a half-transcoded file means downstream.

Sanity check. Three stages should be functions and exactly one should be argued about, and your answer should end with a new failure case rather than with a service name. If the split cost you nothing, you have not yet asked where the intermediate state lives.
