Protection attaches to a front door, and the door decides what can protect it

working 7 min Capability keys ddos-protection and waf. · How AWS WAF works

The one-minute version

  • Shield Standard is always on and carries no charge at three front doors - the authoritative DNS service, the content delivery network and the load balancers.
  • Shield Advanced is the paid tier, adding cost protection, access to a response team and layer-7 rule groups, with protection groups that group resources for detection.
  • AWS WAF is the layer-7 web access control list, and it attaches to five surfaces: the CDN, the application load balancer, the API gateway, the GraphQL service and the customer directory.
  • A web ACL's real limit is web ACL capacity units: 1,500 are included and 5,000 is the maximum, so a rule set is budgeted rather than counted.
  • What it costs: managed rule groups are convenient and consume that budget, so adding several of them can exhaust the capacity before the custom rules are written.

1. The mental model: what attaches where

2. The mechanism: a rule budget, not a rule count

The cost shape is worth knowing even without the numbers: a web ACL is charged monthly, each rule is charged monthly, and requests are charged per million inspected. So a rule set grows the bill in two directions at once, and traffic growth moves the third term on its own.

3. What a request meets on the way in

Shield Advanced's response team is gated on the support plan: contacting it requires a Business or Enterprise support plan. So the incident capability people usually buy Advanced for depends on a separate commercial arrangement, and that is worth confirming before an incident rather than during one.
The reframing Edge protection is not a product you switch on, it is a property of the front door you chose in module 07. The volumetric layer is free and automatic on three managed doors; everything above it is attached, budgeted and paid for per rule and per million requests. Deciding where traffic enters is therefore the security decision, and the rules are the detail.

Check yourself

Retrieval practice

Answer from memory before revealing.

A web ACL rejects a new rule although only a dozen rules are attached. What is the likely cause?
Capacity units, not rule count, are what a web ACL is budgeted in, and managed rule groups consume a large share. There is no small cap on the number of rules, attaching an ACL to several surfaces is normal, and managed and custom rules are designed to be combined.
Which surface can a web ACL not be attached to?
A web ACL attaches to managed front doors - the CDN, the application load balancer, the API gateway, the GraphQL service and the customer directory - not to an instance addressed directly. The first three are all supported attachment points.
What does Shield Standard cost, and where does it apply?
Shield Standard is always on and carries no charge at the DNS service, the CDN and the load balancers. It needs no enabling, and the monthly commitment belongs to Shield Advanced rather than to the standard tier.

Practice about 15 minutes, with paper

Practice 1working

A retailer exposes three things publicly: a web storefront behind the CDN, a partner API on the API gateway, and a legacy pricing service reached directly on an instance's public address. Credential-stuffing attempts are rising on the storefront sign-in, and finance is worried about the cost of absorbing a volumetric attack.

Design the protection for each of the three, name the one that cannot be protected as it stands, and say what argues for the paid DDoS tier.

Hint

Go through the attachment map before writing any rules. One of the three exposures is not behind a managed front door, which settles what can be done about it.

Show the worked solution
  1. Storefront - a web ACL on the CDN distribution. Volumetric protection is already there and free. For credential stuffing, the managed groups for bots and fraud are the mechanism, and a CAPTCHA challenge on the sign-in path is the middle outcome between allowing and blocking, which suits traffic that is suspicious rather than certainly hostile.
  2. Partner API - a web ACL on the API gateway. Same instrument, different attachment point. Keep the rule set smaller here: a partner API has a narrow expected shape, so custom rules encoding that shape are worth more than several managed groups, and they cost less capacity.
  3. Budget the capacity deliberately. A web ACL includes 1,500 capacity units and can reach 5,000. Adopting three managed groups on the storefront can consume most of the included budget, so check what remains before promising the custom rules.
  4. Name the one that cannot be protected. The legacy pricing service on a public instance address. It is behind none of the three managed front doors, so neither the always-on volumetric protection nor a web ACL applies. The fix is architectural - put it behind a load balancer or the CDN - not a rule.
  5. Say what argues for the paid tier. Finance's concern is the bill during an attack, and cost protection is exactly what the paid tier adds, alongside a response team and layer-7 rule groups. Confirm the support plan before relying on the response team, because contacting it requires a Business or Enterprise plan.

Sanity check. Two of your three answers should attach the same product at different points, and the third should be a networking change rather than a security control. If you proposed a firewall rule for the direct instance exposure, re-read the attachment map.
