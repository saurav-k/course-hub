Module 04 · Storage · Lesson 0404

An archive class is chosen by how long you may wait, not by how cold the data feels

working 6 min Capability keys archive-storage, hybrid-storage-gateway and bulk-transfer-appliance. · S3 Glacier storage classes

The one-minute version

  • Archive on AWS is a set of S3 storage classes, not a separate service. The old standalone vault product is legacy and is not the current path.
  • Two of those classes require an explicit restore before the object can be read, and the class is chosen by how long that restore may take.
  • The fastest restore option is measured in minutes. The coldest class has no fast option at all and is measured in hours.
  • Getting bulk data in has three shapes: an online transfer service, an on-premises gateway appliance, and a physical path.
  • What it costs: the offline appliance family is closed to new customers with support ending, and AWS names its successors, so a new migration plan starts from the online path.

1. The mental model: cold is a waiting time, not a temperature

The reframing Choosing an archive class is writing down a recovery time objective for data nobody is watching. Ask what happens when a regulator, a court or an incident asks for one of these objects, and how long the answer "tomorrow" is acceptable for. The price difference is real, and so is the difference between five minutes and two days.

The minimum storage durations from lesson 0400 apply at this end too, and they are longer: ninety days for the flexible class and a hundred and eighty for the coldest, with early-deletion fees for anything removed sooner.

2. The mechanism: how data arrives

The volume flavour of the gateway carries a distinction worth holding. In its cached mode the primary copy lives in the cloud with a local hot cache in front of it; in its stored mode the primary copy stays local and is asynchronously snapshotted to the cloud. Same product, opposite answers to "where does my data actually live".

3. What it costs: the offline path is narrowing

The rugged appliance family that used to be the standard answer for petabyte-scale offline transfer is closed to new customers, with support ending. AWS names its successors directly: DataSync for transfers that can go online, and a physical Data Transfer Terminal for those that cannot (Snow Family).

This is lesson 0103's habit doing real work. A migration plan copied from older material will name an appliance a new customer cannot order, and the discovery usually happens after the timeline has been agreed. Check the status of every service in a migration plan before the plan is signed, not while it is being executed.

Check yourself

Retrieval practice

Answer from memory before revealing.

A regulator may ask for an archived record and expects it within the working day. Which class fits?
The flexible class can be restored well inside a working day and is priced for data that is rarely read. Deep Archive has no expedited option and may take up to forty-eight hours, which misses the requirement. One Zone infrequent access accepts losing a zone, which is wrong for a compliance record, and Standard pays hot prices for data nobody reads.
A team wants on-premises servers to keep writing to a local NFS share while the data lands in S3. What is that?
A gateway stays in place and presents cloud storage through a local protocol, which is exactly the described behaviour. DataSync moves data on a schedule rather than presenting a share. A physical path is a one-way bulk move. And replication copies between buckets, never into a data centre.
A migration plan drafted from older material specifies rugged offline appliances. What is the correct correction?
The family is closed to new customers with support ending, and AWS names DataSync for online transfers and a physical terminal for the rest. A new customer cannot order the appliances at all, so neither keeping them nor padding the schedule helps. The tape flavour of the gateway serves backup software rather than bulk migration.

Practice about 15 minutes, with paper

Practice 1working

A hospital keeps twelve years of imaging studies. Studies from the last month are read daily. Studies from the last two years are pulled occasionally and a clinician expects them within minutes. Everything older is read only for audits, which are scheduled weeks ahead. The whole archive is currently on tape in the hospital's own basement, and the network link is modest.

Design the storage ladder with a class for each of the three ages, and separately choose how the existing archive gets in. Justify the archive class of the oldest data by the audit process rather than by price.

Hint

Three ages, three classes, chosen by how long a reader may wait. Then treat the migration as a separate problem, decided by size and by link speed rather than by the classes you just chose.

Show the worked solution
  1. Last month: Standard. Read daily, so there is no waiting to trade away and no minimum duration to trip over. Lifecycle rules move objects out of it as they age.
  2. Last two years: an archive class that reads immediately. A clinician expecting a study within minutes cannot wait for a restore request, so the class that is archive-priced but readable without one is the fit. Its ninety-day minimum duration is irrelevant against a two-year window.
  3. Older than two years: Deep Archive, justified by the audit. Audits are scheduled weeks ahead, so a retrieval bound of up to forty-eight hours is comfortably inside the notice period. That is the justification - not that the data is old, but that the reader has told you how long they can wait.
  4. Say what would change the answer. If any audit could arrive without notice, the coldest class becomes wrong, because it has no expedited option and no amount of urgency shortens it. That single fact about the process, not the age of the data, is what decides the bottom of the ladder.
  5. Handle the migration separately. Twelve years of imaging over a modest link is the case the physical path exists for, and the appliance family older material would name is closed to new customers. So the plan is DataSync for whatever the link can carry in the available window, and the named physical transfer path for the remainder.

Sanity check. Each of the three classes should be justified by a waiting time somebody stated, and the migration should be decided by link speed rather than by the storage classes. If the oldest data was assigned to the coldest class because it was oldest, you have not yet asked how much notice an audit gives.
