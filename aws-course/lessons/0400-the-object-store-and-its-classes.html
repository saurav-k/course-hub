Module 04 · Storage · Lesson 0400

Durability protects the bytes - everything else about losing data is a separate setting

working 6 min Capability keys object-storage and archive-storage. · Amazon S3

The one-minute version

  • S3 is key-addressed object storage with no capacity to provision, and its published design point is eleven nines of durability.
  • Durability is about the platform losing bytes. It says nothing about you losing them, which is what versioning and Object Lock are for.
  • Storage classes are the cost dial, and lifecycle rules move objects between them without the application knowing.
  • Every cheaper class buys its discount with a minimum storage duration, so an object deleted early is still billed for the rest of it.
  • What it costs: one class drops cross-zone redundancy to be cheaper, so durability and availability part company and the choice has to be made deliberately.

1. The mental model: three independent decisions

2. The mechanism: classes and the lifecycle that moves between them

One class on that diagram is different in kind. One Zone-IA stores data in a single Availability Zone, so it is cheaper and it is exposed to the loss of that zone in a way every other class is not. It is the right answer for data you can regenerate and the wrong answer for anything you cannot.

3. What the discount actually costs

The reframing A storage class is a bet on how long the object will live and how often it will be read. Get either half wrong and the cheaper class costs more: too short a life and you pay the early-deletion fee, too many reads and you pay retrieval charges that outweigh the storage saving. Measure the access pattern, or hand the decision to Intelligent-Tiering and stop guessing.
One class name still appears in old material and should not appear in a new design: Reduced Redundancy Storage, which AWS discourages. If you meet it in an existing bucket policy or lifecycle rule, treat it as something to migrate rather than something to reason about.

Check yourself

Retrieval practice

Answer from memory before revealing.

An engineer deletes a production object by mistake. Which S3 property would have prevented the loss?
Versioning keeps previous copies when an object is overwritten or deleted, and Object Lock goes further by forbidding the deletion outright. Durability and cross-zone redundancy protect against the platform losing data, not against a valid delete request. A lifecycle rule changes cost and nothing else.
A lifecycle rule moves logs to an infrequent-access class after seven days, and the logs are deleted after twenty. What happens to the bill?
The infrequent-access classes carry a thirty-day minimum, so objects deleted at day twenty are still charged for the remaining ten as an early-deletion fee, on top of the transition itself. The rule does fire, and object size does not change the minimum duration.
Which storage class trades away cross-zone redundancy for a lower price?
One Zone-IA keeps data in a single Availability Zone, which is why it is cheaper and why it is only correct for data you can regenerate. Intelligent-Tiering automates movement without changing redundancy, and both Standard-IA and Glacier Instant Retrieval keep the usual cross-zone storage.

Practice about 15 minutes, with paper

Practice 1working

A bucket holds three kinds of object. Application logs are written constantly, queried heavily for two days, occasionally for a month, then deleted at ninety days. Rendered video thumbnails can be regenerated from the source at any time and are read for the life of the product. Signed customer contracts must be retained unaltered for years and are almost never read.

Write a class and lifecycle plan for each, and name the one protection setting that belongs on only one of the three and why the other two do not need it.

Hint

For each object, answer two questions before choosing a class: how long does it live, and can it be regenerated? Then ask separately which one has a requirement that is about deletion rather than about cost.

Show the worked solution
  1. Logs: Standard, then infrequent access, then delete. Do the arithmetic rather than picking a day. The object lives ninety days and the infrequent-access minimum is thirty, so any transition on or before day sixty leaves at least thirty days in the colder class and no early-deletion fee. A transition at day thirty leaves sixty days, which is comfortably safe. Redo this the moment retention changes: at a twenty-day retention, no transition at all avoids the fee.
  2. Thumbnails: One Zone-IA is defensible here and nowhere else in this problem. They are regenerable from the source, so the loss of a zone costs compute rather than data. They are read for the life of the product, so watch the retrieval charges, and compare against Intelligent-Tiering if the read pattern is uneven.
  3. Contracts: an archive class, chosen for retrieval time rather than price. Almost never read and retained for years means the storage cost dominates and the minimum duration is irrelevant. Lesson 0404 works through which archive class, because that decision is made on how long a retrieval may take.
  4. Name the protection setting. Object Lock, on the contracts only. The requirement is that they be retained unaltered, which is a statement about deletion and modification rather than about durability or cost, and write-once-read-many retention is the setting that expresses it.
  5. Say why the other two do not need it. Logs are meant to be deleted on schedule, so a lock would fight the lifecycle rule. Thumbnails are regenerable, so the cost of losing one is a re-render rather than a loss.

Sanity check. Each object should get a class chosen from its life and its read pattern, and exactly one should get a protection setting. If you put One Zone-IA on the contracts because it was cheapest, re-read the requirement: unaltered retention for years is not compatible with the one class that accepts losing a zone.
