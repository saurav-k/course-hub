Four detectors, and the input each one reads decides what it can find

working 7 min Capability keys threat-detection, vulnerability-scanning, data-classification and security-investigation-graph. · Amazon GuardDuty

The one-minute version

  • GuardDuty is agentless threat detection over three streams you already met: the audit trail, network flow logs and DNS logs, with protection plans extending it to storage, Kubernetes runtime, databases, functions, malware and AI workloads.
  • Inspector scans for vulnerabilities: instances by agent and by agentless snapshot, container images continuously in the registry, and functions with their layers and code.
  • Macie classifies data - personal, secret and payment information in object storage - and its automated discovery samples rather than scanning everything.
  • Detective is not a detector at all: it builds a behaviour graph from findings, audit records and flow logs to scope an investigation that somebody else started.
  • What it costs: findings age out. Threat findings are kept 90 days in the console, posture findings are deleted after 90 days without an update, and only an export keeps them longer.

3. What a finding does after it is raised

Automated data discovery samples rather than scanning everything, and discovery jobs carry a monthly volume guardrail. So "we scan our object storage for personal data" is true in a statistical sense and not in an exhaustive one, and a compliance claim that assumes full coverage needs a scheduled job scoped to the buckets that matter (data discovery).

Vulnerability scanning has the opposite property: it is continuous, and it rescans when a new advisory is published rather than only on a schedule, so a package that was clean yesterday can produce a finding today with no change on your side (scanning resources). Instances can be covered by agent or by agentless snapshot scanning, which is what makes coverage of an estate with unmanaged hosts achievable.

The reframing These four answer different questions and are often bought as one thing called "security". What is happening, what is weak, what is sensitive, and what else did it touch - four questions, four inputs, four services. An estate with only the first has no idea what its data is; an estate with only the second has no idea it is under attack.

Check yourself

Retrieval practice

Answer from memory before revealing.

Which service would surface a credential being used from an unusual location?
Behavioural threat detection over the audit trail, flow logs and DNS logs is what notices anomalous credential use. Vulnerability scanning reads software inventories, data classification reads object contents, and the investigation graph scopes a finding that something else raised.
A finding raised four months ago cannot be found in the console. Why?
Threat findings are retained for ninety days and posture findings are deleted after ninety days without an update, so four months is past both. The behaviour graph's year-long span is a different window, and neither resource deletion nor closing an investigation is what removes them.
What does automated data discovery actually do?
Automated discovery samples rather than scanning everything, and a scheduled job is what covers a specific scope exhaustively. It is not limited to new objects, and it does run without a job being defined - it simply does not promise completeness.

Practice about 15 minutes, with paper

Practice 1working

A company suffers an incident. An access key was used from an unfamiliar network, some objects were downloaded, and one container image in the estate turns out to have carried a known vulnerable library for months. The board asks four questions: how did we not notice, what data was taken, what else did the attacker touch, and would we still have this evidence in a year.

Answer each question with the service that addresses it, and say what would have had to be true beforehand for each answer to work.

Hint

Take the four questions in order and match each to an input rather than to a product name. The last question is not about detection at all.

Show the worked solution
  1. How did we not notice - threat detection, over telemetry that must already have been on. GuardDuty reads the audit trail, flow logs and DNS logs, so the honest answer depends on whether those streams were enabled. Lesson 1001's default column decides this, and the vulnerable image is a separate gap: continuous image scanning would have raised a finding when the advisory was published, without anybody rebuilding anything.
  2. What data was taken - data classification, scoped deliberately. Knowing which objects contained personal or payment data is what turns "some objects were downloaded" into a statement a regulator will accept. The precondition is a scheduled discovery job over the buckets that matter, because automated discovery samples and cannot support an exhaustive claim.
  3. What else did the attacker touch - the investigation graph. It builds from findings, audit records and flow logs and spans up to a year, so it answers the scoping question. The precondition is that it was enabled before the incident, since the graph is built from ingested telemetry rather than reconstructed on demand.
  4. Would we still have this evidence in a year - no, not by default. Threat findings are kept ninety days and posture findings disappear ninety days after their last update. The precondition is an export of findings to object storage with a retention that matches the legal requirement, which is a small configuration made long before it is needed.
  5. Say the common thread. Every one of the four answers depends on something being enabled beforehand. None of these services can answer a question about a period during which it was not running.

Sanity check. Each of your four answers should name a different service and a precondition that is a configuration rather than a purchase. If any answer implied a service could reconstruct the past after being switched on, that is the assumption this problem exists to remove.
