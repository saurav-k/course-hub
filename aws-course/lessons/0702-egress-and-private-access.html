A private subnet has two exits and they are priced nothing alike

working 7 min Capability keys nat-gateway and private-endpoint. · NAT gateway

The one-minute version

  • A NAT gateway gives a private subnet outbound-only internet access. It is scoped to one Availability Zone and scales from a 5 Gbps baseline towards 100 Gbps.
  • Its real ceiling is connections, not bandwidth: 55,000 simultaneous connections to one destination per IP address, and it can carry up to eight addresses.
  • Best practice is one NAT gateway per zone. Sharing one across zones works and quietly makes every zone depend on the zone it lives in.
  • VPC endpoints reach AWS services without the internet at all, and they come in two kinds: gateway endpoints for S3 and DynamoDB, which use prefix-list routes and cost nothing extra, and interface endpoints for everything else, billed hourly per zone plus per gigabyte.
  • What it costs: NAT gateways emit metrics only and no per-translation log, so port exhaustion is a metric you have to be watching rather than an entry you can search for afterwards.

1. The mental model: two doors, not one

2. The mechanism: the ceiling that is not bandwidth

When that ceiling is reached there is no log to read. A NAT gateway emits metrics and no per-translation record, and port exhaustion shows up as the ErrorPortAllocation metric. If nothing is alarming on that metric, the failure arrives as intermittent connection errors inside applications with no network evidence anywhere.

3. Zonal placement, and what sharing one costs

Interface endpoints have a second property worth knowing: an endpoint policy attaches to the endpoint itself and filters what may be done through it, which adds a resource-side control that identity policies alone cannot express (endpoint policies). A NAT gateway can also be created with a private connectivity type when the path leads to a transit gateway rather than to the internet.

The reframing A NAT gateway is not "how a private subnet gets out". It is how a private subnet reaches the public internet, which is a much smaller share of most workloads' traffic than it first appears. Enumerate the destinations before sizing the gateway: the ones that turn out to be AWS services belong on endpoints, and what is left is the real internet requirement.

Check yourself

Retrieval practice

Answer from memory before revealing.

A fleet calling one partner API sees intermittent connection failures while NAT bandwidth sits low. What is happening?
55,000 simultaneous connections per destination per address is a limit on connections rather than throughput, so it is hit while bandwidth looks idle. Scaling from the baseline raises throughput rather than dropping connections, address exhaustion would stop instances launching, and a NAT gateway carries no endpoint policy.
Which destination is reachable privately at no extra charge for the endpoint itself?
Gateway endpoints serve S3 and DynamoDB and use a prefix-list route with no extra charge. Interface endpoints, including the ones fronting a partner's own service, bill hourly per zone plus per gigabyte, and an internet destination is not reachable through any endpoint.
What is the cost of routing all three zones' subnets to one NAT gateway?
A NAT gateway is scoped to its own zone, so every subnet routed to it inherits that zone as a dependency. The gateway does not partition its bandwidth or its connection ceiling by consuming zone, and return traffic through a NAT gateway needs no special subnet rule.

Practice about 15 minutes, with paper

Practice 1working

A batch platform runs 1,200 workers across three zones. Each worker reads objects from S3 continuously, writes results to DynamoDB, fetches secrets at start-up, and calls one external pricing API up to 60 times concurrently. Today every subnet routes to a single NAT gateway in the first zone, and the monthly network bill is dominated by processing charges.

Redesign the egress path, show the arithmetic for the external API, and say which change reduces the bill and which change reduces the blast radius.

Hint

Sort the four destinations by which door each one belongs to before changing anything. Then multiply worker count by concurrent connections and compare against the published per-destination ceiling.

Show the worked solution
  1. Sort the destinations. S3 and DynamoDB are gateway endpoints. Secrets Manager is an interface endpoint. The pricing API is the only genuine internet destination, so it is the only traffic that belongs on a NAT gateway at all.
  2. Find the bill. The dominant cost is S3 and DynamoDB traffic being processed by the NAT gateway. Two gateway endpoints and two route entries remove that traffic from the gateway entirely at no extra endpoint charge, which is the change that reduces the bill.
  3. Do the arithmetic on what remains. 1,200 workers at up to 60 concurrent connections each is 72,000 connections to a single destination. One address allows 55,000, so the design is already over the ceiling and would be failing intermittently even after the endpoint change.
  4. Raise the ceiling deliberately. Two addresses on the gateway give 110,000, which clears 72,000 with headroom. Eight is the maximum, so record where the real ceiling now sits rather than treating the problem as solved for ever, and put an alarm on the port-allocation error metric because nothing else will tell you.
  5. Reduce the blast radius separately. A NAT gateway per zone, with each zone's route table pointing at its own. This costs more per hour and changes no throughput, and it is the change that stops a single zone failure removing egress from all three.

Sanity check. Your connection figure should be 72,000 and should exceed the single-address ceiling. Your two changes should be different in kind: one removes traffic, the other removes a shared dependency. If one change did both, re-read what a gateway endpoint carries - it does not carry the pricing API.
