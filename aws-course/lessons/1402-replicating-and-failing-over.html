Replicate into a cheap staging area, and the drill stops being frightening

working 6 min Capability key dr-orchestration. · AWS Elastic Disaster Recovery

The one-minute version

  • An agent on each source server replicates blocks continuously into a low-cost staging subnet - storage and minimal compute, not running copies of your machines.
  • That is what makes the economics work: a recovery point measured in seconds without paying for a second running fleet.
  • The replicated state is crash consistent, and recovery instances are launched from it on demand, giving a recovery time measured in minutes.
  • Because launching is a separate step from replicating, a drill is non-disruptive: it creates instances without interrupting replication or touching production.
  • What it costs: there is no agentless path for disaster recovery. Agentless replication belongs to the migration service, and only for VMware sources.

1. The mechanism: replication and launching are separate

2. Three operations that use the same replication

There is no agentless disaster-recovery path. The agent is required on each source server. Agentless replication exists only in the migration service, and only for VMware sources - so a fleet that cannot take an agent needs a different plan rather than a different setting (Elastic Disaster Recovery).
The reframing The reason this service exists is the cost of the waiting state. Warm standby pays for running machines you hope never to use; continuous replication into staging pays for storage instead, and buys the running machines only at the moment of the disaster. That is why it can sit between pilot light and warm standby on the previous page's curve.

Check yourself

Retrieval practice

Answer from memory before revealing.

Why is a failover drill described as non-disruptive?
Replication and launching are independent, so a drill creates instances while replication continues untouched. Pausing replication would be disruptive by definition, the drill uses current state, and drill instances are launched into a real environment rather than into none.
What sits in the staging subnet between replications?
The staging area holds the replicated data on low-cost storage with minimal compute, which is why it is far cheaper than a standby. Running copies and a scaled-down environment are the warm standby strategy, and the data is deliberately not left in the source Region.
A fleet of servers cannot accept a replication agent. What follows for disaster recovery?
The recovery service has no agentless mode, so the plan has to change rather than a setting. Agentless replication belongs to the migration service and only for VMware sources, and there is no per-server storage-layer substitute offered here.

Practice about 15 minutes, with paper

Practice 1working

A manufacturer runs sixty virtual machines in one Region: application servers, a licence server, and four appliances supplied by a vendor who forbids installing software on them. The business will accept losing a few minutes of data and being down for under an hour. Nobody has ever tested a failover because the last attempt required a maintenance window.

Design the recovery, say what happens to the four appliances, and explain what changes about testing.

Hint

Check the two accepted numbers against what continuous replication provides. Then deal separately with the machines that cannot take an agent, because no setting will help them.

Show the worked solution
  1. Check the numbers. A few minutes of data loss and under an hour of downtime match continuous block replication comfortably: recovery point in seconds and recovery time in minutes, with room to spare for the launch and validation.
  2. Protect the fifty-six servers that can take an agent. Install the replication agent, replicate into a staging subnet in the recovery Region, and prepare launch templates so the recovery instances land in the right subnets with the right security groups.
  3. Deal with the four appliances honestly. There is no agentless recovery path, so they cannot be protected this way. The options are to ask the vendor for a supported replication method, to rebuild them from the vendor's own installation media as part of the recovery procedure, or to accept that they are recovered more slowly and to say so in the plan.
  4. Check the appliances against the objective. If rebuilding an appliance takes two hours, the service's recovery time is two hours regardless of the fifty-six servers - the slowest component rule from the previous lesson. That has to be resolved or the objective renegotiated.
  5. Say what changes about testing. A drill launches recovery instances while replication continues, so no maintenance window is needed and production is untouched. Testing moves from a project to a routine, which is the change that makes the plan believable.

Sanity check. Fifty-six servers should be covered by replication and four should be a named exception with a stated cost, and your testing answer should not contain the phrase maintenance window. If the appliances were quietly left out, the objective is not met.
