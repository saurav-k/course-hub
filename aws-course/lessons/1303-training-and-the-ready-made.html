Before training anything, check whether it already exists as an API

working 6 min Capability keys model-training-platform and speech-vision-document-ai. · Amazon SageMaker AI

The one-minute version

  • SageMaker AI is the build, train, tune and deploy platform for models you own, and a unified studio brings the analytics tooling of module 06 into the same place.
  • Seven ready-made services cover speech to text, text to speech, image and video analysis, document extraction, language understanding, translation and conversational bots.
  • Document extraction goes beyond text: there are variants for expenses, identity documents and lending, which are the shapes teams most often build themselves.
  • Speech to text runs in streaming and batch forms and is eligible for regulated health workloads.
  • What it costs: the name changed and several platform features moved into maintenance, so an existing project's feature list is worth re-checking against the current documentation.

This part of the platform has moved recently. The service was renamed, a new platform appeared under a very similar name, and several features moved into maintenance. Any design that names a specific feature should be checked against the current documentation rather than against a tutorial, because "SageMaker" alone no longer identifies one thing.
The reframing Sort a machine-learning idea by who owns the model's accuracy. Call a ready-made service and accuracy is the vendor's problem. Prompt a foundation model and it is a prompt-engineering and evaluation problem. Train your own and it is yours for ever, including the retraining. All three are legitimate, and only the third is a standing commitment.

Check yourself

Retrieval practice

Answer from memory before revealing.

A team plans to train a model to extract fields from expense receipts. What should be checked first?
Document extraction has an expense variant, so the problem may already be an API call. The other three are real questions about a training project and all of them become moot if the project should not exist.
What is the standing commitment a trained model brings that an API call does not?
A model degrades as its inputs drift, so retraining is an ongoing obligation rather than a one-off. Endpoint identity follows the ordinary workload-identity model, guardrails belong to the model API, and not every trained model produces embeddings.
Which pair describes the two forms of the speech-to-text service?
Streaming handles live audio and batch handles stored files. The other three pairs belong to other services entirely - capacity modes for model inference, and execution models for workflows.

Practice about 15 minutes, with paper

Practice 1working

An insurer proposes four machine-learning projects: transcribing recorded claim calls, extracting fields from uploaded identity documents, detecting fraudulent claims from twelve years of its own claim history, and answering staff questions about internal policy documents.

Route each project to a ready-made service, the model API, or the training platform, and for the one that reaches the training platform name the commitment the business is accepting.

Hint

Ask of each project whether the problem is generic or specific to this company's own data. Only one of the four is genuinely the latter, and one of the others is a retrieval problem in disguise.

Show the worked solution
  1. Transcribing claim calls - a ready-made service. Speech to text in its batch form for recorded audio, or streaming if calls are to be transcribed live. Nothing here is specific to this insurer, so training would be rebuilding a solved problem.
  2. Identity document fields - a ready-made service. The document service has an identity-document variant, which is exactly this task. Note that the accuracy of both of these remains the vendor's problem, which is a genuine benefit rather than a compromise.
  3. Policy questions from internal documents - retrieval, not training. This is lesson 1301's pipeline: a knowledge base over the policy documents, answered by the model API with citations. Training a model on internal documents would be slower, more expensive and harder to keep current than re-indexing them.
  4. Fraud detection from twelve years of claims - the training platform. The signal lives in this insurer's own history and in patterns nobody else has, which is the case that justifies building. Everything from module 06 applies to getting the data ready.
  5. Name the commitment. Retraining, for ever. Fraud patterns change deliberately in response to detection, so the model degrades faster than most, and the business is accepting a permanent data pipeline, an evaluation practice and a retraining schedule - not a project with an end date.

Sanity check. Exactly one project should reach the training platform, and one of the other three should turn out to be a retrieval problem. If all four went to the training platform, re-read what the first three actually depend on.
