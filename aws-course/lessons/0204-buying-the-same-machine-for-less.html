The discount is not a price - it is a contract about who may take the machine back

working 7 min Capability keys spot-capacity, commitment-discounts, batch-compute and vm-instances-simplified. · How Spot Instances work

The one-minute version

  • The same instance is sold four ways, and only one of them changes the machine: on demand, reclaimable, committed, and bundled.
  • Spot is spare capacity at up to a 90 per cent discount that AWS may take back with a two-minute notice - and that notice is best-effort, not a guarantee.
  • The notice arrives twice, as an EventBridge event and as an item in the instance's own metadata, and a separate rebalance signal warns earlier that interruption is becoming likely.
  • Savings Plans trade a one or three year commitment on dollars per hour for up to 72 per cent off, and they flex across family, size, operating system and region, including Fargate and Lambda.
  • What it costs: the trap is not the discount, it is which of these a construct is allowed to contain, and one interruption mode skips the two-minute warning entirely.

1. Four ways to buy one machine

2. The mechanism: what an interruption actually looks like

One interruption mode breaks the two-minute assumption outright. When the interruption behaviour is hibernation, hibernation begins immediately and the two-minute warning is skipped, even though the interruption notice event still fires. Any shutdown work you were relying on that window for does not happen.

3. What the discount forbids

Reclaimable capacity carries restrictions that are easy to discover late. Termination protection is unavailable on Spot instances, so the usual safeguard against accidental deletion is not there. The older fixed-duration Spot Blocks are retired, so a design that assumed a guaranteed uninterrupted block has nothing to fall back on. And Capacity Blocks for ML, which do reserve accelerated capacity for a fixed span booked up to eight weeks ahead, cannot be cancelled once booked, cover up to 64 instances per block, and deliberately do not count against on-demand quotas.

The reframing The right question is never "can we use Spot here?" It is "what does this workload do when a member vanishes with two minutes of warning, or none?" A workload with a good answer can take the discount everywhere. A workload without one should not take it anywhere, however tempting the rate.

4. The scheduler that makes it usable

AWS Batch is the piece that turns interruption tolerance into a working system. It takes job queues, array jobs and multi-node parallel jobs, and runs them on compute environments backed by EC2, Fargate or EKS. Spot-backed environments suit fault-tolerant jobs precisely because Batch owns the retry, and fair-share scheduling decides who gets the capacity when queues contend for it. A job definition pins the container image, the processor and memory request, and the role the job runs as.

Check yourself

Retrieval practice

Answer from memory before revealing.

Which signal should a Spot workload actually build its draining logic around?
The rebalance recommendation warns that interruption is becoming likely and is the only signal with slack in it. The metadata item and the EventBridge notice are two deliveries of the same two-minute warning, which is best-effort and is skipped entirely in hibernation. A health-check failure arrives after the instance has already stopped serving.
A team wants a discount that survives changing instance family next quarter. What fits?
Savings Plans commit dollars per hour rather than attributes, so they flex across family, size, operating system and region. Spot commits nothing but also promises nothing, which fails the implied requirement of predictable capacity. A Capacity Block reserves specific accelerated capacity and cannot be cancelled. A host reservation is tied to the host.
Which statement about a Capacity Block for accelerated compute is correct?
A booked Capacity Block cannot be cancelled, which is the commitment you are making in exchange for guaranteed accelerated capacity. It deliberately does not count against on-demand quotas, it does not convert into anything, and it is reserved capacity rather than reclaimable capacity, so no interruption notice applies.

Practice about 15 minutes, with paper

Practice 1working

An estate has three workloads. A customer-facing API runs a steady twenty instances all year. A nightly report job runs for four hours and can restart any piece it loses. A research team needs eight accelerated instances together for a three-day training run in a month's time.

Assign a purchase option to each, name the one property of the workload that decided it, and say for the reclaimable one what would have to be true of the code before you would sign off on it.

Hint

Three workloads, three different things you are able to give up: the right to keep the machine, the freedom to change your mind, or nothing at all. Match each to the workload that can afford it.

Show the worked solution
  1. The API takes a Savings Plan. The deciding property is that the load is steady and year-round, so a spend commitment is a bet you are certain to win. The plan commits dollars per hour rather than an instance shape, so a family change next year does not strand it.
  2. The report job takes Spot. The deciding property is stated in the requirement: it can restart any piece it loses. That is the only property that makes reclaimable capacity safe, and it is the property to ask about rather than the price.
  3. The training run takes a Capacity Block. The deciding property is that eight accelerated instances must be available together, at a known future time, for a fixed span. This is the one mechanism that reserves that shape, and it is bookable ahead - at the price of not being cancellable.
  4. Set the bar for the Spot workload. Before sign-off, the job has to act on the rebalance recommendation rather than on the two-minute notice, has to checkpoint often enough that losing a member costs less than restarting the job, and must not depend on any shutdown work happening, because a hibernation interruption skips the warning window.
  5. Check what the discounts do not cover. Termination protection is unavailable on Spot, so the usual accidental-deletion safeguard is absent, and the accelerated block does not draw on the on-demand quota, so the account's normal accelerated allowance is a separate conversation.

Sanity check. Each assignment should be justified by a property of the workload rather than by the size of the discount, and the reclaimable one should be the workload whose requirement already said it tolerates loss. If you put the customer-facing API on Spot because the discount was largest, you have chosen a rate and inherited an availability contract.
