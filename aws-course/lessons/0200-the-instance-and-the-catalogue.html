EC2 sells a catalogue of named types, and the name carries the whole contract

working 7 min Capability keys vm-instances, bare-metal and gpu-compute. · EC2 instance types

The one-minute version

  • On AWS you do not set processors and memory independently. You pick a named instance type out of a fixed catalogue, and the name encodes the family, the generation and the size.
  • The families are ratios written down: general purpose, compute optimised, memory optimised, storage optimised and accelerated. Choosing the family is choosing the ratio.
  • Nitro is the hypervisor underneath, and it is why the same catalogue contains a bare-metal type that runs your operating system on the physical server with full network integration.
  • Accelerated computing is where AWS's own silicon sits beside the GPUs: Trainium for training and Inferentia for inference, in the same catalogue.
  • What it costs: your capacity limit is not a number of instances. It is vCPUs per family, per account, per region, and for accelerated families a new account often has none.

1. The mental model: a catalogue, not a dial

Some clouds let you ask for six processors and ninety-six gigabytes and build that machine. AWS does not. It publishes a catalogue of types and you take the nearest one, which means the ratio between processors and memory is chosen for you within a family and only the size varies inside it.

The catalogue has one more member that people miss because they expect it to be a different product. Bare metal instances are types in the same list: your operating system runs directly on the physical server with no hypervisor, while the machine keeps full VPC networking. The price of that is time - a bare-metal launch verifies the hardware first and can take twenty minutes or more, which is a long wait for anything that expected an instance in seconds.

2. The mechanism: Nitro underneath everything

Nitro is the system EC2 runs on, and its design decision is to move networking and storage off the main processors and onto dedicated cards. That is what lets the platform offer a hypervisor-free type without giving up the network, and it is why the largest types reach network bandwidth of up to 400 Gbps (Nitro instances).

The reframing A type name is not a label on a machine, it is a bundle of decisions you are accepting at once: the processor-to-memory ratio, the network ceiling, whether local disk exists, whether accelerators are attached, and which quota pool the launch is charged against. Read a type name as a contract and the catalogue stops feeling arbitrary.

3. The limit that stops the first launch

  1. Start from the quota, not the instance count. Suppose the standard-family quota in this account and region is 64 vCPUs. That number is the whole allowance for every standard-family instance running at once.
  2. Divide by the size you chose. At 8 vCPUs per instance, 64 ÷ 8 = 8 instances. At 4 vCPUs per instance the same quota buys 16, and at 32 vCPUs it buys 2.
  3. Notice what a scaling group does to it. A fleet whose maximum size is 12 instances of 8 vCPUs needs 96 vCPUs, so the group will silently stop growing at 8 members. The group is not broken and nothing in its configuration says so.
  4. Check the accelerated families separately. They have their own quotas, and a new account frequently starts at zero for them, so the arithmetic above gives zero instances however small the type is.
A quota is not a billing limit and it is not a warning. It is a hard refusal at the API, and the most expensive version of that refusal happens at three in the morning when a scaling group tries to replace a failed instance and cannot. Raise quotas per region, before the fleet needs them, and remember that quotas for genuinely global services are requested in us-east-1.

Check yourself

Retrieval practice

Answer from memory before revealing.

A workload wants exactly 6 processors and 96 GB of memory, a ratio no listed type offers. What does EC2 let you do?
EC2 sells fixed named types, so an unusual ratio is met by taking the nearest one and paying for whichever resource you over-bought. Setting the two independently is what other clouds offer, not this one. Service Quotas raises limits and does not mint types. And memory is a property of the type rather than something attached to it.
Where do AWS Trainium and Inferentia sit in the catalogue?
Both are accelerated computing instance types, filed with the NVIDIA P and G families because they answer the same design question. They are not a separate product, they carry no special storage role, and compute optimised describes a processor-to-memory ratio rather than an accelerator.
A scaling group is configured with a maximum of 12 instances at 8 vCPUs each, and the family quota is 64 vCPUs. What happens?
64 divided by 8 is 8, so the ninth launch is refused while the group's own configuration still says 12. Creation is not validated against the quota, nothing raises a quota on your behalf, and the ceiling is a refusal rather than a charge. This silent stop is why the division is worth doing before the fleet is defined.

Practice about 15 minutes, with paper

Practice 1working

You are sizing three workloads in one new account and one region: an in-memory analytics job that needs a lot of memory per processor, a video transcoder that is processor-bound, and a model-training job that needs accelerators.

Name the family for each. Then say, for the account as a whole, how many separate quota conversations you expect to have and why the third workload is the one that will not start today.

Hint

Family follows the resource the workload is short of. Quota follows the family, not the account, so count the families rather than the workloads.

Show the worked solution
  1. Analytics job: memory optimised. The stated shortage is memory per processor, which is exactly the ratio that family encodes.
  2. Transcoder: compute optimised. Processor-bound means the memory that comes with a balanced type is wasted, so the compute-optimised ratio buys more of what is scarce for the same money.
  3. Training job: accelerated computing. This is where both the NVIDIA families and AWS's own Trainium chips sit, so the family is decided by the requirement and only the choice within it remains.
  4. Count the quota conversations. Three, not one, because vCPU quotas are held per family. Two of them are likely to be routine increases against a non-zero starting allowance.
  5. Name the blocker. The accelerated family is the one that commonly starts at zero vCPUs in a new account, so that launch is refused before capacity is even consulted. It needs a quota increase requested in this region before any sizing work matters.

Sanity check. Your answer should have three families and three quota conversations, and the blocked workload should be blocked for a quota reason rather than a capacity reason. If you concluded that the account has one shared allowance, re-read how EC2 counts: the unit is vCPUs within a family.
