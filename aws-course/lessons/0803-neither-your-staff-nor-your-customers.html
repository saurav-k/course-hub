IAM users are the wrong directory for your staff and for your customers

working 7 min Capability keys workforce-sso, managed-directory, os-login, ciam-user-directory, ciam-social-federation and ciam-mfa. · IAM Identity Center

The one-minute version

  • IAM Identity Center is not IAM. It is organisation-scoped workforce sign-in that lives outside account IAM and maps permission sets onto accounts.
  • It accepts exactly one identity source per organisation - a built-in directory, Active Directory, or an external SAML provider - and that is a decision made once.
  • Cognito is the customer-facing directory: user pools that issue JWTs, a hosted sign-in interface, social and enterprise federation, and passkeys usable as a first factor or as MFA.
  • For Windows authentication, LDAP and domain-joined workloads there is Directory Service, in managed, proxy and simple forms.
  • What it costs: the root user still exists in every account, and daily administration is meant to happen through Identity Center rather than through it.

1. The mental model: three audiences, three homes

2. The mechanism: one sign-in, many accounts

The root user is still there in every account, restricted to a small set of tasks with MFA enforced by default, and it is not the account you administer from. Central root-access management lets the organisation delete or reset member accounts' root credentials, which turns a scattered set of highly privileged logins into something the organisation actually controls (IAM identities).

3. Customers, and the tiers that decide what they get

A Cognito user pool is a directory for your application's own users: it issues JWTs, offers a hosted sign-in interface, and brokers sign-in with social providers and with SAML or OIDC enterprise providers. Its factors are TOTP, SMS and email one-time codes, plus WebAuthn passkeys that can serve as a first factor or as MFA, with up to twenty passkeys per user (authentication flows).

The tiers matter more than they look: passkeys are not available on the Lite tier, the Essentials tier is the default and adds passwordless sign-in and refresh-token rotation, and the Plus tier adds adaptive authentication and threat export (Cognito pricing). A requirement for passwordless sign-in is therefore a tier decision before it is a code decision.

Identity pools are the older half of Cognito: they exchange a token for AWS credentials so a mobile client can call AWS directly. They still work, and for machine flows the guidance is to prefer workload roles or STS federation from lessons 0801 and 0802 instead.

4. Reaching a machine, without a key on it

The reframing Ask "who is this person to the business" before asking which AWS service holds them. An employee is a directory entry your company already has; a customer is a row in your product. IAM users are neither, which is why an estate full of them has a joiners-and-leavers problem that no amount of policy tidying will fix.

Check yourself

Retrieval practice

Answer from memory before revealing.

An organisation using an external SAML provider in Identity Center acquires a company with a different provider. What follows?
Identity Center accepts exactly one identity source per organisation, so consolidating two providers is migration work rather than configuration. There is no parallel or fallback source, and the choice is organisation-wide rather than per account.
A product must offer passkey sign-in to its users. What decides whether that is possible?
Passkeys are unavailable on the Lite tier, so the tier is the gating decision. The hosted interface, identity pools and federated providers are all independent choices that do not enable or disable the factor.
What does EC2 Instance Connect leave on the instance after a session ends?
The one-time public key sits in instance metadata for sixty seconds and then is gone, which is what removes long-lived keys from hosts. The other three answers all describe some artefact persisting, which is exactly the situation the mechanism exists to avoid.

Practice about 15 minutes, with paper

Practice 1working

A company has 180 engineers, each with an IAM user in a shared account and access keys in their laptops. It also runs a consumer application with two million users, currently authenticated by a home-grown table of password hashes. Windows file servers are being moved into AWS and need domain joins. Engineers reach production hosts over SSH using a shared private key held in a password manager.

Assign each of the four populations a home, and name the one artefact that disappears in each case.

Hint

Work through the four populations in the order they appear and ask, for each, what long-lived thing exists today only because the population is in the wrong place.

Show the worked solution
  1. Engineers - IAM Identity Center. Sign-in moves to the organisation's single identity source, and permission sets grant access into each account. The artefact that disappears is the access key on 180 laptops, replaced by sessions that expire on their own.
  2. Consumer users - a Cognito user pool. The application receives JWTs instead of checking hashes, and social or enterprise federation becomes configuration rather than code. The artefact that disappears is the home-grown password table, which is also the thing most likely to be breached.
  3. Windows file servers - Directory Service. A managed Microsoft directory supports the domain join, or a connector proxies the existing on-premises directory if that one must stay authoritative. The artefact that disappears is a second, divergent copy of the user directory.
  4. SSH access - EC2 Instance Connect. A one-time key is pushed for sixty seconds under an IAM policy, and an Instance Connect Endpoint reaches hosts with no public address. The artefact that disappears is the shared private key in the password manager, along with the question of who still has a copy of it.
  5. Check what is left in IAM. Roles, and almost no users. That is the target state: every human population has a directory of its own, and IAM holds the principals that machines and federated sessions assume.

Sanity check. Each of your four answers should name a different service and a different long-lived artefact being removed. If any answer kept a credential and merely rotated it, look again - each of these four mechanisms removes the artefact rather than shortening its life.
