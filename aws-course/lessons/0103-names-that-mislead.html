Read the name, then read the status - on AWS neither one implies the other

foundation 7 min The naming traps and the lifecycle ladder that make old AWS knowledge unreliable. · Services in full shutdown

The one-minute version

  • The word serverless names three unrelated things on AWS, and none of them substitutes for another.
  • Some famous names no longer name a service at all. Glacier is a set of storage classes inside S3, not a product you buy.
  • Two names that sound like variants of one idea can be a cache and a database, or a sign-in system and an authorisation system. Similar names are not evidence of similar things.
  • A service has a lifecycle status as well as a name: generally available, closed to new customers, in maintenance, out of support, or shut down. They are five different states with five different consequences.
  • What it costs: every service fact has a shelf life. Cite the vendor page, and check the status before you design on the name.

1. One word, three services

2. Names that moved, and pairs that are not pairs

What you may believeWhat is actually true
Glacier is the archive service. Glacier is a set of storage classes inside S3. The standalone vault product is legacy and should not be taught as the current path.
ElastiCache and MemoryDB are two flavours of cache. MemoryDB is a durable primary database that happens to be in memory, not a cache you can lose.
IAM Identity Center is part of IAM. IAM Identity Center is organisation-scoped workforce sign-in that lives outside account IAM, with one identity source per organisation.
Kinesis Data Firehose is the delivery service. It is now Amazon Data Firehose. Older material and older diagrams still use the previous name.
SageMaker is one product. The classic product became SageMaker AI while a new next-generation platform took the plain SageMaker name. One word, two meanings.
Security Hub is one service. It split into Security Hub CSPM and a separate unified Security Hub, so which one a document means matters.
The reframing A name on AWS is a pointer, not a description. The reliable move is the same every time: take the name to the vendor's own page for it, read the first paragraph, and check what that page says the service is for. Two minutes there beats an hour of arguing from a name that changed.

3. Five statuses, not two

The consequence for design work is narrow and practical. A service that is closed to new customers cannot be the answer for a new workload even though it is visibly running elsewhere in your estate. A service in maintenance can still be the answer for a short-lived workload and is a poor answer for a platform. And a service that has shut down cannot be the answer for anything, however much material still recommends it.

Every retirement AWS announces names a successor, and the successor is usually not a drop-in. Moving off a discontinued service mesh means choosing between two different replacements with different capabilities. Read the successor's own page rather than assuming the shape carried over.

4. What this costs the reader

It costs a habit. Every technical claim in this course carries a link to the vendor page it was read from, and that is not decoration: it is the mechanism by which a page stays useful after a name moves. When a claim here and the vendor page disagree, the vendor page is right and this page is stale.

Check yourself

Retrieval practice

Answer from memory before revealing.

A requirement says the new service "must be serverless". What does that phrase actually settle on AWS?
The word covers a container capacity mode, an event-driven function service and a database capacity model, so alone it settles nothing. Assuming functions is the common error. A capacity decision remains in two of the three cases. And per-request billing describes only one of them.
Which pair is most often assumed to be two versions of one thing when it is not?
MemoryDB is a durable primary database rather than a second flavour of cache, so treating it as an ElastiCache variant leads to the wrong durability assumption. The other three pairs are genuinely a thing and a part of that thing, which is why they read as plausible.
A service you already run is announced as closed to new customers. What follows immediately?
Closed to new customers means existing accounts keep working while nobody new may start, so the practical consequence is on new designs rather than on running ones. Immediate breakage describes shutdown, which is a later rung. And the status is not advisory - it removes a real option from every future design.

Practice about 10 minutes, with paper

Practice 1foundation

You inherit a design document that says: "the archive tier uses Glacier, the sign-in is handled by IAM, the delivery pipeline uses Kinesis Data Firehose, and the compute is serverless so no capacity planning is needed."

Mark each clause as correct, renamed or wrong, say what the writer probably meant, and name the one clause that would produce a real design error rather than only an out-of-date word.

Hint

Three of the four are vocabulary problems that a reader can translate. One of them hides a decision that has not been made.

Show the worked solution
  1. "The archive tier uses Glacier." Renamed rather than wrong. Glacier is a set of storage classes inside S3, so the writer means an S3 bucket whose objects transition into an archive class. No design error, but the sentence hides the retrieval decision that comes with those classes.
  2. "Sign-in is handled by IAM." Probably wrong for workforce sign-in. Account IAM is where permissions are evaluated, while IAM Identity Center is the organisation-scoped workforce sign-in that sits outside it. The writer means one or the other and the document does not say which.
  3. "Uses Kinesis Data Firehose." Renamed only. The service is now Amazon Data Firehose and nothing about the design changes, though the name dates the document and hints that other claims in it are the same age.
  4. "The compute is serverless so no capacity planning is needed." This is the clause that produces a real error. If it means functions, there is a duration limit and a concurrency model to design. If it means a serverless container mode, there is still a task size. If it means serverless database capacity, there is still a cluster and a range to set. In all three readings the second half of the sentence is false.
  5. State the fix. Send the document back with one question rather than four corrections: which of the three serverless products does the compute clause mean? The renames can be corrected in place, but that one cannot be corrected without a decision.

Sanity check. Exactly one clause should survive your review as a genuine design gap, and it should be the one whose ambiguity changes what gets built. If you marked all four as equally serious, you are correcting vocabulary rather than reviewing a design.
