A subnet is public because of its route table and for no other reason

working 7 min Capability keys virtual-network, subnet, route-table, network-interface and ip-address-management. · Amazon VPC

The one-minute version

  • The elastic network interface is the atomic object. It carries the private addresses, the security groups and the MAC, and those follow it as it detaches and reattaches within its Availability Zone.
  • A VPC holds up to five IPv4 and five IPv6 CIDR blocks, each between /16 and /28, and the quota is adjustable.
  • A subnet lives in exactly one zone, may not overlap another in the same VPC, and gives up five reserved addresses - the first four and the last.
  • Public, private and isolated are not subnet settings. They are descriptions of what the subnet's route table points at.
  • What it costs: public IPv4 addresses are now billable, so an address plan is a cost decision as well as a design one, and IPAM is the service that tracks the plan across an organisation.

2. The mechanism: what an address plan costs

Above the individual VPC, IPAM plans and tracks address space in scopes, pools and allocations, integrates with AWS Organizations for a company-wide view, and is normally run from a delegated administrator account. Its operating Regions are declared when it is created, and the advanced tier is what unlocks bring-your-own-IP and audit history (What is IPAM).

3. The interface, and where it may go

The reframing Three of the four objects on this page are containers. Only the route table makes a decision, and every question of the form "why can this reach that" is answered by reading one route table and then one more. Draw the routes before drawing the boxes.
Public IPv4 addresses are billable, which changed the arithmetic of a common pattern: giving every instance a public address for convenience is now a recurring line rather than a free one (Amazon VPC). Private RFC 1918 addressing costs nothing, which is one more reason the default answer is a private subnet with a deliberate way out.

Check yourself

Retrieval practice

Answer from memory before revealing.

An instance in a subnet described as private is reachable from the internet. What is the first thing to read?
Public and private describe what the route table points at, so a route to an internet gateway is what makes the subnet public whatever anyone called it. Auto-assignment of a public address matters only once such a route exists, a host firewall cannot explain reachability from outside the VPC, and additional CIDR blocks change addressing rather than reachability.
How many usable addresses does a /28 subnet provide, and why?
Every subnet reserves five addresses - the first four and the last - so a sixteen-address block leaves eleven. The other three answers each apply a smaller reservation than AWS actually takes, which is the arithmetic that makes a tight subnet run out sooner than expected.
A detached secondary interface must be reattached to an instance in another Availability Zone. What happens?
An interface is created in a subnet, a subnet lives in one zone, and the interface cannot leave it. The other three answers all assume some reconfiguration would make the move work, but nothing about groups or routes changes the zone the interface's subnet is in.

Practice about 15 minutes, with paper

Practice 1working

A team is planning a VPC for a three-tier application across three Availability Zones. They propose a /24 for the VPC, split into nine /28 subnets - a web, application and database subnet per zone - reasoning that each tier runs at most six instances per zone.

Say whether the plan works, show the address arithmetic, and name at least three consumers of addresses the plan has not counted.

Hint

Do the reserved-address subtraction per subnet first. Then list everything other than an instance that will need an address in these subnets - the answer is longer than most first drafts.

Show the worked solution
  1. Check the split itself. A /24 holds sixteen /28 blocks, so nine of them fit with seven left over. The subdivision is legal and a /28 is the smallest subnet AWS allows, so nothing is wrong yet.
  2. Subtract the toll. Each /28 has sixteen addresses and reserves five, leaving eleven. Six instances leaves five spare per subnet, which sounds adequate and is the point at which most plans stop.
  3. Count what else lands there. A load balancer places an interface in each of its subnets, per zone. A NAT gateway takes one. Every interface endpoint takes one per zone. A managed database instance takes one, and so does its standby. A rolling deployment briefly runs replacement instances alongside the old ones, which is another address each.
  4. Redo the arithmetic honestly. On the web tier, six instances plus a load-balancer interface plus even two extra during a rolling update is nine of eleven. Any interface endpoint added later fails to place, and it fails at the moment somebody is trying to make a service private rather than at design time.
  5. State the fix and its cost. Size subnets for the platform's interfaces and for a deployment in flight, not for the steady-state instance count - a /26 per subnet in a /22 VPC costs nothing but private address space. If the /24 is fixed, remember a VPC can carry up to five IPv4 CIDR blocks, so a second block is available rather than a redesign.

Sanity check. Your per-subnet usable figure should be eleven, and your list of uncounted consumers should include at least one thing the team never creates by hand. If the plan looked fine after step two, that is exactly the failure mode this problem is about.
