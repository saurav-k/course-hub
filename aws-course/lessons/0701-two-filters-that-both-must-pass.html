Module 07 · Networking and delivery · Lesson 0701

Every packet passes two filters, and only one of them can say no

working 6 min Capability key stateful-packet-filter. · Security groups

The one-minute version

  • A security group attaches to a network interface, is stateful, and holds allow rules only. There is no deny rule to write.
  • A network ACL sits at the subnet edge, is stateless, evaluates in rule-number order, and does have deny rules.
  • Because the ACL is stateless, a reply is a new packet to it, so an inbound-only rule set silently breaks return traffic unless ephemeral ports are opened.
  • A security group rule can name another security group as its source, which is how a tiered design stops hard-coding addresses that change.
  • What it costs: neither filter emits a per-rule verdict log. Only VPC Flow Logs record accept and reject, so "which rule dropped it" is a question you answer by reasoning rather than by reading.

1. The mechanism: one request, two filters, four crossings

There is no per-rule verdict log on either filter. When a packet disappears, the only first-party record is a VPC Flow Log entry saying ACCEPT or REJECT for the flow - not which rule decided it. The managed firewall layer of module 11 does emit alert and flow logs of its own, which is one of the real reasons estates add it.

2. The pattern that makes security groups worth the constraint

The network ACL earns its place where a security group cannot help: it is the only one of the two that can deny, and it applies to the whole subnet at once regardless of which interfaces are in it. That makes it the right instrument for a blanket exclusion - a range you never want to hear from - and a poor instrument for expressing what an application is allowed to do.

The reframing These are not two layers of the same thing with different strengths. They answer different questions: the security group answers "what may this workload talk to", and the network ACL answers "what may cross this subnet's edge at all". Write application intent in groups, write blanket exclusions in ACLs, and stop trying to express one in the other.

Check yourself

Retrieval practice

Answer from memory before revealing.

Requests reach an instance and clients then time out waiting. Which cause fits best?
A stateless ACL judges the reply on its outbound rules, so an inbound-only rule set delivers requests and drops answers, which reads as a timeout. A missing inbound group rule would stop the request arriving at all, a missing route would stop it earlier still, and security groups have no deny rule to write.
Why does referencing a security group as a rule source beat listing addresses?
Scaling groups replace instances and their addresses, so a rule written against membership keeps meaning what it meant. Rules are not ordered by kind in a security group, zone changes are not what breaks address rules, and an address rule can name any CIDR rather than one subnet.
A single address range must be blocked for everything in a subnet. Which instrument fits?
Denying is exactly what a network ACL is for, and it covers the whole subnet at once. Security groups carry no deny rule at all, a route change affects reachability rather than permission and is easily undone by a more specific route, and group references express what is allowed rather than what is blocked.

Practice about 15 minutes, with paper

Practice 1working

An application tier in a private subnet must accept traffic on port 8080 from the web tier only, reach a PostgreSQL database on 5432, and download packages from the internet through a NAT gateway. Security asks for one hostile address range to be blocked estate-wide. The team is about to write everything as security-group rules with explicit address ranges.

Write the rule set across both filters, saying which rule goes where and why, and name the rule the team's plan would have got wrong.

Hint

Sort the four requirements into "what this workload may talk to" and "what may cross this subnet at all". Then check each direction of each requirement, remembering which filter forgets the request by the time the reply arrives.

Show the worked solution
  1. Inbound to the application tier - a security group rule. Allow 8080 with the web tier's security group as the source. No address appears, so the rule survives every replacement of a web instance.
  2. Outbound to the database - a security group rule on each side. Allow 5432 outbound from the application group, and inbound on the database group with the application group as the source. Both halves are needed because the two interfaces have separate groups, and neither needs a return rule because groups are stateful.
  3. Package downloads - a security group outbound rule plus a route. Allow 443 outbound to the internet. The reply comes back automatically. What actually makes this work is the subnet's route to the NAT gateway, which is a lesson 0700 concern rather than a filter one.
  4. The estate-wide block - a network ACL deny rule. It is the only filter of the two with a deny, and applying it at the subnet edge covers every interface including ones nobody has created yet. Put it at a low rule number so it is evaluated before any broader allow.
  5. Name the mistake. The blocked range. The team planned to express it in security groups, which have no deny rule, so the closest they could get is narrowing every allow rule to exclude that range - many rules, each of which someone can widen later. And if they add any ACL rules at all, they must remember the outbound ephemeral-port rule, or the package downloads in step three will hang rather than fail.

Sanity check. Your answer should contain exactly one network ACL rule and several security group rules, and no address literals except the hostile range itself. If you wrote a deny rule in a security group, that language does not exist.
