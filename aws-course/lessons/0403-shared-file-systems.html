Shared file storage is two answers on AWS, and one of them is four products

working 6 min Capability key file-storage. · Amazon EFS

The one-minute version

  • Block storage attaches to one machine and object storage is reached by key. A shared file system is the third shape: many machines reading and writing one directory tree.
  • EFS is the AWS-built answer: elastic NFS with no capacity to provision, and lifecycle tiering that moves cold files into cheaper classes.
  • FSx is not one product. It is a family of four managed third-party engines, and choosing between them is choosing a file system, not a tier.
  • The engines are picked by protocol and workload: Windows sharing with directory integration, enterprise NAS features, an open-source general engine, and a parallel engine for high-performance computing.
  • What it costs: the highest-throughput engine is the only one of the four that is single-zone, and its availability commitment is visibly lower than the rest.

1. The mental model: your own engine, or somebody else's

The parallel engine has one property the others do not: it links to an S3 bucket, so a computation can read a data set out of object storage at file-system speed and write results back. That link is usually the reason it is chosen, ahead of the raw throughput figure.

2. The mechanism: EFS moves cold files on its own

The reframing Object storage tiers on a rule you wrote about time; this file system tiers on what the workload actually read. That difference is why one of them needs you to know the access pattern in advance and the other does not, and it is a fair way to decide which fits a data set nobody has measured.

3. What it costs: the asymmetry inside the family

The four engines are not equally available, and the gap is the opposite way round from what people assume. Three of them are multi-zone deployments with a 99.99 per cent availability commitment. The parallel high-performance engine is single-zone, with a 99.5 per cent commitment.

That means the fastest file system in the family is the one whose data does not survive the loss of its zone. It is the correct choice for a scratch working set that is reloaded from a bucket, and the wrong choice for anything that is the only copy. Because the engine is chosen for throughput, this is the trade most often made without being noticed.

Check yourself

Retrieval practice

Answer from memory before revealing.

A requirement says Windows clients must access the share over SMB with directory-based permissions. What does that select?
The requirement names a protocol and a directory integration, and one engine in the family is built for exactly that. EFS is an NFS service, so neither of its options answers an SMB requirement. The parallel engine is for high-performance computing and speaks a different protocol entirely.
Which FSx engine is single-zone, and what follows from that?
The parallel engine is the single-zone one, with a visibly lower availability commitment than the other three, which are multi-zone. That makes it right for a reloadable working set and wrong for a sole copy. The other three engines are the multi-zone ones, which is what makes each distractor sound reasonable.
What drives an EFS file into a colder storage class?
Tiering here is driven by time since the file was last read, configurable from as little as a day, and a read brings the file back. Age since creation is how object-storage lifecycle rules work, which is exactly the habit to unlearn. No quota triggers it and no application call is needed.

Practice about 15 minutes, with paper

Practice 1working

A genomics group runs analysis jobs across two hundred instances. Every job reads a reference data set of several terabytes that already lives in an S3 bucket, writes intermediate files that all the instances share, and produces a final result that must be kept for seven years. A separate finance team on the same account needs a Windows share for a legacy reporting tool.

Choose the storage for each of the four jobs in that paragraph, name the property that decided each, and state the one recovery assumption your design depends on.

Hint

There are four distinct jobs hidden here, and only two of them are shared file systems. For the fast one, ask what happens if its zone goes away and whether that matters.

Show the worked solution
  1. Reference data set: leave it in the bucket, linked to the parallel engine. The deciding property is that it already lives in object storage and is read at high throughput by many machines. The high-performance engine links to an S3 bucket, so the data does not have to be copied into a second permanent home.
  2. Shared intermediate files: the same parallel file system. The deciding property is many concurrent writers over a shared tree at high throughput, which is what the engine is for.
  3. Final results for seven years: a general-purpose bucket, tiered. The deciding property is a long retention with rare reads. Lesson 0400's class ladder and lesson 0404's archive classes are the right home, not a file system that is billed to be fast.
  4. Windows share: FSx for Windows File Server. The deciding property is the protocol and the directory integration, which the requirement names outright. It is a multi-zone engine with the higher availability commitment.
  5. State the recovery assumption. The parallel file system is single-zone, so the design assumes that losing its zone costs a rebuild rather than a loss. That is true only because the reference data is still in the bucket and the intermediates are reproducible. Write that assumption down, because it stops being true the moment somebody keeps a unique result there.

Sanity check. Two of your four answers should be file systems and two should not, and the single-zone choice should be justified by reproducibility rather than by speed. If the seven-year results ended up on a file system, ask what you are paying per byte for data nobody reads.
