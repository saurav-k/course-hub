A gateway, two orchestrators, and three capabilities with no product of their own

working 11 min Capability area integration-messaging, rows api-gateway, workflow-orchestration, managed-integration and realtime-messaging. · Azure API Management

The one-minute version

  • API Management is a policy engine in front of an interface: throttling, token validation and caching applied per call, with versions, revisions and a developer portal around it.
  • Its self-hosted gateway is a container that extends the same control plane to a hybrid edge, so an on-premises interface is governed by the same policies.
  • Orchestration comes in two shapes: Logic Apps with a large connector library, and Durable Functions for code-first orchestration.
  • App Configuration is where settings and feature flags live, with Key Vault references for the parts that are secrets - which is the boundary lesson 0804 asked for.
  • Three capabilities have no product of their own: a general-purpose GraphQL service, a standalone scheduler, and a managed application-authorisation service.

A policy engine in front of an interface

The reframing Token validation at the gateway is not a substitute for authorisation in the service. The gateway can verify that a caller presents a valid token, which removes a large class of unauthenticated traffic before it reaches a backend. What the caller is then allowed to do is the backend's decision - and, as lesson 0801 established, Azure has no managed application-authorisation service to delegate it to.

Two ways to orchestrate

Two products offer this. Logic Apps is the visual form with a large connector library, so reaching a third-party system is configuration rather than a client library, and its hosting choice is a networking decision as much as a pricing one - the single-tenant option is what brings virtual network integration, exactly as the tier did for the broker in lesson 1203. Durable Functions is the code-first form, and it is where the four patterns above are named.

Settings live in App Configuration, which holds configuration and feature flags with labels for environments and snapshots for a consistent set, and it takes Key Vault references for the values that are genuinely secrets. That is the division lesson 0804 argued for from the other side: the vault holds secrets, and configuration that is not secret belongs somewhere that does not price and permission every read as a secret read.

Two smaller services complete the integration surface. SignalR Service and Web PubSub are managed websocket publish-subscribe for pushing updates to browsers and devices, with a serverless mode that ties into function triggers. And the routing primitive from lesson 1000 is itself an integration service - a diagnostic setting's event hub destination is how platform telemetry reaches a third-party security system.

Three capabilities with no product

The absences are recorded absences, not guesses. The research behind this course distinguishes a capability delivered inside another service from one the platform genuinely lacks, and all three above are the first kind - the capability is available and the product is not. Writing "Azure cannot schedule jobs" in a design document would be wrong in a way that is expensive to discover later, and the same discipline applies to every gap this course has named.

Check yourself

Retrieval practice

Answer from memory before revealing.

What is the difference between a revision and a version of an interface?
Staging a change against offering a caller a deliberate choice is the distinction, and conflating them produces either breaking changes or version sprawl. The first inverts the two. The third and fourth invent scope and ownership differences.
A design needs a job to run every night. What should it name?
There is no standalone scheduler, and three ordinary services each provide the capability. The first names a product that does not exist. The second and third are workarounds that add machinery for a capability already available.
Where should non-secret application settings live?
Configuration belongs in the configuration service, with references for the secret parts. The second is the pattern lesson 0804 warned against, since it makes every configuration read a secret read. The third and fourth put settings in components that consume them rather than store them.

Practice about 15 minutes, with paper

Practice 1working

A company exposes three interfaces: one public, one to partners, and one running on a server in its own data centre that partners also need. Requirements: rate limits per partner; a single place partners can read documentation; the same policies on all three including the on-premises one; a nightly reconciliation job; and a process that pauses for a human approval before continuing. A proposal puts a gateway in front of the two cloud interfaces, writes a scheduler service request ticket, and builds the approval step as a polling loop.

Fix it: say how the third interface is covered, name the two mechanisms the proposal is missing, and say what to do about the ticket.

Hint

Take the on-premises interface first - the gateway has a component for exactly that. Then look at the two things the proposal is building by hand and ask whether either is a solved problem.

Show the worked solution
  1. Cover the on-premises interface. The self-hosted gateway is a container deployed beside that interface, reporting to the same control plane. The same policies apply, so the partner-facing rate limits and token validation are identical across all three rather than reimplemented locally.
  2. Meet the rate-limit and documentation requirements. Both are gateway features: throttling policies per caller, and the developer portal as the single place partners read documentation and obtain access.
  3. Deal with the ticket. There is no scheduler service to request. The nightly job is a timer-triggered function, a workflow recurrence, or an automation schedule - a design decision to make rather than a product to wait for.
  4. Replace the polling loop. Waiting for a human is one of the named durable orchestration patterns. A code-first orchestration suspends and resumes, so the approval step stops being a loop that costs money while it waits and starts being a state the orchestration is in.
  5. Name the second missing mechanism. If the approval work is better expressed as connectors than as code, the visual workflow product does the same job - and the hosting choice there decides whether it can reach anything inside a virtual network.
  6. Add the configuration boundary. Partner rate limits and endpoint settings belong in the configuration service with labels per environment; only the credentials among them belong in the vault, reached by reference.

Sanity check. Your answer should remove two things the proposal was going to build or wait for, and add nothing that is not already a documented feature. If the scheduler ticket survived, the recorded-absence discipline from this page has not been applied.
