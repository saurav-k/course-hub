An alert is only as good as the stream beneath it, and some questions have no stream

working 12 min Capability area observability, rows alerting, service-health-dashboard and network-diagnostics, with network-flow-log and dns-query-log. · Azure Monitor alerts

The one-minute version

  • Alerts come in four families - metric, log search, control-plane, and health - and all of them route through action groups.
  • The common alert schema standardises the payload, which is what makes one ticketing or webhook integration serve every alert type.
  • Service Health and Resource Health answer different questions: one is the platform event, the other is this resource's own state.
  • Virtual network flow logs carry the allow-or-deny outcome and which rule decided it - but not traffic at a private endpoint, and not several platform families.
  • Some questions have no stream at all. There is no per-query log for public DNS zones and no per-translation record for outbound address translation, so visibility has to be designed onto the path.

Four alert families, one routing layer

The reframing Service Health and Resource Health are not two views of one thing. Service Health is a subscription-scoped feed of platform events - issues, planned maintenance and advisories - and it names which of your resources are affected. Resource Health reports one resource's own state. So "is it me or is it Azure" is answered by looking at both, and the unauthenticated public status page is a third, coarser view that knows nothing about your resources.

Investigating a network path, in order

Flow records are the other half. Virtual network flow logs collect layer-four tuples at network scope every minute into append-only blobs, recording which security rule allowed or denied a flow, the flow state, byte and packet counts, and encryption status. There is a monthly free allowance per subscription and per-gigabyte charging beyond it. Traffic Analytics layers geography, security and topology enrichment on top, priced per gigabyte processed with no free tier - and it aggregates identical flows, so it trades raw tuple fidelity for a smaller, more readable dataset.

The blind spots, named

Two figures in this area are honestly unknown to this course. The aggregation interval used by traffic analytics, and the delay between a Prometheus scrape and the data being queryable, are not stated on the pages the research behind this course read. They are recorded as open items rather than guessed, and a design that depends on either should measure it rather than take a number from a course page.

Check yourself

Retrieval practice

Answer from memory before revealing.

An estate must be able to answer which name a workload resolved. What does the design need?
There is no per-query log for public zones, so something that logs has to be on the path. The first asks for a capability that does not exist. The third is close but assumes a resolver is already there - putting it there is the design decision. The fourth attributes name resolution to a layer-four flow record.
What is the difference between Service Health and Resource Health?
Platform events against a single resource's own state is the split. The first and second invent scope and pricing distinctions. The third splits incidents from maintenance, which both appear in the same platform feed.
Traffic analytics shows no record of a flow that definitely happened. What is a documented reason?
Traffic at a private endpoint produces no record there - the documented advice is to capture at the source. The first is false: the records carry the allow-or-deny outcome. The second confuses a free allowance with a hard stop. The fourth misreads the collection interval as a minimum flow duration.

Practice about 20 minutes, with paper

Practice 1working

A security review asks an estate to prove four things after the fact: that a workload only ever reached approved external names; that no unapproved source reached a database behind a private endpoint; that a particular firewall rule denied a specific connection; and that an outage last month was Azure's rather than the application's. The estate has flow logs and traffic analytics enabled, and nothing else beyond the defaults.

Answer the review: for each of the four, say whether the evidence exists, what would produce it, and which one requires a change to the architecture rather than to a setting.

Hint

For each question, name the stream that would carry the answer before asking whether it is enabled. Two of the four have no direct stream, and only one of those is fixed by putting something new on a path.

Show the worked solution
  1. Approved external names. This is name resolution, and public zones have no per-query log. Flow records carry addresses rather than names, so they cannot answer it either. Nothing existing produces this evidence.
  2. Fix it - and note what kind of fix it is. A firewall DNS proxy or the private resolver has to sit on the resolution path, and logging happens there. That is an architecture change: traffic must be made to traverse something that can see the query.
  3. Sources reaching the private endpoint. Traffic at a private endpoint is not recorded at the endpoint, so the flow logs the estate already has will show nothing there and that absence proves nothing.
  4. Fix it. Capture at the source interfaces, where flow records do exist. This is a configuration change rather than an architecture one, because the sources are already inside networks that can produce records.
  5. The firewall rule denial. This one is answerable. Security groups produce no per-rule verdict log, but the flow record carries the allow-or-deny outcome and which rule decided it, and the managed firewall has its own rule logs. The evidence exists in what is already enabled.
  6. Whose outage it was. Answerable, and from a stream nobody had to configure: the platform health feed records issues affecting your subscription and names the resources involved, while the per-resource feed reports the resource's own state. Both should also be wired to an action group so the next one is noticed rather than reconstructed.
  7. Note one caveat on the analytics. Traffic analytics aggregates identical flows, so a question needing individual tuple fidelity should be answered from the raw records rather than from the enriched view.

Sanity check. Exactly two of the four should be answerable today, and exactly one should require putting something new on a path. If the private-endpoint question looked answerable from existing flow logs, re-read where those records are not collected.
