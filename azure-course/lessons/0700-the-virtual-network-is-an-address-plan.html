A virtual network is an address plan, and the plan is regional

working 11 min Capability area networking-core, rows virtual-network, subnet and ip-address-management. · Azure Virtual Network

The one-minute version

  • A virtual network is a regional resource holding a private address space. Reaching across regions needs peering or a Virtual WAN hub, never the network itself.
  • The address space can be IPv4, IPv6 or both, and there is no transitive routing by default - a fact the whole hub design in lesson 0702 exists to work around.
  • Subnets are where things attach: network interfaces, gateways and private endpoints. Service endpoints and private endpoints are configured per subnet.
  • Azure reserves five addresses in every subnet - the first four and the last - so a small subnet loses a large fraction of itself before anything is deployed.
  • Subnet delegation hands a whole subnet to one platform service, and Virtual Network Manager address management is where a whole estate's ranges are planned so they do not collide.

One region, one address space, several attachment points

The five addresses you never get to use

The reframing The reserved five are the first four addresses and the last one of every subnet. That makes the overhead constant and the waste proportional: it is negligible in a /24 and dominant in a /29. Combined with the fact that a subnet cannot be grown without moving what is attached to it, the practical rule is to size a subnet for what it will hold rather than for what it holds today.

Planning ranges across a whole estate

A virtual network has no transitive routing by default. Two networks peered to a third do not reach each other because of it, and every hub design in lesson 0702 is a way of supplying the transit that the platform declines to assume. Reading peering as "these networks are joined" rather than as "these two networks are joined" is the most expensive misreading in this module.

Retrieval practice

Answer from memory before revealing.

How many addresses can be deployed into in a subnet with 16 total addresses?
Five addresses are reserved in every subnet, so sixteen minus five is eleven. The first option applies a two-address convention from elsewhere. The third puts the reservation at the wrong object. The fourth invents a sixth reservation on top of the five.
A design needs a workload in one region to reach a workload in another. What does the virtual network itself provide?
The network is a regional resource, so cross-region reach comes from peering or a Virtual WAN hub. The first two options try to stretch one network across regions, which it does not do. The third assumes transitive routing, which is off by default.
What does subnet delegation do?
Delegation assigns the subnet to a dedicated platform service. The first option describes the five-address reservation, which happens in every subnet regardless. The second invents cross-network attachment. The fourth confuses delegation with the per-subnet configuration of private endpoints.

Practice about 20 minutes, with paper

Practice 1working

A team is given a single /24 for a new application network and proposes to carve it into eight /27 subnets: web, application, data, private endpoints, a delegated subnet for a platform service, management, a spare, and one held back "in case". The web tier is expected to run twelve machines at peak, and the private-endpoint subnet is expected to hold about twenty endpoints within a year.

Check the plan: work out the usable capacity of each /27, say which of the two named requirements is at risk, and state the general rule you would give the team.

Hint

Do the subtraction before the division. Then compare the usable figure with the requirement, remembering that a private endpoint consumes an address exactly as a machine does.

Show the worked solution
  1. Count the addresses in a /27. A /27 leaves five host bits, so it holds 25 = 32 addresses in total.
  2. Subtract the reservation. Azure reserves the first four and the last, which is five addresses, so 32 - 5 = 27 usable per subnet.
  3. Check the /24 divides. A /24 holds 256 addresses, and eight /27 subnets consume 8 × 32 = 256. The carve-up fits exactly, with nothing left over for a subnet to be grown into later.
  4. Test the web tier. Twelve machines against 27 usable addresses is comfortable, so this requirement is not the problem.
  5. Test the private-endpoint subnet. Twenty endpoints against 27 usable addresses leaves seven spare. Each private endpoint takes an address in the subnet exactly as a machine does, so this subnet is at about three-quarters of capacity on day one of the year it was sized for. It is the requirement at risk.
  6. State the rule. Size for growth rather than for the current count, and leave unallocated space inside the parent range so a subnet can be replaced by a larger one. Here the plan has used every address in the /24, so there is no room to enlarge the private-endpoint subnet without redoing the whole carve-up - and everything attached would have to move.

Sanity check. Your usable figure should be 27 rather than 30 or 32. If you got 30, you applied the two-address convention from ordinary subnetting rather than Azure's five, and every subnet in your plan is three addresses smaller than you think.
