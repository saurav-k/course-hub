Two vault resources, and the features that make a backup hard to delete

working 11 min Capability area resilience-migration, row backup-service. · Azure Backup

The one-minute version

  • Backup uses two different vault resources. Recovery Services vaults cover most workloads; Backup vaults cover blobs and Kubernetes.
  • Coverage is broad: machines, file shares, database engines including SAP workloads, blobs and clusters, each with its own backup behaviour.
  • Blob protection has two tiers: an operational tier that keeps recovery close to the data, and a vaulted tier that keeps a copy in the vault.
  • The ransomware answer is immutable vaults plus soft delete - together they make a backup something an attacker cannot simply delete.
  • Cross-region restore is available on geo-redundant vaults, which is what turns a backup into a regional-failure answer rather than only a deletion answer.

Two vaults, and which one you get

The reframing Blob protection has two tiers that answer two different failures. The operational tier keeps recovery close to the data, which suits accidental deletion and overwriting and recovers quickly. The vaulted tier keeps a copy in the vault itself, which is what survives the storage account being compromised or removed. They are complementary rather than alternative, and a design choosing only the first has protected against mistakes and not against an attacker.

What makes a backup survive an attacker

The redundancy of the vault itself decides what else it can do. A geo-redundant vault supports cross-region restore, so the copy is recoverable in another region when the primary one is unavailable. Without it, a backup answers deletion and corruption and does not answer a regional failure - which is the next lesson's subject.

Backup is not a substitute for the archive tier from lesson 0401, and the archive tier is not a substitute for backup. A backup is a managed copy with a retention policy, a restore path and protection against deletion; an archived blob is the same data on cheaper storage with a rehydration wait. A retention requirement met by moving data to archive has cheaper storage and no recovery guarantee at all.

Check yourself

Retrieval practice

Answer from memory before revealing.

An estate protects virtual machines, file shares, blobs and a Kubernetes cluster. How many vault types are involved?
Recovery Services vaults cover most workloads and Backup vaults cover blobs and Kubernetes, so two types appear. The first misses the split. The second and third invent a granularity the resource model does not have.
Why do immutability and soft delete answer different halves of the ransomware problem?
One buys a recovery window and the other refuses the deletion outright. The first inverts what each protects. The third invents a workload split. The fourth invents a timing split that does not exist.
A backup design must survive the loss of a region. What does the vault need?
Cross-region restore is a property of a geo-redundant vault. The first builds by hand what the vault provides. The second protects against deletion rather than regional loss. The fourth is about where a blob copy sits, not about which region can restore it.

Practice about 15 minutes, with paper

Practice 1working

A company's protection plan says: virtual machines and a database engine are backed up nightly to one vault; blob data is "protected" by a lifecycle rule moving it to archive after ninety days; and the plan notes that the backup administrator account is held by two people. An auditor asks what happens if an attacker obtains that account, and what happens if the region hosting the vault is unavailable.

Answer both questions: identify the three defects in the plan, and say what you would change for each.

Hint

Take the blob line first and ask what archive actually provides. Then read the two auditor questions as two different failures and check which mechanism answers each.

Show the worked solution
  1. Read the blob line honestly. Moving data to archive is a storage-tier change, not protection. It gives cheaper storage and a rehydration wait, and it provides no retention policy, no restore path and no protection against deletion. The blob data is currently unprotected.
  2. Fix the blob line. Blob backup lives in a Backup vault rather than the vault holding the machines, with the operational tier for quick recovery from mistakes and the vaulted tier for a copy that survives the account itself. That also means a second vault type in the design.
  3. Answer the compromised-account question. As written, an attacker with the backup administrator account can delete the recovery points, so the backups do not survive the scenario. Enable soft delete so a deletion is a delay with a recovery window, and immutability so deletion is refused outright.
  4. Note who that changes things for. Immutability constrains the legitimate administrators as well, which is the point. It is the same shape as the deny settings in lesson 1201: a protection worth having is one its own owners cannot casually undo.
  5. Answer the regional question. A single vault in one region answers deletion and corruption and not regional loss. A geo-redundant vault supports cross-region restore, which is what makes the backup usable when the primary region is unavailable.
  6. Name what is still missing. Backup answers data loss; it does not bring a service back quickly. Whether the recovery time is acceptable is the next lesson's question, and the plan should say which of the two it is relying on for each workload.

Sanity check. Your corrected plan should contain two vault types, two protection features that constrain administrators, and one redundancy setting. If the archive rule survived as protection, the difference between a storage tier and a backup has been collapsed.
