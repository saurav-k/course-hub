Azure analytics is two surfaces, and almost every capability appears on both

working 10 min Capability area analytics, rows data-warehouse and data-lake. · Microsoft Fabric Warehouse

The one-minute version

  • Analytics on Azure is not one catalogue. It is an Azure resource surface and a Microsoft Fabric surface, and the same capability usually exists on both.
  • Synapse dedicated SQL pools are the previous flagship warehouse. They remain generally available, and the new work lands in Fabric.
  • The pattern repeats: pipelines, Spark, streaming and graph each have an Azure-resource answer and a Fabric answer.
  • The two surfaces store differently too. Data Lake Storage Gen2 is a storage account with the hierarchical namespace turned on; OneLake is Fabric's own lake, and it is where Delta tables get managed maintenance.
  • This module needs a state the lifecycle picture in lesson 0103 does not have: generally available and superseded - supported, undated, and no longer where features arrive.

Two columns, one catalogue

The reframing Microsoft Fabric is not a product that competes with a service in the list above. It is a second surface with its own capacity model, its own lake and its own versions of the analytics capabilities. Choosing it is choosing where the whole estate lives, which is why the decision belongs at the top of an analytics design rather than inside any one service choice.

The state the lifecycle picture was missing

Two lakes underneath

The hierarchical namespace is enabled per storage account at creation, exactly as lesson 0400 said. A team that discovers a lake requirement after the account exists is looking at a new account and a copy, and no amount of Fabric or Synapse tooling on top changes that. The lake decision is therefore older than the analytics decision, and it is usually made by somebody who was not in the analytics conversation.

Check yourself

Retrieval practice

Answer from memory before revealing.

What does "Synapse dedicated SQL pools are generally available" tell you about a greenfield design?
Generally available says supported; it does not say current. The first option is the misreading this page exists to prevent. The second describes end of sale, which is a different state and has not been announced here. The fourth confuses the state with preview, which is at the other end of the lifecycle.
A design names Azure Data Factory, Azure Databricks and Azure Stream Analytics. What has it implicitly decided?
All three named services sit in the left column, so the surface has been chosen without being discussed. The second option inverts the choice. The third invents a prerequisite. The fourth is wrong because Delta tables live on both surfaces - the format is not what the fork decides.
Which statement about Data Lake Storage Gen2 is correct?
It is the storage account from module 04 with the hierarchical namespace enabled, and that switch is thrown at creation. The first option invents a separate service. The third confuses it with OneLake. The fourth describes a serverless query engine, which is the subject of the next lesson.

Practice about 15 minutes, with paper

Practice 1working

A team is asked to review an analytics proposal for a new product. The proposal names Synapse dedicated SQL pools for the warehouse, Azure Data Factory for ingestion, Azure Databricks for transformation, and Power BI for reporting. It justifies each choice by writing "generally available and supported" beside it, and it notes that the source data already sits in a storage account created last year for application uploads.

Review it: say what the four service choices have in common, what the justification does not establish, and which sentence in the proposal is the largest hidden constraint.

Hint

Sort the four named services into the two columns before judging any of them. Then read the last sentence about the existing storage account against what lesson 0400 said is decided at creation.

Show the worked solution
  1. Sort the services. Three of the four sit in the Azure resource column. The proposal has therefore chosen a surface, and it has done so without saying it chose anything.
  2. Test the justification. "Generally available and supported" is true of every one of them and distinguishes none of them from its counterpart on the Fabric surface. It establishes that the design will work, not that it is the current answer, and those are the two different claims this page separates.
  3. Ask what the review is actually for. A reviewer cannot approve a column choice that was never presented as a choice, so the first correction is to make the fork explicit and have it decided deliberately.
  4. Find the hidden constraint. The storage account was created last year for application uploads, which means the hierarchical namespace was almost certainly left off - it is enabled at creation and an upload store has no reason to want it. So the lake the proposal assumes may not exist yet.
  5. State the consequence. Turning that account into a lake is a new account and a data copy, not a setting. That is a schedule and cost item nobody has budgeted, and it is independent of which analytics column wins.

Sanity check. Your review should raise exactly two structural points - an undeclared surface choice and a storage account that may not be a lake - and neither should be a criticism of any individual service. If your review argues that one of the four named products is bad, re-read the state diagram: none of them is.
