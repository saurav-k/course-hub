A pipeline is three objects, and only one of them decides what you can reach

working 10 min Capability area analytics, row etl-service, with the recorded absence change-data-capture beside it. · Azure Data Factory

The one-minute version

  • Azure Data Factory is serverless orchestrated extract-transform-load with more than ninety connectors, and it is built from three objects: pipelines, triggers and integration runtimes.
  • The integration runtime is the compute that actually moves the bytes, and it is what decides whether a source behind your own firewall is reachable at all.
  • The self-hosted integration runtime is the one you install inside your own network. It is the answer to on-premises data, and it is an operational commitment rather than a setting.
  • Mapping data flows express transformation without code, and existing SSIS packages have a lift-and-shift path rather than a rewrite.
  • Azure ships no standalone change-data-capture product. The capability is delivered inside the migration service, inside Data Factory, and inside Fabric.

Three objects, and what each one is for

The reframing A self-hosted integration runtime is software you run. It is installed inside your own network, and from then on it needs patching, monitoring, capacity and somebody to be responsible for it. That makes it the one part of a serverless ingestion service that is not serverless, and the part whose ownership has to be agreed before the pipeline is designed rather than after.

How a cloud pipeline reads a database it cannot see

Transformation, and the packages you already have

Mapping data flows are how a pipeline transforms data without anybody writing Spark code, which matters because it keeps a transformation inside the same object model as the movement around it. Separately, an estate that already runs SQL Server Integration Services packages has a lift-and-shift path rather than a rewrite: an SSIS integration runtime executes the existing packages. Both matter for the same reason - they let an ingestion migration be a movement of work rather than a re-authoring of it.

The capability with no product

Data Factory sits in the generally available and superseded position from lesson 0600: it is fully supported and widely deployed, while Fabric Pipelines is where greenfield estates on the Fabric surface are pointed. A design that names Data Factory has therefore made the surface choice from the previous lesson, whether or not anyone said so.

Check yourself

Retrieval practice

Answer from memory before revealing.

Which of the three pipeline objects decides whether an on-premises source can be read at all?
Reach is a property of where the compute runs, and that is the integration runtime. The first option describes what is read rather than what can be. The second invents a relationship between scheduling and connectivity. The fourth names the breadth of source types supported, which says nothing about whether a particular host can be reached.
What is the honest description of a self-hosted integration runtime?
It is software with an owner, a patch cycle and a capacity story - the part of a serverless service that is not serverless. The second and fourth options describe managed networking constructs, which is precisely what it is not. The third reduces an installed component to a rule.
A design needs to keep a lake copy current as a source database changes. What should it name?
There is no standalone product, so the design names the host service. The first option looks for a service that does not exist. The second is a workaround that changes the cost and the load without delivering the capability. The third confuses the compute that moves data with the feature that tracks changes.

Practice about 15 minutes, with paper

Practice 1working

A manufacturer wants nightly loads from three sources into its lake: an on-premises SQL Server holding production records, a software-as-a-service application with a public API, and an existing set of SSIS packages that already produce a cleaned extract on a server in the factory. The team wants "no new servers to look after" and a plan they can hand to operations.

Design it: say how many integration runtimes appear, which requirement cannot be met as written, and what you would hand to operations.

Hint

Work source by source and ask, for each one, where the compute has to sit for the read to be possible. Then check the answer against the sentence about new servers.

Show the worked solution
  1. Take the software-as-a-service source first. It has a public API, so an Azure-hosted integration runtime can reach it and nothing has to be installed anywhere. One runtime, no operational burden.
  2. Take the on-premises SQL Server. It sits inside the factory network, so the compute that reads it has to sit there too. That is a self-hosted integration runtime, and it is software with an owner.
  3. Take the SSIS packages. These have a lift-and-shift path rather than a rewrite, so the existing packages keep running. They already read local production data, which puts their execution on the same side of the network boundary as the SQL Server above.
  4. Count what has to sit inside the factory. Two of the three sources are behind the network boundary and one is not. So the design needs Azure-hosted compute for the public API and installed compute inside the factory for the other two, and the architecture diagram that shows only pipelines and triggers has hidden the entire operational half of it.
  5. Test the "no new servers" requirement. It fails. The on-premises source cannot be read by cloud-hosted compute, so a self-hosted runtime is required, and it is a thing to patch, monitor and size. The requirement can only be met by moving the source, which is a different project.
  6. Say what operations receives. Not a pipeline diagram, but an ownership list: who patches the self-hosted runtime, what monitors it, what happens to the nightly load when it is down, and which credentials it holds. Everything else in this design is managed by the platform.

Sanity check. Exactly one of the three sources should have needed nothing installed, and your handover should be about the installed components rather than about the pipelines. If your answer to operations is a schedule, re-read step 5 - the schedule is the part they do not have to own.
