Host tenancy is a billing decision before it is a security one, and confidential compute cuts across it

working 10 min Capability area compute-iaas, rows dedicated-hosts, bare-metal, confidential-compute and spot-capacity. · Azure Dedicated Host

The one-minute version

  • Three rungs of tenancy: a shared host, a dedicated host reserved to your subscription, and bare metal. They are not three grades of the same product.
  • A dedicated host bills per host, not per machine, so the case for it is a density calculation you do on paper first.
  • Confidential computing is a separate axis: it is a property of the size, encrypting memory against the hypervisor itself, and it is available on shared hosts.
  • Bare metal on Azure is not a general-purpose rental. It is a certified path aimed at SAP workloads, ordered through SAP quota.
  • Spot capacity is the discount for accepting eviction, and the eviction policy - deallocate or delete - is the setting that decides whether the machine can come back.

Two independent questions, not one ladder

The confidential sizes name their hardware in the size family. DCasv5 and ECasv5 use AMD SEV-SNP, DCesv5 uses Intel TDX, and the accelerator line extends the same idea to NVIDIA H100 trusted execution environments. As with every size question, the vendor page is the live authority for which families exist in which regions.

The dedicated host arithmetic

Two further properties of a dedicated host matter to a design rather than to a spreadsheet. It gives you host-level maintenance control, which is why it appears in workloads that cannot absorb maintenance at an arbitrary time. And a host group spans availability zones, so dedicated capacity and zonal spread are compatible rather than opposed.

Bare metal on Azure is the rung that most often gets designed in by analogy and then cannot be bought. Baremetal Infrastructure is single-tenant hardware certified mainly for SAP HANA, ordered through SAP quota rather than launched from the catalogue, and Microsoft manages it including the operating-system patching windows. It is a certified appliance path, not a machine you rent for anything you like.

Capacity you agree to give back

The packaging Azure does not sell

One shape that other platforms sell is genuinely absent here, and naming it is more useful than pretending otherwise. There is no bundled fixed-price virtual private server on Azure: no product that packages compute, storage and transfer into a single predictable monthly figure. A hand-sized B-series machine is the nearest thing, and it bills per component like everything else. That is an absence of packaging rather than of capability - Azure will happily rent you a small machine - but a plan that budgets for a flat monthly figure has to be rewritten as a per-component estimate.

Retrieval practice

Answer from memory before revealing.

A workload needs its memory protected from the hypervisor. Which choice delivers that?
Confidential computing is selected as a size property and encrypts memory against hypervisor-level access, with attestation to prove what is running. Reserving a host changes your neighbours, not the platform's access. Bare metal is a certified SAP path rather than a general answer. The fourth option confuses discarding memory with protecting it.
Why is a dedicated host holding two machines usually a poor trade?
The host price is fixed, so the per-machine share falls as one divided by the count and most of the saving arrives in the first few machines. The first option is false - host groups do span zones. The second invents a threshold. The third contradicts the point that the two axes are independent.
A Spot machine is evicted and the team wants to start it again later with its disks intact. Which setting made that possible?
Deallocate keeps the machine so it can be started again, and it is the default. The first option describes the price ceiling, which affects when eviction happens rather than what survives it. The second is unrelated placement. The fourth reverses what Delete does.

Practice about 20 minutes, with paper

Practice 1frontier

A regulated team asks for six machines on dedicated hosts, with confidential computing, spread across two availability zones, and wants the batch tier of the same application to run on Spot capacity to save money. Each dedicated host in the size they want can hold twelve of their machines.

Assess the request: say how much of the host price each machine carries under their plan, what the zone requirement does to that number, and whether the Spot tier is a sound idea beside a regulated tier.

Hint

Two zones means two host groups worth of hardware, not one. Work out the packing per host before you work out the price share, and treat the Spot question as a question about what absorbs an eviction.

Show the worked solution
  1. Pack the machines without the zone requirement. Six machines on a host that holds twelve is half a host, so each machine carries 1 ÷ 6 = about 17 per cent of the host price and the other half of the host is paid for and empty.
  2. Apply the zone requirement. A host is one physical server, so two zones need at least two hosts. Three machines per host means each machine now carries 1 ÷ 3 = about 33 per cent of a host price, and three quarters of the purchased capacity is idle.
  3. Check whether dedicated hosts were needed at all. The stated driver was confidential computing, which is a size property available without dedicated hardware. If the regulation asks for memory encryption and attestation, confidential sizes on shared hosts answer it and the host bill disappears. If it genuinely asks for single tenancy, the arithmetic above is the price of that.
  4. Judge the Spot tier. Spot has no service level agreement and capacity can be unavailable in some sizes and regions. It is sound for the batch tier only if that tier is a fleet that tolerates losing members - a scale set or a Kubernetes node pool, with the eviction policy on Deallocate - and unsound if any single Spot machine is a required component.

Sanity check. The zone requirement should make the per-machine share go up, never down, because splitting a fixed cost across fewer machines per host is the same arithmetic running backwards. If your second number is smaller than your first, the two hosts were counted as one.
