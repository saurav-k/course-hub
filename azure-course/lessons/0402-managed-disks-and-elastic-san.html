Module 04 · Storage · Lesson 0402

Two disk types let you buy performance without buying capacity, and one product shares a performance budget across machines

working 9 min Capability area storage, row block-storage. · Azure managed disk types

The one-minute version

  • A managed disk is a resource of its own with its own lifetime, and the type ladder runs Standard HDD, Standard SSD, Premium SSD v1, Premium SSD v2, Ultra Disk.
  • Premium SSD v2 and Ultra are the two that let input-output operations and throughput be tuned independently, and that can be resized per disk without detaching from the machine.
  • Availability is not uniform across the ladder: not all sizes and regions offer every type, so a design pins a type and then checks it where it will run.
  • A shared disk is the option that lets more than one machine attach the same volume, which is what clustered software expects.
  • Elastic SAN is the different shape: a provisioned capacity pool serving iSCSI volumes, so one performance budget is shared across many machines rather than bought per disk.

The ladder, and the property that changes near the top

Surviving a zone, at the disk level

One volume, or one budget

The reframing Per-disk provisioning and pooled provisioning make opposite bets. Per-disk means every volume must be sized for its own peak, so the estate pays for many peaks that never coincide. Pooled means the peaks share one budget - cheaper when demand is uncorrelated, and a shared failure of headroom when it is not. Which bet is right is a question about your workloads' correlation, not about which product is newer.

Check yourself

Retrieval practice

Answer from memory before revealing.

A workload needs a small volume with very high input-output performance. Which disk types make that combination straightforward?
Premium SSD v2 and Ultra let operations and throughput be set independently of the volume, which is exactly the small-and-fast case. The second names two types without that property. The third confuses a clustering feature with a performance one. The fourth is a different product rather than a property of the disk types.
What does a shared disk enable that an ordinary managed disk does not?
Shared disks exist for clustered scenarios where several machines attach one volume. The first and fourth describe Premium SSD v2 and Ultra properties. The second describes the zone-redundant disk option. All three are real capabilities attached to the wrong feature, which is how this question is usually got wrong.
When is Elastic SAN's pooled model a worse fit than per-disk provisioning?
Pooling wins when demand is uncorrelated and loses when everything peaks at once, because the budget is shared. The first three inventions each sound like a plausible product constraint and none of them is the trade the pooled model actually makes.

Practice about 15 minutes, with paper

Practice 1working

A migration is bringing four workloads off an on-premises storage area network: a two-node clustered database that expects a shared volume, a reporting server whose volume is large and rarely busy, a transaction log volume that is small and extremely latency-sensitive, and twelve general-purpose application servers whose disks were all carved from the same array. The whole estate must survive the loss of one availability zone.

Assign a block-storage answer to each, and say what the zone requirement adds on top.

Hint

Three of the four map onto a different feature from this page. For the fourth, ask whether their demand peaks together - the answer is in the phrase "carved from the same array".

Show the worked solution
  1. The clustered database. A shared disk, because the requirement is literally more than one machine attaching one volume, and that is the feature that exists for clustered software.
  2. The reporting server. Large and rarely busy is the case where capacity dominates and performance does not, so a standard type is the honest choice - buying Premium for a volume that idles is buying a peak nobody uses.
  3. The transaction log. Small and latency-sensitive is the combination that per-size performance makes awkward, so Premium SSD v2 or Ultra, where operations and throughput are tuned independently of the volume. Confirm the type is offered for the machine size and region before committing.
  4. The twelve application servers. They already shared one array's budget on premises, which is evidence their peaks do not coincide. Elastic SAN reproduces that model: one provisioned pool, twelve volumes drawn from it. If their peaks do turn out to be correlated, the pool becomes a shared shortage and per-disk provisioning is the safer bet.
  5. Add the zone requirement. Choose zone-redundant disk options wherever the workload must survive a zone, because a zone-redundant machine sitting on a zonal disk is still stopped by that zone. Check the requirement against each of the four separately - it is a property of the disk, not of the estate.

Sanity check. Only one of the four should end up on the fastest types. If three of them did, the peaks were assumed rather than examined - and the reporting server in particular has no latency requirement to justify it.
