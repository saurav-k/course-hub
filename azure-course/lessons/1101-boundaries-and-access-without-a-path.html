Three controls that do not depend on a network route

working 11 min Capability area security-services, rows service-perimeter, zero-trust-app-access, bastion and packet-mirroring. · Network Security Perimeter

The one-minute version

  • A network security perimeter is a logical boundary around platform resources that blocks public network access by default, with explicit inbound and outbound rules for what may cross.
  • Its coverage is the catch: it applies only to onboarded resource types, and several of those are still preview, so support has to be checked service by service.
  • It does not replace private endpoints. Private Link remains the answer for traffic from a virtual network to a platform service.
  • Entra Private Access reaches internal applications with no virtual private network: connectors sit beside the application and dial out, so no inbound port is opened, and Conditional Access decides each session.
  • Azure Bastion gives an operator a session to a machine that has no public address at all, and its higher tiers add session recording and private-only deployment.

A boundary around services rather than a network

The reframing Private Link and the perimeter answer opposite halves of the same requirement. "No public access to this service" is the perimeter. "My workload can still reach it privately" is the private endpoint and its DNS zone from lesson 0703. A design that names only the first has closed the door without cutting a new one, and a design that names only the second has cut a new door and left the old one open.

Reaching an internal application without a tunnel

It is one half of Global Secure Access, whose other half covers access to the internet rather than to internal applications. The pairing matters mostly because a design that adopts one usually inherits the client and the operating model of the other.

A session to a machine with no address

Virtual network traffic mirroring is in preview, in selected regions, and the corpus notes that the service has been re-scoped more than once. A mirroring configuration is added to the monitored interface and the destination is an address in the same or a peered network, with collectors coming from appliance partners. It is genuinely useful and it is not something to build a compliance commitment on until its current stage has been confirmed - lesson 0103's lifecycle applies, including the possibility of withdrawal from preview.

Check yourself

Retrieval practice

Answer from memory before revealing.

What does a network security perimeter do by default to the resources inside it?
Blocking public access by default is the perimeter's defining behaviour. The first describes the managed firewall from the previous lesson. The second describes Private Link, which the perimeter does not replace. The fourth applies a virtual-network construct to platform resources that do not sit in one.
Why does the private-access connector avoid opening an inbound port?
The connector establishes the connection outward, so nothing has to be reachable from outside. The second still involves an inbound listener. The third names a different mechanism. The fourth misplaces the connector, which sits beside the application.
A control statement says "all platform data services deny public access via the perimeter". What must be verified?
Coverage is per resource type and several types are still preview, so the statement is only true for the types actually supported. The first is not a prerequisite. The third confuses a complementary control with a dependency. The fourth invents a regional deployment requirement.

Practice about 15 minutes, with paper

Practice 1working

An organisation wants to retire its remote-access virtual private network. Three requirements follow: staff must reach a set of internal web applications from anywhere with the same conditions applied as to cloud applications; operators must reach Linux machines that have no public addresses; and an auditor wants a recording of privileged sessions. Separately, a data team wants a commitment that a group of platform data services will refuse all public access. A proposal answers everything with private endpoints.

Take it apart: name the right mechanism for each requirement, and say what has to be checked before the last commitment can be made.

Hint

Ask for each requirement whether somebody needs to reach in, or whether something needs to be closed off. Private endpoints answer only one of those, and only for one kind of traffic.

Show the worked solution
  1. Test the proposal against the first requirement. A private endpoint gives a workload inside a virtual network a private address for a platform service. It does nothing for a member of staff on a laptop reaching an internal web application, so the proposal does not address this at all.
  2. Answer the first requirement. Entra Private Access, with connectors beside the applications dialling out and Conditional Access evaluating each session. That is what gives internal applications the same conditions as cloud ones, which is precisely what the requirement asked for.
  3. Answer the second requirement. Bastion. The machines keep no public address and the operator gets a session, and pairing it with directory sign-in removes the local accounts and stored keys as well.
  4. Answer the third requirement. Session recording is a capability of the higher Bastion tier, and session audit records land in the service's own diagnostics. So the tier choice is driven by the audit requirement rather than by scale.
  5. Answer the data commitment. Denying public access to a group of platform services is the perimeter, and the private endpoints in the proposal are the complementary half - they open the private path once the public one is closed.
  6. Name what has to be checked. The perimeter applies to onboarded resource types, and several are still preview. So before the commitment is written down, confirm service by service that each data service in scope is supported, and state plainly which ones are not covered rather than implying they are.

Sanity check. Your answer should use three different products for the three access requirements, and the private endpoints from the proposal should survive only as half of the fourth. If private endpoints answered the staff requirement, re-read who is doing the reaching.
