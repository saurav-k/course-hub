Module 06 · Analytics · Lesson 0604

Four audiences read analytics output, and each has its own front door

working 11 min Capability area analytics, rows bi-dashboards, managed-search, data-catalog and clean-rooms. · Azure AI Search

The one-minute version

  • People read through Power BI, and its central architecture choice is DirectQuery against Import - query the source live, or hold a copy.
  • Applications read through Azure AI Search, which offers lexical, vector and hybrid retrieval with semantic ranking, and can build the index itself through integrated vectorization.
  • Other organisations read through Azure Confidential Clean Rooms, where several parties analyse combined data without exposing raw rows to each other or to the operator. It is in preview.
  • The estate's own stewards read through Microsoft Purview Unified Catalog: the data map, scanning, classification, lineage and glossary.
  • Two of the four carry a capacity model rather than a per-resource one, so the front door decides how the analytics estate is licensed as well as how it is read.

Four audiences, four doors

The choice that shapes a reporting estate

The reframing Power BI is licensed on Fabric capacity units or on per-user licensing, which means the reporting front door is priced in the same currency as the Fabric surface from lesson 0600. A team that chose the Azure resource column for its engines and Power BI for its readers has one foot in each capacity model, and that is a legitimate design - but it should be a decision rather than a discovery on the first invoice.

How an application-facing index is built

This is the same service module 13 returns to as vector storage for model-backed applications. Meeting it here first is deliberate: it is an analytics front door before it is an artificial-intelligence component, and designs that treat it only as the latter tend to rebuild an indexing pipeline it already has.

Azure Confidential Clean Rooms is in preview. Its multiparty analytics runs confidential-compute Apache Spark SQL, and its trust story comes from confidential computing attestation rather than from a contract, which is exactly what makes it interesting. It is also why a design should confirm the current availability stage before committing to it - lesson 0103's lifecycle picture includes services withdrawn from preview without ever becoming generally available.

Check yourself

Retrieval practice

Answer from memory before revealing.

A dashboard is set to DirectQuery and the warehouse behind it is struggling at peak. What is the mechanism?
DirectQuery sends the interaction through to the source, so readers and load are the same quantity. The first and second options describe Import, which is the other side of this fork. The fourth invents a contention between two services that do not share a meter here.
What does integrated vectorization remove from an application team's work?
The chunking and embedding steps happen inside the service, which is the work removed. The second and third remain decisions the team makes. The fourth describes what the index does rather than work anybody was doing.
Which requirement points at the catalogue rather than at a reporting or retrieval tool?
Provenance and classification are what the data map, lineage and glossary exist for. The first is a reporting requirement, the second a retrieval one, and the third is the clean-room case - each of the four options is one of the four doors, and only the fourth is the catalogue.

Practice about 15 minutes, with paper

Practice 1working

An insurer has built a lake and a warehouse. Four requirements arrive in the same week: claims handlers want an operational dashboard refreshed through the day; the customer-facing assistant must find relevant passages in policy documents; a reinsurance partner wants to run joint analysis over both companies' claims data without either seeing the other's records; and a compliance officer wants to state, for any field in a report, where it came from and whether it is personal data.

Route them: name the door each requirement goes through, say which one is not a production commitment yet, and name the one cross-cutting decision the first requirement forces.

Hint

Name the audience before naming the service for each of the four. Then, for the dashboard alone, ask what happens to the warehouse when a hundred handlers use it at once.

Show the worked solution
  1. Route the dashboard. The audience is people, so the door is Power BI. Nothing about this requirement is unusual except its readership, which the last step returns to.
  2. Route the assistant. The audience is an application, so the door is Azure AI Search. Retrieval over documents with hybrid results and semantic ranking is what it is for, and integrated vectorization means the team does not build a chunking and embedding pipeline of its own.
  3. Route the reinsurance analysis. The audience is another organisation, so the door is Confidential Clean Rooms, whose whole purpose is joint analysis without exposing raw rows to the other party or to the operator.
  4. Route the compliance question. The audience is a steward of the estate, so the door is Purview Unified Catalog - the data map for what exists, classification for whether it is personal, and lineage for where the field came from.
  5. Identify what is not yet a commitment. Clean Rooms is in preview. The requirement can be explored there, and the design should confirm the availability stage before anything contractual depends on it.
  6. Name the cross-cutting decision. The dashboard forces the DirectQuery-or-Import choice, and with a large body of handlers refreshing through the day, DirectQuery turns every interaction into load on the warehouse. That is a capacity conversation about the engine, not a preference about freshness.

Sanity check. All four requirements should route to four different services, and only one of them should have raised a load question. If two requirements landed on the same door, re-read the audience of each - the four doors were chosen precisely because these four audiences keep arriving together.
