Module 11 · Security services · Lesson 1102

Posture is free, protection is a purchase, and one console shows both

working 11 min Capability area security-services, rows posture-management, vulnerability-scanning and data-classification. · Microsoft Defender for Cloud

The one-minute version

  • Foundational posture management is free: a secure score and recommendations mapped to the Microsoft cloud security benchmark, across the estate.
  • The paid posture plan adds agentless vulnerability scanning, data-aware posture, a security explorer for querying the estate, governance rules, and attack-path analysis.
  • Workload protection is separate again. Detections for servers, storage, databases, key vaults, the control plane, containers, application interfaces and model services each need their plan enabled.
  • Classification changes severity. Sensitive-data discovery feeds the posture risk views, so an attack path that ends in sensitive data is ranked above one that does not.
  • The same console covers other clouds through connectors, so the posture story is not confined to Azure resources.

Three products, one console

The reframing Attack-path analysis is the feature that makes a list of findings into a priority order. A hundred recommendations with no relationship between them cannot be worked through rationally. A path - this internet-facing machine, with this vulnerability, holding this identity, which can reach this data - is a single item that justifies fixing four things in a particular order. It sits on the paid posture plan, and it is the main reason to buy it.

Where a finding comes from, and where it goes

Classification, and why it changes the ranking

Two boundaries are easy to blur. Recommendations and alerts come from different products: the free foundational layer never produces a detection, and enabling a workload plan does not by itself improve a secure score. And the regulatory compliance dashboard from lesson 0901 is a view over policy evaluations, not a third assessment engine - so a compliance gap there is fixed by fixing the policy compliance, in module 09, rather than inside this console.

Retrieval practice

Answer from memory before revealing.

An estate has enabled nothing beyond the defaults. What does the security console give it?
Foundational posture is free and produces recommendations; detections need plans. The first inverts which half is free. The second and third both name paid-plan features - agentless scanning is a plan feature despite needing no agent.
Why does data classification change how a security backlog is worked?
Classification feeds severity, so two technically identical findings can be ranked differently by what they expose. The second deletes findings rather than ranking them. The third crosses the recommendation and alert boundary. The fourth describes a guardrail, which is module 09's mechanism.
A compliance dashboard shows a failing control. Where is it fixed?
Compliance reporting is a view over policy evaluations, so the fix is policy compliance. The first hides rather than fixes. The third names a product that produces alerts rather than compliance results. The fourth confuses the score with the compliance view.

Practice about 15 minutes, with paper

Practice 1working

A board asks for four assurances: that the organisation knows which of its resources are misconfigured; that it would be told if a server were being attacked; that it can say which stores hold personal data; and that its security team is working the most important problems first. The organisation has the security console visible in the portal and has purchased nothing.

Answer the board: say which assurances hold today, which need a purchase, and what the fourth one requires beyond a purchase.

Hint

Sort the four into recommendations, alerts, classification and prioritisation. Only one of those four is free.

Show the worked solution
  1. Knowing what is misconfigured. This is foundational posture, which is free and already on. Recommendations mapped to the cloud security benchmark and a secure score exist today, so this assurance holds.
  2. Being told a server is under attack. This is a detection, which comes from a workload protection plan for servers. Nothing is purchased, so this assurance does not hold at all - and the visible console makes it easy to believe otherwise.
  3. Knowing which stores hold personal data. This is data-aware posture, which rides the paid posture plan or the storage protection plan. It needs a purchase, and it also needs time for discovery to run across the estate.
  4. Working the most important problems first. This is attack-path analysis, on the paid posture plan - and it is worth more once classification is in place, because severity depends on what a path reaches.
  5. Name what the fourth needs beyond a purchase. An owner and a process. Governance rules assign a recommendation to somebody with a deadline; without that, prioritisation produces a better-ordered list that nobody works through.
  6. Add the export. Whatever is purchased, arrange continuous export of alerts and findings into the workspace model from module 10, so that correlation and retention are not limited to what the console keeps.

Sanity check. Exactly one of the four assurances should hold today, and your answer to the fourth should name something that is not a product. If all four came back as purchases, the free foundational layer has been undersold.
