What a template does to the resources it does not mention

working 11 min Capability area iac-deployment and governance-policy, rows native-iac-template and deployment-stacks. · Deployment stacks

The one-minute version

  • A deployment runs in one of two modes. Incremental is the default and leaves unmentioned resources alone. Complete deletes them, and it is the most destructive default anybody can change by accident.
  • Complete mode is being wound down, with deletions pointed at deployment stacks instead.
  • What-if previews the changes a deployment would make before it makes them, which is the rehearsal step this course keeps arguing for.
  • Template specs publish an approved template as a resource, so a team consumes a version rather than a copied file.
  • A deployment stack makes a deployment an object: it knows which resources it manages, it can delete them together, and its deny settings block even an Owner.

Two modes, and one of them deletes

Seeing it before it happens

The reframing A template spec is a template published as a resource. That changes how it is consumed: a team references an approved, versioned spec rather than copying a file into their own repository, so an improvement reaches consumers and a copy does not silently rot. It is one of the two paths the vendor names for estates leaving the retired blueprint product behind, and it is the one for reusable content rather than for lifecycle.

The stack, and what it can refuse

Stacks work at resource group, subscription and management group scope, so the same mechanism protects a single environment or a whole platform layer. Lesson 0801 described the deny assignment's own properties - it can be set not to apply to child scopes, it can exclude named principals, and it can be expressed against everyone in the directory - and those are the dials that make a protected stack usable rather than merely rigid.

The blueprint product is retired, having never left preview, and the vendor names two successors: deployment stacks for lifecycle and protection, and template specs for reusable approved content. An estate still holding blueprints is on a migration path with a published end, and this course deliberately links the vendor's retirement material rather than restating its dates.

Retrieval practice

Answer from memory before revealing.

A template containing one storage account is deployed to a resource group in complete mode. What happens?
Complete mode makes the scope match the template, so anything not mentioned is removed. The first describes incremental mode. The second invents a safety refusal. The third borrows the detach behaviour, which belongs to a stack rather than to a mode.
Why does the preview belong in front of the approval gate?
The diff is the effect on this scope, including deletions, which a template alone does not show. The first invents a prerequisite. The third invents locking. The fourth invents a restriction on where gates can go.
What is unusual about a deployment stack's deny settings?
Deny assignments short-circuit the authorisation waterfall, which is why an Owner is stopped. The second confuses them with policy effects. The third overstates the protection. The fourth contradicts lesson 0801 - role assignments only ever add.

Practice about 15 minutes, with paper

Practice 1working

A platform team must deliver three things. Temporary test environments should be creatable and removable cleanly, leaving nothing behind. A shared networking layer must survive an administrator deleting it by mistake, including a subscription Owner. And a set of approved templates should be reusable across eight application teams without each team copying files. The team currently deploys with a pipeline that applies templates in complete mode to keep environments tidy.

Design it: name the mechanism for each requirement, and say what you would change about the current pipeline.

Hint

Two of the three requirements are about a deployment's lifetime and one is about distribution. Then ask what complete mode is being used for, and whether something else does that job with less risk.

Show the worked solution
  1. Temporary environments. A deployment stack. It records the resources it manages, and deleting the stack removes them together - which is exactly "leave nothing behind" without anybody maintaining a teardown script.
  2. Protect the networking layer. A deployment stack again, this time with deny settings. Those materialise as platform deny assignments, and they are the only mechanism that stops an Owner. Choose the scope deliberately: stacks work at resource group, subscription and management group level.
  3. Tune the protection so it stays usable. The deny assignment can exclude named principals and can be set not to apply to child scopes, so the platform team's own automation can still operate while everybody else is blocked.
  4. Distribute the approved templates. Template specs. Each team references an approved, versioned spec rather than copying a file, so an improvement reaches all eight and no copy silently diverges.
  5. Change the pipeline's mode. Complete mode is being used to keep environments tidy, which is precisely the job stacks now do explicitly - and complete mode does it by deleting anything the template omits, on every apply. Move to incremental and let the stack handle removal.
  6. Add the preview. Put what-if in front of the approval gate so a reviewer sees creates, modifications and deletions for the real scope. That is worth doing regardless of mode, and it is what would have caught a complete-mode accident before it happened.

Sanity check. Two of your three answers should be the same mechanism configured differently, and the pipeline change should remove a deletion behaviour rather than add one. If complete mode survived, the tidiness it provides is now being provided twice.
