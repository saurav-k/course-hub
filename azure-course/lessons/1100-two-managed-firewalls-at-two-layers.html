Two managed firewalls, two layers, and neither replaces the packet filter

working 12 min Capability area security-services, rows waf and cloud-firewall. · Azure Firewall

The one-minute version

  • The web application firewall is a rule engine attached to something else: regionally to Application Gateway, globally to Front Door. It is not a resource you place on its own.
  • It runs in detection or prevention mode, and the honest rollout is detection first - exactly the ramp lesson 0901 argued for policy.
  • Azure Firewall is a stateful managed firewall with address translation, fully qualified domain name filtering, and, on its premium tier, TLS inspection and intrusion detection signatures.
  • It deploys standalone in a hub network or as a secured Virtual WAN hub, which is the routing-intent pattern from lesson 0702.
  • Neither replaces the network security group from lesson 0701. The three sit at different layers and answer different questions.

Three layers, three questions

Tuning the application layer without breaking the site

The reframing The application firewall is not a resource you deploy on its own. It attaches to a delivery product, and which one decides its scope: on Front Door it inspects at the global edge before traffic ever reaches a region, and on Application Gateway it inspects inside the region. That makes the choice from lesson 0704 - global product, regional product, or both - also a decision about where inspection happens.

What the premium tier adds, and what it costs you

The standard capabilities are worth naming separately: destination address translation for inbound publishing, source address translation for outbound, and filtering by fully qualified domain name, which is the feature that makes a firewall rule expressible in the vocabulary an application team actually uses.

Two logging quirks belong to this page. Firewall metrics require the older diagnostics-mode export even when the logs themselves use the resource-specific tables, so a design that moves entirely to the modern tables silently loses the metrics. And address-translation rules log only on a match, so a connection that failed because no rule matched leaves no rule log at all - the absence is the finding, and the flow records from lesson 1004 are where the rest of the evidence lives.

The structured log tables are worth knowing by shape rather than by name: separate tables for application rules, network rules, translation rules, threat intelligence hits, intrusion signatures and proxied name resolution. Lesson 1002's plan choice applies to them directly, and the cheaper plan is documented as removing a large share of their cost. Expect up to thirty minutes before logs begin flowing after they are enabled - longer than the ninety-minute worst case in lesson 1000 might suggest for a small setting, and long enough that people conclude the configuration failed.

Check yourself

Retrieval practice

Answer from memory before revealing.

Where does a web application firewall get deployed?
It is a rule engine attached to a delivery product, and which product decides whether inspection is global or regional. The first describes the managed firewall. The third describes security admin rules. The fourth merges two separate products.
Why do TLS inspection and intrusion detection appear on the same tier?
Encrypted traffic is opaque to signature matching, so the two capabilities are technically joined. The first, second and third invent dependencies on deployment shape, billing and logging that are not the reason.
A connection fails and no address-translation rule log appears. What does that mean?
Translation rules log only when they match, so a miss leaves nothing and the absence is itself the finding. The first assumes denials are recorded there. The second inverts the behaviour. The fourth borrows a mode from the application firewall, which the managed firewall does not have.

Practice about 20 minutes, with paper

Practice 1working

A retailer serves customers globally through a front door with regional gateways behind it, and its workloads make outbound calls to a handful of partner services. Security asks for four things: block common web attacks against the storefront; rate-limit a scraping problem coming from one region; ensure workloads can only reach the approved partner destinations; and detect known attack signatures in outbound traffic. The team proposes one managed firewall in the hub and nothing else.

Design it: place each requirement at a layer, say what the proposal cannot do, and name what the fourth requirement costs beyond a tier upgrade.

Hint

Sort the four requirements by which of the three questions they ask. Two are about the request itself and two are about where traffic goes and what is inside it.

Show the worked solution
  1. Place the web-attack requirement. This asks whether the request itself is malicious, so it is the application firewall with its managed rule sets. The traffic arrives globally, so attaching it to the front door means inspection happens at the edge before a region is involved.
  2. Place the rate limit. No managed rule set knows about a scraping problem in one region, so this is a custom rule combining geography and rate limiting - and it sits on the same engine as the first requirement.
  3. Place the partner destinations. This is about where outbound traffic may go, which is the managed firewall, and the natural expression is filtering by fully qualified domain name rather than by address, because partner services are named rather than fixed.
  4. Place the signature detection. Intrusion detection is a premium capability on the managed firewall.
  5. Say what the proposal cannot do. A managed firewall in the hub answers the third and, on the right tier, the fourth. It does not inspect requests, so the first two requirements are entirely unmet by the proposal as written.
  6. Name the real cost of the fourth. The outbound calls are encrypted, so signature matching needs TLS inspection, which means terminating and re-encrypting the traffic - a certificate and trust arrangement, and a decision that somebody has to approve. It is not a checkbox on a tier.
  7. Add the operational detail. Arm the structured logs on a plan chosen with lesson 1002 in mind, remember that metrics need the older export mode alongside them, and allow up to half an hour before logs appear rather than concluding the configuration failed.

Sanity check. Two of your four requirements should land on a product the proposal never mentioned. If all four were satisfied by the hub firewall, the difference between inspecting a destination and inspecting a request has been collapsed.
