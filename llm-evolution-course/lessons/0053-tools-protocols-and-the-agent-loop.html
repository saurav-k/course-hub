Deep dive · The reasoning era · Lesson 0053

Tools, protocols, and the agent loop

Tool use went from a prompting pattern to a trained capability to an industry protocol, and the loop it produces is simple enough to draw and hard enough to make reliable.

Moving Accurate as of 21 August 2026. Next review due February 2027. The last eighteen months. Rewritten freely, and expected to be wrong before it is old.
Where this lesson starts

A model that answers a question is not the same as a model that does something. This lesson is about the second one. It assumes you know what a prompt is and that a model produces text one token at a time.

1. Where this lesson sits

What you need first

  • Thinking is just more tokens A reasoning model does not think in any new sense: it writes a region of working tokens before it answers, which buys both more computation per question and an external place to keep intermediate results.

The one tight idea

Tool use went from a prompting pattern to a trained capability to an industry protocol, and the loop it produces is simple enough to draw and hard enough to make reliable.

2. First it was only a way of writing the prompt

Start from the limitation, because everything here is a response to it. A language model produces text, one piece at a time, from its weights and whatever is in its input. It cannot look anything up, run anything, or change anything in the world. Ask it the current price of something and it will produce a plausible number, because producing plausible text is the only thing it does.

The first repair needed no new model at all. On 6 October 2022, Yao and colleagues published ReAct, and the whole method lives in the input format. You write the model's turn as a repeating pattern: a thought about what to do next, an action to take, and then an observation, which is the result of that action pasted back into the text before the model continues.

Their framing of why the two halves belong together is still the best one-line description of an agent. The reasoning traces help the model induce, track and update its plan, and handle exceptions when something goes wrong; the actions let it reach outside itself to gather information it does not have. Reasoning without acting has nothing to check itself against, and acting without reasoning has no plan.

The results were concrete rather than atmospheric. On question answering and fact verification, letting the model call a simple encyclopaedia lookup between thoughts reduced the invented answers and the errors that compound from them. On an interactive household-task benchmark, the pattern beat imitation and reinforcement learning baselines by 34 percentage points of absolute success rate.

The historically important part is what did not change. No weights were touched. The loop that every agent in 2026 runs was demonstrated in 2022 as a way of arranging text on the page.

3. Then it became something the model was trained to do

Four months later, in February 2023, Schick and colleagues published Toolformer, and the difference is where the decision lives.

In the prompting pattern, a person writes instructions telling the model to consider using a tool. In Toolformer, the model is trained to decide which interface to call, when to call it, what arguments to pass, and how to fold the result into what it writes next. The training is self-supervised and needs only a handful of demonstrations per tool, and the tools in the paper are deliberately mundane: a calculator, a question-answering system, two search engines, a translation system and a calendar.

The paper's own observation about why this is worth doing is the sharpest argument in the area. Large models are remarkable at open-ended language and, paradoxically, poor at arithmetic and factual lookup, which much smaller and simpler programs do perfectly. Tool use is not a way of making the model cleverer. It is a way of not asking it to do things a calculator already does exactly.

By 2023 the interface had also settled into a convention that has not really changed since. The application hands the model a machine-readable description of each available function, with its name, its purpose and the shape of its arguments. The model, instead of writing prose, emits a structured call naming a function and its arguments. The application runs it and hands the result back as another message. That shape is visible in the vendors' own function-calling documentation and, later, in the tool primitive of the protocol described next.

4. Then it became a protocol

By late 2024 the bottleneck had stopped being capability and become arithmetic of a dull kind.

Every application that wanted a model to reach a system had to write that connection itself, in that application's own way. Three assistant applications wanting to reach four systems meant twelve separate pieces of integration work, and every new tool multiplied rather than added. Nothing about this is intellectually interesting, which is exactly why it does not get solved by research.

On 25 November 2024 Anthropic published the Model Context Protocol and open-sourced it, describing it as a standard for connecting assistants to the systems where data lives, and shipping a specification, software development kits, support in a desktop application, and a repository of ready-made servers for common systems. The architecture is deliberately plain: a system exposes itself through a server, an application that wants to use it is a client, and they talk over JSON-RPC.

The design has an explicit ancestor, and the specification names it. It takes some inspiration from the Language Server Protocol, which standardises how support for a programming language is added across a whole ecosystem of development tools. That is precisely the same shape of problem, solved roughly a decade earlier: before it, every code editor implemented every language separately, and after it each language implemented one server and each editor implemented one client. Many times many became many plus many.

The date that matters for whether a protocol is really a standard is not its launch, though. On 9 December 2025 Anthropic donated the protocol to the Agentic AI Foundation, a directed fund under the Linux Foundation, co-founded with Block and OpenAI, where it became a founding project alongside Block's goose and OpenAI's AGENTS.md. KNOWN, from the Linux Foundation's own press release and the protocol maintainers' announcement. That is the point at which a specification stops being one company's document and acquires neutral governance, which is the property that makes a competitor willing to build on it.

The adoption figures published alongside that donation - over 97 million SDK downloads a month and about ten thousand active servers - are the maintainers' own numbers in their own announcement. MARKETING: no independent methodology is given, and the direction of travel is the useful part rather than the digits.

5. The loop itself

Everything above produces one loop, and it is simple enough to draw in seven lines. A goal arrives. The model decides on the next action. It emits a call. Something runs it against the world. A result comes back as text and is appended to the context. The model decides again. Eventually it stops and answers.

Draw it once and you have the architecture of every agent product shipped since 2023. The interesting part is not the loop. It is that each of those arrows fails in a specific way, and the last three years of engineering are almost entirely about the failures rather than the loop.

Two of those annotations get their own treatment elsewhere. Why success at each step does not add up to success across a long run is Why agents are a systems problem. How to build the surrounding machinery is a whole course of its own, next door in Agent Engineering.

6. The problem nobody has solved

One of those annotations is not an engineering task with a known answer. It is structural, and it is the defining unsolved problem of this era, so it belongs in the body of the lesson rather than in a warning box.

A tool returns text. That text is appended to the same context that holds the user's instructions. To the model there is no difference in kind between the two, because both are sequences of tokens in one window, and nothing in the architecture marks one of them as authoritative and the other as data. So a web page, a document, a code comment or a calendar entry that the model happens to read can contain instructions, and the model may follow them.

This was named and demonstrated early. In February 2023 Greshake and colleagues published work on indirect prompt injection, which is the case where the attacker never talks to the model at all and instead plants text in a place the model is likely to retrieve. Their argument is that applications built around models blur the line between data and instructions, and they derived a taxonomy of consequences including data theft, self-propagating attacks and contamination of the information the system draws on, demonstrating them against real deployed products rather than only against a laboratory setup.

The agent turn makes this considerably worse in one specific way. In 2023 a successful injection made a model say something wrong. In an agent loop the same model also holds the authority to act, so the injected instruction can be carried out: a message sent, a file changed, a record deleted, data forwarded through a second connected tool to somewhere the attacker can read it. Researchers have documented exactly that pattern against tool ecosystems, using poisoned tool descriptions as well as poisoned results.

Notice how the protocol specification itself answers this, because the answer is revealing. Its security section is a set of principles for implementors: users must explicitly consent to and understand data access and operations, hosts must obtain consent before exposing data to servers, implementors should provide clear interfaces for reviewing and authorising activity. Those are governance requirements placed on the surrounding application, not a mechanism in the protocol. That is an honest admission rather than an oversight. A protocol cannot separate instructions from data inside a model that has no such separation, so the trust boundary has to be enforced outside the model, by limiting what any given run is permitted to do.

7. Where this leaves things

In four years tool use travelled from a way of formatting a prompt, through a trained capability, to a specification with neutral governance and an ecosystem around it. That is unusually fast for a standard, and the reason is that the underlying problem was never hard: it was only expensive, and expensive in a way that multiplied.

What did not travel is reliability. A loop that works most of the time is not the same thing as a system that works, and the arithmetic of running the loop many times is unforgiving. That is the debt this lesson hands on, and Why agents are a systems problem collects it.

  • Yao et al., ReAct: Synergizing Reasoning and Acting in Language Models, arXiv, 6 October 2022. The abstract is the source for the description of why reasoning and acting belong together, and for the 34-point figure.
  • Schick et al., Toolformer: Language Models Can Teach Themselves to Use Tools, arXiv, 9 February 2023. The source for the list of tools and for the observation about arithmetic and factual lookup.

Retrieval practice

What was new about the 2022 reasoning-and-acting pattern?
Thought, action and observation were written into the prompt, so the loop every agent runs was demonstrated before any model was trained for it.
What problem does a shared tool protocol actually solve?
It is the same argument the Language Server Protocol made for editors and languages, which is where the design came from.
Why is injection through a tool result a structural problem?
Nothing in the architecture marks one span of the context as authoritative and another as data, so the boundary has to be enforced outside the model.
Why did the protocol's donation to a foundation matter?
A competitor will build on a standard it does not have to trust a rival to steward, which is why the December 2025 transfer is the date that counts.
