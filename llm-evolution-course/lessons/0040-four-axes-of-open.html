Four axes of open: weights, code, data, licence

Open is not one question but four independent ones, almost nothing scores well on all four, and the word is now used for releases that would fail three of them.

Moving Accurate as of 21 August 2026. Next review due February 2027. The last eighteen months. Rewritten freely, and expected to be wrong before it is old.
Where this lesson starts

The leak that started an ecosystem uses the word open without defining it. This lesson defines it. It is a vocabulary lesson and it produces a scorecard the rest of the course reuses.

1. Where this lesson sits

What you need first

  • The leak that started an ecosystem A research-only model release leaked within a week, and the tooling that appeared in the following month showed there had been enormous unmet demand for weights anyone could run.

The one tight idea

Open is not one question but four independent ones, almost nothing scores well on all four, and the word is now used for releases that would fail three of them.

2. The word is doing four jobs at once

"Open" gets used about a model release to mean any of four different things, and a release can be any combination of them. Separate them and most arguments about the word turn out to be two people each describing a different axis correctly.

The four axes, and the question that settles each one. Each can be answered from a release page and a licence file in about two minutes.
AxisThe questionWhere the answer is
WeightsCan I download the parameters and run the model on my own machine, offline?A download link, or a gated form, or neither
CodeCan I see the code that trained it, not merely the code that runs it?A repository, and whether it contains a training pipeline or only inference
DataDo I know what it was trained on, well enough to build something comparable?A corpus table with sources and proportions, or a token count and nothing else
LicenceWhat am I permitted to do with it, and at what scale does that change?The LICENSE file, read rather than summarised

The axes are independent, and their independence is the whole point. A model can be fully downloadable with an unknown corpus. It can have a permissive licence and no training code. Almost nothing at frontier scale scores well on all four, and this lesson will not pretend otherwise.

3. Open weights and open source are not the same claim

There is a formal definition of the second one, and it is worth knowing that it exists because it settles what the argument is actually about.

The Open Source Initiative, which has maintained the Open Source Definition for software since the late 1990s, published version 1.0 of an Open Source AI Definition in October 2024. It requires that you be free to use the system for any purpose without asking permission, study how it works, modify it, and share it - and, crucially, that you have "the preferred form to make modifications", which it spells out as three things: data information detailed enough that "a skilled person can build a substantially equivalent system", the complete source code used to train and run it, and the parameters.

By that definition, a downloadable set of weights with an undisclosed corpus and no training code is not open-source AI, whatever the release page says.

The organisation had already applied this reasoning to a specific case. On 20 July 2023, two days after Llama 2 was released, its executive director Stefano Maffulli published a post titled "Meta's LLaMa license is not Open Source". The argument is narrow and it is about the licence rather than about the data: the Open Source Definition forbids discriminating against persons, groups or fields of endeavour, and the Llama licence both restricts commercial use for some users and restricts what the model may be used for. The post accuses the framing rather than the release - the OSI writes that it "is pleased to see that Meta is lowering barriers", and objects to Meta "confusing 'open source' with 'resources available to some users under some conditions,' two very different things".

The counter-argument, stated properly

The reply from the other side is not that the definition is wrong. It is that an all-or-nothing definition names nothing at frontier scale, and so gives up the ability to distinguish releases that differ enormously in practice.

Weights you can download let you run the model offline, inspect its activations, fine-tune it for your own domain, quantize it, audit its behaviour on data you cannot send to a third party, and keep using it after the vendor discontinues it. Those are real freedoms, they are the ones most people actually exercise, and none of them require the corpus. Meanwhile no frontier laboratory is going to publish a web-scale corpus, for reasons that are partly commercial and partly about copyright, so a definition requiring it will be met by nothing in this class - and a word that applies to nothing stops sorting anything.

The OSI's own page on the subject concedes the practical half of this while holding its line, describing open weights as "a milestone in opening up AI systems" that nonetheless "stop short of delivering the level of transparency many researchers and regulators deem essential", and pointing at reproducibility and data opacity as what is lost.

This course does not adjudicate that. It uses open weights as the descriptive term for a downloadable model, keeps open source for the definition above, and insists on the scorecard instead of the adjective.

4. Four licence patterns worth recognising on sight

Almost every model licence in circulation is one of these four shapes.

  1. Permissive. Apache 2.0 or MIT, unmodified. Commercial use, redistribution, derivative works, no user or revenue threshold, no field-of-use restriction. Mistral 7B, released in September 2023 and documented in a paper whose abstract ends "Our models are released under the Apache 2.0 license", is the release that made this the expected shape for a capable open-weight model, and Apache 2.0 stayed the community's reference point for years afterwards.
  2. Custom with a scale threshold. Permissive-looking text with a clause that switches off above some size of business. Llama 2 is the original of this shape and the 2026 frontier licences are its descendants.
  3. Research-only. Weights on request, non-commercial use, approved recipients. LLaMA 1 in February 2023, and the licences of the datasets and weight diffs that the first wave of tuned models shipped under.
  4. Gated. A separate question from the licence: whether you must accept terms or be approved before the download link works at all. A release can be permissively licensed and still gated, and gating is what a licence cannot tell you.

Reading one in two minutes

Four questions, asked of the file itself:

Take the Llama 2 licence as the worked example, since it invented the pattern. Its clause 2, quoted from the file: if "on the Llama 2 version release date, the monthly active users of the products or services made available by or for Licensee, or Licensee's affiliates, is greater than 700 million monthly active users in the preceding calendar month, you must request a license from Meta, which Meta may grant to you in its sole discretion".

Two details in that sentence repay attention. The threshold is measured on the release date, so a company that grew past it afterwards is not caught, and the clause therefore names a specific short list of companies that existed at that size in July 2023. And the remedy is a licence granted "in its sole discretion", which is to say, at the licensor's option.

Three patterns come out of that table, and none of them is what the word "open" would lead you to expect.

The data column collapsed and never recovered. LLaMA 1 lists its corpus because its argument depended on doing so. Llama 2, five months later, says only "a new mix of publicly available data" and gives no sources. Nothing at frontier scale has listed a corpus since. Token counts are published freely - so many trillion - but a count is a size, not a description, and it does not let anyone build a comparable system.

The licences bifurcated by model size, not by laboratory. This is the finding that most surprises people. In August 2026 Alibaba's Qwen released a 27-billion-parameter model under plain Apache 2.0 and, three days later, its 2.4-trillion-parameter flagship under a custom licence. Same laboratory, same week, two different answers, and the variable is how much the model is worth to a competitor.

The gate is aimed at one business, and says so. The Qwen flagship licence reads as an MIT grant with two conditions bolted on: display the model's name in any product with more than 100 million monthly active users or 20 million dollars of monthly revenue, and, if you run a "Model as a Service" or an "AI Work Assistant" business whose revenue exceeds 50 million dollars over any twelve consecutive months, obtain a separate licence. Internal use is explicitly exempt, and the file defines "Model as a Service" as giving a third party access to inference or fine-tuning in a way that lets them control the inputs. Kimi K3's licence has the same architecture with the trigger at 20 million dollars.

Read that carefully. Almost nobody is restricted. A researcher, a startup, a government department, a company embedding the model in its own product: all unaffected. What is restricted is reselling hosted inference at scale, which is exactly the business the laboratory itself is in.

So the honest one-sentence summary of open weights in 2026 is this: you can run it and you can tune it, but you cannot rebuild it and you may not resell it at scale. That is a meaningful amount of freedom and it is not the same freedom as open source, and calling both of them "open" is what makes the announcements so hard to read.

6. How to use this for the rest of the course

Whenever a release is described as open from here on, run the scorecard rather than accepting the adjective. Download the licence file. Search it for a numeral. Check whether the corpus is listed or merely counted. Check whether the published code trains anything or only runs it.

Two warnings about the table above, which apply to any table like it.

The first is that licences are revised, thresholds move, and a model can be relicensed after release. Every claim in this lesson carries the date it was read - 22 August 2026 - and the link goes to the licence text rather than to a summary of it, so that when the two disagree you can see which one changed.

The second is that this scorecard measures terms, not capability or trustworthiness. A permissively licensed model is not thereby a good one, and a gated licence tells you nothing about whether the weights are worth having. Which of these releases is actually any good is a separate question with its own apparatus, and Reading an eval table like a scientist is that apparatus.

The question this lesson leaves open is one of fact rather than of definition. Given that the axes have separated like this, who is still shipping downloadable frontier weights at all, and how far behind the closed frontier are they? Both of those can be measured rather than argued about, and Who ships open weights now measures them.

Retrieval practice

Why does the formal definition require more than downloadable weights?
The definition turns on having the preferred form for making modifications, which it names as data information, complete source code and parameters.
What changed between the first Llama paper and the second on the data axis?
The first paper had to list it because its argument was that public data suffices; the second only says "a new mix of publicly available data".
Who is actually restricted by a 2026 revenue-triggered model licence?
The clause names Model as a Service and exempts internal use, so it targets the licensor's own business rather than users in general.
What does one laboratory shipping two licences in one week tell you?
A 27-billion model went out under Apache 2.0 and a 2.4-trillion one under a gated licence, so the variable is commercial value rather than principle.
