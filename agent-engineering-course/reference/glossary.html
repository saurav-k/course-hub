Glossary

18 terms One definition each. The build-track revision sheet: every term links to the chapter that develops it.

How to use this

  • Cover the definition column and recall it from the term. Retrieval beats re-reading.
  • Any term you cannot define in one sentence is a term you cannot defend in a design review.
  • Definitions here are opinionated and single-meaning on purpose. The chapters carry the nuance.

Pillar 1 · Context and Protocol

Developed in Chapter 1.

TermDefinition
Context engineeringCurating the whole set of tokens available at inference across a long-running loop. A state management discipline, not a writing one.
Custom MCP serverA service exposing resources, prompts, and tools over the Model Context Protocol, so one integration serves every conforming host.
Typed state handoffPassing validated, versioned objects between agents rather than prose, so an ambiguity fails at the producer instead of travelling.
Guardrails as codeSafety rules kept in version control with a diff, a review, a test, and a rollback. A console-edited rule cannot be bisected.

Pillar 2 · Evaluation and the Data Flywheel

Developed in Chapter 2.

TermDefinition
Trajectory evalGrading the sequence of steps and tool calls an agent took, not only its final answer. Strict for side effects, lenient for reads.
Shadow testingRunning a candidate against mirrored production traffic and discarding its output. Real distribution, zero user exposure.
Data flywheelThe pipeline that turns a user complaint into a triaged, labelled case in the golden dataset that gates tomorrow's release.
Public teardownA blameless written account of a fixed bug, ending in the regression case that now fails without the fix.

Pillar 3 · State, Async and Degradation

Developed in Chapter 3.

TermDefinition
Stateful persistenceRecording the agent loop's state externally, as a workflow event history or graph checkpoint, so a crash resumes rather than restarts.
Async tool executionTurning a slow tool into a long-running operation: return a handle now, deliver the result by signed webhook, resume on arrival.
Degradation chainAn ordered ladder of weaker ways to answer when a tier will not serve, each with its own trigger, budget, and measured quality.

Pillar 4 · Latency, Cost and Local-First

Developed in Chapter 4.

TermDefinition
TTFT and ITLTime to first token is the silence before output; inter-token latency is the pace of it. Two clocks with disjoint fixes.
Semantic cachingServing a stored answer when a new query is close enough in embedding space. Savings are workload-dependent and must be measured.
Cost kill-switchAn enforcement point in the model gateway that refuses work per user and per tenant over a short window. An alert is not one.
Local-first inferenceRunning a model on the user's own hardware with MLX or WebLLM. Zero marginal cost and no data egress, against a capability ceiling.

Pillar 5 · Retrieval and Isolation

Developed in Chapter 5.

TermDefinition
Multi-modal RAGIndexing tables, charts, and page layout rather than discarding them in text extraction. Higher recall on visual corpora, larger index.
Multi-tenant vector databaseOne collection partitioned by an indexed tenant field, filtered inside the search. Post-filtering costs recall rather than privacy.
Inter-agent securityTreating one agent's output as untrusted input to the next, and bounding the receiver's authority rather than filtering its prose.
