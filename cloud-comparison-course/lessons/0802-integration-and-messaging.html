Module 08 · Security, delivery, integration and intelligence · Lesson 0802

The rows every cloud answers are the ones where the names mislead most

working 8 min Capability area integration-messaging, 11 rows of the capability matrix: api-gateway, event-bus, graphql-api, managed-integration, message-queue, mqtt-broker, pub-sub, realtime-messaging, scheduler-jobs, telemetry-export-pipeline and workflow-orchestration.

The one-minute version

  • Six of the eleven rows are answered by a product on all four clouds, and those six carry the worst naming traps in the whole comparison.
  • One row holds a fan-out topic, a durable replayable stream and a push-only notifier, and all three are correct answers to the same key.
  • The five remaining rows carry nine genuine absences, five of them on one cloud. An absence still has a workaround, and the workaround is not the product.
  • The discrimination this page teaches - queue against topic against bus against orchestrator - is a question one certification guide asks in its own words.

1. Four shapes carry almost everything

Two more shapes complete the area. A managed front door for APIs is answered by Amazon API Gateway, Azure API Management, Google API Gateway beside Apigee X, and OCI API Gateway. Connector-driven enterprise integration is answered by AWS Transfer Family with Amazon MQ, Azure's connector library, Application Integration and Oracle Integration 3. That row is the one where OCI and Google Cloud lead with a full integration platform and AWS deliberately does not.

2. What a queue actually promises

Those windows are not the same across the area, and the spread is large. Amazon SQS retains a message for four days by default and up to fourteen, and its standard queues are at-least-once while its FIFO queues buy exactly-once processing and ordering within a message group. Azure Service Bus buys the same ordering through sessions instead. OCI Notifications retries a silent endpoint for up to two hours and then stops, because it is a notifier rather than a durable log. And in the orchestration row, Step Functions ships two workflow types whose maximum executions are five minutes and one year, which is the same word covering a five-order-of-magnitude difference.

Three names that mean different things and one that means less than it looks. Azure's Event Grid routes discrete facts by push while Event Hubs ingests high-volume streams that consumers pull, and Service Bus is the enterprise broker beside both. Google Cloud files Cloud Tasks under the queue row, and its own inventory records that Pub/Sub pull subscriptions are the closer analogue of a general broker while Cloud Tasks dispatches deferred tasks. OCI ships five messaging-shaped services - Queue, Notifications, Events, Streaming and Connector Hub - and picking the wrong one is a redesign rather than a rename.

3. The five rows that split, and the nine absences in them

Each absence carries the reason the audit recorded, and two of them are worth reading carefully because they name a working alternative. Azure has no standalone cron service and covers the need with timer-triggered functions, Logic Apps recurrence and Automation schedules. OCI has no general cron service either, and Resource Scheduler starts and stops resources on a schedule while Functions plus Events cover the rest. Both are still absences: no product answers the row. What the reason tells you is what to build instead, not that the row was misfiled.

The other three are simpler. AWS AppSync is the only managed general-purpose GraphQL service in the comparison, and elsewhere GraphQL is self-hosted or fronted by an API gateway. AWS IoT Core and Azure IoT Hub answer the device-broker row, Google retired its own broker and directs customers to partner platforms feeding Pub/Sub, and OCI has none. And OCI has no generally available first-party workflow orchestrator: a product with that name was announced as limited availability, never given documentation on the vendor's own docs site, and the nearest current answers are Oracle Integration 3 process automation and chains of Functions, Events and Connector Hub.

4. What this certification tests

The AZ-305 study guide asks the candidate to recommend between messaging, event-driven and API-integration approaches, which is this page's question in the exam's own words. The Professional Cloud Architect guide names Apigee in its API-management expectations, and its heaviest domain is Designing and planning a cloud solution architecture at about 25 percent. On 1Z0-997-26 the telemetry export row is named directly: Implementing Observability Solutions is 20 percent and its sub-objectives include observability workflows with Connector Hub. SAP-C02 has no integration domain, and its four domains carry 26, 29, 25 and 20 percent.

Check yourself

Retrieval practice

Answer from memory before revealing.

A design needs subscribers to replay the last day of events after a consumer bug. Which row entry supports that directly?
All four fill the pub-sub row and only one of them is a durable stream you can seek within. The first inverts the recorded behaviour: Notifications retries a silent endpoint for up to two hours and is explicitly not a durable event stream. The second and third both name real filtering features, which decide who receives a message rather than whether an old one can be read again, and a filter cannot replay what was never retained.
The matrix records Azure as having no equivalent for scheduler jobs. What does that license you to conclude?
The cell is an absence with a reason, and the reason names timer-triggered functions, Logic Apps recurrence and Automation schedules. The first over-reads it, which is the failure this whole course guards against. The third describes the unfilled state, which the matrix renders differently and which no cell in this area carries. The fourth describes the delivered-elsewhere state, which this area uses nowhere at all.

Practice about 15 minutes, with paper

Practice 1working

An order service emits one event per order. Three teams want it: billing must process every order exactly once, search wants a live feed it can rebuild from after an outage, and operations wants a message in a chat channel when an order exceeds a threshold.

Assign each of the three to one of the four shapes on this page. Then name, for AWS and for OCI, the product each assignment lands on, and say which of the six assignments is the one that cannot be satisfied as stated.

Hint

Ask what each team needs when it is not listening: billing needs the message kept, search needs to go back and read it again, and operations needs it delivered now or not at all.

Hint on the failing assignment

Only one cloud in this pair has a product in the row that supports going back and reading again, and it is not the one whose fan-out service stops retrying after two hours.

Show the worked solution
  1. Billing is point to point. One message, one worker, kept until deleted. On AWS that is SQS, and a FIFO queue if exactly-once processing is the stated requirement. On OCI it is Queue, which is at-least-once with best-effort ordering.
  2. Search is a durable stream. It needs to re-read history after an outage, not merely to receive a copy. On AWS the pub-sub row gives SNS, and its own inventory records fan-out into SQS as the canonical decoupling pattern, so the AWS answer is SNS into a queue that holds the message for up to fourteen days. On OCI the pub-sub row gives Notifications.
  3. Operations is fan-out to a person. On AWS that is SNS to a chat or mobile endpoint. On OCI that is Notifications, which delivers to Slack and PagerDuty among others.
  4. Find the failing assignment. Search on OCI. Notifications retries a silent endpoint for up to two hours and is not a durable event stream, so a subscriber that was down for longer cannot rebuild from it.
  5. Say what you would do instead. Land the events somewhere durable first and read from there, which is what the OCI inventory points at when it separates Queue, Notifications, Events, Streaming and Connector Hub into five distinct answers.

Sanity check. Six assignments, and exactly one should fail. If two failed you probably ruled out AWS for search as well: the retention lives in the queue SNS fans out into, so the requirement is met by a pair of products rather than by one. If none failed, check what the OCI fan-out product promises when nobody is listening.

Your teacher. Before you pick a messaging product on a cloud you do not know well, write down the three windows first: how long the platform keeps the message, how long it keeps retrying, and how long one unit of work may run. Then ask an agent for the vendor page that states each one. A product that cannot answer all three is not the product you meant to choose.
