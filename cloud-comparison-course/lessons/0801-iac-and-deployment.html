The four native engines differ in language, not in who holds the state

working 8 min Capability area iac-deployment, 8 rows of the capability matrix: artifact-registry, cicd-pipeline, config-management, iac-in-code-sdk, kubernetes-config-management, native-iac-template, progressive-delivery and terraform-provider.

The one-minute version

  • AWS and Azure wrote declarative languages of their own. Google Cloud and OCI adopted Terraform as the native engine instead, and ship no language of their own.
  • That difference is smaller than it looks: on all four native paths the provider holds the state, so no team owns a state file until it chooses to run Terraform itself.
  • Thirty of the thirty-two cells are a product. This is the most completely answered area in the module, so a design here is choosing between four working answers rather than around a gap.
  • The real divergence is the rollout layer: one cloud sells a delivery product, and the other three shift traffic with primitives that belong to each compute type.

1. One change, five stops

All four bundle the first half. AWS CodePipeline with CodeBuild, Azure Pipelines beside GitHub Actions, Cloud Build and the OCI DevOps service all take a commit and produce an artifact. Package feeds are equally settled: CodeArtifact, Azure Artifacts, Artifact Registry and OCI Artifact Registry answer one row each. Google Cloud is the one that stops short of the full bundle, because its own Git hosting is closed to new customers and its pipeline product is build-focused.

2. Two languages, two Terraforms, one state custody

CloudFormation carries change sets, automatic rollback, drift detection and StackSets for many accounts at once, with CDK and SAM as authoring layers above it. Bicep is the same idea with the state question answered by Resource Manager rather than by a file, and deployment stacks add a managed unit that can deny writes to what it created. Infrastructure Manager and OCI Resource Manager take HCL and run it for you, with drift jobs on both sides.

Terraform sits in two different rows and they are not the same answer. Every cloud ships a Terraform provider, so the terraform-provider row is filled four times over, and AWS fills it twice: the community hashicorp/aws provider alongside a generated one that tracks new resources through Cloud Control API. That is Terraform you run. The managed services above are Terraform the provider runs. A design that assumes the first is available where only the second is named will be surprised by who owns the plan.

3. The rollout layer, where the products really differ

Only Google Cloud sells a product whose whole job is this: Cloud Deploy holds the pipeline, the targets, the approvals and the canary percentages in one place. AWS assembles the same shapes from primitives that belong to each compute type, so the traffic shift for a function is an alias weight, for a container a task-set swap, and for an API a stage canary setting, with AppConfig covering runtime flags and alarm-triggered rollback. Azure does the same with deployment slots and weighted Container Apps revisions. OCI is between the two: the strategies are blue-green and canary stages inside the DevOps pipeline rather than a separate product.

4. The two rows that are genuinely missing

Thirty of the thirty-two cells in this area are a service. The two that are not are worth naming precisely, because both are absences with a stated reason rather than gaps in the research.

RowMissing onWhat the audit recorded
iac-in-code-sdk Google Cloud No first-party way to provision from a general-purpose language. The path there is a third-party tool over the Terraform provider, with Infrastructure Manager running the resulting plan. The other three each name a first-party or supported in-code route.
kubernetes-config-management OCI No first-party operator exposing OCI resources as Kubernetes custom resources. AWS Controllers for Kubernetes, Azure Service Operator and Config Connector answer it on the other three.

The cost of the second row is not obvious, so it is worth stating with the benefit. An operator lets one control plane reconcile cluster workloads and cloud objects together, which is why a GitOps team wants it. Two of the three are open source you install into your own cluster rather than a managed control plane, so the cluster owner inherits the upgrade and the blast radius along with the convenience.

5. What this certification tests

No professional blueprint gives infrastructure as code a domain of its own, so the weights below are the domains this area sits inside. On 1Z0-997-26 that is Architect Cloud-Native Solutions at 20 percent, whose sub-objectives name Resource Manager and OCI DevOps directly. The Professional Cloud Architect guide splits it between Managing and provisioning a cloud solution infrastructure at about 17.5 percent and Managing implementation at about 12.5 percent. On AZ-305 the largest domain is Design infrastructure solutions at 30 to 35 percent. SAP-C02 names four domains and none of them is deployment: Organizational Complexity 26 percent, New Solutions 29 percent, Continuous Improvement 25 percent and Migration and Modernization 20 percent.

Check yourself

Retrieval practice

Answer from memory before revealing.

A team moving to Google Cloud asks who will look after the Terraform state file on the native path.
Infrastructure Manager is Google-managed Terraform with the state hosted by Google, exactly as OCI Resource Manager locks state server side. The first is what happens when a team runs Terraform itself, which is a real choice and not the native path. The second is true of AWS and Azure and false here. The fourth confuses a Terraform provider, which translates configuration into API calls, with a backend, which is what stores state.
Which cloud sells a product whose only job is progressive delivery?
Cloud Deploy is the one dedicated delivery product in the row. The second is too generous: OCI does name blue-green and canary strategies, but inside its DevOps pipeline rather than as a separate product. The third is contradicted by that same row. The fourth mistakes a configuration name for a product, and those configurations belong to CodeDeploy, which is a deployment service rather than a delivery pipeline.

Practice about 15 minutes, with paper

Practice 1working

A release goes out at ten in the morning. The health signal that would have caught the fault takes 12 minutes to fire, because the alarm needs three consecutive four-minute evaluation periods. Requests arrive at a steady rate.

Work out, for each of the three shapes in the chart above, roughly what share of the traffic in those 12 minutes reached the bad version. Then say which shape you would pick if the alarm were tuned to fire in 90 seconds instead, and why the answer changes.

Hint

Traffic share times minutes is the quantity you want. Draw the 12-minute window on each curve and add up the rectangles under it.

Hint on the second part

A slow ramp only helps while the detector is still deciding. Ask what the linear shape is still buying you once the window shrinks to a minute and a half.

Show the worked solution
  1. All at once. 100 percent for the whole window. 100 × 12 = 1200 percent-minutes, so 100 percent of the window's traffic hit the bad version.
  2. Canary, ten percent for five minutes. 10 × 5 = 50, then 100 × 7 = 700. Total 750 of 1200, so about 63 percent.
  3. Linear, ten percent every ten minutes. 10 × 10 = 100 for the first ten minutes, then 20 × 2 = 40. Total 140 of 1200, so about 12 percent.
  4. Rank them. The linear ramp exposes roughly one eighth of what an all-at-once release does over the same detection window, and the canary sits between the two because its second step is the whole remainder.
  5. Retune the alarm to 90 seconds. Inside a 1.5-minute window all three shapes are still at their first step: all-at-once is at 100 percent, and both the canary and the linear ramp are at 10 percent. The canary finishes at five minutes and the linear ramp at ninety, so the canary buys the same exposure 85 minutes sooner and becomes the better pick.

Sanity check. Every answer must be a share between 0 and 100 percent, and the ranking must put all-at-once worst and the linear ramp best over a long window. If your canary figure came out below the linear one, the second step was missed: the canary goes to the full remainder at five minutes, and seven of the twelve minutes are spent there.

Your teacher. The number that decides your rollout shape is not a preference, it is how long your health signal takes to fire. Measure it: push a deliberately broken change to a staging environment and time the alarm. Then ask an agent to name the traffic-shifting primitive for the exact compute type you deploy on, because on three of the four clouds there is a different one per type.
