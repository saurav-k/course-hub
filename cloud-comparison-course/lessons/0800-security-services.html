Module 08 · Security, delivery, integration and intelligence · Lesson 0800

Half the security rows are commodity, and the other half decide the design

working 8 min Capability area security-services, 14 rows of the capability matrix: ai-safety-guardrails, bastion, cloud-firewall, data-classification, packet-mirroring, posture-management, security-investigation-graph, service-perimeter, threat-detection, verified-permissions, vulnerability-scanning, waf, zero-trust-app-access and zero-trust-routing.

The one-minute version

  • The area holds fourteen capabilities, and seven of them are answered by a named product on all four clouds. Those seven are not where a cloud choice bites.
  • The other seven split, and a split has two very different causes: the cloud ships the capability inside another product, or it genuinely ships nothing.
  • Reading the second as the first is the expensive mistake, and reading the first as the second is the common one. The matrix separates them by design.
  • Three rows are one cloud's alone. Each is a deliberate architectural bet rather than an oversight on the other three.

1. Five jobs, fourteen rows

Five jobs cover all fourteen capabilities: filtering what arrives, detecting what is happening, assessing the configuration, protecting the data, and brokering the access. A cloud that is strong in one of those bands is not automatically strong in another.

The filtering, detection, posture and data bands are settled. All four clouds sell a web application firewall, a managed network firewall, a posture service, a threat detector, a vulnerability scanner, a sensitive-data classifier and an out-of-band traffic tap. Seven rows, twenty-eight cells, every one of them a product with vendor documentation behind it. The differences there are of depth rather than of presence, and the matrix row carries them.

3. Absent, or delivered elsewhere

Both cases look the same from a product catalogue: you search a vendor's site for a name and find nothing. They are opposite findings. One says design around it, the other says you have already bought it.

Bastion is the worked example. Azure Bastion and OCI Bastion are products with that name. AWS has no product called Bastion and brokers the same session through Session Manager, part of AWS Systems Manager, which needs no open port and no public address on the target. Google Cloud does it through TCP forwarding in Identity-Aware Proxy. Four clouds, four working answers, two product names.

The investigation graph splits the same way and then genuinely runs out. Amazon Detective is sold separately. Azure delivers the graph inside Microsoft Sentinel and Google Cloud inside Security Command Center. On OCI the audit found no correlated graph at all: Cloud Guard problems and Threat Intelligence lookups are joined by hand, and that is the absence, stated with its reason rather than inferred from a missing name.

4. The rows one cloud sells alone

Three rows are a single vendor's bet, and each one tells you something about how that cloud thinks.

CapabilityWho ships oneWhat the others do instead
Service perimeter VPC Service Controls, Network Security Perimeter AWS assembles the same effect from resource control policies, service control policies, endpoint policies and resource-policy conditions, evaluated per request rather than as one boundary. OCI has no API-level perimeter.
Verified permissions Amazon Verified Permissions Nothing managed. On the other three the model is hand-built on directory roles and group claims, or on a policy engine you run, because their cloud IAM governs cloud resources rather than your application's own objects.
Zero-trust routing Zero Trust Packet Routing Reachability elsewhere resolves to addresses, groups and ports. Google secure tags come closest by letting a firewall rule name a resource tag, but they do not constrain the path independently of the network.
A one-cloud row is a constraint, not a scoreboard. Zero Trust Packet Routing allows at most three security attributes on a resource, and a packet must still satisfy the route table and the security lists as well as the intent policy, so it adds a layer rather than replacing one. Read the vendor page before you design a portable pattern around any row that only one cloud can answer.

The remaining two split rows follow the same shape. AWS Verified Access, Microsoft Entra Private Access and Identity-Aware Proxy all put identity and device posture in front of an internal application with no VPN client, and OCI has no identity-aware application proxy, brokering host sessions through Bastion instead. For screening a model's prompts and responses, Bedrock Guardrails, Azure AI Content Safety and Model Armor answer the row, and on OCI the safety filtering is whatever the hosted model itself applies.

5. What this certification tests

The four professional exams weight this area very differently, and the weights come from each vendor's own guide.

The Oracle blueprint is the outlier: Architect Security Solutions is 25 percent of 1Z0-997-26 and its heaviest domain, and its sub-objectives name Bastion, Zero Trust Packet Routing, Network Firewall and WAF directly. On AZ-305 security arrives folded into Design identity, governance, and monitoring solutions at 25 to 30 percent. The Professional Cloud Architect guide gives Designing for security and compliance about 17.5 percent. SAP-C02 has no security domain at all: the controls are distributed through all four of its domains, and its unscored emerging-topics block names guardrails and agent access controls.

Retrieval practice

Answer from memory before revealing.

A design needs brokered administrative sessions to hosts with no public address, on AWS. What does the matrix say?
The bastion cell for AWS is a delivered-elsewhere cell pointing at config management, and Session Manager is the named product. The first is the exact mistake this page is about: a missing product name read as a missing capability. The third names a real AWS product doing a different job, putting identity and device posture in front of an application rather than brokering a host shell. The fourth is what Azure and OCI do, and AWS does not.
Which statement about the service perimeter row is supported by the verified research?
Google Cloud and Azure both ship a perimeter object, and the AWS and OCI cells are recorded absences with stated reasons. The first is simply too generous. The second was true of an earlier draft of the research and the repair pass corrected it, which is why the Azure cell now names a product. The third invites you to invent a name that the audit did not find, and inventing one is how a wrong equivalence reaches a page.

Practice about 15 minutes, with paper

Practice 1working

You are asked to write one paragraph for an internal wiki: "administrative access to private hosts, on all four clouds". A colleague has drafted this sentence.

"Only Azure and OCI can broker admin sessions to private hosts. On AWS and Google Cloud you have to run your own jump box."

Rewrite the sentence so that every clause is supported by the matrix, and list the four products it should name. Then say which single word in the draft caused the error.

Hint

Open the matrix on the course map and read the bastion row across all four columns. Two of the four cells are not products, and they are not the same kind of not-a-product either.

Hint on the failing word

Ask which word turns an observation about a product catalogue into a claim about a platform's abilities.

Show the worked solution
  1. Read the row. Azure and OCI cells are services. The AWS and Google Cloud cells are delivered-elsewhere cells, each naming the product that does the job.
  2. Name the four products. Azure Bastion, OCI Bastion, AWS Systems Manager Session Manager, and Identity-Aware Proxy TCP forwarding on Google Cloud.
  3. Rewrite it. "All four clouds broker administrative sessions to hosts with no public address. Azure and OCI sell a service called Bastion. AWS delivers it through Session Manager inside Systems Manager, and Google Cloud through TCP forwarding in Identity-Aware Proxy."
  4. Find the failing word. "Only". It converts the absence of a product name into the absence of a capability, and nothing in the row supports that step.
  5. Check the jump-box clause. It follows from the same error and goes with it. Both replacements need no open inbound port, which is the reason a jump box existed.

Sanity check. Your rewrite should name four products and make no claim that any cloud cannot do the thing. If it still contains the word "only" applied to a capability rather than to a product name, the error survived the rewrite. Four cells, four answers, and the count of working answers should equal the count of columns.

Your teacher. When a comparison you read says a cloud "has no X", ask an agent for the vendor's own page for X on that cloud before you believe it. If the page exists under another product's name, the comparison was counting brand names. If it does not, ask what the vendor recommends instead, and you have the reason that belongs beside the absence.

Primary source to go deeper

Google's VPC Service Controls overview is the single best read after this page. The perimeter is the row where two clouds have no equivalent for architectural reasons rather than for want of a product, and the page states plainly what a perimeter blocks that an identity policy does not: data leaving the boundary even when the caller holds valid credentials.
