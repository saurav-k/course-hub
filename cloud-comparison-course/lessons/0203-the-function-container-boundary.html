Module 02 · Compute: placement, scaling, containers · Lesson 0203

Each cloud drew the line between a function and a container in a different place

working 8 min Capability area serverless-app, three rows of the matrix: functions-faas, paas-web-runtime and static-site-hosting.

The one-minute version

  • All four clouds sell event-driven functions. Azure alone uses a trigger and binding model, where the platform supplies the inputs and collects the outputs. The other three hand your code an event.
  • Google has folded functions onto the container substrate: the product is now called Cloud Run functions and the old name is gone, which quietly breaks older material.
  • A function is bounded in time, and the ceiling is what moves a job onto a container. On OCI that move is documented: a detached invocation buys twelve times the synchronous ceiling, and past that the job belongs on Container Instances.
  • The managed web runtime is the row where the four are least alike, and two of the four services in it are closed or retiring.
  • Static hosting looks identical everywhere and is not: OCI has no bucket website endpoint, so a custom domain arrives through API Gateway.

Three rows, one question

Functions: how the code is called

AWS Lambda bills per request and per gigabyte-second, assumes its execution role automatically, and can be packaged as a container image of up to ten gigabytes pulled from Elastic Container Registry. Aliases carry weighted routing, which is how a canary is done. Azure Functions is the trigger-and-binding cloud, and it is also the one that sells hosting plans as a first-class choice: Consumption scales to zero, Flex Consumption adds per-instance concurrency and virtual network integration, Premium keeps instances pre-warmed, and Dedicated runs on an App Service plan. Its Durable Functions extension adds stateful orchestration on top.

Cloud Run functions is the naming trap of this area. The second generation runs on the Cloud Run substrate and is the current product, the first generation is legacy, and the name Cloud Functions is no longer a product of its own - so a search result or a course written a while ago names something that has moved. OCI Functions is built on the Fn Project, offers memory in fixed steps from 128 megabytes to 3,072, caps a request or response payload at six megabytes, and supports provisioned concurrency and a bring-your-own Dockerfile.

The reframing Read the OCI cell precisely. The row is filled by a service, not marked as an absence, because Visual Builder and APEX are real products that host real applications. What the inventory records is narrower and more useful: no general-purpose runtime of the App Service kind. A design that wants to hand Oracle a Node or Java web application and receive a URL puts it on a container instead, and that is a difference in shape rather than a hole.

Static hosting, where the last difference hides

All four clouds serve a static site from a content network with previews from a repository. AWS Amplify Hosting serves static and server-rendered applications behind CloudFront with branch previews. Azure Static Web Apps adds integrated API functions and a staging environment for every pull request. Firebase Hosting covers Google Cloud, with plain Cloud Storage website hosting as the alternative for a team that does not want Firebase.

OCI is the one that behaves differently, and the reason is worth carrying between clouds. Object Storage has no bucket website endpoint of the kind Amazon S3 offers, so the documented pattern puts API Gateway in front of the bucket to supply the custom domain and the certificate. The capability is there and the plumbing is one component longer.

What this certification tests Serverless is named explicitly in two of the four blueprints. AZ-305 lists serverless among the compute choices being tested under Design infrastructure solutions, 30 to 35 per cent, and the OCI Architect Professional blueprint names Oracle Functions inside Architect Cloud-Native Solutions, 20 per cent. On SAA-C03 the word to watch is different: the official guide's four domains are qualities rather than services, and a scenario that says "least operational overhead" is the one steering you at this capability area.

Check yourself

Retrieval practice

Answer from memory before revealing.

A handler on AWS reads a queue message, calls a database and writes a file. What changes most when the same design moves to Azure Functions?
The trigger and binding model is the structural difference: the platform performs the input and output work that your handler used to do itself. The first option is wrong because both platforms carry a broad language set. The second invents a restriction, and the third has the identity story backwards.
An OCI job takes about twenty minutes per run. Where does it belong, according to Oracle's own documentation?
A detached invocation runs to 3,600 seconds, which covers twenty minutes, and Oracle names Container Instances for jobs that outgrow the synchronous limit. Option one misstates the synchronous ceiling, which is 300 seconds. Option three confuses provisioned concurrency, which is about start-up, with the time limit. Option four is the false negative.
Which statement about the managed web runtime row matches what the verified inventories record?
AWS App Runner is closed to new customers and Azure Spring Apps is retiring, which is two of the services listed on that row. Option two is wrong because OCI ships low-code products rather than that shape. Option three overstates it into an absence the inventory does not record, and option four is wrong because App Engine remains generally available even though Google steers new work elsewhere.

Practice about 15 minutes, with paper

Practice 1working

An image pipeline runs on AWS. A Lambda function is triggered when a file arrives, resizes it, writes three variants back, and takes between eight and twelve minutes on a large input. A small internal web console sits in front of it on Elastic Beanstalk, and a marketing site is served by Amplify Hosting.

Move all three pieces to OCI on paper. For each one, name the OCI service, say whether the row is answered by a product or by a documented pattern, and name the single constraint that forces a change to the design.

Hint

Check the run time against OCI's function ceilings before choosing the service, and check whether OCI Object Storage can serve a custom domain on its own.

Show the worked solution
  1. Take the resize job first. Twelve minutes is 720 seconds, which is over the OCI Functions synchronous ceiling of 300 seconds and under the detached ceiling of 3600. So OCI Functions can hold it, on the detached path, and the constraint that forces a change is that the caller no longer gets the result in the response.
  2. Check the payload as well. An OCI Functions request or response payload is capped at 6 megabytes, so the image itself travels through Object Storage and the function receives a reference. On a large input that is a design change, not a configuration one.
  3. Take the web console. Elastic Beanstalk has no product equivalent on OCI: the row is filled by Visual Builder and APEX, which are low-code, and the documented path for an ordinary web application is a container on OKE or on Container Instances. This is the piece that gains an operational component rather than losing one.
  4. Take the marketing site. Object Storage serves the files, and because there is no bucket website endpoint the custom domain and the certificate come from API Gateway in front of it. The row is answered by a documented pattern rather than a product.

Sanity check. Exactly one of the three pieces should stay serverless in the same sense it was, and two should gain a component. If your answer moved the resize job onto a container, re-check twelve minutes against 3,600 seconds - the detached path covers it, and reaching for a container early costs you the scale-to-zero billing for nothing.

Your teacher. If the module has landed, the useful next question is not about another service. Ask an agent to take one workload you actually run and place it on every rung this module described - machine, fleet, container, function - on your own cloud, and to name what each rung costs you. The rung you are on is rarely the rung you chose.
