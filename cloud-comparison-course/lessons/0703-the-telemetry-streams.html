A telemetry stream is defined by its default, not by its existence

working 9 min Capability area audit-telemetry, 11 rows of the capability matrix: control-plane-audit-log, data-plane-access-log, service-specific-log, load-balancer-access-log, network-flow-log, dns-query-log, firewall-rules-log, nat-logs, identity-provider-audit-log, policy-denied-audit-log and access-transparency-logs.

The one-minute version

  • Exactly one stream is always on and free on all four clouds: the record of configuration-changing API calls.
  • Everything else is off until someone turns it on, and the biggest of them, the record of reads and writes to your data, is the largest hidden cost in a telemetry design.
  • Google Cloud itemises ten of these eleven streams; Azure seven; AWS and OCI six each. The gap is not evenly spread, and four of the five extras are Google's alone.
  • A stream nobody emits is not the same as a fact nobody records. Most of the absences here mean the event lands in a different stream, and the page says which.

1. Three planes, and one of them is free

The control-plane audit log is the one stream you inherit rather than choose. AWS CloudTrail is on by default as a free ninety-day event history, immutable, with a configured trail needed for anything permanent. Azure Activity Log records ARM operations and keeps ninety days free. Google Cloud Admin Activity and System Event logs cannot be disabled at all and sit in the required bucket for four hundred days. OCI Audit records every call to a public API endpoint, always on, with retention fixed tenancy-wide.

Those ninety-day figures are the free tier, not a ceiling. A configured AWS trail writes objects into your own bucket and keeps them as long as you keep them, and Azure exports the Activity Log the same way. The design point is that on two of the four clouds a long audit history is something you set up in advance, and nobody can set it up retroactively.

2. The plane that costs money

Reads and writes to the data inside a service are a different stream from changes to the service itself, and that stream is off by default on all four clouds. CloudTrail data events cover object, item and invoke-level calls and are charged per event delivered, with selectors to narrow what you pay for. Azure resource logs reach nearly every service through a diagnostic setting written per resource. Google Cloud data access audit logs are off for most services, with part of BigQuery excepted, and are enabled per service. OCI enables bucket and file-system access logs per resource.

The last five rows are where a careless sentence does the most damage, so each one is worth stating precisely.

Identity events are recorded on all four clouds. Only Azure keeps them as a separate stream, the Entra audit and sign-in logs. On AWS, Google Cloud and OCI the same events land in the general control-plane audit log, which means sign-in analysis shares one pipeline with resource changes rather than being impossible.

Policy denials are recorded on all four clouds too. Google Cloud gives them their own stream. Elsewhere a denial appears inside the general audit log as a failed operation carrying an error code and, on AWS, the policy that produced it.

Access transparency is a real absence on three clouds. Google Cloud emits a continuous log of Google personnel accessing your content. AWS records your own principals and the AWS service principals acting for you, not support staff reading your content. Azure's Customer Lockbox gates a Microsoft engineer's access behind your approval, which produces approval records rather than a continuous log - a different control, and arguably a stronger one, but not this stream. OCI's Audit service records API calls against your tenancy, not Oracle staff access.

Firewall verdicts and NAT translations are the two rows to read most carefully. Only Google's firewall rules logging names the rule that decided. On the other three the accept or reject is still visible in the flow log, and the managed firewall product has its own logs; what is missing is the attribution to a specific rule of the basic filtering layer. For NAT, only Cloud NAT emits translation events. The other three expose port exhaustion as a metric, so you can see that it happened and cannot identify the flow that failed after the fact.

4. What each stream quietly does not capture

Every stream has a documented blind spot, and the blind spots are more useful than the feature lists. AWS VPC Flow Logs record neither traffic to the DNS resolver nor calls to the instance metadata endpoint, so a detector built only on flow logs cannot see a credential being fetched (flow log limitations). AWS resolver query logging and OCI private resolver logging both skip answers served from cache, so query volumes undercount real client load. Azure offers no per-query log for a public zone at all, and the documented design is to put the firewall DNS proxy or the private resolver on the resolution path (firewall monitoring). Load-balancer logs are explicitly best-effort on AWS and arrive as gzipped objects every five minutes rather than as a stream (ELB access logs).

What this certification tests

The audit and telemetry streams are the evidence layer of every governance answer on the professional exams. Oracle weights Implementing Observability Solutions at twenty percent and names centralised logging and audit logs among its objectives (exam topics). AWS puts the multi-account logging design inside Design Solutions for Organizational Complexity at twenty-six percent (exam guide), and Azure asks for a recommended logging and monitoring solution inside its twenty-five to thirty percent governance domain (skills measured).

Check yourself

Retrieval practice

Answer from memory before revealing.

An auditor asks which of your engineers read a particular object last month. On which clouds does the answer exist by default?
Reading an object is a data-plane event, and the data-plane stream is off by default on all four clouds. The first two options confuse it with the control-plane record, which is indeed always on and free but records the configuration change rather than the read. The third quotes a real AWS number that applies to the wrong stream, since event history is management events only.
Your AWS network detector uses only VPC Flow Logs. Which activity will it never see?
Flow logs exclude traffic to the instance metadata endpoint by documented design, so the classic credential fetch is invisible to them. The first is recorded as a reject. The third is recorded, because the NAT gateway's own interface is a logged interface. The fourth is ordinary flow-log material.

Practice about 15 minutes, with paper

Practice 1working

You are asked to build one tool that runs on all four clouds and answers a single question: "which identity denied which action, and by which rule?" It must work for an identity policy denial and for a network filtering denial.

List the streams you would subscribe to on each cloud, and name the cloud on which the second half of the question cannot be answered from platform telemetry for the basic filtering layer.

Hint

Split the question in two. A policy denial is a control-plane fact on every cloud, though on one of them it has its own stream. A filtering denial is a network fact, and the interesting word in the question is "by which rule" rather than "denied".

Show the worked solution
  1. Policy denials, Google Cloud. Subscribe to the policy-denied audit log, which is its own stream and is always generated.
  2. Policy denials, the other three. Subscribe to the general control-plane audit log and filter on the failure: CloudTrail with an access-denied error code on AWS, a failed operation in the Activity Log naming the assignment on Azure, and the failing response code in OCI Audit.
  3. Filtering denials, Google Cloud. Firewall rules logging gives the verdict and names the rule that produced it, which is the whole question in one stream.
  4. Filtering denials, the other three. The flow log records the reject, so the connection is visible, but the basic filtering layer emits no per-rule verdict. The managed firewall product has its own logs, which cover only the traffic that passes through it.
  5. Answer the second half. AWS, Azure and OCI all fail the "by which rule" half for security groups, network security groups and security lists respectively. Your tool can report that a connection was rejected on all four clouds and can attribute it to a rule on one.

Sanity check. Your answer should subscribe to two streams on Google Cloud and to one general audit stream plus one flow log on each of the other three, and it should end with three named clouds rather than a general complaint. If you wrote that the other three cannot see the denial at all, re-read step 4: the verdict is there, the rule attribution is not.

Your teacher. The single most useful habit from this page is to ask, of any stream, three questions in order: is it on, what does it not capture, and how late is it. Vendors document all three and lead with none of them. Ask an agent to name a telemetry stream and to state its blind spot before its fields, and push back when it answers with a feature list.

Primary source to go deeper

Flow log limitations on AWS is a short page listing exactly what the stream leaves out. Every cloud publishes a page like it for every stream, they are the least-read pages in the documentation, and they are where the difference between a working detector and a confident blind one lives.
