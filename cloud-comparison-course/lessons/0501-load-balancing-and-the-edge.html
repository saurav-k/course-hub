Module 05 · Networking, delivery and edge · Lesson 0501

A front door is a product on two clouds, a property on the third, and a DNS answer on the fourth

working 10 min The six networking-lb-edge rows of the capability matrix, compared across all four clouds.

The one-minute version

  • All four clouds sell a transport-layer balancer and an application-layer one, and the pair behaves much the same on each.
  • The global entry point is where they part. AWS and Azure sell one, Google Cloud's application balancer already is one, and OCI steers at the naming layer rather than through a proxy.
  • That choice decides how a failure is noticed. A proxy re-picks per request, and a DNS answer is cached for its time to live.
  • Two genuine absences sit in this area: no first-party general CDN on OCI, and no transparent appliance balancer on Google Cloud or OCI. Both carry a documented reason.

1. One path, four fillings

The mechanism first. A request leaves a user, arrives at some entry point the provider operates, is matched against a rule that picks a healthy backend, and is carried to that backend. Two things can vary: how far from the user that decision happens, and whether the entry point terminates the connection or merely forwards it. Everything in this area is one combination of those two.

2. Where the global entry lives

AWS Global Accelerator hands you two static anycast addresses that ride the AWS backbone to healthy regional endpoints, and its documentation positions it as the answer for traffic that is not HTTP or that needs fixed addresses - a complement to CloudFront rather than a replacement. Azure Front Door is the fuller shape: global anycast ingress that terminates TLS, caches, runs a rules engine and a web application firewall, and steers on origin health. Google Cloud's external Application Load Balancer is global and anycast by default and terminates TLS at the edge point of presence nearest the user, which is why Google sells no separate front-door product - the capability is real and it lives in the balancer.

OCI answers the same capability with Traffic Management, and the difference is worth stating precisely because it is easy to state wrongly. Oracle's steering is real global steering: failover, weighted, geolocation, autonomous-system and address-prefix rules, driven by health checks. What it is not is a proxy. There is no anycast entry point that terminates TLS near the user, so the steering happens in the answer to a name lookup and the client then connects to a region directly.

3. What that costs: how a failure is noticed

The same trade is written into Oracle's own steering documentation, which names the time-to-live choice as the trade between failover speed and query load, and into Azure Traffic Manager, whose one advantage over a proxy is that it steers to any publicly reachable endpoint rather than only to endpoints on its own cloud.

4. The two balancers, and the one word that separates them

Under the entry point the four clouds converge. AWS ALB, Azure Application Gateway v2, Google Cloud's regional application balancer and the OCI Flexible Load Balancer all terminate TLS and route on host and path, and each is the attachment point for that cloud's web application firewall. The transport-layer twins - AWS NLB, Azure Load Balancer, Google Cloud's network balancer family and the OCI Network Load Balancer - pass flows through without terminating them, which is what preserves the client's own address for the backend to see.

Google Cloud is the one place where that last sentence needs care. Its network load balancing is a family holding both a passthrough form and proxy forms for TCP, TLS and UDP, and Google's own documentation notes that whether the source address survives depends on which of the two you picked. On the other three the transport balancer is passthrough and the question does not arise. Reading "network load balancer" as "passthrough" is a habit that travels badly.

5. Caching and attack absorption: same idea, four packagings

The OCI cell is worth reading carefully, because it is the shape a real absence takes. Oracle ships edge DDoS protection at no charge and does application-layer filtering through its web application firewall, so the attack row is answered. The caching row is not: there is no first-party general-purpose content delivery network, and the documented paths are partner networks fronting OCI origins, the firewall at the edge, Traffic Management steering, and Media Streams for streaming delivery. That is a design constraint to plan around, not a service to go looking for.

Azure's cell is the opposite reading. Azure has edge caching - it is simply inside Front Door, and the separately branded CDN products are legacy. A comparison that reads the retirement of the old product as the loss of the capability gets the answer exactly backwards.

6. The transparent appliance balancer

One row here is a true two-two split. AWS Gateway Load Balancer and the Gateway SKU of the Azure load balancer both exist to drop a fleet of third-party firewalls or intrusion-prevention appliances into the traffic path without the application's addressing changing. Google Cloud and OCI ship no such product, and the audit records the same reason for both: appliances are inserted with routing instead - a next hop that is an internal balancer or a private address, chosen by a route rule. The capability is reachable on all four. The object that makes it easy exists on two.

7. What this certification tests

Azure is again the one that names it. AZ-305's heaviest domain, "Design infrastructure solutions" at 30 to 35 per cent, carries recommending a load-balancing and routing solution as an objective in its own right, and AZ-104 examines the implementation side inside its networking domain at 15 to 20 per cent. On the other three tracks this material is examined through scenario questions inside broader domains rather than under a heading of its own.

Check yourself

Retrieval practice

Answer from memory before revealing.

A design needs users steered to a healthy region within seconds, on a cloud that steers at the naming layer. What sets the floor on that time?
A client keeps a cached answer until the time to live expires, so it cannot notice a change sooner however fast the provider reacts - both Oracle and Microsoft document that trade. The health-check interval decides when the provider changes its answer, which is the other half and not the floor. Region count and balancer bandwidth affect neither.
Why does Google Cloud sell no separate global front-door product?
The external Application Load Balancer is global and anycast by default and terminates TLS at the edge, so it plays the front-door role directly. The first option describes the OCI caching row, not this one. The second is false of every cloud's edge. The third is a true statement about the VPC network that answers a different question - a global network says nothing about where user traffic enters.
Which single cell in this area is a genuine absence rather than a difference in packaging?
Oracle ships no first-party general-purpose content delivery network and documents partner networks as the path, which is an absence to design around. The other three all describe a capability that is present and packaged differently: Azure caches inside Front Door, Google Cloud fronts globally with its balancer, and OCI absorbs attacks at no extra charge rather than selling a tier.

Practice about 15 minutes, with paper

Practice 1working

A payments API serves users on three continents. It speaks HTTPS, it must present two fixed addresses to a partner's firewall allow-list, and a regional outage must move traffic away inside a minute.

(a) Which AWS entry point meets the fixed-address requirement, and why is the application balancer not it?
(b) On Azure, which single product covers the global entry, the caching and the firewall together?
(c) On OCI, name the part of the requirement that the platform's own global entry cannot meet, and say what it would take to meet it.

Hint

For (a), ask which of the two AWS entry points is documented as giving out addresses rather than a name. For (c), work from the failover clock in section 3 rather than from the steering policy list.

Show the worked solution
  1. Pick the AWS entry. Global Accelerator, which is documented as providing two static anycast addresses and is positioned for exactly the case of HTTP traffic that needs fixed addresses. An application balancer is reached by name and its addresses are not yours to pin, so an allow-list built on them is a design that breaks without warning.
  2. Pick the Azure product. Front Door Standard or Premium, which carries the global anycast ingress, the caching, the rules engine and the web application firewall in one product. Application Gateway would give the firewall and the routing but only inside one region.
  3. Name the OCI limit. Traffic Management steers by answering a name lookup, so a client that has cached the previous answer keeps using it until the time to live expires. The steering itself is health-checked and will change, but the sub-minute guarantee belongs to the client's cache, not to Oracle.
  4. Say what it would take. A short time to live, accepting the extra query load Oracle's own documentation names as its cost - or a proxy in the path that is not the platform's, which is the same shape as the partner-CDN answer in the caching row.

Sanity check. Two of the three answers should name a product and one should name a constraint - if all three named a product, part (c) was answered as though every cloud has the same shape, which is the habit this page exists to break. And the AWS answer must be the one that gives out addresses: if your answer is reached only by name, it cannot satisfy an allow-list.
