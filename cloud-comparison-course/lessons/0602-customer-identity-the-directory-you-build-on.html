Module 06 · Identity and access · Lesson 0602

Your application's users live in a directory your staff never enter

working 6 min Capability area identity-customer, three rows of the matrix: ciam-user-directory, ciam-social-federation, ciam-mfa.

The one-minute version

  • Customer identity is a separate directory on all four clouds, because it is sized in millions, filled by self-registration, and billed per monthly active user.
  • Azure and OCI place it inside the identity plane as a dedicated tenant or domain. AWS and Google Cloud sell a separate product beside it.
  • All four broker social and enterprise sign-in, and only OCI puts a counted limit on how many providers one directory may carry.
  • Passkeys are the sharpest divergence: AWS and OCI support WebAuthn, and Google Cloud's customer directory is limited to SMS and one-time codes.
  • The AWS trap is the identity pool, which is not the user directory and exists to hand out cloud credentials rather than to sign anybody in.

1. Why it is a second directory at all

A workforce directory holds people your organisation onboarded, counted in thousands, priced per seat. A customer directory holds people who arrived on their own, counted in millions, priced per monthly active user, and it needs self-registration, consent capture and branded sign-in pages that the workforce directory has no reason to offer. Every cloud therefore ships a second one - and the interesting question is where they put it.

3. What the application actually receives

The sign-in flow looks identical from the outside and ends differently on AWS, because one of its two objects is a bridge into the platform rather than a directory.

Three names that are not what they sound like A Cognito user pool is the directory; a Cognito identity pool hands out AWS credentials and is the legacy path. Azure External ID is the strategic customer platform and Azure AD B2C is the earlier one, closed to new customers with support committed for years yet - an end of sale, not a retirement. An OCI External User domain is for consumers, and employee accounts are not meant to live in one.

4. What this certification tests

This is the lightest identity area of the four on every professional track: the verified inventories mark every customer-identity row as low exam weight on AWS, Google Cloud and OCI, and medium on Azure only. That is a finding rather than an omission - the professional architect exams test how you govern the platform, and a customer directory is something you build a product on rather than something you govern the estate with. Azure carries more of it because External ID lives inside the same identity, governance and monitoring domain that already runs at 25 to 30 percent.

Retrieval practice

Answer from memory before revealing.

A product must offer customers passwordless sign-in with a passkey. Which cloud's customer directory cannot?
Identity Platform's second factors are documented as message codes and one-time codes, with no WebAuthn factor at all. The other three each name a hardware-backed factor: OCI lists FIDO2 and Yubico keys, Cognito supports passkeys above its lowest tier, and Entra lists FIDO2 and passkeys. Each wrong option is a true statement about a capable directory, which is exactly why the row is worth checking rather than assuming.
Which statement correctly separates a Cognito user pool from a Cognito identity pool?
A user pool authenticates people and issues application tokens; an identity pool exchanges a token for AWS credentials and is the legacy bridge. The first option invents a split that does not exist, since groups live inside the user pool. The second and fourth are plausible-sounding attributes that no AWS page states, and the second in particular describes refresh-token behaviour that belongs to the user pool.
Why do Azure and OCI put customer identity inside the identity plane rather than beside it?
An external tenant and an External User domain are the same identity product configured for a different population, which is why they inherit its federation and factor machinery. The second is wrong and is explicitly warned against for OCI, where employee accounts are not meant to live in an External User domain. The third and fourth describe consequences nobody documents.

Practice about 12 minutes, with paper

Practice 1working

A consumer application has two hard requirements: customers sign in with a passkey and no password at all, and the operator must be able to place the customer directory under the same administrative governance as the rest of the estate.

Rank the four clouds against those two requirements and name the one that fails the first outright.

Hint

The two requirements pull in different directions. One is answered by the factor list of the directory, and the other by where the directory sits in the diagram at the top of this page.

Show the worked solution
  1. Take the factor requirement first. Passkeys need a WebAuthn factor. AWS lists WebAuthn passkeys usable as a first factor, OCI lists FIDO2 and Yubico keys, and Azure lists FIDO2 and passkeys. Google Cloud Identity Platform documents message and one-time codes only, so it fails outright.
  2. Take the governance requirement. Azure External ID is a tenant inside the identity plane and OCI External User domains are a domain type inside the same IAM, so both inherit the platform's own administration. Cognito is a separate product with its own administration beside account IAM.
  3. Combine them. Azure and OCI satisfy both. AWS satisfies the factor requirement and answers the governance one with a separate surface. Google Cloud fails the first.
  4. Name the cost of the ranking. The two clouds that win here win because their customer directory is the same product as their staff directory, which is also the reason its limits are the platform's limits - the OCI provider cap of five on the free tier is a platform tier decision, not an application one.

Sanity check. Exactly one cloud should fail on the factor requirement, and the two that satisfy both should be the two whose directory sits inside the identity plane in the second figure. If your ranking puts AWS first on governance, re-read where Cognito sits.

Your teacher. If the user-pool and identity-pool split still feels arbitrary, ask an agent to draw the two objects for one sign-in and mark which arrow carries an application token and which carries AWS credentials. The reason the two are separate becomes obvious the moment you see that only one of them ever talks to an AWS service.
