# AGENTS.md - COURSE NAME

Instructions for AI coding agents working inside this course folder.
The repository root [`../AGENTS.md`](../AGENTS.md) still binds, and it wins wherever the two disagree.
This file adds only what is true of this course and nowhere else.

Fill this template from what the course actually is, then cut anything that came out generic.
A short honest file beats a long boilerplate one nobody reads.

## What this course is

Two or three sentences, compressed from `MISSION.md`: what the course teaches, who it is for, what shape it takes, and what it owns in this hub that no sibling course owns.
An agent reading only this file should still not violate the course.
Point rather than restate: where a fuller statement exists elsewhere, name the file.

## Read before you write

In this order:

1. [`MISSION.md`](MISSION.md) - why the course exists and what is out of scope. Canonical, settled by interview; do not rewrite it as a side effect of other work.
2. [`NOTES.md`](NOTES.md) - how this course teaches: cadence, diagram policy, known gotchas.
3. [`BUILDER-SPEC.md`](BUILDER-SPEC.md) - the markup contract for a page. Delete this row if the course has no spec.
4. [`RESOURCES.md`](RESOURCES.md) - the sources this course trusts. Add anything new there before citing it. Delete this row if the course keeps citations per lesson instead.
5. [`PLOT.md`](PLOT.md) - the true reading order and everything planned but unwritten. Place any new session by it, never at the bottom.
6. Two neighbouring lessons, to match voice, depth, and structure.

## The rules that bite hardest here

The two to four rules an agent violates first in *this* course, each stated in one line and pointed at the file that carries the full statement.
Rules that merely restate the repository root `AGENTS.md` do not belong here.

## Out of scope here

One line naming what this course never covers, pointing at `MISSION.md`, which owns the full list and the reasons.
