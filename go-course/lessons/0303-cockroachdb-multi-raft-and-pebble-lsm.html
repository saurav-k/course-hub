Module 03 · Distributed Consensus · Lesson 0303

CockroachDB scales distributed SQL across thousands of consensus groups using Multi-Raft, range leases, and the pure-Go Pebble LSM engine

foundation 12 min Distributed storage architecture in CockroachDB · cockroachdb/cockroach

The one-minute version

  • Single-Raft systems (like etcd) cannot scale horizontally beyond a single leader; CockroachDB divides its entire key-value keyspace into 64 MB chunks called Ranges, each managed by its own independent Raft group (Multi-Raft).
  • To avoid paying network round-trip latencies for read queries, CockroachDB introduces Range Leases: a time-bounded lease held by one replica that serves linearizable reads locally from disk without consensus RPCs.
  • Early CockroachDB versions used C++ RocksDB via Cgo, but Cgo transitions (stack switching, pointer pinning, and scheduler contention) severely degraded tail latencies.
  • Cockroach Labs engineered Pebble, a pure-Go Log-Structured Merge-tree (LSM) storage engine that eliminated Cgo overhead, improved write throughput, and integrated natively with Go tooling.

1. Multi-Raft: breaking the single-leader bottleneck

In standard Raft implementations like etcd, every proposal in the entire database must pass through a single Raft leader node. While this works beautifully for configuration stores and Kubernetes control planes, it cannot scale to petabyte-scale relational databases processing hundreds of thousands of transactions per second.

CockroachDB solves this by partitioning its ordered global keyspace into contiguous 64 MB blocks called Ranges. Each range is independently replicated across 3 or 5 nodes using a dedicated instance of go.etcd.io/raft.

On a single physical CockroachDB server, a single Go process may manage 50,000 active Raft groups. Heartbeats and messages for all co-located ranges are coalesced and multiplexed across persistent gRPC stream connections, keeping CPU utilization and socket overhead low.

2. Range leases: zero-network consistent reads

Under textbook Raft, reading data requires either proposing a dummy log entry or executing a round of heartbeats (ReadIndex) to verify that the current leader has not been deposed by a network partition. In read-heavy workloads, this network tax cripples throughput.

CockroachDB bypasses this with Range Leases. At any given moment, each range has exactly one Leaseholder (typically the Raft leader):

  • The lease is granted through a special Raft log entry with a duration (e.g. 9 seconds).
  • While the lease is active, the Raft protocol guarantees that no other node can be granted a lease or commit overlapping writes.
  • Therefore, when a client issues a SELECT query, the Leaseholder can read the data directly from its local storage engine with zero network communication, while strictly guaranteeing linearizability.

3. Why Pebble replaced RocksDB: the Cgo tax

When CockroachDB was first built, it used Facebook's C++ RocksDB through Go's Cgo bridge. While RocksDB is an exceptional storage engine, the friction between the Go runtime and C++ became CockroachDB's primary operational ceiling.

The penalties of Cgo in high-concurrency systems are severe:

  • Goroutine stack switching: A goroutine calling a C function must transition from its dynamic 2 KB stack to a full 2 MB pthread stack, forcing CPU cache invalidations.
  • Pointer passing overhead: Go's garbage collector verifies that pointers passed across Cgo boundaries do not violate memory pinning rules (runtime.cgoCheckPointer).
  • Profiler blindness: Standard Go tools like pprof, trace, and race detectors cannot peer into C++ memory or threads.

To break through this ceiling, Cockroach Labs built Pebble, an LSM-tree database written in 100% pure Go. Pebble matched RocksDB's performance while completely eliminating Cgo call overhead, reducing memory fragmentation, and allowing Go's work-stealing scheduler to coordinate CPU threads seamlessly.

Why did Cockroach Labs replace C++ RocksDB with pure-Go Pebble?
Cgo context switches between Go goroutine stacks and C pthread stacks introduced substantial CPU latency, and prevented native Go profiling tools from inspecting storage internals.
How does a Range Leaseholder in CockroachDB serve linearizable reads without Raft RPCs?
Because the time-bounded lease guarantees that no conflicting write can be committed elsewhere during the lease duration, the leaseholder can safely return data directly from local storage.
In CockroachDB's Multi-Raft architecture, what represents a single Raft consensus group?
The keyspace is partitioned into independent 64 MB contiguous ranges; each range runs its own distinct Raft consensus instance replicated across cluster nodes.
Systems insight. Writing system software in Go often tempts teams to reach for mature C/C++ libraries via Cgo. While convenient initially, high-throughput systems always run into Cgo scheduling overheads. CockroachDB's transition to Pebble proves that pure-Go implementations designed with mechanical sympathy frequently surpass Cgo-wrapped alternatives.
