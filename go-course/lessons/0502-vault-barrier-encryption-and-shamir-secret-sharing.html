Vault protects sensitive state across untrusted backends using AES-GCM envelope barriers, Galois field Shamir splitting, and lease revocation

foundation 12 min The zero-trust security architecture of HashiCorp Vault · hashicorp/vault

The one-minute version

  • Vault is designed with zero trust toward its storage medium: whether backed by Consul, Raft, or S3, data is assumed to be stored on an adversary-controlled disk.
  • All data crossing the persistence boundary passes through a Cryptographic Barrier utilizing AES-256-GCM authenticated encryption, providing both confidentiality and tamper detection.
  • The barrier is unlocked using a root Master Key that is never written to disk; on initialization, the key is split into $N$ shards with a threshold of $T$ using Shamir's Secret Sharing over finite Galois Field $GF(2^8)$.
  • Vault rejects static passwords in favor of Dynamic Leases: temporary credentials generated with a Time-To-Live (TTL), automatically revoked by an internal background expiration manager when time expires.

1. The zero-trust cryptographic barrier

Most applications trust their database: if an attacker compromises the database backup or disk volume, all credentials are lost. Vault assumes from day one that the storage backend is untrusted and compromised.

In vault/barrier.go, all storage operations implement the SecurityBarrier interface. Every write is encrypted using AES-256 in Galois/Counter Mode (GCM):

// Pattern from vault/barrier_aes_gcm.go
type SecurityBarrier interface {
	Put(ctx context.Context, entry *Entry) error
	Get(ctx context.Context, key string) (*Entry, error)
	Delete(ctx context.Context, key string) error
}

func (b *AESGCMBarrier) encrypt(key []byte, plaintext []byte) ([]byte, error) {
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, err
	}
	aesgcm, err := cipher.NewGCM(block)
	if err != nil {
		return nil, err
	}

	// 12-byte cryptographic random nonce
	nonce := make([]byte, aesgcm.NonceSize())
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		return nil, err
	}

	// Encrypt and append 16-byte authentication tag
	return aesgcm.Seal(nonce, nonce, plaintext, nil), nil
}

AES-GCM is an Authenticated Encryption with Associated Data (AEAD) cipher. If an attacker tampers with a single bit of the encrypted payload in the storage layer, the 128-bit authentication tag fails validation, and Vault refuses to deserialize the corrupted block.

2. Shamir's Secret Sharing over Galois Field GF(256)

How do you protect the Master Key that decrypts the barrier? If you store it on disk, the machine is vulnerable upon reboot. If you give it to one human administrator, that administrator has unchecked unilateral power.

Vault uses Shamir's Secret Sharing Scheme ($T$-of-$N$ threshold). When Vault initializes:

  1. A 256-bit cryptographic Master Key ($S$) is generated in volatile RAM.
  2. A random polynomial of degree $T-1$ is chosen: $f(x) = S + a_1 x + a_2 x^2 + \dots + a_{T-1} x^{T-1}$.
  3. Calculations are performed over the finite Galois Field $GF(2^8)$ to avoid arbitrary-precision integer leakage.
  4. $N$ points on the curve $(x_i, f(x_i))$ are distributed to $N$ administrators as unseal keys.

3. Dynamic leases and lease expiration trees

The ultimate goal of systems security is eliminating long-lived credentials. If a password never changes, it will eventually leak onto GitHub, into logs, or onto an engineer's laptop.

Vault solves this through Dynamic Secrets. When an application asks for a database credential, Vault logs into PostgreSQL, creates a brand-new user with a randomized password, grants permissions, and issues a Lease with a Time-To-Live (e.g. 1 hour).

// Pattern from vault/expiration.go
type ExpirationManager struct {
	// Leases ordered chronologically by expiration time
	leaseHeap *priorityQueue
	mu        sync.Mutex
}

func (m *ExpirationManager) run() {
	for {
		now := time.Now()
		m.mu.Lock()
		nextLease := m.leaseHeap.Peek()
		if nextLease == nil || nextLease.ExpireTime.After(now) {
			m.mu.Unlock()
			time.Sleep(1 * time.Second)
			continue
		}

		// Lease expired! Pop from heap and invoke backend revocation
		expired := m.leaseHeap.Pop()
		m.mu.Unlock()

		go m.revokeLease(expired)
	}
}

Retrieval practice

Answer from memory before revealing.

Why does Vault treat its physical storage backends (Consul, Raft, S3) as untrusted?
By assuming the storage layer is compromised, Vault encrypts all data with AES-256-GCM before writing, ensuring that stolen disk snapshots or compromised databases reveal zero secrets.
What mathematical principle powers Vault's threshold unseal key sharing?
Shamir's Secret Sharing uses polynomial interpolation over a finite Galois Field GF(2^8) (GF(256)) to reconstruct the master key from any T-of-N unseal shards.
What occurs when a dynamic secret lease expires without renewal in Vault?
When a lease expires, Vault's internal expiration manager calls the respective secret engine plugin to drop the user, delete the credential, or terminate the session.
Systems insight. Vault's design teaches an essential security principle: defense in depth requires untrusted persistence. Never rely solely on network firewalls or database passwords to protect confidential state. Encrypt application payloads at rest with authenticated ciphers and retain encryption keys strictly in volatile memory.
