MinIO achieves gigabyte-per-second object storage resilience using SIMD-accelerated Reed-Solomon erasure coding and HighwayHash bitrot verification

foundation 12 min Extreme-performance distributed object storage · minio/minio

The one-minute version

  • Traditional storage engines rely on 3-way replication, wasting 200% extra storage capacity to protect against hardware drive failure.
  • MinIO uses Reed-Solomon Erasure Coding: objects are partitioned into $K$ data shards and $M$ parity shards (e.g. 12 data + 4 parity), tolerating the loss of any 4 drives with only 33% overhead.
  • To encode and decode at wire speeds (10+ GB/sec per node), MinIO utilizes Klaus Post's reedsolomon library, leveraging hand-tuned AVX-512, AVX2, and ARM NEON SIMD assembly routines.
  • To defend against silent media corruption ("bit rot"), MinIO tags every 1MB chunk with a HighwayHash-256 checksum; if a drive returns corrupted bytes, MinIO reconstructs the shard on-the-fly from remaining parity drives.

1. Reed-Solomon erasure coding and SIMD vectorization

In a cluster with 16 drives, an erasure set configuration of $12+4$ means that an object is sliced into 12 equal data shards, from which 4 mathematical parity shards are computed. The object can be read as long as any 12 of the 16 drives are online.

Computing Reed-Solomon parity requires matrix multiplication over Galois Field $GF(2^8)$. Performing this naively in Go loops would saturate CPU registers and throttle storage throughput to a few hundred megabytes per second.

MinIO uses Klaus Post's assembly-accelerated library (github.com/klauspost/reedsolomon), executing Plan 9 assembly routines utilizing 512-bit vector registers:

// Pattern from klauspost/reedsolomon
type Encoder interface {
	Encode(shards [][]byte) error
	Reconstruct(shards [][]byte) error
	Verify(shards [][]byte) (bool, error)
}

func New(dataShards, parityShards int) (Encoder, error) {
	// Dynamically detects AVX-512, AVX2, or ARM NEON CPU features
	if cpu.X86.HasAVX512 {
		return newAVX512(dataShards, parityShards)
	}
	if cpu.X86.HasAVX2 {
		return newAVX2(dataShards, parityShards)
	}
	return newGeneric(dataShards, parityShards)
}

With AVX-512, a single CPU core processes 64 bytes per instruction cycle, encoding parity at over 12 GB/s - outpacing 100GbE network cards!

2. Defeating silent bit rot with HighwayHash

Hard drives and SSDs suffer from bit rot: electrical interference, magnetic decay, or firmware bugs that flip bits without the drive controller reporting an I/O error. If unaddressed, silent bit rot corrupts backups over time.

In distributed storage, split-brain scenarios must be prevented. MinIO enforces strict read and write quorum based on the erasure set geometry:

// Pattern from minio/cmd/erasure-common.go
func (e *ErasureSet) WriteQuorum() int {
	// Must write to at least K+1 drives to prevent dual-master writes
	return e.dataBlocks + 1
}

func (e *ErasureSet) ReadQuorum() int {
	// Requires at least K drives online to reconstruct data
	return e.dataBlocks
}

Retrieval practice

Answer from memory before revealing.

Why does MinIO use Reed-Solomon erasure coding instead of 3-way drive replication?
3-way replication incurs a 200% storage overhead; Reed-Solomon erasure coding (e.g. 12+4) provides equal or better fault tolerance with only ~33% storage overhead.
How does MinIO achieve multi-gigabyte-per-second Reed-Solomon encoding in Go?
MinIO uses Klaus Post's reedsolomon library, which implements Galois field matrix operations using hand-crafted AVX-512 and AVX2 SIMD vector assembly instructions.
What happens when MinIO detects a HighwayHash checksum mismatch on disk read?
When HighwayHash detects bit rot, the corrupted block is discarded, reconstructed on-the-fly using the remaining parity shards, and rewritten cleanly to disk by a background healer.
Systems insight. High-performance Go code frequently bridges into hardware acceleration. When pure Go arithmetic creates a bottleneck for massive data streams, write or import Plan 9 vector assembly using AVX or NEON SIMD instructions to unleash the full capability of modern silicon.
